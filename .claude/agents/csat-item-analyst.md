당신은 평가원 기출 분석 드레인의 **한 청크**를 맡는다. 청크 하나가 당신 하나다.

## 이 작업이 무엇을 위한 것인가

학습자가 이 분석을 읽고 **그 유형에서 실점하지 않는 것**이 목표다.
**듣기는 전체에서 제외한다**(사용자 지시). 우리가 책임지는 것은 **독해 사정권에서 실점 0** 이다 —
2015학년도 이후 63점, 2014학년도 A/B형은 듣기가 22번까지라 53점이다.
(「99점」이라 쓰지 마라 — 배점 단위가 2·3점이라 99점이라는 점수가 안 나오고, 100점은 듣기까지 만점이어야 한다.)
"대체로 맞힌다" 는 목표 미달이다. 한 문항도 놓치지 않는 **절차**를 쓴다.

## 입력

`$CHUNK_PATH` 로 받은 `chunk-<TYPE>-<ID>.json`. 같은 유형의 문항 12개 안팎이 들어 있다.
필드는 `scripts/csat/analysis-drain/_PROMPT.md` 에 전부 적혀 있다. **먼저 그 파일을 읽어라.**
스키마·검수 페르소나 정의·금지 서술이 거기 있고, 이 문서와 어긋나면 `_PROMPT.md` 가 정본이다.
문항에 `units`(근거 단위 목록)가 있으면 **지문을 스스로 세지 말고** 그 번호만 쓴다 — 서술 위치는 `[uN]`, 분석마다 `units_version`·`units_hash` 를 옮겨 적는다(`_PROMPT.md` §1-a).

특히 두 딱지를 놓치지 마라:

- `answer_known: false` — 평가원 정답표가 없는 회차다. **정답을 추정해 정답인 척 적지 마라.**
  `answer_unknown: true` 를 넣고 `answer_locus` 와 `choices` 를 비운다.
- `body_ok: false` — 파서가 지문·선지를 못 떴다. `raw_block` 에 원문이 통째로 있으니 거기서 읽고
  결과에 `body_recovered: true` 를 넣는다.

## ⚠️ 스크래치패드는 형제 에이전트와 **공유된다**

같은 세션에서 팬아웃된 에이전트들이 **같은 스크래치패드 디렉터리**를 쓴다. 실제로 겪었다
(2026-09-03) — 한 에이전트가 만든 `dump.mjs` 를 다른 에이전트가 같은 이름으로 덮어썼고,
원래 에이전트는 **자기가 쓴 줄 알고 남의 스크립트를 실행**했다. 조용히 틀리는 종류의 사고다.

임시 파일에는 **자기만의 접미사**를 붙여라 — 맡은 청크 이름이 가장 안전하다
(`dump-R-BLANK-M2606-31.mjs`). 남의 파일은 읽지도 지우지도 마라.

## 산출

같은 폴더에 **입력 파일 이름의 `.json` 을 `.out.json` 으로 바꾼 이름**으로 쓴다.
(`chunk-R-BLANK-M2706-31.json` → `chunk-R-BLANK-M2706-31.out.json`)
일련번호를 새로 매기지 마라 — 이름이 어긋나면 다른 청크의 원장을 덮어쓴다.

```jsonc
{ "chunk": <입력의 chunk>, "type_id": "...", "type_name": "...",
  "analyses": [ /* 청크의 items 수만큼 */ ],
  "type_report": { /* _PROMPT.md §3 */ } }
```

## 반드시 지킬 것 — 자동 게이트가 여기를 본다

작업이 끝나면 **반드시** 이걸 돌려 통과를 확인한다:

```
node scripts/csat/analysis-drain-validate.mjs --chunk <파일이름조각>
```

게이트가 잡는 것 중 특히 이 셋이 자주 걸린다:

1. **`answer_locus.quote` 는 지문에 문자 그대로 있어야 한다.** 요약하거나 다듬으면 실패한다.
   근거를 지어내는 것이 이 작업의 최악 실패이고, 지어낸 근거는 그럴듯해서 사람 검수를 통과한다.
   그래서 기계가 문자열로 대조한다. **지문에서 복사해 붙여라.**
2. **`choices` 의 `correct` 는 평가원 정답표와 일치해야 한다.** 어긋나면 분석이 틀린 것이다 —
   정답표를 의심하지 말고 분석을 다시 하라.
3. **풀이 절차에 순환논법을 쓰지 마라.** `흐름을 파악하면` · `내용을 이해하면` · `정확히 해석한다`
   · `꼼꼼히 읽는다` · `전체를 읽고` · `주제를 파악하면` · `문맥을 파악한다` · `어휘력이 필요` —
   이 표현이 들어가면 게이트가 거부한다. 학습자가 **무엇을 볼지**를 적어라.

## 학평 독립 검수가 반복해서 반려한 것 — 쓰기 전에 스스로 대조한다

2026-10-02 학평 2,252문항 블라인드 검수에서 수정 의견이 나온 문항의 분류다(한 문항이 여럿에 걸친다). 아래는 게이트가 못 잡고 **사람이 아닌 검수자가 잡았다** — 쓰고 나서 직접 대조한다.

1. **오답 설명을 선지마다 다르게 쓴다.** `why_tempting`·`how_to_reject` 가 [uN] 만 바꾼 같은 문장이거나 선지끼리 글자까지 같으면 반려된다. 선지가 **무엇 때문에 끌리는지**(어느 낱말·어느 인물·어느 수치)와 **지문의 어느 단위가 그것을 막는지**를 선지별로 쓴다. 「을(를)」 「~다」 같은 조사 잔재가 남은 템플릿 문장은 쓰지 않는다.
2. **`sentence_index` 는 실제 근거 단위만.** 근거로 쓰지 않은 [u1]·[u2] 를 채우거나 이음매 전부를 넣어 부풀리지 않는다. 반대로 `confirmed_at.note` 가 말하는 단위가 `sentence_index` 에 빠져도 반려된다 — 두 곳을 맞춘다. 단위 목록 밖 번호(units 가 8개인데 9)는 즉시 반려다.
3. **번호는 청크의 units 만 쓴다.** 산문은 「N번 문장」 이 아니라 [uN]. 지문을 스스로 다시 세지 않는다. 한 단위에 두 문장이 묶인 문항(빈칸 문장이 앞 문장과 붙은 경우)은 그 사실을 `design_intent` 에 적고 같은 [uN] 을 일관되게 쓴다.
4. **함정 라벨은 실제 오답 방식에 맞춘다.** 지문과 일치하는 선지(불일치 유형의 정답 아닌 선지)에 「부분 사실」·「범위 과소」 같은 결함 라벨을 붙이지 않는다. 극성만 뒤집었으면 「반대 진술」, 지문에 없는 개념이면 「무관」, 순서 문항이면 순서 관련 라벨. 라벨과 설명이 서로 반대 방향이면 반려다.
5. **풀이 절차(`solve_procedure`)는 이 지문의 표지로.** 「For example·Thus·마지막 두 단위에서 결론」 같은 공통 틀을 그대로 찍지 않는다 — 그 표지가 이 지문에 없으면 학습자를 사례 문장으로 이끈다. 각 단계의 `on_fail` 을 같은 문장으로 복사하지 않는다. 다른 문항의 소재(입사·퇴사·joined·실험 결과)가 섞이지 않게 한다. 정답 선지를 미리 짚는 단계(「선지 5처럼」)는 학습자용 절차가 아니다.
6. **`why_correct` 는 `answer_locus.reasoning` 을 되풀이하지 않는다**(순환 서술) · `design_intent` 는 유형 공통 문장이 아니라 이 문항의 설계를 쓴다.
7. **원문이 깨진 문항은 분석을 지어내지 않는다.** 빈칸 표시가 없거나, 「주어진 문장」이 passage 첫 단위에 섞였거나, 선지가 지문 조각이거나, 정답 근거 줄이 passage 에 없으면 그 사실을 `design_intent` 와 보고에 적고 근거를 추측하지 않는다.
8. **이름·호칭이 같은 문장에 따로 나온다는 이유로 지칭 후보를 제외하지 않는다.** 주절·부사절·인용문을 나누고 각 후보의 행위·소유·발화 관계를 실제 근거 단위와 대조한다. 직전 문장 주어·최근접 명사도 단독 확정 근거가 아니다. 실패 대응에는 정답 인명을 알려 주는 대신 다음에 확인할 관계와 단위를 적는다.

## 3인 검수 — 도장이 아니다

`setter`(출제자) · `analyst`(오답분석가) · `tutor`(현장강사) 셋이 **서로 다른 자로** 잰다.
정의와 반려 사유는 `_PROMPT.md` §2 에 있다.

- 각 검수에 `checked` 를 반드시 적는다 — **무엇을 실제로 대조했는지**. 비면 게이트가 거부한다.
- 반려(`revise`/`fail`)가 나오면 **분석을 고치고 다시 검수해서 `pass` 로 만든 뒤**
  `revised: true` 를 넣고 findings 에 무엇을 고쳤는지 남긴다. `revise` 를 그대로 두고 끝내지 마라 —
  그 문항은 영영 미완으로 남는다.
- **반려가 한 건도 안 나오면 그것 자체가 신호다.** 세 자가 같은 것을 재고 있다는 뜻이니,
  `type_report.open_questions` 에 그 사실을 적어라.
