# Vocaflow CSAT 기출분석 — 전역 기본골격 최종 합의 기준선 v4.0

- 기준일: 2026-10-23
- 성격: **설계 정책 기준선(Baseline) / 구현·교육 효과 입증서 아님**
- 적용: 수능·모의평가·학력평가 영어의 실제 모든 문항 유형, PC 1280/1440, `/csat/item/[slug]`, 학습지도·Workspace 연계
- 입력: 사용자 제공 `csat-design-kit-20261023.zip`의 `00/02/03`, 대표 문항 `items/2026-{34,22,38}.{json,txt}`, `evidence/*`, 54개 격리 캡처; 기존 v3.0/v3.1 설계서
- 자료 제한: 원문 PDF 전문·영문 선택지 전문·정상 로그인/RLS 증빙·수능 듣기 원음·학생 학습 효과 측정 자료는 이번 묶음에 없다. 격리 화면의 빈 PDF를 서비스 결함이라고 단정하지 않는다.
- 심사 성격: **하나의 AI가 서로 다른 역할의 평가 기준을 독립 적용·교차 반박한 모의 합의**. 역할들이 아래 핵심 설계 규칙을 모두 수용할 수 있도록 충돌을 정리한 것이며, 현실의 학습자·교사·전문가로부터 만장일치를 받은 사실은 아니다.

## 0. 최종 판정과 이 문서의 우선순위

**기본 골격: 설계상 합의 가능 / 구현 착수 권고.** 아래 `CORE-01~CORE-12`는 이 단계에서 하나의 해석으로 확정하며, 실제 코드/자료와 모순되면 `ADR`과 반례를 기록해 해당 조항을 개정한다. 전체 제품 `CONTENT_VALIDATED`, `PRODUCT_VERIFIED`, `LEARNER_USABILITY_OBSERVED`, `TRANSFER_EVIDENCED`를 PASS 했다는 의미는 아니다.

**이 문서를 최상위 제품 계약으로 사용한다.** v3.1의 구체적 37개 강의 cue 분석표와 34·22·38 세부 해설은 **이 문서와 충돌하지 않는 범위에서** 참고한다. 오래된 문서들의 모든 규칙을 무조건 중첩 적용하지 않는다. 팀/에이전트마다 서로 다른 '최종안'을 해석하지 않도록 변경은 이 문서의 결정 ID에 연결한다.

## 1. 학습자에게 최종적으로 남길 능력과 서비스의 경계

최상위 교육 목표: *정답을 읽는 학생이 아니라, 발문의 요구와 원문의 조건을 구분하고, 근거→선지→판단→원리/한계의 논리를 설명하며, 새로운 검증된 실제 기출에서 그 원리의 적용·비적용을 분별하는 학습자를 지원한다.*

| 결과 | 학습자가 하게 될 실질적 판단 | 서비스가 제공할 경험 | 독립적 성취 판단 |
|---|---|---|---|
| O1 발문 | 어떤 대상/범위/극성에 답하는가 | 발문·선지 요구와 부정 범위를 근거와 연결 | 별도 관찰/독립 수행 필요 |
| O2 의미·조건 | 원문 의미와 `If`, `Ideally`, `might` 등 한정을 지키는가 | 선택 가능한 부분 인용, 문맥, 한정 구조 | 동일 |
| O3 근거 | 어느 사실이 어떤 결론을 어떻게 지지하는가 | 증거↔판단 관계선·대조·원문 점프 | 동일 |
| O4 답/오답 | 성립/실패/판단 불가/부분 사실/위치 부적합을 구별하는가 | 검수된 후보별 이유와 실제 근거 | 동일 |
| O5 원리·한계 | 어떤 조건에서 재사용하고 언제 적용하면 안 되는가 | 조건·적용 경계 대비 | 동일 |
| O6 새 기출 | 표면 유사성이 아니라 같은 판단 원리를 적절하게 적용하는가 | 검증·공개된 실기출 비교, 없으면 부재 명시 | 새 문항의 유효한 독립 판단이 필요 |
| O7 자기 조절 | 모르는 것, 필요한 도움, 이해했다고 생각하는 것을 구별하는가 | 도움 수준·강의·해설 자유 선택, 비채점 자가 점검 | 자가보고≠숙달 |

**교육적 기회 제공, 해설 후 확인, 독립 수행과 숙달은 서로 다른 사건이다.** 클릭·근거 펼침·강의 완주·탐색 완료·세션 종료·선택적 확인만으로 성적·숙달·학습지도 도달 수준을 올리지 않는다. 필수 퀴즈 통과, 자유서술 자동 채점, 개인 임의 업로드 자료 평가를 추가하지 않는다.

| L2 숙련 학습자 | 알고 있는 부분 건너뛰고 자유로운 경로 선택 | 강제 순서/문제 통과 후 해설 잠금 | CORE-03 수용 |

| E 수능 전문 강사 | 결정적 근거와 대표 대조를 빠르게 이해 | 과잉 강의·표지어 암기 공식 | CORE-04,05 수용 |

| C 학습과학·교수설계 전문가 | 판단 기회와 명시적 설명 모델링 병존 | 클릭=이해 또는 강의 먼저를 실패로 취급 | CORE-02,03,08 수용 |

| G 학부모·운영 관점 | 어디까지 배웠고 무엇이 미확인인지 정직하게 전달 | 강의 시청량을 학습 효과·등급 개선으로 홍보 | CORE-08,12 수용 |

## 3. 모든 역할이 수용하는 변경 불가 핵심 계약(설계 기준선)

| 결정 ID | 최종 단일 결정 | 허용되는 예외 또는 검증 기준 |

| CORE-01 증거 엄정성 | `공식 정답/원문 관찰/연결 추론/출제 설계 가설`을 구별; 검증된 문구만 사용 | 공식 출처 미대조면 '저장된 정답 정보·대조 필요' |
| CORE-02 판단의 의미 | 학생이 원문과 관계를 스스로 살펴볼 기회를 주고, 설명을 본 뒤 확인도 정상 학습으로 인정 | 어떤 클릭도 자동 숙달 아님 |

| CORE-05 사고 구조 | 시험 유형×판단 기능×증거 매체×데이터 준비도로 장면 조합 | 유형별 동일 6탭/모두 문장막대 강제 금지 |

| CORE-09 강의 | 기존 대본 원본 보존, cue를 시선·비교·판단·화면 반응에 결합; 읽기/TTS/무음 지원 | 음성 실패에도 학생 위치·선택·포커스 유지 |

위 12개 계약의 우선순위는 **정확성·접근 통제 > 오개념 방지 > 학습자 통제 > 가독성·디자인 > 편의성**이다. 단, 충돌 시 학생의 이용 자체를 차단하기보다 잘못된 해당 기능만 숨기는 부분 실패를 기본으로 한다.

## 4. 제품 골격: 진입·단일 화면·이동

### 4.1 진입과 홈

- 홈: 기존 **상단 간결한 도형 패턴/시작 공간 + 아래 리스트형 Workspace** 유지. 홈에서 26개 유형의 상세 장면을 늘어놓지 않는다.
- 진입: 학습지도/Workspace/목록/최근 문항에서 동일한 `/csat/item/[slug]`로; 복귀 출처, 최소 TASK 식별자, 사용자가 선택한 현재 장면을 안전하게 전달.
- 동일 문항에서 `근거 먼저`(새 진입 기본 추천), `해설과 함께`, `강의 먼저` 자유 전환. 개인의 명시적 선호나 이미 공개한 설명 상태를 뜻밖에 되돌리지 않는다.

### 4.2 한 장면(scene)의 교육 계약

각 scene에는 `지금의 판단 질문`, `검증된 자료/핵심 한정`, `학습자가 해볼 수 있는 선택적 행동`, `선택별 근거 반응`, `강의 cue`, `정답 공개 위험`, `데이터/권한/오류 대체`가 있어야 한다. 여러 조건을 동시에 보아야 하는 삽입/순서/듣기는 한 장면에 여러 자료를 함께 표시할 수 있다. 핵심은 **시각 구조가 판단의 논리 구조를 나타내야 한다**는 것.

- 발문 요구 이해 → 문장/발화의 의미·조건 탐색 → 근거 연결 → 선택지/위치 판정 → 원리 및 한계 → 다른 문항으로 전이: **공통 학습 질문 목록**이지 반드시 여섯 번 통과해야 하는 UI 상태 기계가 아님.
- 세부 해설, 원문 전체, 비교 자료, 강의 대본 전문은 별도로 펼쳐 볼 수 있고, 서로 동일한 설명을 반복 쌓지 않는다.

### 4.3 PC 와이어프레임(원칙, 실측 아님)

```text
┌ 문항·출처·복귀 / 학습 경로 전환 / 강의·접근성 조작 ─────────────────────┐
│ 현재 판단 질문 · 조건 강조 · 자유로운 활동 선택                      │
├──────────────────────────────────────┬─────────────────────────────┤
│ 증거 면: 로컬 PDF / 검증 부분 인용    │ 판단 면: 유형 전용 시각 모델 │
│ 문장·조건·도표 / 듣기 오디오·화자     │ 후보·연결·명제 대조          │
│ 선택 항목과 근거 앵커 연결            │ 선택 후 이유·원리의 한계     │
│ 자체 확대·스크롤                      │ 필요할 때 상세 설명         │
├──────────────────────────────────────┴─────────────────────────────┤
│ 현재 강의 cue 1개 · 읽기/TTS/무음 · 직접/암시적 정답 안내              │
└────────────────────────────────────────────────────────────────────┘
```

- PC 1280/1440에서 증거면과 판단면이 모두 접근 가능해야 한다. 도표·장문·삽입·듣기는 비율/세로 구성/확대를 달리할 수 있다. 상단·하단·drawer·스크롤 경계·글자/카드 크기는 **3B 실측 자료가 없는 만큼 실제 브라우저에서 측정해 조정**한다.
- 중립적 밝은 바탕/얇은 구분선/절제된 아이콘·색. 보라색 전체 배경·장식성 그림으로 학습 내용을 덮지 않는다. 중첩 팝업 금지; 한 시점에 하나의 인라인 상세나 비중첩 drawer.
- 시각 아이콘 자체는 작아도 목표 조작 면적 44×44 CSSpx; 보이는 포커스·키보드·비색상 상태 표시·드래그 대안·문맥 유지, 불필요한 자동 이동 방지. WCAG 2.2 2.5.8의 AA 최소는 24px 및 예외; 44px은 제품 강화 목표/AAA 강화 기준과 구별한다.

## 5. 콘텐츠 공개·강의·피드백의 타입 계약

### 5.1 공개는 두 독립 입력 + 실제 누출 검사

- `depth = CORE | EVIDENCE | ADVANCED` : 요약의 깊이.
- `reveal = SOURCE_ONLY | LOCATION_HINT | RELATION_FEEDBACK | OFFICIAL_ANSWER`: 답/풀이 공개 의도.
- `lectureMode = OFF | READ | TTS | SILENT`: 음성/설명 모드.
- 콘텐츠 조각(text, 관계선, 하이라이트, 선지 표식, 강의 cue, TTS, 툴팁, 화면 읽기용 숨김 텍스트, ARIA 이름)은 `none | strategic_hint | answer_implying | direct_answer` 위험 등급을 검수한다.
- 설명 깊이 `ADVANCED`가 정답 공개 허용 `SOURCE_ONLY`를 자동으로 무력화할 수 없다. 즉 심화 정보 중 정답을 암시하는 부분만 추가 선택 후 공개. **자동 텍스트 의미검출만으로 누출 0을 보증하지 말고 검수·대표 테스트를 수행**한다.
- 정답 포함 해설/강의는 정상 학습 경로이며, 사용자가 원하는 경우 즉시 공개한다. 먼저 보지 않기를 택한 경우 시스템이 예고 없이 노출하지 않는다. 실제 PDF 원문에 본래 정답을 유추할 단서가 있다는 사실은 시스템 누출로 간주하지 않는다.

### 5.2 오답은 타입별로 다르게 설명

공통 표시: `evidenceStatus=supported|contradicted|not_established|not_applicable`, `coverage=whole|partial|off_scope|not_applicable`, `requirementFit=satisfies|fails|undetermined`, `failureReasons[]`, `evidenceRefs[]`, `sourceRevision`, `reviewState`.

- 빈칸/함축: `조건·부정 범위·완성 명제`가 맞는지.
- 주제/요지/제목: `중심성·내용 포괄 범위·표현 강도`가 맞는지. 부분 사실과 전체 요지 혼동 금지.
- 삽입/순서: `앞 연결·뒤 연결·기존 연결 보존`으로 평가. 위치의 참/거짓 boolean 금지.
- 사실 일치/도표: `주체·시간·수치·단위·예외`의 실제 대조.
- 어법/어휘: `문장 구조 의존·문맥 의미`.
- 듣기: `화자·시간 범위·발화 기능·음원 출처·검수된 전사`.

이 구조는 **검수된 콘텐츠 표시 계약**이며 문항의 새 정답을 자동 산출하거나 자유서술을 채점하는 신규 엔진이 아니다.

### 5.3 기존 강의 37 cue 보존과 개선

현재 첨부: 2026-34 강의 v2/12차례, 2026-22 강의 v2/13차례, 2026-38 강의 v3/12차례. 세 문항의 분석은 별도 체계 v5. `est_sec`는 추정 길이. 차례당 `cueId / originalScript / displayedTarget / learnerLookAt / compareJudge / visualResponse / clueDisclosure / correctionProposal / evidenceRefs / cueRevision`.

- 34 c1/c4/c12: `Ideally`/`If` 및 부정의 범위를 줄여 ‘반대말 찾기’ 공식으로 만들지 않음.
- 22 c13: 이 글에서 정의→경향 진단→조건부 권고 구조가 작동한다는 근거를 보이되 '요지는 항상 결론 표지 뒤' 일반화 금지.
- 38 c1/c12: 예시 표지 반복만으로 삽입 위치 공식화 금지. c1은 번호를 말하지 않아도 간접 답 암시 위험 가능.
- 기존 대본과 새 문구는 revision을 분리해 근거 문장·선지와 연결해 수동 내용 감수 후 게시; 원본 자동 덮어쓰기 금지.
- 학습자는 cue를 직접 고르고 읽기/TTS/무음 사이 전환할 수 있음. 강의 진행이 사용자가 선택한 원문·장면·포커스·스크롤을 빼앗지 않음. TTS 실패 때 현재 상태 유지.

### 5.4 에러와 불확실성은 첫 번째 클래스

각 자원별 `readiness=ready|missing|stale|mismatch|unknown`, `review=accepted|pending|rejected|unknown`, `permission=allowed|denied|embargoed|unknown`, `pdfMatch=matched|absent|mismatch|unverified`를 독립 관리.

- PDF 미등록 → 검증된 부분 인용만, 전체 원문처럼 표시하지 않음.
- 해시/문장 수 mismatch → 관련 위치 강조 중지, 해설의 검증된 부분은 유지.
- 상세 의미 미준비 → 근거 없는 관계도 생성 금지; 기본 해설·관찰로 낮춤.
- 비교 짝 0 → 같은 원리 직접 비교 `UNAVAILABLE`; 다른 유형 링크는 `다른 사고 모델 살펴보기`로만 제공.
- 비교 짝 비공개/권한 미확인 → **클라이언트로 비공개 본문을 아예 전송하지 않음**.
- 강의 cue 앵커 불일치 → cue 읽기는 가능할 수 있으나 잘못된 하이라이트 대신 ‘근거 연결 미확인’.
- 평가 듣기 원음 미검증 → TTS를 평가 원음으로 대체하지 않음.

## 9. 학습지도 연결과 학습성과 판정

- 진입·복귀는 `returnContext`, `itemSlug`, `taskContext`의 검증된 최소 정보로 처리. 모든 경로에서 같은 분석 UI를 쓴다.
- 학습지도에는 '분석 활동 이력·선택한 원리/도움 상태'를 **학습 활동**으로 보여줄 수 있다.
- `ACTIVITY_ONLY`, `SELF_REPORT`, `EXPLANATION_CHECK`는 `INDEPENDENT_EVIDENCE`로 변환하지 않는다. `INDEPENDENT_EVIDENCE`가 확보되었다고 해도 기존 목표 달성 엔진의 기준과 별도 검토 없이 숙달을 자동 상승시키지 않는다.
- 새로운 실제 문항의 독립 수행, 인간 관찰, 사전/사후 조건 차이 등의 효과 근거는 **제품 내 필수 퀴즈가 아니라 별도 연구/평가 경로**로 확인할 수 있다.

## 10. 설계 완료와 실제 구현/효과 완료는 다른 승인 게이트

| Gate | 승인 명세 | 지금의 증거 상태 |
|---|---|---|
| G0 설계 수렴 | 모든 CORE에 단일 결정·반례·수용 테스트 존재, 역할간 정책 충돌 없음 | **문서상 수렴**. 실제 사람 합의 아님 |
| G1 콘텐츠 | 공식 답/원문·선지 실제 대조, 부분 자료 검수, cue 수정안 검토 | 대표 3문항 일부 근거만. `NOT_COMPLETE` |
| G2 제품 | 정상 로그인/RLS, 로컬 PDF, 1280/1440, TTS, 접근성, 권한·오류 | 격리 캡처 수준. `NOT_COMPLETE` |
| G3 학생 사용성 | 초심/숙련 학생이 스스로 찾아보고 오류를 해결하는가 | `NOT_EVALUATED` |
| G4 전이·성과 | 새로운 기출에 원리 적용/비적용을 독립적으로 설명하는가 | `NOT_EVALUATED` |

`G0`을 충족했다는 사실은 `G1~G4`를 PASS 했다는 뜻이 아니다. 실제 학습자 관찰 없이 이해/점수/등급이 향상되었다고 표시하지 않는다.

개발 정책: 일반 작업을 새 TASK·브랜치·PR로 불필요하게 쪼개지 않음. 기능 단위 **구현→필요 검증→간결한 문서→커밋·가능한 push**. DB 변경·삭제는 기존 승인 정책 준수; 배포/권한/내용 공개 전에는 해당 변경의 실제 검증 조건 준수. 인증/CI/검수 미실행 결과를 PASS로 꾸미지 않는다.

## 13. 남은 검증·개선 항목의 처리 원칙 (의견 갈림과 증거 부족 구분)

1. **확정된 설계 정책:** CORE-01~12. 동일 근거를 반복 토론하지 않고 구현 기준으로 사용한다.
2. **실제 자료 확인:** PDF/선지/정답 공식 대조, 3문항 외 강의 전수, 전체 유형 실제 매핑, 로그인/RLS/개별 권한, 오디오 원음·전사 등. 증거 없으면 `UNVERIFIED`; 어떤 전문가 역할도 이를 PASS로 바꿀 수 없다.
3. **실제 학생의 반응:** 본문 길이, 도움 공개 기본값, 화면 폭·탐색성, 원리 이해/전이. 서로 다른 학생이 다른 선호를 보일 수 있으므로 다양한 경로를 제공하고 실제 관찰로 결정한다.
4. **결정 변경 절차:** 발견된 반례에 `결정 ID → 실제 증거 → 수정 가능한 최소 범위 → 영향 테스트 → 콘텐츠 revision`을 붙인다. 필수 보존 계약을 깨는 제안은 별도 승인/심사 없이는 구현하지 않는다.

**최종 상태: `BASELINE_CONVERGED / IMPLEMENTATION_NOT_VERIFIED / LEARNING_EFFECT_NOT_EVALUATED`.** 

본 설계는 '모든 역할이 무조건 좋다고 말한 가상 만장일치'가 아니라 **반론할 수 있는 조건을 테스트로 바꿔, 정책상 모순이 남지 않도록 정리한 최소 공통 골격**이다. 실제 반례에 대한 수정을 허용하는 것이 설계의 품질 보장 조건이다.
