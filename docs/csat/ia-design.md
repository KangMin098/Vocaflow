# /csat 기출분석공간 — 정보 구조 · 지속 학습 설계 (2026-09-24 승인 · 2026-09-25 적용)

> 과제 3단계 산출물. 근거는 [needs-research.md](./needs-research.md)(니즈 N1–N24 · 중단 이유 S1–S11).
> **판정 기준은 하나다: 학습자가 다시 돌아와 이어서 하는가.** 모든 결정 옆에 그 결정이 막는 중단 이유(S)를 적었다.
> 2026-09-24 승인, 2026-09-25 적용. 설계와 **달라진 점**은 맨 아래 §8.

## 0. 설계 원칙

1. **메인 첫 줄은 「이어서」다.** 재방문한 학습자가 가장 먼저 보는 것은 설명도 목록도 아니고 **지난번 멈춘 자리와 오늘 할 복습**이다(S9 · S10).
2. **두 입구, 한 도착지.** 「유형별」(자료 축)과 「목적별」(니즈 축)은 **같은 필터 상태**로 번역된다. 도착지는 늘 같은 표 · 같은 문항 화면이다. 그래서 경로가 둘이어도 화면은 늘지 않는다.
3. **한 번에 작게.** 기본 단위는 **3문항 · 약 12분 세션**이다. 긴 계획 대신 짧은 세션을 여러 번 한다(S2 · S9).
4. **다시 묻되, 같은 문항으로 묻지 않는다.** 복습은 **같은 함정을 가진 다른 문항**으로 낸다. 외운 답은 통하지 않는다(S6).
5. **진척은 조용히 보인다.** 정답률 · 랭킹 · 뱃지는 두지 않는다(brief A2 · A7). 대신 「본 유형 x/26 · 만난 함정 x/32 · 내 공식 n」처럼 **덮어 간 넓이**를 보여 준다(S11 · Implicit Progress).
6. **결.** 메인과 하위 목록 화면은 **3B 앱 메인 결**(왼쪽 메뉴 · 띠 · 탭 + 표)로 통일한다. 해설 극장 판(레일 + 두 판 + 바닥 카드)은 **문항 해설 `/csat/item` 에만** 쓴다(사용자 지적 「극장 스타일 아님」, 2026-09-24).

지키는 제약(`csat-learner/DECISIONS.md`): 원문 비노출 · PDF 는 기기 안에서만 · 정답/해설은 예측 뒤 API 로만 · 수치는 계산값 · 새 화면은 진입 + 상호작용 이벤트를 같은 커밋에(D2/D3).

## 1. 정보 구조

### 1-1. 메뉴(왼쪽 레일) — 모든 /csat 화면 공통

```
[V] 기출분석공간
────────────────
 ▸ 홈                     /csat
 ▸ 이어서 · 복습  (3)      /csat?view=continue        ← 개수 = 오늘 due + 진행 중 세트
 ▸ 내 기록                 /csat/record               ← 신규(진척 · 공식 · 만난 함정)
────────────────
 목적별                                               ← 니즈 축
   처음 시작하기           → 오늘의 해부 3문항 + 방법 한 장      N1 N14 · S1
   킬러 유형 잡기          → 유형 = 빈칸·순서·삽입              N17
   오답 선지 설계 보기     → 탭 = 함정                          N3 N12
   근거 문장 찾기          → 지문 지도 있는 문항만              N4
   최근 기출부터           → 2023학년도 이후                    N16
   시간 재고 풀기          → 해부 세션 + 유형 시간 예산         N15
────────────────
 유형별  26                                           ← 자료 축
   빈칸 추론 115 · 안내문 일치 57 · …                  N5 N20
────────────────
 회차별  29                                           ← 시험지 축
   2027학년도 6월 모의평가 · …                         N22
```

- 「목적별」 한 줄 = **미리 짜 둔 필터 한 벌**(URL 쿼리). 새 데이터가 없다.
- 「유형별」 · 「회차별」 = 같은 표의 필터. 두 축 어느 쪽으로 들어가도 **같은 문항 화면**(`/csat/item/[slug]`)에 닿는다.
- 대응 자료가 없는 니즈(N2 등급 판정 · N8 구문 · N18 정답률 · N19 EBS 연계)는 **메뉴에 넣지 않는다.** 없는 것을 있는 것처럼 두지 않는다. §6 에 후속 후보로만 둔다.

## 2. 와이어프레임

### 2-1. 홈 `/csat` — 재방문 상태

```
┌──────────┬──────────────────────────────────────────────────────────────────────┐

│ (1-1)    │ ┌──────────────────────────────────────────────────────────────────┐ │
│          │ │ ○○●●○○ (격자 원 띠)   ┌ 이어서 ────────────────────────────┐  ○●● │ │
│          │ │                       │ ▶ 빈칸 추론 세트 2/3 · 약 4분 남음   │     │ │
│          │ │                       │   오늘 복습 2 · 「주체 역전」 함정    │     │ │
│          │ │                       │ [이어서 하기]        [복습 2문항]   │     │ │
│          │ │                       └────────────────────────────────────┘     │ │
│          │ ├──────────────────────────────────────────────────────────────────┤ │
│          │ │ 목적별  처음 시작 · 킬러 유형 · 오답 설계 · 근거 찾기 · 최근 · 시간 │ │

│          │ │ [유형 26] [함정 32]  덮은 넓이: 유형 7/26 · 함정 11/32   채움 현황 │ │
│          │ │ 01 빈칸 추론   115문항 · 오답 460   ● 본 문항 6   예시 2026 수능 34 │ │
│          │ │ …                                                                │ │
└──────────┴──────────────────────────────────────────────────────────────────────┘
```

- 띠 위 상자 = 지금의 「무엇을 해부할까요?」 입력 자리. 재방문이면 **이어서 카드**로, 첫 방문이면 **처음 시작 카드**(2-2)로 바뀐다. 찾기 입력은 표 머리로 내린다.
- 표의 「본 문항」 열 = 이 학습자가 그 유형에서 연 문항 수(item 열람 기록).

### 2-3. 며칠 공백 후 복귀 (S9 · S10)

```
┌ 다시 오셨네요 ─────────────────────────────────────────┐
│ 지난번: 9월 18일 · 빈칸 추론 세트 2/3에서 멈춤          │
│ 밀린 복습 9개 중 **오늘은 3개만** 골랐어요.              │
│ [3문항만 하기 · 약 12분]    [멈춘 세트 이어서]          │
└───────────────────────────────────────────────────────┘
```

- 밀린 복습을 전부 들이밀지 않는다. **최대 3개로 압축**하고 나머지는 날짜를 뒤로 민다(what-the-hell 효과 차단).
- 죄책감 문구 · 연속 끊김 표시는 쓰지 않는다(Empathetic Feedback).

### 3-1. 서버 동기화 — 데이터 설계 (승인 필요 · 마이그레이션)

- 새 표 대신 **기존 죽은 경로를 살리는 안**과 **jsonb 한 행 안**을 비교했다. 추천: **`csat_learner_state(user_id pk, record jsonb, updated_at)` 한 표**.
  - 이유: `DissectionRecord` 는 이미 버전 붙은 JSON 한 덩어리다. 행을 쪼개면 queue · formulas · predictions 마다 표가 는다. 기존 `csat_session_attempts` · `csat_review_queue` 는 옛 `LearnerRecord` 모양이라 맞지 않는다.
  - 병합: 기기 기록과 서버 기록이 다르면 **항목별 최신(updated_at) 우선**, queue 는 tag 기준 합집합. `JSON.stringify` 비교 금지(AGENTS — 키 순서).
  - RLS: 본인 행만 읽기/쓰기.
- 원문 · PDF · 해시 외 식별자는 싣지 않는다(기존 제약 그대로).
- **마이그레이션 SQL 은 적용 단계에서 보여 드리고 승인 후 적용한다.**

## 5. 지속 학습 지표 · 측정

이벤트는 `funnel_events`(기존)로 보낸다. 속성은 숫자 · 불리언 · 닫힌 열거형만(D3).

| 지표 | 정의 | 이벤트(신규 ★) | 속성 |
|---|---|---|---|
| 홈 진입 상태 분포 | 첫 방문 / 재방문 / 공백 복귀 비율 | ★ `csat_home_viewed` | `state: first\|return\|comeback` · `due: 0\|1-3\|4+` · `gap: 0\|1-2\|3-6\|7+`(일) |
| 이어하기 사용률 | 이어서 카드가 보인 방문 중 누른 비율 | ★ `csat_resume_clicked` | `kind: set\|review\|comeback` · `from: home\|today\|record` |
| 복습 완료율 | 시작한 복습 중 끝낸 비율 | ★ `csat_review_started` / ★ `csat_review_done` | `size` · `substituted: bool`(다른 문항으로 냈는가) |
| 재방문율(D1 · D7) | 첫 학습 뒤 1일 · 7일 안에 다시 연 사용자 비율 | 위 이벤트의 user_id · occurred_at 으로 계산 | — |
| 연속 학습일 | 사용자별 학습한 날의 연속 길이(내부 지표 — 화면에 연속 끊김을 표시하지 않는다) | `csat_session_started` · `csat_review_started` | — |
| 경로 비율 | 목적별 / 유형별 / 회차별 중 어디로 들어왔는가 | ★ `csat_path_chosen` | `axis: need\|type\|exam` · `need: start\|killer\|trap\|evidence\|recent\|timed` |
| 막다른 길 해소 | item 에서 목록으로 돌아간 비율 | ★ `csat_item_back` | `to: home\|type\|browse` |

측정 방법: `funnel_events` 를 사용자 · 날짜로 묶는 SQL 을 `scripts/csat/continuity-metrics.mjs` 로 두고, PLATFORM_AUDIT 분기 진단에서 읽는다. **현재 실사용 0**이라 기준선은 0에서 시작한다. 지표를 목표로 삼기 전에 학습자 유입이 먼저다(AGENTS 「수요 측」).
