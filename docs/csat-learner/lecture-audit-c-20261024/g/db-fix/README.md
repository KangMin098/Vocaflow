## 3. SQL

| 파일 | sha256 |
|---|---|
| `forward.sql` | `b67b62201d8d8718c9a6061b77282bcf2d2426c55fa3856e7154bc39aadb61bd` |
| `recovery.sql` | `3153bfbae43ea7df3a76bcaaa98ab8dad4c2df2dc330051aaa2655451b000dd7` |

- 한 개의 `DO` 블록이다. 각 UPDATE 는 승인 시점 값의 md5 가 같을 때만 바꾼다. 바뀐 행 수가 4가 아니면 예외로 전체를 되돌린다.
- 승인 뒤 실행 방법: `mcp__supabase__execute_sql` 로 forward.sql 전문을 보낸다(DML 이라 migration 아님). 실행 직전에 파일 sha256 을 다시 계산해 위 값과 맞는지 확인한다.

## 5. 복구 계획 (비파괴)

- `recovery.sql` 이 정정된 값의 md5 를 확인한 뒤 원래 문자열로 되돌린다. 행 삭제나 백업 테이블 같은 DDL 없이, 4행 모두 정확히 원래 md5 로 돌아간다(왕복 검증).
- 정정 뒤 다른 변경이 섞였으면 복구 SQL 은 아무것도 바꾸지 않고 예외로 멈춘다.
