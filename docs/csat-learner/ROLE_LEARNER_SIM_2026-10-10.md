# 역할 학습자 시뮬레이션 — E축 확인 과제(2026-10-10)

> 사용자 지시: 「실제 학습자가 필요하면 역할을 부여해서 claude code 로 진행」.
> **이 결과는 프로세스 검증이지 학습 효과 근거가 아니다.** 학습자는 모델(Claude Code 서브에이전트)과 규칙 학습자다. MC-12(실제 학습자 효과)는 여전히 UNKNOWN 이다.

## 무엇을 했나

1. **내보내기** `scripts/csat/map/role-learners-export.mts`(개발 DB 읽기만)
   - E축 두 과제의 확인 문항 묶음을 학습자 화면 그대로 내보냈다. 과제당 6문항이다.
     - option-restate: 2026·2025 수능 22–24번
     - evidence-locate: 2026 수능 31–34번, 2025 수능 31·32번
   - 내보낸 내용은 번호 붙은 지문 문장 · 발문 · 선지다. 정답 · 근거는 넣지 않았다.
   - 문장 경계가 골격과 12/12 같았다.
2. **역할 학습자 3명**(맹검 서브에이전트 · 병렬)이 12문항을 풀었다. 페르소나는 기초(중3) · 중위(고2 3등급) · 상위(고3 1등급)다.
3. **채점 · 엔진 통과** `scripts/csat/map/role-learners-simulate.mts`(DB 안 씀)
   - 실제 채점기 `gradeEvidence` 를 쓴다.
   - 직접 확인 엔진 `skillDiagnosis` 와 생애주기 `lifecycleCells` 를 그대로 거친다.

## 발견 1 — 골격 근거 표시를 정답으로 쓰면 안 된다(결함 → 수정)

첫 판(골격 answer 앵커를 그대로 정답으로 씀)의 결과는 이랬다.
- 상위 페르소나의 근거 판단이 2/6 이었다.
- 오답 5건을 지문으로 대조했더니 앵커 쪽이 틀렸다.
  - 빈칸 문항에서 앵커가 **빈칸 문장 자체**를 가리켰다. 2026#32 는 앵커 7 = 빈칸 문장 7 이었다.
  - 앵커는 「해설에서 정답 표현이 걸리는 곳」이지 「근거 문장」이 아니다.

수정:
- 판정자 B(맹검 서브에이전트)를 하나 더 두었다. B 는 정답 · 빈칸 문장 · 근거로 인정할 범위를 판정했다.
- **근거 = B 의 인정 범위 ∩ (골격 앵커 ∪ 상위 페르소나 답)** 으로 정했다. B 의 인정 범위 중 나머지는 「갈린 문장」으로 두어 골라도 틀리지 않게 했다. 빈칸 문장은 근거에서 뺐다.
- 결과는 합의 주석 `apps/web/src/lib/knowledge/annotations/evidence-tasks.v1.json` 12문항이다. 12/12 문항에 합의된 근거가 있다.
- 골격 앵커만으로 과제를 만드는 경로는 없앴다. 테스트 `vertical-evidence-locate.test.ts` 가 이를 지킨다.

## 발견 2 — 모델 페르소나는 사람의 오류 습관을 재현하지 못한다(한계)

합의 주석 기준 정답 수(6문항 중):

| 페르소나 | 선지 재진술 | 빈칸 근거 | 직접 확인 |
|---|---|---|---|
| 기초 | 5 | 6 | 확정 안 됨(unverified) |
| 중위 | 6 | 5 | 확정 안 됨 |
| 상위 | 6 | 6 | 확정 안 됨 |

- 「기초 학생」 역할도 근거를 대부분 찾았다. 모델은 읽기 능력을 낮춰 연기하지 못한다.
- 상위 페르소나의 답은 합의 주석 재료에 들어갔다. 그래서 상위 6/6 은 **순환 근거**다(품질 지표로 쓰지 않는다).
- 정당한 오답이 적어서 직접 확인이 열리지 않았다. 엔진이 우연한 한두 개 오답으로 확정하지 않는 쪽으로 동작했다는 뜻이다.

## 발견 3 — 오류 습관을 규칙으로 준 학습자는 생애주기를 끝까지 지난다

규칙 학습자 두 명을 두었다. 둘 다 처음 두 문항에서 습관대로 고른다(빈칸 바로 옆 문장 · 글 첫 문장).

| 규칙 학습자 | 결과 | 생애주기 4칸 |
|---|---|---|
| habit-then-repair(바로잡기 뒤 근거를 고름) | 두 과제 모두 **resolved** | 확인 ✓ · 바로잡기 ✓ · 적용 ✓ · 다시 확인 ✓ |
| habit-persistent(다시 확인에서도 한 번 더 습관) | 두 과제 모두 **still_needed** | 확인 ✓ · 바로잡기 지금 · 적용 열림 · 다시 확인 지금 |

- 습관 오답 일부는 함정 문장(오답 선지가 비튼 곳)에 걸렸다. 화면은 이를 「매력적인 오답이 바꿔 쓴 곳」 으로 알려 준다(§13 7단계).

## 결론과 다음

- 프로세스(FIND → 직접 확인 → REPAIR → TRANSFER → CHECK → 해소/계속)는 E축 두 과제에서 끝까지 돈다.
- 콘텐츠 품질 점검에서 실제 결함(앵커 ≠ 근거)을 잡았다. 이것이 이번 시뮬레이션의 가장 큰 가치다.
- 효과는 모른다. 실제 학습자의 오류 분포 · 바로잡기 뒤 변화는 실학습자 기록 전까지 UNKNOWN 이다.
- 재실행: export(재실행 안전) → 서브에이전트 답 파일 `answers-*.json` → simulate(재실행 안전, DB 안 씀).
