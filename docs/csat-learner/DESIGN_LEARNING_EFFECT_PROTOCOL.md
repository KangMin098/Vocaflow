# 출제 설계 학습 — 효과 검증 프로토콜(초안 · 2026-10-11)

> 목적: 개선된 해설 극장(설계 설명 · 자기 설명 · 비교)이 **처음 보는 문항에서 근거와 조건을 설명하는 능력**을 내용만 읽는 조건보다
> 더 키우는지 잰다. 실제 학습자 표본이 없으면 효과는 PASS 가 아니다 — 지금 상태는 「기능 검증 진행 중 · 교육 효과 확인 대기」.
> 모집 · 외부 연락은 이 문서로 시작하지 않는다(별도 사용자 지시 필요).

재사용: 효과 판정 `apps/web/src/lib/knowledge/protocol.ts`(사전 · 사후 · 지연 · 전이 단계, 효과 입력 제외 규칙 `effectEligible`),
기록 원장 G2(`learning_task_attempts`), 학습 계약 [G0](./G0_LEARNING_CONTRACT.md), 파일럿 절차 [MAP_PILOT_PROTOCOL](./MAP_PILOT_PROTOCOL.md) §1(동의 · 개인정보) · §4(결측 · 도움).

## 1. 사용성 검증과 교육 효과 검증을 나눈다

| | 사용성 | 교육 효과 |
|---|---|---|
| 질문 | 학습자가 설명 · 강의 · 자기 설명 · 다음 문항에 막힘 없이 닿는가 | 처음 보는 문항의 근거 · 조건 설명이 나아지는가 |
| 표본 | 합성 학습자 가능(역할극 함정 주의) | 실제 학습자만 |
| 지표 | 경로 도달 · 오류 · 이탈 지점 · 키보드 · 저장 실패 회복 | 아래 §3 |
| 판정에 쓰지 않는 것 | — | 풀이 정답률 · 완주율 · 체류시간 · 클릭 수(ICAP: 클릭 ≠ 구성적 활동) |

## 2. 조건

- **A(내용 읽기):** 해설 블록만 — 학습 목표 · 자기 설명 · 비교 숨김.
- **B(설계 학습):** 학습 목표 + 설계 설명 + 자기 설명(선택) + 같은 원리 다른 소재 비교 1문항.
- 같은 학습자가 두 조건을 다른 유형에서 겪는 교차(within) 배치 — 유형 · 순서 균형. 표본 수는 고정 숫자로 정하지 않는다:
  실행 가능 인원과 효과 추정의 신뢰구간 폭을 사전 등록하고, 구간이 0 을 포함하면 「판정 불가」로 남긴다.

## 3. 측정

| 단계 | 과제 | 채점 |
|---|---|---|
| 사전 | 처음 보는 문항 2개 — 정답 근거 위치 + 오답 하나의 바뀐 성분 | 검수된 관계(교수 계약 `answerDesign` · `lureDesign`)로 구조화 응답 채점 · 정당한 대안 허용 |
| 사후(즉시) | 같은 유형 · 다른 소재 2개(가까운 전이) | 동일 |
| 지연(7일) | 다른 유형 · 같은 관계 1개(먼 전이) + 사후 유형 재설명 1개 | 동일 |

- 자유 서술은 자동 의미 채점하지 않는다 — 두 명의 독립 채점(사람) 또는 「채점 불가」로 남긴다.
- **효과 입력에서 빼는 것:** 합성 계정 · 관리자 미리보기 · 이미 본 문항 · 해설 뒤 시도(`viewed_first` · `afterExplanation`) · 같은 문항 설명 후 맞힘.
  해설 극장의 모든 열람은 이제 `viewed_first` 이므로 극장 안의 시도는 구조상 효과 입력이 아니다 — 측정은 극장 밖 과제로만 한다.

## 4. 연구 근거와 적용 한계

| 연구 | 이 설계에 쓴 것 | 한계 |
|---|---|---|
| Chi 외 1989 자기 설명 | 자기 설명 카드(오답 설계를 내 말로) | 물리 예제 · 대학생 — 영어 독해 · 고등학생 효과는 이 측정으로만 확인 |
| Atkinson 외 2003 예제→독립 수행 | 설명 먼저 · 부분 확인 · 비교 적용 | 도움을 줄여 가는 단계(fading)는 아직 구현 안 됨 |
| Chi & Wylie 2014 ICAP | 듣기 · 클릭과 관계 설명 · 비교 결과물을 구분 | 기록 구분은 §10 계측 과제로 남음 |
| Schwartz & Bransford 1998 대조 사례 | 같은 원리 다른 소재 비교 | 비교 쌍 검수 전에는 전이를 주장하지 않는다 |
| Szpunar 외 2013 강의 중 인출 | 강의 사이 짧은 원리 확인 검토 | 원 연구는 긴 강의 — 2~4분 강의에 기계적으로 옮기지 않는다 |

## 5. 시작 전에 필요한 것

1. 비교 문항 연결(M4)과 사전/사후 과제 문항 풀(검수된 관계 포함).
2. `protocol.ts` 에 이 과제 키 · 지표 연결.
3. 실제 학습자 모집 — 사용자 지시 · 동의 절차.
