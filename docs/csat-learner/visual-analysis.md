KEEP: PDF 파이프라인, 서버 공개 분석/RLS, 예측·저장·전이, LecturePlayer/WebSpeechAdapter, 공용 토큰/폰트. MODIFY: 홈 비교 판면, 원리 지도, 분석 읽기 판면. CREATE: 자료 기반 문장 구조도와 선택 상태를 공유하는 시각 컴포넌트. REMOVE CANDIDATE: 대체되는 홈의 화살표/단순 목록 CSS만 참조 검사 후 제거. API/DB/인증은 변경하지 않는다.

## 연구를 적용하는 방법

- [Bret Victor, Explorable Explanations](https://worrydream.com/ExplorableExplanations/): 조작과 설명이 한 문맥에서 반응한다. 근거/오답 선택 시 구조도와 원문·설명을 함께 강조한다. 물리 시뮬레이션 스타일을 복제하지 않는다.
- [Argdown argument maps](https://argdown.org/guide/creating-argument-maps.html): 연결은 명시적 관계가 있을 때만 그린다. 지지/배제와 선택 상태를 구분하고, 가상의 원인·변환 단계를 추가하지 않는다. 그래프 편집기는 필요 없다.
- [Idyll](https://idyll-lang.org/docs): 글과 시각 요소가 동일 상태를 참조하는 방식을 채택한다. 별도 프레임워크 도입 없이 React 상태와 기존 TTS target으로 구현한다.

세 자료를 2026-09-18 확인했다. 이는 설계 근거이며 학습 효과의 실험적 증명은 아니다.

A Editorial: 원문 주석을 강화하나 홈의 구조 부재는 남는다. B Visual system: 관계도만 주도하면 긴 분석의 근거 확인이 어렵다. C Synthesis 선택: 홈은 같은 패턴 두 문항의 앵커·선지 관계를 정렬하고, 분석은 원문과 관계도를 옆에 둔다. 문장/노드 클릭과 TTS가 같은 대상에 초점을 맞춘다.

N1: 실제 기출 문장 길이·앵커·선지 번호가 형태를 결정한다. N2: 로컬 선택 한 번에 두 문항의 대응과 설명이 함께 바뀐다. N3: Dual Coding과 Cognitive Load — 관계와 원문을 멀리 왕복하지 않고 같은 판면에서 확인한다.

Recharts/three/lucide와 기존 Playwright/axe가 있으나 이번 관계는 작은 유향 구조다. CSS+SVG+native button으로 충분하므로 추가 패키지·이미지 생성은 사용하지 않는다. 래스터 그림은 원문 선택이나 TTS와 연결할 수 없어 적합하지 않다.

## 렌더 비평과 수정

1. 1280 홈의 문장 번호·선지 라벨이 작았다 → 번호/선지 글자를 키웠다. `QuestionArchitecture`, `visual-analysis.module.css`. 같은 크기에서 읽고 누를 수 있는지 재캡처한다.
2. 분석 화면의 이동/제목/듣기 영역이 높아 실제 관계가 첫 화면 아래로 밀렸다 → 읽기 모드의 이동과 듣기를 한 행으로 줄이고 판면을 넓혔다. `session.module.css`. 원문과 정답 표현이 동시에 보이는지 확인한다.
3. 여러 근거 문장 중 첫 위치만 선으로 연결하면 관계를 축약해 오해를 만든다 → 모든 실제 앵커 위치를 연결한다. `QuestionArchitecture`. 원문 구절 위치는 `buildDissectionPassage`로 예측/읽기가 공유하며 잘못된 범위는 사용하지 않는다.

첫 SVG title의 분할 텍스트로 발생한 hydration 불일치를 단일 문자열로 수정하고 pageerror 검사를 유지했다. 구조도 텍스트가 SSR에도 남으며 브라우저 렌더로만 우회하지 않는다.

추가 데이터 감사에서 `reject:n` 앵커 중 `from: tempt`가 있음을 확인했다. ID만으로 모두 배제 근거라고 해석하면 틀린다. `tempt`는 「오답 유인」 점선 화살표, `reject`는 「오답 배제」 점선 막대 끝으로 구분한다. 원문 라벨과 설명도 같은 origin을 따른다. 예: 초기 부정문 비교의 2024 31번은 배제, 2026 34번은 유인이다. 이 구별을 브라우저 회귀로 검사한다.

시각 증거: `apps/web/test-results/csat-visual-iteration1/` → `iteration2/` → `iteration3/`. 1280 첫 화면, 1440 전체 홈, 분석·다크 화면을 직접 열어 검토했다. 단순 노드 장식 대신 실제 문장 순서/길이/앵커가 모양을 결정하며, 설명은 관계를 선택했을 때 펼친다. 사람 대상 이해도 실험은 수행하지 않았다.

`csat-visual-final-dev`에서 1280/1440/1728 양방향 선택·키보드·axe·축소 모션 3검사를 통과했다. 1728 홈과 1440 다크 분석을 열어 본 뒤 문장 길이 막대가 다크에서 희미한 점을 발견해 경계색 대신 본문 보조색 80%로 보정했다. 이 마지막 CSS까지 포함된 운영 산출물로 다시 검증한다.
