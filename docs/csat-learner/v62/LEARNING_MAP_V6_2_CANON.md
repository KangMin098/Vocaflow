## 0. 최종 확정 선언

**Domain(영역)** 은 학평·모평·수능 영어의 의미 이해·논리 구성·근거 판단·청취·실전 실행을 만드는 핵심 수행 엔진이다. **TASK** 는 이 엔진에 속한 관찰·교수 가능한 하위 수행 또는 그 결합을 보여주는 통합 관찰이며, 시험 결과와 관련될 수 있지만 **개별 정답·오답으로 자동 측정되는 잠재능력 수치가 아니다.**

**Vocaflow 학습지도** 는 위 교육 구조를 기출 문항의 원문/판단/정답·오답 설계, 학습자의 시험·직접 수행 기록, 목표 시험·점수/등급, 학습방법·교재·Workspace·PLAN 및 플랫폼 지원 공백과 **단일 TASK ID** 로 결속하는 하나의 학습·증거 운영 인터페이스이다.

제품이 설명해야 할 질문은 ① 무엇이 시험에 필요한가? ② 나의 관찰된 수행은 무엇이며 무엇은 모르는가? ③ 왜 이 TASK를 확인/학습해야 하는가? ④ 어떤 출제 원리·교재·방법으로, 얼마나 연습할 것인가? ⑤ 미노출 기출에서 무엇을 독립적으로 수행했는가? ⑥ 다음 요구와 계획은 어떻게 바뀌는가? 이다.

**v6.2가 확정하는 것**: 개념의 경계, 영구 식별자, 불변식, 데이터·평가·교수·목표·화면의 책임, 커버리지 계산의 분모 및 검증 게이트.  
**v6.2가 확정하지 않는 것**: 개별 학생의 미측정 숙달률, TASK별 점수 상승 인과효과, 교수방법의 우열, 21개 후보의 실증적 독립성, 충분히 관찰되지 않은 선수·전이 관계, 실제 학생에게 적정한 총필요 문항 수.

## 1. 연구 근거와 실제 검증 수준

### 1.1 출처의 층위

- **교육·평가 이론:** NRC의 인지–관찰–해석 평가 삼각형, ETS의 학습용 ECD(ECDL; 학생·증거·과제·교수 모델) 등은 구조 설계의 근거이다. 개별 Vocaflow TASK와 학습 효과의 검증 자체는 아니다.
- **기출 분석 제품 자료:** 공개 v3의 의미·판단·출제 설계·오답 비교는 가르칠 내용을 만드는 운영 자산이다. 운영 `verified`는 인간 전문가에 의한 인지진단 타당성 검증을 의미하지 않는다.
- **Codex v1.2 연구:** 프로토콜 동결, 문항 입력 복원, 이중 AI 분류 및 논리 반증으로 **어디까지 주장할 수 있는지** 명시한 연구 자산이다. 독립 학습자 평가 자료는 아니다.
- **학습자 데이터:** 시험기록·독립 첫 수행·노출·도움·전이·지연 응답이 있어야 개인 수준과 변화에 관한 주장으로 이어질 수 있다.

**핵심 작업 모형:** **조건·범위를 보존하는 의미 구성 → 필요한 연결·통합 → 발문 기준으로 후보 비교 → 사용한 정보로 확정 가능한 범위 점검**. 이는 교육적 설명층이지 모든 학습자의 고정된 사고 순서가 아니다. 국소 정보 판별에는 전역 담화 전체 이해가 항상 필요하지 않다.

**평가 과제 분리:** `Answer Identification`(정답 발견에 충분한 경로)과 `Full Option Verification`(실제 모든 선지별 성립/실패 조건 검수)은 다르다. 하나가 다른 하나의 성공 근거가 아니다. `textual_support`, `task_fit`, 실제세계 사실 판단을 분리하고 비교의 문맥·허용 읽기 범위를 기록한다.

### 1.3 근거 수준·승격 계약

| 단계 | 이름 | 교육 모델에서 허용 | 개인 상태에 허용 |
|---|---|---|---|
| R0 | 후보/추론 | 내부 TASK/원리/교수법 조사·표시(후보 라벨) | 불가 |
| R1 | 원문 결속 AI 검토 | 예시·관련성 및 검토 결과의 제한적 근거 | 학생 진단 불가 |
| R2 | 재현·반례를 갖춘 검수 콘텐츠 | 공개 요건 충족 시 교수 설명·학습 자료 | 콘텐츠 검수만으로 학생 상태 변경 불가 |
| R3 | TASK별 채점 과제·루브릭 및 증거 자격 검증 | 독립 관찰 과제 실행 | **실제 유효 응답 범위에 한해** 조건부 관찰 |
| R4 | 반복·다양한 조건·지연 수행 자료와 측정 검증 | 목표 관련 추천 보정의 근거 | 검증된 해석 범위 안에서만 수준/변화 주장 |
| R5 | 비교 연구·실사용 결과로 교수 효과 확인 | 교재·방법의 적합성 보정 | 집단 효과 ≠ 개별 학습자 점수 향상 보장 |

이 단계는 **제품 연구·출시의 상태 머신 제안**이며 현재 전체 TASK가 단계별 요건을 충족한다는 선언이 아니다. 기존 공개 승인·저작권·Reveal/Embargo 관문은 계속 적용한다. AI 역할 분리와 승인 범위는 실제 권한 정책과 일치해야 하며 우회하지 않는다.

## 2. 영역 Domain과 수행 TASK 정본

### 2.1 핵심 엔진

| 코드 | 교육적 기능 | 사용자에게 설명하는 질문 | 핵심 과제 경계 |
|---|---|---|---|
| V | 어휘·표현 의미를 정확히 회상/문맥화 | 이 표현이 **여기에서** 무엇을 뜻하는가? | 어휘 뜻 ≠ 선지의 논리적 타당성 |
| S | 구조·한정·의미 범위로 문장의 명제 구성 | 누가, 무엇을, 어떤 조건에서 말하는가? | 문법 라벨 ≠ 문장 의미 구성 |
| R | 문장 참조·관계·역할·전체 글 의미·추론 | 문장과 문단은 어떤 관계로 글의 의미를 만드는가? | 중심 문장 클릭 ≠ 전체 글의 의미 이해 |
| E | 발문 요구에 맞춘 자료 근거·선지 판단 | 무엇을 묻고, 어떤 근거가 어떤 후보를 지지/배제하는가? | 정답 번호 ≠ 독립 논증/전원 선지 검수 |
| L | 음성/대화의 실시간 의미·정보·응답 판단 | 듣고 무엇을 이해하고 판단했는가? | 읽기 정오로 듣기 실력 판정 금지 |
| X | 제한 시간·순서·막힘·지속 수행의 시험 운영 | 같은 이해를 시간과 상황 제약에서 유지할 수 있는가? | 단순 처리 속도 ≠ 실전 운영 능력 |

V/S/R/E는 핵심 읽기 이해·판단 구조이며 순차 선수 진도가 아니다. L은 현재 보류 중인 별도 청각 입력 수행 모델이고, X는 언어 숙달 능력의 또 다른 합산 축이 아니라 시험 실행 모델이다. K(배경지식), 주제 친숙도, 문항 난도, 형식, 접근 지원, 처리 속도/정확성/안정성은 관찰 **조건·공변 요인**이며 증거 없이 독립 숙달 수치를 만들지 않는다.

### 2.2 영구 ID 30개 목록과 교수·관찰 경계

**현재 계약:** 비보류 21개(원자 수행 후보 18·통합 관찰 3), 보류 9개(L 원자 4·X 원자 4+통합 관찰 1). `V1/R5` 표시는 변경 가능한 표시 순서이며 아래 semantic slug가 영구 ID다.

| 영역 | 표시/영구 ID | 수행 의미 및 경계 | 현행 상태 |
|---|---|---|---|
| V | V1 `v.core_meaning` | 기출 관련 표현의 기본 의미 인출(문맥 답 맞힘과 분리) | 후보, 직접확인 자료 부족 |
| V | V2 `v.contextual_sense` | 문장/문맥에서 정확한 뜻 선택(담화 판단 facet 구별) | 정의 세분 연구 후보 |

### 2.3 TASK와 혼동하면 안 되는 객체

- `QuestionLens`: 문항 유형(B·현행 26개 코드 등); 출제 요구의 관찰 조건이다.
- `ItemFeature`: 오답 함정·근거 구조·본문의 특성(C), 학생 오답 원인이 아니다.
- `LearningBehavior/Context`: 풀이 기록·도움·시간·과거 시험 시점(D/J 일부).
- `InstructionMethod`: 구문 해부, 직독직해, 대조 찾기, 문제 접근 방법(I·교수법 연구). 교육 TASK 대신 학생 숙달 노드로 승격 금지.
- `LegacyLine/Activity`: A/B/C/D/I/J 54라인과 기존 활동 183개(전부 영구 TASK 아님).
- `IntegratedObservation`: S/R/E/X-O1; 구성 TASK의 점수 평균 금지.
- `Principle`: 문항 논리에서 재구성한 조건부 출제 원리. 독립적인 학습자 능력이 아니다.

## 3. 세 그래프의 분리와 단일 학습지도 결속

### G1. 공통 교육 그래프

`Domain → Task`, `Task —PART_OF/SUPPORTS/INTEGRATES_WITH/PREREQUISITE/ALTERNATIVE_PATH/TRANSFERS_TO→ Task`; 34개 기존 관계를 상태 유지하여 읽는다. 기존 approved 14는 구성 정의에 대한 승인이다. 나머지 proposed 또는 연구상 추가 지지는 자동 승인되지 않는다. **동시 출현은 인과 선수 증거가 아니다.**

### G2. 기출 출제·판단 그래프

`ExamBlueprint → ExamItem → Passage/Audio/Table → Proposition/Relation/TaskDemand → EvidenceAnchor → OptionSupport/TaskFit → ReasoningPrinciple`. 이 그래프는 기출의 성립을 설명하며 학생의 머릿속 실제 사고를 기록한 것으로 표현하지 않는다.

### G3. 학습자별 증거·목표 그래프

`Learner → Attempt/Session/Exposure → ValidEvidence → TaskObservation`; 목표 `TargetSpec → GoalRequirement`; 그 둘을 분리 계산해 `NeedRank → Intervention/Workspace/Plan → Activity → new Attempt`로 되돌린다. 공유 문항/노출/동일 시도는 다른 TASK나 Workspace로 독립 증거를 복제하지 않는다.

### 관계 데이터의 최소 계약

`edge_id; from/to; kind; direction; claim; source_item_ids; passage_group; analysis_revision/units_hash; evidence_tier; logic_status; research_status; approval_status; limitations; learner_use_scope; definition_version`.

`direct`=해당 문항 판단에 직접 요구된다는 근거, `indirect`=도울 수 있다는 근거, `not_applicable`=실제 검토 후 무관하다는 근거, `unknown`=미검토/불충분. **AI 후보는 `candidate_relevance`라는 별도 필드**이고 검토된 `relevance`로 자동 복사하지 않는다. 누락 태그를 `not_applicable`로 해석 금지. G2의 직접·간접성은 G3의 숙달/결손과 무관하다.

### v1.2 원장 처리 결정

- 23,580개 조합 중 **검토된 46건**과 자동 후보 6,310건을 서로 다른 컬렉션/상태로 유지한다.
- 110개 bounded 원리의 **문구 검토**와 양쪽 원문 결속 재검증 **0건**을 구별한다.
- 기존 749개 비교쌍은 최초 공개 상태·분석 버전을 보존한다. 다른 유형 원리 17개 후보를 실제 공개 전이 근거로 승격하지 않는다.
- 연구에서 추론·textual_support·관계 판단이 미해결인 부분은 직접 TASK 판정에 사용하는 근거로 올리지 않는다.
- v1.3 독립 연구는 병렬 진행할 수 있지만 v6.2 UI·R5 수직 연결을 전면 차단하지 않는다.

### 예시: 근거에 비추어 문항을 판단할 때

**학습 전이 행동:** 다른 기출에서 동일한 '본문 범위와 후보 범위 비교' 수행을 도움 없이 재구성함.  
셋은 별도의 학습·평가 주장과 응답 기록으로 보존한다.

## 5. 학습자 상태: 관찰·수준·신뢰·전이·실행을 분리

### 5.1 학생에게 공개할 수 있는 최소 상태

| 독립된 차원 | 가능한 표현 | 필수 조건 | 피해야 할 표현 |
|---|---|---|---|
| 시험 결과 | `해당 회차 64점/목표 80점` | 채점·회차·체제 확인 | 다른 시험 원점수 평균=영어 실력 |
| 영역 관찰 | `기출 기록에서 확인 후보` | 해당 시험·문항 매핑의 근거와 신뢰 범위 | `어휘 42% 취약 확정` |
| TASK 직접 관찰 | `미측정/확인 중/해당 조건에서 보완 필요/해당 조건 독립 수행 관찰` | 명시된 직접과제·응답·채점·독립성 | 검증 전 일반 숙달 |
| 수행 깊이 | 의미 정확성/관계 설명/근거·반례 처리 수준 | TASK별 루브릭·독립 검수 | 비검수 공통 0~100 점수 |
| 독립성 | 힌트 후·지도 연습·도움 없음 | 도움·정답 사전 노출 기록 | 접근성 지원 사용을 감점 |
| 적용 범위 | 같은 과제·새 지문·다른 유형·다른 주제 | 본문 동일성·노출 체크·정답 공개 여부 | 새로운 지문 1개=일반 전이 완료 |
| 지연 유지 | `다른 날 재확인 관찰` | 실제 경과 시간·새 과제·독립 수행 | 일정 예약만으로 유지 완료 |
| 학습 진행 | planned/done/remaining | 유효 세션·저장 성공 | 완료율=실력 향상 |
| 플랫폼 준비 | supported/partial/unsupported/unknown | 라이브 자격·권리·자료·루브릭 검사 | 자료 부족=학생 결손 |

`n/k`는 **실제 유효 시도 수/그중 관찰된 성공 수** 등 분모와 정의를 함께 표시한다. 동일 지문에서 여러 후보에 답했다고 독립 n=5로 세지 않는다. 지문·시험·문항·학생 단위의 종속성을 고려한다.

### 5.2 후보 수준 U/S1~S4의 사용 금지선

- `U`=확인 근거 부족. 0점·최저 수준 아님.
- `S1` 지원받은 수행, `S2` 해당 조건의 독립 수행, `S3` 미노출 다른 지문 적용, `S4` 유효한 지연 재확인의 **제안된 증거 진행 단위**.
- **v6.2에서는 이를 학생의 확정 능력등급/숙달 점수로 자동 배정하지 않는다.** 해당 TASK별 도구·루브릭·정성 판정 계약이 R3 수준으로 검증되면 그 수행 조건의 관찰 상태로 활성화 가능하다.
- 실행 수는 레벨이 아니다. 서로 다른 난도·주제의 수행을 동일 척도로 평균하지 않는다. IRT/CDM/베이지안 숙달 추정은 실사용 반응·문항 특성·측정 적합성 검증 후 별도 도입한다.

### 5.3 증거 자격 체크

`record_quality ∧ eligible_item ∧ source_binding ∧ rubric_valid ∧ first_independent_attempt ∧ no_answer_hint ∧ not_pre_exposed ∧ answered_at_valid ∧ task_specific_response`를 모두 확인한 범위에서만 독립 TASK 수행으로 사용할 수 있다. 접근 보조는 정답 제공과 구별하고 평가하는 기능에 대한 영향만 기록한다. 합성 계정 E2E는 프로덕트 동작 검증에만 사용한다. 학생 전체 통계의 실측 성공과 합치지 않는다.

기존 `verified_need`는 **직접 확인된 학습 요구**, `resolved`는 **현재 운영 정책을 통과한 상태**다. 곧바로 v6.2 일반 숙달·S4·지연 유지로 바꾸지 않는다. 목표 변경·활동 체크·원리/관계 추가·교재 공개·전이 1회만으로 학생 능력을 올리지 않는다.

## 6. 목표(Outcome/Competency/Learning)와 필요 학습

### 6.1 세 층의 목표

1. **Exam Outcome:** 목표 시험 종류/회차/형/시점과 점수·등급·목표일까지. 시험 종류별 배점·등급 정책·상호 비교 가능성 확인.
2. **Competency Criterion:** 해당 TASK에서 **어떤 수행을 어떤 본문·난도·도움·전이 조건에서** 보일 수 있어야 하는지. 시험 점수에서 역산한 TASK별 백분율이 아니다.
3. **Learning Plan:** 지금 학생에게 실제로 배정할 교재·활동·전이·확인 과제와 가용 시간·버전.

`TargetSpec = { examScope, score?, grade?, targetDate?, personalFocus?, timeBudget?, definitionVersion, goalVersion }` 논리 계약. 기존 main의 `ToBeGoal {score,set}`, 점수-only 목표 RPC는 호환 입력으로 유지한다. **현재 DB의 `target_score NOT NULL`과 목표 종류 범위 제한상 등급-only, 단일 회차·형, 복수 범위·시간 예산의 영속화는 구현 전 DB/API 감사 및 필요 시 승인 대상**이다. 저장되지 않는 필드는 `저장된 목표`로 보이지 않는다. 목표 없이 기출/TASK 탐색·자율 연습 허용.

### 6.2 목표 관련성(Relevance)과 학습 요구(Need)의 차이

1. `ExamBlueprint`의 시험 체제·전체 문항을 신뢰 가능한 독립 답안표/메타데이터와 대조한다.
2. 각 문항의 실제 수행 요구와 TASK 사이의 **검토된** 직접/간접 링크를 모은다. `unknown`을 교육적으로 `not_applicable`로 처리하지 않는다.
3. 기존 `splitMust`는 목표 점수에 따른 **시험 수행 전략용 문항 관련도**로 보존한다. `splitMust=0`이라서 TASK가 불필요하다는 뜻으로 확대하지 않는다.
4. 학생의 현재 증거 상태와 목표 수행 조건을 비교한다. 기록이 없거나 관련성 검토가 부족하면 결손 확정 대신 `확인 필요/판단 보류`.
5. `NeedRank`로 확인·보완·통합·전이·유지 요청의 교육적 중요도를 정한다. 근거/우선순위가 불안정하면 동급 후보와 구별 과제를 제공한다.
6. `ActionRank`는 콘텐츠 자격·학습자 선택·현재 계획과 연결하여 지금 가능한 행동을 고른다. 미가용 TASK를 필요 목록에서 삭제하지 않는다.

**NeedRank 최소 입력:** validated relevance/unknown, 목표 수행 조건, 직접 수행 근거·유효성, 과거 작업·학습자 선택, 관계의 검증 수준.  
**ActionRank 최소 입력:** NeedRank, 공개/권리/원문 결속/미노출/phase eligibility, 실행 가능한 Workspace, 시간 예산, 기존 계속하기.  
**정렬 금지:** 추정 점수 상승, 실증 없는 TASK 가중합 0~100, 미검증 관계의 선수 강제, 교수 자료 수량만으로 교육 필요 순위 변경.

### 6.3 정성 조건·정량 계획의 정확한 정의

| 구분 | 학생에게 표시할 예 | 계산 근거 | 해석 제한 |
|---|---|---|---|
| 현재 시험→목표 차이 | `최근 유효 회차 64점 / 목표 80점` | 해당 시험 점수·목표 정의 | 향후 회차 예측 아님 |
| TASK 현재 증거 | `새 문항에서 근거를 설명한 유효 2회` | 직접 수행·루브릭 | 독립 일반 숙달 아님 |
| 목표 수행 기준 | `안 본 글에서 중심 주장·근거·조건 설명` | TASK별 승인된 평가 명세 | 점수 목표에서 자동 역산 금지 |
| 콘텐츠 가용량 | `독립 확인 가능 3문항` | 공개·권리·노출·난도/역할 검수 후 | 개인 필요량 아님 |
| 이번 계획량 | `이번 주 다른 기출 2개 분석` | 사용자가 조정한 실행 계획과 유효 재고 | 목표 달성 보장치 아님 |
| 실제 실행량 | `배정 2개 중 수행 1개` | 실제 저장된 시도 | 숙달률 50% 아님 |
| 아직 충족되지 않은 조건 | `다른 주제 미노출 지문 재확인 필요` | 판정·전이·지연 정책 | 문항 개수 자동 추정 금지 |
| 효과·예상 총필요량 | `근거 미확보` | 실제 학습량-성과의 검증 모델 필요 | 임의 예측 금지 |

### 6.4 시험기록 비교의 제한

평가원/교육청/구 체제 A·B형을 하나의 원점수 성장선으로 평균하지 않는다. 같은 시험 유형이라도 회차 난도·시간·원문 완전성 차이는 조건으로 기록한다. 기출 분석 없이 문항 번호만 알고 TASK별 수준을 계산하지 않는다.

## 7. 교수방법·교재 적합성·Workspace

### 7.1 `InterventionUnit` 최소 계약

`id; task_ids(core/support); exam_item_refs; source_revision; learning_objective; method_id; method_claim; applicability_conditions; learner_prerequisite_observations; instructional_role; material_type; expected_response; rubric_ref; hint_scaffold; difficulty_dimensions; relation/principle_ref; exposure_policy; copyright/embargo/reveal_status; version; validation_tier; effectiveness_status; available_pool/estimated_time_basis`.

`instructional_role`은 `source_analysis / model_explanation / guided_practice / independent_check / transfer / delayed_check`를 분리한다. 같은 문항이라도 역할은 다를 수 있지만 **동일 학습자에게 학습/노출한 기출을 미노출 독립 확인으로 다시 배정하지 않는다.**

### 7.2 교수 방법 선택의 원칙

- `방법 관련성`: TASK 수행을 실제로 다루는가?
- `오류·지원의 적합성`: 학생에게 확인된 어려움/미확인 대안에 맞는가? 확인 전에는 선택적 연습 후보.
- `자료 적합성`: 원문·제시형/각주·정답·오답 해부, 난도·주제·권리·공개·노출 조건이 맞는가?
- `검증 가능성`: 학생의 산출물과 새 지문 확인 과제를 얻을 수 있는가?
- `학습 효율`: 실사용 데이터 전에는 학습자별 최선·소요 시간 단정 금지.

| 중심 TASK | 지도 학습용 기출 해부 | 연습 방법 후보 | 직접 확인·전이 설계 |
|---|---|---|---|
| V2 문맥 의미 | 다의어의 실제 문장·주변 맥락, 각주 | 다른 문맥 대비·의미 선택 이유 | 새로운 문장 의미·근거 제시 |
| S5 의미 범위 | 조건·부정·양화·비교·지시 대상 | 최소대립쌍/명제 재구성 | 새 구조에서 정확한 조건·대안 설명 |
| R5 중심 의미 | 핵심 명제·지지/부연·글 구조, 단일 문장 과대 일반화 반례 | 요지 생성·주장/근거 구별·반례 | 선지 없이 새 글의 핵심과 조건 설명 |
| E3 선지 대응 | 본문과 모든 후보의 textual support/task fit, 조건·강도·주체 | 본문↔선지 대조·배제 이유 생성 | 새로운 기출에 정답 탐지와 전체 선지 검수 구별 |

**교수 순서의 성격:** `FIND → REPAIR → TRANSFER → CHECK`는 기존 실행 상태 머신. REPAIR 내부에 원문 의미·출제 설계 조건·모델 설명·자기 설명·반례·지원 감소를 배치한다. 모든 학생에게 동일한 시간/진도를 강제하지 않는다. 즉시 CHECK와 진정한 지연 확인은 별도 기록·증거 자격. 기출 분석 자료는 설명과 판단의 주축이며 단순 해설 링크에 숨기지 않는다.

## 8. 목표 지원 커버리지 — 6 Ledger와 8 공백

### 8.1 서로 다른 분모의 Ledger

| Ledger | 분모 | 분자·완료 근거 | 피해야 할 계산 |
|---|---|---|---|
| **ExamInventoryCoverage** | 대상 시험의 정본 전체 문항/배점(시험·회차·형별) | 답안표/메타데이터/실제 문항 카탈로그 결속 | '읽기 28문항'을 자동 전체 45로 보지 않음 |
| **ReasoningCoverage** | 분석 대상의 필수 문항·발문·후보/원문 요소 | 실제 검수된 의미·정답·오답·근거·불확실성 | 항목 1개 있으면 전 문항 완전 분석 처리 |
| **TaskLinkCoverage** | 목표 시험 문항과 **범위가 확인된 관련성 주장** | 실제 원문 결속·검토된 직접/간접 링크; unknown 별도 | 786×30 전체 조합을 모두 필수 링크로 보지 않음 |
| **InstructionCoverage** | 시험과 관련된 TASK별 요구 교수·교재 역할 | 출제 원리·설명·지도 연습·공개·권리·실행 가능한 Unit | 문항수=교재량/효과로 대체 |
| **AssessmentCoverage** | 측정하고자 주장하는 TASK×조건/응답 유형 | 유효 확인 과제·루브릭·채점·독립성/노출 검증 | static `live`=학생 능력 검증 완료 |
| **GoalSupportCoverage** | TargetSpec의 필수 시험 범위 및 관련 TASK·지원 조건 | 위 5개 Ledger와 전이/재확인/실행의 단계별 지원 | 플랫폼 지원율=점수/숙달 확률 |

서로 다른 학년도/기관/형의 분모를 **독립적으로** 검증한다. 같은 문항에 여러 TASK가 연결되어도 원문 문항수/배점을 중복 합산하지 않는다. 실제 전체 시험 모형이 모호하면 denominator=null, status=`unknown`이지 0 또는 완료 100%가 아니다. 현행 2026 수능의 독해 28문항과 전체 45문항/100점 혼동은 명시적인 실패 테스트다.

### 8.2 8개 지원 공백

| 공백 코드 | 누락 의미 | 복원 방법 |
|---|---|---|
| `CONCEPT_GAP` | TASK 정의·실제 관련 기출/원리 결속 부족 | 정의/원문 검토/반례 |
| `ASSESSMENT_GAP` | 직접 확인 문항·루브릭·채점 증거 부족 | 검사 과제 제작·품질 검수 |
| `LEVEL_GAP` | 목표/현재 수준을 해석할 조건·정책 부족 | 판단 기준·해석 검증 |
| `METHOD_GAP` | 실제 수행을 다루는 교수법 부재/검토 부족 | 교수 방법·적용 조건 연구 |
| `CONTENT_GAP` | 적격 교재·원문·권리·활성 자료 부족 | 콘텐츠 제작·검수·공개 |
| `EXECUTION_GAP` | Workspace·실행·응답 저장 미지원 | 실제 제품 수직 E2E |
| `TRANSFER_GAP` | 새로운 과제/주제/유형에서 적용할 풀 부족 | 학생별 미노출·콘텐츠 검수 |
| `VERIFICATION_GAP` | 독립/지연 수행 확인 또는 재계산 부족 | 관찰 정책·재확인 콘텐츠·측정 |

지원 단계마다 `supported / partial / unsupported / unknown`, `evidence_source`, `claim_scope`, `version`, `as_of`, `rights`, `readiness`, `learner_exposure`를 기록한다. `unknown`=조회·검수 미실시이고 `unsupported`=확인된 미지원이다. 해당 TASK의 지원 공백은 학생의 실패가 아니다. **연구 미검증·콘텐츠 미공개·제품 미실행·실제 학생 학습 효과 미측정** 역시 서로 다른 상태로 기록한다.

### 8.3 실측 상태의 바른 표시

현재 연구 `coverage.json`의 첫 6개 지원축 `partial` 및 전이/지연 실증 `unsupported`는 **연구 산출물의 검사 범위**다. 제품 R5의 합성 E2E가 존재한 사실과 모순되지 않는다. 제품 실행 경로의 가용성은 새 제품 실측 검사로 별도 입증하고, 실제 학생의 성공 여부는 학생 수행 관찰로 입증한다.

## 9. 단일 화면 UX·상태 계약

### 9.1 하나의 학습지도, 여러 진입 주소

- **정규 전체 주소** `/csat/diagnosis?tab=map&view=full`.
- 기존 `/csat/diagnosis?tab=map` / `view=core`는 동일한 `UnifiedLearningMap`으로 정규화하되 `asof`, `focus`, `record/modal`, TASK/Workspace/계획 복귀 키/해시를 보존한다.
- `/csat`는 PR #239·#240 이후 **지도 중심 홈**이다. 이 홈도 동일한 `UnifiedLearningMap` 계산·교육 구조를 재사용하고 별도 `LearnerMap` 판정 엔진으로 두 번째 지도를 만들지 않는다. 진입 동선은 v3의 두 메뉴/기출 탐구·문항 복귀 계약을 보존한다.
- `MapScreen`에서 `LearnerMap` vs `LearningMap`의 두 지도를 그리는 분기를 제거한다. `view=full`은 **동일 그래프의 전체 표현**이며 다른 교육 분류·판정을 뜻하지 않는다.

### 9.2 화면의 3영역

1. **상단 목표·기록**: 시험 종류/범위·목표 점수/등급(저장된 값만)·기준 시점; `전체 기록 N / 진단 활용 M / 제외 사유`. 기록 2·활용 0을 '기록 없음'으로 보이지 않는다.
2. **관계도 캔버스**: V/S/R/E 중심, L과 X 동일 지도에서 구조·준비도 확인; TASK 간 구성·지원·통합/제안 연결. 영역과 TASK는 탐색 가능, 우선 TASK는 강조하지만 나머지는 잠금 금지. 선택 이전 전체 6영역과 TASK의 위치/전체 목록에 접근할 수 있어야 한다.
3. **TASK Inspector**: 상단 고정 `TASK 이름 + 한 가지 다음 행동`, 아래에 `현재와 목표 / 기출과 출제 논리 / 교재·학습·계획 / 결과와 개선`. 같은 데이터를 다른 탭·별도 아래쪽 대시보드에 반복하지 않는다. `GoalCoveragePanel`은 접을 수 있는 지원공백 보기.

**1440px 기하:** 레일 접힘 64px, 화면 안쪽 여백·Inspector 340~380px·간격을 확보하면 **6열 × 206px=1236px을 상시 나열할 수 없다.** 그러므로 첫 시야는 **6영역 전체 개요와 관련 TASK 탐색 표식**을 유지하고, 영역 초점에서 선택 영역의 TASK 관계를 확장하는 **같은 캔버스의 상태**로 구현한다. 30개 노드는 검색·키보드·전체 펼침 선택으로 모두 접근 가능해야 한다. 이 개요는 별도의 두 번째 학습지도가 아니다. 그래프 내부만 스크롤하고 페이지 전체 가로 넘침은 금지. 1280/1440 실화면에서 실제 배치 판단.

**관계선:** 평소 희미하게, 선택된 TASK의 직접 구성·승인 관계만 강조. proposed는 점선 및 '연결 연구 중'. 순서도식 강제 선수 화살표 금지. 통합관찰은 원자 TASK와 스타일·상태를 구분. 수치는 Inspector에만. 지도 포커스·선택·계획 편집·스크롤은 학습 실행 이후 복원.

### 9.3 실제 행동과 복귀

선택 → 기출 근거/원리 확인 → Workspace 계획·활동 → FIND(독립) → REPAIR(설명·자기 설명) → TRANSFER(미노출) → CHECK(별도 독립 확인) → **동일 TASK의 지도**. `TaskInspector`, `/csat` 첫 행동, 학습자 문항 복귀, 서버 로깅은 기존 `decideStep` 및 `composeV4`의 승인된 단일 출처를 사용한다.

- 기존 `task`(활동 ID/일부 TASK slug)와 새 `map_task`(영구 TASK ID)를 구별한다. `map_task`는 정의에 존재하는 ID만 수용.
- `ws` 템플릿 slug와 학습자 `map_workspace_id` UUID를 구별. `map_plan_version`, `map_goal_version`은 UUID·사용자 소유권·계획 행의 목표 버전과 정확히 결속한다.
- 학습자에게 이전 계획으로 복귀한 사실과 현재 최신 계획으로 전환할 수 있음을 명시. 종료 후 같은 템플릿 재생성 시 과거 UUID 버전을 잘못 복원하지 않는다.
- 다른 학생의 계획 UUID 조회·조합 쿼리 조작은 거절. `asof` 과거 기준은 읽기 전용이고 현재 학습 시도를 과거 지도에 저장하지 않는다.
- 저장 실패 시 사용자가 작성한 초안/응답을 보존, 서버 저장 성공 전에 완료 표시 금지. 이전 탭·Workspace의 늦은 응답이 현재 선택을 바꾸지 못한다.

## 10. 데이터·API 및 버전 정합성

### 10.1 단일 계산 계약

`UnifiedMapView = composeV4(asIs, toBe, workspace, plan) + DomainTaskGraph/ReasoningReferences + GoalCoverageLedger + TaskEvidenceProfile + TargetSpec(확장 가능성)`.

- 기존 `composeV4`의 As-Is/To-Be·Workspace·PLAN 계산은 한 출처. 별도 UI 구성요소가 독립 재계산해서 다른 상태를 내지 않는다.
- `lib/knowledge/learning-decision.ts`의 `decideStep`은 StepSheet/서버 기록과 같은 원리·확인·과제·방법·버전을 사용. Adapter로 공유하며 임의 새 처방 생성 금지.
- `NeedRank`/`ActionRank`/coverage는 별도 책임의 순수 계산; 연구 후보와 검증 관계를 혼합하지 않는다.
- 화면·계획 저장 API는 동일 목표 범위/정의 버전/as_of/evidence 정책/계획 서명을 사용한다. 프런트의 가용량·진단 자격을 서버에서 신뢰하지 않는다.

### 10.3 저장 멱등성·경합 필수 규칙

동일한 `(사용자, workspace UUID, mutation ID, 요청 본문 서명)`은 첫 저장 결과를 재사용한다. 동일 ID의 다른 본문은 충돌. 이미 성공한 재시도는 **신규 요청의 달라진 목표/재고 검사로 거절하지 않는다**. 최초 신규 저장은 최신 권한·목표·계획 버전·콘텐츠 상태를 검증한다. 이 구분은 서버/DB의 원자적 계약 및 읽기 권한을 필요로 한다. 미지원이면 구현 완료 표시하지 말고 DB 변경 승인 절차로 보낸다.

### 10.4 버전·이관

- 교육 정본 `canon_version`: 이전 rev2.1/rev4 기록과 v6.2 설명 버전을 구분.
- 연구 출처 `research_protocol/version`, 원문 `source_revision/presentation_sha`, 기출 분석 `analysis_version/units_hash`, 평가 `rubric_version/evidence_policy_version`, 목표 `goal_version`, 계획 `(workspace_id, plan_version)`, 학습 이벤트 `timestamp/attempt_id`를 명확히 구분.
- 정의나 판정 변경은 과거 결론의 원본을 덮어쓰기보다 버전별 재분석으로 남긴다. 기존 판단에 새로운 의미를 소급 이식하지 않는다.
- DB 마이그레이션/RPC/RLS/기존 데이터 삭제는 영향 분석·체크포인트·복구 계획과 명시적 승인 필요. 연구 보고서·앱 코드·DB 기록을 한 단계에서 무단 동기화하지 않는다.

## 12. 검증 게이트: 명시적인 재현·반례·인수 기준

### 12.1 교육·연구 게이트

- R5·E3·V2·S5의 TASK별 **인지 목표/관찰 과제/해석 루브릭/교수 유닛**을 분리하여 추적; 원자/통합 관찰 상태 혼합 금지.
- 기출↔TASK 관련성은 직접/간접/무관/unknown, 연구 후보/실검토, 증거 버전으로 대조.
- AI/FOV 정답·다섯 후보 검수의 필요 정보 범위와 논리적 결함을 구별.
- 연구 프로토콜 v1.2 실패 축을 사후 수치 조정으로 PASS로 만들지 않는다. 실제 원리 재현·독립 검증을 입증한 범위만 승격.
- 교수효과 없는 전략은 '교육적 후보'로 표시, 추천 우열을 효과로 주장하지 않는다.

### 12.2 MAP·개인화 게이트

- 기록 0, 기록 2/활용 0, 목표 없음/변경, 과거 재분석, 사용자 선택 TASK, 학생/자료 미지원, 오류·조회 실패를 개별 확인.
- 같은 응답/공유지문·도움·해설 노출을 독립 TASK 증거로 이중 계수하지 않는다.
- `verified_need`는 요구, `resolved`는 현재 운영 해소. R5 확인/보완/전이/재확인 실측 및 합성 시나리오의 실패/성공 판정 모두 일관.
- 개인 수준·신뢰도·적합도·점수예상 `n%`는 검증 없이 생성 금지; 관찰된 `k/n`과 이번 계획 `done/planned`는 서로 다른 수치로 구분.
- 필요한 교육 TASK가 콘텐츠 미지원이라는 이유로 NeedRank에서 조용히 삭제되지 않는다.

### 12.3 Goal Coverage·시험 분모 게이트

- 블루프린트는 실제 시험 전체 inventory/독립 답안표와 회차·형·배점을 대조. missing/duplicate/score mismatch는 완전 지원 차단.
- 2026 수능 등 전체 45문항/100점 체제에 대해 읽기 28문항/63점만 갖춘 카탈로그를 전체 100%로 표시하지 않는다(다른 체제에는 독립 메타데이터 적용).
- 다중 TASK 연결로 문항수/배점 중복 집계 금지. 23,580 unknown과 연구 자동 후보를 검증된 매핑으로 계산하지 않는다.
- 연구적 `unsupported`, 제품 기능 미구현, 학생별 미노출 재고 0, 학습 효과 미측정을 서로 다른 차원으로 보고한다.

### 12.4 UX·기능·보안 게이트

- `/csat`, `?tab=map`, `?tab=map&view=full`에 **독립 능력 지도/판정 엔진이 2개 이상 존재하지 않음**. 30 TASK ID 접근 가능, 전역 레일/기출 탐구 복귀 유지.
- 1280/1440 PC × 레일 펼침/접힘; 스크롤·키보드 포커스·44px 목표·대비·오버플로·모달·URL 선택 복원; 필요하면 실제 디자인 `ref-compare`.
- MAP↔PLAN↔Workspace의 목표·근거·설명·활동 URL·버전 일치, plan edit/초안/저장 오류·느린 응답/중복 mutation 보존.
- 본인 UUID만 계획/목표 버전 조회, 종료 Workspace와 재생성 Workspace 분리, 오래된 링크·과거 `asof`의 읽기 전용 확인.
- 공개·저작권·Embargo/Reveal·원문 해시·근거 앵커·TTS/PDF 회귀; 민감한 노트/원문/사용자 ID는 분석 이벤트에서 제외.
- 실제 브라우저·DB E2E의 `PASS`와 로컬 HTML 시안·합성 계정·실제 학생 학습효과의 `PASS`를 각각 구분.

### 12.5 완료 표현의 제한

- `DESIGN_CLOSED`: 교육·제품 **목표 계약**이 확정되어 구현 가능한 상태.
- `PRODUCT_INTEGRATED`: 위 UI·판정·PLAN/Workspace·안전 게이트를 실제 제품에서 통과.
- `SUPPORT_COVERED`: 해당 목표·TASK·단계별 콘텐츠·평가·전이가 증거와 함께 지원됨. **전체 목표**는 모든 필수 하위 범위가 충족될 때만.
- `LEARNING_EFFECT_VALIDATED`: 실제 학습자·적절한 독립/지연 과제·설계/표본을 사용한 별도 결과가 있음.

서로 다른 완료 기준을 합쳐 '학습지도 완성, 전 학생의 학습 향상 입증'이라고 하지 않는다.
