# V2-F1 — 뜻 선택지가 판별 정답을 드러내는 결함(F1) 해결

> 기준 main `9c19f15b1`(#276 병합). PR #276 의 비활성 instrument 수용(ACCEPT_WITH_LIMITS)은 그대로 두고, PR #278 파일럿 12문항이 찾은 F1 · F2 · F5 · F6 를 고친다.
> 합의 주석은 0개, 출시는 0행이다. 이 변경으로 V2 를 열지 않는다. DB · RPC · RLS · `knowledge_applications` 는 바꾸지 않았다.
> **Codex 독립 수용 전에는 출시 가능한 V2 instrument 라고 하지 않는다.**

## 1. 결함 재현

- 수정 전 `contextualSensePanel` 은 서버 props 로 `senseOptions` 를 내려보냈다. 그래서 「직접 확인하기」를 누르기 전부터 RSC payload 에 있었고, 열면 DOM 에 있었다. 화면에서 버튼을 잠가도 DOM · 네트워크로 읽을 수 있었다.
- PR #278 파일럿 12/12 문항에서 오답 뜻 하나가 「밑줄 낱말 자체의 뜻」이다. 선택지만 보고 다섯 밑줄 중 어느 것의 뜻을 묻는지 알 수 있다 → B(판별) 정답 단서.
- 이 상태로 기록된 첫 시도는 「혼자 판별했다」는 증거가 될 수 없다. 측정 자체가 무효다.

## 2. 설계안 비교

| 안 | 내용 | 무결성 | 필요한 것 | 판정 |
|---|---|---|---|---|
| A | 서버가 B 를 먼저 확정(중간 제출) → D 제시 → 둘 다 기록 | 높음 | 같은 문항 두 단계 기록 = 새 phase 또는 중간 제출 RPC. 승인 대상 | 보류(승인 필요) |
| B | B 를 드러내지 않는 다른 뜻 선택지 구조(다섯 자리 모두 선택지 · 낱말 자체 뜻 제외) | 중간 | 주석 재작성 · 5배 선택지. 낱말 뜻을 빼면 D 가 더 쉬워진다(F2 악화) | 기각 |
| **C** | **B 판별(+C 근거)을 확인 기록으로, D 를 제출 뒤 지도 연습으로 분리** | 높음(제출 전 단서 0) | 기존 G2 writer 한 번 · 새 phase/RPC 없음 | **선택** |
| D | 지금 B+D 구조는 지도 연습으로만, 독립 확인 instrument 는 따로 설계 | 높음 | 독립 확인 도구가 없어진다 | C 가 같은 효과 + 독립 확인 B 를 남김 |

**선택한 C 의 동작**
- 제출 전 화면 모양(`panel`) = 문장 수 · 밑줄 문장 번호 · 밑줄 표지 · 근거 채점 여부. 뜻 선택지 · 정답 · 배제 이유는 없다.
- 첫 제출 `{ misfit, cue }` 를 기존 `/api/csat/item/{slug}/task` → G2 writer 로 한 번 기록한다. `sense` 를 섞어 보내면 `invalid_input` 이다.
- 정오(`isCorrect`)는 B 판별뿐이다. 근거(C)는 검수된 경우만 채점하고 따로 보고한다.
- 채점 응답 `followUp` 은 **B 를 맞혔을 때만** 뜻 선택지와 정답 번호를 담는다. B 를 틀리면 `null` 이다. 선택지가 정답 단서이기 때문이다.
- 화면은 저장이 확인된(`inserted` / `duplicate`) 뒤에만 뜻 연습을 보인다. 그때 B · 근거 버튼은 잠겨 있다. 뜻 선택은 서버에 보내지 않고 원장에도 쓰지 않는다.
- 클라이언트 `savedGrade` 는 「B 오답 + 선택지」 응답을 버린다(완료 아님 · 단서 미표시).

## 4. F2 · F5 · F6

- **F2(D = 반의 · 극성)** — 이 PR 은 **F2 를 해결하지 않는다.** Codex Stage 2(봉인 커밋 `9ec2b9c3b`)가 12/12 를 재설계 대상으로 판정했다. 후속 명세: [V2_F2_FOLLOWUP_SPEC](./V2_F2_FOLLOWUP_SPEC.md). 이 PR 에서는 D 가 이제 평가가 아니라 지도 연습이다. 계약상 D 는 「극성 확인 연습」이고, V2 문맥 뜻 생성 · 독립 문맥 추론의 근거로 쓰지 않는다. 같은 극성 근접 뜻을 오답으로 넣는 재설계는 D 를 다시 평가로 쓸 때의 과제다.
- **F5**: 주석 `markerStyle: 'circled' | 'letter'` 를 추가했고 출시 필수다. 화면은 `markers` 로 표지를 그린다.
- 독립 수용 보완: 서버 원문 관문에서 현재 `type_id`와 `markerStyle`도 대조한다. X-VOCAB=circled 또는 R-VOCAB=letter 주석은 노출·제출을 닫는다(최초 실패 보존).
- **F6**: 주석 `construct: 'lexical_sense' | 'sentence_logic'` 를 추가했다. `sentence_logic` 이나 미분류는 출시 자격이 없다. 이런 문항을 V2/S5 혼합 근거로 자동 사용하지 않는다.

## 5. 측정 주장의 변화

| 이전(#276) | 이후 |
|---|---|
| 조건 성공 = B + D | 조건 성공 = **B 판별** |
| D 는 확인 기록의 일부 | D 는 기록하지 않는 제출 뒤 연습 |
| 표지 ①~⑤ 고정 | 유형별 표지 |

B 는 공식 정답이 공개된 문항이라 정답을 아는 학습자도 맞힐 수 있다. 그래서 극장 열람 · 해설 선노출은 T4 계약에 따라 독립 확인으로 세지 않는다. 그래도 B 성공은 「이 문항의 판별 조건 충족」이지 V2 숙달 · 전이가 아니다.

## 6. 기존 주석 revision 영향

- 저장소의 합의 주석은 0개라 깨지는 출시 자료가 없다.
- PR #278 의 DRAFT 12건은 `validAnnotation` 을 그대로 통과한다(새 필드는 선택). 출시 전에는 `markerStyle` · `construct` 를 채워야 한다. 그러면 주석 JSON 이 바뀌어 `contextualSenseHash`(content_hash)가 새 값이 된다 → 맹검 첫 제출 해시 원장과 별도로 **주석 revision 을 올려야 한다**.
- PR #278 의 맹검 입력 · 비공개 초안 · 검수 결과는 수정하지 않았다(읽기만 함).
- 맹검 2단계(뜻 선택지)의 의미가 바뀐다. D 는 이제 평가가 아니다. D 일치율은 연습 선택지 품질 검수로만 쓰고, 출시 판정의 핵심 일치는 B(공개 정답이라 독립성 증거 아님) · C 근거로 본다 — #278 BLIND_REVIEW 에 반영할 결정이다(이 PR 밖).

## 7. 서버 측 무결성 — 해결한 것과 남은 위험

**해결한 것(서버 단)**
- 제출 전 정답 단서: 서버 props 에 뜻 선택지가 없다. 프런트 잠금이 아니라 **내용 자체를 보내지 않는다.**
- 뜻 선택(D)은 서버로 가지 않고 원장에 쓰이지 않는다. D 공개 뒤 B 를 바꿔 다시 보내도 그것은 같은 문항의 반복 시도다(새 행 · 첫 시도 아님 · T4 「반복 = 독립 관찰 아님」).
- B 를 틀린 응답에는 선택지가 없다(서버 `grade` 단계).

**남은 위험(이번 PR 로 해결 안 됨 · DB 변경 필요 → 승인 대상)**
- R1 **첫 시도 선정이 클라이언트 시각 기준이다.** `learning_first_attempts` 뷰는 `answered_at` 오름차순으로 첫 시도를 고른다. `parseClientMeta` 는 과거 30일까지 시각을 받는다.
  - 그래서 B 를 틀렸다는 결과를 본 뒤 재시도에 더 이른 `answeredAt` 을 넣어 보내면, 그 재시도가 「첫 독립 시도」로 선정될 수 있다.
  - R5 확인 과제에도 있는 기존 위험이며 F1 수정과 무관하게 남는다.
  - 최소 대안: 첫 시도 선정을 서버 수신 순서(`received_at` · `id`)로 바꾸거나, 이미 기록이 있는 (사용자 · 과제 · 문항 · 단계)에 더 이른 `answered_at` 이 오면 `timing_uncertain` 으로 보류한다. 뷰 · RPC 변경이므로 SQL 은 쓰지 않았고 적용하지 않았다.
- R2 B 는 공식 정답이 공개된 문항이다. 극장 열람(`viewed_first`) · 해설 열람은 T4 계약대로 독립에서 빠지지만, 외부에서 정답을 본 것은 기록되지 않는다. 그래서 B 성공은 「판별 조건 충족」 관찰까지만이다.
- R3 `followUp` 은 D 정답 번호를 응답에 담는다. D 가 연습인 지금은 문제가 없지만, 나중에 D 를 평가로 되돌리면 이 응답을 바꿔야 한다(F2 후속).

따라서 이번 PR 의 주장은 **「B 판단 전 정답 단서 노출 제거」** 까지다. 독립 평가 무결성 전체(R1)는 해결됐다고 하지 않는다.
