# 학습지도 v6.2 — P-M2 학습 경로 · 복귀 · 계획 안정성 기록

> 정본 §9.3 · §10.3 · 실측 2026-10-14 개발 서버 · 개발 DB. **합성 계정 E2E 는 제품 흐름 검증이며 학습 효과의 증거가 아니다.** DB · RLS · RPC 변경 0.

## 1. 계약 대조 → 구현

| # | 계약 | 결과 |
|---|---|---|
| 1 | `map_task`(영구 TASK) ↔ 활동 `task` 구분 | 복귀 문맥 별도 키. 계획 「활동 시작」 링크도 이제 `map_task` 를 싣는다 |
| 2 | 같은 TASK · 묶음 · 단계로 복귀 | 문항 → 「학습 지도로」 → 홈 지도에서 같은 TASK 선택 · 같은 묶음 계획 열림(E2E ②) |
| 3 | 학습자 Workspace UUID ↔ 템플릿 구분 | `map_ws`(UUID) 를 `ws`(템플릿) 와 따로 싣는다. 돌아왔을 때 지금 열린 Workspace 와 다르면 「다른 계획」 알림 · 옛 것을 되살리지 않음(E2E ⑤) |
| 4 | 떠날 때 계획 · 목표 버전 ↔ 지금 최신 | `map_plan` · `map_goal` 비교 → 「계획이 바뀌었어요」 · 「목표가 바뀌었어요」 · 최신 버전 표시(E2E ③ ④) |
| 5 | 저장 실패 · 재시도 · 중복 mutation | 기존 4차 계약 그대로(같은 요청 서명 = 같은 키 · 409 · 재시도 reused — `e2e-map-v4-save.mjs` 36/36). 이번에 서버 계약은 바꾸지 않았다 |
| 6 | TASK 선택 변경 시 계획 편집 초안 보존 | 계획 칸은 TASK 선택과 따로 열려 있고(묶음 단위), 초안은 기존대로 기기 저장 |
| 7 | 늦은 응답이 다른 묶음 상태를 덮지 않게 | 계획 편집을 묶음마다 다른 인스턴스로(`key=ws`) |
| 8 | 과거 지도 ↔ 현재 실행 | 과거 기준(`?asof=`)에는 다음 행동 링크 없음(E2E ⑥) |
| 9 | `/csat` 홈 첫 제안 = ActionRank | `homeFocusOf` — composeV4 → ActionRank. 옛 읽기 7단계 초점(learnerPath.focus) 판정 제거 · 「지도에서 보기」는 Inspector 로 |
| 10 | 중복 컴포넌트 · 판정 제거 | P-M1 에서 옛 지도 5파일 삭제 · 이번에 홈의 두 번째 판정 제거 |

## 2. 발견 · 수정한 결함 — 계획 저장 뒤 선택 문맥 소실

실측: 계획을 「확정」하면 서버 새로 고침으로 지도가 다시 올라와 고른 TASK 가 첫 추천(E3)으로 바뀌고 계획 칸이 닫혔다(최우선 성공 기준 위반).
주소를 몰래 바꾸는 방법(replaceState)은 Next 라우터가 옛 주소로 되돌려 실패했다. 고른 TASK · 열린 묶음을 이 탭 동안만 기억해(서버 렌더 · 다른 탭에는 없음) 다시 올라온 지도가 이어받는다. 복귀 링크 문맥이 있으면 그것이 먼저다.

## 4. 하지 않은 것

- 다른 사람 Workspace UUID 의 서버측 거절 검증: 지도는 UUID 로 조회하지 않으므로(비교만) 읽기 노출 경로가 없다. 계획 저장 API 의 남의 `userId` 위조 거절은 4차 E2E(25번)에서 확인된 그대로다.
- DB 원자 멱등성 보강(정본 §10.3 「성공한 재시도를 신규 검사로 거절하지 않음」의 서버 원자 계약): 지금 RPC 로 충분한지 재감사는 P-M3 전 별도 — 새 RPC 가 필요하면 승인 대상.
