## 1. 무엇을 대체하는가

- **자리**: `/csat/dissect` 의 `reading` 모드. 라우트는 늘리지 않는다(브리프 A1 = 학습자 라우트 3개).
- **교체 대상**: `AnalysisWorkbench`(원문 + 구조도 + focusNav 탭). 원문 패널과 관계 상세는 극장의 두 판으로 흡수되고,
  `QuestionArchitecture`(SVG 구조도)는 **부가 정보 패널의 «뼈대» 블록**으로 들어간다(문장 길이 막대).
- **그대로 쓰는 것**: `LecturePlayer`(큐 엔진·붙들기·탭 이탈 처리) · `LectureStage`(DOM 에 `data-lecture-state` 달기 · 블록 클릭 점프 · Space/←/→) ·
  `tts.ts`(WebSpeech/Silent 어댑터) · `analysisSections()` · `buildDissectionPassage()` · `PaperDrop`(PDF reflow).
  **새 재생 엔진을 쓰지 않는다** — 큐가 이미 `target`·`focus`·`pause_after_ms` 를 들고 있어 순차 표출에 필요한 것이 전부 있다.

## 2. 골격

```
┌ 머리띠 ────────────────────────────────────────────────────────────┐
│ 문항 이름 · 표식 │ 소리 · 배속 · ← → │ [상영 시작]                  │
│ ▬▬▬▬▬▬▬▬░░░░░░░░ 진행 2px                                          │
├─────────────┬──────────────────────────────────────────────────────┤
│ ① 레일      │ ② 무대                                               │
│ 20.5rem     │  ┌ 바: 지금 단계 · 범례(근거 ━ / 비튼 자리 ┄) ─────┐ │
│             │  ├──────────────────────┬───────────────────────────┤ │
│ 문항 카드   │  │ 원문 패널            │ 부가 정보 패널            │ │
│ (발문·정답) │  │ 01 …                 │ ┌ 칩 ─ 제목 ─ 본문 ─ 인용 │ │
│             │  │ 02 …   ← 하이라이트  │ │ (큐마다 한 블록 append) │ │
│ ─ 단계 01   │  │ 03 ______            │ └───────────────────────  │ │
│ ─ 단계 02   │  │ …                    │                           │ │
│ ● 단계 03   │  │ ─ 선지 ①~⑤ (정답 표시)│                          │ │
│   본문 2~3줄│  └──────────────────────┴───────────────────────────┘ │
│ [되묻기]    │  ┌ ③ 장 카드 8개 (면 색 8% + 점 격자) ─────────────┐ │
│ [지금 여기 ↓]│  └──────────────────────────────────────────────────┘ │
└─────────────┴──────────────────────────────────────────────────────┘
```

- **폭**: 판면 96rem. 레일 20.5rem 고정, 무대가 나머지. 무대 안 두 판은 `1.05fr / 1fr`.
- **높이**: ≥901px 에서 `clamp(34rem, 78vh, 52rem)` — 레일·원문·블록 목록이 **각자 스크롤**한다. 한 화면 안에서 셋이 같이 움직이는 것이 이 화면의 전부다.
- **접힘**: ≤1180px 무대 2판 → 1열(원문 위, 부가 정보 아래). ≤900px 레일이 위로 올라가고 단계 목록은 최대 20rem 스크롤. 장 카드 줄은 언제나 가로 스크롤.
- **면**: 레일·원문 = 종이(`--bg`), 부가 정보 = 캔버스(`--bg2`), 블록 = 종이 위 1px + 왼쪽 3px 눈금. 장 카드는 DD-68 §25 그대로 — 면 색 8% + 점 격자.

## 3. 큐 계약 — 한 큐 = 왼쪽 한 단계 + 오른쪽 한 블록 + 하이라이트 하나

이것이 이 설계의 유일한 규칙이다. 셋이 **같은 인덱스**에서 움직이므로 귀·왼쪽·오른쪽이 갈라질 수 없다.

```ts
// 기존 LectureCue 에 화면 쪽 필드 둘만 더한다 (스키마 변경 아님 — 화면 계층에서 합성)
interface TheaterCue {
  cue: LectureCue                                      // 그대로
  rail: { kind: string; name: string; body: string }   // 왼쪽 한 단계
  block: TheaterBlock | null                           // 오른쪽 한 블록 (null = 원문만 움직이는 큐)
  ask?: { question: string; kind: 'evidence-locus' }   // R6 — 되묻기
}
type TheaterBlock =
  | { kind: 'meta';    chips; title; kv?: [string, string][]; bars?: boolean; body?: string[] }
  | { kind: 'intent' | 'evidence' | 'trap'; chips; title; body: string[]; quote?: string }
  | { kind: 'formula'; chips; title; formula: string; body?: string[] }
```

`rail.body` · `block.body` 는 **대본 문자열이 아니다**. 대본(`segments`)은 지금처럼 재생을 누른 뒤
`/api/csat/lecture` 로만 온다(`lecture/types.ts` 의 경고 그대로). 화면 글은 `analysisSections()` 의 `text` 에서 온다.

## 4. 매핑 — 분석 자료의 역할 → 좌 / 우

`ROLE_ORDER` 를 그대로 따른다. 없는 역할은 건너뛴다(빈 칸을 지어내지 않는다).

| 순 | role | 왼쪽 단계 | 오른쪽 블록 | 원문 |
|---|---|---|---|---|
| 01 | `intro` | 무엇을 연결하는 문항인가 | `meta` — 소재·형식·정답·유형 | — |
| 02 | `structure` | 지문의 뼈대 | `meta` + 문장 길이 막대(빈칸 자리 점선) | 빈칸 문장 |
| 03 | `strategy` | 출제자가 확인하려는 읽기 | `intent` — 의도 서술 | 도입 문장 |
| 04 | — | **여기서 한 번 예측** | (없음) | — |
| 05 | `evidence` | 근거에서 정답으로 | `evidence` — 칩 `근거·확인` + 정답 선지 인용 | 근거 문장 실선 + 인용 구 밑줄 |
| 06 | `eliminate`/`trap` | 그 관계를 비튼 오답 | `trap` — 계열 칩 + 오답 선지 인용 | 비튼 문장 점선 |
| 07 | `vocab` | 걸림돌 어휘 | `meta` — 낱말/뜻 대조 | 그 낱말이 든 문장 |
| 08 | `wrapup` | 다음 지문에 가져갈 원리 | `formula` — 공식 한 줄 + 같은 공식 문항 | — |

**흐림 규칙**: 지금 큐가 가리키는 문장만 또렷하고 나머지는 34%. 지나간 큐의 표식(실선·점선·선지 표시)은 **남는다** —
쌓이는 것이 이 화면의 산출물이다. `LectureStage` 의 `active/path/inside/dim` 을 그대로 쓴다.

## 5. 되묻기 한 번 (R6)

- **자리**: `evidence` 직전, 상영당 **한 번만**.
- **묻는 것**: 「근거는 몇 번째 문장일까요?」 — 문장 번호 칩 + 「모르겠어요 · 바로 보기」.
- **답한 뒤**: 「적중」 / 「출제자는 여기를 봤습니다」 — **같은 톤, 점수 없음**(브리프 A2·A7 유지). 소리도 «틀림»음을 쓰지 않는다(§6).
- **기록**: 기존 `Prediction { step: 1 }` 그대로 `DissectionRecord.predictions` 에 넣는다. 이미 분석을 읽은 문항(`inspected`)이면 적중 통계에서 빼는 현재 규칙을 그대로 적용한다.
- 답할 때까지 재생은 **멈춘다**(말은 질문까지 읽고 멈춘다). 이것이 「보여 주기만 하는 해설」로 미끄러지지 않게 하는 장치다.

## 6. 소리

| 층 | 무엇 | 규칙 |
|---|---|---|
| 말(주) | 한국어 TTS — 지금의 `WebSpeechAdapter`. 한국어 목소리가 없으면 `SilentAdapter`(추정 시간만큼 하이라이트만) | 그대로 |
| 효과음(부) | **큐 경계에서만.** 말 위에 겹치지 않는다 | 전부 ≤ 300ms · 말 대비 −12 dB 이하 |
| 배경음 | **없다** | 정독 화면에 루프 BGM 을 얹지 않는다 — 게임(`/play/*`)과 예산이 다르다 |

여섯 소리, 하나씩 뜻이 있다:

| 이름 | 언제 | 무엇 |
|---|---|---|
| `step` | 왼쪽에 단계가 한 칸 얹힐 때 | 마른 나무 탁 (40ms) |
| `mark` | 근거 밑줄이 그어질 때 | 붓 한 획 (≈300ms) |
| `trap` | 오답 점선이 드러날 때 | 낮고 마른 탁 — **경고가 아니라 표시** |
| `hit` | 예측 적중 | 두 음 종 |
| `near` | 예측 빗나감 | 낮게 내려앉는 한 음. **오답음(`wrong.wav`)을 쓰지 않는다** — 정답률을 세지 않는 화면에서 「틀림」 소리는 거짓말이다 |
| `seal` | 공식이 찍힐 때 | 도장. 상영당 한 번 |

- **자산**: `apps/web/public/audio/csat/` 에 6개. 조달 기준은 게임과 같다 — **실녹음 스테레오**, 대역제한 합성음 반려(`gamekit.tsx` v07.6 의 판정 그대로), 출처는 `CREDITS.txt`.
  재생은 `useSfx` 와 같은 방식(Web Audio 버퍼 · 피치 지터 ±45센트 · 로드 실패 때만 합성 폴백).
  **시제품 링크의 효과음은 합성음이다** — 자리와 박자를 보이려는 것이고, 제품에 그대로 넣지 않는다.
- **기본값 끔.** 브라우저가 제스처 전 오디오를 막으므로, 「상영 시작」을 누를 때 함께 켜자고 한 줄로 묻고 그 선택을 기기에 남긴다.
- 같은 소리를 연속 2회 내지 않는다(`step` 이 연달아 필요하면 두 번째는 −6 dB).

## 7. 접근성

- **`prefers-reduced-motion`**: 순차 표출은 **끄지 않는다**(그게 내용이다). 끄는 것은 이동·페이드·부드러운 스크롤뿐 — 단계는 즉시 나타나고 스크롤은 `auto`.
- 무음 모드에서도 상영은 끝까지 돈다(추정 시간). 「한국어 음성이 없어 강조만 진행해요」를 지금처럼 `role="status"` 로 알린다.
- 단계·장 카드·선지 전부 44px 이상, 보이는 focus 표시, 큐가 바뀔 때 `aria-live="polite"` 로 「n단계 · 이름」.
- 색만으로 말하지 않는다: 근거 = **실선**, 비튼 자리 = **점선**, 칩에 글자 라벨. 범례가 무대 바에 상주.
- 키보드: `Space` 재생·멈춤 · `←/→` 단계 · 레일 단계와 장 카드는 탭 순서 안의 버튼. `LectureStage` 가 이미 갖고 있다.

## 8. 계측 (D2·D3)

새 이벤트를 만들지 않고 기존 둘을 쓴다 — 속성은 숫자·불리언·닫힌 열거형만:

- `csat_lecture_played { mode: voice|silent, from: start|cue|block, rate: 90|100|115, theater: true }`
- `csat_lecture_ended { cues, jumps, mode, theater: true }`
- 되묻기는 `csat_session_explained { kind: 'evidence' }` — 이미 있는 이름 그대로.

보는 값: **끝까지 본 비율**(ended/played) · **점프 수**(되짚기가 실제로 쓰이는가) · **되묻기 응답률**(무시되면 R6 는 장식이다).

## 10. 브리프와 부딪히는 곳 — 기록

| 브리프 | 이 설계 | 왜 |

| A4 「탭·모드·렌즈 UI 금지, 표 금지」 | 장 카드 줄(8개)을 둔다 | 카드는 «필터»가 아니라 **목차**다 — 순서가 내용인 화면에서 목차는 정보다. 표는 여전히 쓰지 않는다 |

두 줄을 이 표로 대체한다.
