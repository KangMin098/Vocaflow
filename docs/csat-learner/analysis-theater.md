### 3-0. 첫 판은 판면이 틀렸다 — 그리고 왜 틀렸나

2026-09-23 오전 판은 **읽기 판면 42rem 안**에 두 판을 넣었다(`.shell` 의 기본 최대 폭). 실화면에서
두 판이 손가락만큼 좁아 문장 막대가 점이 되고 인용문이 한 낱말씩 끊겼다. 원인은 셸 규칙 하나다 —
`learning-home.module.css` 의 `.shell` 은 기본 42rem 이고, 넓게 쓰는 화면만 `:has()` 로 예외를 얻는다.
그리고 `/csat/item/*` 이 `NO_BANNER` 에 없어 분홍 모듈 머리띠까지 얹혔다.

참조는 **읽는 문서가 아니라 작업 공간**이다. 그 사실을 판면으로 옮기는 것이 이 화면의 첫 조건이다:

- `.shell:has([data-csat-theater]) { max-width: none; padding: 0 }` — 셸 판면을 벗어난다
- `NO_BANNER` 에 `/^\/csat\/item\//` — 머리띠를 걷는다(이 화면은 제 상단 막대를 갖는다)
- `.workspace { height: calc(100dvh - 4rem) }` — 셸 막대만 비우고 나머지를 전부 차지한다

### 3-1. 왜 강의 큐가 「사고 과정」인가

792문항의 강의는 이미 **큐 12~14개**로 쓰여 있고, 큐마다 역할(`role`)과 가리킬 곳(`target`)이 붙어 있다.
그 차례가 곧 이 문항을 읽는 순서다:

```
열기(intro) → 준비(strategy) → 뼈대(structure) → 근거(evidence) → 배제(eliminate, 오답마다)
→ 함정(trap) → 어휘(vocab) → 정리(wrapup = 다시 풀 때의 절차)
```

새 순서를 발명할 이유가 없다. `theater.ts` 가 하는 일은 그 차례에 **사람이 읽을 이름**을 붙이는 것뿐이다
(`anchor:sentence:6` → 「7번째 문장」 · `analysis:reject:1` → 「오답 ① 지우기」 · `analysis:procedure` → 「다시 풀 때의 절차」).
모르는 타깃은 **지어내지 않고** 키를 그대로 보여 준다.

### 3-2. 한 큐 = 왼쪽 한 단계 + 오른쪽 한 블록 + 지도 하이라이트 하나

이것이 유일한 규칙이다. 셋이 같은 인덱스에서 움직이므로 귀·왼쪽·오른쪽이 갈라질 수 없다.
`anchor:sentence:k` 큐는 블록이 아니라 **지도**를 가리키므로 `analysis:map` 으로 보낸다 —
그러지 않으면 문장을 짚는 큐마다 오른쪽이 「가리킬 곳 없음」이 된다(회귀가 이 매핑을 잠근다).

재생 엔진은 손대지 않았다. `LecturePlayer`(큐 순회 · 붙들기 · 탭 이탈) · `LectureStage`
(`data-lecture-state` = active/path/inside/dim · 블록 클릭 점프 · Space/←/→) · `tts.ts`(WebSpeech/Silent)를 그대로 쓴다.

### 3-3. 재생 전에도 레일이 선다 — `lectureOutline`

`LectureStage` 의 큐 목록은 `/api/csat/lecture` 를 부른 뒤에야 생긴다. 그때까지 레일이 비면 화면이
「눌러 보기 전에는 아무것도 아닌 것」이 된다. 그래서 서버가 **역할 · 가리킬 곳 · 길이 · 말한 문장 번호**만
미리 준다(`lecture/store.ts` 의 `lectureOutline`). **대본(`segments`)은 여전히 서버 HTML 에 한 자도 없다** —
A1 이 막는 것은 대본이지 차례가 아니다.

### 3-4. 오른쪽 블록은 분석 자료의 층 그대로

`CsatItemExplain` 의 층을 그대로 블록으로 옮긴다(`theaterBlocks`). **비어 있는 칸은 만들지 않는다** —
근거가 없으면 근거 블록이 없는 것이고, 그 자리에 「준비 중」을 그리지 않는다.

| 블록 | 출처 | 비고 |
|---|---|---|
| 문항 열기 | 회차·번호·유형·배점·권장 시간·정답 | 정답표가 없는 회차는 **답을 지목하지 않고** 그 사실을 말한다 |
| 이 문항이 재는 것 | `measured_ability` | 802문항 전부에 있다 |
| 출제 의도 | `design_intent` | |
| 답이 왜 이것인가 | `why_correct` + `evidence_reasoning` + `evidence_quote` | 인용은 발췌(≤ 40낱말 상한은 로더가 건다) |
| ⓝ가 왜 아닌가 | `distractors[]` | **선지마다 한 블록**, 함정 이름이 칩 |
| 다시 풀 때의 절차 | `procedure[]` | 번호 + 「막히면 …」이 같은 줄에 |
| 걸림돌 어휘 | `required_vocab[]` | |

본문은 **분석 자료의 글자 그대로**다. 요약하거나 고쳐 쓰지 않는다(회귀가 대조한다).

### 3-5. 순차 표출은 기본값이지 감옥이 아니다

머리띠의 **「전부 펼쳐 읽기」** 로 한 번에 전환된다. 이미 아는 문항을 다시 여는 사람에게 12단계를
강요하면 화면이 느려지기만 한다. 강의가 없는 문항(10개)은 처음부터 전부 펼친 상태로 연다.

## 4. 소리

| 층 | 무엇 | 규칙 |
|---|---|---|
| 말(주) | 한국어 TTS. 없으면 무음 모드(추정 시간만큼 하이라이트만) | 기존 어댑터 그대로 |
| 효과음(부) | **큐 경계에서만** | 말 대비 −12 dB 아래 · 200ms 안 재탕은 절반 음량 |
| 배경음 | **없다** | 정독 화면에 루프 BGM 을 얹지 않는다 — 게임(`/play/*`)과 예산이 다르다 |

소리는 넷, 뜻도 넷이다. 다섯째를 더하려면 다섯째 뜻을 먼저 찾아야 한다.

| 이름 | 언제 | 자산 · 배속 · 음량 |
|---|---|---|
| `step` | 단계가 한 칸 얹힐 때 | `click.wav`(타자기) 1.0× · .18 |
| `mark` | 근거를 그을 때(evidence) | `correct.wav`(벨) 0.92× · .20 |
| `trap` | 오답·함정 자리를 짚을 때 | `click.wav` **0.6×** · .30 → 마른 「탁」 |
| `seal` | 정리를 찍을 때(wrapup) | `complete.ogg`(금관) 0.88× · .24 |

- **자산을 새로 받지 않았다.** `public/audio/sfx/` 의 실녹음 샘플을 배속으로 다시 쓴다. 게임이 v07.6 에서
  합성음(대역제한·모노·스펙트럴 평탄도 0)을 걷어내고 넣은 것들이라 이미 검증돼 있고, 필요한 네 소리는
  이 셋의 음높이를 옮긴 것으로 정확히 만들어진다. 새 파일을 받으면 출처·라이선스를 한 벌 더 관리해야 한다.
- **`wrong.wav` 는 쓰지 않는다.** 이 화면은 정답률을 세지 않는다 — 「틀림」 소리가 나면 학습자가 채점당한다고 느낀다.
- **기본은 끔.** 브라우저가 제스처 전 오디오를 막으므로 켜 두면 첫 상영에서 소리가 안 나고 「고장」처럼 보인다.
  학습자가 켜면 기기에 남긴다(`localStorage`). 샘플을 못 받으면 **소리 없이 간다** — 합성음으로 때우지 않는다.

## 5. 접근성

- **`prefers-reduced-motion`**: 순차 표출은 끄지 않는다(그게 내용이다). 끄는 것은 전환 시간뿐 — 전역
  `[data-lecture-state]` 규칙도 페이드는 남긴다(무엇이 바뀌었는지는 보여야 한다).
- 무음 모드에서도 상영은 끝까지 돈다. 「한국어 음성이 없어 소리 없이 강조만 넘어가요」를 `role="status"` 로 알린다.
- 단계·장 카드·칩·목록 칩 전부 44px 이상, 보이는 focus 표시(`--ju` 2px), 지금 단계에 `aria-current="step"`.
- 색만으로 말하지 않는다: 근거 = **실선**, 오답 = **점선**, 칩에 글자 라벨, 범례가 무대 바에 상주.
- 서가의 번호 칩은 `aria-label` 에 「회차 · 번호 · 유형 · 배점 · 상영 유무」를 다 담는다(칩 글자는 짧다).

## 6. 계측

새 이벤트를 만들지 않았다. `csat_lecture_played` / `csat_lecture_ended` 가 극장에서도 그대로 나간다
(`LectureStage` 안에 있다). 보는 값: 끝까지 본 비율 · 점프 수 · 서가에서 연 문항의 회차·유형 분포.

## 8. 아직 안 한 것 — 정직하게

- **R6(상영 중 되묻기)는 넣지 않았다.** 예측→대조는 `/csat/dissect` 가 이미 하고 있고, 극장에 한 번 더
  넣으면 같은 학습 행동이 두 화면에 갈라진다. 먼저 극장을 쓰는 사람이 실제로 생긴 뒤에, 그때 어디에
  둘지 정한다(지금 넣으면 근거 없이 화면을 늘리는 것이다).
- **`/csat/dissect` 는 그대로다.** 예측 화면은 1열 유지 — 2열은 「이미 아는 것을 정리하는」 읽기에 맞고
  예측에는 방해다. 브리프 A6 은 분석 모드에만 대체된다.
- **서가의 개인 기록 표시 없음.** 「내가 본 문항」 배지는 기기 기록(IndexedDB)을 서가에 끌어와야 하는데,
  802행 × 기기 조회를 홈 첫 화면에 넣기 전에 먼저 서가가 쓰이는지를 본다.
