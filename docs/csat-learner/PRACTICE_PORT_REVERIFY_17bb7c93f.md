## P1-2. g2 도움 수준 — FAIL(g2 · 응답 유실 경로)
고쳐진 것:
- g2 시도가 `p_help_level: null` 을 보내 **세션 값을 상속**(`practice-writer.ts:156-157`) — 세션과 모순되는 값으로 인한 영구 500 경로는 닫힘.
- 판단을 보낸 뒤 해설을 열면 답 입력 잠금(`ClaimPractice.tsx` · `17bb7c93f`) — 해설을 보고 고친 답이 독립 시도로 저장되는 경로 차단. 「해설 먼저 보기」 링크는 판단을 보낸 세션에선 사라지고 「해설 보기」(별도 행동)로 바뀜 — 기존 독립 판단 이력 보존.
- 해설 열람은 `explanation_viewed_at` 으로 따로 남김(`practice.ts:177` · `practice-server.ts:193`).

**남은 결함(P1 · g2 모드)**: 첫 제출이 **저장됐지만 응답만 유실**된 경우 — 학습자가 해설을 연 뒤 같은 답을 같은 `client_mutation_id` 로 재전송하면, `responseOf` 가 `explanation_viewed_at`(null → 시각)을 **`p_response` 안에** 넣는다(`practice-writer.ts:74-83` · `:160`). G2 RPC 는 멱등 비교에 `response` 전체를 쓰므로(G2 계약 — 모든 의미 필드 비교) **conflict → 409 「화면을 새로 고쳐 주세요」**(`practice-server.ts:202`) 로 막힌다. 새로 고쳐도 같은 세션 · 같은 id 면 반복.
- direct 모드는 `sameAttempt` 가 `explanation_viewed_at` 을 비교하지 않아(`practice-writer.ts:59-72`) **duplicate 로 정상 처리** — 현재 기본 동작에는 영향 없음. 단 그 경우 해설 열람 시각은 어디에도 남지 않는다(P2).
- E2E 신규 시나리오(`:159-182`)는 가짜 서버가 **저장 전에** 실패시키므로 이 경로를 덮지 않는다.
- **권고**: 해설 열람을 같은 시도의 `response` 에 넣지 말고 별도 행동(세션 쪽 기록 또는 별도 mutation)으로 남긴다 — 재전송 payload 는 첫 제출과 비트 단위로 같아야 한다. G2 계약 변경은 필요 없다(계약이 정상적으로 막는 것).
