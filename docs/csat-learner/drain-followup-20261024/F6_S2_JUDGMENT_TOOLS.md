## 2. 공통 설계 원칙 (모든 도구)

1. **3단계가 화면 상태로 갈린다.** 한 도구 안에서 ① 표지 관찰(지문 위에서 표지를 표시) → ② 의미 범위 확인(그 표지가 걸리는 범위를 늘이고 줄임) → ③ 근거 관계 판단(범위와 선지·빈칸·자리를 연결하고 관계 라벨 고르기) 순서로 열린다. 다음 단계는 앞 단계를 **조작한 뒤에만** 열린다. 「다음」 버튼만 눌러 넘어가는 경로는 만들지 않는다. 단, 「건너뛰고 해설 보기」는 언제나 둔다(강제 학습 금지). 건너뛴 기록은 수행이 아니다.
2. **대비 쌍(contrast pair)이 기본 단위.** 같은 원리에서 표지 규칙이 통하는 문항과 깨지는 문항(drain D2 반례)을 나란히 두고, 학습자가 두 문항에서 같은 조작을 한 뒤 결과 차이를 직접 본다. 쌍 데이터는 **미등록 후보**이며(D2 원문 표기), 등록 전에 독립 검토와 원문 대조가 필요하다.
3. **오답 설계 논리 대조.** 「이 오답의 함정 라벨은?」을 맞히는 것(현행 lure check)이 아니라 학습자가 ⓐ 매력 오답을 끌어당긴 지문 조각(표지·반복어)과 ⓑ 정답을 잠그는 근거 범위를 각각 직접 표시하게 한 뒤 두 표시를 겹쳐 보여 준다. 어긋나는 지점(범위·극성·주체·대상)이 학습자의 선택 결과로 드러난다.
4. **근거 단위는 모델 `units`를 따른다.** 문장·절·밑줄 범위·단락·표 칸·도표 값·빈칸·요약 칸. 단위 자료가 없으면 그 단계는 「자료 없음」 상태로 남기고 문장 단위로 몰래 대체하지 않는다.
5. **기록과 숙달.** 모든 조작 기록은 「설명 후 수행」 또는 「탐색」으로 남기며 숙달로 산입하지 않는다(D8: 숙달은 `attemptRole==='independent_check'`만). 자유서술 입력은 두지 않고, 개인이 가져온 임의 자료는 채점하지 않는다.
6. **자료 없음 상태.** 각 도구는 필요 자료를 명시하고, 없으면 도구 자리를 비우지 않고 「이 문항은 ○○ 자료가 아직 없어 이 판단 도구를 쓸 수 없습니다」 + 사용 가능한 공통 과제만 보여 준다. 가짜 범위·추정 값으로 채우지 않는다. 도표 값처럼 원본 없이 확정 못 하는 것은 「방법만」 남긴다(`teaching-contract.ts:16` F11 계약 유지).
7. **키보드.** 모든 선택은 `<button aria-pressed>` 또는 listbox/grid 패턴. 범위 늘이기·줄이기는 Shift+←/→(문자/낱말 단위), 단락·자리 이동은 ↑/↓, 확정 Enter, 취소 Esc. **선행 조건**: `AnalysisTheater.tsx:892-895` 전역 ←/→ 장면 이동이 도구 포커스 안에서 동작하지 않도록 범위 한정(KNOWN 04 P1-2). 인라인 문장 클릭과 함께 44px 번호 버튼을 병설한다.
8. **모션.** 장식 모션 없음. 범위가 겹칠 때의 강조 전환만 `--dur-*` 토큰 페이드, reduced-motion에서는 이동 없이 페이드만.

## 3. 계열별 판단 도구 명세

### T1 · 범위 저울 (Scope Balance) — 중심 명제 계열

- **대상**: R-GIST · R-TOPIC · R-TITLE · X-TITLE · R-CLAIM · R-PURPOSE (R-SUMMARY는 T5).
- **학습자 조작**: ① 지문에서 필자 판단 표지(당위어·평가어·처방어·요청 동사·통념 주어)를 눌러 표시 → ② 표시한 표지가 걸리는 범위를 문장 단위로 늘이고 줄여 「필자 입장 범위」를 정함(통념 주어 문장은 「필자 아님」으로 분류) → ③ 선지 5개를 「범위보다 넓음 / 맞음 / 좁음 / 관점 반대」 4칸 저울에 끌어 놓거나 키보드로 배치.
- **근거 단위**: 문장(단문) · 단락(X-TITLE) · 선지.
- **3단계 드러남**: 표지는 지문 위 밑줄형 표시, 범위는 지문 옆 세로 막대 길이, 관계는 저울 4칸. 세 표시가 한 화면에 동시에 남는다.
- **오답 설계 논리**: 학습자가 ③에서 「좁음」 칸에 놓은 매력 오답을 누르면 그 선지가 덮는 문장 범위가 ②의 필자 범위와 겹쳐 그려진다 → 부분 사실(일부 범위만 덮음)·범위 과대가 눈으로 보임. 라벨(`PROPOSITION_TRAPS`)은 학습자 배치 뒤에 비교용으로만 노출.
- **대비 쌍(실제 문항, 미등록 후보)**: 2026#22(말미 처방이 진단을 포섭 — P-GIST 성립) ↔ 2023#22(사례 나열형, 말미가 부가 조건 — D2a-01) · 2026#20(당위 표지 = 주장) ↔ 2023#20(당위 표지 없는 평가형 — D2a-02) · 2026#18(행동 요구 동사 = 목적) ↔ 2024#18(광고, 요구 문장이 수사 — D2a-04) · 2026#24 ↔ 2024#23(두 항 중 한쪽 옹호인데 balancing 선지가 매력 오답 — D2a-05).
- **필요 데이터 / 공백**: 표지 위치(문장 내 문자 범위)와 필자 입장 범위 정답 — 현재 DB에 없음(D3 R-CLAIM 행). 선지↔문장 덮개 범위 — 없음. 문장 분할은 `csat_item_units`(kind:"sentence") 있음. X-TITLE 세트 키는 `exam_id+no` 파생 가능(D4b-23, 컬럼 추가 불필요).
- **자료 없을 때**: ①②는 「학습자 표시 → 해설의 근거 문장과 겹쳐 보기」로만 열고(지도 `answerSentences` 있으면), ③ 저울은 선지 범위 자료가 없으면 비활성 + 「자료 없음」 문구.
- **키보드**: 표지 = 문장 번호 버튼 → 낱말 Tab 순회 + Space 표시; 범위 = Shift+↑/↓; 저울 = 선지 포커스 후 1~4 키로 칸 지정.

### T2 · 완성 명제 검증기 (Completed-Proposition Check) — 빈칸 계열

- **대상**: R-BLANK (retired BLANK2 · X-BLANK · X-BLANK2는 보관).
- **학습자 조작**: ① 빈칸 앞뒤의 논리 표지(부정어 + `simply/only/merely` 한정어 · 재진술 표지 `In other words/Putting this another way` · 이유절 · 조건절)를 표시 → ② 부정이 무엇에 걸리는지 4택(참 / 충분성 / 능력 / 인식)을 고름 — 이것이 의미 범위 확인 → ③ 선지 하나씩 빈칸에 넣어 **완성 명제**를 화면에 만들고, 그 명제를 재진술 문장·결과절과 「같은 말 / 반대 / 무관」으로 연결.
- **근거 단위**: 빈칸 · 절(부정 범위) · 문장(재진술 근거).
- **오답 설계 논리**: 반복 어휘 미끼 대조 — 학습자가 「지문에 나온 낱말」 표시를 켜면 각 선지의 어간이 지문 어디서 왔는지 연결선이 생기고, ③의 완성 명제 판단과 나란히 놓인다. 반복어 선지가 완성 명제 검증에서 탈락하는 것을 학습자가 직접 확인한다. 「반복어 = 정답」·「반복어 = 오답」 어느 쪽도 규칙으로 가르치지 않고 점검 항목으로만 둔다(D2b: 답 어간 일치 4건 존재).
- **대비 쌍**: 2026#34(참 부정) ↔ 2024#31(`not simply` 충분성 부정, D2b-05) · 2023#34(it is not that A… 대조형, 성립) ↔ 2024#31 · H2510G1#31(② correction 반복어 미끼, D2b-01) ↔ H2009G2#31(반복어가 정답) · 2026#32 ↔ H2209G1#34(부정 + 재진술, D2b-07).
- **필요 데이터 / 공백**: 빈칸 위치(reflow 빈칸 있음) · 재진술 근거 문장 결속(지도 answerSentences로 부분 대체 가능) · 부정 범위 정답 라벨 — 없음. 2026#34 ② 진위 감수 미결(KNOWN) → 해당 선지는 「판정 보류」 상태로 표시.
- **자료 없을 때**: ②의 4택은 정답 라벨이 없으면 학습자 선택만 기록하고 채점하지 않음(「비교용」 표시). ③은 완성 명제 생성만으로도 가능(문자열 치환, 새 내용 생성 아님).
- **키보드**: 선지 ↑/↓ → Enter로 빈칸에 넣기 → 1/2/3 키로 관계 지정.

### T3 · 이음매 시험 배치 (Seam Trial) — 담화 결속 계열

- **대상**: R-INSERT · R-ORDER · X-ORDER · R-IRRELEVANT · X-REFER (S1의 T-SEAM 후보와 같은 축).
- **학습자 조작**: ① 지문 전체에서 요구 표지(this/such+새 명사 · However/But · For example · also/Another · 정관사 the)를 표시 — 주어진 문장 안과 **본문 문장 쪽 모두**(D2c-01) → ② 표시한 표지마다 「받을 대상 범위」를 앞쪽 구간으로 늘이거나 줄임(한 문장 / 여러 문장 / 단락 전체) → ③ 주어진 문장(또는 단락)을 후보 자리에 **시험 배치**하면 각 표지의 요구가 충족/미충족으로 갈린 결과가 자리마다 표에 쌓임. R-IRRELEVANT는 문장 하나를 「빼 보기」로 같은 표를 만든다. X-REFER는 밑줄 지칭 5개를 인물 열에 끌어 놓기.
- **근거 단위**: 문장 · 단락 · 밑줄(X-REFER).
- **오답 설계 논리**: 「매끄러워 보이는 기존 연결」 대조 — 학습자가 매력 자리(예: 2024#38 ②→But)에 놓았을 때 충족 표가 「But의 대조 상대 = ② 한 문장」으로 그려지고, 정답 자리에서는 「Yes(양보) ↔ But」 짝이 완결된다. 두 배치 결과를 같은 표에서 행 비교. 현행 `POSITION_TRAPS` 라벨은 배치 뒤 비교용.
- **대비 쌍**: 2023#38(뒤 문장 this가 삽입문을 건너뜀, D2c-02) ↔ 2025#38(Such가 삽입문 포함 구간을 받음) · 2022#39(표지가 뒤 문장, D2c-01) ↔ 2025#38 · 2024#38(Yes…But 양보 짝, D2c-03) ↔ 2026#38 ④ · 2024#39(However가 유비 전체와 대조, D2c-04) ↔ 2025#38 · 2025#35(장식 also, D2c-09) ↔ 2025#39 Additionally · 2024#35(극성 역전 무관문, D2c-10) ↔ 2026#35(기준 변경).
- **필요 데이터 / 공백**: 문장·단락 경계(units·passage에 (A)(B)(C) 표지 있음) · 표지↔대상 범위 정답 — 없음(Cohesion 채택 문항의 probe가 일부 대체, 수 UNKNOWN). 2026#38 ⑤는 C1 승인 전 학습자 보류(KNOWN) · 2026#38 choices 보정 필요. X-REFER 밑줄↔인물 결속 없음.
- **자료 없을 때**: ③ 시험 배치는 자리 이동과 「배치 후 지문 다시 읽기」까지만 허용하고 충족 판정은 「정답 자료 없음」 표시. 조작 결과로 정답을 암시하지 않는다.
- **키보드**: 주어진 문장 포커스 → ↑/↓로 자리 이동 → Enter 배치 · Esc 원위치. 이 도구가 포커스를 가진 동안 전역 ←/→ 비활성(선행 조건).

### T4 · 절 렌즈 (Clause Lens) — 밑줄 형태·어휘 계열

- **대상**: R-GRAMMAR · R-VOCAB · X-VOCAB · R-IMPLY.
- **학습자 조작**:
  - R-GRAMMAR: ① 밑줄 범위 표시(원본) → ② 밑줄이 속한 절의 경계를 학습자가 지정(절 시작·끝 Shift+←/→)하고 그 절의 주어·정동사를 표시 → ③ 그 절 구조가 요구하는 형태를 닫힌 목록(수일치 · 정동사/준동사 · 관계사/명사절 접속사 · 태 · 병렬 · 대명사 수/재귀)에서 고르고, 밑줄 형태와 「일치/불일치」 판정.
  - R-VOCAB · X-VOCAB: 현행 `ContextSensePanel` 3단(misfit 밑줄 → 단서 문장 → 맞는 낱말)을 확장해 ② 단서 범위를 앞 원인 절만이 아니라 **글 주장 방향**과 함께 놓고 극성(+/−) 두 개를 비교.
  - R-IMPLY: ① 밑줄 비유 표현 → ② 원관념을 담은 문장 범위 지정 → ③ 선지와 「원관념과 같음 / 축자 의미 / 결과 혼동 / 문맥 밖 일반론」 연결.
- **근거 단위**: 밑줄 범위 · 절 · 문장.
- **choiceTruth 처리**: 정답 선택과 선지 진위를 분리 표시(`teaching-contract.ts:15`). 비선정 선지는 「왜 맞는 형태/낱말인가」를 학습자가 ③에서 같은 절차로 확인한다 — 오답 대조가 아니라 「맞는 이유」 대조임을 화면에 명시.
- **대비 쌍**: 2025#29 ②(수일치, 목록으로 성립) ↔ 2023#29 ②(재귀대명사, D2d-03) · 2021#29 ⑤(what/whether, D2d-04) · R-VOCAB: 2025#30 ④(앞 국소 단서가 글 주장과 역방향, D2d-05 — 원문 전사 감수 필요) ↔ 08 대표 성립 문항(미지정, 선정 필요).
- **필요 데이터 / 공백**: **밑줄 끝점 없음**(D4b-07~10, 시작점 ①~⑤ 129/129) — R-GRAMMAR·R-IMPLY 도구의 ①②는 이 결속 없이는 성립 불가. 복구 경로: 학평 수집기 `getOperatorList` 선 검출 확장(D4b-09). 절 경계·문법 범주 정답 — 없음. 네모 어법 4건 미분류.
- **자료 없을 때**: 학습자 로컬 PDF 크롭(`VISUAL_PAPER_TYPES`)이 있으면 원본을 옆에 보여 주되 범위 조작은 비활성, 없으면 기존 빈 상태 문구 유지. 밑줄 위치를 추정해 그리지 않는다.
- **키보드**: 밑줄 ①~⑤ 번호 버튼 → Shift+←/→ 절 경계 → 1~7 범주 선택.

### T5 · 칸 대조 격자 (Cell Grid) — 정보 대조 계열

- **대상**: R-FACT · X-FACT · R-NOTICE · R-CHART · R-SUMMARY · R-MOOD(전환 2구역).
- **학습자 조작**:
  - R-FACT · X-FACT: ① 선지를 성분(주체 · 행위 · 대상 · 시점 · 수량)으로 나눠진 칸으로 보기 → ② 각 칸에 대응하는 지문 범위(문장/단락)를 학습자가 연결 → ③ 칸별 「같음 / 바뀜 / 지문에 없음」 판정. 바뀐 칸 하나가 근거.
  - R-NOTICE: 안내문을 행·열 표로 복원해 ② 선지 성분을 **표 칸**에 연결(병합 셀 범위 포함, D2d-02).
  - R-CHART: ① 범주·계열·단위 표시 → ② 선지가 말하는 두 값을 도표 값 칸에서 고름 → ③ 연산(차 · 배수 · %p vs %)을 고르고 결과와 선지 비교.
  - R-SUMMARY: (A)(B) 칸마다 ② 지문의 극성·방향 범위를 연결 → ③ 선지 쌍을 칸별로 판정(한 칸만 맞는 쌍 대조).
  - R-MOOD: 전환점을 학습자가 지정해 전/후 2구역 → 구역별 감정어 표시 → 극성 방향 + **감정 종류** 2축 판정(D2d-06·07이 극성만으로는 실패함을 보임).
- **근거 단위**: 선지 성분 칸 · 문장 · 단락 · 표 칸 · 도표 값 · 요약 칸.
- **오답 설계 논리**: 성분 칸 중 「바뀜」 한 칸이 매력 오답의 설계 지점 — 학습자가 그 칸을 직접 찾고, 나머지 칸이 모두 「같음」이라 끌린다는 것을 격자에서 본다(부분 사실). choiceTruth 유형은 진위 열과 정답 선택 열을 분리.
- **대비 쌍**: X-FACT 2025#45 ④(사건이 두 단락에 걸침, D2d-01) ↔ 단락 1개 근거 성립 문항(선정 필요) · R-NOTICE 2025#27 ③(병합 셀, D2d-02) · R-SUMMARY 2023#40 ↔ 2024#40(극성 역전 배제 성립, D2 §2) · R-MOOD H1903G3#19(−→− 감정 종류 변화, D2d-07) ↔ H2306G2#19(+→+ 강화, D2d-06).
- **필요 데이터 / 공백**: 선지 성분 분해·지문 대응 — 없음. 안내문 표 셀(`table_cells`) — 없음, R-NOTICE는 PDF 크롭 경로도 없음(D4b-16). 도표 값 표(`chart_series`) 형식 자체 없음, 비공개 PNG 1/133, 재배포 권리 미정(D4b-02~06). R-SUMMARY 학평 101건 body_ok=false로 하류 제외(D4b-19~21). R-MOOD 전환점 cue — 없음.
- **자료 없을 때**: 격자 칸은 학습자가 채운 연결만 보여 주고 정답 칸 판정 비활성. R-CHART는 원본이 없으면 값 칸을 비우고 「연산 방법」 단계만(③의 연산 종류 선택은 도표 없이도 가능). 값을 지문 문장에서 추정해 채우지 않는다.
- **키보드**: 격자 = `role="grid"` 방향키 셀 이동, Enter로 연결 모드 → 지문 문장/칸 ↑/↓ → Enter 확정.

## 5. 구현 우선순위

순위 근거는 **데이터 준비도·기존 코드 재사용·충돌 수**다. 학습 효과 우위가 아니다. 모든 착수는 S1 수용 + 사용자 범위 승인 뒤이며, DB 쓰기는 별도 SQL 승인.

## 6. 수용 점검(설계 단계에서 쓸 기준)

- 각 도구에서 「다음」만 눌러 끝까지 가는 경로가 없는가(조작 없이 단계가 열리지 않음, 건너뛰기는 수행으로 기록 안 됨).
- 근거 단위가 모델 `units`와 같은가. 자료 없을 때 문장 단위로 대체하지 않고 「자료 없음」을 보이는가.
- 오답 대조가 라벨 맞히기가 아니라 학습자 표시 두 개의 겹침으로 드러나는가.
- 키보드만으로 ①②③ 전 과정이 가능하고, 전역 ←/→와 충돌하지 않는가. 44px 번호 버튼 병설.
- 기록이 숙달로 가지 않는가(`attemptRole` 독립 첫 시도만).
- 반례 쌍 문항이 독립 검토·원문 대조를 거쳤는가(현재 전부 미등록 후보).
