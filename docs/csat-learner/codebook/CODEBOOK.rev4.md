## 0. 이 코드북이 하는 일 · 하지 않는 일

- 코드 하나는 **한 번의 풀이(attempt)에서 일어난 실패 사건**이다. 학생을 설명하지 않는다.
  모든 정의는 「이 attempt 에서 학생이 ___ 때문에 정답 판단에 실패했다는 증거가 있을 때 사용한다」 꼴로 쓴다. 「이 학생은 구문이 약하다」 같은 문장은 쓰지 않는다.
- **문항만 보고 원인을 정하지 않는다.** 같은 문항을 틀린 두 학생의 원인은 다를 수 있다. 문항 유형(빈칸 · 순서 · 삽입 …)이나 선지 함정(Choice Trap)은 원인이 아니다 — 판정자가 참고하는 관찰일 뿐이다.
- 원인 판정에는 **학생 과정 증거가 반드시 필요하다**(§2 증거 충분성). 결과(고른 번호 · 정오)만 있으면 판정하지 않는다.
- **범위: v0.1 = 읽기(Reading Error Cause).** 듣기는 v0.2 확장(§8). 도표 · 그림 문항은 자극 증거가 없어 판정 제외(§2 `unsupported_stimulus`).
- 원인이 같아도 숙달도 · 역량 진단으로 자동 승격하지 않는다. `linked_core` 는 나중에 볼 진단 후보를 가리킬 뿐이다.

## 1. 상위 구조(family)

판정은 「처리 단계」 순서로 좁힌다 — 영어 입력을 받기 전 · 한 문장 안 · 문장 사이(글) · 문제 · 선지 판단 · 결정 방식 · 시험 실행.

| family | 실패하는 처리 단계 | 코드 수 |
|---|---|---|
| **V** 어휘 처리 | 낱말 · 낱말 덩어리의 뜻을 얻는 단계 | 3 |
| **S** 문장 처리 | 한 문장 안의 구조 · 수식 · 연산자 범위 · 문법 형태 | 4 |
| **R** 글 이해 | 문장 사이 연결 · 지시 · 글의 중심 · 함축 | 4 |
| **E** 문제 · 선지 판단 | 글은 처리했는데 발문 이해 · 근거 대응 · 선지 대조가 틀림 | 3 |
| **B** 결정 방식 | 근거 대조 자체를 건너뛰고 다른 방식으로 고름 | 3 |
| **X** 시험 실행 | 시간 · 주의가 정상 절차를 깨뜨림 | 2 |
| L 듣기 | **v0.1 에 넣지 않는다** — §8 | 0 |

**B 와 X 는 합치지 않는다**(§9 dry run 근거). 차이: B 는 시간 · 주의가 정상이어도 고르는 **방식**이 근거 대조를 건너뛴 것, X 는 정상 절차를 할 수 있었는데 **조건**(남은 시간 · 집중 붕괴)이 막은 것이다. 처방이 다르다(B → 풀이 절차 교정, X → 시간 배분 · 실전 훈련).

**추측(guess)은 원인 코드가 아니다** — 이전 초안의 `B.guess` 는 폐기. 추측했다는 것은 「무엇이 실패했는지 모른다」는 뜻이므로 증거 충분성 쪽 신호다(§2). 시간 때문에 추측했다는 증거가 있으면 `X.time`, 아니면 `insufficient_evidence`.

## 2. 증거 충분성(Evidence Adequacy) — 원인과 따로 매긴다

| 등급 | 있는 것 | 판정 |
|---|---|---|
| **A0** 결과만 | 고른 번호 · 정오(· 확신도) | 원인 판정 **금지** → `insufficient_evidence` |
| **A1** 자기보고만 | 확신도 · 학생이 고른 범주(단어/문장/흐름/근거/선지/시간)뿐, 구체적 내용 없음 | 가설만. 판정은 `insufficient_evidence`(학생 범주는 메모로 남긴다) |
| **A2** 구체적 과정 증거 1종 | 내용 있는 고른 이유 · 막힌 곳 표시 · 학생 해석 · 시험 상황 기록 중 하나 | 원인 **제안** 가능 |
| **A3** 서로 독립된 증거 2종 이상이 같은 방향 | 예: 막힌 곳 + 틀린 해석이 같은 구절을 가리킴 | 사람 확인(검수 승인) 후보 |

- 「내용 있는 고른 이유」 = 지문 · 선지의 특정 부분이나 학생의 판단 과정이 드러나는 문장. 「헷갈려서」「어려워서」「그냥」은 내용 없음(A1).
- 학생이 고른 범주(self_category)는 **증거가 아니라 주장**이다. 다른 증거와 어긋나면 증거를 따른다.
- 증거끼리 어긋나면(막힌 곳은 낱말인데 이유는 선지 비교) 등급과 별개로 결과 `inconsistent_evidence` 를 쓸 수 있다.

### 판정 결과(outcome) — 원인을 못 고르는 것도 정상 결과다

결과는 **증거가 무엇을 하는가**로 정한다. 판정자의 확신도가 아니다(rev3 고정 — 2026-10-04 사용자 지시).

| 결과 | 정의 | 아닌 것 |
|---|---|---|
| `identified` | 지금 과정 증거가 **경쟁 원인을 실제로 배제해** 한 원인을 지지한다 | 「60% 정도 확신」도 증거가 한쪽을 지지하면 identified — 확신이 낮으면 `judge_confidence: low` 로 따로 적는다 |
| `multiple_plausible` | 원인 판정을 시도할 증거는 있는데(A2 이상), **둘 이상의 원인을 지금 증거로 구별할 수 없다** — 후보를 적고 primary 는 비운다 | 확신이 낮다는 뜻이 아니다. 후보마다 최소 증거가 있어야 한다(R9 · R10) |
| `insufficient_evidence` | 원인을 판정할 만한 과정 증거가 **애초에 없다**(A0 · A1, 또는 무엇이 실패했는지까지 말하지 않음) | 후보가 둘 보이는 것과 다르다 — 후보가 하나라도 최소 증거를 갖추면 여기가 아니다 |
| `inconsistent_evidence` | 서로 다른 증거가 **동시에 참일 수 없는** 원인을 지지해 하나의 설명을 만들 수 없다 | 증거가 다른 단계를 가리킬 뿐이면 아니다(R3), 자기진단 vs 구체 증거면 아니다(R4) |

**판정자 확신도(`judge_confidence`: low · medium · high)는 결과와 따로 적는다.** 결과를 정한 뒤 「이 판정을 다시 해도 같을까」를 적는다 — 집계 · 승격에는 쓰지 않고 사람 dry run 분석(확신도와 불일치의 관계)에만 쓴다.

**판정 제외(`unsupported_stimulus`)** — 학생 증거가 가리켜야 할 자극이 DB 에 없는 문항(도표 · 그림의 값, 듣기 음성 · 대본)은 판정하지 않는다. 원인 결과가 아니라 **판정 대상 밖**이며 taxonomy 의 coverage 실패로 세지 않는다. 지금 해당: 도표(`R-CHART`) 문항 · 듣기 전체.

> DB(`csat_ec_judgment.outcome`)에는 지금 `code · no_cause · insufficient_evidence · no_fitting_code` 만 있다. `multiple_plausible` · `inconsistent_evidence` 를 그대로 저장하려면 v0.1 시드와 함께 CHECK 확장 마이그레이션이 필요하다 — §10 J 미결.

## 3. primary · contributing — 「최초의 결정적 실패」

- **primary = 근거로 확인되는 가장 이른 결정적 실패.** 「결정적」 = 그 실패가 없었다면 이 오답에 이르지 않았을 것이라고 증거로 말할 수 있다.
- **contributing = 그 뒤에 더해졌거나 함께 작용한 실패**(최대 2). 연쇄를 전부 적지 않는다 — 낱말을 몰라 → 문장을 잘못 읽어 → 요지를 잘못 잡아 → 오답, 이면 primary `V.unknown_word`, 증거가 따로 있을 때만 contributing 하나.
- 마지막 단계(「선지를 잘못 골랐다」)만 적지 않는다 — 결과를 원인으로 적는 것이다.
- 첫 실패가 증거로 안 보이면 primary 를 비우고 보이는 것만 contributing 으로 두거나 `insufficient_evidence`.
- 원인 그래프(V → S → R → E)를 별도 구조로 만들지 않는다. 연쇄는 판정 메모에 쓴다.

## 4. 판정자 decision flow

목록에서 고르지 않는다. 아래 순서로 좁힌 뒤 family 안에서 leaf 를 고른다.

```
Q-  자극 증거가 DB 에 있는 문항인가(도표 · 그림 · 듣기 아님)?   아니오 → unsupported_stimulus (판정 제외)
Q0  증거 충분성 A2 이상인가?                         아니오 → insufficient_evidence (A1 이면 학생 범주를 메모)
Q1  구체적 증거끼리 동시에 참일 수 없는가?          예   → inconsistent_evidence (자기진단 vs 증거는 R4, 단계가 다를 뿐이면 R3)
Q2  시간 부족 · 집중 붕괴 · 표기 실수가 정상 절차를 막았다는 진술 · 기록이 있는가? (기록만 있고 그런 진술이 없으면 R1)
                                                     예   → X (X.time / X.attention). 영어 처리 실패 증거가 따로 있으면 그것을 contributing
Q3  학생이 발문(묻는 것)을 다르게 이해했는가?        예   → E.task_misread
Q4  학생의 해석 · 막힌 곳이 한 문장 안에서 이미 어긋났는가?
     4a 낱말 · 덩어리 뜻이 비었거나 틀렸나?          예   → V
     4b 낱말 뜻은 맞는데 구조 · 수식 · 범위 · 형태가 틀렸나? 예 → S
Q5  각 문장은 맞게 읽었는데 문장 사이 연결 · 지시 · 중심 · 함축에서 어긋났는가?   예 → R
Q6  글은 맞게 이해했는데 근거 위치 · 선지 대조에서 틀렸는가?                     예 → E
Q7  근거 대조 없이 상식 · 표면 낱말 · 첫 인상으로 골랐는가?                       예 → B
Q8  어디에도 안 맞는데 증거는 충분하다                                            → no_fitting_code (코드북 보강 후보로 기록)
끝  후보가 Q4–Q7 에서 둘 이상 남았나?
     하나만 최소 증거를 갖춤(나머지는 배제됨)                                     → identified (+ contributing)
     둘 이상이 최소 증거를 갖추고 증거로 서로 배제되지 않음                        → multiple_plausible (후보 기록, primary 비움)
     → 그 다음 판정자 확신도(judge_confidence)를 따로 적는다 — 결과를 바꾸지 않는다
```

- **Q4 → Q5 → Q6 순서가 핵심이다.** 더 이른 단계의 실패 증거가 있으면 뒤 단계 코드를 primary 로 쓰지 않는다.
- Q7(B)은 Q6(E)보다 뒤다 — 학생이 실제로 대조했다는 흔적(근거 문장을 가리킴)이 있으면 E, 대조 흔적이 없고 다른 결정 근거(상식 · 낱말 겹침 · 「제일 그럴듯해서」)가 있으면 B.

### 4-1. 적용 규칙(rev2 — dry run 1회차 불일치에서 추가)

| # | 상황 | 규칙 |
|---|---|---|
| R1 | 시간 기록(남은 시간 · 풀이 시간)이 있지만 학생 진술이 「시간 때문에 건너뛰었다/못 읽었다」가 아니다 | **Q2 에서 멈추지 않는다.** 시간 기록은 contributing `X.time` 후보일 뿐, primary 는 Q3 이하에서 찾는다. X 를 primary 로 쓰려면 「시간 · 집중 때문에 단계를 못 했다」는 **학생 진술**, 또는 지문 · 선지의 일부를 **읽지 않았다는 증거**(막힌 곳 · 이유가 앞부분에만 있고 「뒤는 못 봤다」)가 있어야 한다. 풀이 시간 수치만으로는 정하지 않는다(rev3 — 「짧은 시간」 기준이 판정자마다 달랐다) |
| R2 | `X.time` vs `X.attention` | **단계를 건너뛰었으면 time**(안 읽음 · 대조 안 함), **읽었는데 잘못 봤으면 attention**(not · un- · 숫자 · 마킹). 서둘러서 잘못 봤다면 primary attention, contributing time |
| R3 | 증거가 서로 다른 처리 단계를 가리킨다(예: 해석은 S 오류, 이유는 같은 낱말) | 둘 다 사실일 수 있으면 **inconsistent 가 아니다** — 더 이른 단계(Q4 → Q5 → Q6 → Q7)의 **구체적 증거**를 primary, 뒤 단계는 contributing. `inconsistent_evidence` 는 증거끼리 **동시에 참일 수 없을 때만**(예: 「charred 를 몰랐다」 + 그 문장 해석이 정확) |
| R4 | 학생의 자기진단(「단어를 몰랐다」 · self_category)과 구체적 증거(해석 · 막힌 곳)가 다르다 | **구체적 증거를 따라 identified**. 자기진단은 메모로 남긴다. 구체적 증거끼리 충돌할 때만 R3 의 inconsistent |
| R5 | 연결어 · 지시 표현(However · Other · this · such) 을 단서로 썼는데 틀렸다 | 담화 처리다 → R. `B.surface_match` 는 **내용어**(명사 · 동사 · 형용사)가 글과 선지/문장에 **같거나 비슷하게 반복된다는 것만**을 근거로 들었을 때. **R 안에서**(rev3): `R.reference` = 학생이 대명사 · 지시 표현 · 대용 표현(this/these + 명사 · such · the former · Others)이 **가리키는 대상 · 개념을 잘못 이었다는 직접 증거**가 있다. `R.relation` = **참조 대상은 맞게 파악했는데** 명제 · 문장 사이의 대조 · 인과 · 예시 · 일반-구체 · 조건 · 전개 관계를 잘못 구성했다는 증거가 있다. 둘 다 진술했으면 먼저 틀린 쪽(대개 reference)을 primary. 참조 대상을 어떻게 잡았는지 증거가 없으면 relation 으로 추정하지 않는다 |
| R6 | 학생이 말의 **사전 뜻 하나**를 썼는데 글에서는 다른 뜻이다 | 검사(rev3): **글에서 쓰인 그 뜻이 사전에 올라 있는가?** 올라 있으면(다의어 · 극성이 다른 뜻 — fiction=허구, problem=문제점) `V.wrong_sense`, 고정 표현이면 `V.multiword`. 사전에 없고 **글이 만든 비유 · 확장 의미**(밑줄 친 비유 · 글쓴이가 새로 비유한 구절)면 `R.inference`. **판정 단위(rev4)**: 검사는 **학생 증거가 실패를 보인 단위**에 적용한다 — ① 학생이 구절 안 **한 낱말**에 다른 사전 뜻을 넣었고 그 뜻 때문에 해석이 틀었다 → 그 낱말에 R6 적용(`V.wrong_sense`) ② 낱말들의 사전 뜻은 거의 맞게 잡았는데(예: divorce=분리) **글쓴이가 그 구절로 만든 비유 · 대응**(hands=육체노동 · head=정신노동)을 잘못 옮겼다 → 구절 단위로 R6 적용(`R.inference`) ③ 둘 다 보이면 R3 단계 순서로 더 이른 낱말 실패(V)를 primary, 구절 비유 실패를 contributing. 낱말 뜻이 맞았는지 증거가 없으면 ①로 추정하지 않는다 |
| R7 | 대명사 · 재귀대명사가 **한 문장 안**에서 무엇을 가리키는지 틀렸다 | `R.reference` 에 포함한다(지시 대상 추적은 문장 안팎을 가리지 않는다) |
| R8 | 어법 — 학생이 말한 **구조**가 틀렸는가 | 「동사가 둘」「주어가 ~」처럼 구조 진술이 틀렸으면 `S.core_structure`, 구조 진술은 맞고 형태 규칙만 틀렸으면 `S.form_rule`. 구조 진술이 없으면 `multiple_plausible`(S.core_structure · S.form_rule) |
| R9 | A2 인데 증거가 실패 단계까지 말하지 않는다 | `multiple_plausible` 은 **두 코드가 각각 최소 증거를 갖출 때만**. 어느 코드도 최소 증거가 없으면 `insufficient_evidence` |
| R10 | identified 와 multiple_plausible 사이(rev3 — 2회차 불일치의 대부분) | 두 후보 중 **하나만 최소 증거를 갖추면 identified**(다른 하나는 contributing 이나 메모). 둘 다 갖췄고 R3 의 단계 순서로도 앞뒤가 정해지지 않을 때만 multiple_plausible. 「다른 해석도 가능해 보인다」는 느낌은 multiple_plausible 의 근거가 아니다 |
| R12 | V 세 코드가 겹칠 때(rev4) | ① 학생이 그 자리에 넣은 뜻이 **그 낱말의 어떤 사전 뜻도 아니다**(추측 · 빈칸 채우기) → 학생 확신도와 무관하게 `V.unknown_word`. 그 낱말의 **실제 사전 뜻 하나**를 넣었다 → `V.wrong_sense` ② **고정 표현**(사전에 하나의 뜻으로 오른 숙어 · 구동사 · 연어) 안의 한 낱말에 다른 사전 뜻을 넣어 표현 전체를 낱말 합으로 읽었다 → `V.multiword`(표현이 판정 단위 — R6 ①은 고정 표현 밖 낱말에만) ③ 학생 증거가 표현 전체 직역인지 한 낱말의 다른 뜻인지 구별되지 않으면 둘 다 최소 증거를 갖출 때만 `multiple_plausible`(V.multiword · V.wrong_sense), 아니면 R9 |
| R11 | `B.no_verification` | **contributing 전용**(rev3). 「확인하지 않았다」는 무엇을 잘못 이해했는지를 말하지 않는다 — 다른 primary 가 없으면 `insufficient_evidence`(메모에 남김). dry run 202판정에서 primary 1회 · 보조 15회 |

## 5. 코드 정의(19개)

각 코드: 정의 · 포함 · 제외 · 최소 증거 · primary 가능 여부 · 인접 코드 · 가르는 규칙 · 예 · 반례 · 판정 불가 예 · 연결 진단 후보.
예시는 실제 문항을 베끼지 않고 구성한 짧은 문장이다. 실제 문항 사례는 [CASES.md](./CASES.md).

### V — 어휘 처리

#### `V.unknown_word` 모르는 낱말
- **정의**: 이 attempt 에서 학생이 판단에 필요한 낱말의 뜻을 **얻지 못해**(모름 · 비워 둠) 정답 판단에 실패했다는 증거가 있을 때.
- **포함**: 학생이 특정 낱말을 「몰랐다」고 표시하거나, 해석에서 그 낱말을 빼먹고 / 엉뚱한 추측으로 채웠고, 그 낱말이 정답 판단에 필요한 자리에 있다.
- **제외**: 아는 뜻이 있는데 이 문맥의 뜻과 다르다 → `V.wrong_sense`. 낱말은 다 아는데 덩어리(숙어 · 구동사 · 연어) 뜻이 틀렸다 → `V.multiword`. 모르는 낱말이 있었지만 판단과 무관한 자리다 → 원인 아님.
- **최소 증거**: 막힌 곳(그 낱말) 또는 해석 중 하나 + 그 낱말이 판단 자리에 있음을 판정자가 확인.
- **primary**: 가능(가장 흔한 최초 실패).
- **인접**: `V.wrong_sense` · `S.core_structure` · `R.main_point`.
- **가르는 규칙**: 학생 해석에 그 낱말 자리의 뜻이 **없거나 추측**이면 unknown, **다른 확정된 뜻**이면 wrong_sense. 「확정된 뜻」 = 그 낱말의 **실제 사전 뜻**이다 — 채운 뜻이 어떤 사전 뜻도 아니면 학생이 확신했어도 unknown(R12 ①).
- **예**: 「`mitigate` 를 몰라서 그 문장을 '무언가를 한다' 정도로만 읽었다」 + 막힌 곳 mitigate.
- **반례**: 「`mitigate` 를 '강화하다'로 알았다」 → wrong_sense.
- **판정 불가 예**: 「모르는 단어가 많았어요」 + 막힌 곳 없음 → A1, insufficient.
- **연결 진단 후보**: V(어휘).

#### `V.wrong_sense` 다른 뜻으로 읽음
- **정의**: 이 attempt 에서 학생이 낱말을 **아는 다른 뜻**(1차 뜻 · 다의어의 다른 뜻 · 비슷한 철자 낱말의 뜻)으로 처리해 정답 판단에 실패했다는 증거가 있을 때.
- **포함**: 학생 해석에 그 낱말이 문맥과 다른 확정 뜻으로 들어 있다. 어휘 문항(문맥상 낱말 쓰임)에서 낱말 뜻 자체를 다르게 잡은 경우 포함.
- **제외**: 뜻을 몰랐다 · 채운 뜻이 그 낱말의 사전 뜻이 아니다 → unknown_word(R12 ①). 고정 표현 안의 한 낱말을 다른 사전 뜻으로 읽어 표현 전체를 낱말 합으로 처리했다 → `V.multiword`(R12 ②). 낱말 뜻은 맞는데 문장 안 역할 · 범위가 틀렸다 → S. 낱말 뜻은 맞는데 글 흐름상 반대가 와야 한다는 것을 못 봤다(어휘 문항) → `R.relation`. 낱말 뜻은 맞게 잡았는데 글쓴이가 만든 구절 비유를 잘못 옮겼다 → `R.inference`(R6 ②).
- **최소 증거**: 해석 또는 고른 이유에 그 낱말의 학생 쪽 뜻이 드러나야 한다.
- **primary**: 가능.
- **인접**: `V.unknown_word` · `V.multiword` · `R.relation`.
- **가르는 규칙**: 어휘 문항에서 「이 낱말은 이런 뜻이라 맞다」고 했는데 그 뜻이 틀렸으면 V, 뜻은 맞게 알면서 「앞 문장과 같은 방향」이라고 잘못 연결했으면 R.
- **예**: 「`novel` 을 '소설'로 읽어 '소설 같은 방법'으로 해석했다」.
- **반례**: 「`novel` 이 '새로운'인 건 알았는데 앞에서 전통을 칭찬해서 반대 말이 와야 한다고 생각했다」 → R.relation.
- **판정 불가 예**: 고른 이유 「단어 뜻이 헷갈렸어요」만 → A1.
- **연결 진단 후보**: V.

#### `V.multiword` 덩어리 뜻을 놓침
- **정의**: 이 attempt 에서 학생이 각 낱말은 처리했으나 **여러 낱말이 이루는 고정 표현**(구동사 · 숙어 · 연어 · 관용 비유)의 뜻을 낱말 합으로 처리해 판단에 실패했다는 증거가 있을 때.
- **포함**: 해석이 낱말별 직역이고 고정 표현의 뜻과 어긋난다(예: `turn down` → '아래로 돌리다').
- **제외**: 표현 중 한 낱말을 몰랐다 → unknown_word. 고정 표현이 아닌 자리의 한 낱말을 다른 사전 뜻으로 읽었다 → `V.wrong_sense`(R12 ②). 문장 구조상 어디에 붙는지를 잘못 잡았다 → `S.attachment`. 밑줄 친 비유가 글에서 가리키는 뜻(함축)을 못 잡았다 → `R.inference`.
- **최소 증거**: 해석(직역이 드러나야 함) 또는 막힌 곳이 그 표현 전체.
- **primary**: 가능.
- **인접**: `V.wrong_sense` · `R.inference` · `S.attachment`.
- **가르는 규칙**: 사전에 하나의 뜻으로 올라 있는 고정 표현이면 multiword, 글쓴이가 그 글에서 만든 비유면 R.inference.
- **예**: 「`fall short of` 를 '~보다 짧게 떨어지다'로 읽어 기대를 넘었다고 생각」.
- **반례**: 함축 문항의 밑줄 「the canvas becomes the conversation」을 글의 논지로 못 옮김 → R.inference.
- **판정 불가 예**: 막힌 곳이 표현인데 해석 · 이유 없음 → A2 이지만 unknown/multiword 구별 불가 → `multiple_plausible`.
- **연결 진단 후보**: V.

### S — 문장 처리

#### `S.core_structure` 문장 뼈대를 잘못 잡음
- **정의**: 이 attempt 에서 학생이 한 문장의 **주어 · 동사 · 절의 경계**(어디까지가 주어인지 · 본동사가 무엇인지 · 관계절/명사절이 어디서 끝나는지 · 생략 · 도치)를 잘못 잡아 그 문장의 뜻을 틀리게 구성했다는 증거가 있을 때.
- **포함**: 해석에서 주어와 목적어가 바뀌었다 · 관계절 동사를 본동사로 읽었다 · 도치 · 생략을 못 풀었다. 어법 문항에서 주어를 잘못 찾아 수일치를 틀렸다.
- **제외**: 뼈대는 맞는데 수식어가 어느 말에 붙는지 틀렸다 → `S.attachment`. 부정 · 비교 · 조건의 범위 · 방향만 틀렸다 → `S.operator_scope`. 구조는 맞게 봤는데 문법 형태 규칙(분사 태 · 관계사 선택)을 모른다 → `S.form_rule`.
- **최소 증거**: 해석(구조가 드러나는 오역) 또는 막힌 곳 + 「어디까지가 주어인지 모르겠다」류 이유.
- **primary**: 가능.
- **인접**: `S.attachment` · `S.form_rule` · `V.unknown_word`.
- **가르는 규칙**: 해석에서 **문장 성분이 바뀌었으면** core, 성분은 맞고 꾸밈 관계만 바뀌었으면 attachment.
- **예**: 「The idea that the experts rejected was simple」을 「전문가들이 그 생각을 거절했다는 생각은 단순했다」.
- **반례**: 「전문가들이 거절한 그 생각이 단순했다」로 바로 읽었으나 '단순하다'를 '쉽다'로 → V.wrong_sense.
- **판정 불가 예**: 「문장이 길어서 해석이 안 됐어요」 + 막힌 곳 없음 → A1.
- **연결 진단 후보**: S(문장 해석).

#### `S.attachment` 꾸밈 · 연결 대상을 잘못 붙임
- **정의**: 이 attempt 에서 학생이 수식어(전치사구 · 분사구 · to부정사 · 관계절 · 부사)나 대명사가 아닌 **문장 안의 연결어가 어느 말에 걸리는지**를 잘못 붙여 문장 뜻이 바뀌었다는 증거가 있을 때.
- **포함**: 「~하는 사람들의 ~」에서 수식 대상을 바꿈 · and 로 이어진 병렬 짝을 잘못 묶음.
- **제외**: 문장 성분 자체가 바뀜 → core_structure. 문장 사이의 대명사 · 지시어 → `R.reference`.
- **최소 증거**: 해석(꾸밈 관계가 드러나야 함). 막힌 곳만으로는 core 와 구별되지 않는 경우가 많다 → 그때는 `multiple_plausible`.
- **primary**: 가능.
- **관찰 상태(rev3)**: dry run 101건 · 202판정에서 **한 번도 쓰이지 않았다**(작성자도 이 기제로 쓴 사례 0). 실제 Pilot 에서도 관찰 0 이면 `S.core_structure` 로 병합한다 — 「독립적으로 관찰할 수 없음」(병합 기준).
- **인접**: `S.core_structure` · `R.reference` · `V.multiword`.
- **가르는 규칙**: 한 문장 안이면 S, 앞 · 뒤 문장의 말을 가리키는 문제면 R.reference.
- **예**: 「students with limited access to libraries in rural areas」를 「시골의 도서관에 접근이 제한된 학생」 vs 「도서관 접근이 제한된, 시골 지역의 학생」 — 판단에 쓰이는 정보가 달라진 경우.
- **반례**: 「it 이 앞 문장의 '실험'인지 '결과'인지」 → R.reference.
- **판정 불가 예**: 막힌 곳이 긴 명사구 전체이고 해석 없음 → core/attachment 구별 불가.
- **연결 진단 후보**: S.

#### `S.operator_scope` 부정 · 비교 · 조건의 범위 · 방향
- **정의**: 이 attempt 에서 학생이 부정(not · no · hardly · fail to · without) · 비교(more/less than · as … as · rather than · the -er) · 조건 · 양보 · 정도(only · too … to) 표현이 **무엇을 얼마나 뒤집거나 제한하는지**를 잘못 처리해 문장 뜻이 반대 · 다른 강도가 됐다는 증거가 있을 때.
- **포함**: 해석에서 부정이 빠지거나 다른 말에 걸림 · 비교의 두 대상이 바뀜 · `not A but B` 를 반대로.
- **제외**: 발문의 NOT/불일치를 놓침 → `E.task_misread`. 선지의 강도(always · only)를 지문과 비교하지 않음 → `E.option_mismatch`. 지문 문장은 맞게 읽고 문장 사이 대조(However)를 놓침 → `R.relation`.
- **최소 증거**: 해석(부정 · 비교의 처리 결과가 보여야 함).
- **primary**: 가능.
- **인접**: `R.relation` · `E.option_mismatch` · `X.attention`.
- **가르는 규칙**: **지문 한 문장 안**의 연산자를 틀리게 처리했으면 S, 선지 문장의 강도를 지문과 대조하지 않았으면 E, 읽을 수 있었는데 훑다가 not 을 못 봤다는 증거(시간 · 「못 봤다」)면 X.attention.
- **예**: 「Few people would deny that…」을 「…를 부정할 사람들이 있다」로.
- **반례**: 지문은 「대부분」인데 「항상」 선지를 고름, 지문 해석은 맞음 → E.option_mismatch.
- **판정 불가 예**: 「not 이 있었나요?」 같은 회상만 → A1.
- **연결 진단 후보**: S.

#### `S.form_rule` 문법 형태 판단 규칙
- **정의**: 이 attempt 에서 학생이 문장 구조는 맞게 파악했으나 **형태를 고르는 규칙**(능동/수동 분사 · 관계사 what/that/which · 동사/준동사 자리 · 대명사 수 · 형용사/부사 · 병렬 형태)을 틀리게 적용해 어법 판단에 실패했다는 증거가 있을 때.
- **포함**: 어법 문항에서 「주어가 사물이라 능동」처럼 틀린 규칙을 이유로 댐 · 규칙을 모른다고 표시.
- **제외**: 주어를 잘못 찾아 수일치를 틀림 → core_structure(구조 파악 실패가 먼저). 낱말 뜻을 몰라 문장을 못 읽음 → V.
- **최소 증거**: 고른 이유에 학생이 쓴 규칙(틀린 규칙) 또는 「~ 규칙을 몰랐다」 + 막힌 곳이 그 형태.
- **primary**: 가능. **이 코드는 거의 어법 문항에서만 나온다** — 그래도 원인은 문항 유형이 아니라 학생이 쓴 규칙이다.
- **인접**: `S.core_structure` · `X.attention`.
- **가르는 규칙**: 학생이 **구조를 어떻게 봤는지**가 맞으면 form_rule, 구조 파악이 틀렸으면 core.
- **예**: 「which 다음에 완전한 문장이 와도 되는 줄 알았다」.
- **반례**: 「The number of students」의 주어를 students 로 봐서 are 가 맞다고 함 → core_structure.
- **판정 불가 예**: 어법 문항 오답 + 「감으로」 → B 가 아니라 insufficient(규칙 · 구조 증거 없음).
- **연결 진단 후보**: S.

### R — 글 이해

#### `R.reference` 지시 대상 추적 실패
- **정의**: 이 attempt 에서 학생이 대명사 · 재귀대명사 · 지시어(this · such · these + 명사 · the former) · 대용어가 **무엇을 가리키는지**(앞 · 뒤 문장, 또는 같은 문장 안 — 규칙 R7)를 잘못 이어 글의 내용 · 순서를 틀리게 구성했다는 증거가 있을 때.
- **포함**: 순서 · 삽입 문항에서 「this problem 이 (A)의 문제라고 생각」이 틀림 · 지칭 대상 문항에서 등장인물을 바꿈.
- **제외**: 한 문장 안의 수식 관계 → S.attachment. 지시어가 아닌 연결어(however · thus)의 논리 → R.relation.
- **최소 증거**: 이유나 해석에 학생이 연결한 지시 대상이 드러나야 한다.
- **primary**: 가능.
- **인접**: `R.relation` · `S.attachment`.
- **가르는 규칙**: 학생이 틀린 것이 「무엇을 가리키나」면 reference, 「어떤 관계로 이어지나」면 relation.
- **예**: 「they 를 연구자들로 봤는데 실험 참가자였다」.
- **반례**: 「(B)가 However 로 시작해서 앞 내용과 반대일 줄 알았다」 → R.relation.
- **판정 불가 예**: 순서 오답 + 「흐름이 이상했다」만 → A1.
- **연결 진단 후보**: R(독해).

#### `R.relation` 문장 사이 관계를 잘못 연결
- **정의**: 이 attempt 에서 학생이 각 문장과 참조 대상은 맞게 파악했으나 문장 · 단락 사이의 **논리 관계**(대조 · 인과 · 예시 · 일반화 · 양보 · 시간 순서 · 문제-해결)를 잘못 이어 글의 흐름을 틀리게 구성했다는 증거가 있을 때.
- **포함**: However 앞뒤를 같은 방향으로 읽음 · 예시를 주장으로 읽음 · 빈칸에서 앞 문장과 반대 방향이 와야 하는데 같은 방향을 고름(낱말 뜻은 앎) · 무관 문장 문항에서 흐름 이탈을 못 봄.
- **제외**: 문장 하나의 해석이 틀림 → V/S. 관계는 맞게 봤는데 글 전체의 중심을 잘못 잡음 → R.main_point. 지시어 대상 → R.reference.
- **최소 증거**: 학생이 두 부분을 **어떤 관계로 봤는지**가 이유 · 해석에 드러나야 한다.
- **primary**: 가능.
- **인접**: `R.main_point` · `R.reference` · `S.operator_scope` · `V.wrong_sense`.
- **가르는 규칙**: 관계가 **두 문장(부분) 사이**의 것이면 relation, **글 전체에서 무엇이 중심인가**의 문제면 main_point.
- **예**: 「앞에서 단점을 말하고 But 이후는 장점인데, 계속 단점 얘기인 줄 알고 부정적인 말을 넣었다」.
- **반례**: 「예시 부분이 길어서 그게 주제인 줄 알았다」 → R.main_point.
- **판정 불가 예**: 빈칸 오답 + 확신도 guess 만 → A1.
- **연결 진단 후보**: R.

#### `R.main_point` 글의 중심 · 위계를 잘못 잡음
- **정의**: 이 attempt 에서 학생이 문장들은 처리했으나 **글 전체에서 무엇이 중심 주장이고 무엇이 뒷받침 · 예시 · 배경인지**를 잘못 정해 요지 · 주제 · 제목 · 요약 판단에 실패했다는 증거가 있을 때.
- **포함**: 예시 · 통념(도입부 반박 대상)을 주장으로 고름 · 세부 하나를 전체로 · 글쓴이 주장과 인용된 남의 주장을 바꿈.
- **제외**: 중심을 맞게 잡았는데 선지가 그 중심을 과대 · 과소 진술한 것을 못 가림 → `E.option_mismatch`. 문장 사이 관계를 틀려서 중심이 틀어짐(연결 오류가 먼저 보임) → R.relation primary.
- **최소 증거**: 학생이 글의 중심을 무엇으로 봤는지(이유 · 해석)가 드러나야 한다.
- **primary**: 가능.
- **인접**: `R.relation` · `E.option_mismatch` · `R.inference`.
- **가르는 규칙**: 학생이 말한 「이 글의 요지」가 틀렸으면 main_point, 요지는 맞게 말했는데 그걸 담지 못한 선지를 골랐으면 E.option_mismatch.
- **예**: 「처음에 '사람들은 흔히 ~라고 믿는다'가 글쓴이 주장인 줄 알았다」.
- **반례**: 「요지는 '습관이 중요하다'인 걸 알았는데 ③이 그 말 같아서」(③은 범위가 더 넓음) → E.option_mismatch.
- **판정 불가 예**: 주제 오답 + 「대충 그런 내용 같아서」 → 대조 흔적 없음, B.no_verification 후보이나 무엇을 중심으로 봤는지 없음 → insufficient 또는 B(Q7 판단).
- **연결 진단 후보**: R.

#### `R.inference` 함축 · 추론을 잘못 구성
- **정의**: 이 attempt 에서 학생이 글에 직접 쓰이지 않은 뜻(밑줄 비유의 의미 · 글쓴이의 태도 · 함축된 결론 · 인물 심경)을 **글의 근거에서 잘못 이끌어 내거나 문자 그대로 읽어** 판단에 실패했다는 증거가 있을 때.
- **포함**: 함축 문항에서 밑줄을 문자 그대로 해석 · 근거 없이 지나치게 나아간 추론 · 심경 변화의 방향을 반대로.
- **제외**: 밑줄이 사전상 숙어인데 몰랐다 → V.multiword. 글 밖 상식으로 결론을 채움 → `B.outside_knowledge`. 글의 중심 주장을 잘못 잡아 함축이 틀어짐(중심 오류가 먼저 보임) → R.main_point primary.
- **최소 증거**: 학생이 이끌어 낸 뜻(해석 · 이유)과 그 근거로 삼은 부분.
- **primary**: 가능.
- **인접**: `R.main_point` · `V.multiword` · `B.outside_knowledge`.
- **가르는 규칙**: 추론의 근거를 **글에서** 가져왔는데 잘못 이었으면 R.inference, 근거를 **글 밖에서** 가져왔으면 B.outside_knowledge.
- **예**: 「'시계를 거꾸로 돌린다'를 실제 시계 얘기로 봤다」.
- **반례**: 「원래 운동은 몸에 좋으니까」로 결론 선택 → B.outside_knowledge.
- **판정 불가 예**: 함축 오답 + 막힌 곳이 밑줄 전체 + 이유 없음 → V.multiword · R.inference 구별 불가 → `multiple_plausible`.
- **연결 진단 후보**: R.

### E — 문제 · 선지 판단

#### `E.task_misread` 묻는 것을 다르게 이해
- **정의**: 이 attempt 에서 학생이 **발문이 요구하는 것**(일치 vs 불일치 · 가장 적절한 vs 적절하지 않은 · 밑줄의 의미 vs 밑줄 자체 · 글의 목적 vs 내용 · 요약문 빈칸 (A)(B) 대응)을 다르게 이해해 다른 기준으로 답을 고른 증거가 있을 때.
- **포함**: 불일치 문항에서 일치하는 선지를 고르고 「지문에 있는 내용이라서」라고 씀 · 목적 문항에서 세부 내용을 고름 · 무관 문장 문항에서 「가장 중요한 문장」을 찾음.
- **제외**: 발문은 알았는데 훑다가 NOT 을 놓쳤다는 증거(「다시 보니 not 이었다」 · 시간 기록) → `X.attention`. 지문 안 부정을 잘못 처리 → S.operator_scope.
- **최소 증거**: 고른 이유가 발문과 다른 기준을 드러낸다.
- **primary**: 가능.
- **인접**: `X.attention` · `S.operator_scope` · `R.main_point`.
- **가르는 규칙**: 학생이 **다른 기준을 갖고** 골랐으면 task_misread, 기준은 맞게 알았는데 순간 놓쳤다는 증거가 있으면 X.attention. 구별 증거가 없으면 task_misread(관찰 가능한 쪽).
- **예**: 불일치 문항에서 「④는 지문에 그대로 있어서 골랐어요」.
- **반례**: 「불일치인 거 알았는데 시간이 없어서 일치를 찾다가 마킹했다」 → X.attention.
- **판정 불가 예**: 불일치 문항 오답 + 이유 없음 → A0.
- **연결 진단 후보**: E(근거 판단).

#### `E.evidence_location` 근거 위치를 잘못 대응
- **정의**: 이 attempt 에서 학생이 글은 맞게 읽었으나 선지 · 빈칸 · 문항이 요구하는 정보에 **글의 다른 부분을 대응시켜** 판단한 증거가 있을 때.
- **포함**: 내용 일치에서 선지를 다른 인물 · 다른 연도 · 다른 항목 문장과 대조 · 도표 문항에서 다른 행 · 열을 읽음 · 빈칸의 단서를 빈칸과 무관한 문단에서 가져옴.
- **제외**: 맞는 위치를 봤는데 그 문장을 오역 → V/S. 맞는 위치 · 맞는 해석인데 선지와의 차이를 못 봄 → E.option_mismatch. 숫자를 잘못 읽음(위치는 맞음) → X.attention.
- **최소 증거**: 막힌 곳 · 고른 이유가 학생이 근거로 쓴 **다른 위치**를 가리킨다.
- **primary**: 가능.
- **인접**: `E.option_mismatch` · `R.reference` · `X.attention`.
- **가르는 규칙**: 학생이 가리킨 근거 문장이 **틀린 곳**이면 location, **맞는 곳**인데 선지 판단이 틀렸으면 option_mismatch.
- **예**: 「안내문에서 '토요일 휴관'을 봤다」(실제로는 다른 시설의 휴관 정보).
- **반례**: 맞는 줄을 가리키며 「거의 같은 말이라서」(실제로 '일부'와 '전부' 차이) → option_mismatch.
- **판정 불가 예**: 도표 오답 + 「계산 실수한 것 같아요」 → X.attention 후보이나 어느 숫자인지 없음 → insufficient.
- **연결 진단 후보**: E.

#### `E.option_mismatch` 선지와 글의 차이를 못 가림
- **정의**: 이 attempt 에서 학생이 글의 해당 부분을 맞게 이해했으나 **선지가 그 내용과 범위 · 강도 · 방향 · 관계(주체 · 인과 · 대상)에서 다르다는 것**을 가리지 못해 오답을 받아들였거나, 정답 선지가 글을 다른 말로 바꿔 쓴 것(재진술)을 알아보지 못해 버린 증거가 있을 때.
- **포함**: 「글에도 비슷한 말이 있어서」(실제로 '일부'→'모두') · 정답이 다른 말로 바꿔 써서 「글에 없는 말이라」 버림(학생이 글 내용은 맞게 말함) · 요약문에서 (A)는 맞고 (B)의 방향을 거꾸로 받아들임(글 이해는 맞음).
- **제외**: 글 자체를 틀리게 이해 → V/S/R(먼저). 선지 낱말 뜻을 몰라서 재진술을 못 알아봄 → V(선지 낱말이라도 V). 대조 없이 골랐다 → B. 선지 왜곡의 **종류**(범위/강도/방향)는 원인 코드가 아니다 — Choice Trap 으로 따로 기록돼 있다.
- **최소 증거**: 학생이 글 내용을 맞게 말했다는 증거 + 선지를 같은 것으로 / 다른 것으로 판단한 이유.
- **primary**: 가능 — 단, 「글 이해가 맞았다」는 증거가 없으면 primary 로 쓰지 않는다(그때는 insufficient 또는 B).
- **인접**: `R.main_point` · `B.surface_match` · `E.evidence_location` · `V.wrong_sense`.
- **가르는 규칙**: 학생이 **글 내용을 맞게 진술**했으면 option_mismatch, 글 내용을 틀리게 진술했으면 그 틀린 단계(V/S/R). 학생이 글과 선지를 **대조한 흔적**이 있으면 E, 겹치는 낱말만 근거로 들면 B.surface_match.
- **예**: 「글에서 '많은 경우 효과가 있다'고 했고, ②도 효과 있다는 말이라 맞다고 봤다」(②는 '항상').
- **반례**: 「②에 지문 단어 efficiency 가 그대로 있어서」 → B.surface_match.
- **판정 불가 예**: 「선지가 다 비슷해 보였어요」 → A1.
- **연결 진단 후보**: E.

### B — 결정 방식(근거 대조를 건너뜀)

#### `B.outside_knowledge` 글 밖 지식으로 판단
- **정의**: 이 attempt 에서 학생이 선지 · 결론을 **글의 내용과 맞지 않거나 글이 말하지 않는 자기 상식 · 배경지식 · 가치 판단**에 근거해 골랐다는 증거가 있을 때.
- **포함**: 「상식적으로 맞는 말이라서」 · 「원래 그런 거니까」 · 글과 무관하거나 글과 반대인 사실을 근거로 듦.
- **제외**: 글의 근거에서 잘못 추론 → R.inference. 배경지식을 **글의 단서와 함께** 써서 이해를 도운 것은 정상 독해다(평가원 출제 방향은 배경지식 · 글의 단서를 함께 쓰는 독해를 전제한다 — [SOURCES.md](./SOURCES.md)) — 이 코드는 글과 **충돌하거나 글을 대신한** 경우만.
- **최소 증거**: 고른 이유에 글 밖 근거가 드러나야 한다.
- **primary**: 가능. 글 이해 실패가 먼저 보이면 그 코드가 primary, 이것은 contributing.
- **인접**: `R.inference` · `B.surface_match`.
- **가르는 규칙**: 근거 출처가 글 안이면 R, 글 밖이면 B.
- **예**: 「환경 보호가 중요하니까 ③이 주제일 것 같았다」(글은 환경 정책의 비용을 다룸).
- **반례**: 「마지막 문장에서 정책이 필요하다고 해서」(그 문장을 오독) → R/S.
- **판정 불가 예**: 「그게 맞는 말 같아서」 → 글 밖 근거인지 불명 → A1.
- **연결 진단 후보**: 없음(행동 진단 D 후보).

#### `B.surface_match` 겹치는 낱말로 고름
- **정의**: 이 attempt 에서 학생이 **선지와 글에 같은 낱말 · 비슷한 낱말이 있다는 것**을 주된 근거로 골랐고, 뜻 대조 흔적이 없다는 증거가 있을 때.
- **포함**: 「지문에 나온 단어가 있어서」 · 「이 단어가 계속 나와서」.
- **제외**: 뜻을 대조했는데 차이를 못 가림 → E.option_mismatch. 그 낱말 뜻을 잘못 앎 → V.
- **최소 증거**: 고른 이유가 낱말 겹침을 근거로 든다.
- **primary**: 가능.
- **인접**: `E.option_mismatch` · `B.no_verification`.
- **가르는 규칙**: 이유가 「같은 단어」면 surface, 「같은 뜻」(학생이 뜻을 말함)이면 E.
- **예**: 「글에 technology 가 많이 나와서 기술 관련 ②를 골랐다」.
- **반례**: 「기술이 사람을 편하게 한다는 내용이라 ②」(글은 그 반대를 말하지만 학생이 글을 그렇게 이해) → R.main_point.
- **판정 불가 예**: 이유 없음 · 선지가 지문 낱말을 포함하는 선지(Choice Trap `lexical_overlap`)를 골랐다는 사실뿐 → **함정 종류만으로 B 를 정하지 않는다**, A0.
- **연결 진단 후보**: 없음(행동).

#### `B.no_verification` 다른 선지를 확인하지 않음
- **정의**: 이 attempt 에서 학생이 그럴듯한 첫 선지에서 **멈추거나 나머지 선지 · 근거를 확인하지 않고** 골랐다는 증거가 있고, 시간 부족 때문이라는 증거는 없을 때.
- **포함**: 「①이 맞는 것 같아서 나머지는 안 봤다」 · 「대충 다 맞는 말 같아서 하나 골랐다」.
- **제외**: 시간이 없어서 → X.time. 확인했지만 차이를 못 가림 → E.option_mismatch.
- **최소 증거**: 고른 이유 · 상황 기록에 확인을 생략했다는 진술.
- **primary**: **불가 — contributing 전용**(rev3, 규칙 R11). 이것만 있으면 `insufficient_evidence`.
- **인접**: `X.time` · `B.surface_match` · `E.option_mismatch`.
- **가르는 규칙**: 생략의 이유가 남은 시간이면 X, 습관 · 확신이면 B.
- **예**: 「첫 번째 거 보자마자 맞다고 생각해서 바로 넘어갔어요」 + 이 문항 25초 + 남은 시간 충분.
- **반례**: 「시간이 3분 남아서 ①만 보고 찍었다」 → X.time.
- **판정 불가 예**: 「확실하지 않았어요」 → A1.
- **연결 진단 후보**: 없음(행동).

### X — 시험 실행

#### `X.time` 시간 부족
- **정의**: 이 attempt 에서 **남은 시간이 부족해** 학생이 정상 풀이(읽기 · 대조)를 끝내지 못하고 골랐다는 증거가 있을 때.
- **포함**: 상황 기록(남은 시간 · 마지막 몇 문항 · 풀이 시간이 매우 짧음) + 「시간이 없어서」.
- **제외**: 시간은 있었는데 확인을 생략 → B.no_verification. 시간이 있었는데 처리 실패 → 해당 V/S/R/E.
- **최소 증거**: 시간 상황 기록 또는 「시간이 부족했다」 + 그것이 이 문항에 해당한다는 근거(순서 · 남은 시간).
- **primary**: 가능. 영어 처리 실패 증거가 따로 있으면 그것을 contributing.
- **인접**: `B.no_verification` · `X.attention`.
- **가르는 규칙**: 학생 진술만 「시간이 없었다」이고 기록(이 문항 풀이 시간 · 남은 시간)이 반대면 진술을 따르지 않는다 → inconsistent.
- **예**: 「마지막 2분에 지문을 다 못 읽고 찍었다」 + 이 문항 40초.
- **반례**: 「시간은 남았는데 귀찮아서」 → B.no_verification.
- **판정 불가 예**: 확신도 guess 만 → A1.
- **연결 진단 후보**: X(실전 실행).

#### `X.attention` 주의 이탈 · 표기 실수
- **정의**: 이 attempt 에서 학생이 처리할 수 있는 정보를 **순간적으로 놓치거나 잘못 옮긴** 증거가 있을 때(숫자 · 낱말을 잘못 봄 · 발문의 NOT 을 알면서 놓침 · 답을 알았는데 다른 번호에 표시).
- **포함**: 「다시 보니 not 이 있었다」 · 「답은 ③이라고 생각했는데 ④에 마킹」 · 도표에서 2를 7로 봄.
- **제외**: 발문 기준을 다르게 이해 → E.task_misread. 시간 부족 → X.time.
- **최소 증거**: 학생이 정보를 알 수 있었다는 증거(재확인 진술 · 다른 문항에서의 처리) + 놓친 지점.
- **primary**: 가능.
- **인접**: `E.task_misread` · `S.operator_scope` · `E.evidence_location`.
- **가르는 규칙**: 학생이 **다시 보고 바로 알아챘다**는 진술이 있으면 attention, 다시 봐도 같은 기준이면 task_misread.
- **예**: 「일치 문항인 줄 알았는데 다시 보니 '않는'이었어요. 알고 있었는데 급하게 읽었다」.
- **반례**: 「불일치 문항도 지문에 있는 걸 고르는 줄 알았다」 → E.task_misread.
- **판정 불가 예**: 「실수한 것 같아요」만 → A1.
- **연결 진단 후보**: X.

## 6. 가장 헷갈리는 경계(decision table)

| 경계 | A 를 고르는 증거 | B 를 고르는 증거 | 둘 다 없으면 |
|---|---|---|---|
| **V vs S** | 해석에 낱말 자리의 뜻이 비었거나 틀림 | 낱말 뜻은 다 맞는데 성분 · 꾸밈 · 범위가 틀림 | 막힌 곳이 **특정 낱말 · 구조를 가리키고** V · S 후보가 **각각** 최소 증거를 갖출 때만 `multiple_plausible`(V · S) — 막힌 곳이 문장 전체이고 해석 · 이유가 실패 단계를 말하지 않으면 R9 에 따라 `insufficient_evidence`(rev4) |
| **S vs R** | 한 문장의 해석이 이미 틀림 | 각 문장 해석은 맞고 문장 사이 연결 · 지시 · 중심이 틀림 | 해석 증거 없으면 insufficient |
| **R vs E** | 학생이 말한 글 내용 · 요지가 틀림 | 글 내용은 맞게 말했는데 선지 · 근거 판단이 틀림 | 「글을 어떻게 이해했나」가 없으면 E 를 primary 로 쓰지 않는다 |
| **E vs B** | 근거 문장을 가리키며 대조한 흔적 | 대조 흔적 없이 상식 · 같은 낱말 · 첫 인상 | 이유가 없으면 insufficient(B 로 추정 금지) |
| **B vs X** | 시간 · 집중에 문제 없다는 기록이거나 기록 없음 + 습관 진술 | 남은 시간 · 풀이 시간 · 「시간이 없어서」 | 둘 다 없으면 insufficient |
| **E.task_misread vs X.attention** | 다른 기준으로 골랐다는 이유 | 다시 보고 알아챘다 · 급했다 | 관찰 가능한 task_misread |
| **R.inference vs V.multiword / V.wrong_sense** | 글이 그 말을 비유 · 확장 의미로 씀(사전 뜻을 그대로 적용한 학생) — R6 · 판정 단위는 R6 ① · ② | 사전에 있는 고정 표현을 모름(multiword) · 문맥상 사전의 다른 뜻(wrong_sense) | `multiple_plausible` |
| **R.relation/R.reference vs B.surface_match** | 연결어 · 지시 표현을 단서로 씀 — R5 | 내용어 반복만 근거 | 근거 진술이 없으면 insufficient |
| **X.time vs X.attention** | 단계를 건너뜀(안 읽음 · 대조 안 함) — R2 | 읽었는데 잘못 봄 | 진술 없이 시간 기록만 → X 는 contributing(R1) |
| **V.unknown_word vs V.wrong_sense vs V.multiword** | 채운 뜻이 사전 뜻이 아님(unknown) | 실제 다른 사전 뜻(wrong_sense) · 고정 표현을 낱말 합으로(multiword) — R12 | 구별 증거가 없으면 R12 ③ |
| **R.relation vs R.main_point** | 두 부분 사이의 관계 진술 | 글 전체 중심 진술 | 더 이른 쪽(relation) 을 primary 로 · 단 증거가 있을 때만 |

## 7. 문항 유형 · 선지 함정과의 관계(원인이 아니다)

- 이전 초안의 「빈칸 실패 · 순서 실패 · 고난도 · 해석 안 됨」 같은 이름은 결과 · 유형이라 코드로 두지 않는다.
- 「재진술 실패」(`E.paraphrase_match`)는 **분리 코드로 유지하지 않는다**: 재진술을 못 알아본 이유가 선지 낱말 뜻(V) · 글 이해(R) · 선지 대조(E)로 나뉘어야 하고, 앞의 둘은 이미 V · R 이 받는다. 남는 「글도 선지 낱말도 맞게 알았는데 같은 뜻임을 못 봤다」만 `E.option_mismatch` 에 합쳤다.
- 학생이 Choice Trap(예: `scope_strength`)이 걸린 선지를 골랐다는 사실은 판정자 화면의 **참고 정보**다. 「범위 함정 선지를 골랐으니 E.option_mismatch」처럼 자동으로 잇지 않는다.

## 8. 듣기(L) — v0.1 에 넣지 않는다 (H 판단)

- 수능 영어 45문항 중 듣기 17. 장기적으로 듣기 원인이 필요하다.
- v0.1 에 넣지 않는 이유:
  1. **자극 자료가 없다** — DB `csat_items` 는 읽기 28문항만 원문을 갖고(듣기 대본 · 음성 없음), 학생 막힌 곳을 「대본의 어느 부분」으로 남길 수 없다. 증거 등급 A2 를 만들 수 없으면 판정을 못 한다.
  2. **DB 제약** — 원인 코드 형식 CHECK(`^[VSREBX]\.`)와 축 CHECK 가 L 을 받지 않는다. L 을 넣으려면 마이그레이션이 필요하다(이번 단계 금지).
  3. **실패 단계가 다르다** — 소리 → 낱말 분절 · 연결 발화 · 기억 유지 · 화자 의도처럼 읽기에 없는 단계가 있다(Field 2008 의 해독 층위 — 근거표 참조). 읽기 코드를 재사용하면 「들은 낱말을 몰랐다」와 「낱말을 알지만 소리로 못 알아들었다」가 섞인다.
- 제안: **v0.1 = 읽기 전용**, 듣기는 `v0.2-listening` 으로 따로 설계한다. v0.2 의 선행 조건: 듣기 대본 · 문장 단위 참조, 학생 증거 형식(못 들은 구간 · 들은 대로 받아 적기), 코드 CHECK 확장 마이그레이션. 초안 후보 family(미검증): 소리 분절(아는 낱말을 못 알아들음) · 듣기 중 낱말 뜻 · 정보 유지(앞 내용을 잊음) · 화자 의도/관계 · 듣기 중 시간 압박(다음 문항 읽기와 겹침).
