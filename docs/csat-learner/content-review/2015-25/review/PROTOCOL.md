## 트랙과 점검 항목(각 항목 PASS / FAIL / UNKNOWN + 근거)

**T1 공식 정답** — O1 정답표 원본이 「④, ⑤」인가 · O2 공식 발표가 ⑤ 사유를 percent/percent point 로 밝히는가 · O3 DB answers 가 {4,5} 인가 · O4 패키지가 ④ 단독 의도를 사실로 쓰지 않는가.

**T2 교육적 해설(분석 v6 · 탐구 수정안)** — E1 ⑤ why_correct 의 계산(2→20: 차 18%p · 증가율 900%)이 맞는가 · E2 ④ 설명(29×3=87, 53÷29≈1.8)이 맞는가 · E3 ①②③ 판정·도표 값이 v5 와 같고 맞는가 · E4 풀이 2단계 규칙이 일반 규칙으로 맞는가(퍼센트 증가=비율 · 퍼센트포인트=차) · E5 출제 의도가 사실/확정하지 않음을 갈랐는가 · E6 탐구 원리 수정이 맞고 과잉 일반화가 아닌가 · E7 SQL 초안이 v1~v5 를 바꾸지 않고 필드를 보존하는가.

**T3 강의 cue(v4 제안)** — L1 바뀐 cue 7개 각각 사실 오류가 없는가 · L2 공식 정답 {4,5} 와 충돌하는 진술이 없는가 · L3 공개 경계(stopBefore 3) 앞 c1~c3 이 정답을 드러내지 않는가 · L4 c9 대상(anchor:sentence:5)·역할(evidence)이 말하는 문장과 맞는가 · L5 c10 이 ④ 항목 안에서 사실인가 · L6 바뀌지 않은 cue(c3 · c5~c8)에 남은 오류가 없는가 · L7 학습자가 듣기에 오해할 표현이 없는가.

## 트랙 판정과 합의 규칙(고정)

- 트랙 판정 = `ACCEPT`(모든 항목 PASS) · `REVISE`(FAIL 이 있으나 수정 문안을 제시할 수 있음) · `REJECT`(근거 자체가 틀림) · `UNKNOWN`(확인 못 함 — PASS 로 세지 않는다).
- **합의 = A 와 B 가 같은 트랙에서 둘 다 ACCEPT 일 때만 「위임 감수 통과」.** 하나라도 REVISE/REJECT/UNKNOWN 이면 그 트랙은 통과가 아니다. 불일치는 항목 단위로 기록하고, 수정 후 같은 규약으로 재판정한다.
- 판정 파일: `judgments-A.json` · `judgments-B.json` — 같은 키(트랙 · 항목 · 판정 · 근거 · 위치). 집계: `aggregate.json`.
