## 1. 태그 스키마(`csat-lecture-disclosure-sidecar/v1`)

cue 마다: `lecture_id` · `lecture_version` · `cue_id` · `order` · `index` · `source_hash`(sha256(cue 원문 JSON)) · `local_disclosure_level` · `cumulative_disclosure_level` · `cumulative_lower_bound` · `channels`(speech · script · highlight · elimination) · `auto`(규칙 근거 · 제안 수준 · 불확실) · `review`(상태 · 검토자별 판정 · 충돌 · `promoted`).
수준: NONE / HINT / DECISIVE / ANSWER, 검증 안 됨 = UNKNOWN.

생성 `cue-audit/sidecar-build.mjs <repo> main <answers> <out>` → 병합 `cue-audit/review-merge.mjs <repo> main` → `sidecar-reviewed/`. 미검수 sidecar(`sidecar/`)는 재생성 가능해 커밋하지 않는다.

## 5. 제품 적용 판단

- 승격 1,888 cue 만으로는 강의 단위 안전 구간을 정할 수 없다(강의마다 앞쪽에 UNKNOWN · 충돌이 섞인다).
- **보수 규칙(제안):** UNKNOWN · 충돌 cue 는 HINT 이상으로 취급, 누적은 하한이 아니라 「HINT 이상 가능」 으로 취급. 이 규칙이면 거의 모든 강의가 **첫 cue 부터 「정답을 좁힐 수 있음」** 이다 — 현 대본에 「답 없이 들을 수 있는 구간」 은 사실상 없다.
- 따라서 구현 우선순위: ① 강의 시작 전 일괄 안내(전 강의 공통, 태그 불필요) ② 확정 공개(ANSWER) 경계 앞 안내 — 규칙 확정 데이터로 바로 가능 ③ cue 단위 HINT/DECISIVE 안내는 태그 검수 품질 보강(근거 문구 필수 · 충돌 3자 판정) 뒤.

## 6. 정답 공개 UX 계약(14 결정 1 의 구체화)

| 규칙 | 내용 |
|---|---|
| U1 경로 | 근거 우선 · 해설 우선 · 강의 우선 모두 언제든 선택. 답 선택을 공개의 전제로 두지 않는다 |
| U2 강의 시작 | 학습자가 정답을 아직 열람하지 않았으면 재생 전에 「이 강의는 정답과 정답을 좁히는 단서를 말해요」 를 알리고 **계속 / 정답 부분 전까지만 / 취소** 를 고른다. 태그가 없거나 미검증인 강의도 같은 안내(정답 없음을 가정하지 않는다) |
| U3 확정 공개 경계 | 「정답 부분 전까지만」 을 고르면 R1 · R2 확정 ANSWER cue 직전에 멈추고 **계속 / 건너뛰기 / 여기서 멈춤** 을 묻는다. 누적 소거 DECISIVE(R7) 도 같은 경계로 본다 |
| U4 단일 공개 상태 | 음성 · 읽기 강의 대본 · 화면 강조(정답 블록 · 소거 대상) · 소거 순서 · 역할 라벨 · ARIA 문구가 같은 상태를 읽는다. 대본 탭은 멈춘 경계 뒤 cue 를 접어 두고, 소거 강조도 같은 경계를 넘지 않는다 |
| U5 기록 | `answer_viewed`(경계를 넘은 시각 포함) · `checked_after_explanation` · `independent_attempt` · `mastery` 분리 — 탐색 · 청취 · 열람은 숙달 비산입, 자동 숙달 승격 없음 |
| U6 학습자 소유 | 안내는 학습자 선택 없이 상태를 바꾸지 않는다(자동 장면 이동 · 스크롤 금지 원칙과 같다) |

필요 데이터: U2 는 없음(즉시 가능) · U3 은 확정 경계(R1 · R2 · R7) — sidecar 규칙 확정분으로 충분, 원본에 키를 넣지 않고 sidecar 를 런타임에 읽는 방식이면 원본 콘텐츠 변경 없이 가능(단 sidecar 를 제품 경로로 옮기는 것은 코드 변경 · 승인 대상) · U5 는 기록 구조 조사 필요(스키마 변경 시 SQL 승인).

## 7. 원본 JSON 키 추가가 필요해질 경우(승인 전 실행 안 함)

- 범위: `lecture-data/*.json` 29개의 각 cue 에 `disclosure` 키 1개.
- 해시 영향: 파일 blob · sha256 이 모두 바뀌어 이 sidecar 의 결속(`source.blob`, cue `source_hash`)이 깨진다 → 키 추가 후 sidecar 재생성 · 재결속 필요. 강의 렌더 코드(`store.ts` 는 필요한 키만 읽음)는 영향 없음으로 보이나 미검증.
- 복구: 단일 커밋으로 넣고 `git revert` 로 되돌린다.
- 현재 판단: **필요 없음** — U2 · U3 은 sidecar 로 충분.
