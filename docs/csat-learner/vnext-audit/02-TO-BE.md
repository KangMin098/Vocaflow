# 02. TO-BE: 재설계 명세 (제안)

이 문서의 모든 내용은 **[가설·제안]**입니다. 구현과 DB 적용은 승인 뒤에 합니다.
제안마다 **근거 · 변경 범위 · 버릴 것 · 실패 가능성 · 검증 기준**을 붙였습니다.

## 0. 아키텍처 대안 비교 (공통 학습 세션)

| | A. 정본 `learning_task_attempts` 확장 | B. 기출 전용 새 표 `csat_learning_sessions`·`csat_learning_steps` | C. 지금 jsonb 레코드에 필드 추가 |
|---|---|---|---|
| 구조 | 문항 한 번 시도 = 행 1개. `phase`에 `theater`·`dissect` 등 모드를 더하거나 별도 열 `mode`를 둠. 멱등 키 `client_attempt_id`를 추가 | 세션·단계를 정규화한 새 표 2개 | `DissectionRecord`에 `sessions[]`를 추가 |
| 수정 비용 | 중간. 정본이 이미 개발 DB에 있음. 열 2–3개와 유일 제약 추가 | 높음. 표·RLS·RPC를 새로 만들고 정본과 이중 기록이 생김 | 낮음 |
| 학습 효과 측정 | **좋음.** 효과 프로토콜(pre/post/delayed/transfer)과 같은 표를 씀 | 정본으로 옮기는 변환이 필요 | 나쁨. 서버 jsonb 하나라 질의가 불가능하고 900KB 한도가 있음 |
| 이전 위험 | 낮음. 지금 레코드는 그대로 두고 새 기록만 이중 기록 | 중간 | 병합 규칙(합집합)의 부활 버그를 그대로 물려받음 |
| 다른 세션과 충돌 | 정본 소유는 methodology-vnext. **합의가 필요함** | 충돌은 적지만 두 정본이 생김 | 없음 |
| **판단** | **권고** | 대안 | 단기 임시책으로만 (완료 표시) |

**권고: A + C 단기 병행.**
- 1주차: 지금 레코드(C)에 완료 상태만 더해 화면 루프를 닫습니다. DB 변경이 없습니다.
- 4주차: 정본 표(A)에 서버 기록을 이중으로 남깁니다(합의 뒤).
- 근거: 효과 검증은 결국 정본 표에서 읽습니다. 이중 정본(B)은 지금 레코드와 정본, 둘 사이의 불일치를 하나 더 만듭니다.
- 실패 가능성: 정본의 `phase` 의미(pre/post…)와 학습 모드(극장·해부)가 섞일 수 있습니다. 이 때문에 `mode`를 별도 열로 둘 것을 권고합니다([03 §5](./03-PARALLEL.md#5-공통-스키마-전-합의-사항)).

## 5. 데이터 계약 (제안)

### 5-1. 학습 시도 (정본 `learning_task_attempts` 확장 · 합의 대상)
| 필드 | 지금 정본 | 제안 |
|---|---|---|
| `client_attempt_id uuid` | 없음 | **추가.** 유일 키 `(user_id, client_attempt_id)`. 이것으로 멱등성을 보장 |
| `mode text` | 없음 | 추가: `theater` \| `dissect` \| `practice` \| `review` \| `transfer` |
| `completion text` | 없음 | 추가: `viewed` \| `completed_guided` \| `completed_independent` \| `transfer_passed` |
| `item_ref` | 있음 | `csat_items.id` (예: `2026#34`) |
| `content_hash` | 있음 | **분석 버전 id + 자산 해시** (과거 기록 결속) |
| `phase` | pre/practice/post/delayed/transfer | 효과 프로토콜 의미로만 씀 (모드와 섞지 않음) |
| `response jsonb` | 있음 | `{sentence, choice, confidence, design?, hint_used}` |
| `synthetic` | 있음 | 합성 학습자·검증 계정은 true |

### 5-1a. 네 축 분리와 세션↔시도 관계 (2차 심사 요청 반영)

정본 `phase` 하나에 모든 의미를 싣지 않고, 서로 독립된 네 축으로 나눕니다.

| 축 | 질문 | 값 (닫힌 열거형) | 저장 위치 |
|---|---|---|---|
| 학습 활동 `activity` | 무엇을 했나 | `theater`(기출 문항 학습) \| `dissect`(유형 훈련) \| `practice`(원리 연습) | 세션 |
| 수행 방식 `help` | 어떻게 했나 | `independent` \| `hint` \| `viewed_first`(해설 바로 보기) | 시도 |
| 평가 단계 `phase` | 측정상 무엇인가 | `practice` \| `review` \| `transfer` \| `pre`·`post`·`delayed`(효과 프로토콜에서만) | 시도 |
| 학습 결과 | 무엇이 나왔나 | `choice_correct` bool · `evidence_correct` bool · `completion`(세션) | 시도·세션 |

- **세션** = 학습자가 한 문항(또는 한 세트)에 들어와 나갈 때까지의 단위입니다. `session_id`(클라이언트가 만든 uuid), `activity`, `item_ref` 또는 `set_ref`, 시작·종료 시각, `completion`을 가집니다.
- **시도** = 세션 안에서 한 번 판단을 제출한 것입니다. 한 세션에 0개 이상이 있습니다. 확정, 전이 문항 응답, 복습 응답이 각각 시도입니다. 해설 바로 보기는 시도가 아니라 세션의 `help` 기록입니다.
- **관계**: 시도는 `session_id`를 가집니다. `completion`은 시도에서 파생하는 세션 속성입니다(예: 독립 시도가 1개 이상이고 정리 단계에 도달하면 `completed_independent`). 정본 표는 시도 단위이므로 세션은 ⓐ 새 표 하나를 두거나 ⓑ 시도의 `session_id`로 묶어 파생합니다. **권고는 ⓑ**입니다. 새 표를 만들지 않고, 완료는 서버 질의로 계산합니다. 이것은 합의 사항 [03 §5](./03-PARALLEL.md#5-공통-스키마-전-합의-사항)에 들어갑니다.

### 5-1b. 기존 적중률 데이터 처리
- 대상: 기기와 서버 레코드에 있는 `predictions` 중 `source:'theater'`, `sentence=null`, `choice=null`인 항목입니다. 이것이 「모르겠어요」로 생긴 기록입니다.
- 처리: 지우지 않습니다. 읽을 때 `viewed_first`로 재해석하고 적중 통계에서 제외하는 **읽기 시점 변환**만 합니다. 레코드 버전은 그대로 둡니다.
- 이벤트: 과거 `funnel_events`에는 확정 이벤트가 없었으므로 정정할 대상이 없습니다. 새 이벤트부터 구분합니다.
- 실제 학습자 데이터가 0명이므로 영향은 검증 계정 2명분뿐입니다 [사실·DB].

### 5-1c. 기능 검증과 학습 효과 검증의 분리
| | 기능 검증 | 학습 효과 검증 |
|---|---|---|
| 주체 | 합성 학습자와 에이전트 | 실제 학습자만 |
| 기록 | `synthetic=true` | `synthetic=false` |
| 판정 | 상태 전이·저장·이벤트·재개가 명세대로 동작 | pre/post/delayed/transfer 비교, N≥20 |
| 지금 가능 | **예.** 구현을 계속할 수 있음 | **아니오.** 미검증 상태로 표시 |
| 화면 문구 | — | 효과를 주장하는 문구 금지 |

### 5-2. 기기 레코드 (단기 · DB 변경 없음)
- `DissectionRecord`에 `sessions: {id, item, mode, step, completion?, at, updatedAt}[]`를 추가합니다.
- 병합 키는 `id`입니다. 삭제 표시를 넣어 부활 버그(합집합 병합)를 막습니다.
- 모르겠어요는 `predictions`에서 빼고 `sessions.completion='viewed'`로 기록합니다. 적중 통계에서 제외됩니다.

### 5-3. 복습
- 복습 대상: 문항이 아니라 **원리 + 새 문항 1개**. 같은 문항을 다시 보는 것은 재인이라 복습 성공으로 세지 않습니다.
- 성공: 도움 없이 근거와 정답을 모두 맞힌 경우만.
- 간격: 지금은 고정 3일입니다. FSRS를 쓸지는 「원리 카드」를 기억 단위로 정의한 뒤 실험합니다. 해설을 열었다는 사실로 기억 강도를 올리지 않습니다.

## 7. 저작권·권한·품질 게이트
- **원문**: 서버가 보내지 않는 경계를 유지합니다(D17 미결). 링크는 평가원 공식 게시판만 걸고, 학평은 링크하지 않습니다(지금과 같음).
- **원문 없는 시도**: 「원문 없이 해설만 보기」는 `viewed`로만 기록합니다. 시도형 완료로 인정하지 않습니다.
- **정답 키**: 지금 클라이언트 props에 있습니다(09-25 결정, 보안 경계 아님). 효과 검증(transfer·post) 문항은 **서버 채점**으로 바꿉니다. 정본 practice 방식과 같습니다.
- **배포 게이트(06)**: published이고, 공통 독립 검수를 통과했고, 자산 해시가 일치하고, 모드 자격이 있어야 합니다.
