# Vocaflow 기출 분석 시스템: 외부 재설계 검토용 전체 정리

작성일은 2026-10-08입니다. 수치는 이날 Supabase DB에 직접 질의해 얻었고, 구조는 저장소 코드와 문서를 직접 확인해 적었습니다.
이 문서의 독자는 외부 검토자(ChatGPT)입니다. 검토자는 코드를 볼 수 없으므로 이 문서만으로 판단할 수 있게 썼습니다.
기출을 추가하는 단계부터 분석, 검수와 발행, 파생 자산을 거쳐 학습자 화면에 이르는 전 과정을 다룹니다. 검토 요청은 §9에 있고, 그중 **학습자 화면·설명·서비스·기능·이벤트·디자인**을 가장 중점으로 봐 주시기 바랍니다.

---

## 0. 배경

### 제품
- **Vocaflow**는 영어 학습 플랫폼입니다. 웹은 Next.js 14와 Supabase로 만들었고, 대상은 한국 고등학생부터 성인까지입니다.
- 학습 모듈 9개와 함께 **수능(CSAT) 기출 영역**(`/csat/*`)이 있습니다.

### 기출 영역의 목표
- 학습자의 행동을 "문제를 많이 풀기"에서 **"출제자의 설계를 읽기"**로 바꾸는 것이 목표입니다.
- 학습자는 문항마다 다음을 배웁니다.
  - 무엇을 재는 문항인가
  - 정답 근거가 지문의 어디에 있는가
  - 오답은 어떤 함정으로 만들었는가
  - 어떤 절차로 풀면 되는가
- 이렇게 얻은 것을 유형마다 "내 공식"으로 쌓게 합니다.

### 저작권 경계 (절대 제약)
- 평가원과 교육청의 지문·선지·발문 원문은 **서버가 학습자에게 보내지 않습니다.**
- 학습자가 공개 문제지 PDF를 화면에 놓으면, 브라우저가 기기 안에서 글자를 뽑아 IndexedDB에 저장하고 보여 줍니다(reflow).
- 서버는 문장 길이와 해설 인용으로 만든 "골격"만 보냅니다.
- reflow로 재조판하는 방식의 적법성은 **변호사 자문 대기(D17, 미결)**입니다.

### 학습 과학 원칙 (제품 전체 공통)
- 인출 연습, 간격 반복(FSRS), 바람직한 어려움, 이중 부호화, 맥락 의존, 인지 부하(작업기억 약 4), 정서 부호화

### 디자인
- `/csat/*`과 관리자 화면은 **3B 앱**(neon-currant.3b.dev)을 참조합니다. 그 밖의 화면은 Tines 웹사이트를 참조합니다.
- 디자인 작업 대상은 **PC 웹만**입니다. 모바일은 현재 범위 밖입니다.

## 1. 전체 흐름 한눈에

```
[1 원문 수집·추출] → [2 원장·DB 동기화] → [3 근거 단위] → [4 분석 드레인] → [5 검수·발행 관문]
        → [6 파생 자산 굽기: 유형 리포트·함정 지도·골격·강의·블루프린트] → [7 학습자 화면]
                                                                     ↘ [교재 공장 9칸(별도 축)]
```

- 모든 단계는 **CLI 스크립트**로 실행됩니다. 관리자 화면은 상태를 보여 주고 실행할 명령을 복사하게 해 줄 뿐 **실행 버튼이 없습니다.**
- LLM이 판단해야 하는 일(분석·검수·강의 대본)은 외부 API를 부르지 않습니다. **에이전트(Claude Code / Codex)가 직접 처리하는 배치 드레인**입니다.
  - 순서: export로 청크 JSON을 만들고, 에이전트가 `.out.json`을 채우고, validate를 거쳐 import로 DB에 넣습니다.
- 회차 id 문법은 다음과 같습니다.
  - 수능: 학년도 4자리(`2026`, `2014A`)
  - 평가원 모의평가: `M2706`
  - 교육청 학력평가: `H2503G1`(시행연도·월·학년)
  - 문항: `2026#34`. 학습자 URL에서는 `/csat/item/2026-34`
- 평가원(KICE) 기출이 **규칙 도출의 정본**입니다. 학평은 **보조·검증용 홀드아웃**이며 통계를 합산하지 않습니다. 학평 원문은 재배포 금지라 저장소에 커밋하지 않습니다.

## 2. 단계별 상세 (입력 → 처리 → 출력 → 화면 → 관문)

### 단계 1. 원문 수집과 추출
- **평가원**
  - 입력: PDF 문제지와 정답표.
  - 처리: `pdftotext -layout`과 단(column) 분리를 씁니다. 파일 판정은 이름이 아니라 내용으로 합니다(정답표라는 이름의 파일 7개가 실제로는 듣기 대본이었습니다).
  - 정답: PDF 글꼴 표로 기계 해독합니다. 검산 4개(45문항, 1~5 범위, 배점 합 100, [3점] 표시 일치) 중 하나라도 실패하면 그 회차의 정답을 받지 않고 `answer_unknown`으로 둡니다.
- **학평**
  - 처리: pdfjs 좌표로 읽고, 빈칸 밑줄은 PDF 선 좌표로 복원합니다.
  - 정답과 배점: 정답은 해설지에서, 배점은 [3점] 표시에서 읽고 "3점 10문항, 합 100"으로 검산합니다.
- 출력: 로컬 JSON과 텍스트 파일.
- 화면: 없음.
- 관문: 위의 검산.

### 단계 2. 원장 생성과 DB 동기화
- 처리: `build-corpus` → 무결성 테스트 PASS → `corpus-sync --commit` 순서로 `csat_types`, `csat_exams`, `csat_items`에 upsert합니다.
- 삭제하지 않습니다. 삭제하면 분석이 CASCADE로 함께 사라지기 때문입니다.
- 원문 수리는 `source-repair`로 합니다. PDF 해시와 필드별 before/after를 기록하고, 정답·유형·원본 블록은 보존합니다.

### 단계 3. 근거 단위 (학평만)
- 지문을 문장(단위)으로 나누고 해시를 붙입니다.
- 단위가 바뀌면 DB 트리거가 발행된 분석을 자동으로 보류(`in_review`)합니다.
- **평가원 문항에는 단위가 없습니다.** 그래서 분석의 문장 번호가 0기준과 1기준으로 섞여 있고, 다른 지문의 어휘가 섞인 결함이 기록되어 있습니다.

### 단계 4. 분석 드레인
- export: 유형별로 최신 회차부터 6문항씩 청크를 만듭니다.
- 에이전트 `csat-item-analyst`: 명세는 296줄입니다. 문항마다 아래 항목을 씁니다.
  - `measured_ability`(재는 능력), `design_intent`(설계 의도)
  - `answer_locus`(근거 문장 번호와 지문 그대로의 인용, 추론)
  - 선지별 분석: 정답은 `why_correct`와 확인 위치, 오답은 **함정 라벨**과 `why_tempting`(왜 끌리나), `how_to_reject`(어떻게 지우나)
  - `solve_procedure`(단계와 실패 시 대처), `time_budget_sec`, 예측 난이도와 그 요인, `required_vocab`
  - 3인 페르소나 검수(출제자·오답분석가·현장강사)
  - 청크마다 **유형 리포트**: 반복 함정, 근거 위치 패턴, 절차, 실패 양상, 시간, 열린 질문
- validate가 오류로 잡는 것: 인용이 지문에 없음, 정답표와 불일치, 순환논법 표현, `why_correct`가 40자 미만, 검수 미기재. 경고는 "용의자 명단"으로만 씁니다.
- import는 게이트를 통과한 것만 적재하고, **덮어쓰지 않고 새 버전 행**으로 넣습니다.
- 과거 사고
  - 중복 판정이 고장 나 802행이 중복으로 늘었습니다.
  - 유형 리포트 13개의 서술이 덮어쓰여 되돌아갔습니다.

### 단계 5. 검수와 발행 관문
- **평가원:** 분석한 에이전트가 **스스로** 적은 3인 검수가 pass이면 DB 트리거가 발행을 허용합니다.
- **학평 (2026-09-28 도입, 독립 검수)**
  - 도입 이유: 같은 주체가 쓰고 검수하니 소견이 틀로 찍혔습니다(42개 청크 중 40개).
  - 검수자 순서: 시작 → (도표라면 이미지 확인) → **블라인드 풀이(한 번만)** → 분석 공개 → 판정.
  - DB가 막는 것: 3인 미달, 자기 검수, 풀이 전 공개, 원문·정답·분석·단위 해시 불일치.
  - 사전 검사 v4(번호·지칭·내부 메모 노출)가 블라인드 전에 걸러 냅니다. 다만 결함 5건 중 3건만 잡았습니다.
  - 도표 문항은 연결된 정본 PNG가 없으면 발행이 보류됩니다.
- **모순:** 학평에서 "자기 검수는 형식뿐"이라고 판단해 놓고, **평가원에는 그 판단을 소급하지 않았습니다.** 의도한 것인지는 문서에 없습니다.
- 관리자 화면 `/admin/csat/evidence`의 탭 4개
  - 운영 현황: 학습 준비 수와 원천 결함 수
  - 작업 큐: P1 원문·채점 → P2 분석·연결 → P3 메타데이터 → P4 보고서
  - 문항 탐색: 8축 교차 진단, 대상 JSON 내보내기
  - 검수 진행: 학평 전용, 읽기 전용
  - "학습자 배포 기준"(최신 공개 분석, 앵커, 함정 보기 4개, 의도 보기 3개)은 "원천 결함 없음"과 다른 기준으로 따로 표시됩니다.

### 단계 6. 파생 자산 (발행 뒤에 굽기)
| 자산 | 내용 | 학습자 노출 |
|---|---|---|
| 유형 리포트 `csat_type_reports` | 유형×출제기관×학년. 반복 함정, 근거 위치, 절차, 시간 | 홈 표와 해설 |
| 함정 지도 `trap-atlas*.json` | 오답 3,208개, 함정 이름 513종. **상위 9종이 60%** | 홈의 "함정" 탭 |
| 골격 | 문장 길이와 해설 인용 앵커만 담고 원문은 없음. 평가원은 저장소 JSON, 학평은 DB(발행분만, RLS) | 해설 극장 "지문 지도" |
| 강의 | 역할 순서 intro → strategy → structure → evidence → eliminate → trap → vocab → wrapup. 브라우저 TTS로 재생. 대본은 API로만 전달 | 해설 극장 하단 도크 |
| 블루프린트 | 수능 실측 규칙을 교재 생성 문항 23종에 대응 | 교재 공장(학습자 직접 노출 없음) |
| 진단 정답표 `csat_dx_*` | 학습자가 시험 답안을 입력하면 채점 | `/csat/diagnosis` |

### 별도 축: 교재 공장 (참고)
- `/admin/csat/*` 대부분은 **교재 공장 9칸**입니다. 순서는 ① 기출 원천 → ② 기획 → ③ 설계 → ④ 소재 → ⑤ 집필 → ⑥ 해설 → ⑦ 검수 → ⑧ 조판·발행 → ⑨ 운영·개정입니다.
- 이 공장은 기출을 닮은 생성 문항(`csat_dcp_items`, 약 83만~88만 행)을 만듭니다.
- 기출 분석은 이 중 **①칸 하나**에 해당합니다. 그런데 화면 이름(review, explain 등)이 겹쳐 혼동됩니다.

## 3. 학습자 화면 지도

라우트는 두 그룹으로 나뉩니다.
- 풀스크린 앱 그룹: `/csat`, `/csat/browse`, `/csat/record`, `/csat/diagnosis`, `/csat/workspace/[id]`. 자체 왼쪽 레일 `CsatRail`이 있습니다.
- 앱 셸 안 그룹: `/csat/item/[slug]`, `/csat/dissect`, `/csat/formulas`

### 3-1. 홈 `/csat`
- 목적: 유형 26과 함정 표에서 범위를 고르고, 멈춘 자리에서 이어 가는 화면입니다.
- 쿼리가 없으면 **Workspace 탭이 기본**으로 열립니다.
- 영역
  1. 레일: 홈, 이어서·복습(n), 내 기록, 내 진단 / 유형, 함정, 전체 서가 / Workspace 목록과 [+]
  2. 상단 줄: "기출 N문항 · 연도"
  3. **이어서 카드**: 첫 방문 / 재방문 이어서 / 공백 뒤 복귀(오늘 3개만) 중 하나. 버튼은 `/csat/dissect`로 갑니다.
  4. 진단 카드
  5. 판: 탭 [Workspace | 유형 | 함정](개수 뱃지), 도구줄(검색, 예시 있는 것만, N학년도 이후, 킬러 칩), 넓이 줄("본 유형 x/26 · 함정 계열 · 내 공식"). 표의 줄을 펼치면 단계 카드가 나옵니다.
  6. 바닥: 수치 기준일과 저작권 안내
- 팝업: **Workspace 만들기**. 출발점 5갈래와 범위 편집기(토큰, 실제 포함 문항 수)가 있습니다.
- 학습 기록은 기기 IndexedDB와 서버 `/api/csat/state`를 합쳐 읽습니다. 밀린 복습이 3개를 넘으면 압축합니다.

### 3-2. 전체 서가 `/csat/browse`
- 필터 4축(시험 종류, 학년도, 유형, 상태), 찾기, 무작위 한 문항이 있습니다.
- 회차별 번호 칩을 누르면 해설 극장으로 갑니다. 원문은 없고 번호·유형·배점만 보입니다.
- **이벤트가 없습니다.**

### 3-3. 문항 해설 극장 `/csat/item/[slug]` (핵심 화면, 발행 문항 전부)
- 상단: ← 홈, 제목(예: 2026학년도 수능 34번), 유형·배점 태그, "이 유형 목록", "서가", 효과음, 전부 펼치기, 속도(0.9/1/1.15), **[예측 후 상영]**
- **왼쪽 열 "기출문제 원본"**
  - 기기에 추출본이 있으면 발문·지문·선지를 보여 주고, 없으면 PDF를 놓는 칸을 보여 줍니다.
  - 추출 실패나 밑줄·도표 7유형은 원본 크롭 이미지를 보여 줍니다.
  - 개발 서버는 로컬 PDF를 자동으로 읽습니다.
  - 아래에 행동 상자가 있습니다: "이 문항으로 무엇을 할까요?" [다음 단계][진행 보기][같은 유형 다음 문항], n/N 단계와 경과 시간.
- **가운데 왼쪽 판 "지문 지도"(고정)**
  - 먼저 **예측 게이트**가 나옵니다. 묻는 것은 근거 문장(문장 길이 막대 중 선택), 설계 주석이 있으면 주제문·뼈대·표현 변환, 정답 ①~⑤, 확신도 5단계입니다.
  - 버튼은 [확정하고 대조하기]와 [모르겠어요—바로 보기]입니다.
  - 확정하면 **차이 카드**가 뜹니다. 어긋난 항목을 먼저 보이고, 확신이 높았는데 틀리면 경고합니다.
  - 그 뒤로 **지문 지도**(문장 막대와 정답·오답 근거 앵커 칩)가 나옵니다.
- **가운데 오른쪽 판**: 탭 [분석 | 진행 | 같은 유형]
  - 분석: 블록 카드(재는 능력, 설계 의도, 정답 근거, 오답 지우기, 절차, 어휘, 근거 등급 칩). 확정하기 전에는 머리 블록과 재는 능력만 열려 있고 나머지는 "N개가 아직 닫혀 있어요"로 가려집니다.
  - 진행: 지표 4개, 간트, 차례 목록
  - 같은 유형: 형제 문항 링크
- **하단 도크**: 강의 차례 카드(14개 내외, 역할별 파스텔). 확정 뒤에 상영할 수 있고, 키보드 ←/→로 이동합니다.
- 상태 문구: "기록을 확인하는 중…", "문제지를 여는 중…", "지문 골격을 구하지 못해 지도가 없어요". 오류일 때는 문장 하나만 나오고 재시도 버튼이 없습니다.
- 이벤트: 뒤로, 강의 재생·종료, 근거 열기, 문제지 읽기. **예측 확정 이벤트는 없습니다.**

### 3-4. 해부 `/csat/dissect` (원래 설계의 중심 루프)
- 세트는 같은 유형·다른 소재 2문항과 전이 1문항으로 구성되며, 목표 시간은 12분입니다.
- 흐름: 훑기(정답 선공개) → 예측1/대조1(근거 문장) → 예측2/대조2(오답 계열) → 예측3/대조3(설계 의도) → 설계도 5칸("같은 설계를 다르게 내면?") → 공식([내 공식에 넣기][아직 모르겠음])
- 2번째 문항 뒤에는 대조 카드("같은 유형, 어디가 달랐나요?")가 들어갑니다.
- 끝 화면: "예측 x/y 적중 · 공식 +n · 새 계열", 다음 복습까지 남은 날.
- 보조 기능: [분석 바로 읽고 듣기](TTS). 이렇게 연 문항은 적중 통계에서 빠집니다.
- **손으로 검토한 메타데이터가 있는 소수 문항으로만 돕니다**(검토 12, 노출 7). 실측 기록은 시작 76회, 완료 1회입니다.

### 3-5. 내 공식 `/csat/formulas`
- 수치 3칸(공식 수, 최근 30수 적중률, 계열 커버리지)과 유형→공식→출처 계보가 있습니다.
- 공식마다 "이 공식으로 해부하기" 링크가 있습니다.
- 기기에만 저장되고 이벤트가 없습니다. **레일에 링크가 없습니다.** 빈 상태는 Tines 삽화라 스킨이 섞여 있습니다.

### 3-6. 내 기록 `/csat/record`
- 학습일 칸과 공식 링크로 진척을 "넓이"로 보여 줍니다. 정답률·랭킹·뱃지는 없습니다.

### 3-7. Workspace `/csat/workspace/[id]`
- 학습자가 범위를 직접 담은 학습 묶음입니다.
- 주 행동 "다음 문항 학습"은 **해설 극장**을 엽니다(해부가 아닙니다).
- 진행, 약점 변화(예측 적중, 표본이 모자라면 "판단 보류"), 보완 제안, 범위 수정 팝업이 있습니다.

### 3-8. 내 진단 `/csat/diagnosis` (로그인 필수)
- 실제 시험 답안을 입력하면 서버가 채점해 **점수·등급**을 보여 줍니다.
- 탭은 [개요 | 시험 기록 | 학습 지도]입니다. 개요는 게이지·도넛·막대·레이더이고, 시험 기록은 기록/유형/오답 함정/틀린 문항으로 나뉩니다.
- 모달 3종이 URL로 열립니다.
  - 기록 입력: [시험][답안] 탭
  - 기록 상세: [요약][답안][틀린 문항], 두 번 눌러 삭제
  - 학습 지도 노드 팝업: 목표·달성·현 상태·근거 탭과 과제 체크
- 이벤트 사용량이 가장 많은 화면입니다(조회 841).

### 3-9. 화면 사이의 연결

```
/hub ─(이어서)→ /csat 홈 ─(이어서 카드·start)→ /csat/dissect (소수 문항)
                  ├─(유형/함정 표 단계 카드)→ /csat/item/* · /csat/browse
                  ├─(Workspace)→ /csat/workspace/[id] ─(다음 문항)→ /csat/item/*
                  ├─(레일 진단)→ /csat/diagnosis
                  └─(레일 기록)→ /csat/record ─→ /csat/formulas ─→ /csat/dissect?formula=
```

## 5. 구조적 문제 (확인된 사실)

### 학습자 측
1. **학습 루프가 둘로 갈라져 있습니다.** 홈의 주 버튼은 해부(소수 문항, 예측 3수, 공식 축적)로 보내고, Workspace와 서가는 해설 극장(전체 문항, 예측 게이트 1회, 강의)으로 보냅니다. "내 공식"은 해부에서만 쌓이므로, 극장에서 공부한 내용은 공식·적중률에 거의 남지 않습니다.
2. **진입 장벽이 큽니다.** 극장의 왼쪽 원본은 학습자가 PDF를 직접 구해 놓아야 보입니다. 학평은 공개 링크조차 없습니다.
3. **"끝"이 정의되어 있지 않습니다.** 극장에는 완료 상태, 다음 복습 예약, 결과 저장 이벤트가 없습니다(예측 확정 이벤트도 없음). 간격 반복(FSRS)이 극장 학습과 연결되어 있지 않습니다.
4. **화면 수에 비해 측정이 비어 있습니다.** 서가, 게이트 확정, 내 공식에 이벤트가 없어서 퍼널을 볼 수 없습니다.
5. **한 영역 안에 결이 다른 화면이 섞여 있습니다.** 진단(점수·등급·차트)과 해부(정답률 없음)가 같은 영역에 있습니다. 스킨도 3B와 Tines가 섞여 있습니다.
6. 쓰지 않는 조각이 남아 있습니다. 빈 임시 파일 3개, 호환용으로만 남은 reveal API, 관리자에서만 쓰는 학습자 컴포넌트 6개가 있습니다.

### 공급(파이프라인) 측
7. 평가원과 학평의 **검수 기준이 다릅니다**(자기 3인 검수 vs 독립 블라인드 3인).
8. 평가원에는 근거 단위가 없어 문장 번호 결함이 남아 있습니다.
9. 추출기를 고친 뒤 영향을 받는 문항을 찾는 도구가 없어 사람이 비교합니다.
10. 관리자 화면이 아무것도 실행하지 않습니다. 모든 조치가 명령 복사와 CLI 실행입니다. 화면 이름도 교재 공장과 겹칩니다.
11. 도움말 안에서 도표 게이트 SQL을 적용했는지 여부가 엇갈립니다.

### 사업 측
12. 공급(분석 5,746행, 검수 1만 건 이상)과 수요(학습자 2명, 해부 완료 1회)가 극단적으로 불균형합니다. 새 분석을 더 만드는 것보다 **학습자가 한 번이라도 끝까지 가게 하는 것**이 병목일 가능성이 큽니다. 다만 이것은 가설이고 검증되지 않았습니다.

## 7. 바꾸지 말아야 할 제약 (재설계에서도 유지)
- 원문을 서버에서 학습자에게 보내지 않습니다(저작권). 대안이 있다면 법적 근거와 함께 제안해 주십시오.
- 수치는 DB 실측이나 즉석 계산만 씁니다. 지어낸 이용자 수·후기는 쓰지 않습니다.
- 학습 상태 컬럼(`memory_state` 등)은 저장하지 않고 동적으로 계산합니다.
- 접근성: 44px 이상 터치 타겟, 보이는 포커스, 색만으로 정보를 전하지 않음.
- 이벤트 속성은 숫자, 불리언, 닫힌 열거형만 씁니다.
- PC 웹만 대상으로 하고, 디자인은 3B 앱 참조입니다.
- LLM 작업은 에이전트 배치 드레인(export → 에이전트 → import) 구조를 씁니다.

## 9. 검토 요청 (ChatGPT에게)

아래 순서로 답해 주십시오. 각 제안에는 **근거**(학습 과학, 실측 데이터, 경쟁 서비스 사례), **비용**(새로 만드는 것과 버리는 것), **검증 방법**(어떤 이벤트·지표로 성패를 볼지)을 붙여 주십시오.

### A. 방향성
1. "출제자의 설계를 읽게 한다"는 목표가 고등학생 수능 영어 학습자에게 맞는 핵심 가치입니까? 더 강한 가치 제안이 있다면 무엇입니까?
2. 최종 목적지(학습자가 얻어야 하는 결과)를 한 문장으로 정의해 주십시오. 예를 들어 "유형별 공식 축적", "실전 점수 상승", "오답 함정 면역" 중 무엇입니까, 아니면 다른 것입니까? 그 목적지에서 거꾸로 볼 때 지금 파이프라인에서 불필요하거나 빠진 것은 무엇입니까?

### B. 학습자 경험 (가장 중점)
3. 갈라진 두 루프(해부 vs 해설 극장)를 하나로 통합할지, 역할을 나눌지 정하고 구체적인 흐름을 제시해 주십시오.
4. 홈 `/csat`의 첫 화면에서 학습자가 해야 할 **단 하나의 행동**은 무엇이어야 합니까? 지금 홈 영역(이어서 카드, 진단 카드, Workspace·유형·함정 표)의 우선순위를 재배치해 주십시오.
5. 해설 극장의 정보 구조(왼쪽 원본, 지문 지도와 게이트, 분석 탭, 강의 도크, 행동 상자)가 인지 부하 관점에서 과하지 않습니까? 단계적 공개(Progressive Disclosure) 순서를 다시 짜 주십시오.
6. PDF를 직접 놓아야 하는 진입 장벽의 대안을 제시해 주십시오(저작권 경계 안에서).
7. "끝"과 "다시 오기" 설계: 한 문항이나 한 세트를 마칠 때의 완료 상태, 피드백 문구, 간격 반복 예약, 다음 행동을 제안해 주십시오.
8. 진단(점수·등급)을 어디에 두어야 합니까? 원래 "채점 없음" 철학과 어떻게 공존해야 합니까?
9. 설명 문구(재는 능력, 설계 가설, 함정 이름 513종)를 학습자 언어로 어떻게 정리해야 합니까? 함정 이름 체계를 학습자용으로 몇 개 계열로 묶어야 합니까?
10. 각 화면의 팝업, 탭, 상태(로딩·빈·오류), 이벤트 목록을 재설계안으로 표로 내 주십시오. 측정이 비어 있는 곳(서가, 게이트 확정, 공식, 완료)을 반드시 포함해 주십시오.
11. 화면 디자인: 3B 앱 계열의 앱형 UI에서 이 영역에 맞는 레이아웃 원칙(밀도, 2열·3열 여부, 고정 판, 도크)을 제안해 주십시오.

### C. 파이프라인
12. 기출을 추가하는 단계부터 학습자 노출까지의 단계 중 합치거나 없앨 것, 자동화할 것을 제안해 주십시오(관리자 화면이 아무것도 실행하지 않는 현재 방식의 장단 포함).
13. 평가원과 학평의 검수 기준이 다른 문제를 어떻게 정리해야 합니까?
14. 수요 검증이 0인 지금, 공급(분석·검수) 작업을 어디서 멈추고 무엇을 먼저 해야 합니까? 우선순위를 단계별 로드맵(1주 / 4주 / 12주)으로 주십시오.

### D. 산출물 형식
- 재설계가 필요한지 결론(필요 / 부분 / 불필요)과 이유
- 새 정보 구조도(화면 목록과 화면 사이의 이동)
- 핵심 화면 3개의 와이어프레임(텍스트 ASCII)
- 이벤트 사양표(이름, 시점, 속성)
- 하지 않을 것 목록
