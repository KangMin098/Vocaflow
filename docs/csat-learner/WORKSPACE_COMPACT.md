## 3. 네 탐구 요소 ↔ 일곱 장면 (`lib/csat/inquiry/dock.ts` · `InquiryDock.tsx`)

| 요소 | 아이콘(접근 이름) | 장면 | 제목 첫 진입 |
|---|---|---|---|
| 원문 이해 | Target 평가 과제 · BookOpen 원문 이해 | task · meaning | meaning |
| 문항 설계 | Scale 문항 성립 · GitBranch 설계 재구성 | judgment · design | judgment |
| 비교와 원리 | Columns2 기출 비교 · Network 조건부 원리 | compare · principle | compare |
| 학습 정리(옛 내 설명 · T-0091) | NotebookPen 학습 정리 | explain | explain |

- 제목 = 그 요소의 마지막 장면(탭 메모리) · 아이콘 = 정확한 장면. 장면 정본(`scenes.ts` ID · 파서 · 별칭 · 기본 task)과 `scene=` 직접 주소가 먼저다.
- 선택은 면색 + 테두리 + `aria-pressed`(제목) · `aria-current`(아이콘). 제목과 아이콘은 형제 버튼(중첩 없음). 아이콘 이름은 `aria-label` + 호버 · 포커스 툴팁.
- 키보드: 제목 그룹 포커스에서만 ←/→ · Home/End(전역 강의 ←/→ 로 새지 않음) · Enter/Space 선택 · Tab 으로 아이콘.
- 방문 수 · 진행률 · 완료 체크 없음. 자료가 없는 장면도 열리고 이유를 말한다.

## 4. 두 판의 역할

| 장면 | 근거·관계(가운데) | 설명·판단(오른쪽) |
|---|---|---|
| task | 지문 지도(근거 위치) | 질문 · 확인할 관계 · 발문 요구(V3Task) |
| meaning | 지도(v3.1 의미 대조 강조) / 관계: 구조 도식 | MeaningSupportPanel(전체 → 정확한 뜻 → 왜/깊이 · 구절) |
| judgment | 지도(선지 근거) / 관계: 변환 도식 | V3Judgment · 정답 성립 · 비선정 조건 |
| design | 지도 / 관계: 설계 선택 도식 | 관찰 ↔ 설계 가설 구별 · V3Design |
| compare | 지도(비교 근거) | V3CompareExplorer(검수 쌍 · 대응 표 · 한계) |
| principle | 지도 | 원리 수준 · 잠정 원리 · 저장 |
| explain | 지도(과거 노트 근거 짚기) | 학습 정리(핵심 관계 · 제공 근거 · 원리/조건/반례 · 확인 과제 준비 상태 · 다음 활동) + 과거 작성 기록 읽기 전용 — 서술 입력 없음(DECISIONS CL-SL-1) |

- 「관계」 보기는 그 장면에 검수된 설계 도식이 있을 때만(관계선을 새로 만들지 않음 · 서술형 뼈대를 모든 유형에 씌우지 않음). 근거 판을 접으면 도식은 설명 판 아래로 온다.
- MeaningSupportPanel 내부의 관계 보기(MeaningRelationView)는 공개/대조 모델 재작성 금지에 따라 설명 판 안에 그대로 두었다 — 가운데 판으로 옮기지 않았다(잔여 §8).

## 5. 상태 · 저장

- 장면별 근거 선택 · 설명 판 스크롤 = 문항별 탭 메모리(`AnalysisTheater` `sceneMem`). 주소 · 뒤로가기가 장면을 정하고 메모리는 그 장면의 선택만 되살린다. 해제는 해제로 남는다(자동 선택 없음). 예외: 비교 장면의 쌍 근거(pair · diff)는 되살리지 않는다 — 비교 쌍 선택은 화면이 다시 열릴 때 새로 고르므로, 강조만 되살리면 보이지 않는 쌍의 근거를 비춘다. 문항 성립의 선지 근거(choice-n)를 되살리면 그 선지 설명도 함께 연다. 이어 온 맥락(bridge)이 있으면 지난 선택 대신 그 맥락.
- 학습자의 직접 장면 선택(도크 · 다음 장면)은 재생 중 강의를 기존 toggle 로 멈춘다 — 강의의 자동 장면 따라가기가 학습자 선택을 덮지 않는다. 재개는 학습자가.
- **T-0091(2026-10-23) 이후 아래 자기 설명 · 초안 · 노트 근거 연결 작성 흐름은 걷혔다** — 학습 정리에는 쓰는 칸 · 저장 · 대조가 없고, 예전 기록은 읽기 전용(지우지 · 덮지 · 재채점하지 않음). 아래 세 항목은 기록 계약(타입 · 병합 · 탭 메모리 옛 칸)의 이력으로 남긴다.
- (이력) 자기 설명: `onSave → Promise<boolean>`. 실패면 입력 · 같은 id · 처음 시각 보존 + 「다시 저장」, 성공이면 보낸 판만 비운다(보낸 뒤 새로 쓴 글은 지킨다). 부모 `saveExplanation` 은 같은 id 교체 · 실제 저장 성공 때만 목록 갱신(`lib/csat/explain-draft.ts`).
  - **수정 전 실패 증거**: `csat-workspace-compact` ① 을 변경 전 코드에서 실행 → `toHaveValue` 실패(`Received: ""` — 저장 실패에도 입력이 비워짐). 수정 후 통과(새로고침 뒤 같은 글 1건).
- 초안: 자기 설명 · 원리 노트의 입력 · 선지 · 비교 선택 · 저장 대기 id 를 문항별 부모 메모리에 — 장면 왕복 보존, 「새로고침 · 탭 종료면 사라져요」 안내. 의미 메모는 기존 무저장 정책 그대로.
- 원리 노트 근거 연결: 지금(또는 앞 장면에서 마지막으로) 고른 문장 근거를 「노트에 연결」 → 해제 가능 → 기존 `evidence` 로 저장 → 다시 열면 「연결한 근거 N번 문장 짚기」 가 지도에 비춘다. 지도 분할이 v3 와 다르거나 분석 버전이 다르면 위치를 짚지 않고 글로만. 밑줄 · 도표 등 문장 번호로 대응하지 않는 단위는 번호를 만들지 않는다. evidence 가 빈 기존 노트는 「연결한 근거 없음」.
- 원문 폭: 선호(저장) ≠ 표시. 메인 최소 712px 을 남기고 · 본문 크기 변화(레일 전환) 관찰 · 줄여 보일 때 안내(`lib/csat/paper-width.ts`). 기본 1280 ≈ 313 · 1440 ≈ 352.
