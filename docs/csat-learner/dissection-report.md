# /csat 분석 중심 구현 검증 — 2026-09-17

## 개발 서버 청크 복구 — 2026-09-18

3000번에서 `app/(main)/layout` 청크 로드 실패 제보를 받았다. 검사 시 해당 URL은 200이었으므로 최초 실패 원인은 확정하지 않는다.
동시에 실행되던 3000/3100 개발 서버를 종료하고 3000만 별도 `.next-dev-3000` 캐시로 재시작했다. 기존 캐시·소스는 삭제하지 않았다.
Next가 tsconfig에 새 생성 타입 경로를 추가했다. 청크 200과 브라우저의 3문항 예측·설계도·공식 화면을 확인했다.
같은 검사에 포함된 3G 성능 단언은 개발 모드에서 18,602ms로 실패했다. 앞선 프로덕션 측정과 구분하며, 전체 E2E 통과로 기록하지 않는다.
이미 열려 있던 브라우저 탭은 강력 새로고침하여 예전 모듈 그래프를 버려야 한다.

현재 구현은 정답 선공개 → 근거/오답 제조법/의도 예측 → 인라인 대조 → 설계도 → 공식 저장이다.
같은 유형·다른 소재 두 문항 뒤 전이 문항을 제공한다. 기존 인증·API·관리자 분석·DB 스키마는 유지했다.
**전체 저장소 테스트는 통과 상태가 아니므로 배포 완료로 판정하지 않는다.**

| MODIFY | 홈 카드, ItemScreen, SessionRunner, 내 공식 화면, 라우트/계측 선언, 관리자 evidence와 도움말 |

| REMOVE | `/csat/session`, `/csat/progress`의 페이지. 기존 채점 UI/이벤트 발행. 참조 검색 후 ReflowPassage의 사용되지 않는 해설 렌더 분기 제거 |
| CREATE | `/csat/dissect`, `/csat/formulas`, 순수 해부 모델, 검토 메타데이터·위치 산출물, 카탈로그 준비도 검사와 회귀 |

새 애플리케이션 패키지는 없다. Lighthouse 13은 기존 게이트와 같은 임시 검증 도구이며 package.json/lockfile에 추가하지 않았다.
새 예측·공식·전이 큐는 기기 IndexedDB 별도 키에 보관한다. 기존 풀이 정답률을 재해석하지 않으며 새 기록의 기기 간 동기화는 제공하지 않는다.

## Gate 0: 실제 데이터와 후보 제한

공개 문항 802개와 latest published 분석을 직접 조회했다. 근거/소재를 임의로 채우지 않는다.

| 필드 검사 | 충족 문항 |
|---|---:|
| 정답 · 근거 설명 · 출제 의도 | 각각 802/802 |
| 정답 문장 앵커 | 675/802 |
| 근거 위치가 있는 오답 제조법 | 575/802 |
| 같은 유형·길이 ±20%의 의도 보기 3개 | 793/802 |
| 함정 보기 4개 | 802/802 |
| 검토한 소재 · 형식 · wrapup 기반 공식 | 각각 12/802 |
| 실제 동형 기출 이력 | 7/802 |
| 모든 조건을 통과한 배포 후보 | **7/802** |

후보는 2026 #32·#34, 2025 #31·#34, 2024 #31·#33·#34다. 나머지 795문항은 제외 이유가 관리자 evidence에 표시된다.
이 목록은 읽기 전용 진단이며 DB 이벤트 테이블에 적재하지 않는다. 후보를 늘리려면 원문·분석·wrapup 의미 검토와 동형 이력 검증이 필요하다.

기존 공유 골격을 덮어쓰지 않고 로컬 원본 PDF에서 12문항을 검증했다. `dissect-anchors.json`에는 문장 길이·SHA-256·구간 위치만 담긴다.
서버 런타임은 지문/선지 컬럼을 조회하지 않고, 브라우저는 PDF 해시만 식별 API로 보낸다. 새 위치 산출물에 원문 문자열이 없고 구간이 유효한지 회귀로 검사한다.
인증이 만료되어 분석 조회가 비면 결함 802건으로 캐시하지 않고 오류로 처리한다.

## 동작·시각 검증

- Gate 1: 실제 PDF 2026/M2706 재측정. 문항 경계 100%, 문장 앵커 99.4%. [측정 JSON](./gate1-sample.json).
- 375/768/1440: 3문항 전 흐름, 제출 전 각 분석 미렌더, 본문 18px, 문장 터치 ≥48px, 의도/함정 보기 수, 설계도 5항목의 앞선 텍스트 출처, 공식 저장과 전이를 검사한다.
- 스크린샷 검토 후 설계도에서 반복 지문을 접고, 보조 강의 UI를 제거하고, 요약 글자를 18px로 맞췄다. 데스크톱은 읽기 폭을 제한하고 모바일은 한 열을 유지한다.
- axe WCAG2 A/AA·WCAG2.1 AA, 키보드 선택/제출, 가로 넘침, runtime 오류를 검사한다. 어두운 테마도 별도 검증한다.
- PDF 캐시 시 3G 조건(지연 150ms, 다운로드 200KB/s)에서 홈 탐색 시작 → 시작 한 번 → 첫 문항을 측정했다. 375/768/1440 각각 **1,230/1,274/1,270ms**로 모두 10초 이내다.
- Lighthouse 모바일 접근성: 홈/해부 진입/내 공식 100점. 해부 Lighthouse는 PDF 없는 진입 상태이며 실제 지문/설계도는 Playwright axe로 검증한다. [결과](./dissection-accessibility.json).
- Lighthouse의 홈/내 공식에는 점수에 반영되지 않는 `label-content-name-mismatch` 권고가 남아 있다. 100점이 모든 보조 진단 0건이라는 뜻은 아니다.
- 공유 라우트 `/library/books`, `/wordvault/browse`, `/dashboard`, `/text`를 프로덕션에서 확인한다.
- 관리자 패널은 개발 검증에서 채움률을 측정한다. 프로덕션 학습자 계정은 패널에 진입하지 못하는지 별도로 검사한다. 권한을 높이거나 가드를 우회하지 않았다.
- 최종 프로덕션에서 화면 3크기·공유 라우트/다크 테마 4검사 통과, 관리자 접근 경계 1검사 별도 통과. 키보드로 예측/저장/전이를 끝내고, 375px에서는 실패 캐시 → 문제지 다시 놓기 → 원문 재추출도 통과했다.

이미지는 원문을 포함하므로 무시된 `apps/web/test-results/` 아래에만 저장한다. 최종 프로덕션 실행 결과와 스크린샷은 `csat-production-final` 하위에 남긴다.

## 빌드·회귀와 남은 검증 문제

- 관련 회귀 **106개 통과**: 해부 구성/3일 전이/셔플/중복 공식/메타데이터 누락/원문 경계/인증 빈 조회, 기존 reflow·풀이 모델·동기화·계측·API 참조·링크 그래프.
- 피드 발견 회귀 **35개 통과**. 전체 검사에서 발견한 시스템 날짜 의존 오류를 주입 시각 사용으로 수정했다.
- 워크스페이스 lint/typecheck **10 작업 통과**. 기존 다른 모듈 hook 경고는 남아 있다.
- 최종 `pnpm --filter web build` **종료 코드 0**. 변경 완료 후 고정된 빌드를 3101 포트에서 실행해 검증했다.
- 웹 전체 실행은 **3,607 통과·22 실패·3 건너뜀**이었다. 이번 화면의 호출 제거로 생긴 API 참조 실패 2건은 기존 API 계약 보존 사유를 명시한 후 관련 회귀에서 통과했다.
- 남은 실패는 교재 라우트 선언 불일치, 기존 관리자 터치 검사/드레인 문서·스냅샷, 삭제된 오버레이를 읽는 옛 테스트, 기존 강의 인용 경계, 페이징/쓰기 예산, 실 DB 사전·발행 콘텐츠·컴포저 품질·DB 통계·채점 관측이다. 이 상태를 통과로 숨기거나 DB 데이터를 디자인 수정에 맞춰 변경하지 않았다.
- 전체 테스트 재실행과 브라우저 검증은 검증 계정을 공유하므로 병렬로 돌리면 인증에 영향을 준다. 재실행은 중단하고 관련 회귀·브라우저·최종 빌드를 분리 검증했다.
- 전체 회귀가 실패한 상태의 push는 AGENTS.md Git 규칙상 확인 대상이다. 이번 작업은 커밋/푸시하지 않았다.

## 재현

저장소 루트에서 `pnpm.cmd --filter web typecheck`, `pnpm.cmd --filter web lint`, `pnpm.cmd --filter web build`.
브라우저 세션은 기존 `apps/web/scripts/e2e-session.mts`로 갱신한다. 전체 통합 테스트와 동시에 갱신하지 않는다.
`PLAYWRIGHT_BASE_URL`을 실행 중인 서버로 설정한 뒤 `pnpm.cmd --filter web exec playwright test tests/e2e/47-csat-session.spec.ts`.
프로덕션 학습자 계정 검증은 `CSAT_EXPECT_ADMIN_DENIED=1`로 관리자 접근 거부를 기대한다. 개발 관리자 검사에서는 설정하지 않는다.
Lighthouse는 `scripts/csat-learner/dissection-accessibility.mts --lighthouse <설치된 lighthouse/core/index.js> --base <로컬 서버>`로 실행한다. 인증 값은 로그/리포트에 남기지 않는다.
