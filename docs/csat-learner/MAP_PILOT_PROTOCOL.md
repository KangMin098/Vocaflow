# 학습 지도 실제 학습자 파일럿 프로토콜(초안 · 2026-10-10 · MC-12)

> 상태: **준비(PROPOSED)**. 모집 · 수집은 하지 않았다. 사용자 승인과 동의 절차가 준비돼야 시작한다.
> 목적은 하나다. 지도의 생애주기(직접 확인 → 바로잡기 → 적용 → 다시 확인)가 **실제 학습자에게** 근거 판단 능력의 변화를 만드는지 잰다. 실제 표본이 없으면 효과는 PASS 가 아니다(MAP_EDUCATIONALLY_VALIDATED 아님).
> 재사용하는 것: 효과 판정 `apps/web/src/lib/knowledge/protocol.ts`(사전 · 사후 · 지연 · 전이 단계, 효과 입력 제외 규칙), 기록 계약 G2(`learning_task_attempts` 추가 전용 원장), 학습 계약 [G0_LEARNING_CONTRACT](./G0_LEARNING_CONTRACT.md).

## 1. 대상 · 동의 · 개인정보

| 항목 | 내용 |
|---|---|
| 대상 | 고등학생(수능 준비). 초등 · 중등은 확인 문항이 고등 기출뿐이라 이번 파일럿에서 뺀다(D-10 결정 뒤 별도) |
| 동의 | 본인 동의. 미성년이면 보호자 동의도 받는다. 동의서에 적을 것: 목적 · 수집 항목(과제 응답 · 판단 시각 · 도움 여부) · 보관 기간 · 철회 방법 · 성적과 무관함 |
| 최소 수집 | 이름 · 학교는 받지 않는다. 계정 id 와 학교급만 받는다. 분석 산출물에는 계정 id 해시만 남긴다 |
| 철회 | 철회하면 분석에서 뺀다. 원장은 추가 전용이므로 지우지 않고 「분석 제외」 목록으로 처리한다 |
| 합성 제외 | example.com · 관리자 미리보기 · 역할 학습자 기록은 효과 입력에서 자동으로 빠진다(`effectEligible`) |

## 2. 일정(학습자 1인)

| 주 | 단계 | 문항 | 기록 phase |
|---|---|---|---|
| 0 | 사전 평가 | 근거 판단 · 본문↔선지 확인 문항 각 3(같은 유형 · 처음 보는 문항) | `pre` |
| 1–2 | 학습 | 지도 생애주기 — 직접 확인 → 바로잡기(§13 절차) → 다른 글 적용 → 다시 확인 | `practice` · `transfer` |
| 2 | 사후 평가 | 처음 보는 같은 유형 문항 각 3 | `post` |
| 4 | 지연 평가 | 처음 보는 같은 유형 문항 각 3(사후 14일 뒤 · `DELAYED_DAYS`) | `delayed` |
| 4 | 전이 | 연습하지 않은 유형(예: 요약 · 함축)의 근거 문장 찾기 각 3 | `transfer` |

- 문항은 사전 · 사후 · 지연 · 전이 사이에 겹치지 않는다. 배정은 학습자마다 무작위로 균형을 맞춘다(같은 문항이 늘 사전에만 오지 않게).
- 확인 문항 풀이 모자란다. 지금 활성은 근거 11문항이다. 파일럿 전에 과제당 최소 12문항(사전 3 + 사후 3 + 지연 3 + 직접 확인 · 다시 확인 3 이상)을 합의 주석 · 맹검 채택으로 늘린다.

## 3. 측정 · 판정

- **주 지표:** 근거 문장 선택 첫 시도 정답률의 사전 → 사후 · 지연 변화.
- **보조 지표:** 함정 문장 선택률(오답 선지가 비튼 문장), 선지 정답률, 전이 정답률.
- **판정:** `protocol.ts` 기준을 그대로 쓴다.
  - 표본: 학습자 20명 이상, 학습자당 사전 · 사후 각 3 이상. 모자라면 `insufficient_data`.
  - 결과 범주: positive · no_effect · negative · inconclusive.
- **비교 조건:** 같은 기간 지도 생애주기를 거치지 않은 학습자의 같은 문항 정답률이다. 무작위 배정이 어려우면 대기 통제(나중 시작) 집단을 둔다.

## 4. 결측 · 도움 처리

- **해설 먼저 본 시도:** `viewed_first` · 해설 뒤 · 시각 불확실 시도는 효과 입력에서 빠진다(독립 첫 시도만).
- **중도 이탈:** 사후 · 지연을 빠뜨린 학습자는 그 단계 분석에서 빠진다. 이탈률은 따로 보고한다(결과를 좋게 보이게 빼지 않는다).
- **기한:** 지연 평가가 14일 ±3일을 벗어나면 「지연 시점 벗어남」 으로 표시하고 따로 본다.

## 5. 결과 기록

- 결과는 완료 계약 MC-12 행과 `docs/csat-learner/pilot-runs/` 에 날짜 · 표본 수 · 판정 · 제외 수를 남긴다.
- 표본이 기준에 못 미치면 MC-12 는 UNKNOWN 으로 남긴다.

## 6. 시작 전에 필요한 것(승인 대상)

0. **효과 판정 연결(코드):** `protocol.ts` 는 지금 `claim-support` 과제와 `claimHit` 지표만 집계한다. 그래서 E축 기록(evidence-locate · option-restate)은 효과 입력에서 모두 빠진다. 파일럿 전에 E축 과제 키와 정답 지표(`isCorrect`)를 판정 입력에 연결해야 한다(Codex P2).
1. 사용자 승인: 대상 · 동의서 문안 · 보관 기간.
2. 확인 문항 풀 확장(과제당 12 이상): 합의 주석 · 맹검 채택 → 활성화. 개발 DB 쓰기다.
3. 사전 · 사후 · 지연 배정 화면. 지금 지도에는 `pre` · `post` · `delayed` 단계 배정 화면이 없다. 구현이 필요하다.
