# v3.1 원문 이해 — 교수 · 화면 · 데이터 · 검수 계약

## 0. 목적과 경계

학습자가 영어 문장이 전달하는 의미를 형성하고, 쉬운 말로 바꾸되 주체·조건·부정·범위를 보존하고, 문장들을 연결해 글의 생각·상황을 이해하도록 돕는다. 이렇게 이해한 의미를 문항 성립과 설계 해석으로 연결한다. 번역·구문 라벨·정답 요령만 추가하는 작업이 아니다.

기존 7장면(task→meaning→judgment→design→compare→principle→explain)은 유지한다. 아래 여섯 교수 과정은 **meaning 안의 지원 방식**이며, 필수 수행 순서·여섯 메뉴·여섯 점검 시험이 아니다. 정답 제출·글쓰기·강의 완료를 열람 조건으로 삼지 않는다.

PC 1280/1440 라이트, 기존 CSAT 셸·3B 방향·토큰 보존. 다크/모바일 제외. 메뉴·강의 확장·학평·비공개 비교 12쌍 보류. 원리 노트와 지도 진단의 의미·권한·기록을 변경하지 않는다.

## 1. 교수 과정과 관찰할 행동

| 지원 | 어려움과 목표 | 처음 제시 → 더 보기 | 선택 행동과 확인 기준 |
|---|---|---|---|
| 의미 형성 | 복잡한 구문에서 누가 무엇을 하는지 파악 | 원문 선택 위치 + 문맥 뜻 → 주절·수식·절의 연결 | 주어/술어·수식 대상 구별. 용어 암기가 아니라 결합 후 전체 의미 설명 |
| 쉬운 재구성 | 번역을 읽어도 개념이 어려움 | 정확한 뜻 + 쉬운 말 1개 → 용어를 익숙한 개념으로 풀기 | 같은 내용을 자기 말로 표현. 친숙한 비유는 설명용임을 표시하고 원문 사실과 구별 |
| 의미 보존 | 쉬운 말이 범위·조건을 바꿈 | 이번 의미의 핵심 보존 조건 → 최소 변형 오해 예와 다른 점 | 주체·부정·조건·수량·가능성·시간·지시를 원문과 대조. 체크는 자기 확인이지 채점 아님 |
| 문장 연결 | 개별 뜻은 알지만 연결이 안 됨 | 두 의미 + 실제 변화 설명 → 그 관계의 구문·지시 단서 | ‘양보’라는 이름 대신 무엇을 인정하고 무엇을 유지하는지 설명 |
| 전체 통합 | 핵심 생각/사건이 안 잡힘 | 유형에 맞는 짧은 글 전체 이해 → 선택 문장의 기여·예외 | 핵심 주장과 조건, 또는 사건·행위·상황의 흐름을 함께 설명 |
| 추론 검증 | 어디까지 읽어도 되는지 불확실 | 명시 내용 / 연결을 위한 추론 / 원문 밖 확장 → 각 근거와 한계 | 지문이 말한 것과 분석자의 연결 해석을 구별. 불확실한 추론을 유일한 결론으로 단정하지 않음 |

단어·구문·쉬운 재진술·연결 설명은 이해를 돕는 **제품 가설**이다. McNamara의 SERT 연구도 단순 재진술과 설명 전략을 구별하며, 효과는 배경지식·텍스트·질문 종류에 따라 달랐다. 이 설계의 한국 EFL 기출 학습 효과를 입증하지 않는다. [원 논문](https://andymatuschak.org/files/papers/McNamara%20-%202004%20-%20SERT.pdf), [저자 연구실 서지](https://soletlab.asu.edu/reading-comprehension-publications/).

첨부가 언급한 국내 강사·교재의 이름/원 자료가 제공되지 않아 특정 교수법을 검증했다고 쓰지 않는다. 익숙한 표현을 쓰되 교재 설명을 복제하지 않는다.

## 2. 정보 구조와 화면 골격

```text
기존 원문 판                     02 원문 이해 — 기존 분석 판
문장 / 구절 선택                 이번 글의 생각·상황(짧게) + 선택 위치
원문 표시 그대로                 핵심만 | 왜 그런가 | 깊이 탐구
선택·근거 표식                   정확한 뜻 → 쉬운 말 → 보존할 조건
                                [선택한 의미가 앞뒤와 연결되는 방식]
기존 지도: 같은 근거 표시         필요할 때 구문 결합 / 오해 대조 / 내 말로
                                문항 성립에서 보기 · 설계 재구성에서 보기
```

- 새 최상위 메뉴/화면/진단을 추가하지 않는다. 기존 좌측 원문과 우측 작업 판을 사용한다.
- 기존 의미 목록과 교수 설명을 동일 내용으로 중복 쌓지 않는다. 확장 ready 문항은 기존 meaning 목록을 ‘탐구할 의미’ 선택기로 재사용하고, 하나의 설명 영역을 바꾼다. 확장 없는 문항은 V3Meaning+StructureDiagram 그대로다.
- 처음에는 검수된 전체 이해 1~2문장과 시작 의미 1개, 짧은 정확한 뜻·쉬운 말·핵심 보존 조건만 보인다. 교사가 선택한 defaultUnit은 추천 시작점일 뿐 ‘가장 중요한 문장’이나 학습자 취약점 판정이 아니다. 다른 문장·의미를 바로 고를 수 있다.
- 깊이는 모든 학습자에게 열려 있다. 깊이를 점수·수준·진단으로 자동 선택하거나 저장하지 않는다.
- ‘핵심만’: 선택 의미의 정확한 뜻·쉬운 말·핵심 보존 조건 + 전체에서의 기여.
- ‘왜 그런가’: 위 내용 + 구문 결합 이유 + 앞뒤 관계의 실제 의미 설명.
- ‘깊이 탐구’: 위 내용 + 오해 변형·추론 경계·다른 가능한 읽기. ‘내 말로’는 선택적 disclosure이며 어느 깊이에서도 열 수 있다.
- 새 데이터로 전체 이해를 표시할 때는 ‘전체의 생각’·‘사건 흐름’·‘안내 내용’·‘도표 읽는 범위’ 등 유형에 맞는 제목을 쓴다. 전체 문장별 번역을 기본 펼침으로 제공하지 않는다.
- 연속 장문 카드를 쌓지 않고 선택 의미/관계와 한 설명 판을 공유한다. 설명 길이의 숫자 상한을 맞추려고 의미를 생략하지 않는다. 길이는 파일럿 화면과 학습자 관찰로 조정한다.
- 원문 없는 경우 한국어 검수 설명은 허용된 공개 범위 안에서 읽을 수 있다. 없는 영어 원문을 서버에서 새로 제공하거나 구절 선택이 가능한 것처럼 보이지 않는다.
- 원문 존재 여부·표시 방식(PDF 글자/이미지/추출 실패)을 분리한다. 이미지로만 보이는 도표/원문에는 정확한 구절 선택을 강요하지 않는다.

## 3. 원문 선택과 의미 연결

### 3.1 단일 선택 상태

부모 AnalysisTheater가 `selectedUnitId`, `selectedRelationId`, `depth`, `focusOrigin`을 소유한다. Focus origin=`learner|lecture|none`; 새 탐구는 learner다. V3Meaning/MeaningSupportPanel/PassageMap/원문 판이 같은 선택을 소비한다. 선택이 강의 재생·seek를 일으키지 않는다.

- 원문 문장 선택 → 그 문장을 포함한 검수된 unit 1개면 선택. 여러 개면 짧은 후보 목록. 없음이면 ‘이 문장은 추가 설명이 아직 없어요’와 기존 의미/구조 설명 제공. 영어 클릭만으로 설명 생성하지 않는다.
- 구절 선택 → 브라우저 원문 구간을 검증된 anchor와 대조. 겹치는 검수 unit만 제안하며 사용자 선택 문자열은 서버·이벤트로 보내지 않는다. 여러 번 등장하는 구절은 문장/구간까지 일치해야 한다.
- 카드 선택 → 동일 문장·구절을 표시. 다시 선택/해제, 다른 unit, 관계 변경, 장면 이탈, 문항 변경에는 이전 의미 강조가 남지 않는다.
- 관계 선택 → 양쪽 unit 요약과 ‘앞 의미가 뒤에서 어떻게 변했나’를 한 판에 보인다. 근거 단어·구문을 열 수 있다. 실제 antecedent를 임의로 앞 문장이라고 고정하지 않는다.
- 구문 선택 → 원문 안 주절/수식 관계 표시 + 원래 어순으로 다시 결합한 뜻. 표시된 교정 문장은 원문과 구별한다.

현재 PassageMap의 `onSelect`는 근거 칩 이벤트다. 별도 `onSentenceSelect` 계약을 추가해 의미 문장 선택을 오답/정답 칩 선택과 혼동하지 않는다. 실제 글자 판 선택은 ItemPaper가 제공하는 현재 기기 passage 경로와 연결하며 PDF 캔버스에 DOM 글자 선택이 가능하다고 가정하지 않는다. 파일럿에서는 의미 선택기→원문 위치 확인도 완전한 경로로 제공한다.

### 3.2 다른 장면으로 이어가기

기존 `v3.choices[].meaning_ids`를 통해 unit의 legacyMeaningIds와 선택지 결정 조건을 연결한다. 자동 정답 제출이나 선택지 채점은 없다.

- ‘문항 성립에서 보기’ → `scene=judgment`에 검증된 의미/선지 연결. 없으면 장면만 이동하고 자동 관련 선지 표시를 하지 않는다.
- ‘설계 재구성에서 보기’ → `scene=design`; source observation과 design hypothesis를 구별한다. 관계 설명이 출제자 사고의 공식 기록으로 바뀌지 않는다.
- URL: `scene=meaning&meaning=<검증된 unit id>&depth=brief|why|deep`. ID는 현재 문항 allowlist로 검증하고 잘못된 값은 기본 상태로 정규화한다. 자유 선택 문자열·개인 초안을 URL에 넣지 않는다.
- judgment/design으로 이어갈 때도 meaning/depth와 기존 `from=map`, `check`, `pair`, `back` 맥락을 보존한다. 현재 이를 함께 처리하는 공용 parser는 없으므로 `meaning-support/model.ts`에 새 순수 parser/URL builder를 두고 기존 pair 처리·scene parser와 결합해 검증한다. ‘원문 이해로’ 복귀/브라우저 history가 선택을 복원한다. 문항별 허용 pair를 확인하고 back은 기존 내부 slug 규칙을 따른다.
- check 모드에서는 새 의미 설명을 자동 공개하지 않는다. 학습자가 설명으로 진입하면 기존 reveal/help 기록 계약을 따라 independent 시도와 설명 후 활동을 구별한다. 새 구현이 채점·진단 모델을 건드리지 않는다.

## 4. 이벤트 · 반응 · 예외 · 상태 전이

상태 축을 독립 유지한다: 콘텐츠=`missing|unreviewed|stale|ready|withheld`, 원문=`absent|image_only|mapped|unmapped`, 선택=`none|unit|relation`, 초안=`empty|editing|compared`. 설명 조회 실패가 전체 문항·기존 분석을 잠그지 않는다.
검수 보류(review_hold)는 빌드 단계에서 배포 파일에 들어가지 않는다. 현재 접근 보류(access_withheld)는 이미 pass인 자료도 현재 문항 권한 때문에 조회/SSR에서 제외되는 상태다. 두 층을 같은 fixture 주입 방식으로 테스트하지 않는다.

| UI 이벤트 | 상태/반응 | 예외와 복귀 |
|---|---|---|
| meaning 진입 | 콘텐츠 lookup, allowlist URL 복원, 기본 brief | 확장 없음/보류/낡음은 기존 패널로 fallback; 이유 과장 안 함 |
| 문장·구절·의미 선택 | 같은 unit과 원문/지도 focus | 원문 없거나 mapping 실패면 설명은 유지, 구절 강조 끔 |
| 관계 선택 | unit 두 개와 semantic change 설명 | 연결 unit 누락은 데이터 검증 실패; 빈 카드 생성 안 함 |
| 깊이 변경 | 현재 선택 유지, 설명 disclosure 변경 | 데이터 없는 깊이는 사실 안내. 강의/점수/진도 변경 없음 |
| 구문/오해 보기 | 원문 범위와 설명·반례를 같이 확인 | 원문 오류 교정과 학습용 변형은 original 표시를 덮지 않음 |
| 내 말로 작성 | 현재 unit의 짧은 초안 | 600자 초과는 잘라내지 않고 오류 안내. 자동 ‘정답’ 판정 없음 |
| 보존 조건 대조 | 검수 예·보존 목록과 내 글 병렬 | 유창성·키워드 일치로 이해도 판정 안 함; 틀린 항목을 시스템이 추측하지 않음 |
| unit/장면 변경 | 해당 초안을 부모의 item+unit 메모리에 유지; focus 교체/해제 | 초안이 사라지는 조건(새로고침/문항 이탈)을 작성 전 표시 |
| 판단/설계로 이동 | 기존 navigation+검증된 연계 target | 링크 대상 없음은 장면 이동만. source rights/reveal 재검사 |
| popstate/새로고침 | 유효한 URL 선택·깊이 재구성 | 메모리 초안은 복원되지 않음. 저장 성공 배지 없음 |
| 원문 교체/로그아웃 | 구절 대응 재검증, 개인 초안 초기화 | 옛 오프셋 재사용 금지; 서버/캐시 비공개 데이터 제거 |

UI 이벤트는 typed callback/reducer 이벤트다. 퍼널 DB 이벤트와 별개다. 기존 `screen_viewed` 진입을 중복 집계하지 않고, 검수 설명을 사용자가 펼치는 행위에는 의미가 맞는 기존 `csat_session_explained(kind='more')`만 사용한다. 깊이·문장 선택을 `csat_evidence_opened(kind='answer|reject')`로 위장하지 않는다. 세부 계측이 필요하면 별도 변경안(타입·API whitelist·DB CHECK·검수·승인)을 만들고 승인 전 전송하지 않는다. 자유 글·원문·선택 구절·문항 ID·해시를 퍼널 속성으로 보내지 않는다.

첫 파일럿의 ‘내 말로’는 **메모리 초안**이다. 저장 버튼/저장 완료/서버 동기화 없음. 같은 문항 내 unit/장면 이동에서는 유지하고 문항 이탈·새로고침·로그아웃에서는 소실됨을 표시한다. 영구 원문 이해 노트는 별도 후속 설계이며 ReasoningNoteForm/원리/진단에 흡수하지 않는다. 학습 효과 검증에 초안을 수집하려면 별도 참여 동의·보관/삭제 계약을 먼저 정한다.

## 5. 최소 콘텐츠 계약 — 기존 v3와 분리

`InquiryV3`를 통째로 다시 쓰지 않는다. 신규 서버 전용 정적 sidecar `apps/web/src/lib/csat/meaning-support-data.json`와 labels/lookup 모듈을 제안한다. 이름은 신규 파일이며 현재 구현되어 있지 않다. 기존 의미 IDs를 참조하고, 새 설명 content hash를 기존 inquiry hash 밖에 둔다. 786개 검수 pass·749쌍 결속·110개 원리를 무효화하는 부수 효과를 방지한다.

### 5.1 논리 모양

```ts
type Depth = 'brief' | 'why' | 'deep'
type Facet = 'agent' | 'polarity' | 'condition' | 'quantity' | 'modality' | 'time' | 'reference' | 'causality' | 'comparison'
type Basis = 'source_observation' | 'bridging_inference' | 'explanatory_elaboration'
interface Anchor {
  id: string
  sentence: number                 // 기존 입력 1-기반, 인쇄 순서를 보존
  quote?: string                   // 기존 공개 expression 재사용, 최대8단어
  occurrence?: number              // quote가 있으면 문장 안 중복 구절 1-기반
  sourceRange?: { start: number; end: number; spanHash: string } // 원문 없는 메타데이터
  mode: 'original'                 // 모든 anchor는 실제 원문에만 결속
}
interface Proposition {
  id: string
  textKo: string
  basis: Basis
  anchorIds: string[]
  warrantsKo: string[]             // 추론이면 연결 이유; 관찰이면 빈 배열 가능
  limitKo: string                  // 추론/비유의 경계; 명시 관찰은 빈 문자열 가능
}
interface MeaningUnit {
  id: string
  sentences: number[]
  legacyMeaningIds: string[]
  labelKo: string
  exactKo: string
  simpleKo: string
  propositionIds: string[]
  preserves: { facet: Facet; valueKo: string; anchorIds: string[]; explanationKo: string }[]
  syntax?: {
    parts: { id: string; role: 'main' | 'modifier' | 'clause' | 'connector'; anchorIds: string[]; meaningKo: string }[]
    attachments: { fromPart: string; toPart: string; whyKo: string }[]
    recombinedKo: string
    originalIssueKo?: string
    correction?: { form: string; explanationKo: string } // 작성한 교정 예, 원문 anchor가 아님
  }
  misunderstanding?: { alteredKo: string; lostFacet: Facet; whyWrongKo: string; anchorIds: string[] }
}
interface MeaningRelation {
  id: string
  from: string[]                    // unit IDs, 실제 선행 조건
  to: string[]
  kind: 'add' | 'example' | 'contrast' | 'concession' | 'cause' | 'condition' | 'reference' | 'temporal' | 'purpose' | 'other'
  beforeKo: string
  afterKo: string
  changeKo: string                 // 인정/추가/제한/수정/사건 전제가 실제로 무엇인지
  propositionIds: string[]
  anchorIds: string[]
  basis: Basis
  warrantsKo: string[]
  limitKo: string
}
interface ReadingSupportV31 {
  schema: 'meaning-support/1'
  itemId: string
  binding: { analysisVersion: number; unitsHash: string; basePublicHash: string; sourceSnapshotHash: string }
  sourceRef: { organizer: 'kice'; examId: string; itemNo: number; inputRef: string }
  defaultUnitId: string
  anchors: Anchor[]
  propositions: Proposition[]
  units: MeaningUnit[]
  relations: MeaningRelation[]
  whole: { genre: 'argument' | 'expository' | 'narrative' | 'practical' | 'visual'; summaryKo: string; propositionIds: string[]; relationIds: string[]; limitsKo: string[] }
  bridges: { unitId: string; meaningIds: string[]; choiceNumbers: number[]; designClaimIndices: number[] }[]
}
```

이 타입은 **설계 계약**이다. production 타입/검증기는 C1에서 작성한다. 모든 문장/구문을 분석하지 않는다. 파일럿은 문항마다 실제 도움이 필요한 unit 2~4개부터 시작하며 기본 수량을 전체 유형에 강요하지 않는다. syntax·misunderstanding은 필요한 unit에만 둔다. facet 빈 배열은 해당 의미에 보존해야 할 한정이 없다는 독립 검수 판단이 있을 때 가능하고, 부정/조건/수량/가능성의 누락을 빈 배열로 숨기지 않는다.

각 unit은 원문 의미 형성과 문맥 통합에 필요한 의미를 다룬다. 선택지 판정에 직결되지 않는 일반 이해 unit도 허용한다. bridges는 확인된 연결만; 빈 배열이 허용된다. `legacyMeaningIds`가 없는 unit은 기존 의미를 임의 생성하지 않고 문장·명제 근거로 검수한다.

### 5.1a 기존 scope와 보존 facet

| 기존 scope | 새 지원에서 재사용할 후보 | 자동 변환 금지/보완 |
|---|---|---|
| negation | polarity | 부정이 걸리는 정확한 명제를 원문 대조 |
| condition | condition | 조건인지 may의 가능성인지 분리; may는 modality 후보 |
| agent | agent | 실제 행위자·대상·화자와 구별 |
| time | time | 인쇄 순서·사건 순서·시제를 분리 |
| quantity | quantity 또는 comparison | 수량/범주와 순위/배수 관계를 내용으로 판정 |
| reference | reference | 지시 대상과 범위를 검수 |
| contrast | relation.kind=contrast의 후보 | facet로 억지 변환하지 않고 실제 바뀌는 주체/범위/극성을 따로 확인 |
| none | 후보 없음 | 조건·가능성 부재라는 뜻 아님; 필요한 한정은 원문에서 새로 확인 |

modality·causality·comparison은 원문에 실제로 있을 때 추가한다. 이 표는 작성자의 탐구 질문이며 새 보존 조건을 자동 판정하는 변환 함수가 아니다.

### 5.1b 파일럿 인용 예산과 구간 정보

파일럿의 **새 원문 영어 인용 예산은 0**이다. 공개 anchor.quote/설명 안 영어 원문은 해당 문항에서 이미 공개된 `v3.meanings[].expression`의 표현/그 안의 연속 구절만 재사용한다. 8단어 이하이며 같은 표현을 여러 필드에 복제해 원문을 재구성하지 않는다. C0는 현재 expression의 문항별 인용 단어 수·중복 제거 원문 구간·원문 대비 비율을 비공개 입력으로 측정해 기준선을 남긴다. 새 공개 인용 구간의 합집합은 그 기준선 구간의 부분집합이어야 하고, 같은 표현의 반복 렌더는 한 번으로 합친다. 권리 확인이나 전체 의미 재구성의 적법성을 이 수치만으로 통과시키지 않는다.

기존 인용 밖 구문을 실제 원문 판에서 강조할 때는 quote 없이 sourceRange를 사용한다. anchor에는 quote 또는 sourceRange 중 하나 이상이 필요하다. sourceRange의 start/end는 원문 입력 문장의 공백 정규화 문자열(연속 공백→한 칸, 양끝 trim) 기준 0-기반 UTF-16 반열린 구간, spanHash는 그 구간의 SHA-256이다. 생성 시 전체 원문으로 검증하고 표시 시 같은 정규화와 원문 index 대응표를 사용해 실제 표시 구간을 찾는다. 원문 없이 해시에서 문자열을 복원하지 않는다. 현재 표시 원문과 구간 해시가 다르거나 index 대응이 불확실하면 구절 강조를 끄고 문장 수준/설명 fallback한다. correction은 별도 작성 예로 표시하고 인용 예산 검사와 원문 정합 검수에서 교정 전후를 구별한다.

향후 새 인용이 필요하면 구체 문항·추가 구간·누적 예산·권리 근거가 있는 별도 변경안으로 다룬다. 기존 8단어 제한을 잘게 쪼개 원문 전체를 공개하지 않는다.

basePublicHash는 **실제로 배포된 inquiry-data.json의 해당 item 전체 레코드**(analysis_version·review·distractors·principle·v3)를 파싱한 뒤 canonical JSON으로 SHA-256한 값이다. 객체 키는 재귀 정렬, 배열 순서는 유지하고 문자열 의미를 바꾸는 정규화는 하지 않는다. 빌드·CI·서버 lookup이 같은 순수 함수를 사용한다. 기존 작성 결과의 contentHash/inquiry_hash와는 다른 값이다. 파일 경로·메타데이터는 해시 입력에서 제외하고 레코드 필드를 임의로 생략하지 않는다. basePublicHash를 기존 비교 결속의 inquiry_hash에 대입하거나 기존 검수 해시를 바꾸지 않는다.

sourceSnapshotHash는 비공개 원문 입력의 원문·발문·선지·도표 확인 상태를 안정적 직렬화로 해시한 값이다. 원문 입력 파일 본문이나 학습자 개인 PDF 파일 경로를 공용 산출물에 넣지 않는다. §5.1b의 짧은 anchor.quote는 예외이며 C1에서 8단어·새 구간0 예산을 검사한다. inputRef는 공정의 비민감 식별자다. 실제 원문 개정 감지는 해당 해시 재계산과 기기 표시 원문의 대응 검증으로 수행하며 정적 JSON만으로 DB 원문 변경이 자동 감지된다고 주장하지 않는다.

### 5.2 결속·공개와 서버 projection

1. 현재 문항 접근권한/Reveal Gate 확인 → lookupInquiry가 ready인 경우에만 확장 lookup.
2. sidecar.analysisVersion/unitsHash/basePublicHash를 **현재 공개 base inquiry 레코드와 그 직접 계산 해시**에 대조. live analysis_version도 현재 item과 일치해야 한다. 별도 writer hash manifest만 대조하지 않는다. 같은 분석 버전/문장 분할에서 meaning_ko만 바뀌어도 basePublicHash가 바뀌어야 한다. 값 없음·불일치는 sidecar stale, 기존 유효 v3는 유지.
3. 검수는 별도 문항·schema·revision·binding·contentHash·writerRun·reviewerRun·criteriaVersion·explicit verdict에 결속. 기존 inquiry pass로 새 설명을 공개하지 않는다.
4. 서버는 현재 공개 문항 1개의 허용 projection만 보낸다. corpus JSON client import, 보류 설명 SSR/Flight/공용 API 전송, 원문/PDF/개인 초안 첨부 금지.
5. 실제 렌더 원문이 없으면 한국어 설명은 권리 정책이 허용하는 범위만 읽고 anchor는 inactive. mapped 상태의 구절 강조는 문장 수/길이가 아니라 실제 구절·중복 occurrence·문장 대응으로 검증한다.
6. 문장 단위 매핑만 확실하면 문장 강조만, 구절이 불명확하면 span 표시 끔. 재업로드/문항 변경에 매핑 캐시 무효화. 동일 길이 다른 텍스트 사례로 검증한다.
7. 어법은 original/correction 표시. anchor는 실제 원문에만 둔다. 교정 예는 syntax.correction에 두고 오류 원문에 실재하는 인용처럼 매칭하지 않는다. 실제 원문 오류를 조용히 고치지 않는다.
8. 비교/원리의 base inquiry hash는 이 확장 데이터 변경으로 바뀌지 않는다. base가 바뀌면 신규 sidecar도 재검수하며 기존 비교의 자체 게이트가 작동한다.
9. basePublicHash는 전체 레코드에 보수적으로 결속한다. 원리 문구/검수 상태 변경도 stale이 되는 것은 의도된 정책이다. build/CI는 stale 문항 수·이유를 출력하고, 기대 공개 manifest의 항목이 새로 stale이면 성공으로 삼키지 않고 실패시킨다. 일반 확장 없는 문항과 새로 stale된 문항을 coverage에서 구별한다.

## 6. 유형별 처리 — 26유형 유지

| 유형 IDs | 전체 이해와 주요 지원 | 강요하지 않을 것 |
|---|---|---|
| R-TOPIC, R-GIST, R-TITLE, R-CLAIM, R-IMPLY, X-TITLE | 주장/명제·전제·예외·함축의 근거 | 모든 글을 문제→해결로 만들기 |
| R-BLANK, R-BLANK2, X-BLANK, X-BLANK2 | 빈칸 앞뒤 의미, 조건·부정·추론의 범위 | 정답부터 넣어 원문 뜻을 확정하기 |
| R-ORDER, R-INSERT, R-IRRELEVANT | 주어진/단락 단위의 명제 전제·지시·의미 연결 | 인쇄된 문장 번호를 읽기 순서로 재번호 |
| R-GRAMMAR, R-VOCAB | 구문 결합과 문맥 의미·의도된 의미/원문 오류 구별 | 정동사·분사 용어만 표시, 교정을 원문으로 교체 |

| R-MOOD | 사건·인물 상태·변화 근거 | 감정 낱말 일대일 번역을 전체 이해로 간주 |

등록 유형은 기존 레지스트리·실계수 26개에 맞춘다. 개별 문항이 설명문/서사로 다른 경우 type→genre를 무조건 고정하지 않는다. 과제 단위(ID)·원문 인쇄 순서·탐구 읽기 순서·시간 순서를 구별한다.

## 7. 대표 문항의 실제 제시 시나리오

아래는 로컬 원문 입력과 공개 v3를 대조한 **파일럿 작성 초안**이다. 새 독립 검수 통과 콘텐츠가 아니다. 문장 번호는 해당 입력의 n이며 현재 DB/PDF와 C0에서 다시 결속한다. 전체 번역을 공개 문서에 복제하지 않는다.

### 7.1 2026#34 — R-BLANK, 분석 v5, units 7fb095d3cac4821e

- 시작: 6·7번 의미 선택. 정확한 뜻: 이상적인 법은 이성적 존재가 자유롭게 고를 원칙을 구현한다. 그 법이 금지하는 행동을 이성적으로 어차피 선택하지 않을 경우에 대한 If 조건과 뒤 부정을 따로 확인한다.
- 쉬운 말 초안: ‘이성적으로 어차피 선택하지 않을 행동을 금지하는 이 경우, 그 법을 자유의 구속으로 볼 수 없다는 것이 글의 결론이다.’ ‘모든 법은 자유를 제한하지 않는다’로 일반화하지 않는다.
- 왜: 6의 Ideally 한정→7의 If 조건→cannot be가 빈칸 전체를 부정. ‘선택하지 않음’과 ‘원하지 않음’은 항상 같지 않다.
- 보존 대조: ‘사람은 모든 금지를 좋아한다’는 원문 밖 주장; ‘어떤 법이든 자유 보장’은 조건 상실. 오해 예로 표시한다.
- 전체: 법치와 자유를 연결하는 글의 조건을 설명한 뒤, 기존 m1·m2·m3→문항 성립 선택지 3의 결정 조건으로 이동. 정답 번호가 의미 설명의 출발점이 아니다.

### 7.2 2026#36 — R-ORDER, 분석 v4, units 79c616281a5e44a2

## 8. 의미 검수와 공개 판정

기계 검증 통과와 독립 내용 검수를 구별한다. 최초 대표 파일럿도 아래 게이트 전에는 학습자에게 공개하지 않는다.

| 검수 축 | pass 기준 | revise/hold 예 |
|---|---|---|
| 원문 의미 | 문맥·화자·논항·절 결합·표현 범위가 원문과 맞음 | ‘선택 안 함’을 ‘원치 않음’으로 단정 |
| 쉬운 재구성 | 어려운 표현을 풀고 핵심 명제·한정을 보존 | may→항상, 일부→전부, 조건 삭제 |
| 구문 설명 | 표시 구간·수식 대상·재결합 뜻이 일치 | 길이 정렬만으로 다른 문장 표시 |
| 관계 설명 | 연결한 두 명제와 변화가 설명됨; 근거와 추론 구별 | 접속사 이름만 제시, 인과 방향 역전 |
| 전체 통합 | 핵심 주장/사건·예외·시점/지시가 unit들과 일관 | 서사를 논증 결론으로 강제 |
| 추론 경계 | 명시·연결 추론·비유가 구별되고 한계가 있음 | 외부 상식을 원문 사실로 승격 |
| 문항 연결 | 기존 meaning/choice/design referent가 실제로 존재하고 맞음 | 원문 이해를 공식 출제 의도로 표현 |
| 도표/오류/권리 | 미확인 수치 보류, 원문 오류와 교정 구별, 재구성 공개 권리 확인 | 기존 숫자를 확인된 원본 값으로 승격, 한국어로 원문 전체 우회 배포 |

독립 검수는 별도 에이전트 세션(Claude와 다른 Codex 또는 별도 컨텍스트의 전용 Claude 세션)이 맡는다. 같은 작성 세션의 자기 검토/3페르소나/작성 설명을 공유한 하위 에이전트를 독립 pass로 세지 않는다. 검수자는 원문·발문·선지·새 확장 본문 전체를 읽고, 작성자의 자기평가/합리화/검수 예상 답은 받지 않는다. 기존 분석은 대조 자료이며 의미 판정의 정답지로 취급하지 않는다. 새 설명을 숨기는 맹검은 설명의 정확성을 검수할 수 없으므로 사용하지 않는다. 기준 정본은 [CONTENT_REVIEW_CRITERIA.md](CONTENT_REVIEW_CRITERIA.md)의 `meaning-support-v1.0`이다. writer run과 reviewer run은 다르며 contentHash+binding+criteriaVersion에 결속된 명시 pass만 공개. 동일 revision/hash에 revise가 있으면 hold, 누락된 판정/애매한 의견을 pass로 채우지 않는다. 다른 후보 읽기는 limitations에 보존하고 충돌하는 판정은 무한 수정 대신 비공개 후보 원장에 남긴다. 대표8문항은 전량 원문 재대조, 확대 회차는 유형/지원별 표본 재대조와 불일치를 별도 기록한다.

형식 가드는 dangling ID, 잘못된 unit/구간, 같은 길이 다른 원문, 중복 구절, scope 누락 의심, modality/수량 강화 의심을 잡는다. 자동 탐지 신호는 검토 후보이며 의미 정확성의 자동 판정이 아니다. 지표는 ‘검수 항목 충족’이고 ‘학습자 이해 완료’가 아니다.

## 9. 기술 완료와 교육 효과

- 기술: sidecar 가드·권한·원문 대응·선택/URL/초안 상태·기존 분석 fallback·회귀와 PC 라이트 화면 증거.
- 사용성: 실제 학습자가 필요한 설명을 찾고 원문-쉬운말-관계를 이동하는 데 겪는 장애를 관찰. 내부 에이전트 조작만으로 사용성 입증하지 않음.
- 교육 효과: 별도 자발적 참여 파일럿. 원문 의미 재구성/조건 보존/두 문장 연결/추론 경계의 기준선과 후속, 가능하면 지연·새 지문 과제를 사전 정의한다. 정답률·클릭·노트 길이로 대체하지 않는다.
- 연구용 판단은 ‘주체·한정 보존 / 근거 없는 추가 / 의미 연결 설명’ 항목을 별도 평가자들이 원문 대조로 판정하고 불일치를 보고한다. 플랫폼 자동 진단 점수로 반영하지 않는다.
- 실제 참여자가 없으면 기술 문서만 완료하고 효과는 미검증. 큰 공급 확대의 효과 근거로 가정하지 않는다.
