## 저장 계약

새 테이블 없이 기존 `DissectionRecord`(기기 IndexedDB + `/api/csat/state` 서버 동기화)에 `meaningNotes` 를 더했다 — `apps/web/src/lib/csat/meaning-note.ts`.

- `id = 문항|의미` — 의미 하나에 노트 하나. 동시 탭 · 다른 기기 · 재시도 중복은 같은 칸을 덮고, 병합은 id 단위로 새로 고친 쪽(`updatedAt`)이 이긴다(`mergeMeaningNotes` · `mergeDissection`).
- 필드: `item` · `unitId` · `binding{analysisVersion, contentHash}` · `first`(처음 설명) · `revised?` · `change?` · `compared` · `at` · `updatedAt`.
- 결속: 쓸 때의 분석 버전 · 교수 본문 해시(`review.contentHash` 를 서버 projection 이 `contentHash` 로 넘긴다). 지금 설명과 다르면 「예전 설명을 보고 쓴 노트」로 표시하고 정본 설명과 섞지 않는다. 기록은 지우지 않는다.
- 개인 글은 본인 기록에만 있다. 원문 영어 · 정답 · 선지 번호를 담지 않는다. 보류 문항의 노트는 `withoutHeldCorrectness` 가 내보내지 않는다(서버 사본은 그대로).
- 저장 실패(기기 쓰기 실패)면 글을 지키고 「다시 저장」. 저장 전 입력은 문항별 탭 메모리(`item-tab-memory`)가 지킨다.

## 계측

새 이벤트를 만들지 않았다. 대조는 기존 `csat_meaning_draft_compared{length: lt50|lt200|gte200}` 를 쓴다(학습자 글 · 의미 id 없음). 의미 선택 · 깊이 · 관계 · 거슬러 오르기 · 이어 가기는 기존 6종(`20261014150000_funnel_allow_csat_meaning`, 승인 후 적용 · 83 → 89종). 어떤 계측도 숙달 · 효과 판정에 쓰지 않는다.

## 읽어 주기

「이 의미 읽어 주기」는 정확한 뜻 → 쉬운 말 → 지킬 조건을 검수 본문 그대로 읽는다(`meaning-support/narration.ts`). 학습자 글은 읽지 않는다. 다른 의미를 고르면 멈춘다. **실제 한국어 음성 · 영어 고유명사 · 숫자 청취는 헤드리스 브라우저(음성 없음 · 무음 어댑터)에서 확인할 수 없어 미검증이다.**
