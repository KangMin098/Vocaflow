# 목표 달성형 학습 — 구현 계약

2026-10-23 사용자 요청의 첫 구현 범위는 **목표 입력 → 주간 예산 → 기존 TASK 편성 → 오늘의 실제 실행**이다. 기존 목표·To-Be/As-Is·Workspace·G2·PLAN 판정과 추가 전용 저장을 재사용한다. TASK 정의(비보류21·보류9), 자료 역할·독립 첫 시도 적격성, T-0087 R5 입력 SHA·사람 결정은 변경하지 않는다.

## 저장과 기간 배분

- 기존 `csat_map_goal_version`의 시험·점수·선택 등급·목표일·id를 사용한다. 등급만인 목표는 기존 DB의 점수 필수 제약 때문에 지원하지 않으며 임의 점수로 채우지 않는다.
- `20261023090000_csat_goal_budget.sql`은 **공유 개발 DB 미적용·사용자 승인 대기**다. `planning_budget` 한 열과 검증 함수·service-role 전용 `csat_map_goal_budget_set`을 추가한다. 예산은 주간 분·월~일 선택 시간·문항/지문당 잠정 분·선택 우선 TASK다. API에서 보류·알 수 없는 우선 TASK를 거절한다. 새 예산은 새 목표 버전에만 들어가며 옛 목표·PLAN을 수정하지 않는다.
- 기간 계획에는 시험·목표일·점수·주간 시간이 필요하다. 기존 점수 전용 목표는 계속 읽고 저장할 수 있다. 열 미설치만 기존 조회로 전환하며 권한·연결 오류는 숨기지 않는다. 예산 RPC 미설치는 503 `budget_not_installed`이며 목표·시간 모두 저장 성공으로 표시하지 않는다.
- 예산 저장에는 화면에서 본 `expectedGoalVersion`이 필요하다(첫 목표는null). 새 writer는 기존 목표 writer·PLAN과 같은 사용자 잠금 안에서 최신 id를 비교한다. 다른 기기에서 목표가 바뀌면409 `goal_changed`로 거절한다. 성공한 같은 요청키 재전송은 목표일·현재 버전이 바뀌어도 원래 영수증을 돌려주며 본문이 다르면409다.
- 시간은 사용자가 조정하는 일정 배분이다. 기본 문항·지문당10분은 측정 시간이나 교육 효과 추정치가 아니다. 요일 미지정이면 주간 한도 안에서 온전한 단위로 월~일에 나누고, 요일 지정이면 해당 상한만 사용한다. 주중 진입은 남은 요일에만 배정하며 지난 요일의 예산을 옮겨 과배정하지 않는다. 목표일은 포함하고, 지난 목표일·10년 초과·유효하지 않은 날짜를 구별한다.
- 새로고침으로 오늘 예산이 되살아나지 않게 G2 수행·재시도 기록마다 현재 잠정 단위 시간을 차감한다. 서버 수신 시각(없으면 수행 시각)의 서울 날짜를 쓰며 중복 시도 id·합성·미래 기록은 제외한다. 도움받은 연습도 시간은 차감하지만 독립 근거로 승격하지 않는다. 이는 실제 경과 시간 계측이 아니며 화면에 그 한계를 표시한다.
- `goalSchedule`은 기존 NeedRank와 선택 우선 TASK를 읽는다. 현재 단계의 같은 목표·유효 PLAN이 확정되고 실행 링크가 있는 수량만 편성한다. 실제 실행은 기존 `outgoingCtx`와 `withMapReturn`을 사용해 같은 TASK·Workspace·PLAN으로 복귀한다.
- 자료·도구 부족, 목표 관련성 미확인, 조회 실패, PLAN 재확정, 유지 확인 기준 미정, 시간 부족을 미배정 사유로 구분한다. `null`을0으로 바꾸거나 없는 실행 링크를 만들지 않는다. 서로 다른 문항·지문을 합산한 수행량을 만들지 않는다.
- 일정은 **현재 단계의 배분 제안**이다. 이후 단계의 총량과 전체 목표 달성 시점은 미확인이다. 기존 PLAN 수량·단계·근거를 바꾸거나 일정을 자동 확정하지 않는다. 결과가 바뀌면 기존 G2/PLAN의 재확정 관문을 따른다. 과거 기준 지도에서는 현재 실행 일정을 표시하지 않는다.

## 다음 수용 범위

요청 전체의 `PRODUCT_CODE_COMPLETE`는 아직 아니다. 기간 일정의 명시적 확정·버전별 달력 스냅샷·지속되는 재계획 전후 비교, 목표 기준 후속 시험의 비교 조건·달성 판정은 추가 구현·수용이 필요하다. 기존 Workspace PLAN 이력은 계속 보존되지만 이를 기간 달력 이력으로 부르지 않는다. 목표 점수 달성률이나 실제 교육 효과를 TASK 수행량에서 만들지 않는다. 시험 비교는 [시험 입력 계약 §3](./LEARNING_MAP_EXAM_INPUT_CONTRACT.md)의 같은 시험지 직접 비교와 동등화 미지원 경계를 유지한다.

공유 DB 적용 승인 후 실제 인증 전체 지도에서 목표·예산 저장→PLAN 확정→실제 자료 실행→독립 실패/바로잡기→재확정과 목표·시간 변경을 확인한다. 사람 Gold·권리 승인과 실제 교육 효과는 각각 별도다. 승인이 필요한 DB 쓰기와 무관한 코드는 먼저 구현·검증한다.

## DB 승인 범위

제안 SQL은 기존 목표 이력에 nullable JSONB 열과 검증 제약을 추가한다. 기존 데이터 수정·삭제·대량 적재·새 테이블은 없고 기존 목표 writer·PLAN writer·추가 전용 트리거·RLS는 그대로다. 새 writer 실행은 service_role만 허용한다. 새 기능을 되돌릴 때는 애플리케이션을 기존 writer로 복귀하고 새 열과 이력은 보존한다. 삭제 롤백 SQL은 실행하지 않는다. 공유 DB 적용 전후 checkpoint와 적용 후 스키마·권한·읽기 검증이 필요하다.

## 3차 — 목표 대비 변화·도달 판정(`v62/goal-outcome.ts` · `GoalOutcome`)

- 입력은 저장 목표(시험·점수·선택 등급·설정 시각), 본인 시험 기록(`csat_dx_session` + 회차 `organizer·kind·month` → `examScopeOf`), 현재 TASK 계획이다. DB 변경 없음.
- 목표 설정일 **뒤** 본 기록 중 입력 신뢰도를 통과하고 **처음 본 시험지**인 마지막 기록만 판정에 쓴다. 이미 본 시험지 재풀이는 `repeated_paper`(새 평가 아님), 신뢰 미통과는 `unreliable`.
- 목표 시험과 같은 종류일 때만 원점수를 목표와 비교한다(`below`/`reached` + 점수 차). 다른 종류는 `different_exam`, 목표 시험 미정은 `no_goal_exam`. 등급은 기록된 등급끼리만 비교하고 점수에서 만들지 않는다.
- 변화(목표 전 → 후)는 같은 `exam_id` 끼리만 점수 차를 낸다. 다른 시험지는 `different_paper`(동등화 없음, 시험 입력 계약 §3).
- TASK 활동(목표 관련 요구 수·다시 확인 통과 수)은 별도 줄이며 목표 도달 근거로 쓰지 않는다. 예측·확률·퍼센트 없음.
- 다음 행동: `below`·`no_score` → 새 기록 반영 PLAN 재확정(기존 PLAN 사유 `new_exam`), `reached` → 유지 확인, 기록 없음 → 새 회차 시험 기록.
- 미구현 한계: 앱 안에서 그 시험지의 문항을 먼저 학습했는지는 아직 판정에 넣지 않는다.
