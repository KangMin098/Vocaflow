# CSAT_LEARNER_UX_V3 — 화면·조작·상태 계약

2026-10-12 · PC 웹 1280/1440, 라이트/다크. 3B 토큰·셸·접근성·포털을 유지한다. 아래 wireframe은 목표 정보 구조이며 이번에 렌더한 화면이 아니다.

## 1. 전체 진입과 기본 작업면

상시 메뉴는 **내 학습 지도(`/csat`) / 기출 탐구(`/csat/browse`)** 두 개다. 목적별은 상태/근거에 따른 다음 행동, 유형/회차는 탐구의 조건이다. 기록·원리 노트·개인 묶음은 지도 본문에서 사용 시 접근한다. 일곱 장면을 사이트 메뉴로 올리지 않는다. 기존 메뉴 N 계획의 모든 URL·Workspace·기록을 보존한다.

```text
기출 탐구 > 2026학년도 수능 34번      [출처/분석 정보] [원래 위치로]
평가 과제 / 원문 이해 / 문항 성립 / 설계 재구성 / 비교 / 원리 / 내 설명
┌ 원문과 근거: 지속 표시 ─────┬ 현재 관계를 탐구하는 작업면 ──────────┐
│ 기기 원문 또는 근거 지도    │ 핵심 질문 하나                       │
│ 선택한 단위/영역            │ 주도식 또는 비교 하나                │
│ 의미/구문 도움(펼침)        │ 선택한 조건·선지의 설명               │
│ 실제 출처·없는 상태 안내    │ [근거 보기] [선택적 구성/자기 대조]   │
└───────────────────────────┴──────────────────────────────────────┘
장면 강의: [읽기] [듣기] [일시정지] [속도]  대상/이유 표시
```

일곱 링크는 간결한 장면 탐색으로 제공하며 현재 위치만 강하게 표시한다. 1280에서 기존 레일/원문/분석 폭을 실측해 구조를 결정한다. 비좁으면 지속 원문 + 작업면의 두 판을 유지하고 장면 목록을 얇은 레일/접기 가능한 차례로 표현한다. 메뉴 카드 7개·장면 설명 7개를 동시에 펼치거나 전체 원문을 축소하지 않는다. 새 사이드 레일과 기존 셸 레일을 중첩하지 않는다.

원문이 없어도 저작권 정책 안의 설명·짧은 인용은 볼 수 있다. 기기 PDF를 넣어야 강의를 열 수 있는 관문으로 만들지 않는다. 자료 영역과 판정 근거가 필요한 기능만 unavailable을 설명한다.

## 2. URL와 기존 주소 호환

canonical query: `?scene=task|meaning|judgment|design|compare|principle|explain`.

| 옛 값 | v3 정규화 | 유지할 문맥 |
|---|---|---|
| 없음·무효값·essence | task | 도입 질문. 무효값을 에러로 만들지 않음 |
| structure | meaning | 유효한 기존 원문 선택이 있으면 유지 |
| answer | judgment | 정답/발문 하위 보기 |
| distractor | judgment | 비선정 선지 하위 보기. 기존 값만으로 특정 선지 번호를 지어내지 않음 |
| compare | compare | 검수된 실제 pair ID가 있으면 서버 확인 |
| principle | principle | 직접 진입 허용. 잠정/일반화 표시 |

`judgmentView=answer|options`는 두 옛 링크의 의미를 구별할 내부 초기 상태다. 공유가 필요하면 닫힌 query로 명시하고 일반 자유 문자열을 넣지 않는다. 정규화는 replace, 수동 장면 이동은 push, audio 따라가기는 기존 URL 문맥을 보존한 replace다. popstate도 같은 parser를 사용한다. 어떤 장면 변경도 정답/확신 제출을 요구하지 않는다.

`?check=1`은 기존 독립 확인 모드다. scene과 동시에 오면 독립 확인 모드를 먼저 렌더한다. ‘해설 보기’를 선택한 시점에 도움 이력을 기존 API로 기록하고 scene을 적용해 탐구로 이동한다. **권한·공개 보류 판정이 허용되지 않으면** explanation/대본/큐/메타/캐시 어느 쪽도 공개하지 않는다. **독립 확인 응답이 없거나 틀렸어도**, 공개 권한이 있으면 설명을 볼 수 있다. **응답/도움 이력 저장 요청이 실패해도** 허용된 설명은 열고 입력·pending 도움 기록·재시도를 보존하며 해당 시도를 독립 진단에 반영하지 않는다. 저장 실패를 정오 0으로 만들거나 권한 허용으로 간주하지 않는다.

지도에서 시작한 활동은 원래 step/task/phase로, 자유 탐구는 원래 browse 조건/스크롤로 돌아간다. 반환 경로는 `lib/auth/redirect.ts`의 안전한 내부 경로 판정을 사용한다. source/analysis binding이 바뀌면 과거 문항 선택을 최신 근거로 자동 복원하지 않는다.

## 3. 장면별 화면과 주목 대상

| 장면 | 기본 구성·주목 | 선택→반응 | 도움/다음/없는 상태 |
|---|---|---|---|
| task | 발문 동작/조건 → 질문 → 평가 요구. 정답을 찾으라는 입력창 없음 | 조건 선택→관련 의미/근거를 오른쪽 설명과 함께 선택 | 요구 분석 없음은 원문 발문만/방법. meaning으로 추천, 어디든 자유 이동 |
| meaning | 선택한 영어 단위와 한국어 의미 → 구문/범위 → 관련 문장 → 전체 구조 | 구절/문장/영역 선택→같은 ID의 의미·관계 강조. 관계 선택→양끝 근거 동시 표시 | 어휘/문법 도움은 해당 근거 안 펼침. 주석 없음/기기 원문 없음 구별 |
| judgment | 발문 조건 → 원문 명제 → 선지 1개 → 유지/변경/결정 조건 | 선지 변경→관련 근거·조건·설명 갱신. 정답/내용 truth/발문 충족을 별도 표시 | 맞는 내용이 정답이 아닌 유형과 위치 선택 모델 지원. 답 모름은 정답 단정 없음 |
| design | 능력 해석→발문 요구→관찰 증거→설계 가설. 각 근거 수준 라벨 | 가설/연결 선택→사실 근거·가설 범위/대안 설명 | 제작 순서 재연 없음. hypothesis 없음은 앞 장면 탐구 유지 |
| compare | 양쪽 관련 단위·판단 조건·대응 관계. 전체 지문 2개 강제 축소 없음 | pair/대응선 선택→양쪽 근거를 동시에 강조. 표면 공통 vs 구조 차이 선택 | 준비/권한/stale/검수 부족 구별. 같은 유형 서가는 일반 찾기이며 대체 검수 아님 |
| principle | 조건부 진술 → 지지 사례 → 성립 조건/반례/범위 | 조건 선택→관련 pair/evidence. ‘내 설명에 가져오기’→explain draft | 검수 지지 없으면 candidate 라벨. 비교 클릭이 잠금 해제 조건 아님 |
| explain | 짧은 관계 설명·조건·경계 + 근거 첨부 | 저장/대조/근거 변경. ‘모범 설명과 같음’ 자동 점수 없음 | 작성 없이 이동 가능. 저장 실패는 입력 보존·재시도/기기 상태 표시 |

‘본질’은 task에 확정 요약으로 선노출하지 않고 judgment 이후 증거에 기반한 문항 요약으로 얻는다. 비선정 선지에 altered=[]가 적합하면 ‘유지됐으나 질문이 요구한 답이 아님’ 또는 위치 조건을 설명한다.

## 4. 공통 상태와 이벤트 전이

```text
접근 확인 → 로드 → ready | missing | stale | withheld | error
ready + 수동 선택 → 현재 장면/근거 갱신(자동 재생 없음)
ready + 듣기 시작 → 재생 모델/강의 binding 확인 → audio-follow
audio-follow + 수동 탐구 → 강의 일시정지 → manual-focus
manual-focus + 다시 강의 따라가기 → 현재 큐 기준 focus 복원
저장 → saving → saved | device_only | save_error (입력은 유지)
```

| 이벤트 | 상태/반응 | 불변식 |
|---|---|---|
| enter_item | 권한→snapshot→장면 parser | 일반 탐구 viewed_first/열람, 독립 확인과 구별 |
| select_scene | TTS 재생 중이면 일시정지 후 수동 이동, 동일 상태 재선택은 중복 history 없음 | 도움 접근 자유. 분석 본문 클릭으로 자동 start 금지 |
| select_evidence / select_claim | primary 대상 하나 + related 근거 강조, 설명 연결 | sourceHash 불일치 시 잘못된 문장 강조 금지 |
| select_choice | 선택지 조건 모델 변경 | 클릭은 정답 제출/진단 response 아님 |
| open_help | 의미/구문/검수 설명 펼침 | 확인 시도면 도움 선행 기록; 일반 탐구에서는 시험 이벤트 아님 |
| select_pair | 양쪽 공개 상태/binding 확인 후 비교 | stale/held 파트는 사용하지 않음. arbitrary pair query로 원문 노출 금지 |
| start_audio | 선택 장면의 검수된 큐 시작; 텍스트와 같은 claim 사용 | cue 없는 장면은 읽기 유지; 예상 시간을 이해 점수로 바꾸지 않음 |
| audio_target | auto-follow일 때 해당 장면 replace·related 강조 | manual 선택을 audio가 덮어쓰지 않음; focus 강제 탈취 없음 |
| pause/skip/cancel | 기존 player의 cancellation 완료·run token으로 오래된 콜백 차단 | 한 명령의 중복 handle/음성 겹침 금지 |
| save_note / compare_note | id 단위 저장/본인 설명 대조 표시 | 실제 자동 의미 채점/verified_diagnosis 전이 없음 |
| leave/back | 문맥/실제 진행 위치 복원, 오디오 정지 | 저장 실패 안내를 버리지 않음. 원본/음성을 강제로 재입력하지 않음 |

일반 학습 상태는 콘텐츠와 사용자 기록을 구별한다. 콘텐츠가 없다는 이유로 능력 부족을 표시하지 않는다. 학평의 공개 보류를 사용자가 `scene`/`check` query로 해제할 수 없다.

## 5. TTS와 읽기의 한 경험

강의 대본은 평가 과제→실제 의미→조건 판단→설계 해석→비교→원리/자기 설명 지원의 논리 순서를 따라 작성한다. 한 장면은 여러 큐일 수 있고 모든 장면에 음성 큐를 억지로 채우지 않는다. 비교 자료 없음은 가상의 비교 대본을 만들 이유가 아니다.

기존 `LecturePlayer`·tts adapter·언어 segment 분리·pause_after·focus를 재사용한다. 장면별 lecture binding이 `claimIds/evidenceIds/primaryTarget/relatedTargets`를 가진다. 실제로 DOM에 있는 대상만 재생한다. 두 판에 같은 `data-lecture-target`를 중복 부여하지 않고, data-evidence-id는 related용으로 복수 사용한다. 주대상 요소와 원문 강조의 역할을 분리한다.

main의 역할 단조 순서 ROLE_ORDER는 어휘가 뒤에 오는 옛 강의 계약이다. 새 의미 설명 강의를 vocab→structure로 재배치하면 기존 validator가 실패하므로 DATA의 v3 schema 분기를 먼저 만든다. 옛 큐는 검증된 기존 차례를 유지하고, 새 차례라고 거짓 표기하지 않는다. 원리 저장/자기 설명 칸에 강의가 들어오면 입력을 중단하거나 글자를 바꾸지 않는다.

키보드: 장면 링크는 Tab/Enter와 보이는 focus; 도식은 목록형 대안 제공. 원문 선택/입력/combobox/모달/slider에서 전역 Arrow/Space를 탈취하지 않는다. `prefers-reduced-motion`은 이동을 줄이고 상태 페이드를 유지한다.

## 6. 대표 문항의 제시 시나리오

아래 정답/내용은 이번 DB의 최신 발행 분석에서 확인한 기준이며 원본 판독·근거 단위·강의·비교를 구현 파일럿에서 다시 대조한다. 교정 시 기존 분석이 아니라 공식 정답/원본을 우선한다.

| 문항 | 데이터 기준과 시나리오 | 꼭 확인할 예외 |
|---|---|---|
| **2026#34 빈칸** | v5·정답③. task=조건/부정 범위 질문. meaning=법·자유 명제와 이성적으로 선택하지 않을 행위의 금지. judgment=선지를 `cannot be`와 결합한 전체 명제 대조. design=부정 범위를 평가에 사용했다는 해석. compare=같은 부정 범위/다른 적용 경계 쌍이 검수됐을 때. principle=부정 결합과 근거 대조의 조건. explain=그 이유와 다른 절 부정의 한계 | ‘부정이면 지문 반대말’ 무조건 규칙 금지. 기존 inquiry note/원리도 부정 scope와 원문 재대조 |
| 2026#36 순서 | v4·정답④. 반복 과정이라는 의미→문단 간 선행 조건/재진술→배열 전체의 연결 가능성. 인접 단어 반복보다 의미 선행 조건을 주도식으로 | 문단(A/B/C) 원본 identity를 문장 순서처럼 변환하지 않음 |
| 2026#38 삽입 | v5·정답⑤. 삽입문 앞의 서사 지시 대상과 뒤의 정체성 예시를 양쪽 경계로 대조 | 한쪽 For example만으로 삽입 위치 확정 금지. 원문 혼입/번호 확인 |
| 2026#29 어법 | v5·정답②. 수식 used와 비정형 being/정동사 성립 조건을 구문 도식으로 연결 | 비선정 선지는 정상 문법일 수 있음. 모든 선지를 왜곡 오답으로 설명하지 않음 |
| 2026#25 도표 | v5·정답④. 실제 도표의 범주/단위/값과 선지의 순위 비교를 연결 | DB 숫자는 visual 독립 판독의 대체물이 아님. 원본 없는 상태에서는 순위 확정/새 그래프 생성 금지 |
| M2706#36 모평 | v4·정답⑤. 방어 종류/이웃 도움/상호작용의 선행 조건을 탐구 | 일반 다음 문항 추천과 구조 검수 비교를 구별 |
| H2603G3#34 학평 고3 | v2·정답③. 요약·재진술 의미 대응. 기존 u4 등 정본 unit과 대조 | 학평/고3를 명시. 공개/검수 게이트·source/units hash 일치 전 v3 확장 공개 금지 |

고1/고2 학평도 각각 별도 대표 문항을 M0의 실제 공개 목록에서 선정한다. 번호/단위/정답이 확인되지 않은 문항 ID를 여기서 만들어 넣지 않는다. 파일럿 원장에 선정 이유·제외 이유·결속 버전을 적는다.

## 7. 메뉴·옛 주소·학습 지도 연결

`/csat`의 첫 제안은 기존 지도/기록/Workspace 상태에서 한 개만 선택한다. 아래 상태는 새 진단 점수/DB 컬럼이 아니라 기존 loader와 과제의 실제 상태에 대한 표시 계약이다.

| 홈 상태 | 확인할 기존 근거 | 첫 제안 행동·진입 | 금지된 판정/관문 |
|---|---|---|---|
| 익명 | 인증 세션 없음 | 기출 한 편 탐구→browse. 개인 지도는 로그인 진입을 옆에서 안내 | 개인 loader 호출·진단 제출 후 탐구 강제 |
| 로그인·기록 없음 | 기록 조회 성공이고 유효 기록/진행 과제 없음 | 기존 기록 입력/지도 시작 진입. 기출 탐구는 항상 이용 가능 | 데이터 조회 오류를 기록0으로 삼키기·설문/새 진단 시험 추가 |
| 기록 작성/자료 처리 미완료 | 실제 draft/import/검수 상태 | 해당 기록/자료 처리 이어가기. 처리 실패는 기존 복구 경로 | 미완료 자료로 능력 필요/충족 확정 |
| 관찰 있음·독립 확인 부족 | 지도 관찰과 미확인 셀, 채택/활성 확인 과제 | 가능한 기존 근거 확인 과제로 이동. 과제 미승인이면 관찰 설명/허용 탐구 제공 | 관찰/열람을 verified로 승격·미승인 과제 공개 |
| 바로잡기 진행 | 실제 활성 Workspace/처방·마지막 저장 위치 | 같은 과제 바로잡기 이어가기; 연결 문항 탐구 가능 | 새 7장면을 모두 끝내야 복귀 허용 |
| 다시 확인 필요 | 기존 lifecycle의 재확인 가능 상태·독립 과제 | 검수/권한 조건을 만족한 기존 다시 확인 진입 | 설명 후 수행을 독립 확인으로 채택 |
| 탐구에서 복귀 | 안전 return context와 실제 마지막 활동 | 원래 지도 step/task/phase에 돌아가 상태/다음 가능한 행동 표시 | 탐구 복귀를 자동 개선·능력 해소로 판정 |
| 기록만 있고 진행 과제 없음 | 유효 기록과 지도, 개인 노트/탐구 이력 | 내 지도 보기. 실제 재개 이력이 있으면 본문 이어보기 | 임의 문항/처방/완료 수치 생성 |
| 로드/오류/권한 제한 | loader의 loading/error/forbidden | 상태 안내+재시도/허용 기출 탐구 | 오류를 ‘진단 필요’로 표시 |

동시에 맞으면 오류/권한→복귀 문맥→활성 과제/미완료 기록→독립 확인 필요→기록만 있음→기록 없음 순으로 첫 제안을 정한다. 익명은 별도 분기다. 같은 우선순위에서 현재 활성 task ID를 사용하고 새 인기/정답률/예상 약점 순위를 만들지 않는다. 기본 지도와 자료 찾기는 한 화면에 역할을 나눠 두며 진단을 탐구 입장권으로 만들지 않는다.

`/csat/diagnosis`의 개요/records/map/full/focus/record 모달은 유지한다. root에서 MapScreen을 재사용할 때 기록/상세 base는 초기 `/csat/diagnosis`로 유지한다. 익명에서는 개인 지도 loader를 호출하지 않는다. 목표 입력·시험 기록·Workspace 생성은 자유 탐구 전제 아님.

`/csat/space`는 기본 지도, `/csat/workspace`와 `/new`는 명시 workspace query의 개인 묶음 view, `/record`·`/formulas`는 개인 기록으로 연결. 원래 `?tab=type/trap`, 허용 `?need=`·`?view=continue`는 옛 URL 전용이며 새 본문 링크는 browse 조건 또는 `/csat#ongoing`으로 변경한다. 무효 need는 기본 지도. `WorkspaceDetail`의 목록/삭제 복귀, `ProgressView`의 첫 탐구 링크, `SessionRunner`의 자료 없음/완료/학습 허브, `RecordScreen`의 이어서 링크를 의도별로 분류한다. 개인 묶음 `from`은 계측 출처이지 안전 반환 URL이 아니다.

지도 `StepKey`와 v3 장면의 연결은 다대다 adapter다. 어휘/문장/관계/구조 도움은 meaning, 본문↔선지/근거는 judgment, 이해 체계화는 design/compare/principle/explain에서 지원한다. 새 장면을 봤다고 해당 능력이 verified로 바뀌지 않는다. 독립 확인은 기존 knowledge adoption/active/맹검/도움 제외 계약을 따른다.

## 8. 실화면 검수 계약

PC 1280/1440×light/dark에서 첫 주목 대상, 읽을 수 있는 원문/설명 폭, 텍스트 선택, focus·dialog·실제 overflow, 강의 취소/따라가기, 데이터 없음/held/stale/error·저장 실패·뒤로가기를 캡처하고 이미지를 직접 확인한다. 44px 조작 영역, 한글 break-keep, 색 외 라벨/연결 설명을 유지한다. 3B 참조 기하는 existing spec/CSS 변수와 `pnpm design:ref-compare` 표로 검증한다. 새 도식 치수는 대응 참조를 측정해 명세에 추가하며 눈대중 일치 주장을 하지 않는다. 자동 E2E 통과는 가독성·교육 효과 확인을 대신하지 않는다.
