# CSAT_LEARNING_PROCESS_V3 — 교육 모델과 장면 계약

2026-10-12 · 목표 계약. 실제 학습자의 효과는 아직 미입증이다. 정답률/속도/점수가 아닌 **의미·문항 성립·설계 원리의 설명과 사례 구별**을 이 환경의 핵심 성과로 삼는다.

## 1. 서로 다른 ‘7단계’의 분리

| 층 | 정본/역할 | v3 변경 |
|---|---|---|
| 개인 능력 경로 | `map/learner-path.ts`: 어휘→문장→관계→구조→본문↔선지→근거→시간 내 통합 | 보존. 이 화면의 직접 목표를 시간/점수로 바꾸지 않음 |
| 확인/바로잡기 과제 절차 | `map/curriculum.ts.PROTOCOL`과 repair 숫자 | 보존. 번호를 새 장면으로 치환하면 repair 계약이 깨짐 |
| 문항 탐구 장면 | 기존 inquiry 여섯 장면 | 이 문서의 7장면으로 개정. 자유 이동이며 선수 능력 등급/잠금이 아님 |

개인 지도에서 필요한 관계를 추천할 수 있지만 ‘문장 이해가 확인되지 않았으니 비교 금지’로 잠그지 않는다. 깊이 조절은 검수된 도움의 펼침 상태이며 학습자 수준을 클릭으로 추정한 새 진단이 아니다.

## 3. 장면별 교육·콘텐츠 계약

각 장면의 원문 참조는 같은 evidence ID를 사용한다. 화면의 주목 대상과 클릭 전이는 [UX](CSAT_LEARNER_UX_V3.md), 필드는 [DATA](CSAT_REASONING_DATA_V3.md)가 소유한다.

### 01 문항의 평가 과제 확인 (`task`)

- 질문: 무엇을 이해하고 어디까지 판단해야 하는가?
- 순서: 회차/기관/유형·발문 정보 → 탐구 질문 → 요구 조건/읽기 범위. `measured_ability`는 검수된 분석자의 능력 해석이며 문항별 공식 확인과 구별한다.
- 주목: 발문의 동작과 조건. ‘본질은 대조’ 같은 확정 결론/정답 채점창 대신 확인할 질문 하나.
- 선택: 발문 조건을 선택하면 해당 의미/판단 증거로 이동. 정답은 알고 있어도 일반 탐구 접근을 제한하지 않는다.
- 데이터 없음: 원문을 기기에서 확보한 경우 발문 자체와 검수된 방법만. 질문 분석 없음은 명시하고 만들어 채우지 않음.

### 02 원문 의미·구조·관계 해부 (`meaning`)

- 질문: 문장과 글이 실제로 무엇을 말하며 그 관계는 어떻게 성립하는가?
- 순서: 핵심 영어 표현의 문맥 뜻 → 주어/술어/절/부정·조건의 범위 → 문장 의미 → 앞뒤 관계 → 글 전체 핵심 → 문항에 필요한 관계.
- 주목: 선택한 근거의 실제 의미와 범위. 역할 사슬은 설명의 결론이 아니라 의미와 함께 대조하는 도구.
- 선택: 문장/밑줄/자료 영역 선택 → 한국어 의미 주석·구문 도움·관련 앞뒤 근거. 전체 번역을 줄줄이 먼저 펼치지 않는다.
- 없음: 원문 기기 캐시 없으면 저작권 정책 안의 짧은 인용·의미 주석/공개 원본 접근 제공. 의미 주석 없으면 기존 검수 분석만, 역할 라벨을 번역처럼 제시하지 않음.

### 03 발문·정답·오답의 성립 논리 (`judgment`)

- 질문: 어떤 조건 때문에 한 선택지가 정답이고 다른 선택지는 요구를 충족하지 못하는가?
- 순서: 발문 요구 → 원문 명제/관계 → 정답 표현 변환과 전체 문장 성립 → 비선정 선지의 유지·변경·실패 조건.
- 주목: 지금 선택한 선지와 하나의 결정적 조건. 원문↔선지 성분을 나란히 보고 근거 선택 시 연결선/설명을 함께 갱신.
- 선택: 모든 선지를 자유롭게 선택, ‘바뀐 부분 표시’는 선택적 구성 활동. 잘못 표시했을 때 근거와 대조하며 점수·등급을 만들지 않음.
- 예외: 어법/불일치에서 비선정 선지가 참인 경우, 위치/지칭에서 truth가 부적합한 경우, 원문 밖 조건 부재를 판정하는 경우를 각각 설명. 오답 4개에 왜곡을 강제하지 않음.

### 04 설계 원리의 근거 기반 재구성 (`design`)

- 질문: 관찰된 의미 관계를 어떤 판단 과제로 이용했다고 해석할 수 있는가?
- 순서: 분석자가 해석한 능력 → 실제 발문 요구 → 답을 구별하는 증거 → 설계 해석/경쟁 가설 → 확인하지 못한 부분.
- 주목: 관찰 사실에서 가설로 넘어가는 연결. 공식 출제 방향·공식 정답만으로 지문 선정 의도/오답 유인 효과를 확정하지 않음.
- 선택: 가설을 선택하면 근거·다른 가능한 설명·범위를 확인. ‘출제자가 지문을 먼저 골라…’와 같은 제작 타임라인은 공식 제작 기록이 없으면 제공하지 않는다.
- 없음: 설계 가설이 없어도 앞 장면의 문항 성립 설명은 유지한다. ECD는 설계 관계를 정리하는 참고 틀이며 평가원이 실제 ECD로 이 문항을 만들었다고 주장하지 않는다.

### 05 기출의 구조 비교 (`compare`)

- 질문: 다른 기출에도 같은 관계가 있으며 무엇이 같고 무엇이 다른가?
- 순서: 검수된 목적(동일 구조/조건 차이) → 양쪽 평가 과제 → 원문 의미와 근거 → 조건/변환 대응 → 공통점·차이.
- 주목: 두 문항의 대응 관계 하나. 원문 전체 두 장을 축소하지 않고 관련 단위와 조건을 나란히 보여 준다.
- 선택: 검수된 쌍을 선택해 대응선을 탐구. 같은 유형 일반 탐색은 별도 행동이며 공통 원리 검수처럼 보이지 않음.
- 없음: 후보 없음/권한/원문 없음/버전 stale을 구별. 공개 가능한 단일 문항 탐구와 잠정 원리는 유지. 검수 안 된 후보를 자동 대체하지 않는다.

### 06 공통 원리·조건·한계 (`principle`)

- 질문: 어떤 조건에서 같은 판단을 적용하고 어느 경우 적용하지 못하는가?
- 순서: 조건부 문장 → 지지 비교 근거 → 적용 조건 → 반례/적용 경계 → 현재 검토 범위.
- 주목: 조건과 제한. 원리가 단일 문항에서 온 것이면 **‘이 문항에서 얻은 잠정 원리’**이며 보편 규칙으로 말하지 않음.
- 선택: 조건을 선택해 해당 근거/비교를 열고 ‘내 설명에 가져오기’를 선택. 저장 자체는 이해 증거가 아님.
- 일반화의 공개 자격: 독립 검수된 지지 비교와 경계 논증이 필요한 **콘텐츠 품질 조건**이다. 학습자가 05에서 버튼을 눌러야 06이 열리는 자격 조건이 아니다. 06 직접 진입도 근거 비교를 바로 확인할 수 있다.
- 없음: 지지 자료 미확인/보류·stale이면 일반화 상태를 후보로 낮추거나 보류하며 이유 표시. 가짜 반례나 ‘데이터가 없으면 적용 금지’를 원리의 반례로 쓰지 않음.

### 07 자기 설명과 체계화 (`explain`)

- 질문: 원리·근거·조건·경계를 내 말로 연결할 수 있는가?
- 순서: ‘이 판단이 성립하는 이유’·‘다른 사례에 통하는 조건’·‘통하지 않는 경우’ 짧은 선택적 입력 → 근거/비교 첨부 → 검수된 설명과 자기 대조.
- 주목: 현재 쓰는 관계와 그 근거. 글자 수·장문 작성·감상문을 요구하지 않는다.
- 선택: 작성/건너뛰기/저장/나중에 계속/검수 설명 비교. 기존 lure 자기 설명과 원리 기록은 읽기 adapter로 보존한다.
- 기록: 열람·저장·자기 대조·독립 확인을 별도로 보존. 자동 LLM 점수나 완주→숙달 전이는 도입하지 않는다.
- 실패: 로그인/동기화/저장소 오류가 있어도 탐구를 계속하고 입력 유실·저장 위치를 정직하게 알린다.

## 4. 축약과 유형별 깊이

7장면은 의미/권한 계약이다. 단순 문항은 01·02를 한 화면의 연속 구역으로 제공하고 03에서 정답/오답을 교차 선택한다. 장면별 새 페이지 7개나 큰 탭 두 줄을 만들지 않는다. 04~07도 필요한 자료가 없다고 강제 문구로 채우지 않는다. 모든 유형에서 질문/명세는 유지하되 unavailable/n/a를 이유와 함께 표현한다.

주제/요지/제목은 핵심 명제와 추상화, 순서/삽입은 선후 경계, 어법은 구문 성립, 도표는 실제 자료 대조가 중심이다. 26유형별 전체 대응은 DATA 문서에 있다. 듣기 유형까지 현재 읽기 26유형 계약으로 덮지 않는다. 학평은 기관/학년을 별도 표기하고 ‘평가원 출제 원리’의 동일 근거 표본으로 조용히 합산하지 않는다.

첨부의 조정식·이명학 세부 교수법, 2024 난이도 코퍼스의 수치, 2004/2023 선택지 연구의 결과와 Chi 1989의 구체 실험 결과는 이번에 원문까지 검증하지 못했다. 출처 미확인 주장으로 새 필드/알고리즘을 확정하지 않는다. 다음 연구 검토에서 원문과 표본/과제/지표를 확보한다. 인기가 있거나 첨부 보고서에 있다는 이유로 효과 증거로 승격하지 않는다.

## 6. 실제 교육 효과 검증

기능 검증: 같은 evidence ID가 같은 원문 단위·claim·선지 조건을 가리키는가, 설명 접근/취소/복귀/예외가 정확한가. 별도의 전문가 콘텐츠 검수: 의미·구문·필수 근거·반례를 전량 확인한다.

교육 효과 파일럿은 실제 학습자가 있을 때 별도 진행한다. 기존 v2와 v3를 가능한 동일 문항·설명량·노출 시간으로 비교하고, 사전 수준/원문 이해 부담을 기록한다. 비교쌍 사용·설명 후 수행과 미노출 전이 수행을 구별하고 채점자는 조건을 모르게 한다. 사전에 루브릭(원문 의미 정확성, 발문↔근거 연결, 비선정 이유, 공통점/차이, 적용 조건/경계)을 정의한다. 즉시·지연·미노출 사례를 사용하며 반응 통계와 표본·탈락·불확실성을 보고한다. 표본/기간/효과 임계값은 연구 설계로 정하고 임의 상수를 제품에 넣지 않는다.

학생이 없으면 `verified_technical`/콘텐츠 정합성까지만 보고하고 `validated_learning`은 미확인으로 둔다. 강의 완주·이해했어요·저장·비교했어요는 효과 검증의 대체물이 아니다.
