# F08 파일럿 — 원본 크롭 위 밑줄 · 선지 기호 위치 (2026-10-13)

> 목적: 「원본을 보여 주기」(이미 됨 — 밑줄 · 도표 유형 7종은 기기 추출에서 원본 크롭으로 표시)와 「선택한 근거를 원본 위치에 연결하기」(F08)를 가른다. 공개 구현 전에 좌표 정확성을 사람 대조로 확인한다.
> 도구: `scripts/csat/f08-paper-marks-pilot.mts`(로컬 공개 문제지 · 개발 전용) · 계산: `apps/web/src/lib/csat/reflow/paper-marks.ts`. DB · 원문 서버 업로드 · 도표 영역 강조 없음.

## 방법

- 학습자 기기와 같은 길: pdf.js 글자 조각 · 그린 가로선 → `reflowExam` 의 문항 자리(boxes) → `renderCrop` 과 같은 크롭(2.5배 · 단 조각 세로 잇기).
- 밑줄 = 기준선이 선보다 0.8~4.8pt 위인 글자가 선 길이의 50% 넘게 덮는 선. 빈칸(덮임 30% 미만) · 상자선(글자 없음) · 한글 줄(발문 강조 「틀린」·「밑줄 친 …」)은 제외.
- 기호: 유형으로 정함 — 세트(X-) = (a)~(e) · 함축 = 없음(아래 선지 ①~⑤ 는 지문 기호 아님) · 그 밖 기호 선지 = ①~⑤. 같은 번호가 여럿이면(발문 · 선지) 밑줄이 따라오는 하나만.
- 짝: 같은 줄에서 기호 어림 위치에 가장 가까운 밑줄. 줄 끝까지 간 밑줄은 다음 줄 글자 여백에서 시작하는 밑줄로 잇는다.
- 대응이 없거나 모호하면 표시하지 않고 이유 코드(no_underline · ambiguous_underline · implied_groups · marker_count · unclaimed_underline).
- 위치는 크롭 이미지 비율(%)로 낸다 → 화면 확대/축소와 무관(구조상). 실브라우저 확대 검증은 구현 단계.

## 대상 · 결과

6개 회차(2014A · 2018 · 2022 · 2026 · M2309 · M2706) × 함의 · 어법 · 어휘 · 지칭 · 세트(42 · 44) = 27문항. 캡처 27장을 사람이 대조했다.

| 구분 | 결과 |
|---|---|
| 밑줄 위치(기호 ↔ 밑줄 · 함축 밑줄) | **114 / 114 정확 · 오탐 0** — 한 글자 밑줄(I · he) · 두 줄 밑줄(함축 2022#21 · M2309#21) · 두 단 세트(6문항, 크롭 2조각 잇기) 포함 |
| 미대응 | 2014A#28 5개 — DB 유형은 어휘지만 실제는 네모 낱말 고르기(밑줄 없음). **표시 안 함이 정답** |
| 기호 상자(파란 표시) | ①~⑤ 가 별도 조각인 회차는 정확. (a)~(e) 가 줄 조각 안에 있는 세트는 양쪽 정렬로 글자 위치 어림이 몇 pt 어긋남 → **화면에는 밑줄만 표시하고 기호 상자는 쓰지 않는다** |
| 여러 쪽에 걸친 문항 | 표본에 없음(세트도 한 쪽 두 단) — 구현 단계에서 별도 확인 |

## 실측으로 바뀐 규칙

1. **기준선 거리** — 2018 문제지는 밑줄이 기준선 약 1.9pt 아래(최신 3.1~3.4pt). 거리 대신 덮임으로 빈칸과 가른다.
2. **선 최소 폭** — 제품 `hlinesOfOps` 는 12pt 이상만 모은다. 12pt 로 다시 돌리면 한 글자 밑줄(he · I)이 빠져 114 → 104, 함축 두 줄 묶음도 깨진다. **위치 계산용 선은 4pt 이상으로 따로 모으고, 빈칸 복원(blankFrags)은 지금 12pt 그대로 둔다**(빈칸 복원 회귀 없음 — 이번 파일럿은 기존 추출 코드를 바꾸지 않았다).
3. **글자 여백** — 두 줄 밑줄 잇기는 단 경계가 아니라 실제 줄 시작 · 끝으로 잰다.

## 캐시 · 배포 설계(구현 단계)

- 원본 크롭은 기기 캐시에 없고 **탭 메모리**에만 있다(read-paper `crops`). 크롭을 그리는 순간 = PDF 바이트가 있는 순간이므로, 위치도 그때 같이 계산해 같은 탭 메모리에 둔다. **추출 버전(REFLOW_VERSION)을 올리지 않는다** — 기존 추출본을 무효화하지 않는다.
- 기존 추출본만 있고 이번 탭에서 문제지를 놓지 않았으면 지금처럼 「밑줄·도표를 원본으로 확인하려면 문제지를 다시 놓아 주세요」 — 위치 연결도 그때 열린다는 문구를 더한다.
- 개발 서버의 로컬 PDF 자동 공급(`/api/csat/dev-paper`)은 학습자 환경이 아니다 — 구현 검증은 「문제지를 놓은」 경로(PaperDrop)로도 따로 한다.

## 공개 구현 범위 제안

- 근거로 선지 n 을 고르면(기호 선지 유형 · 세트) 원본 크롭 위 그 밑줄을 표시. 함축은 밑줄 어구를 「평가 과제」 장면에서 표시.
- 대응 실패 · 모호면 표시 없이 이유 한 줄. 도표는 원본 표시만.
- 전량(밑줄 유형 · 로컬 문제지 있는 회차) 자동 판정표를 구현 단계에서 돌리고, 미대응 · 이유 코드 분포를 확인한 뒤 공개.
