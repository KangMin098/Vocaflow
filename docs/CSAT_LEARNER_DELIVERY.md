## 1. 무엇이 잘못됐었나 — 잰 값

`/csat` 은 **분석이 부족한 화면이 아니었다.** 802문항이 100% 분석돼 있고 26유형 전부 리포트가
있었다. 잘못된 것은 **그것을 내놓는 방식**이었다. 2026-09-15 실측:

| 화면 | 보이는 글자 | 가장 긴 산문 덩어리 | 접힌 위 글자 | 접힌 위 **증명** | 조작 컨트롤 |
|---|---|---|---|---|---|
| 허브 `/csat` | 4,030 | 228 | 1,256 | **0** | **0** |
| 유형 `/csat/R-BLANK` | 10,730 | **1,084** | 1,702 | **0** | **0** |
| 유형 `/csat/R-ORDER` | 6,175 | 660 | 1,368 | **0** | **0** |
| 문항 `/csat/item/…` | 1,213 | 223 | 662 | 0 | 3 |
| 계획 `/csat/plan` | 4,076 | 278 | 845 | **0** | **0** |

여섯 화면 중 **다섯이 조작 불가**였고 **여섯 모두 접힌 위에 「수행한 결과」가 없었다.**
학습자가 도착해서 얻는 것은 읽을거리 26개였다 — 무엇부터 할지는 말해 주지 않는 목록.

**핵심 진단**: 분석은 산문으로 쓰여 있었고, **산문은 학습자가 검증할 수 없다.** 읽고 믿거나
말거나다. 그런데 이 분석의 주장은 대부분 **셀 수 있는 것**이었다 — 근거가 지문의 어디에
있는지, 어떤 함정이 몇 번 나오는지, 시간이 얼마나 드는지. 셀 수 있는 것을 산문으로 쓰면
증명이 사라진다.

자: `apps/web/scripts/csat-surface-measure.mts`(수치) · `csat-shot.mts`(눈). 사이클마다 둘 다 본다 —
**수치가 좋아져도 화면이 깨져 있을 수 있다**(실제로 두 번 그랬다. §6 참조).

## 2. 발견 — 외울 것은 26이 아니라 9다

`csat_item_analyses.choice_analysis` 는 문항마다 오답 선지를 하나씩 뜯어 **함정 이름**을 붙여
두었다. 802문항 × 오답 4개 = **3,208개**(문항마다 **최신 버전 하나만** 센 값 — 버전을 안 접으면
11,788 로 세 배 부풀고, 분석을 많이 고친 문항일수록 크게 세어져 분포 자체가 거짓이 된다).

이름은 518가지로 흩어져 있는 것처럼 보이지만 세어 보면 그렇지 않다:

| | |
|---|---|
| 상위 **9가지** | 1,938개 = **60.4%** · 각각 **26유형 중 13~17유형**에 걸쳐 나온다 |
| 10위부터 | 갑자기 **4~5유형** |
| 상위 20가지 | 72.0% |
| 1회뿐인 이름 | 361가지 (11%) |

**13 과 4 사이의 이 틈이 화면 전체의 근거다.** 위쪽 아홉은 유형을 가로지르는 기술이고 아래쪽은
유형에 매인 요령이다. 곧 학습자가 들고 갈 것은 **26벌의 절차가 아니라 9 + (지금 푸는 유형의 몇 개)**
다 (작업기억 ~4항목 · Sweller — 학습과학 원칙 6. 26 → 9 는 그 방향이다).

| 순위 | 함정 | 개수 | 유형 수 |
|---|---|---|---|
| 1 | 어휘 함정 | 392 | 17 |
| 2 | 반대 진술 | 301 | 17 |
| 3 | 부분 사실 | 300 | 16 |
| 4 | 무관 | 269 | 14 |
| 5 | 지문 밖 상식 | 219 | 17 |
| 6 | 주체 역전 | 144 | 16 |
| 7 | 범위 과대 | 140 | 15 |
| 8 | 범위 과소 | 92 | 14 |
| 9 | 인과 역전 | 81 | 13 |
| — | (10위 지시어 선행사 절단) | 71 | **4** ← 틈 |

> **이 표는 2026-09-16 재굽기 값이다.** 하루 전 값과 견주면 낱개는 움직였지만(어휘 함정
> 389→392 · 반대 진술과 부분 사실이 2·3위를 바꿈 · 범위 과대 14→15유형) **구조는 그대로다**:
> 상위 아홉이 60.3% → **60.4%**, 틈은 여전히 13 → 4. 화면이 「아홉 가지」를 상수로 박지 않고
> `universalCoverage()` 로 세는 이유가 이것이다 — 분석이 늘면 문구가 따라 움직인다.

이 틈이 사라지면 「아홉 가지」라는 말도 근거를 잃는다. 그래서 임계값을 조용히 옮기는 대신
회귀가 **틈의 존속 자체**를 검사한다(`lib/csat/__tests__/trap-atlas.test.ts`).

> **왜 이것이 우리만 할 수 있는가**(설계 판정 §A-N1): 선지별 분석 **3,208건**이 있어야 나오는
> 수치다. 지문을 복제하지 않고도 말할 수 있고(우리가 쓴 분석이다), 경쟁사는 같은 코퍼스를
> 만들기 전에는 이 문장을 못 쓴다.

## 3. 전달 모델 — 정보 구조를 뒤집는다

| | 전 | 후 |
|---|---|---|
| 1급 시민 | **유형 26개** | **오답 만드는 법 9개** |
| 유형의 역할 | 모든 것의 입구 | 2급 — 「그 아홉이 여기서 어떻게 섞이는가」 |
| 화면이 주는 것 | 읽을거리 | **센 것 + 조작면** |
| 산문 | 첫 화면에 쏟음 | **접어 둠**(지우지 않음) · 손잡이가 분량을 말함 |

### 화면마다 답하는 질문 **하나**

| 화면 | 답하는 질문 | 증명 | 조작 |
|---|---|---|---|
| `/csat` 허브 | 평가원은 오답을 **어떻게** 만드는가 | 함정 분포 막대(3,208개 실측) | 유형 칩 8 · 「최근 4개년만」 |
| `/csat/[typeId]` 유형 | 이 유형에서 **유난한** 것은 무엇인가 | 근거 자리 분포 + 오답 구성 + **전체 대비 배수** | 함정 줄 펴기 · 절차 「막히면」 |
| `/csat/item/[slug]` 문항 | 그래서 **왜 ③인가** | 지문 지도(문장 막대 + 근거 자리) | 근거 칩 |
| `/csat/plan` 계획 | 시험 시간이 **몇 번에서** 바닥나는가 · **무엇부터 공부하나** | 시간 띠 + 45분 선 | 읽기 속도 칩 3 · 순서 토글 |
| `/csat/drill` 훈련 | 나는 이 수법을 **알아보는가** | 실제 기출 오답 해설 한 장 | 보기 4 · 다음 |
| `/csat/overlay` 오버레이 | 내 문제지 **그 자리**에 해설을 얹으면 | PDF 위 좌표 상자 | 파일 떨어뜨리기 |
| `/csat/map` 지형 | 이 유형은 **언제부터** 얼마나 자주 나오나 | 연도 × 유형 히트맵(30회차 802문항) | 칸 고르기 · 화살표 키 |
| `/csat/predict` 사정권 | **무엇부터** 볼 것인가 | 최근 출제 빈도 막대 + A/B/C | 범위 슬라이더 |

**같은 질문을 두 화면이 답하지 않는다.** 답이 겹치면 학습자는 어느 화면에 가야 할지 모른다.

### 레일 — 화면들이 서로의 존재를 알게 한다 (2026-09-16)

위 표의 화면들은 저마다 쓸모가 있었지만 **서로 링크가 없었다.** 그래서 `app/(main)/csat/layout.tsx`
가 5칸 레일을 깐다(정본 `lib/csat/steps.ts` — 지도·지형·사정권·겨루기·주파).
**막힌 칸은 없다.** 순서는 보여 주되 **강제하지 않는다** — 어느 칸으로든
바로 들어간다.

⚠️ **레일의 첫 판이 거짓말을 했다.** 브리프의 7단계를 실제 라우트를 안 보고 옮기면서
`/csat/drill` 이 있는데도 「훈련 — 아직 열리지 않음」이라 적었고 `/csat/plan` 은 통째로 빠뜨렸다.
레일은 「어디로 갈까」에 답하는 줄인데 **있는 문을 없다고 말한 것**이라 없는 문을 만드는 것보다
나쁘다. 그래서 회귀가 이름을 맞춰 보는 대신 **파일 시스템에 `page.tsx` 가 있는지** 양방향으로
본다(`lib/csat/__tests__/axes-steps.test.ts` — 변이 둘로 확인: 드릴 빠뜨림·없는 라우트 둘 다 잡힘).

⚠️ **같은 거짓말을 두 번 했다.** 위를 고치면서 ⑦ 「내 기록 — 저장할 칸이 아직 없다」를
`later` 로 남겼는데, 그 사이 §9 마이그레이션이 적용돼 있었고(`20260916021500` · 실측 **57행**)
`my-traps.ts` 를 허브 칩과 주파 순서가 **이미 쓰고 있었다.** 게다가 그것은 독립 화면이 아니라
기존 화면에 얹히는 **층**이라, 칸을 주면 눌러 갈 곳이 없다. 칸을 없앴다.
두 번 다 원인이 같다 — **문서를 베껴 적고 저장소·DB 를 안 봤다.**

⚠️ **「묶기」(`/csat/patterns`)를 걷어냈다**(2026-09-16). 하루 전에 내가 지은 화면인데 같은 날
`my-traps.ts` 가 들어오면서 **잉여가 됐다** — 둘 다 「내가 챙길 함정」에 답하는데, 묶기는
*손으로 고른* 것을 `localStorage` 에 담고 기록은 *실제로 틀린* 것을 DB 에 담아 표본 문턱까지
지키며 주파 순서에 쓰인다. **측정이 자기보고를 이긴다.** 더 나쁜 것은 학습자가 브라우저에만
있는 묶음을 자기 「기록」으로 오해할 수 있다는 점이다. 위 「같은 질문을 두 화면이 답하지
않는다」에 걸린 첫 사례다.

⚠️ 레일에 **안 넣는 라우트가 둘** 있고 둘 다 의도다: `/csat/[typeId]`·`/csat/item/[slug]` 은
입구가 아니라 **드릴다운 목적지**이고, `/csat/overlay` 는 단계가 아니라 **도구**다.

두 축(형식·소재)의 색·기호는 `lib/csat/axes.ts` 한 곳에서만 정한다 — 화면마다 파랑을 고르면
학습자가 두 벌을 배운다. 하드코딩 색 0(전부 토큰 참조).

### 학습자 5단계 — 무엇이 있고 무엇이 없는가

```
① 알기   함정 지도에서 「평가원이 쓰는 아홉 가지」를 본다          ✅ /csat
② 짚기   함정 하나를 골라 그 함정이 든 실제 기출을 본다            ✅ /csat 줄 펴기 → /csat/item
③ 겨루기 오답 해설을 읽고 «그 수법의 이름»을 맞힌다                ✅ /csat/drill
④ 재기   내가 어느 함정에 되풀이해 걸리는지 개인 분포가 쌓인다      ✅ /csat 「내 기록」 칩
⑤ 주파   내 약한 함정 순서로 한 회차를 짠다                       ✅ /csat/plan 「내 약한 것 먼저」
```

### ③ 겨루기 — 왜 이 형태인가 (2026-09-15)

지문을 실을 수 없으니 「문제를 푼다」는 못 한다. 대신 **우리가 쓴 오답 해설**(끌리는 이유 ·
버리는 법)을 읽고 **수법의 이름**을 고르게 했다. 그러면 평가원 저작물이 **한 글자도** 필요
없고, 그 자리에서 **1,013문제**가 생긴다(범용 아홉 × 함정당 최대 120).

재는 것을 망가뜨리는 길이 셋 있고 셋 다 화면은 멀쩡히 돈다 — 그래서 회귀로 막았다:

| 망가지는 길 | 막은 방법 |
|---|---|
| 보기를 전체에서 뽑으면 **소거법**으로 풀린다 | 그 유형에서 **실제로 나오는** 함정 중에서 뽑는다 (`by_type`) |
| 여덟을 그냥 뽑으면 **어휘 함정(20%)이 셋** 나온다 | 함정마다 최대 둘 — 한 세트가 넷 이상을 묻는다 |
| 해설이 정답 이름을 품으면 **읽기 검사**가 된다 | 굽는 단계에서 버린다(실측 3건 · 0.16%) |

그리고 **한 번 틀린 것을 「약점」이라 부르지 않는다.** 여덟 문항에서 1/1 은 표본이 아니고,
그걸 약점이라 적으면 학습자가 **없는 결함**을 고치러 간다(철학 3). 두 번 보고 두 번 다
놓친 것만 이름을 부른다.

### ④ 재기 — 붙였다 (2026-09-16 · 마이그레이션 `20260916021500`)

훈련이 **문제마다** 한 행을 쓰고(세트 끝이 아니라 — 중간에 그만둔 것도 기록이다),
`/csat` 지도에 「내 기록」 칩이 생겨 **같은 막대를 내 오답으로 다시 센다.** 화면이 유형에
대해 이미 하던 말(「여기서 유난하다」)을 **학습자 자신에 대해** 하게 되는 지점이다.

기존 `csat_item_attempts` 를 못 쓴 이유는 **문항 id 를 담을 칸이 없어서**다: `question_id` ·
`text_id` · `dcp_item_id` 가 전부 `uuid` 인데 `csat_items.id` 는 `M2309#42` 같은 **TEXT** 다.
그래서 `csat_trap_attempts` 를 따로 세웠다(스키마는 [DB_SCHEMA.md](./DB_SCHEMA.md)).

#### 여기서 가장 조심한 것 — **얇은 표본으로 「당신의 약점」을 적지 않는다**

세 번 만나 두 번 틀린 것과 스무 번 만나 열네 번 틀린 것은 같은 66%가 아닌데, **막대는 둘을
똑같이 그린다.** 그래서 문턱을 코드에 박았다(`lib/csat/my-traps.ts`):

| | 문턱 | 넘기 전에는 |
|---|---|---|
| 한 함정의 **배수**를 말하려면 | 그 함정을 **3회** 이상 | 「2번 봄」처럼 **센 것만** |
| 전체를 **「분포」**라 부르려면 | 시도 **20회** 이상 | 「분포라고 부르기엔 일러요」 |

「되풀이해 걸린다」는 3회 이상 만나 절반 넘게 놓친 것만 부르고, **셋까지만** 부른다 —
여섯이 다 걸리면 문장이 목록이 되고 그건 §6-1 과 같은 병이다.

실측(검증 계정 57문항): 범위 과대 22회(46.8%) **×8.2** · 주체 역전 ×1.8 · 나머지 「비슷」.

### ⑤ 주파 — 붙였다 (2026-09-16)

지도는 유형마다 오답이 **어떤 수법으로** 만들어졌는지 알고, 기록은 내가 **어떤 수법에**
걸리는지 안다. 둘을 곱하면 「이 유형에서 내가 잃을 몫」이 나온다 — 조인 하나로 나오고
새 테이블이 필요 없다(`lib/csat/plan-order.ts`):

```
risk(유형) = Σ_수법  (내 오답 중 그 수법의 몫) × (그 유형 오답 중 그 수법의 몫)
```

계획 화면에 「시험 순서 / 내 약한 것 먼저」 토글이 생기고, 줄마다 **왜 위로 왔는지** 적는다
(「내가 자주 놓치는 수법 — 범위 과대 · 이 유형 오답의 15%」). 실측: 18번으로 시작하던 줄이
**27번 안내문 일치**로 바뀐다.

#### ⚠️ 이 화면이 줄 수 있는 가장 나쁜 조언을 막는다

**시험은 번호 순서로 치른다.** 이 순서를 「시험장에서 문제를 건너뛰며 푸는 법」으로 읽으면
학습자가 손해를 본다. 그래서 세 가지를 못 박았다:

1. 토글을 켠 동안 화면이 **「시험은 번호 순서로 치릅니다 — 이건 공부할 순서예요」** 를 띄운다
2. **시간 띠는 언제나 번호 순서**다(정렬은 목록에만 적용 — 회귀가 띠의 `data-no` 가 오름차순인지 본다)
3. 기록이 문턱(20회) 아래면 **토글을 아예 안 내민다** — 다섯 문항으로 「네 약점 순서」를
   내밀면 그건 순서가 아니라 잡음이다. 대신 왜 없는지와 훈련으로 가는 문을 적는다

## 4. 구성 규칙 — 다음 화면을 만들 때 그대로 쓴다

1. **셀 수 있는 것을 산문으로 쓰지 않는다.** 분석에 「대개 뒤쪽에 있다」가 적혀 있으면 그건
   세어서 그릴 수 있다는 뜻이다. 세어 그리면 학습자가 **검증할 수 있다**.
2. **증명이 접힌 위에서 끝난다**(데스크톱 1280×900). 클릭 0 · 입력 0.
3. **조작이 하나는 있다.** 값을 바꾸면 결과가 **네트워크 왕복 없이** 바뀐다 — 구운 JSON +
   순수 함수(`rankFor` · `buildTimeline`). 왕복이 있으면 200ms 를 지킬 수 없다.
4. **산문은 지우지 않고 접는다.** 손잡이에 **분량을 적는다**(「약 13.0천 자 →」) — 몇 자를
   여는지 알고 열어야 한다.
5. **순위가 아니라 배수로 말한다.** 어느 유형을 열어도 1~2위는 같다(전체 1~2위니까).
   학습자에게 정보가 되는 것은 **여기서 유난한가**다. 단, §6-1 의 분모 함정을 조심할 것.
6. **색만으로 말하지 않는다.** 기호(◆/◇) + 글자(「17유형」) + 톤 셋으로 낸다. 색이 실어
   나르는 정보가 색 말고 다른 곳에도 있어야 한다.
7. **비난하지 않는다**(철학 3). 시간이 모자라면 「절차가 아직 무겁다는 뜻」이라고 적는다.
   색은 `--warning`(주의)이지 `--error`(실패)가 아니다.
8. **「그 밖」을 지우지 않는다.** 60%라고 말하려면 나머지 40%가 화면에 있어야 한다.
9. **계측을 같은 커밋에.** 조작을 넣었으면 그 조작이 실제로 일어나는지 세는 이벤트를 함께
   넣는다 — 안 재면 그 조작이 장식인지 아닌지 영원히 모른다.
   현재: `csat_atlas_scoped` · `csat_trap_opened` · `csat_plan_speed_set` · `csat_evidence_opened` ·
   `csat_drill_answered` · `csat_drill_finished` · `csat_plan_ordered`.
10. **못 하는 것을 화면이 말한다.** 훈련 결과가 저장되지 않으면 그렇게 적는다 — 안 적으면
    학습자는 쌓이는 줄 알고 돌아왔다가 빈 화면을 본다. 막다른 화면 금지는 **거짓 약속 금지**다.

## 6. 이 작업에서 실제로 틀렸던 것 — 다음 사람이 같은 데 빠지지 않게

전부 **화면은 멀쩡히 뜨는데 틀린** 종류였다. 그래서 회귀로 잠갔다.

### 6-1. 배수의 분모가 달랐다
「유형 안 비율 ÷ 전체 비율」로 쟀다. 그런데 전체는 24.4%가 「그 밖」인데 `R-BLANK` 는 오답
460개가 **전부 이름을 받아** 그 밖이 0이다 → **여섯 줄이 모두 ×1.3 이상**으로 떴다.
**전부 유난하면 아무것도 유난하지 않다.** 분모를 「이름 붙은 것끼리의 몫」으로 맞췄다
(`baselineShare` · `liftOf`). 같은 결함이 `standoutFor`(허브 카드)에도 있었다.

### 6-2. 막대가 자기 비율보다 길었다
「그 밖」(24.4%)을 1위(12.1%)만 기준으로 그려 **컨테이너를 넘어 꽉 찬 막대**가 됐다.
수치는 맞는데 **그림이 거짓말하는** 종류다. 회귀: 모든 줄의 `폭/비율` 이 같은가.

### 6-3. 띠가 아예 안 칠해져 있었다
`color-mix` 의 둘째 인자로 쓴 `var(--sf)` 가 그 자리에서 안 풀려 색이 통째로 무효가 됐다
(계산된 배경 `rgba(0,0,0,0)`). 그런데 **화면은 뜨고 `data-proof` 도 그대로라 계측기가
「증명 1개」로 보고했다** — 자가 스스로를 속인 경우다. 회귀: 칸의 배경이 투명하지 않은가.

### 6-4. h1 이 하나도 없었다
히어로를 컴포넌트로 뽑으면서 기본값 `h2` 를 그대로 썼다. **`axe` 의 wcag2a/aa 로는 안 잡힌다**
— 빈 h1 은 best-practice 규칙이다(중복 landmark 와 같은 사각지대). 기존 스펙 41 이 잡았다.

### 6-5. 규칙을 스펙에 베껴 썼다
터치 타깃 판정을 손으로 다시 적었다가 **문장 속 인라인 링크 예외**를 빠뜨려 144건이 거짓
양성으로 잡혔다. 단일 출처는 `tests/e2e/utils/tap-target.ts` 다 — 그 파일 머리말이 정확히
이 일을 경고하고 있었다.

### 6-6. 산문 마크업이 맨손으로 나갔다
계획 화면이 `{r.first_step}` 을 그대로 찍어 학습자에게 **별표가 보였다**
(`**타인의 말을 근거에서 뺀다**`). 같은 글을 유형 화면은 `ReportText` 로 그리고 있었다 —
한쪽만 맨손이었다. 리포트에서 온 문자열은 **반드시** `ReportText` 를 거친다.

## 9. ④ 재기의 저장소 — 적용됨 (2026-09-16)

사용자 승인 뒤 적용했다. 실제 파일은 `supabase/migrations/20260916021500_csat_trap_attempts.sql`
이고 아래는 그 요지다 — 왜 이 모양인지는 그 파일 머리말에 더 적혀 있다.

```sql
-- supabase/migrations/20260916021500_csat_trap_attempts.sql
--
-- 오답 감별 훈련의 기록. 기존 `csat_item_attempts` 를 못 쓰는 이유는 그 표의 문항 칸이
-- 전부 uuid 인데 `csat_items.id` 는 'M2309#42' 같은 TEXT 라서다.

create table if not exists public.csat_trap_attempts (
  id          uuid primary key default gen_random_uuid(),
  user_id     uuid not null references auth.users(id) on delete cascade,
  item_id     text not null references public.csat_items(id) on delete cascade,
  -- 몇 번 선지에 대한 판정이었나. 같은 문항의 다른 오답이 다른 문제가 된다.
  choice      smallint not null,
  -- 정답 함정과 고른 함정. 이름은 분석이 쥐고 있으므로 FK 를 걸지 않는다(이름이 바뀌면
  -- 과거 기록은 그때의 이름으로 남는 것이 옳다 — 지난 답을 소급해 고치지 않는다).
  answer_trap text not null,
  picked_trap text not null,
  is_correct  boolean generated always as (answer_trap = picked_trap) stored,
  answered_at timestamptz not null default now()
);

-- 「내 분포」는 늘 한 사람 것을 최근 순으로 읽는다.
create index if not exists csat_trap_attempts_user_time
  on public.csat_trap_attempts (user_id, answered_at desc);
-- 함정별 집계용.
create index if not exists csat_trap_attempts_user_trap
  on public.csat_trap_attempts (user_id, answer_trap);

alter table public.csat_trap_attempts enable row level security;

-- 자기 기록만 쓰고 읽는다. 남의 성적은 보이지 않는다.
create policy csat_trap_attempts_own_select on public.csat_trap_attempts
  for select to authenticated using (auth.uid() = user_id);
create policy csat_trap_attempts_own_insert on public.csat_trap_attempts
  for insert to authenticated with check (auth.uid() = user_id);
-- update/delete 정책은 두지 않는다 — 지난 답을 고칠 수 있으면 기록이 아니다.
```

붙인 뒤 한 일 — 넷 다 했다:

1. ✅ 훈련이 답마다 한 행을 쓴다(세트 끝이 아니라 **문제마다** — 중간에 그만둔 것도 기록이다).
   `app/(main)/csat/drill/actions.ts`. **기다리지 않는다** — 쓰기가 느리거나 실패해도 학습자는
   다음 문제로 간다. 실패한 건이 있으면 끝 화면이 그 수를 말한다.
2. ✅ 끝 화면의 「아직 저장되지 않아요」를 지웠다 — 그 문구가 남아 있으면 거짓말이 된다.
3. ✅ `/csat` 지도에 「내 기록」 칩. 같은 막대를 내 오답으로 다시 센다(`rankFromCounts`).
4. ✅ 문턱을 코드에 박았다 — 함정당 **3회**, 전체 **20회**. 그 아래에서는 「2번 봄」처럼
   센 것만 보여 준다(`lib/csat/my-traps.ts` · 회귀 `my-traps.test.ts` 11종).

⚠️ **이 표는 e2e 가 쓴다.** 스펙 45 가 훈련을 끝까지 풀면 검증 계정에 행이 남는다. 지우지
않는다 — 기록이 있어야 「내 기록」 칩이 있는 상태를 검사할 수 있고, 비우면 그 검사가 조용히
건너뛰어진다.
