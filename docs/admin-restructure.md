# 관리자 구조 재편 — 2026-10-19

> 이 문서는 로컬 1차 구현 기록이다. 후속 요청에 따른 [하위 메뉴·파이프라인 심층 재설계안과 기존 비교](./admin-submenu-redesign.md)는 별도 제안이며 아직 화면에 적용하지 않았다.

## 목적과 적용 범위

관리자가 파이프라인 약어를 기억해서 화면을 찾던 구조를 업무 대상별 진입 구조로 바꾼다. 처리 엔진과 권한은 유지하면서 메뉴·화면 소속·돌아가기·도움말을 함께 정리했다. PC 웹이 대상이다.

최신 main의 관리자 페이지 파일 89개를 전수 확인했다. 기존 상세·생성 URL은 유지하고, 역할이 겹치거나 안내만 하던 일부 진입 URL은 검색값을 보존해 통합 화면으로 연결한다. 기준 코드와 회귀 검사는 각각 `apps/web/src/lib/admin/navigation.ts`, `sidebar-screen-titles.test.tsx`다.

## 결정한 메뉴와 화면 소속

| 왼쪽 메뉴 | 내부 화면 | 구분 원칙 |
|---|---|---|
| 작업 홈 | 처리 대기·실패·최근 변경·실측 요약 | 상세 분석은 활동 분석으로 이동 |
| 콘텐츠 | 도서 / 짧은 글 / 만화 / 주제 코퍼스 | 먼저 자료 종류를 선택하고 수집 방식을 선택 |
| 교재 제작 | 제작 현황 / 한 권 만들기 / 발행 교재 | 한 권의 기준을 선택한 뒤 글감·문항·해설·검수·발행으로 이동 |
| 어휘·사전 | 사전 / 단어장 제작 / 사전 보강 / 품질·분류 | 단어장 생산과 공용 사전 보강을 구분 |
| 학습자·진단 | 사용자 / 영어 진단 / 어휘 진단·수준 / 활동 분석 | 학습자 대상의 진단과 활동을 모음 |
| 연구·기준 | 기존 학습 원리 5공간 / 기출 분석 / 교재 기준 | 운영 공정의 결과와 근거·설계를 구분 |
| 운영·시스템 | 콘텐츠 품질 / DB 상태 / 홍보 영상 / 연결·지원 상태 | 운영 도구와 아직 연결되지 않은 기능의 상태 |

기존 main의 사이드바 DOM 링크는 30개였다. 새 사이드바의 업무 진입점은 7개이며 브랜드·학습 화면 링크는 별도다. 현재 영역의 화면과 작업 도구만 본문 위에 표시한다. 접기 상태를 저장하던 옛 localStorage 값은 새 메뉴에 영향을 주지 않는다.

`/admin/csat/diagnosis`는 학습자·진단, `/admin/csat/evidence`, `strategy`, `blueprint`는 연구·기준이다. URL이 CSAT 아래 있다는 이유로 교재 제작 제목이나 복귀 링크를 붙이지 않는다. 어휘 진단·사용자 수준·수준 이력도 어휘 품질 관리와 분리했다. Knowledge의 기존 세부 탭은 유지하고 중복된 상위 탐색 행만 공통 내비로 통합했다.

## 처리 흐름과 상태 보존

### 도서

기존 소스별 9개 탭을 **도서 목록 / 수집 / 검토 대기** 3개 보기로 정리했다. 수집 보기에서 소스 카탈로그·묶음 검색·seed·ID·Wikibooks·Wikisource·OpenStax·StoryWeaver의 기존 입력 기능을 선택한다. 기존 수집 컴포넌트와 서버 액션을 재사용한다.

목록은 25행씩 표시한다. 검색·소스·수준·처리 상태·페이지·선택 상세는 URL에 남긴다. 필터 변경 시 첫 페이지로 돌아가며 범위를 넘긴 페이지는 마지막 페이지로 보정한다. 같은 갱신 시각의 행도 ID로 순서를 고정한다. 머리글의 전체 선택은 현재 페이지에만 적용되고 직접 선택한 다른 페이지의 행은 일괄 작업의 선택 수에 남는다.

수집 성공 후에는 이전 필터와 선택을 초기화하고 도서 목록을 새로 읽는다. 성공을 확인하기 전에 목록을 초기화하지 않는다. URL 갱신은 Next의 검색 파라미터 구독이 함께 갱신되도록 내부 history 상태를 복사하지 않는 공통 함수를 사용한다.

상단 통계는 한 줄 요약으로 줄이고, 처리할 도서가 없는 경우 중복된 작업 순서 안내를 숨겼다. 검토 대기에 들어가거나 나올 때에는 해당 큐의 상태·페이지·선택 상세를 초기화한다. 일반 목록과 수집 사이의 이동은 기존 검색·필터를 보존한다.

### 교재

시리즈·단계·학년·유형·권 식별자를 기존 페이지 사이의 링크에 전달한다. 이 값은 탐색 기준이며 서버에 저장된 주문이나 주문별 진척을 새로 만든 것이 아니다. 공장 전체 재고와 주문별 진행률을 혼동하지 않도록 화면에 명시한다.

문항과 해설은 `/admin/csat/authoring`의 두 보기로 연결한다. 기존 제작·해설 클라이언트를 유지하고 `view=items|explanation`으로 전환한다. 검수·발행 엔진과 게이트는 바꾸지 않는다.

### 어휘·연결 상태

단어장 제작은 Studio로 진입한다. 기존 사전으로 조립하는 Studio와 새 seed로 만드는 Runs는 서로 다른 생산 방식으로 유지한다. 공용 사전의 누락을 채우는 Pending Words는 사전 보강으로 구분한다.

신고·결제·설정의 저장 경로 없는 토글과 중복 안내 화면은 연결·지원 상태 한 화면으로 모았다. 실제로 실행하지 않는 기능을 실행 가능한 설정처럼 보여 주지 않는다. 활동 분석은 실제 집계와 기존 리텐션·교사 퍼널 패널을 제공한다. 작업 홈의 부재 reports 집계와 신고 배지는 제거했다. 사용자 현황의 기존 목업 고지는 유지한다.

## 기존 URL 호환

| 기존 진입 | 통합 목적지 |
|---|---|
| `/admin/library` | `/admin/curation?view=library` |
| `/admin/reports` | `/admin/settings#reports` |
| `/admin/billing` | `/admin/settings#billing` |
| `/admin/csat/explain` | `/admin/csat/authoring?view=explanation` |

기존 검색 파라미터와 복수 값은 보존하고 통합 화면에 필요한 보기 값만 정규화한다. `/admin/vocab`의 기존 Runs redirect도 유지한다. API·RPC·DB 스키마·인증·권한 계약은 변경하지 않았다.

## 화면 참조 검증

3B의 기존 2026-10-03 측정 자산에서 외곽 프레임 규격을 재사용했다. `docs/design/refs/3b/admin/spec.json`은 출처·원본 해시·한계를 명시한다. 캡처의 작업 영역 경계를 사용하며 인증된 참조 앱 전체 DOM을 새로 측정했다는 뜻은 아니다. 내부 모든 화면의 픽셀 일치를 주장하지 않는다.

`node scripts/design/ref-compare.mjs --admin --base http://localhost:3300`의 1440×900 라이트 결과:

## 검증과 운영상 한계

- 관리자 브라우저 회귀는 호환 URL, 수집 8개 입력 방식, 빠른 전환·뒤로 가기, 검토 대기의 필터 초기화, 필터·페이지·순서 복원, 문항/해설 전환과 제작 기준 전달, 진단/연구 제목, PC 4개 화면 조건을 확인한다.
- 최종 `playwright test 'admin-restructure.spec.ts$' --workers=1`: 11개 통과, 건너뜀·실패·불안정 재시도 0개(개발 모드, 134초). `PLAYWRIGHT_BASE_URL`로 독립 서버를 지정했다. 사용자 데이터의 수집·발행 버튼은 실행하지 않았다.
- 89개 페이지의 업무 소속·메뉴 목적지 존재·정확한 활성 상태·도움말·URL 계약을 자동 검사한다.
- 관리자와 인증 단위·조회 통합 회귀 56파일 866개가 통과했다. `vitest run src/components/admin src/lib/admin src/app/admin` 및 인증의 `protected-routes`·`redirect`·`errors` 세 파일을 실행했다.
- 배포용 `next build`가 lint·타입 검사·페이지 생성을 포함해 통과했다. 공유 PC의 메모리 압박으로 초기 병렬 실행을 중단하고 작업 수를 제한해 재실행했다. 기존 경고는 남아 있다.
- 배포 모드에서는 검증 계정이 일반 사용자로 판정되어 관리자 URL에서 `/hub`로 복귀했다. 기존 권한 차단을 확인했으며, 계정 권한을 변경하지 않았다. 관리자 화면의 브라우저 검증은 기존 개발 모드 환경에서 진행한다. 배포 모드의 관리자 권한 화면 QA는 별도 관리자 계정이 필요하다.
- Claude 교차 리뷰의 필터 초기화·활동 분석 목업 표시 두 결함은 수정하고 회귀로 고정했다. 가져오기 원장의 소속 누락 지적은 기존 WORKSPACES 탭 정의로 이미 연결됨을 전수 검사와 명시 사례로 확인해 반려했다.
- 도서 수집·대량 판정·발행·DB 변경은 이 검증에서 실행하지 않았다. 기존 처리 엔진의 콘텐츠 품질이나 처리 성능을 새로 검증했다는 의미는 아니다.
- 콘텐츠·교재·어휘는 책임과 입력 방식이 달라 공통 작업 엔진으로 합치지 않았다. 이번 통합은 진입·화면 연결·표시 상태를 대상으로 한다.

사용자가 2026-10-19 「로컬 구현·검증까지만 유지」로 범위를 지정했다. 변경은 `feat/admin-restructure-20261019`의 독립 워크트리에 미커밋 상태로 보존하고 커밋·push·PR을 만들지 않는다. 기존 공유 워크트리의 변경과 충돌은 건드리지 않았다. DB 역변환이나 롤백은 필요하지 않다.
