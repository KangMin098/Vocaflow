## 이번 후속의 목적

도서 상세 팝업에서 검수로 이동할 때 기존 오버레이의 뒤로가기 정리가 새 페이지를 취소하는 결함을 실제 PC 왕복에서 재현했다. `useCloseOnBack`의 기존 `afterUnwindRef`를 공용 Dialog에 전달해 이력 정리가 끝난 뒤 이동한다. 검수로 보낼 목록 주소는 닫기 전에 보존하며 새 탭 열기는 기본 링크 동작을 유지한다.

적용 추적도 같은 Reveal Gate를 적용한다. 현재 과제와 단일·복수 audience 대상 전체를 먼저 검사하며 보류 대상이 하나라도 있으면 사슬·수행·검증 조회 전에 보류 화면으로 끝낸다. 수행 원장은 응답 전체 대신 버전 메타를 읽고 허용된 시도·문항만 정오를 읽는다. 과거 수행에 보류 문항이 있으면 이를 제외하고 결속이 확정되지 않은 trial·효과 결과도 숨긴다. 판정 실패·누락·결속 불일치는 실제 0건으로 바꾸지 않는다.

2026-10-20 잔여 작업은 LOCAL_FAST로 이어간다. 최종 누적 리뷰에서 확인한 수행 정오의 Reveal Gate 누락, 다음 기출·도서 본문 검수의 목록 복귀 손실을 수정했다. 수행은 민감 정오를 제외한 메타데이터를 먼저 읽고 문항별 보류 판정 후 허용된 사용자·시도·문항만 정오를 조회한다. 보류행은 문항·결속까지 가리며 전부 보류된 페이지도 원본 커서로 이동한다. 식별 문항이 없는 기록의 정오는 조회하지 않는다. 도서 원장에 주문·공급이 없다는 이유로 수요도 없다고 표시하던 문구는 좁혔다. 앞선 “외부 query 테스트 불일치” 리뷰는 기존 `safeInternalPath`의 선행 거부를 확인해 오탐으로 철회했다.

기출 다음 상세는 검증된 유형 목록 `returnTo`를 이어 받고, 도서 상세→본문 검수는 보기·검색·소스·레벨·상태·쪽·선택 UUID를 허용 목록으로 검증해 전달한다. 검수의 복귀 링크와 작업 성공 후 이동이 같은 주소를 사용한다. 발행·보관의 실제 공유 DB 쓰기는 검증을 위해 실행하지 않으며 성공/실패 이동은 고정 mock 회귀로 검증한다. 누적 경로/기존 계약을 재생성하지 않는다. 최종 커밋의 로컬 실행·PC·독립 수용·통합 결과는 중앙 T-0054와 `verification/local/` 기록으로 판별한다. 실행하지 않은 항목이나 보류된 canonical 주문 계보를 완료로 올리지 않는다.

메뉴 분류 뒤에 남은 실제 수행·계획·공급·진단과 제품 적용 추적을 연결했다. 기존 7개 영역·22개 하위 공간과 89개 경로는 유지한다. 도메인 엔진·추천 판정·검수/발행 게이트·DB를 변경하지 않는다. 동일한 전수 조사 대신 기존 조사와 수정 대상의 실제 코드·개발 DB를 대조했다.

현재 누적 수용은 중앙 `T-0054`의 같은 최종 커밋에 결속된 증거와 `verification/reviews/`, `verification/local/` 기록을 따른다. PC 왕복은 기출 다음 상세·도서 검수 복귀·학습자 원장·적용 추적과 기존 메뉴 시나리오를 포함한다. 오류·보류·빈 결과·결속 불일치 경계는 고정 회귀로 확인하고, 실제 화면 확인과 구분한다. 격리 전체 E2E나 실제 공급 완료 사례를 실행하지 않았다면 그 성공을 주장하지 않는다.

## 기존 검증 이력 — 현재 수용 증거 아님

- 후속 로컬 전체 실행은 공유 DB 연결을 끄고 파일별 프로세스로 539파일을 끝까지 실행했다: 495파일/5,914개 통과, 43파일/248개 건너뜀, 새 인증 세션 mock 미반영 1개 실패. 해당 mock과 인자 검증을 수정한 뒤 관련 3파일 14개는 통과했다. 이를 전체 단일 실행 성공이나 생략 없는 통합 검증으로 합산하지 않는다. 생성된 감사 JSON 2개는 테스트 전 HEAD로 복원했다.
- 검증 당시 GitHub가 [Actions 처리 지연 장애](https://www.githubstatus.com/incidents/8tzbpcnl75jp)를 공지했고 최신 PR CI는 queued였다. 안전 병합 dry-run은 최신 HEAD 성공 체크 부재로 거부됐다. 로컬 결과로 이 게이트를 대체하지 않으며 CI와 main 병합은 완료 상태가 아니다.

- 목적 대조 리뷰에서 공급 행이 있을 때 `workspace_line_fulfillment`가 세션 없는 관리자 클라이언트를 거부하는 문제를 발견했다. 설치된 함수와 RLS를 직접 조회해 확인했다. Workspace는 본인 읽기만 허용하므로 관리자 소유 조회를 유지하고, 기존 충족도 RPC에만 요청의 인증 클라이언트를 전달한다. SQL·RLS를 바꾸지 않았다. 읽기·세션 전달·실패 구별과 기존 격리 공급 계약을 포함한 4파일 60개가 통과했다. 실제 관리자 계정의 공급 행이 있는 운영 사례를 검증했다는 뜻은 아니다.
- 최초 PR 통합 검사에서 미사용 `csat_plan_ordered` 정의와 컴포넌트 CSS 변수 출처 누락 2건을 발견했다. 은퇴 이벤트를 활성 계약에서 제거하고, 관리자 프레임·레일에 기존 검사기의 `tokens-from` 계약으로 실제 상위 CSS 모듈을 명시했다. 토큰을 전역으로 옮기거나 검사 예외를 추가하지 않았다.
- 수정 후 실패 관련 3파일 86개·집중 lint·web/스크립트 타입 검사는 통과했다. 공유 DB 연결을 끈 로컬 전체 단위 테스트는 Node 메모리 부족으로 중단돼 통과로 계산하지 않는다. 전체 재검증은 최신 PR HEAD의 격리 CI 결과를 따른다.

- 관리자·인증·기존 읽기 통합 회귀: 67파일 946개 통과, skip 0. 이후 연구 중복 내비 수정은 집중 회귀 1개와 lint를 별도로 통과했다. 새 조회/버전/결속/복귀 중심 42개는 위 회귀에 포함되며 중복 합산하지 않는다.
- 전체 빌드: lint·타입·페이지 생성까지 exit 0. 이후 연구 내부 내비 중복 제거와 브라우저 locator 수정은 집중 lint·회귀·실제 렌더로 확인했다. 최종 push HEAD의 전체 재검증은 PR의 필수 CI를 따른다.
- 신규 PC 브라우저 3개 통과, skip 0: 기출 회차/검색 상세 복귀, 같은 대상의 실제 수행 수·계획 미결속·페이지 경계, 실제 등록 적용의 버전/전역 효과 분리. 최초 실행에서 접힌 본문 링크를 잘못 선택한 테스트를 실제 목록으로 좁혀 고쳤다. 그 뒤 기존 스펙까지 한 번에 재실행하던 개발 서버가 종료돼 해당 반복을 중단했고, 복구 후 변경된 3개만 재실행했다. v2.1의 기존 16개 통과 기록과 합쳐 새 19개 전부를 한 번에 통과했다고 보고하지 않는다.
