# 관리자 파이프라인 전체 단계 실테스트 — 진행 중

2026-10-21 · 앞선 [사용성 점검](usability-audit.md)의 조회·팝업 검증을 확장한다. 사용자는 **격리 DB에서 생성·발행·실패·복구까지 테스트**하는 방식을 선택했다. 공유 DB는 구조·권한 메타데이터를 읽기 전용 트랜잭션으로 조회했으며 사용자·콘텐츠 행은 복제하지 않았다. 아래 결과를 전체 18개 파이프라인의 완료 판정으로 읽지 않는다.

## 실행 환경과 판정

- 전용 로컬 PostgreSQL 17.10에 현재 구조를 복원했다. public/auth 271표, 공개·인증 함수 496개와 reveal 경계의 private 함수 7개, RLS 정책 198개, 역할별 권한 5,601개를 가져왔다. 필수값 제약도 대조했다. 원 소유자·클라우드 확장·스케줄 실행까지 동일한 Supabase 복제본이라는 뜻은 아니다.
- 단어장·코퍼스는 실제 처리 모듈을 실행하고 PostgreSQL에 저장했다. DB 전송에는 격리 query adapter를 사용한다. PostgREST·GoTrue의 실서비스 통합이나 배포 계정 권한을 이 결과로 인증하지 않는다.
- 외부 모델·수집 사이트 대신 직접 작성한 시험 입력과 소스 응답을 사용한다. 데이터·작업 상태·파일 결과를 따로 확인하고, 오류 주입을 제거한 뒤 같은 입력의 재시도를 검사한다.
- DB 시나리오는 트랜잭션 종료 시 롤백한다. 원 실패 영수증을 덮어쓰지 않는다. `skip`, 미실행, 환경 차이는 통과와 구별한다. GitHub·원격 CI·공유 DB 쓰기는 없다.

## 현재 재현·수정한 결함

추가 재현(기사): 기존 50개 어휘를 가진 글의 재분석에서 실제 DB INSERT를 실패시키자 기존 어휘가 0개가 됐다. 새 분석을 먼저 upsert하고 완료 후 오래된 어휘를 정리하도록 바꾼 뒤 같은 실패에서 50개 보존·재실행 50개를 확인했다. 조회·정리 실패도 보고한다. 다중 요청 전체의 원자성·동시 재분석은 별도 한계다.

추가 재현(영상): 실제 설정된 무료 Edge TTS가 HTTP 403을 반환했다. 기존 함수는 빈 manifest를 정상 반환했고 부분 음성은 CLI에서 voiced로 처리할 수 있었다. 같은 부분 응답 fixture와 실제 PostgreSQL을 연결해 이전 CLI 소스는 `voiced/exit 0`, 수정 CLI는 `failed/exit 1`임을 실행으로 비교했다. 실제 제공자의 2장면 403도 현재 CLI에서 `failed/exit 1`로 기록했다. 제공자 장애는 해결되지 않았다. 로컬 Windows 음성으로 만든 명시적 시험 파일을 사용해 실제 Remotion에서 6.7초·음성 포함 3규격 MP4·포스터·VTT·설명글을 생성하고 HTTP HEAD/Range·브라우저 재생/탐색을 확인했다. 이는 Edge TTS 정상화나 실서비스 발행의 증거가 아니다. 시험 설계도의 필수 필드 누락으로 중단된 첫 포장 실행도 원 기록에 남겼다.

분류·진단 추가 실행: 실제 관리자 분류 조회는 수준 12/트랙 6/분야 8/기능 5개와 범위 밖 분류 거부를 확인했다. 영어 진단은 실제 엔진 설정 검사·활성화, 45응답 저장, 동일 client_key 중복 방지, 채점·진단, 결과 저장/복원 및 활성 설정 단일성까지 통과했다. 어휘 진단은 실제 분석·적용 RPC에서 수준 2·정확도 0.8과 프로필·이력 연결, 타인 결과 적용 거부를 확인했다.

추가 재현(PDCP): hOCR는 `bubbles.manifest.json`을 생성했으나 정제 CLI가 `bubbles.local.manifest.json`만 찾아 정상 추출 뒤 중단됐다. 두 형식을 우선순위대로 받고 실제 입력명을 보존하도록 수정했다. 실제 CLI에서 3컷/3대사 정제·현대화까지 이어졌으며 자체 OCR 우선 경로도 회귀로 확인했다. 직접 작성한 hOCR이므로 외부 OCR 인식 정확도는 측정하지 않았다.

| 위치 | 실제 실패 | 보완·재검증 |
|---|---|---|
| TCP 실패 복구 | 실제 큐 트리거로 release RPC를 실패시키면 배치 오류 없이 `claimed`가 남았다 | 복구 오류·큐 ID를 응답에 포함한다. 영구 skip 저장이 실패하면 skip 성공으로 세지 않는다 |
| TCP 이미 수확한 문서 재실행 | 문서 중복은 막혔지만 ingest의 조기 반환 뒤 현재 claim은 종료되지 않았다 | 이미 수확한 경우 현재 claimed 행을 별도 완료 처리한다. 문서 1개·관측량 유지와 done 복귀를 확인했다 |
| VCB 보강 적재 | 실제 UPDATE 오류 뒤 `imported=0, failed=1, ok=true`였다 | `ok=false`와 실패 수를 반환한다. 오류 제거 후 동일 JSONL의 저장 성공을 확인했다 |
| VCB 발행 시작 | publishing 상태 UPDATE를 거부해도 원자 발행 RPC가 실행됐다 | 원 상태와 일치하는 행의 전이·영수증이 있어야 발행한다 |
| VCB 재발행 복구 | 기존 공개 판이 있는 run의 재발행 실패 뒤 상태가 curating으로 바뀌었다 | 기존 published 상태를 복원하고 다른 실행의 완료를 덮지 않는다. 복구 오류도 보고한다 |

TCP 화면은 배치의 일시 실패가 있으면 자동 반복을 멈추도록 보완했다. ‘처리 가능한 대기 없음’은 ‘실패 없음’과 구별한다. 실제 컴포넌트·앱 CSS·격리 DB·실제 처리 함수를 연결한 Chromium에서 수확 3편, 503 후 1회 중단, release 실패 HTTP 500에도 갱신, 원인 제거 후 재시도, 미리보기/취소/5어휘 승격, 임계값 변경 시 무효화를 통과했다. 조회도 실제 overview RPC로 다시 읽어 대기 0·문서 4·승격 5를 화면에 반영했다. 1440/1280px 넘침·JS 오류 없음. Router의 refresh는 격리 조회 콜백으로 연결했으므로 Next RSC/실제 인증의 전체 통합과 구별한다. 동일 실패 조건의 지속 가능한 브라우저 회귀 3개도 통과했다.

VCB의 50개 시험 단어는 사전에서 복사한 데이터가 아니라 이 실행에서 직접 작성한 격리 입력이다. 산출물 50행과 published 상태·카탈로그 연결을 확인했다. 이는 실제 학습자에게 배포한 콘텐츠 품질이나 학습 효과를 증명하지 않는다. 영상의 DB 원장 상태와 실제 영상 파일 생성도 별도다.

원 증거는 `.agent-logs/pipeline-depth-20261021/`에 보존한다. 테스트 fixture·전송 adapter의 오류로 중단된 실행과 제품 결함의 실패 주입을 구별해 기록한다. 기존 2026-10-20 수용 기록은 변경하지 않는다.

빌드 추가 발견: 별도 distDir의 첫 프로덕션 빌드는 Terser의 `DataCloneError: Data cannot be cloned, out of memory`로 실패했다. 공유 16GB PC에서 전체 CPU 기반 Worker 병렬도를 2로 제한해 재검증한다. 실패 로그를 보존하며 3001은 기존 정상 빌드를 유지 중이다. 이 항목이 끝나기 전 현재 변경의 3001 적용 완료로 보고하지 않는다.

## 중간 회귀 확인

관련 web 18개·library-pipeline 전체 2,735개·video-factory 전체 117개·PDCP CLI 2개, 합계 2,872개 통과/실패 0/건너뜀 0을 확인했다. web·vcb-core·library-pipeline 타입과 수정 web 파일 lint도 통과했다. 영상 타입 명령은 성공했지만 원료가 없는 정규 Remotion Root/index 두 파일을 명시적으로 제외했으므로 해당 진입점 전체 타입 통과라고 보고하지 않는다. 실제 영상은 별도 시험 진입점에서 생성했다. 현재 변경의 프로덕션 빌드·3001 반영 및 최종 브라우저 확인은 아직 수행하지 않았다.
