# 관리자 전체 사용성 점검 — 2026-10-20

대상은 `http://localhost:3001`의 관리자 PC 화면이다. 관리자 재구조화의 앞선 23개 목적지 수용과 구분해, 기존 89개 경로(고정 72·동적 17), 팝업 호출부, 18개 파이프라인을 조사했다. 1440×900과 1280×900 Chromium에서 실제 Supabase 인증을 사용한다. 인증 우회·모바일·GitHub·원격 CI는 사용하지 않는다.

## 판정 방법

- HTTP 200 외에 실제 본문, 주 메뉴 소속, 제목, 페이지 오류, 가로 넘침, 탭·도움말·키보드를 확인한다.
- 동적 경로는 실제 목록 링크와 조회로 확인한 ID를 쓴다. 고정 경로를 동적 상세로 잘못 세지 않는다. 자료 없음·의도한 운영 차단·정상 상세를 구분한다.
- 팝업은 열기, 본문 로딩, Tab, Escape, 취소, 부모 유지, 목록 조건 복귀를 확인한다. 최초부터 중첩된 창과 순차로 연 창, 작업 중 닫기 거부도 별도 회귀로 검사한다.
- 파이프라인은 화면 연결 및 기존 계약·실패·권한·재실행 검증과 실제 운영 실행을 구분한다. 실제 수집·생성·발행·삭제·납품은 실행하지 않는다.
- 자체 실행 UUID와 합성 표시를 가진 새 계정만 임시 관리자 권한으로 쓴다. 종료 시 권한 제거·정지·차단을 직접 재확인하고 이력은 보존한다. 기존 계정의 권한·비밀번호는 바꾸지 않는다.

## 로컬 검증 증거

- 최종 코드의 연관 계약: web 129파일/1,378개, library-pipeline 159파일/2,731개, video-factory 6파일/113개 — 합계 294파일/4,222개 통과, skip 0. 외부 네트워크를 차단하고 공유 DB 쓰기 테스트는 제외했다. 패키지 소스는 앞선 통과 이후 변경하지 않았다.
- 기존 실제 관리자 시나리오 최초 실행: 20개 중 18개 통과. 적용 fixture가 빈 문제와 도서 조회의 5초 기대 시간 초과를 재검증 대상으로 분류했다. 후자의 실제 별도 본문 검수/목록 복귀는 통과했다.
- 팝업 공용 회귀는 실제 React/Dialog와 Chromium을 사용한다. 테스트 DOM 라이브러리나 DB에 의존하지 않는다. Dialog 19사례와 큐 배너 응답 순서 2사례를 별도로 검사한다. 순차 중첩, Back, StrictMode, 최초 중첩, 작업 중 닫기 거부, 실제 트리거 DOM 교체, 사용자 포커스 유지, 비활성 교체 요소, 경로 이동, 닫힌 목록의 이전 이력과 검수 이동 순서, URL 기반 창의 작업 중 Back 거부와 해제를 검사한다. 여러 이력 건너뛰기·부모 이력 복구·같은 URL의 다른 상태·다른 경로의 저장된 Router tree도 격리 회귀에 포함한다. 새 이력 회귀 2개는 수정 전 둘 다 실패하고 수정 후 통과했다. 격리 Router 모델의 경계 검사와 실제 Next의 일반 Back 검사는 구분하며, 다른 문서로 떠나는 브라우저 탐색을 모두 차단한다는 뜻이 아니다. 복원 감시는 식별자를 명시한 트리거에만 적용하며 성공/상호작용/새 팝업/탐색 경계에서 끝난다. 다음 입력이나 교체가 없으면 단일 감시가 남을 수 있으므로 시간 제한이 있는 감시라고 주장하지 않는다.
- 최초 axe는 색 대비를 제외했다. 최종 화면 점검에서는 대비도 포함하고 결과를 별도로 공개한다. 최초 결과만으로 접근성 전체 통과를 주장하지 않는다.

정상 데이터가 있는 팝업과 실제 확정 후에만 생기는 응답 창은 구분한다. 아래 운영 확정 단계는 정상 계정을 변경하거나 생성 비용·데이터 삭제를 발생시키므로 실물 성공을 주장하지 않는다.

| 도서 상세·삭제/복귀 확인·수집 입력·카탈로그 상세 | 열기·본문·키보드·취소·목록 검색/선택 복원 | 수집 등록·되돌리기 확정·영구 삭제 |
| 장 단어장·장 퀴즈·기사 단어장 | 기존 분석의 팝업 본문·Tab·Escape | 새 분석/문항 생성 |
| 소스 프로필·원문 검사 | 실제 출처/원문의 조회·팝업 | 원문 재판정 적재 |
| 새 학습 기록·기존 기록 상세 | 종류·시험 선택·탭·읽기·취소 | 다른 사람의 답안 저장/기록 삭제 |

소스 프로필 검사에서 숨겨진 첫 버튼을 고른 실패는 제품 결함과 구분해 보존하고 보이는 버튼으로 다시 검사한다. 영상 요청은 실제 양성 자료가 없어 요청 상세의 정상 본문·반려/철회 실물은 미검증이며, 존재하지 않는 ID의 복귀/부정 상태를 두 너비에서 확인한다. 운영 확정 미실행은 회귀 테스트의 skip을 통과로 세는 방식으로 감추지 않는다.

최종 수정본의 영향 범위 재검증과 모든 자체 검사 계정의 정리를 완료했다. 아래 최종 기록은 이전 실패를 보존한 뒤 수정 범위와 실제 재검증을 연결한 결과다.


### r16 작업 중 Back 재현과 추가 보완

실제 Next 빌드 r16의 선행 팝업 검사는 일반 닫기 1건 통과, 작업 중 Back 1건 실패였다. 실패 후 전체 화면·전체 팝업·20개 흐름 검사를 실행하지 않았고 검사 계정은 차단했다. 보관 RPC는 브라우저에서 가로채 503으로 응답했으며 실제 보관을 수행하지 않았다. Window의 popstate 리스너는 capture 옵션만으로 기존 Next 리스너보다 먼저 실행되지 않는다. 작업 중에는 같은 상세 URL의 보호 이력을 쌓아 일반 Back에서도 선택 URL이 유지되게 보완한다. 여러 이력을 건너뛴 경우에는 소비된 부모/현재 팝업 이력을 함께 복구하여 닫기 후 목록 이전까지 되감기는 것을 방지한다. 이 보완의 최종 실제 브라우저 결과는 아래 최종 실행 기록으로 판정한다.

r17(`dpAYudpQzbD7TPSapl1tO`) 실행 `aecd06b4-067e-45a3-a1a8-7058deead1a1`의 실제 Next 선행 2사례는 모두 통과했다. 작업 중 Back 후 18초 동안 상세와 닫기 금지를 유지했고, 로컬 503 응답 뒤 오류 안내와 닫기 복구, 한 번의 Back으로 목록 복귀를 확인했다. 가로챈 POST 1건의 도서 UUID를 대조했으며 외부 RPC 전달은 0건, 기존 도서의 상태·갱신 시각은 전후 동일했다. 실패한 실행에서도 가로채기 기록을 남기도록 새 실행의 영수증 저장 시점을 요청 직전/직후와 finally로 보강했다. 격리 회귀의 통과와 실제 Next 결과를 구분한다.

### r17 초기 읽기와 화면 재마운트 경합

r17은 영향 화면 16회·팝업 31사례를 통과했지만 빠른 업무 흐름은 19/20이었다. trace에는 Enter가 정상 실행돼 선택 URL과 Dialog가 실제 존재한 뒤 추가 사용자 입력 없이 닫힌 과정이 남았다. 포커스 손실이라는 초기 추정은 폐기했다. 추가 실행 `536cb571-a681-415e-839b-a7b81b98826e`는 기본 2회와 초기 읽기 응답 보류 2회 모두 자동 닫힘을 재현했다. React commit/unmount와 History 기록에서 목록·Dialog 제거 → 팝업 cleanup의 Back → 선택 없는 URL → 새 목록 마운트를 확인했다. 이 진단의 러너 종료 0은 사용성 통과가 아니다. 계정은 자동으로 권한 회수·정지·차단했다.

책 props 동기화만 가정한 격리 모형은 기존 코드에서도 통과해 원인을 증명하지 못했으므로 채택하지 않았다. 설치된 Next의 action queue는 진행 중 Server Action에 URL 복원이 끼어들면 재갱신을 예약한다. 초기 상태 조회 4건과 8초 폴링에 사용하던 읽기 Server Action 세 종류를 관리자 GET API로 분리하고 같은 세션/RLS·필터·정렬·limit 100·응답 row를 유지한다. 적재·삭제·발행 액션과 DB는 바꾸지 않는다. 통신 실패는 빈 성공 대신 실패 결과를 반환하고, 가드/전송 회귀와 실제 빠른 열기에서 관련 초기 Server Action 요청 0건을 확인한다. 검증 전 임의 대기로 빠른 시나리오를 피하지 않는다.


r18은 컴파일·타입·lint를 통과했지만 실제 인증 재검증 전에 GET 응답 역전 경계를 추가 검사했다. 실제 DrainQueueBanner 격리 회귀 2건에서 이전 빈 응답이 새 진행 상태를 지우고, 느린 조회 중 폴링이 중복되는 것을 재현했다. 요청 세대로 최신 조회만 상태와 loading에 반영하고, 진행 중인 백그라운드 폴링은 건너뛰되 완료 후 다시 조회하도록 보완한다. 이 변경의 최종 실행 대상은 r19이며 r18을 최종 실제 수용으로 세지 않는다. 이전 빌드의 생성 타입 3,007파일은 원본 바이트를 보존한 채 앱 바깥의 로컬 검사 보관 폴더로 옮겨 중복 타입 검사를 줄였다. 앱 코드·빌드 JS·CSS·증거는 삭제하지 않았다.


r19는 컴파일 이후 타입 검사 중 실행 프로세스가 종료되어 BUILD_ID와 완료 영수증이 없다. 통과 빌드로 세지 않는다. 재개 시 이전 검사 계정 16개가 모두 닫힌 기록과 보존된 코드를 확인하고 새 실행 세대로 작업을 인수했다. 최종 빌드는 r20으로 다시 검증하며 완료 전 수용하지 않는다. 이전 3000·3001 listener도 더 이상 관찰되지 않았지만 3000의 코드·설정·환경은 변경하지 않았다.
