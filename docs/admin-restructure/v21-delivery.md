# 관리자 v2.1 구현·지원 범위

2026-10-19 · PC 웹 · [v2 설계](../admin-submenu-redesign.md) · [프로세스 분석](./pipeline-analysis.md)

## 목적과 보존 기준

메뉴 수보다 정확한 대상·기준으로 업무를 끝내고 학습자 제품까지 인계하는 데 초점을 맞췄다. 사용자 첨부 재검토 §7에 따라 v2의 근거를 재사용해 구현했다. 상위 7개·하위 22개, 기존 89개 페이지를 유지한다. 새 DB·공통 큐·Product Order 테이블·파이프라인 엔진은 만들지 않았다.

v1 구현과 v2 조사 문서·소스 스냅샷은 커밋 `ca0fd2bee`에 보존하고 작업 브랜치에 push했다. 이전의 ‘로컬 보존만’ 범위는 이번 사용자 첨부의 기능 단위 커밋·push 지시로 갱신됐다. main 병합은 이 작업에 포함하지 않는다.

v2 문서와 `submenu-plan.json`은 설계 당시 기록이다. 해당 파일의 `proposed`·`v1`·소스 해시를 현재 구현 상태로 덮어쓰지 않는다. 현재 경로·소속은 [v21-route-support.json](./v21-route-support.json), 검사는 `node scripts/admin/v21-audit.mjs --write`다. 옛 `submenu-audit.mjs`의 기본 검사는 설계 당시 코드 스냅샷에 결속돼 있으므로 이번 의도된 코드 변경 뒤에는 실패할 수 있다.

## 실제 데이터 결속과 제품 인계

### 교재

현재 체크아웃에는 canonical Product Order를 읽는 운영 reader/API가 없다. 순수 계보 계약·보류 SQL과 실제 설치·관리자 reader 연결은 다른 사실이다. 학습자 수요의 `factory_order`를 Product Order로 대신 쓰지 않았다.

| 단계 | 현재 조회/결속 | 표시·한계 |
|---|---|---|
| 제작 현황·집필·해설·글감 | 기존 공유 재고와 후보 | 선택 기준이 전달돼도 주문별 집계 아님을 표시 |
| 검수의 조판 요약 | 선택 시리즈 + 실제 `step` | 같은 단계의 다른 시리즈 혼입 차단. 전체 문항 결함 원장은 별도 집계임을 표시 |
| 발행 승인 | 선택 시리즈 + 실제 `step`의 조판 기록 | 실제 행의 series/band로 기존 승인 액션·게이트 수행. URL의 band를 승인 키로 사용하지 않음 |
| 공개/개인 납품 | 기존 공개·납품 계약 유지 | 승인·DB 발행·학습자 공개·개인 납품·실제 노출을 같은 완료 상태로 합치지 않음 |

**식별자 주의:** 기존 제작 기준 URL의 `band`는 카탈로그의 `rung.step`을 담는다. `textbook_volume_renders.band`와 다르므로 서버는 `series`와 `step`으로 조회한다. 모르는 시리즈·단계·불완전 기준은 전체 재고로 대체하지 않고 거부한다. 동일 단계라도 시리즈별 카탈로그 지원 범위가 다르다.

선택 권의 사다리 분모는 1이며 실제 선택 단계를 표시한다. 전체 문항 결함은 상단·실패 목록 모두 별도 집계임을 표시한다. 기존 외부 명령은 전체/고정 예시로 명시하고 `--series reading`을 적었다. 예시를 현재 선택 권의 실행 명령으로 생성하지 않으며, 실제 V밴드·출력 경로 확인은 기존 운영 절차를 따른다.

근거: [factory-scope.ts](../../apps/web/src/lib/admin/factory-scope.ts), [factory-line-views.ts](../../apps/web/src/lib/csat/factory-line-views.ts), [승인 액션](../../apps/web/src/app/admin/csat/press/actions.ts).

### 기출 분석→근거 검수→원리·제품

문항 상세에서 측정 역량·출제 의도·정오답 설명에 더해 기존 `passage_design`의 지문 선정 이유·구조·정답 변환을 표시한다. 분석 버전은 검수 도장으로 간주하지 않는다.

근거 검수 링크는 URLSearchParams로 문항 ID와 회차를 인코딩하고 기존 시험 집합/학년을 유지한다. 원리·제품 연결은 등록된 TASK별 `surface_ref`와 정확히 일치하는 적용만 조회한다. 초안·중단·과거 버전도 확인할 수 있고, 실제 적용 UUID의 기존 추적 상세로 이동한다. 문항 ID를 원리 slug로 추정하지 않는다. 연결 없음과 조회 실패는 별도 표시한다.

제품 추적 상세는 기존 원리 사슬·탐구 질문·근거·trial·실제 수행을 재사용한다. 연구 항목과 학습 설계의 적용 링크도 목록 대신 해당 적용 ID로 이동한다. 적용 status만으로 실제 노출 버전 일치나 학습 효과를 주장하지 않는다.

근거: [AdminItemHandoff](../../apps/web/src/components/admin/knowledge/AdminItemHandoff.tsx), [적용 reader](../../apps/web/src/lib/admin/item-applications.ts).

### 진단→목표·TASK 계획→수행·재진단

기존 학습자 상세에서 UUID·실존 계정·관리자 확인을 통과한 같은 ID로 `loadSavedPlans`를 호출한다. 저장 목표 버전, 열린 Workspace, 계획 버전·정의·기준 시각, TASK와 저장 당시 계획량을 읽는다. 목표 없음·저장 구조 미설치·조회 실패를 구분한다.

`loadMapPage`는 읽는 동안 판단 로그를 쓰므로 재사용하지 않았다. 로그인 관리자 자신의 학습자 화면에 대상 UUID query를 붙여 대리 조회하는 링크도 만들지 않았다. 일반 사용자 집계·어휘 수준은 원천별 기록이며 동일 인물 검증 없는 통합 CRM은 아니다.

수행 원장·추천 근거·재진단 비교를 같은 대상과 버전으로 잇는 관리자 reader는 아직 없다. 저장된 계획만으로 수행이나 효과를 추정하지 않는다.

근거: [학습자 상세](../../apps/web/src/app/admin/csat/diagnosis/learners/[id]/page.tsx), [AdminLearnerPlans](../../apps/web/src/components/admin/csat-diagnosis/AdminLearnerPlans.tsx), [기존 저장소](../../apps/web/src/lib/csat/map/v4/plan-store.ts).

## 실행·복구·권한

- 큐 등록/계획 등록/브라우저 반복/외부 드레인/검수·발행은 기존 주체와 게이트를 유지한다. 도서 재수집의 삭제 영향·발행 단어장/학습 진도 보호를 변경하지 않았다. 수집·드레인·발행·회수·삭제 버튼은 검증 중 실행하지 않는다.
- Compose는 DB 호출이 없는 소스 검증·발견도 있으므로 공통 db()에만 가드를 넣지 않았다. 17개 export 각각 입력 처리보다 먼저 `requireAdmin`을 실행한다. redirect가 일반 실패로 삼켜지지 않게 기존 try/catch 밖에서 호출한다.
- 기존 공통 역할 `admin|curator`와 정지·해지 차단을 재사용한다. service 권한으로 Compose 쓰기를 바꾸거나 RLS를 새로 만들지 않았다. 설치된 RLS/RPC 정의 전량을 실제 DB에서 검증했다는 뜻은 아니다.
- 기존 SQL의 역할 검사와 서버의 계정 상태 검사를 구별한다. 새 회귀는 권한 거부 시 fetch·DB·RPC·화면 재검증이 발생하지 않는지 확인한다.

## 검증 기록

- 전체 경로 정적 검사: 89/89, 상위 7·하위 22, 누락·소속 오류 0.
- 관리자·인증 집중 회귀: 61파일 911개 통과, skip 0. 기존 읽기 전용 DB 통합 조회도 포함한다. 파괴적 액션은 호출하지 않았다.
- 후속 수정 집중 회귀: 범위·선택 단계 표시·기존 화면·도움말 117개 통과(23+94, 위 911개와 중복 포함). 선택 단계 사다리 회귀 1개를 추가했다.
- PC 브라우저: 기존 11개+신규 5개 시나리오 확인, skip 0. 최초 정상 서버 실행에서 15개 통과·1개 상태 코드 단언 실패, 스트리밍 `notFound` 화면 기준으로 고쳐 해당 1개 재실행 통과. 도서 상태·레거시 링크·제작 범위·Compose/CCP 탭 복귀·홈·1440/1280 라이트/다크 접근성을 확인했다.
- 추가 읽기 검증: 실제 `2017#18` 문항의 지문 설계 주석·분석 버전 및 item/exam을 유지한 근거 검수 이동을 확인했다. 해당 문항의 등록 적용은 0개이며 조회 오류 없이 연결 없음으로 표시됐다. 제품 적용 존재·버전/상태별 reader 경계는 회귀로 확인했고 실제 제품 반영·효과는 주장하지 않는다.
- 기존 진단 학습자 상세에서 같은 대상 ID의 저장 목표 표시와 열린 Workspace 계획 없음 상태를 확인했다. 다른 사람의 수행·계획으로 대신 채우지 않았다. 계획이 존재하는 경우·저장 구조 미설치·조회 실패는 컴포넌트 회귀로 검증했다.
- 집중 소스 리뷰: Factory 3건(P2: 고정 명령 범위, 선택 분모, 전체 결함 라벨)을 수정하고 회귀를 통과했다. 기출 인계·개인 이력 분리 및 Compose 권한·학습자 대상 결속·탭 복귀 리뷰에서는 P1/P2 발견 없음. 전체 외부 시스템이나 실제 업무 효과의 검증은 아니다.
- 최종 빌드: `CIRCLE_NODE_TOTAL=3 NEXT_DIST_DIR=.next-verify-admin-v21 pnpm --filter web build` exit 0. lint·타입 검사와 정적 페이지 생성까지 통과했다. 첫 실행의 미사용 import 오류는 수정했다. 기존 lint 경고·공개 지표 읽기 timeout 경고는 남으며 미조회 수치를 성공·0건으로 보고하지 않는다.

v1의 검증 수치와 v2.1 결과를 합산해 효과를 주장하지 않는다. 브라우저는 기존 개발 전용 관리자 우회 환경이며 기출 조회는 기존 검증 계정으로 로그인해 확인했다. 익명 `csat_items_public` 조회의 권한 거부(42501)를 직접 확인했고 권한·RLS를 바꾸지 않았다. 이 실행은 프로덕션 관리자 역할·설치된 RLS 전량 검증을 대신하지 않는다. 검증 중 수집·발행·삭제·드레인 액션을 실행하지 않았다.

## 남은 Gap·다음 작업

| Gap / blocker | 현재 처리 | 다음 작업·선행 조건 |
|---|---|---|
| Product Order별 생산·납품 계보 reader 부재 | 전체 재고/선택 조판만 구분, 가짜 주문 진행률 없음 | 기존 Factory 정본 계약·현재 적용 패키지와 읽기 어댑터를 대조. 실제 lineage가 연결된 뒤 주문 작업판 활성화 |
