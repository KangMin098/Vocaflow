# 하위 메뉴 재설계안 검증 기록

2026-10-19 · [설계 본문](../admin-submenu-redesign.md)

## 범위

검증 대상은 설계·비교 문서, 경로 이행 명세와 정적 검사 스크립트다. 기존 1차안의 앱 코드를 변경하거나 파이프라인을 실행하지 않았다. DB 조회·쓰기·마이그레이션·콘텐츠 수집·발행·Git 커밋·push·PR 생성은 수행하지 않았다.

## 정적 확인

검사 명령: `node scripts/admin/submenu-audit.mjs`.

| 검사 | 결과 |
|---|---|
| 실제 관리자 페이지와 제안 명세 대조 | 89 / 89, 누락·중복 0 |
| 기존 페이지 목적지·상세·호환 연결 | 목적지 파일 존재, 원래 경로 유지 |
| 로컬 v1 소속 대조 | 실제 navigation 모듈의 판정과 일치 |
| 관찰 소스 해시 | 572개 일치 |
| 서버 액션 조사 범위 | module-level use server 24개 모듈·101개 exported 함수 선언 |
| 권한 근거의 상태 | 명시적/내부 helper 호출 83, RPC SQL 본문 1, 추가 확인 Compose 17. 실행 검증 통과율이 아님 |
| 기준 main 탐색 구조 | 그룹 7, 직접 링크 30, 자식 링크 28 |
| 로컬 v1 구조 | 상위 7, 하위 작업 공간 26 |
| v2 설계 구조 | 상위 7, 하위 작업 공간 22 |

소스 해시는 이 조사에서 관찰한 코드와 현재 파일이 일치함을 확인한다. 관찰 밖 파일의 동일성이나 배포된 worker의 가동을 검증하지 않는다. 향후 화면 구현 뒤에는 해시 검사가 실패하는 것이 정상이며, 설계 근거를 다시 조사·갱신해야 한다. 검사 통과를 위해 해시만 임의 교체하지 않는다.

## 교차 리뷰

독립 읽기 전용 Claude 계획 리뷰 1차에서 5건, 재검토에서 추가 1건을 지적했고 모두 설계·명세·guard에 반영했다. 2차 리뷰는 기존 5건의 해소를 확인했다. 3차는 남은 권한 모듈 누락과 수치·분류의 수정 확인에 한정해 `NO_FINDINGS`를 받았다. 24모듈·101함수·83/1/17 분류와 수집 범위를 소스에서 다시 대조했다. 이 결과는 설계의 해당 지적 해소이며 production 권한·새 화면의 동작 검증은 아니다.

| 지적 | 반영 |
|---|---|
| P2 기출 첫 화면도 관리자 개인 이력을 조회 | `/admin/kice` 내 기록 칩까지 공용 분석 분리 범위에 포함 |
| P2 기존 메뉴 소속의 추정값 미표시·미검사 | 직접 링크/URL 접두사 추정을 구별하고 기준 HEAD와 대조 |
| P2 액션별 권한 근거 부재 | 권한 경계표·함수별 JSON, RPC SQL 근거와 실제 배포 미확인 구분 |
| P3 제작 공정 진입점의 상세 분류 혼재 | `/admin/csat/new`를 진입 유지로 정리, 공간 진입의 detail 오분류 검사 |
| P3 alias의 query/hash 미검사 | 실제 redirect/adminCompatibilityHref 목적지를 AST로 대조 |
| P2 파일명이 actions.ts인 모듈만 조사 | use server 지시문으로 수집. vnext-actions와 VCB 13모듈 포함, 24모듈·101함수 확인 |

정적 검사에는 실제 페이지 누락·중복, 없는 목적지, 잘못된 소속, 구현 상태 허위 표시, 원래 소속 오류, 추정값 미표시, alias query 불일치, 진입점 상세 오분류, 낡은 소스 해시, vnext 모듈 누락, 권한 근거 해시 변경의 **12가지 잘못된 명세를 넣어 실패하는지** 확인했다. 모두 실패했고 원본 명세 복원 후 정상 통과했다. 본문·분석·권한 경계·검증·이행표·v1 기록의 상대 링크 96개는 깨진 링크 0개다. `node --check`와 `git diff --check`도 통과했다.

저장소의 `agents/scripts/review.mjs`는 현재 `--plan` 처리 없이 Git 커밋 diff를 읽는다. 이번 산출물은 사용자 지시로 미커밋 상태이므로 목적 파일·설계·분석·경로 JSON·guard를 직접 지정한 Claude CLI 읽기 전용 리뷰를 사용한다. 허용 도구는 Read/Grep/Glob, DB·명령 실행·편집은 허용하지 않는다.

## 한계

실제 v2 화면·데이터 어댑터는 미구현이다. 따라서 새 화면의 lint·타입·빌드·사용성·브라우저 회귀·생산 실행 성공을 검증했다고 주장하지 않는다. 기존 v1 검증은 [1차 구현 기록](../admin-restructure.md)에 별도로 있다. 실제 적용 단계의 수용 시나리오는 설계 본문 §8을 따른다.
