# 3 — 기존 소량 제작물을 선택·편집·재검수하는 FAST 경로

2F의 실제 공급 호출부와 AI 검증에 따른 판본 수정 뒤 확정. 기존 1B 패킷과 출력·1C 검수/원천 판정·HTML 렌더러를 재사용한다. 최초 범위는 동일 원천의 중심 의미 3문항 팩이다. 새20제품군·새 LLM API·콘텐츠 대량 수집을 추가하지 않는다. 사용자의 사람 대체 지침에 따라 Codex 교사 역할의 실제 선택/편집과 독립 Claude 검수로 검증한다.

## 제품 흐름

기존 공장 `새 교재 만들기`에서 PC3B `빠른 학습지`로 진입한다. 하나의 기존 제작 팩을 가져와 원문·문항·근거를 확인 → 문항 순서·발문·선지 편집 → 필수 검수 확인 → 학생용 문제지와 교사용 해설지를 내려받는다. 초기 화면에서 지원 범위/문항 수/초안 상태를 정확히 표시한다. 입력은 한 묶음 JSON으로 운반하고 CLI가 기존 packet/output/review 파일에서 묶음을 만들 수 있게 한다. 없는 저장소 조회를 가짜 재고 목록으로 대체하지 않는다.

- 원문·원천 정책·TASK·역할·주문 수량/계보는 편집하지 않는다. 원래3문항 팩의 수량을 몰래2로 바꾸지 않는다. 새 수량은 새 주문 대상이라는 명시적 오류를 준다.
- 문항 편집과 순서 변경은 새 출력 바이트/문항 해시를 만든다. 원본은 보존하고 새 판본을 기록한다. 작성자·편집 기록을 구별하고 AI가 수행하지 않은 검토를 모델 이름으로 채우지 않는다.
- 편집 전 검수는 새 바이트에 상속되지 않는다. 실제 새 검수 대상 패킷/프롬프트를 내려받고, 지금 실행 중인 Claude/Codex가 **신규 세션**에서 채운 검수 JSON을 가져오는 드레인 흐름을 사용한다. 서버에서 LLM 키를 기다리거나 검수를 자동 pass 하지 않는다.
- 기존 `checkPacketIntegrity`/`validateOutput`/`checkReview`/`checkSource`/`evaluateSource`와 출처·권리 제한을 재사용한다. 원천 현재 확인은 관리자 API에서 현재 DB 행을 읽는다. 원천·본문/정책 digest 불일치, 검수 대상 불일치, 정답 중복·없는 인용·개인정보·삽입 HTML 등을 차단한다. 미상 축은 미상으로 남긴다.
- 기존 자료 재사용에서는 동적인 `has_items`만 달라져도 기존 전체 source_digest가 바뀐다는 한계가 있다. 원본 source_snapshot을 묶음에 포함해 그 digest가 원래 패킷과 일치하는지 검증하고, 현재 원천을 실제로 재판정한다. 필요하면 기존 source binding facts를 공용 순수 함수로 추출해 **has_items만 제외한 나머지 전체 결속 값**을 비교한다. 재고 사실만 달라졌고 현재 적격인 경우에만 로컬 재사용을 허용하며 두 관측을 그대로 기록한다. 실제 값/패킷 해시를 위조하지 않고, 1C 입고의 기존 엄격한 규칙은 바꾸지 않는다. 본문/라이선스/게이트 등 다른 값이 바뀌면 반드시 거절한다. 이를 반례로 잠근다.
- FAST 내용 검수와 전체 FQ/출시/납품을 구별한다. 파일 출력은 로컬 검수/AI 검증 후보이며 권리·출시·등록을 위조하지 않는다. 승인되지 않은 자료에 승인 배지를 붙이지 않는다. 부족한 권한/축은 구체적 이유를 표시한다. 실제 출시가 필요한 행위는 기존 승인·공급 경로를 사용한다.
- 문제지에는 정답/Gold/검수 원본을 넣지 않는다. 해설지는 관리자 전용 응답에서만 만든다. 기존 HTML escape/CSP를 유지하고 미리보기 iframe은 sandbox를 사용한다. JSON 입력/출력만으로 XSS가 실행되지 않게 한다.

## 구현 범위

순수 FAST 검증/편집/렌더 helper, 인증된 admin API(preview/export; DB 쓰기 없음), 기존 새 교재 페이지에서 연결된 실제 편집 화면, 재실행 안전 CLI(bundle/verify/export), 실제 앱 CSS 브라우저 하네스가 필요하다. UI에서 쓰지 않는 helper만 추가하지 않는다. 신규 AdminScreenHelp 항목과 실제 버튼 순서/검수 재실행·복구 절차를 같이 고친다. 코드 로직은 시각을 주입하고 실제 속도 기록은 외곽 실행기에서 측정한다.

기존 `recordAiReviewedSupply` 관리자 API는 2A에서 실제 호출 경계가 있으므로 중복 등록 체계를 만들지 않는다. FAST DCP 편집을 authored로 등록하거나 원래 DEEP 교수 순서를 바꾸지 않는다. 같은 source/type 슬롯의 구판 DCP를 덮어쓰지 않는다. FAST 파일 판본과 DB 공급 판본은 별개이며 잘못된 연결은 차단한다.

## 수용 시험

1. 실제1B 제작 파일을 가져와 원문/정책 확인, 3문항 재배치, 발문 수정, 저장/새로 열기, 이전 검수 거절, 신규 독립 검수 수락, 문제지/해설지/manifest 출력까지 실제 제품 호출부를 실행한다. 출력 해시·편집 diff·검수 세션·원천 판본을 남긴다.
2. Codex 교사 선택 `01a15de1-34d4-7250-8dbe-2132827d1b7b`: topic→main_point→title, main_point 발문을 `다음 글의 중심 생각으로 가장 적절한 것은?`로 수정. runtime의 선택/편집 파일은 준비 자료다. **실제 앱이 만든 바이트가 다르면 준비 검수 해시를 맞추도록 코드를 바꾸지 말고 그 실제 바이트를 신규 세션에서 다시 검수한다.**
3. 편집 후 옛 검수, source 변경, 불일치 주문, 변조 키/금지 필드, 원문 없는 인용, 미검수 출력, 요청 실패/동일 재시도/기존 파일 충돌/부분 쓰기 실패를 반례로 확인한다. 실제 렌더 결과를 PC1440 브라우저에서 눈으로 확인한다.
4. 실제 작업 회차의 CLI·AI 선택/검수·브라우저 시간과 실패 이유를 분리해 기록한다. 이를 사람 교사 절약 시간이나 시중 제품 우위로 변환하지 않는다. 비교 가능한 상용 실행 자료가 없으면 비교 미실행으로 남긴다.
5. 관련 기능·API·CLI·브라우저 시험, web/scripts 타입·lint. 새 스크립트는 tsconfig.scripts에 포함. Admin 도움말·ROUTES/ADMIN_CONSOLE/MODULES/CHANGELOG/로드맵·03 결과 동반. <30파일의 일관된 범위. 공유 DB 쓰기·발행·배포 없음.

이 결과 다음에는 전체 브랜치 빌드/종단 수용 확인과 SQL 적용 승인 패키지를 정리한다. 원문 라이선스 관측은 외부 권리 부여가 아니다. 실제 사람 검증을 대기로 남기지 않는다.
