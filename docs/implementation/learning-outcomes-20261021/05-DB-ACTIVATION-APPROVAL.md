## 검증·실패·복구

결합 SQL 설치와 실제 서비스/계획 POST는 격리 PGlite에서 검증했다. 별도 DATA SQL 5개는 정확한 두 설명 수정/복구, 기존 시도 보존, 두 번째 행 변경 시 전체 롤백, 원문 변경·기존 자격/입고 차단을 확인했다. 공유 Supabase 실행·실 RLS/두 연결 경쟁은 **NOT_RUN**이다.

SQL은 먼저 기존 핵심 함수 6개의 본문 SHA와 신규 표 부재를 검사한다. 모든 단계가 한 트랜잭션이므로 중간 오류는 전체 롤백한다. 적용 전 DB checkpoint를 확보하고, 적용 뒤 표·RLS·권한·함수와 기존 행 수·두 해설 외 불변성을 읽기 검증한다. [두 해설 복구 SQL](../../../supabase/deploy/learning-outcomes-20261021/rationale-correction-rollback.sql)은 **자격/입고 전**에만 사용할 수 있으며 실제 복구도 별도 승인을 받는다. 기록이 생긴 뒤에는 원장을 지우지 않고 새 쓰기 진입을 중지한 뒤 별도 복구안을 확정한다.

## 설치 후 남는 작업

이 승인으로 콘텐츠 발행·실 학습자 계정 조작·합성 생산 패킷의 계보 승격을 묶어 승인받지 않는다. 현재 제작 패킷은 합성 계보다. 실제 현재 목표/계획/주문으로 새 패킷을 만들고 새 바이트에 검수를 결속해야 등록·자격·관리자 승인·수령이 가능하다. 미적용 수정안 검수도 현재 행 재조회가 일치한 뒤에만 사용할 수 있다. 창작 8문항 등록·AI 결정·자격·공개 평가 승인 역시 실제 관리자 API와 별도 데이터 범위를 확정해 수행한다.

사람 검증 대기는 없다. 소프트웨어 경로와 AI 역할 검증 결과는 분리하며, 전이 천장으로 판정 불가였던 비교를 실제 학생의 인과효과·장기 기억·전체 R0 출시로 보고하지 않는다.
