# Claude Code·Codex 검증 역할 계약

근거: 2026-10-21 사용자 지시. 실제 사람에게 배정하던 학습자 수행·교수 적합성 검수·채점·사용성 확인·결과 분석을 모두 두 AI가 맡는다. 사람 모집과 사람 검수를 기다리지 않는다.

| 역할 | 최초 담당 | 독립 확인 | 실제 수행과 증거 |
|---|---|---|---|
| 구현·활동 제작 | Claude Code 새 세션 | Codex | 제품 호출부, diff, 타입/단위/통합/브라우저 로그 |
| 교수설계·문항 검수 | Codex | 별도 Claude 세션 | 목표-활동-응답-평가 정렬, 의미 왜곡, 정오답 근거, 대안 정답 검토 |
| 가상 학습자 A/B | 별도 Claude 세션과 별도 Codex 세션 | 서로의 실행 기록 | 학습자 입력·학습 활동·답안·도움·노출·시간·콘텐츠 hash |
| 독립 채점 | 답안을 만들지 않은 모델 | 반대 모델의 별도 세션 | 고정 루브릭 항목별 점수·근거; 조건 A/B와 생성 모델 라벨을 숨긴다 |
| 반례·보안·데이터 결속 | Codex | Claude 수정 후 재시험 | 타인·구버전·중복·누출·철회·실패 회복의 양성/음성 대조 |
| 효과 분석·개선 | Codex | Claude 재계산 | 같은 평가 기회 기준 비교, 결측·누출 제외 사유, 수정 전후 결과 |

## 가상 학습자 실행

- 학습자의 수준 역할은 초급/중간/숙련의 명시된 입력 제약으로 정한다. 역할은 실제 학생의 인지 상태를 재현했다고 간주하지 않는다.
- A는 같은 목표의 문제풀이·해설·오답 복습, B는 원리 시범·자기 설명·구조 재구성·적용 활동이다. 학습자가 받는 지문/활동/평가 기회와 토큰·행동 예산을 사전에 기록한다. 모델 응답 시간은 사람 학습시간과 구분한다.
- 구현자/문항 작성자의 현재 대화를 학습자 역할로 전환하지 않는다. 모델별로 신규 독립 세션을 만들고 학습자에게 필요한 입력만 전달한다. 정답·루브릭·평가 후 해설·다른 조건 결과는 숨긴다.
- 사전·학습·사후·전이 지문을 ID와 정규화 본문 hash로 분리한다. 동일 본문의 이름만 바꾼 것을 신규 전이로 세지 않는다. 유사 지문·같은 원천의 중복은 별도 검수한다.
- ‘미노출’은 이번 실행의 입력·세션 노출 원장 기준이다. 기반 모델의 사전학습에서 지문을 봤는지는 확인할 수 없다.
- 지연 평가를 실제 날짜 경과 없이 실행하면 SIMULATED_DELAY로 기록한다. 2~4주를 실제로 관측했다고 기록하지 않는다.

## 채점·비교

- 출력 전에 루브릭과 분석 계획을 고정한다. 정답 여부와 근거 설명·관계 재구성·조건/범위 구분을 나눠 채점한다.
- 동일 답안을 두 모델이 독립 채점하고 불일치 항목과 이유를 보존한다. 사후에 평균을 맞추거나 반대 의견을 지워 합의 점수를 만들지 않는다. 기준 변경이 필요하면 새 판으로 재채점한다.
- QA/시뮬레이션/실사용 계정을 분리한다. AI 합성 기록을 제품의 실제 학습자 성과 통계에 넣지 않는다.
- PASS는 기능/교수 정렬/AI 수행/교차 채점 등 명시된 범위만 뜻한다. 근거 없는 사람의 향상·등급·인과효과·상용 제품 대비 우월성을 주장하지 않는다.
- 비교 결과가 없거나 개선이 관찰되지 않으면 그대로 기록한다. 어느 조건이든 미리 우승으로 정하지 않는다.
- 실패가 확인되면 같은 작업에서 원인·영향을 확인하고 활동 또는 공급/채점 규칙을 수정한 뒤 재시험한다. 변경 전 결과도 보존한다.

## 승인·권한

검증 역할의 AI 대체는 사용자의 DB/삭제/migration 적용/main merge/배포 승인을 대신하지 않는다. 기존 권리 근거와 등록된 승인자를 AI가 임의 발급하지 않는다. AI 검수 의견은 검수 의견으로 기록하고, 기술적 자격 레지스트리의 승인·서명·철회 검사를 우회하지 않는다.
