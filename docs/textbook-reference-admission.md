# Open-reference and multi-grade benchmark admission

The existing `frym-benchmark/2` selection and admission remains the sealed, single-grade commercial-textbook path. It must not be relabeled as an open-reference or multi-grade cohort.

`scripts/textbook/frym-benchmark/reference-admission.mjs` provides a separate file-backed reference contract. A sealed selection rule names one cohort, an inventory hash, the nine-axis codebook and full measurement-contract hashes, a deterministic seed, and a maximum sample count. Screening binds candidate IDs, original `grade_scope`, file and content hashes, and reviewed evidence; files without an eligible passage remain in a separate held-file list with reasons. A file cannot be both held and eligible. The manifest must match independent hash ranking of eligible candidates. Altering any link makes admission fail.

Admission re-reads the external source file, verifies its hash, checks separately reviewed edition, grade scope, passage/item boundaries and analysis rights, and binds the nine-axis analysis to the same passage and item set. For an open reference, rights review must cover both the passage and items, record a compatible license and URL, and explicitly rule out third-party exceptions. A curriculum-wide license alone does not establish rights for a particular embedded text. The returned receipt contains hashes and identifiers, not textbook text. The reference row retains `single_grade`, `grade_range` or `multi_grade` as supplied; it never coerces a range to one grade.

`evaluateAdmittedMultiGradeBenchmark` re-admits each file-backed bundle and compares the result with the supplied receipt/reference before evaluation. The multi-grade contract must explicitly name `reference_cohort`; open and commercial references cannot be combined. A single accepted reference does not meet the minimum reference counts or create a defensible grade distribution. Open-reference comparisons must be reported as open-reference results, never as commercial-market estimates.

The create-only CLI is `node scripts/textbook/frym-benchmark/reference-admit.mjs <rules> <screening> <manifest> <external-bundle> <new-receipt-output>`. Keep the bundle (including extracted passage, items, and local source path) outside the repository. The CLI re-reads it and writes only receipt/reference metadata. Re-running with the same output path fails; to change evidence, create a new screening and manifest revision and a new output path. This is an admission adapter, not a license adjudicator: reviewers must verify actual edition, scope, rights, and passage/item evidence before setting the reviewed fields. The rule seal and manifest hashes must be preserved as preregistration artifacts before nine-axis review.
