## 0. 결론 요약

1. **10/10 은 원래 목표의 완료 기준이 아니었다.** 저장소에 정의가 없다. 대화 중 이 세션이 만든 기준이다. 실제로 확인된 것은 **한 원리(주장과 근거, 글 구조 단계) · 한 과제 경로**의 기능 연결뿐이다.
2. 원래 목표(`LEARNING_MAP_VNEXT.md` rev2.1 · 2026-10-04 사용자 승인)는 6축(V·S·R·E·L·X) × 읽기 길 7단계(LP1–7) + 듣기 4단계 · 학년별 권장 노출(초등 고학년~고등) · FIND→REPAIR→TRANSFER→CHECK 생애주기다. 이 기준으로 보면 **실행 경로가 있는 칸은 7+4 단계 중 1단계(글 구조)뿐이고, 부분 경로(확인 과제만 · 노출 대기)가 1단계(문장 관계) 더 있다.**
3. **진단은 전부 `rule_proxy`(유형 기본값 상속)다.** `verified_diagnosis` 를 만드는 경로가 코드에 없다. 그래서 처방 생애주기는 FIND 에서 멈춘다. REPAIR · TRANSFER · CHECK 가 열리지 않는다.
4. **확인 과제 · Practice 결과는 지도 단계 상태와 진단에 들어가지 않는다.** 결과 줄과 문구에만 보인다. 「재평가」는 새 기출 기록으로 가는 **링크**일 뿐이다.
5. **수요가 0이다.** 새 학습 기록(sessions · attempts · first_attempts)은 0행이다. 실제 진단 사용자는 1명(세션 2)이다. 효과 검증 12건은 모두 planned 이고, efficacy 는 157개 항목 전부 not_assessed 다.
6. **학년 지원은 사실상 고교 수능 영어 전용이다.** 초등 · 중등 기출 · 진단 데이터는 없고, 학습자 학년은 저장되지 않는다(`csat_dx_profile_hist` 0행).

## H. Codex 독립 검토 반영 — 정정 · 보강(2026-10-09)

Codex 독립 검토가 11건을 지적했다(높음 3 · 중간 7 · 낮음 1). 정본과 코드를 직접 대조해 모두 반영했다.

**정정(위 본문에 반영했거나, 판정을 다시 읽는 방법)**

1. **「vNext 미이관」 판정을 정정한다.** 정본은 축과 LP 를 다른 층으로 둔다. Phase 1 은 단계 상태를 축에서 빌리고, 기존 계산을 유지하도록 명시했다(VNEXT :12 · :153 · :655–656). 단계별 과제 묶음도 이미 다르다(learner-path.ts:39–46).
   - 그래서 A 표의 「데이터 체계 미이관」과 E4 · E10 은 **결함이 아니라 승인된 단계적 설계**다.
   - 남는 질문은 「Phase 2 에서 단계를 언제 · 무엇으로 가를지」다(정책 제안).
2. **「문장 의미는 S 에 합쳐짐」은 결함이 아니다.** 정본의 S 는 구조로 명제를 만드는 처리이고, S-O1 은 통합 관찰이다(VNEXT :41 · :88–93 · :174).
   - E6 은 갭이 아니라 요청자 표기(여섯 층위)와 정본 사이의 **용어 차이**로 다시 분류한다.
3. **「목표가 먼저 할 일 선택에 쓰이지 않음」(E9)은 미충족이 아니다.** 목표 중심 재설계가 기존 routing 을 유지하고, 목표와 단계의 관계는 문항 · 배점 사실로만 보이도록 정했다(VNEXT :674 · :682 · :684). → 새 **정책 제안**으로 옮긴다.
4. **Practice 전이를 고친다.** 주제 · 제목 전이(골격 문항)는 관리자 미리보기에서만 나온다. 학생용 Practice 는 20번 주석 문항뿐이다.
   - 지도 결과 환류의 「다른 지문 적용」은 확인 문항 밖에서 같은 과제를 수행한 것을 센다. 그래서 정식 전이(TRANSFER) 경로를 증명하지 않는다.
   - B-1 의 「글 구조 Practice ✓」를 △ 로 내린다.
5. **확인 문항 수를 고친다.** 실행 가능한 주석 레지스트리는 9개다. DB 적용 행 10개와 다르다(claim-support.ts:55–65).
6. **D 표 판정 조건을 고친다.**
   - coverage 는 「본 배점 / 전체 배점」이다.
   - 순위 보류는 세 조건 중 **하나**만 해당해도 일어난다. 경쟁 축이 없으면 provisional 로 남는다.

**누락 보강(새 갭)**

- **E13. 원인 확정의 단위 계약.** 정본은 세 상태를 단위별로 나눈다(VNEXT :244–253 · :285–288).
  - `cause_adjudicated`: attempt × 원인 · 사람 검수
  - `cause_confirmed`: student × axis · 누적 8조건 · Diagnostic Priority Signal
  - `verified_diagnosis`: 직접 진단 · 설계 미정
  - FIND 의 `confirmed_need`(find-outcome.ts:25 · :71–73)는 이 셋 어느 것과도 같지 않다. E1 의 설계는 이 세 단위를 지켜야 한다.
- **E14. Evidence Anchor · 원문 결속.** 세부 태깅 전 전제로 정본이 요구하는 것이 있다(VNEXT :439–458 · :479–492 · :535).
  - 원문 정체성 · 해시
  - 유일한 좌표(unit_id 또는 신뢰 문자 범위)
  - 후보 → 검증 → 사람 검수 승격
  - 지금 과제의 골격 서명은 문장 길이만 해시한다(claim-support.ts:71–74). 그래서 이 계약을 충족하지 않는다.
- **E15. 과제 안 7단계 분석 Protocol.** REPAIR 의 정본 정의는 Sentence Meaning → … → Distortion 으로 다시 처리하는 것이다(VNEXT :324–333 · prescription.ts:12–16). 생애주기 단계가 열렸는지만으로 완료를 판정할 수 없다.
- **E16. X 정의 불일치.** 정본은 처리 속도를 X 에서 빼고 V · S · R · E 의 가로 측정 차원으로 옮겼다(VNEXT :145 · :163–167). 그런데 코드의 X 설명에는 아직 「처리 속도」가 있다(core.ts:40). X 실행 근거 모델은 승인된 보류 조건(VNEXT :530)에 묶여 있다.
