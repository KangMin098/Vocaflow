## 4. 미착수 — 그리고 이 감사가 틀렸던 곳

### 4-0. 이 감사가 **세 번** 틀렸다 (전부 정정함)

| 무엇 | 왜 틀렸나 | 지금 |
|---|---|---|
| ④ 소재를 「통과」로 적었다 | 눈금(4/4)만 읽고 `state()` 가 주입하는 「못 잼」을 셈에 안 넣었다. 화면을 본 쪽이 옳았다 | **「못 잼」으로 정정 → 그 뒤 A 로 실제 해소** |
| ⑦ L3 를 「19/19」로 적었다 | SQL `jsonb is not null` 이 **JSON 의 `null` 을 「있음」으로 센다.** 앱은 JS 로 읽어 3건을 없는 것으로 센다 | **「16/19」로 정정** |
| 「현황판에 도움말이 없다」 | 키를 `^  '이름':` 로만 훑는 정규식이 **따옴표 없는** `csat:` 를 못 봤다 | **결함 아님 — 취소 (§4-3)** |

계측 규칙은 그 전에도 두 번 틀렸다(`writeFileSync` 를 DB 쓰기로 셈 13→0 · 블라인드 평가 세트를
드레인으로 셈 19→11). **다섯 번 모두 코드가 아니라 자가 틀렸다.**

교훈 셋을 자에 박았다:
1. **판정은 `state()`/`judgeStage` 를 태워서 낸다** — 눈금을 직접 읽으면 주입된 「못 잼」을 놓친다.
2. **SQL 로 앱 수치를 검증할 때 `jsonb_typeof(x) <> 'null'`** — `is not null` 은 JSON null 을 「있음」으로 센다.
3. **「없다」고 말하기 전에 정본을 실행해서 확인한다** — 정규식으로 센 「없음」은 대개 정규식이 없는 것이다.

### 4-1. 해소한 것 — A (④ 게이트 라벨 정합)

`factory-model.ts` 의 `gateGauges` 가 「게이트가 있는 밴드 중 지문 보유」인데 `factory.ts` 가 내는
라벨은 「지문으로 채우는 밴드 중 재고 보유」였다. 이름이 안 맞으면 `state()` 가 「못 잼」 눈금을
꽂도록 돼 있으므로, ④는 **재고 87,556편을 두고 「못 잼」**으로 서 있었다.

**어느 이름이 옳은지는 물어보지 않고 git 이력으로 답했다:**

| 커밋 | 날짜 | 무엇 |
|---|---|---|
| `f8ef73af` | 2026-09-06 | 게이트와 눈금을 **이름으로 묶는** 장치를 넣으며 옛 라벨로 `gateGauges` 를 적었다 |
| `5982ac67` | 2026-09-15 | ④의 셈법을 **게이트의 `metric` 에 맡기도록** 바꾸며 `factory.ts` 라벨을 고쳤다. 커밋 본문이 이유를 적고 있다 — S5 의 합격선은 `listening` 하나뿐이라 **지문을 수확해서 채우는 칸이 아닌데** 옛 셈법이 그 칸을 늘 빨갛게 세웠다 |

즉 **나중 것이 의도된 변경**이고 `factory-model.ts` 만 안 따라갔다. `gate` 문장도 함께 맞췄다 —
문장만 옛 뜻으로 두면 눈금과 다시 따로 놀고, 그 어긋남을 잡는 장치는 **이름**뿐이라 문장은 아무도 안 본다.

결과: `factory-model.test.ts` **56/56 통과**(실패하던 회귀가 초록) · ④ `unmeasured` → `pass`.
