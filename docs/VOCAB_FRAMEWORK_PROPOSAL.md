# 단어 학습 프레임워크 — 설계 방안 (제안)

> **상태: 미승인 제안.** 이 문서는 사실 기술이 아니라 **설계안**이다. 다른 `docs/*.md` 와 달리
> 아직 구현되지 않은 내용을 담고 있으므로, 승인 전에는 이 문서를 근거로 코드를 쓰지 않는다.
> 작성 2026-08-11 · 근거: 읽기 전용 조사 6갈래 144건 (코드·DB 실측 + 이론 + 국내외 서비스).

## 0. 한 장 요약

문제는 "메뉴가 많다" 가 아니다. **활동(모드)이 최상위 메뉴에 올라가 있다**는 것이다.
Flashcard · WordBlitz · PairFlip · SpellForge · Game Lab · ScriptQuiz · Dictation 은
"무엇을 배우는가" 가 아니라 "어떻게 연습하는가" 인데, 지금 사이드바의 리프로 서 있다.
그래서 새 게임을 만들 때마다 메뉴가 늘거나(Game Lab), 어디에도 못 들어간다(EchoMatch).

조사한 국외 12종이 **독립적으로 같은 답**에 도달했다 — 콘텐츠(무엇을) × 모드(어떻게)를
직교 분리하고 **메뉴에는 콘텐츠 축만 노출**한다. Quizlet·Blooket·Kahoot 셋 다
"세트 선택 → 모드 선택" 이고, Duolingo·Rosetta 는 활동 유형을 **경로 노드 타입**으로 섞는다.

제안하는 것은 세 가지다.

| # | 제안 | 지금 |
|---|---|---|
| ① | **축 3개 분리** — 콘텐츠(메뉴) × 면(무엇을 아는가) × 단계(어디까지) | 축이 없다. 활동 이름이 곧 메뉴 |
| ② | **활동 레지스트리 하나** — 활동당 정식명 1개 · 면 · 아키타입 · 콘텐츠 요구 · FSRS 기여 | 내비 표면 **9곳**이 각자 목록·라벨을 갖는다 |
| ③ | **콘텐츠 다형 계약** `content_ref{type,id,chapter}` | 유형 추가 비용이 **7곳**에 흩어짐 |

이행은 화면을 바꾸는 것부터 하지 않는다. Memrise 가 courses→scenarios 전환에서 배운 것은
**구조 변경 비용이 UI 가 아니라 데이터·신뢰에서 발생한다**는 것이다. 그래서 Phase 0 은
화면 변경 0 — 이름과 레지스트리만 정한다.

## 1. 왜 지금 상태가 되었나 (실측)

사용자 진단("지속적인 개발·개선·추가로 현 상태")이 코드에서 그대로 확인된다.

### 1.1 같은 것을 부르는 이름이 표면마다 다르다

**라벨 세트 7종이 공존한다** — 사이드바(영문) · hub ModuleCard(한영 혼용) · ModePills ·
VocabSetPreviewModal · SessionFrame select · PLAN_ACTIVITIES · FlowNav 단계.
이름 충돌 5개는 화면 배치만 바꿔서는 해소되지 않는다:

| 충돌 | 뜻 A | 뜻 B |
|---|---|---|
| **따라읽기** | ModePills `?mode=shadow` 인라인 따라읽기 | hub 처방 → `/text/[id]/echo` (EchoMatch). `/plan` 은 같은 것을 "따라하기" |
| **스크립트** | 내가 등록한 텍스트(`/text`) | Library 탭의 ACP 큐레이션 아티클(`/library/scripts`). hub 는 또 `/text` |
| **단어장** | 내 단어(`/wordvault`) | 공용 세트(`/library/vocab`) |
| **레벨** | V-Level 0-11 | 아케이드 localStorage Lv |
| **Streak** | DB streak | 아케이드 localStorage streak |

`/my/texts` 는 같은 컴포넌트를 "TextVault" 라는 **여덟 번째 이름**으로 렌더한다.

### 1.2 모듈과 게임의 경계가 이미 무너졌다

- **WordBlitz 는 양쪽 소속** — 사이드바 Practice 의 독립 항목이면서, `/arcade` 안에서는
  'Rapid Recall' 계열 카드의 'Classic' 모드로 접혀 있다.
- 계열 접기 때문에 **4개 게임 이름이 `/arcade` 화면에 아예 없다**(WordBlitz · Ghost Race ·
  Word Economy · Daily Blitz). 사이드바에서 'WordBlitz' 를 본 학습자가 Game Lab 안에서
  이름으로 찾을 수 없다.
- **EchoMatch 는 어느 메뉴에도 없다.** 진입 경로 2개뿐이고 둘 다 'EchoMatch' 라는 이름을
  쓰지 않는다.
- PairFlip 은 아케이드 카탈로그에 없고, SpellForge 의 ModePills 는 `/spellforge` 로 가지 않고
  워크스페이스 내부에서 같은 컴포넌트를 다시 렌더한다.

**판단**: "9모듈 + 아케이드 19종" 이분법은 코드 실태와 맞지 않는다. 유지할 근거가 없다면 버려야 한다.

### 1.3 "다음에 할 것" 을 말하는 표면이 7개이고 서로를 무효화한다

| 표면 | 근거 |
|---|---|
| FlowNav 추천 | **하드코딩 mock** — 모든 학습자에게 항상 Practice(87%) · "거의 다 왔어요 13%만 더!" |
| hub 오늘 | `prescribe_today` RPC (유일한 개인화 정본) |
| arcade Today's Experiment | `pickDailyGame` — **사용자 상태 미사용**(`void vocabCount`), KST 날짜 % 18 |
| WordVault 추천 세트 | `recommend_word_sets_for_user` RPC |
| Flashcard·SpellForge 허브 TodayQueue | **mock 상수** |
| PairFlipNextActionCard | 정확도 분기 |
| Dashboard MemoryStatus CTA | `/flashcard` 고정 |

FlowNav 의 `/text/1` 링크는 uuid 체계에서 **존재하지 않는 경로**다.

### 1.4 모바일에는 전역 내비가 없다

사이드바는 `hidden md:flex` 이고 모바일 하단 탭이 없다. 모바일에서 `/hub` · `/dashboard` ·
`/arcade` · `/pairflip` · `/spellforge` · `/settings` 로 가는 전역 링크가 **하나도 없다**.
데스크톱 사이드바를 다듬는 방식으로는 모바일 IA 가 생기지 않는다.

### 1.5 콘텐츠 결합이 침묵으로 끊긴다

- 공용 세트의 단어와 학습자 `vocabularies` 가 **75.7~99.7% 어긋난다**. 예외가 아니라 정상 상태다.
  그런데 `recordGameResult` 는 없는 단어를 `{ok:true, updated:false}` 로 **성공 반환**한다.
- `scores` 에 콘텐츠 참조가 `text_id` 하나뿐이고 **48행 전부 NULL** — "어떤 도서/챕터/세트를
  학습했나" 를 **어떤 쿼리로도 답할 수 없다**.
- ScriptQuiz · Dictation 이 FSRS 에 **0행**을 쓴다. "본문 기반 모듈 = 최상위 인출(L5/L6)" 이라는
  학습 모델과 정면 충돌한다.
- 설계된 19종 중 **5종은 `learning_records` 실측 0건**(connections · letter-forge ·
  lexicon-hands · lexicon-detective · word-orrery).
- `word_familiarity` 테이블이 **부재**해 학습자 스크립트 추출과 알아요/몰라요가 런타임 실패 중이다.

## 2. 설계 축 3개

프레임워크의 뼈대는 축을 분리하는 것이다. 지금은 활동 이름이 축을 대신하고 있다.

```
        콘텐츠 (무엇을)          ← 메뉴에 노출되는 유일한 축
   도서 · 스크립트 · 공용 세트 · 짧은 글 · 만화 · 내 단어
                  ×
        면 (무엇을 아는가)        ← 처방·진행률의 축. 메뉴에 없음
   형태-의미 재인 / 철자 생산 / 청각 / 형태·어원 / 문맥·연어 / 유창성
                  ×
        단계 (어디까지)          ← 단어 하나의 상태 기계
   S0 만남 → S1 인식 → S2 인출 → S3 사용 → S4 자동화
```

활동(Flashcard · Cascade · SpellForge …)은 **축이 아니다.** 축의 한 칸을 채우는 수단이다.
이 구분이 이 제안의 핵심이다.

### 2.1 면(facet) — Nation 18칸을 6면으로 축소

Nation 의 "무엇을 아는 것이 단어를 아는 것인가" 는 9면 × 수용/생산 = 18칸이다. 전부 다루려는
설계는 우리 데이터로 측정할 수 없다. **측정 가능한 6면**으로 줄인다.

| 면 | 인출 형식 | 현 활동 | 상태 |
|---|---|---|--:|
| **F1 형태-의미 재인** | 뜻→단어 / 단어→뜻, 후보 있음 | Flashcard · PairFlip · Cascade 외 **10종** | 과잉 |
| **F2 철자 생산** | 후보 없이 타이핑 | SpellForge · wordsmith-vigil · letter-forge · ghost-race(아웃코스) | 적정 |
| **F3 청각** | 소리→단어 / 단어→발화 | wordfall-cadence(응답이 뜻) · EchoMatch(**신호 연결됨** 2026-08-14) | 발화 모방만 |
| **F4 형태·어원** | 형태소 조립·분해 | morpheme-rules · morphmerge · glyph-tongue | 조건부 |
| **F5 문맥·연어** | 문맥 빈칸 · 위조 판정 | ScriptQuiz · word-customs · Dictation | 기록 안 됨 |
| **F6 유창성** | 정확 + 속도 대역 | wordblitz 계열 | 미정의 |

**F1 이 10종으로 과잉**이라는 것이 아케이드 정리의 근거다. 이 10종을 서로 구별하는 것은
면이 아니라 **판돈 구조**(시계·거리·자본·박)다 → 면 축에서는 하나로 접고, 판돈은 게임의
개성으로 남긴다(브리핑이 이미 그 차이를 가르친다).

**아키타입은 새로 만들지 않는다.** `BriefKind` 5종(`pick`/`group`/`assemble`/`judge`/`type`)이
이미 손동작 축으로 정착돼 있고 재인/인출 구분과 거의 함수 대응한다 — 재사용해야 drift 지점이
하나로 유지된다.

### 2.2 단계(Stage) — 단어 하나의 생애

```
S0 만남      텍스트에서 봤다. 누적 만남 횟수만 센다. 인출 없음.
S1 인식      F1 통과 (후보 있는 재인)
S2 인출      F2 통과 (후보 없이 생산)
S3 사용      F5 통과 (문맥에서 정확)
S4 자동화    F6 — 정답 + 속도 대역
```

**해금은 선수 관계 그래프에서 도출된 것만 허용한다**(ALEKS 방식). 임의 임계 게이트는 배제.
그리고 이론이 강제하는 제약이 하나 있다 — **초기 부호화 단계에서 생산 과제를 강제하면
오히려 해롭다**(Barcroft 의 자원 소모 + 전문성 역전). 즉 `state=new` 단어를 SpellForge ·
EchoMatch 로 바로 보내면 안 된다. 현재 규칙(shaky→stable 이후 배정)은 근거가 있으니
**명문화해 지킨다**.

난이도는 "항상 어렵게" 가 아니라 **정답률 85% 대역을 상한으로 삼는 자동 조절**로 둔다.

### 2.3 진행 축은 하나만 노출한다

국외 관측이 일치한다 — WordUp=빈도 랭크, Duolingo=CEFR 섹션>유닛, Busuu=CEFR 레벨,
Vocabulary.com=단어별 20단계. **학습자에게 보이는 진행 축은 항상 하나다.**

우리 VRL 4축(V-Level · Track · Domain · Skill) 중 **경로 축은 V-Level 하나만** 쓰고
나머지 셋은 내부 편성 신호로 숨긴다.

그리고 **단일 mastery 스칼라(0~100%)는 배제한다** — 면이 6개인데 하나의 숫자로 접으면
"무엇이 부족한지" 를 말할 수 없다. 진행률은 `면 × 단계` 매트릭스로 표현하고, 화면에는
그 중 **가장 뒤처진 면 하나**를 처방으로 보여준다.

## 3. 메뉴 재편안

### 3.1 최상위를 4개로

국외 관측치: Busuu 3 · Memrise 3 · Babbel 4 · Vocabulary.com 4 · Duolingo 코어 6.
**현재 우리는 8 표면 / 14 리프** — 이 범위 밖이다.

| 새 최상위 | 담는 것 | 지금 어디 흩어져 있나 |
|---|---|---|
| **오늘** | 처방 정본 하나. 오늘 할 것과 "언제 끝나는지" | hub + FlowNav 추천 + arcade Today + 허브 4곳 |
| **서재** | 도서 · 스크립트 · 공용 세트 · 짧은 글 · 만화 = **콘텐츠 축 전부** | Library(3탭) + My Scripts + Comics(2) |
| **내 단어** | WordVault — 내 단어의 면×단계 상태 | WordVault |
| **성장** | 대시보드 · 리포트 · 증빙 | Dashboard + reports |

교사용 **교실(Class)** 은 footer 에 분리(권한이 다른 표면이다).

**메뉴에서 내리는 것**: Flashcard · WordBlitz · PairFlip · SpellForge · ScriptQuiz ·
Dictation · Game Lab. 이들은 **콘텐츠를 고른 뒤의 모드 선택** 또는 **경로 노드**가 된다.

이건 취향이 아니라 선례가 강제한다 — **별도 게임/활동 탭은 사용률로 정당화되지 않으면
유지된 사례가 없다.** Quizlet 은 저사용 모드(Gravity)를 제거하고 Write·Spell 을 Learn 의
옵션으로 강등했고, Duolingo 는 Stories 전용 탭을 없앤 뒤 전용 탭이 아닌 Practice Hub
항목으로만 복원했다.

### 3.2 이탈구는 정확히 1개

단선 경로의 위험은 "내가 하고 싶은 걸 못 한다" 다. Duolingo 가 경로 도입 후 **실제로 되돌린
유일한 것이 Practice Hub** 이고, 그 성격은 "경로에서 잠깐 쉬며 특정 스킬을 골라 하는 곳" 으로
문구까지 한정돼 있다 — **두 번째 경로가 아니다**.

우리의 이탈구는 **Game Lab** 이다. 다만 성격을 바꾼다:

- 지금: 사이드바의 독립 리프 = 두 번째 경로
- 제안: **오늘 화면 안의 "골라서 연습" 한 칸** = 이탈구 1개

19종은 그대로 둔다. 없애는 것이 아니라 **위치를 바꾸는 것**이다.

### 3.3 모바일이 출발점

모바일 전역 내비가 없는 상태에서 데스크톱 사이드바를 다듬으면 모바일은 그대로다.
**4개 최상위를 하단 탭 4개로 먼저 설계**하고 데스크톱은 그 확장으로 둔다.
(4±1 로 줄이는 결정이 모바일 하단 탭과 자연히 맞는다 — 우연이 아니라 같은 제약이다.)

## 4. 활동 레지스트리 (제안 ②)

### 4.1 왜 이것이 먼저인가

**단일 IA 재설계는 최소 9개 내비 표면을 동시에 고쳐야 한다**:
`sidebar-config.ts` · `FlowNav.STAGES` · `ModuleCard.MODULE_META` · `ModePills.MODES` ·
`SessionFrame.STAGE_OPTIONS` · `VocabSetPreviewModal.CHAPTER_GAMES` · `PLAN_ACTIVITIES` ·
`lib/game/catalog` · `TodayPrescriptionCard`.

9곳을 하나로 접지 않으면 **어떤 재설계도 즉시 drift 한다.** 이건 추측이 아니라 이 프로젝트의
기록이다 — `catalog.tsx` 헤더에 "게임 정의가 4곳에 복제돼 카운트·메타가 각각 낡음" 이라는
같은 실패가 이미 적혀 있다.

### 4.2 활동 하나가 선언하는 것

```
Activity {
  id            안정 키 (module_id enum · ScoreModule · ArcadeGameId 의 단일 출처)
  name          정식명 1개  ← 표면마다 다르게 쓰지 않는다
  alias         짧은 별칭 1개 (좁은 자리용)
  facets        [F1..F6]  훈련하는 면
  archetype     BriefKind 재사용 (pick/group/assemble/judge/type)
  stages        [S1..S4]  어느 단계에 배치 가능한가
  contentNeed   'none' | 'set' | 'text' | 'book+chapter'  (콘텐츠 의존성)
  minWords      플레이 가능 하한
  records       FSRS 기여 여부 + 기여하는 면
  brief         Protocol 브리핑 (이미 19종 완비)
  route         단일 규약
}
```

**라벨은 표면별로 정할 수 없다** — 활동당 정식명 1개 + 별칭 1개를 여기 고정한다.
§1.1 의 충돌 5개는 이 표를 채우는 순간 결정된다(결정이지 발견이 아니다 — 누군가 이름을 골라야 한다).

### 4.3 라우트 규약을 하나로

현재 이중 규약(`/<module>/play` vs `/play/<slug>`)이 스코프 전달 · 풀스크린 판정
(`endsWith('/play')`) · 세션 메타 조회를 **전부 경로 문자열에 의존**시켜 취약하다.
하나를 고른다. 레지스트리가 있으면 어느 쪽이든 파생 가능하다.

### 4.4 진행/보상을 단일 통화로

localStorage XP·Lv·streak(아케이드) 와 DB streak · V-Level · FSRS 가 병존해서
**"오늘 다 했나" 에 3개의 다른 답**이 나온다(daily_word_goal 12 · 30 XP · 처방 60~75분).
학습자에게 노출하는 통화는 하나여야 한다.

## 5. 콘텐츠 결합 (제안 ③)

### 5.1 다형 계약 하나

콘텐츠 유형 추가 비용이 지금 **최소 7곳**에 흩어져 있다:
`shared_word_sets.category` 문자열 + `curation_query` jsonb 관례 / 유형별 `*_vocabularies`
테이블 / 유형별 subscribe RPC / `texts.source` enum ALTER / `scoped-words.ts` 분기 /
`plan-activities.ts` MaterialRef switch / 스코프 쿼리스트링.

이 패턴의 대가가 실제로 발생했다 — **article 이 book 을 복사하며 밴드·상한을 빠뜨렸다.**

```
content_ref { type: 'book'|'text'|'set'|'article'|'comic'|'mine', id, chapter? }
```

를 **스코프 · 세션 귀속 · 처방의 공통 표현**으로 둔다. 유형이 늘 때 구현하는 것은
**어댑터 1개**(그 유형에서 단어를 꺼내는 함수)뿐이다.

### 5.2 결합 병목이 2개 파일이라는 것은 강한 레버

`lib/game/record-result.ts` · `lib/srs/flush-actions.ts` — 이 두 곳만 콘텐츠 인지형으로
바꾸면 19+ 활동 전체가 따라온다. **활동별로 결합을 구현하게 하는 설계는 배제한다**
(v07.8 이 이미 그 이유로 중앙화했다).

### 5.3 세트 ↔ 내 단어의 어긋남은 정상 상태다

75.7~99.7% 가 어긋나므로 **분리를 전제로** 설계한다. 선택지는 둘뿐이다:

| 안 | 내용 | 대가 |
|---|---|---|
| **(a) lazy 승격** | 플레이 시점에 `shared_words → vocabularies` upsert | 내 단어장이 의도 없이 커진다 |
| (b) 스킵 노출 | "이 중 N개는 아직 내 단어가 아니에요" 를 화면에 | 학습자가 한 걸음 더 밟아야 한다 |

**지금처럼 `{ok:true, updated:false}` 로 성공을 반환하는 침묵은 배제한다.**
권장은 (a) + 승격 사실을 알리기 — 학습자가 "이 세트로 놀았으니 내 단어가 됐다" 를
기대하는 것이 자연스럽다.

### 5.4 세션 귀속 스키마를 먼저 고친다

`scores` 에 `content_ref` 가 없으면 콘텐츠 단위 진행률 · 리포트 · i+1 승급이 **전부 불가능**하다.
지금 48행 전부 `text_id` NULL 이므로 이건 설계 전제이지 개선 항목이 아니다.

> **✅ 적용됨 (2026-08-13 · 마이그레이션 `20260813090000_scores_content_ref`).**
> `scores.content_type` / `content_id` / `content_chapter` 3컬럼 + `lib/content/content-ref.ts`
> (어댑터 1개 패턴) + 적재 배선(아케이드 19종은 `use-session-recorder` 한 곳으로 따라옴).
> 검증: 큐레이션 챕터 퀴즈 완주 → `content_type='book'` · `content_id` → `library_books.title`
> 조인 성공(`text_id` 는 여전히 NULL). 회귀는 `05-learner-loop` 단언 3건 + 단위 13건.
> **이 항목만 적용된 것이며 문서 전체는 여전히 미승인 제안이다** — 나머지 Phase 는 미착수.

### 5.5 단어 결합 키

소문자 `word` 를 유지한다 — 유일하게 실측 일관된 불변식(42,481행 100% 소문자)이고
`lemma` 는 `origin='library'` 에서 **0% 채워져** 결합 키로 쓸 수 없다.
lemma 기반 결합은 백필 없이는 배제.

한 단어가 여러 챕터·도서에 등장하므로 단일값 `vocabularies.shared_set_id` 로는 다중 출처를
표현할 수 없다 → **귀속은 세션 쪽(`scores`/`learning_records`)에서만 한다**고 명시한다.

## 6. 진행 가이드 — "오늘 이만큼 하면 끝"

### 6.1 개수로 닫는다

국외 선례가 일치한다 — Elevate 하루 3~5 게임, Beelinguapp 주 1~3/4~6/7~10 스토리.
**하루 목표를 단어 수·XP 가 아니라 세션/콘텐츠 개수로 표기**해 "언제 끝나는지" 를 닫는다.

### 6.2 국내 맥락: Day 단위 + 회차 점검

**"Day 단위 + 회차 점검" 이 한국 학습자의 기본 멘탈 모델이다**(워드마스터 Daily/Final
Check-up, 해커스 30일 완성). FSRS due 큐만 제시하면 "오늘 어디까지 하면 끝인지" 에
답하지 못한다 → **큐 위에 일일 묶음(오늘의 분량) + 3일 누적 점검**을 얹는다.

단, 완료 정의는 클래스카드식 "반복 소진" 이 아니라 **R(t) 기반 정착률**로 두고 그 차이를
도움말에 명시한다.

### 6.3 처방은 정본 하나

`prescribe_today` 를 유일한 정본으로 삼고, FlowNav mock 추천과 `pickDailyGame`(사용자 무관)은
**실데이터로 교체하거나 표면에서 제거**한다. 이건 전제 조건이다 — mock 이 남아 있는 동안에는
어떤 진행 UX 도 검증할 수 없다.

LingQ 의 계산 방식(다음 텍스트를 **'아는 단어 %'** 로 추천)은 우리 처방에 그대로 차용 가능하다.

### 6.4 조합 규칙 — Four Strands 25%

Nation 의 Four Strands 배분을 진행 지표로 쓸 수 있고, 우리 데이터로 산출 가능하다:

| Strand | 우리 활동 | 현재 |
|---|---|---|
| meaning-focused **input** | L2 워크스페이스 읽기 | 있음 |
| meaning-focused **output** | — | **없음** |
| language-focused learning | WordVault · Flashcard · SpellForge · 아케이드 대부분 | **편중** |
| fluency development | WordBlitz 계열 · 재독 | 미정의 |

**현 배분은 language-focused 편중이다.** 프레임워크는 이 불균형을 지표로 드러내야 한다.

### 6.5 간섭 회피 — FSRS 의 카드 독립 가정 보정

FSRS 는 카드 단위 독립을 가정한다. 우리 계층에서 보정한다:

- **같은 텍스트/동일 어족 파생 항목을 같은 세션에 몰지 않는다**(Anki Disperse Siblings 상당).
- **의미 세트(동의어 · 상위개념 공유)를 같은 세션에 묶지 않고** thematic 묶음(같은 장면 ·
  같은 사건)으로 대체한다.

지금의 "텍스트 단위 단어 추출 → 그대로 큐" 흐름은 의미 클러스터 간섭을 **자동 생산**한다.

### 6.6 노출 횟수와 커버리지

- 노출 횟수 목표를 단일 상수로 못 박지 않는다(문헌 6~20+). 단어별 **누적 만남 횟수**를 저장하고
  8~10회를 **하한 신호**로만 쓰며, 부족분은 **narrow reading**(같은 도서 연속 챕터)으로 채운다
  — 우리 `library_books` 챕터 구조 · `user_book_group_id` 와 이미 정합한다.
- 어휘량 이정표는 두 개: **95% 커버리지 = 4~5천 어족(최소)** / **98% = 8~9천 어족(최적)**.
- **커버리지 임계를 하드 게이트로 쓰지 않는다** — Schmitt et al.(2011)은 임계값 자체의 증거가
  없고 관계가 선형이라고 보고했다. 도서 진입은 "98% 미달이면 차단" 이 아니라 **예상 미지어
  밀도를 연속값으로 보여주고 지원(hover 사전 · 주석)의 양을 조절**하는 방식이어야 한다.

## 7. 프레임워크가 요구하는 빈칸

축을 정의하면 비어 있는 칸이 드러난다. **이것이 다음 개발의 근거가 된다.**

| 빈칸 | 왜 필요한가 | 선행 조건 |
|---|---|---|
| **문장 생산 (F5 생산 / meaning-focused output)** | 현 19종 중 **어느 것도** 채우지 못한다. Four Strands 의 한 축이 통째로 빈다 | 채점 신뢰(§8 자동 채점 주의) |
| **청각 면 신호 (F3)** | 유일한 청각 게임은 응답이 '뜻' 이라 발음 지식을 검증하지 않고, EchoMatch 는 FSRS 밖(`echo_match_attempts`)에 산다 → **청각 처방이 불가능** | EchoMatch 를 어휘 단위 신호로 잇기 |
| **F5 문맥 기록** | ScriptQuiz · Dictation 이 FSRS 에 0행. "L5/L6 = 최상위 인출" 주장과 충돌 | 두 모듈을 결합 계약의 1급 시민으로 ⚠️ **전제 절반이 틀렸다 — 아래 참조** |
| **어원 면 (F4) 확장** | 되살리려면 v07.9 의 삭제 결정을 뒤집는 것 | **검증된 어근/접사 사전**(substring 매칭 금지). 없이 하면 "틀린 형태론을 단정 교육" 하는 과거 결함 재발 |
| 교육과정 등급 태그 | V-Level 단독으로는 "교과 진도 어디" 에 답할 수 없다. 2022 개정 기본 어휘 3,000(초 800 / 중고 공통 1,200 / 기타 1,000)과 권장 90% 커버리지는 학교 채택 시 실제로 요구된다 | 교육부 고시 별책 원문 목록 확보 |
| 클래스(그룹) + 공유 리포트 | 국내 채택 조건이 **"세트 · 클래스 배포 · 자동 리포트" 3종 묶음**이다(클래스카드 · AutoVoca · 밀크T · 리딩게이트 예외 없음). 학습 모드가 좋아도 교사 배포·증빙 경로가 없으면 교실에 못 들어간다 | 학생별 공유 URL + 엑셀 일괄 내보내기(국내 실무 표준) |

> **✅ 청각 면 신호(F3) 적용됨 (2026-08-14 · 마이그레이션 `20260814090000_module_id_echo`).**
> EchoMatch 가 `learning_records(module='echo')` 로 어휘 단위 신호를 남긴다.
> 근거를 **두 등급으로 나눴다**: 음성인식 전사(`matchedKeys`)가 있으면 단어마다 판정하고,
> 없을 때만 프로소디 점수를 문장 단위 보조 근거로 쓴다(한 발화 최대 3단어).
> 실측이 게이트를 하나 추가하게 했다 — `echo_match_attempts` 6건 중 **4건이 발화 실패**여서,
> 측정 실패를 오답으로 적재하면 마이크 문제가 청각 처방이 된다. 실패는 **무기록**이다.
>
> **다만 FSRS 카드는 일부러 안 움직인다.** 문장이 화면에 떠 있는 채로 따라 말하는 것은
> 인출이 아니다(본 문서 §8 배제 목록의 TAP 원칙). 남는 것은 면 이력과 그날의 활동뿐이다.
> 이 빈칸의 목적이 "청각 처방을 가능하게" 였고 그 조건은 신호이지 스케줄이 아니다.

> **⚠️ F5 문맥 기록 — 이 빈칸의 전제 절반이 틀렸다 (실측 2026-08-15).**
> "ScriptQuiz · Dictation 을 결합 계약의 1급 시민으로" 라고 썼는데, 둘의 사정이 전혀 다르다.
>
> · **Dictation** — 맞다. 문장 안 타깃 단어를 실제로 받아 적으므로 어휘 인출이다.
>   v07 에서 해소했다(실측 `learning_records(dictation)` 109행).
> · **ScriptQuiz** — **배선 문제가 아니다.** 문항 1,019 + 5 건 **어디에도 대상 단어가 없고**,
>   문항이 서사 이해다(줄거리·인물·동기). 줄거리 문제 정답을 그 문장에 든 단어의 인출로 세는 것은
>   본 문서 §9 가 금지한 바로 그 종류의 승격이다. 이 활동이 재는 본문 이해는 이미 `scores`
>   에 남는다(실측 15행) — **적재 경로가 없는 게 아니라 층이 다르다.**
>
> 그러므로 이 빈칸을 닫으려면 배선이 아니라 **문항이 대상 단어를 갖게 하는 콘텐츠 모델 변경**
> (`library_chapter_quiz` 에 대상 단어 + 1,019 문항 백필)이 선행돼야 한다. 비용이 크므로
> 별도 결정 사항으로 남긴다. 그 전까지 이 항목을 "연결하면 된다" 로 읽지 말 것.

## 8. 하지 않을 것 (근거 포함)

설계에서 **배제**를 명시하는 것이 채택 목록보다 중요하다. 이것이 없으면 다음 사람이 같은 것을 다시 넣는다.

| 배제 | 근거 |
|---|---|
| 랭킹 · 리더보드 · 연속일수 압박 | 외적 보상이 내재 동기를 깎는다(Deci et al. d=-0.28~-0.40). 국내 초등 실증에서 게임형 랭킹·점수·레벨에 관심이 없었고 잠금화면·오답노트형 반복은 거부되었다(인효혜·표시연 2020). 우리 "폭죽·트로피 금지" 규칙과 일치 |
| **진행률을 반복 횟수로 정의** | 클래스카드 스펠은 힌트 요청조차 오답 처리해 재복습을 강제하는데, 이 강제성이 **자동화 핵 생태계의 직접 원인**이다. 반복 횟수로 정의하는 순간 우회 대상이 된다 |
| 커버리지 임계 하드 게이트 | Schmitt et al. 2011 — 임계값 증거 없음, 관계는 선형 |
| DKT 계열 적응형 | 재현성·블랙박스·단순 베이스라인 대비 이득 불명. 숙련도 추정은 **해석 가능한 모델**(FSRS D/S/R + 단순 IRT)로 유지 |
| involvement index 를 해금 예측식으로 | 동일 지수가 다른 결과를 내고 수용/생산 측정 방향으로 뒤집힌다. **"이 과제가 왜 무거운가" 를 설명하는 라벨로만** 쓴다 |
| 확장 간격을 우월하다고 서술 | 어휘에서는 등간격이 더 좋았다는 보고가 있다 |
| SRS 지표를 실사용 능력의 증거로 제시 | 간격은 explicit 지식만 밀어올렸고 tacit 지식은 아니었다 → Dashboard 에서 **내부 지표(R)와 생산 능력 지표(EchoMatch·Dictation 실적)를 분리**해야 한다 |
| 4지선다로 학습한 단어를 "말할 수 있다" 로 표기 | 전이 적합 처리(TAP) — 인출 형식이 최종 사용 형식과 일치해야 한다. **모듈별 "보장하는 인출 형식" 을 상태로 저장**한다 |
| `new` 단어에 생산 과제 강제 | Barcroft 자원 소모 + 전문성 역전 |
| 학교식 "출제자가 원하는 단어만 정답" | 7원칙 3(Empathetic Feedback)과 정면 충돌. 채점 관용은 클래스카드 수준(특수문자·띄어쓰기 무시) 이상 |
| 정답을 클라이언트에 노출 | 클래스카드 `data-idx` 사례 — 노출되면 리포트 전체가 무효화된다. 리포트를 만들 이상 **서버 검증 + 이상 탐지가 전제** |
| 자동 채점(스피킹·서술형)을 사람 검토 없이 출시 | 국내 사용자 불만에서 "AI가 틀린 걸 맞다고 한다" 가 신뢰 훼손 사유로 직접 지목된다 → **관리자 재판정 큐 필요** |
| 두 번째 경로 | 이탈구는 1개(§3.2) |
| 단일 mastery 스칼라 | 면이 6개인데 하나의 숫자로 접으면 무엇이 부족한지 말할 수 없다 |
| 문서를 SSoT 로 신뢰하는 절차 | CLAUDE.md·VOCAB_LAYERS.md 수치가 2~4배, migrations 34건 어긋나 있고 VOCAB_LAYERS.md 는 깨진 v2 RPC 를 정상 커넥터로 기술한다. **프레임워크 문서는 DB 쿼리로 재생성 가능한 형태**여야 drift 가 재발하지 않는다 |

### 우리 7원칙 중 재진술이 필요한 둘

- **Context-Dependent** — Elgort(2011)에 따르면 탈맥락 의도 학습도 자동성 있는 표상을 만든다.
  "맥락 없는 학습은 얕다" 는 강한 형태는 지지되지 않는다 → 맥락은 **use(연어·사용 제약) 칸을
  채우는 수단**으로 좁혀 서술한다.
- **Desirable Difficulty** — 초기 부호화에서는 해롭다(§2.2). "항상 어렵게" 가 아니라
  **정답률 85% 대역 자동 조절**로 재진술한다.

## 9. 선택이 필요한 지점 (사용자 결정)

설계를 확정하려면 세 가지는 골라야 한다. 각각 권장안을 붙였다.

### 결정 1 — 경로(단선) vs 자유 선택

| 안 | 내용 | 선례 |
|---|---|---|
| **A. 단선 경로 + 이탈구 1개** (권장) | 오늘 화면이 다음 한 걸음을 정하고, Game Lab 이 유일한 이탈구 | Duolingo · Rosetta · Busuu |
| B. 자유 선택 | "다음에 뭘 하지" 를 학습자에게 넘긴다 | LingQ("There is no set order") · Anki |
| C. 하이브리드 | 콘텐츠는 자유, 콘텐츠 안에서는 경로 | Vocabulary.com |

**권장 A** — 우리 문제가 "선택지가 많아 무엇을 할지 모른다" 이므로 B 는 문제를 키운다.
다만 C 도 성립한다(서재에서 도서는 자유롭게 고르고, 도서 안에서는 경로).
**실은 A 와 C 의 차이는 "콘텐츠 선택을 처방에 넣는가" 하나뿐**이므로, C 로 시작해
데이터가 쌓이면 A 로 좁히는 것이 되돌리기 쉽다.

> **✅ 결정됨 — C 채택 (2026-08-14).** 콘텐츠는 자유(서재에서 고른다), 콘텐츠 안에서는 경로.
> A 로 좁히는 것은 **데이터가 말할 때** 한다 — 지금은 실사용 분포를 모른다(§12 위험 1).
> 되돌리기 쉬운 쪽을 먼저 둔다는 원칙 그대로다.
>
> 이 결정이 코드에 요구하는 것은 **"콘텐츠 하나를 고르면 그 안에서 할 수 있는 활동이
> 도출된다"** 이고, 그 도출은 이미 `registry.activitiesForContent(ref)` 가 한다.
> 즉 C 의 선행 조건은 **콘텐츠 표현의 단일화(Phase 2)** 지 메뉴 개편이 아니다.

### 결정 2 — 아케이드 19종의 처지

| 안 | 내용 |
|---|---|
| **A. 전부 유지, 위치만 이동** (권장) | 메뉴에서 내리고 경로 노드 + 이탈구로. 브리핑 19종이 이미 완비돼 있어 비용이 낮다 |
| B. 면 중복 정리 후 축소 | F1 10종을 3~4종으로 줄인다. 5종은 이미 실사용 0건 |
| C. 현행 유지 | 배제 — 문제의 원인 |

**권장 A 로 시작, B 는 데이터로**. 실사용 0건인 5종을 지금 없애는 것은 유혹적이지만,
0건인 이유가 "재미없어서" 인지 "메뉴에서 안 보여서" 인지 구분되지 않는다.
IA 를 고친 뒤 다시 재면 그 답이 나온다.

> **✅ 결정됨 — A 채택 (2026-08-14).** 19종을 **하나도 지우지 않는다.** 위치만 바뀐다.
> B(축소)는 IA 를 고친 뒤 재측정해서 판단한다 — 지금 지우면 "안 보여서 0건" 인 것까지
> 함께 지우고, 그 사실은 영영 알 수 없게 된다.
>
> 지금 시점에 이 결정이 요구하는 것은 **삭제 금지**뿐이라 코드 변경이 없다.
> 위치 이동(메뉴 → 모드 선택/경로 노드)은 Phase 3 이고, 그 전에 Phase 2 가 와야 한다.

### 결정 3 — 세트 ↔ 내 단어 승격

§5.3 의 (a) lazy 승격 vs (b) 스킵 노출. **권장 (a) + 승격 알림.**

> **✅ 결정됨 — (a) 채택 (2026-08-14).** v08.5 가 먼저 (b)로 구현돼 있었고, 이번에 (a)로 전환했다.
> `recordGameResult` 가 내 단어가 아니면 **지금 놀고 있는 그 세트에서 담아 오고**(`promoteFromSet`)
> 이어서 FSRS 를 올린다. 담았다는 사실은 `promoted` 로 돌려 스캐폴드가 고지한다
> ("이 세션에서 만난 N개를 내 단어장에 담았어요").
>
> 자격을 **현재 세트로 좁힌 것**이 이 구현의 핵심 판단이다 — 구독 전체로 넓히면 게임 내장
> 뱅크 단어가 이름만 겹쳐 딸려 들어와 학습자 단어장이 오염된다. 담을 수 없는 경우
> (뱅크 단어 · `meaning_ko` 없음)는 (b)의 고지를 그대로 유지한다.
>
> 함정 하나: `vocabularies.lemma` 는 `shared_dictionary(word)` FK 라 세트 lemma 가 사전에
> 없으면 INSERT 전체가 죽는다 → **lemma 없이 재시도**로 방어한다(결합 키는 소문자 `word`, §5.5).
>
> 계약: `tests/e2e/16-coupling-notice.spec.ts` (고지 + `vocabularies` 실적재 DB 단언 · finally 원복).

## 11. 조사에서 확인 못 한 것 (설계 위험)

정직하게 남긴다. 이 중 일부는 설계 확정 전에 채워야 한다.

- **실사용 분포를 모른다** — `scores` 총 48행 · 13모듈이고 최신 활동이 개발 계정 성격이어서
  "어느 화면이 실제로 쓰이는가" 를 데이터로 판정할 수 없었다. **결정 2(B안)의 근거가 없다.**
- `prescribe_today` 내부 로직(5블록 선정 · stage_band 계산)을 열지 않아, hub 처방이
  아케이드·PairFlip·SpellForge 를 **구조적으로** 배제하는지 단지 블록 종류가 5개라서 그런지
  구분하지 못했다.
- `word_familiarity` 가 왜 사라졌는지 — 마이그레이션 적용 기록(20260715224958)은 있는데
  테이블이 없다. VACUUM FULL/복원 과정 유실인지 다른 세션의 DROP 인지 미확인.
- 한국 학습자의 단어장 앱 이탈률 정량 데이터(D1/D7/D30)를 국내 공개 자료에서 찾지 못했다.
  확보한 것은 정성 근거뿐이다.
- 2022 개정 기본 어휘 3,000 원문 목록(교육부 고시 제2022-33호 별책 14) 미확보 —
  등급 태깅의 선행 과제.
- 클래스카드 암기/리콜/스펠의 정확한 완료 조건·반복 알고리즘(로그인 장벽), 리포트 지표 필드 명세.
- Duolingo 트리→경로 전환의 정량 근거(A/B·완주율) — 공식 발표에 지표 없음.
- Nation 2006 / Four Strands 2007 원문 본문 미파싱(PDF 추출 실패·403) — 어휘량 이정표
  수치는 2차 자료 기준이다.
- 의미 클러스터 간섭 연구는 대부분 novice·짧은 리스트 실험이다. **이미 stable 인 단어의
  복습 큐에도 같은 간섭이 있는지는 미확인** — §6.5 는 그만큼 잠정이다.
