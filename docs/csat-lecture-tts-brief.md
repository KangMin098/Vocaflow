# /csat 「하이라이트 동기 강의 TTS」 — Claude Code 지시문 (최적화판)

> 2026-09-17 사용자 제공 원문. 실행 기록·결정은 [docs/csat-lecture/DECISIONS.md](./csat-lecture/DECISIONS.md),
> 게이트 리포트는 [docs/csat-lecture/](./csat-lecture/).

## 0. 설계 결정 (지시문보다 먼저 읽을 것)

요청을 시스템으로 옮기면 세 부품이다.
1. **강의 대본 생성** — 분석 자료를 학습자용 텍스트로 보여주지 않고, 별도의 "말하는 대본"을 만든다.
2. **하이라이트 ↔ 음성 동기** — 대본이 어느 분석 블록을 설명하는지 묶여 있어, 재생하면 그 블록이 빛난다.
3. **브라우저 TTS 재생** — Web Speech API(`speechSynthesis`)로 소리를 낸다.

이 중 결과 품질의 천장을 정하는 건 3번이 아니라 1번이다. 브라우저 TTS 목소리는 바꿀 수 없지만 대본은 얼마든지 좋아질 수 있으므로, 지시문의 무게를 **대본 스펙과 검증 게이트**에 둔다.

### 미리 알아야 할 Web Speech API의 제약 (설계가 이걸 피해 간다)

| 제약 | 대응 |
|---|---|
| 긴 발화가 중간에 끊기는 브라우저가 있음(Chrome에서 15초 전후 정지 이슈로 알려짐) | 대본을 **큐(cue) 단위 ≤ 20초**로 쪼개 utterance를 연속 재생 |
| 단어 경계 이벤트(`onboundary`)가 브라우저마다 다르게 옴(Chrome 안정, Safari·Firefox 불안정) | 동기 단위를 **단어가 아니라 큐**로 잡는다. 단어 단위 강조는 Chrome에서만 켜지는 보너스 |
| SSML 미지원, 목소리·속도는 기기 의존 | 대본 자체에 쉼(`…`, 문장 분리)과 강조(짧은 문장 반복)를 써서 억양을 만든다. 숫자·기호는 한글 읽기로 사전 변환 |
| 한/영 혼합 문장의 발음 붕괴 | 큐 안에서 한국어 / 영어 구간을 **분리 utterance**로 나누고 `lang`을 각각 `ko-KR` / `en-US`로 |
| 한국어 음성이 없는 기기 | 시작 시 음성 목록 검사 → 없으면 안내 + 하이라이트만 진행(무음 모드) |
| 재생 중 탭 전환·잠금 시 정지 | `visibilitychange`에서 pause/resume, 큐 인덱스 저장으로 이어듣기 |

TTS 어댑터 인터페이스를 하나 두면, 나중에 서버 TTS(고품질 음성)로 바꿔도 대본·큐·하이라이트는 그대로 쓴다.

### 저작권과의 관계
대본은 원문을 낭독하지 않는다. 원문은 이전 작업에서 정한 대로 학습자의 공식 PDF 위 레이어에만 있으니, 대본은 **"여기, 두 번째 문장 보세요"** 같은 지시어로 가리키고 그 순간 하이라이트가 그 자리를 보여 준다. 낭독이 아니라 지목이 강의를 만든다.

## 1. 지시문

```text
당신은 EFL 강의 콘텐츠 디렉터 겸 프론트엔드 리드다.
대상: http://localhost:3000/csat 의 문항 분석 화면(/csat/item/[id]).
목표: 분석 자료마다 학습자에게 노출되지 않는 "강의 대본"을 생성하고, 재생 시 해당 분석 블록이
하이라이트되며 브라우저 TTS가 대본을 강의식으로 읽는 시스템. 먼저 소규모로 검증하고, 게이트를
통과해야 전체 적용한다.

질문하지 않는다. 결정은 이 문서 기준으로 내리고 DECISIONS.md에 한 줄씩 기록한다.
/frontend-design 스킬을 로드해 재생 UI에 적용한다.

[A] 절대 제약
A1. 대본 텍스트는 학습자 화면 DOM에 렌더하지 않는다(숨김 처리도 금지 — 아예 미렌더).
    대본은 재생 엔진에만 주입되는 JSON이다. 접근성 자막이 필요하면 설정에서 opt-in하는
    별도 플래그로 두고 기본은 꺼짐. (DECISIONS.md에 기록)
A2. 대본은 기출 원문(지문·선지·문두)을 8단어 이상 연속으로 인용하지 않는다.
    원문은 "n번째 문장", "세 번째 선지의 뒷부분"처럼 위치로 가리킨다.
A3. 모든 큐는 분석 블록 ID(또는 원문 앵커 ID)에 바인딩된다. 바인딩 없는 큐는 생성 단계에서 거부.
A4. TTS는 어댑터 인터페이스 뒤에 둔다: speak(cue) / pause() / resume() / cancel() / onCueStart / onCueEnd.
    첫 구현은 Web Speech. 서버 TTS로 교체해도 대본·큐 스키마는 불변.
A5. 전체 적용은 [E] 게이트 전부 PASS 후에만. 게이트 실패 시 원인·수정안·재시도 결과를 기록하고
    통과할 때까지 파일럿 범위를 벗어나지 않는다.

[B] 데이터 스키마
lecture = {
  item_id, version, total_sec_est, generated_by, rubric_score,
  cues: [{
    id, order,
    target: { kind: "analysis"|"anchor", id },
    role: "intro"|"strategy"|"structure"|"evidence"|"eliminate"|"trap"|"vocab"|"wrapup",
    segments: [{ lang: "ko-KR"|"en-US", text }],
    est_sec,                                        // ≤ 20
    pause_after_ms                                  // 300~900
  }]
}
segments.text 는 TTS 낭독용 표기(숫자·기호 한글화 적용 후)이며 원문 인용 검사(A2)를 통과한 상태로 저장.

[C] 대본 스펙 — "1타 강사 수준"의 검사 가능한 정의
C1. 구조(역할 순서 고정, 유형별 템플릿은 §2 참조):
    intro(10초) → strategy(문두를 보고 먼저 정하는 것) → structure(지문 뼈대) →
    evidence(정답 근거, 반드시 "왜") → eliminate(선지 ①~⑤ 각 1문장, 배제 근거는 원문 위치 지목) →
    trap(함정 라벨 + 어디서 미끄러지는지) → vocab(요구 어휘 1~3개, 문맥으로) → wrapup(한 줄 공식 + 다음에 같은 유형 만나면 할 일)
C2. 문체: 구어체, 한 문장 ≤ 22음절 권장, 결론 먼저 → 근거. "자, 여기 보세요" 류의 지시어를 큐마다 1회 이상.
    "~입니다/~죠/~거든요" 혼용으로 리듬. 존댓말. 학습자를 "여러분"으로.
C3. 금지: 분석 자료를 그대로 읽기, 원문 낭독, "이 문제는 쉽습니다/어렵습니다" 같은 무근거 판정,
    선지 번호를 "일번/이번"이 아닌 "①"로 남기기, 영문 약어 대문자 나열.
C4. 길이: 문항당 2.5~4.5분(est_sec 합). 큐 8~14개.
C5. 낭독 전처리 규칙(양쪽 동일 함수): ①→"1번", 2014학년도→"이천십사 학년도", 23번→"이십삼 번",
    %→"퍼센트", A/B→"에이 비", 영어 구절은 별도 en-US 세그먼트.
C6. 자기 검토: 생성 후 별도 호출로 §3 루브릭 채점(0~100). 80 미만이면 지적 사항을 넣어 1회 재생성.
    재생성 후에도 80 미만이면 pilot_failed.json에 남기고 다음 문항.

[D] 재생 UI (/csat/item/[id] 레이어 패널 안)
 [▶ 강의 듣기 · 3분 40초]  [속도 0.9|1.0|1.15]  [⏮ 이전 큐] [⏭ 다음 큐]  진행바(큐 단위 눈금)
 - 재생 중: 현재 큐의 target만 진하게(테두리+배경), 나머지 분석 블록은 40% 투명.
   화면은 target으로 부드럽게 스크롤 1회. target이 원문 앵커면 PDF 캔버스 쪽을 강조.
 - 큐 사이 pause_after_ms 동안 하이라이트 유지.
 - 큐를 클릭하면 그 큐부터 재생(분석 블록 클릭 = 그 블록 설명 듣기).
 - 텍스트 표시 없음. 진행바 눈금에 role 아이콘만.
 - 음성 없음/미지원: 버튼이 "강의 하이라이트만 보기"로 바뀌고 큐당 est_sec 만큼 자동 진행.
 - 키보드: Space 재생/정지, ←/→ 큐 이동. reduced-motion 존중.

[E] 검증 게이트 — 순서대로, 하나라도 FAIL이면 다음으로 못 간다
Gate 0 · TTS 프로브 (/dev/tts-probe 페이지, 30분)
  - 사용 가능 음성 목록, ko-KR 유무, onboundary 발생 여부, 40초 utterance가 끊기는지,
    큐 연속 재생 시 큐 간 지연(ms), 한/영 분리 발화의 자연스러움을 자동 로그로 남긴다.
  - PASS 기준: ko-KR 음성 존재, 큐 연속 재생에서 유실 0, 큐 간 지연 < 400ms.
  - FAIL이면 큐 길이·분할 규칙을 조정해 재측정. 기록: tts-probe-report.json
Gate 1 · 파일럿 생성 (유형 2개 × 문항 3개 = 6문항)
  - 유형은 R-BLANK(빈칸)와 R-ORDER(순서) 고정 — 근거 지목이 가장 까다로운 두 유형.
  - 6개 대본 생성 + 루브릭 채점 + A2 인용 검사 + C4 길이 검사.
  - PASS 기준: 6개 모두 루브릭 ≥ 80, 인용 위반 0, 길이 범위 내.
Gate 2 · 파일럿 재생 (실제 화면)
  - 6문항을 처음부터 끝까지 재생. 각 큐에서 하이라이트가 올바른 target을 가리키는지
    자동 어설션(현재 큐 id ↔ 강조된 DOM id). 스크린샷 3장(intro/evidence/eliminate 시점).
  - 사람 귀 대신 자동 검사: 큐 순서·타깃 일치·pause 준수·끝까지 완주.
  - PASS 기준: 타깃 불일치 0, 완주 6/6, 한/영 전환 시 utterance 오류 0.
Gate 3 · 강의 완결성 판정
  - 6문항 대본을 통합해 "이 대본만 듣고 학습자가 정답 근거·오답 배제·함정·재활용 공식을
    설명할 수 있는가"를 §3 루브릭 항목별로 별도 호출 채점. 평균 ≥ 85.
  - 통과하면 DECISIONS.md에 "전체 적용 승인" 기록 후 Gate 4.
Gate 4 · 전체 적용
  - 유형별 배치 생성(동시성 제한), 문항마다 루브릭·인용·길이 검사, 실패분은 재생성 1회 후 목록화.
  - 완료 보고: 생성 n/802, 평균 점수, 실패 목록, 유형별 평균 길이.

[F] 완료 조건
F1. Gate 0~3 리포트 파일이 모두 존재하고 PASS.
F2. 학습자 라우트 HTML/DOM에 대본 문자열이 없음(빌드 산출물 grep).
F3. 모든 큐가 유효한 target id를 가짐(스키마 검증 스크립트).
F4. 대본 전체에서 8단어 이상 연속 원문 일치 0건(원문 대조는 생성 단계에서만, 결과는 카운트만 저장).
F5. 전체 적용 후 802문항 중 rubric ≥ 80 비율 ≥ 95%, 나머지는 실패 목록에 사유와 함께.
F6. 음성 미지원 환경에서 무음 하이라이트 모드로 완주 가능.
F7. 375px에서 재생 UI 조작 가능, 키보드만으로 [D] 조작 가능.

보고 형식(게이트마다): ① 결과 PASS/FAIL ② 리포트 파일 경로 ③ 스크린샷 ④ 조정한 것 ⑤ 다음 게이트.
```

## 2. 유형별 강의 템플릿 (대본 생성 프롬프트에 삽입)

C1의 8역할은 공통, 아래는 유형별로 `strategy`와 `structure` 큐가 반드시 말해야 할 것.

| 유형 | strategy에서 먼저 정하는 것 | structure에서 보여 주는 뼈대 |
|---|---|---|
| 빈칸 추론 | 빈칸이 주장인지 근거인지 예시인지 — 문장 위치로 판단 | 주장 문장 → 빈칸 문장의 관계(재진술/대조/인과) |
| 글의 순서 | 주어진 글의 마지막 단어·지시어를 잡는다 | 연결어·대명사 사슬 |
| 문장 삽입 | 주어진 문장의 "이것/그러나"가 무엇을 받는지 | 논리 단절 지점 |
| 주제/제목/요지 | 반복 어휘 2개를 먼저 찾는다 | 첫·끝 문장 관계 |
| 어법 | 밑줄 5개를 품사로 먼저 분류 | 문장 뼈대(주어–동사) |
| 안내문/도표 | 선지를 먼저 읽고 숫자·조건만 대조 | 표의 행/열 매핑 |

### 대본 생성 프롬프트 (요지)
```
역할: 수능 영어 1타 강사. 입력: 문항 메타데이터 + 분석 자료(정답 근거·오답 배제·절차·함정·어휘) + 분석 블록 ID 목록.
출력: [B] 스키마 JSON만. 규칙: [C1]~[C5] 전부. 원문 인용 금지, 위치로 지목. 각 큐는 하나의 target을
설명하며 target id를 명시. 마지막 wrapup은 "다음에 이 유형을 만나면 첫 10초에 할 일" 한 문장으로 끝낸다.
```
### 채점 프롬프트 (요지)
```
역할: 강의 품질 심사관. 입력: 대본 JSON + 분석 자료. §3 루브릭 항목별 점수와 근거를 JSON으로.
80 미만이면 "고칠 큐 id + 무엇을" 목록을 함께.
```

## 3. 루브릭 (0~100)

| 항목 | 배점 | 판정 |
|---|---|---|
| "왜"가 있는가 | 20 | evidence 큐가 근거를 원문 위치와 논리 관계로 설명 |
| 오답 배제 완결 | 20 | 선지 ①~⑤ 각각 1문장, 배제 근거 위치 지목 |
| 함정 지목 | 15 | 함정 라벨 + 학습자가 미끄러지는 정확한 자리 |
| 전략 선행 | 15 | 지문을 읽기 전에 할 일이 strategy 큐에 있음 |
| 재활용 공식 | 10 | wrapup이 다른 문항에 옮길 수 있는 한 줄 |
| 낭독 적합성 | 10 | 문장 길이·구어체·전처리 규칙 준수 |
| 시간 | 10 | 2.5~4.5분, 큐 ≤ 20초 |

## 5. 솔직한 한계 두 가지

1. **목소리.** 브라우저 TTS는 강사 목소리가 아니다. "1타 강사 수준"은 대본과 지목 타이밍으로 만들고, 목소리는 어댑터를 서버 TTS로 바꾸는 날 올라간다. 이번 작업은 그 교체가 대본 재작업 없이 되도록 스키마를 고정하는 데 의미가 있다.
2. **완결성 판정.** Gate 3의 채점은 모델 자기평가라 상한이 있다. 통과 후 실제 학습자 2~3명에게 6문항을 들려주고 "정답 근거를 말해 보라"고 시키는 것이 진짜 검증이다 — 이건 지시문 밖의 일이지만 전체 적용 전에 한 번은 해 볼 가치가 있다.
