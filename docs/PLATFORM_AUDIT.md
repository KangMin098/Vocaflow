## 3. 실측 절차 A — 운영 DB

Supabase project `jajenrevcbmrpaliomxv`. `mcp__supabase__execute_sql` 로 실행.

```sql
-- A1. 수요 측 (가장 중요 — 맨 먼저 본다)
select 'auth_users' k, count(*)::text v from auth.users
union all select 'learning_records', count(*)::text from public.learning_records
union all select 'reading_sessions', count(*)::text from public.reading_sessions
union all select 'daily_activity',   count(*)::text from public.daily_activity
union all select 'scores',           count(*)::text from public.scores
order by 1;

-- A2. 공급 측 (행 수 상위 — 어디에 노동이 들어갔는지)
select relname, n_live_tup
from pg_stat_user_tables
where schemaname='public' and n_live_tup > 0
order by n_live_tup desc limit 20;

-- A3. 학습자에게 실제로 보이는 카탈로그 (발행률 병목)
select status, count(*) n from library_books group by 1 order by 2 desc;

-- A4. 신규 가입 추이 (코호트가 생기면 여기부터 리텐션 계산)
select date_trunc('month', created_at)::date m, count(*) n
from auth.users group by 1 order by 1;
```

**판정 기준** — 공급 측 상위 10개 테이블 합계 대비 수요 측 합계 비율.
2026-08-16 기준 253만 : 728 = **3,480 : 1**. 이 비율이 개선되지 않으면 그 분기는 실패로 기록한다.

## 6. 산술 모델 — 매 분기 같은 식에 최신 값을 넣는다

```
가입 N
  × MAU/가입 (기본 가정 10~20%, 실측 생기면 교체)
  × 유료전환/MAU (기본 5~9%, 듀오링고 9.2%가 업계 상한 — 신생은 절반 이하)
  × ARPU (현재 /pricing Pro ₩9,900)
  = MRR
```

**2026-08 산출** — 가입 10만 → MAU 1~2만 → 유료 500~1,800 → **연매출 0.6~2.1억**.

```
LTV  = ARPU × 평균 구독 개월(기본 8)          = ₩79,200
CAC  = 가입당 획득비 ÷ (유료/가입 전환율)
허용 CAC(가입당) = LTV ÷ 3 × (유료/가입 전환율)  = ₩400 내외
```

> **결론(변하지 않는 한 유효)**: 가입 1명을 400원 이하로 데려올 유료 채널은 없다.
> → 10만은 광고가 아니라 **교사 3,500명 × 학급 30명** (CAC 0) 으로만 도달한다.
> 클래스카드 교사 기반의 3.2%.

### 6-1. 활성화·리텐션은 이제 화면에서 읽는다 (2026-08-16)

F4 를 "이벤트 6종 수집" 으로 적어 뒀지만, 실측해 보니 **6종 중 5종이 이미 기존 테이블에서
파생**된다(가입=`auth.users` · 첫 학습/세션/단어장/퀴즈=`learning_records`+`scores`).
빠진 것은 **순수 재방문(학습 없는 페이지 조회)** 하나뿐이고, 그것은 **일부러 수집하지 않는다** —
학습 제품에서 조회만 한 방문은 가치가 아니고 쫓으면 지표가 실제 학습과 멀어진다.
(조회 리텐션이 필요해지는 시점은 유료 전환 퍼널을 붙일 때다.)

즉 F4 의 실체는 "수집 장치가 없다" 가 아니라 **"아무도 계산해 본 적이 없다"** 였다.
→ `/admin` 상단 "학습자 활성화 · 리텐션" 패널에서 상시 판독한다
(`lib/admin/retention.ts` · 새 테이블·쓰기 경로 0).

**1회차 판독 (2026-08-16)** — 가입 3 · 활성화 3 · **가입→첫 학습 중앙값 55일** ·
D1 0/3 · D7 1/3 · D30 1/3 · 최근7일 3 · 최근28일 3.

> ⚠️ **이 3명은 개발·검증 계정이다. 사용자 행동이 아니다.** 여기서 읽을 것은 비율이 아니라
> **장치가 돈다는 사실** 하나다. 그래서 패널은 분모 20명 미만이면 퍼센트를 아예 그리지 않는다
> — 작은 표본의 퍼센트는 근거가 아니라 착시이고, 이 문서 §2 가 금지하는 "수치를 근거로 쓰기" 가
> 거기서 시작된다.
>
> 다만 **55일**은 표본이 작아도 방향을 말한다: 문제는 리텐션 이전의 **활성화**다.
> 가입하고 두 달 뒤에 첫 학습을 한다면 D1/D7 은 애초에 잴 대상이 아니다.
