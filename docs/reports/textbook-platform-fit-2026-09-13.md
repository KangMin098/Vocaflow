## 1. 시중 출판 프로세스 대응 — 8/8 자리 있음, done 2

`packages/library-pipeline/src/textbook/production-stages.ts` 실계수:

| | 수 |
|---|--:|
| 단계 | 8 |
| `done` | **2** (① 기획 · ④ 원고 검토) |
| `partial` | **6** |
| `missing` | **0** |

**없는 단계가 0 이라는 것이 이 파이프라인의 강점이다.** 시중 편집 실무의 8단계가 전부
코드에 대응물을 갖고 있고, 각 단계에 「누가 하는가」(`script`/`claude`/`human`)와 Claude Code
드레인 짝이 적혀 있다. 이 구조는 시중 교재 제작을 흉내 낸 것이 아니라 **집행한다** —
⑦ 내부 검수는 `publish-gate.ts` 가 3인 미달을 `process.exit(1)` 로 막는다.

### 다만 표가 자기 상태를 틀리게 적은 전력이 있다

⑦ 내부 검수는 2026-09-13 까지 `done` 이었는데 실제 3인 검수는 0건이었다(그 커밋이 `partial`
로 고쳤다). 「없는 것을 done 으로 적는 것」은 이 표에서 **가장 위험한 방향의 오류**다 —
다른 오류는 일을 중복시키지만 이것은 일을 안 하게 만든다. 그래서 아래 §4 의 계기를 붙였다.

## 3. 브랜드 · 시리즈 · 단행본 생성 — 코드 상수라 「생성」이 아니다

| | 현재 | 근거 |
|---|---|---|
| 시리즈 정의 | **3** (reading · vocab · syntax) | `series-catalog.ts` |
| 그중 조판돼 나간 것 | **1** (reading) | 같은 파일 `status` |
| 시중 시리즈 | **22** (NE능률 한 곳이 13) | 코퍼스 실측 |
| 브랜드 | 3개 문자열 상수 | `SERIES_BRAND` · `VOCAB_BRAND` · `SYNTAX_BRAND` |
| **단행본** | **개념 없음** | 저장소 전체 grep — 코드에 `standalone` 은 「자립성 지문」이고 단행본이 아니다 |

**셋 다 `as const` 배열이다.** 새 브랜드를 하나 세우려면 TypeScript 를 고치고 배포해야 한다.
사용자 요청의 「다양한 브랜드 생성, 시리즈 생성, 단행본 생성 할 수 있는 플랫폼」과의 격차가
여기다 — 지금은 **플랫폼이 아니라 카탈로그**다.

### 좋은 소식: DB 는 이미 준비돼 있다

`textbook_volume_renders` 의 PK 가 2026-09-06 에 `band` → **`(series, band)`** 로 바뀌었다.
즉 **시리즈 축은 이미 데이터다.** 단행본은 「단이 하나뿐인 시리즈」로 그 키에 그대로 들어간다 —
**마이그레이션 없이** 표현 가능하다. 막고 있는 것은 스키마가 아니라 `SeriesId` 가
`'reading' | 'vocab' | 'syntax'` 유니온이라는 **코드 쪽 좁힘**이다.

> 왜 PK 가 바뀌었는지가 이 판단의 근거다 — 시리즈가 하나일 때 어휘 V5 를 시험 조판했더니
> **발행 중인 독해 V5 의 조판 기록이 덮여 지워졌다.** 그 사고가 시리즈를 데이터로 만들었다.

## 4. 검수 · 해설 — 「다각·다수」의 자리는 있다, 채운 양은 못 쟀다

### 다각 — 3인 페르소나

`csat_item_reviews`(마이그레이션 20260912210000) · `unique(item_id, persona)` 가
「서로 다른 3인」을 **DB 로 강제**한다. `REVIEW_PERSONA_QUORUM = 3`.

| persona | 무엇을 보는가 |
|---|---|
| `setter` 출제자 | 정답이 유일하게 성립하나 · 근거가 지문에 문자 그대로 있나 |
| `analyst` 오답분석가 | 오답 4개가 **서로 다른 이유로** 틀리나 · 매력이 있나 |
| `tutor` 현장강사 | 그 학년이 풀 수 있나 · 해설이 「왜 나머지가 아닌지」를 짚나 |

세 사람이 **각자 독립으로** 읽는 것이 명세에 박혀 있다 — 앞 사람 판정을 보고 맞추면
3인 검수가 아니라 한 사람의 판정이 세 번 적힌 것이다.

### 집행 — 판정이 실제로 막는다

`publish-gate.ts` 는 **근거의 종류로 차단과 경고를 가른다.** 그 권 자체의 실측(해설 누락 ·
자동 검수 미통과 · 3인 미달)은 **차단**이고, 통계 관행이거나 오탐이 있는 자(정답 쏠림 `V≥0.1` ·
교정 규칙 3% 오탐)는 **경고**다. 전부 차단으로 만들면 `--allow-defects` 가 상수처럼 붙어
게이트가 장식이 된다 — 이 설계는 옳다.

### 못 쟀다

지면 문항(2026-09-12 기준 19권 1,860문항) 중 3인 검수를 통과한 수는 **이번에 못 쟀다**(DB).
로컬에 `item-review-drain/_round1` · `_round2` 가 각 7청크 산출 완료 상태로 있으나
**적재 여부는 DB 를 봐야 안다** — 파일이 있다는 것이 적재됐다는 뜻이 아니다.

### 「절대 이견이 없도록」에 아직 모자란 것

지금 구조는 **다각(3관점) × 1회**다. 사용자 요청의 「다수」는 그 위다:

- 같은 페르소나를 **다른 회차로 두 번** 읽히는 장치가 없다(`unique(item_id, persona)` 가
  오히려 재검을 막는다 — 회차 열이 없다).
- 세 판정이 **갈렸을 때의 중재 규칙**이 코드에 없다. 지금은 「셋 다 pass 여야 통과」라
  갈리면 그냥 막힌다 — 막히는 것은 안전하지만 **왜 갈렸는지가 기록에 안 남는다.**
