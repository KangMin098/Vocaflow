### P2 — 7축을 모두 측정했다는 의미로 읽히면 안 됨

적격 스캐너는 `outsidePct: null`을 고정 전달한다. 9,539편의 `usable`은 어휘 축이 미측정이고,
21,059편의 `excerpt`는 규격 분기에서 반환돼 어휘 축까지 도달하지 않는다.
고등 밴드의 어휘 분포 기준도 미측정이다. “7축 항목이 있다”와 “7축을 모두 검증했다”를 구분해야 한다.

### P2 — 스냅샷과 실제 DB의 차이

적격·재고 스냅샷은 **2026-09-15T16:23Z**다. 원천 목록 108,953→현재109,043, 후보87,626→87,716,
적격30,508→30,598로 각각 **90편 차이**가 난다. 등급 차이는 usable +85, excerpt +5다.
화면의 HTTP 응답에도 아직 `30,508`이 나온다. 다른 진단 스냅샷들도 9월13~15일 값이다.
이번 감사에서는 증거 보존을 위해 기존 스냅샷을 갱신하지 않았다.

### P3 — 중복 및 해시 재검증 필요

content_hash 중복은 **115그룹·287행**으로 모두 후보 상태다(VOA 90행·Gutenberg197행).
이 중 110그룹은 실제 본문 MD5도 동일하고, **5그룹은 같은 저장 해시인데 실제 본문이 다르다**.
따라서 287행을 모두 완전 중복으로 보거나 172행을 바로 삭제하는 것은 잘못이다.
정규화 방식·본문 수정 후 해시 갱신 여부를 확인해야 한다. 실제 본문 동일성 확인에도 의미상 중복·저작권 판단은 포함되지 않는다.

## Codex 작업 가능성

이 턴에서 DB SQL, pnpm/tsx 스캔, Vitest, Node 테스트가 실제 실행됐다.
내용 판정은 export → 에이전트의 JSON 청크 작성 → validate → import 구조다.
`gate-book-export`, `gate-article-export`, `gate-drain-validate`, `gate-import`에는 Claude 모델 API를 강제하는 의존성이 없다.
도움말의 “Claude Code가 채운다”는 역할 설명이며 Codex가 같은 입출력 계약을 수행할 수 있다.
단, 모든 ACP 생성·분석 경로를 모델별로 실행 검증한 것은 아니다.

Windows에서는 실행 정책에 막히는 `pnpm.ps1` 대신 **`pnpm.cmd`**로 실행했다.
API 키를 새로 발급하거나 Claude 전용 도구를 설치할 필요 없이 이번 감사가 완료됐다.

## 재검출 가드와 검증

추가 파일: `scripts/audit/csat-sources-audit.mjs`, `csat-sources-checks.mjs`, 전용 Node 테스트.
DB에는 GET만 보내고 기존 UI 스냅샷은 읽기만 한다. 기본 출력은 git 제외된 `.agent-logs/csat-sources-audit.json`이다.
반려·유해 장르 통과, 저장 게이트와 현재 결정 불일치, 분석 값 이상을 `--check`에서 exit 1로 알린다.
읽기용 운문 예외를 별도 분류하는 회귀를 포함했다. 이것은 **감사 가드이며 생산 조판을 차단하도록 연결된 수정은 아니다**.

```powershell
pnpm.cmd exec tsx scripts/audit/csat-sources-audit.mjs --check
pnpm.cmd exec tsx scripts/textbook/source-eligibility-scan.mjs --no-write
pnpm.cmd exec tsx scripts/textbook/extraction-defect-scan.mjs --all --no-write
node --test scripts/audit/__tests__/csat-sources-checks.test.mjs
```

실행 증거: 적격 스캔 288.6초, 본문 결함 전수 스캔303.7초. 화면·모델61 + 적격·결함58 + 감사 가드4 = **123개 테스트 통과**.
감사 `--check`는 발견된 모순을 이유로 **의도대로 exit 1**. 테스트 실패나 스캔 중단이 아니다.
전체 저장소 build/lint/test를 실행한 것은 아니다.

공용 에이전트 설정 검사 `node agents/scripts/check.mjs`는 **8/9 통과**했다. 기존 `.codex/config.toml`에
MCP 생성물의 `GENERATED` 마커가 없어서 D2가 실패한다. DB 조회·스캔 실행은 가능했지만,
Claude→Codex의 설정 동기화까지 정상이라고 단정할 수는 없다. 해당 설정은 이번 작업에서 수정하지 않았다.
커밋 전 공용 검사가 실패하는 상태이며 공유 트리에 기존 변경도 다수 있어, 감사 산출물은 로컬에 남기고 커밋·push하지 않았다.

조치 순서: 반려 예외 우선순위 수정 및 3개 원문의285문항 추적 → 화면과 실제 조판 조건 분리/통일 →
VOA·NASA·PLOS 추출기와 결함 규칙의 오탐/미탐 보완 → 부족한 판정/분석을 대상 ID로 처리 → 관련 스냅샷 재생성.
원문 대량 상태 변경이나 삭제는 이 감사 결과만으로 실행하지 않았다.
