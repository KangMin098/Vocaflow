### [B1] 셸의 Esc 와 게임의 Esc 가 동시에 발화 — 게임이 광고한 조작이 학습자를 게임 밖으로 내보낸다 (blocker · 축 A2/A6)

- 위치
  - `apps/web/src/components/layout/SessionFrame.tsx:167-180`
  - `apps/web/src/components/game/lexicon-estate/LexiconEstateGame.tsx:1110,1118`
  - `apps/web/src/components/game/morphmerge/MorphmergeGame.tsx:665-668`
  - `apps/web/src/components/game/lexicon-hands/LexiconHandsGame.tsx:1077`
  - `apps/web/src/components/game/word-customs/WordCustomsGame.tsx:841`
  - `apps/web/src/components/game/morpheme-rules/MorphemeRulesGame.tsx:666`
  - `apps/web/src/components/spellforge/SpellForge.tsx:370-374`
- 증상: Lexicon Estate 에서 카드를 손에 든 채 화면이 시키는 대로 `Esc`(“다른 카드 보기”)를 누르면, 카드를 내려놓는 **동시에** `/arcade` 로 튕겨 나간다. 판이 통째로 끝난다. Morphmerge 에서 `Esc`(“전체 해제”)도, Word Customs 의 `Esc`(“서류 다시 보기”)도, SpellForge 의 `Esc`(“건너뛰기”)도 같다. 재현: 해당 게임 진입 → 첫 상호작용 후 `Esc`.
- 근거: 두 리스너가 **모두 발화**한다. 게임은 `window`/`document` 의 **버블** 단계에 붙고 `e.preventDefault()` 만 부른다 — `preventDefault` 는 다른 리스너를 막지 않는다.

  ```ts
  // SessionFrame.tsx:167-180 — 풀스크린 라우트 전역
  const handleEscape = useCallback((e: KeyboardEvent) => {
    if (e.key === 'Escape') { router.push(closeHref) }
  }, [router, closeHref])
  useEffect(() => { if (!isFullScreen) return
    window.addEventListener('keydown', handleEscape) ... }, [isFullScreen, handleEscape])
  ```
  ```ts
  // LexiconEstateGame.tsx:1118 — 같은 키를 게임도 듣는다
  if (e.key === 'Escape' && heldCard) { e.preventDefault(); cancelAppraise(); return; }
  ```
  그리고 이 조작은 **학습자에게 문서로 약속돼 있다**:
  `lib/game/brief/stake.ts:253` `'… Esc = 정초석 없이 시작 / 다른 카드 보기'` ·
  `lib/game/brief/assemble.ts:429` `'… Esc 전체 해제 …'` ·
  `lib/game/brief/rule.ts:449` `'… Esc 서류 다시 보기 …'` ·
  화면 안에도 `<Kbd>Esc</Kbd>` 로 찍혀 있다(`LexiconEstateGame.tsx:1350,1374` · `MorphmergeGame.tsx:982` · `WordCustomsGame.tsx:1055`).
- 고칠 방향: 같은 저장소에 **이미 정답이 있다** — `components/game/brief/GameBriefModal.tsx:100-123` 은 `document.addEventListener('keydown', onKey, true)`(캡처) + `e.stopPropagation()` 으로 셸의 Esc 를 정확히 차단한다. 두 갈래 중 하나:
  ① 게임 5종의 키 핸들러를 캡처 단계 등록 + `stopPropagation()` 으로 바꾼다(국소 수정, 5파일).
  ② 더 낫다 — `SessionFrame` 이 Esc 를 소유하지 않게 하고, 게임이 자기 상태를 소진한 뒤에만 나가도록 `GamePlayScaffold` 가 `onEscape` 를 중재한다. 그러면 Esc 로 나가는 것이 **의도된** wordfall-cadence · pirate-quest 와도 한 규칙으로 정리된다.
- 영향 화면: /play/lexicon-estate, /play/lexicon-hands, /play/morpheme-rules, /play/morphmerge, /play/word-customs, /spellforge/play

### [B3] PairFlip 중도 이탈 = 그 판의 FSRS 기록과 점수 전량 유실 (blocker · 축 A2)

- 위치: `apps/web/src/components/pairflip/PairFlipGameScreen.tsx:47-104`
- 증상: PairFlip 을 8쌍 중 6쌍까지 맞힌 상태에서 셸의 X 를 누르거나(또는 `Esc`, 브라우저 뒤로) 나가면 **아무것도 남지 않는다** — 맞힌 6쌍의 FSRS 평점도, `scores` 세션 행도. 다음에 들어가면 그 6쌍이 여전히 복습 대기다.

  ```ts
  const onComplete = useRef((result: PairFlipResultData) => {
    if (usingReal) { for (const pr of result.pairResults) pushPendingResult({...}) ; void flushPendingSession() }
    void recordGameScore({ module: 'pairflip', ... })   // :72
    ...
    setTimeout(() => { router.replace('/pairflip/results') }, 1400)  // :103

  ```
- 대비: 아케이드 19종은 같은 문제를 **이미 해결했다** — `lib/game/use-session-recorder.ts:96` 이 `useEffect(() => () => flushRef.current(), [])` 로 언마운트마다 flush 하고, 헤더 주석(`:5-14`)이 바로 이 사고(“learning_records 6행 / scores 0행”)를 기록하고 있다. PairFlip 만 그 수정을 받지 않았다.
- 고칠 방향: `PairFlipGameScreen` 이 `useGameSessionRecorder`(또는 최소한 같은 언마운트-flush 패턴)를 쓰도록 하고, 매칭이 확정될 때마다 `pushPendingResult` 를 즉시 부른다(현재는 결과 배열을 끝까지 들고 있다).

### [M2] 화면이 보여준 점수와 DB·랭킹이 세는 점수가 다르다 (major · 축 A5/A6)

- 위치: `apps/web/src/lib/game/use-session-recorder.ts:63` · `apps/web/src/lib/game/play-scaffold.tsx:54`(스캐폴드 props) · `apps/web/src/lib/game/ranking.ts:77`
- 증상: Cascade 를 끝내면 결과 화면이 “점수 **870**”을 크게 보여준다. 그런데 `scores` 에 적재되는 값은 `정답 수 × 100` 이고, `/arcade/ranking` 의 Cascade 순위표는 그 값으로 줄을 세운다. 학습자는 자기가 본 적 없는 숫자로 순위가 매겨진다. 개인 최고(`usePersonalBest`, localStorage)는 또 게임 점수라, 같은 게임에 **서로 다른 “최고” 두 개**가 존재한다.
- 근거:
  ```ts
  // use-session-recorder.ts:63 — computeScore 를 주지 않으면 정답×100
  score: computeScore ? computeScore(correct, wrong) : correct * 100,
  ```
