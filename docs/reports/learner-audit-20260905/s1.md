## 요약

- 검사한 화면: 7개
  - `/wordvault` (허브) · `/wordvault/browse` · `/wordvault/study` · `/wordvault/review`
  - `/flashcard` (허브) · `/flashcard/play` · `/my/words`
- 결함: **blocker 2 · major 11 · minor 12**

### 슬라이스 전체 소견 (결함 아님 · 맥락)

잘 되어 있는 것부터 적는다 — 뒤의 지적이 "전부 나쁘다"로 읽히지 않게.

- **금지 컬럼 위반 0건.** `memory_state` / `mastery_progress` / `last_days` / `next_days` 를 읽거나 쓰는
  코드는 저장소 전체에 없다(grep 결과 전부 "쓰지 말라"는 주석). 4상태 판정은 `lib/srs/state.ts`
  의 `getMemoryState` 하나를 거친다 — 허브(`useHubStats`) · 목록(`WordRow`) · 필터
  (`state-filter`) · 세션 큐(`session-queue-query`) · 성장 띠(`growth-stats`) 가 전부 같은 함수다.
- **허브 수치와 세션 내용이 어긋나지 않는다.** `/flashcard` 가 세는 큐와 `/flashcard/play` 가
  뽑는 단어가 같은 `fetchStudyVocabularies` 를 쓴다(`lib/learner/session-queue-query.ts:24`,
  `lib/flashcard/hub-words.ts:30`).
- **PostgREST 1,000행 절단**은 `pagedSelect` 로 이미 처리돼 있다.
- **44px 하한**은 목록·세션의 주요 타깃에서 음수 마진 기법으로 실제 bounding rect 까지 지켜져 있다.
- **비로그인 직접 진입**은 `/wordvault/{browse,study,review}` 가 `?next=` 를 붙여 로그인으로 보낸다.
- 서버 권위 재계산(`lib/srs/flush-actions.ts:94-104`)이 클라이언트가 보낸 카드 상태를 무시하고
  DB 행의 D/S 로 다시 계산한다 — 스코프 진입이 진행도를 리셋하는 사고를 원천 차단한다.

아래 결함은 그 위에 남은 것들이다.

### [B1] 세션 중간에 나가면 그때까지의 평가가 DB 로 가지 않는다 — 탭을 닫으면 사라진다 (blocker · 축 A6)

- 위치:
  - `apps/web/src/components/flashcard/FlashcardSession.tsx:92-99`
  - `apps/web/src/lib/srs/flush-session.ts:15-36`
  - `apps/web/src/lib/srs/session-storage.ts:41-59`
  - `apps/web/src/components/layout/SessionFrame.tsx:167-174, 283-293` (나가는 두 수단)
- 증상: `/flashcard/play` 에서 카드 30장 중 12장을 평가한 뒤 상단 ✕ 를 누르거나 Esc 를 치거나
  브라우저 뒤로가기를 하면, 12장의 평가는 `vocabularies` 에도 `learning_records` 에도
  들어가지 않는다. 학습자는 12장을 공부했지만 SRS 는 아무 일도 없었던 것으로 남는다.
  그 12개는 `sessionStorage['srs_pending']` 에 남아 있다가 **같은 탭에서 다음 세션을 끝까지
  마칠 때** 비로소 함께 올라간다. 탭을 닫거나 새 탭에서 다시 열면 영구 소실된다
  (sessionStorage 는 탭 수명이다).
- 근거: flush 를 부르는 유일한 조건이 "완주" 다.

  ```tsx
  // FlashcardSession.tsx:93-99
  const flushedRef = useRef(false)
  useEffect(() => {
    if (isComplete && !flushedRef.current) {   // ← isComplete 일 때만
      flushedRef.current = true
      void flushPendingSession()
    }
  }, [isComplete])
  ```

  저장소 전체에 `beforeunload` · `pagehide` · `visibilitychange` 로 flush 를 거는 코드가 없다
  (grep: `beforeunload|pagehide|visibilitychange` — 히트는 GhostRace·WordsmithVigil 의 게임
  일시정지뿐). 그리고 `/flashcard/play` 를 나가는 두 수단은 둘 다 flush 를 모른다:
  `SessionFrame` 의 ✕ 는 `<Link href={closeHref}>` 이고, Esc 는 `router.push(closeHref)` 다.
- 정도 차이: `/wordvault/study` · `/wordvault/review` 는 **화면 안의 "← 종료" 와 Esc 로 나가면
  flush 된다**(`StudyMode.tsx:54-60` 의 `finish()`). 다만 이 두 화면은 풀스크린이 아니라
  사이드바가 살아 있으므로(`lib/layout/full-screen-routes.ts` 에 없다) 사이드바 링크·뒤로가기·
  새로고침으로 나가는 경로가 훨씬 흔하고, 그 경로는 똑같이 flush 를 건너뛴다.
- 고칠 방향: flush 를 "완주 이벤트"가 아니라 "**이탈 이벤트**"에 건다.
  1. `lib/srs/flush-session.ts` 에 `flushOnLeave()` 를 추가한다 —
     `navigator.sendBeacon` 또는 `fetch(..., { keepalive: true })` 로 보내는 경로가 필요하다
     (server action 은 언로드 중 완주를 보장하지 않는다). 즉 `flush-actions` 를
     `app/api/srs/flush/route.ts` 로도 노출해야 한다.
  2. `FlashcardSession` · `StudyMode` · `SpellForge` · `PairFlipGameScreen` 이 공유하도록
     `hooks/useSrsFlushOnLeave.ts` 하나로 묶고, `pagehide` + `visibilitychange(hidden)` 에 건다
     (`beforeunload` 는 모바일 Safari 에서 안 뜬다).
  3. `SessionFrame` 의 ✕ 와 Esc 는 라우팅 전에 같은 훅의 flush 를 부르게 한다 — 지금은
     셸이 세션의 존재를 모르므로, `SessionContext` 에 `onBeforeClose?: () => void` 를 추가해
     세션이 등록하는 형태가 가장 작다.
  4. flush 는 이미 멱등하지 않다고 명시돼 있으므로(`flush-actions.ts:39`) 큐를 비우는 순서를
     지금처럼 "성공 후"로 유지한다.
- 영향 화면: `/flashcard/play`, `/wordvault/study`, `/wordvault/review`
  (같은 원인이 `/spellforge/play`, `/pairflip/play` 에도 있으나 그쪽은 다른 슬라이스다)

### [B2] 새로고침하면 세션이 1번 카드로 되돌아가고, 버린 1회차 평가도 DB 에 함께 들어간다 (blocker · 축 A6)

- 위치:
  - `apps/web/src/hooks/useFlashcardSession.ts:21-24` (진행 상태가 전부 `useState` 초기값)
  - `apps/web/src/app/(main)/flashcard/play/page.tsx:84-86` (매 진입 시 큐 재조회)
  - `apps/web/src/lib/srs/flush-actions.ts:73-104` (누적 적용)
- 증상: `/flashcard/play?limit=30` 에서 12장을 평가하고 새로고침(또는 뒤로 갔다 다시 들어오면)
  화면은 **1 / 30 부터 다시** 시작한다. 이미 평가한 12장이 그대로 다시 나온다.
  여기서 30장을 끝까지 마치면 flush 는 `sessionStorage` 에 남아 있던 1회차 12건 + 2회차 30건
  = **42건**을 전부 올린다. 그 12개 단어는 몇 분 간격의 리뷰 2건으로 기록되어
  `learning_records` 에 두 행이 남고 `vocabularies` 의 D/S 에 두 번 누적 적용된다.
- 근거: 진행 상태에 영속 계층이 없다.

  ```tsx
  // useFlashcardSession.ts:21-24
  const [queue] = useState(() => sortByPriority(initialWords))
  const [currentIdx, setCurrentIdx] = useState(0)   // ← 복구 지점 없음
  ```

  `/flashcard/page.tsx` 머리 주석도 이 사실을 이미 적어 두었다: *"재개 지점을 저장하는 곳이
  없다(grep: resume/last_position/session_state 0건)"* — 그래서 ContinueRow 를 지웠다.
  즉 **알려진 공백이고, 지운 것은 UI 뿐 원인은 그대로다.**
  누적 적용은 `flush-actions.ts:73-77` 의 `running` 맵이 명시적으로 시간순 누적을 한다.
- 고칠 방향: B1 과 같은 훅에서 세션 진행도까지 저장한다.
  1. `lib/srs/session-storage.ts` 에 `saveSessionCursor({ route, wordIds, currentIdx, startedAt })`
     / `readSessionCursor(route)` 를 추가한다 (`sessionStorage` 가 아니라 `localStorage` 여야
     탭을 닫아도 산다).
  2. `/flashcard/play` 가 저장된 커서의 `wordIds` 와 이번 조회 결과가 겹치면 **"12장까지 하셨어요 —
     이어서 할까요 / 처음부터"** 를 묻는다. Calm UI 이므로 모달이 아니라 카드 위 한 줄.
  3. 이어하기를 고르면 이미 평가한 `wordIds` 는 큐에서 뺀다 — 그래야 같은 단어가 두 번
     기록되지 않는다.
  4. flush 성공 시 커서도 함께 지운다.
- 영향 화면: `/flashcard/play` (동일 구조가 `/wordvault/study`, `/wordvault/review` 에도 있다 —
  `StudyMode.tsx:43` 의 `useState(0)`)

### [M3] 평가 버튼이 약속하는 "다음 복습" 간격이 상수이고, 실제 적용되는 FSRS 간격과 다르다 (major · 축 A5)

- 위치:
  - `apps/web/src/components/flashcard/SRSBar.tsx:67, 78` (표시)
  - `apps/web/src/lib/flashcard/hub-words.ts:62` · `apps/web/src/lib/flashcard/scoped-words.ts:67` (입력이 언제나 초기값)

  그런데 그 네 값은 **모든 카드에서 똑같다** — 30번 리뷰한 단어든 오늘 처음 보는 단어든 같다.
  그리고 그 값은 실제로 저장되는 간격이 아니다: 저장은 FSRS(`applyReview`)가 DB 의 D/S 로
  다시 계산한다. 학습자는 "이걸 누르면 3일 뒤"라고 읽고 누르는데 실제 예약은 다른 날이다.
- 근거: 표시는 SM-2 상태 `srs` 를 쓰는데, 그 `srs` 가 항상 새 카드다.

  ```ts

  srs: createInitialSRS(),                       // ← 모든 단어가 동일한 초기값
  srsV2: rowToCard(r as unknown as VocabularyRow) // ← 진짜 상태는 여기
  ```
  ```tsx
  // SRSBar.tsx:78
  {formatNextReview(rating, srs)}   // srs = 위의 createInitialSRS() 결과
  ```
  `createInitialSRS()`(`lib/srs/sm2.ts:29-37`)는 `interval: 0, repetitions: 0, nextReviewAt: new Date()`
  로 고정이다. 한편 영속화 경로는 `srsV2` → `applyReview`(FSRS) → 서버 재계산이다
  (`FlashcardSession.tsx:159-174`, `flush-actions.ts:95-100`). 두 계산이 만나지 않는다.

  `/wordvault/study` 는 계산조차 안 하고 문자열 상수다:
  ```ts
  // StudyMode.tsx:34-40
  { rate: 1, label: 'Again', srs: '10 min', ... }  // 5개 전부 하드코딩
  ```
- 고칠 방향: 표시와 적용을 같은 함수로 만든다.
  1. `lib/srs/fsrs.ts` 에 `previewIntervals(card: SrsCard, now): Record<RatingValue, Date>` 를
     노출한다 (`applyReview` 를 4번 dry-run 하면 된다 — 이미 순수 함수다).
  2. `SRSBar` 의 prop 을 `srs: SRSState` → `card: SrsCard` 로 바꾸고 `currentWord.srsV2` 를 넘긴다.
  3. `StudyMode` 의 `RATINGS[].srs` 상수를 지우고 같은 preview 를 쓴다. `w` 의 카드가
     `getCachedCard(key) ?? createNewCard(key)`(StudyMode.tsx:88)라 여기도 실제 DB 상태가 아니다 —
     `WordItem.srs`(browse-queries 가 이미 채워 넣는다)를 쓰도록 바꾼다.
  4. `formatNextReview`/`calculateNextSRS`(SM-2)는 표시에서 손을 뗀다.
- 영향 화면: `/flashcard/play`, `/wordvault/study`, `/wordvault/review`

## 특히 볼 것 — 질문별 답

**1. 세션 프로세스 최적합 / 중간 이탈 시 진행 상황**
→ **유실된다.** 두 갈래다: (a) 평가 결과가 DB 로 안 간다 — `flushPendingSession` 이 완주에만
걸려 있고 이탈 훅이 없다 [B1]. `sessionStorage` 에 남으므로 같은 탭에서 다음 세션을 완주하면
뒤늦게 올라가지만, 탭을 닫으면 끝이다. (b) 진행 위치는 아예 저장되지 않는다 — 새로고침하면
1번 카드로 리셋되고, 버렸다고 생각한 1회차 평가가 나중에 함께 커밋되어 같은 단어가 두 번
기록된다 [B2]. `/wordvault/study` 는 화면 안 "← 종료"·Esc 로 나가면 flush 되지만, 그 화면은
풀스크린이 아니라 사이드바·뒤로가기로 나가는 경로가 더 흔하고 그쪽은 flush 하지 않는다.

**2. 뒤로가기**
→ **명시적 수단은 세 화면 모두 있다.** `/flashcard/play` 와 `/wordvault/browse` 는 풀스크린이라
`SessionFrame` 이 44px ✕ + Esc 를 준다(`SessionFrame.tsx:283-293`). `/wordvault/study` ·
`/wordvault/review` 는 풀스크린이 아니어서 사이드바가 살아 있고, 추가로 `StudyMode` 자체가
"← 종료"(min-h 44px)와 Esc 를 갖는다. **직접 URL 진입도 앱 밖으로 나가지 않는다** —
비로그인은 `?next=` 를 달아 `/login` 으로(`browse:42`, `study:35-39`, `review:28`),
`/flashcard/play` 는 안내 화면으로 간다(다만 `?next=` 누락 [m12]).
남은 문제는 **목적지**다: `/wordvault/study` 는 `?from` 을 안 받아 browse 에서 들어와도
허브로 나간다 [m8].

**3. 낭비**
→ 가장 큰 것은 `/wordvault` 허브다. 클라이언트에서 `vocabularies` 전량을 **두 번** 내려받고
(`useHubStats:84` · `VocabularyLevelMap:84`), `auth.getUser()` 를 8번, `user_profiles` 를 4번,
`library_books` 를 4번, `texts` 를 3번, `daily_activity` 를 2번 친다 [M1]. 그중
`useHubStats` 의 `books` 산출물(추가 3~4 왕복)은 **아무도 렌더하지 않는다** [M2].
`?view=` 레거시 경로는 버릴 조회를 한 번 더 한다 [m10].
`/wordvault/browse` 도 사용자 단어 전량을 받아 클라에서 거르지만(`browse/page.tsx:45`),
칩 카운트·검색·듣기 큐가 전부 그 배열 위에서 돌고 렌더는 `WordList` 가 80개씩 지연 렌더하므로
(`WordList.tsx:45-64`) 의도된 트레이드오프로 본다 — 결함으로 세지 않았다.
SWR 키가 매 렌더 바뀌는 곳은 없었다(`useSubscribedSets:108-112` 의 배열 키는 SWR 이 직렬화한다).
같은 쿼리를 두 번 하는 곳은 위 허브가 전부다 — 허브↔play 사이는 오히려 `fetchStudyVocabularies`
하나로 통일돼 있어 드리프트가 없다.

**4. FSRS / R(t)**
→ **금지 컬럼 위반 0건.** `memory_state` · `mastery_progress` · `last_days` · `next_days` 를
읽거나 쓰는 코드는 없다(전체 히트가 "쓰지 말라"는 주석 10건). `browse-queries.ts:177-182` 의
`lastDays`/`nextDays` 는 DB 컬럼이 아니라 `WordItem` 의 파생 필드이므로 규칙 위반이 아니다.
**R(t) 판정은 갈라지지 않았다** — 6개 소비처가 전부 `lib/srs/state.ts` 의 `getMemoryState`
하나를 거친다. 다만 수식 구현이 두 벌 있고 `S=0` 경계가 정반대다 [m5].
진짜 갈라진 것은 **표시**다: 학습자에게 보이는 "다음 복습" 간격은 SM-2 초기 카드 상수이고,
실제 저장되는 스케줄은 FSRS 다 [M3]. 즉 계산은 하나인데 화면이 다른 계산을 말한다.
