### [M1] 로그인·가입 성공이 `push` — 뒤로가기가 로그인 폼으로 돌아오고, 로그인한 채 로그인 화면이 보인다 (major · 축 A4)

- 위치: `apps/web/src/app/(auth)/login/page.tsx:96` · `apps/web/src/app/(auth)/signup/page.tsx:160` · `apps/web/src/middleware.ts:126-150`
- 증상: 보호 URL(`/wordvault`)로 직접 들어와 로그인으로 튕긴 뒤 로그인하면 `/wordvault` 로 잘 돌아간다. 그런데 거기서 **뒤로가기 한 번**이면 `/login?next=%2Fwordvault` 가 다시 뜬다 — 이미 로그인한 사람에게 로그인 폼이 나온다. 미들웨어에 인증 사용자를 인증 화면 밖으로 내보내는 규칙이 없어서 그대로 렌더된다.
- 근거:
  ```
  login/page.tsx:96    router.push(resolveReturnTo(searchParams))
  signup/page.tsx:160  router.push(returnTo)
  ```
  같은 저장소의 `reset-password/page.tsx:127` 은 정확히 이 자리에서 `router.replace('/hub')` 를 쓴다 — 어느 쪽이 옳은지 이미 알고 있으면서 두 화면만 어긋나 있다. 미들웨어는 `pathname === '/'` 인증 사용자만 `/hub` 로 보내고(`middleware.ts:110`), `/login`·`/signup` 은 손대지 않는다.
- 고칠 방향: 두 곳을 `router.replace(...)` 로 바꾼다(히스토리에서 인증 화면을 소거). 추가로 미들웨어에 `if (user && ['/login','/signup'].includes(pathname)) return redirectTo(resolveReturnTo(...) ?? '/hub')` 를 넣으면 북마크·뒤로가기·[M2] 가 한 번에 닫힌다.
- 영향 화면: `/login`, `/signup`

### [M2] 로그인한 사용자가 공개 화면의 "무료로 시작하기" 를 누르면 조용히 로그아웃된다 (major · 축 A4)

- 위치: `apps/web/src/app/(auth)/signup/page.tsx:108-115`
- 증상 (재현): 로그인 상태로 `/pricing` 또는 `/about` 을 연다(둘 다 공개 라우트이고 세션을 읽지 않아 항상 `로그인` / `무료로 시작하기` 를 보여준다) → `무료로 시작하기` → `/signup` 이 그대로 뜬다(미들웨어가 안 막는다) → 폼을 채워 제출 → **제출 순간 세션이 삭제되고** 그 다음 `이미 가입된 이메일입니다` 배너가 뜬다. 사용자는 가입도 못 하고 로그인도 잃었다.
- 근거:
  ```
  signup/page.tsx:110-115
    try { await supabase.auth.signOut({ scope: 'local' }) } catch { … }
  ```
  주석은 "stale 세션 차단(한글 메타데이터가 헤더로 흘러 ISO-8859-1 검증 실패)" 이라고 적혀 있다 — 목적은 타당하지만 **현재 로그인한 사람의 유효 세션까지 지운다.**
- 고칠 방향: `signOut` 앞에 `const { data:{ user } } = await supabase.auth.getUser()` 를 두고, 이미 로그인한 사용자라면 폼을 제출시키는 대신 "이미 로그인되어 있어요 — 계속하기" 로 `/hub` 를 안내한다. 근본 해결은 [M1] 의 미들웨어 가드다(인증 사용자를 `/signup` 에 애초에 들이지 않는다).

- **로그인 후 복귀(returnTo)** — 작동한다. 미들웨어가 `?next=` 에 **쿼리스트링까지** 실어 보내고(`middleware.ts:88-89, 143`), 로그인·가입 양쪽이 `resolveReturnTo` 로 읽으며 별칭 3종(`next`/`returnTo`/`redirect`)을 흡수한다(`lib/auth/redirect.ts:29`). open redirect 는 `safeInternalPath` 한 곳이 막고, 인증 화면 자기참조 루프도 차단한다. `/api/auth/callback` 도 `safeInternalPath(next)` 를 type별 기본값보다 우선한다. 회귀 `lib/auth/__tests__/redirect.test.ts`·`protected-routes.test.ts` 존재. **단, 뒤로가기 문제는 [M1] 별건.**
- **인증 에러 매핑** — `lib/auth/errors.ts` 가 잘못된 비밀번호(계정 열거 방지로 "없는 계정" 과 동일 문구)·만료 링크·이미 가입된 이메일(에러 경로 + Supabase 의 침묵형 `identities: []` 경로 **둘 다**)·정지/해지 계정을 각각 다른 한국어 문구로 처리한다. 모든 핸들러에 `catch` 가 있어 네트워크 예외가 삼켜지지 않는다. 유일한 구멍이 [M7].
