# FYM calibration 운영 준비 완료 · 2026-10-05

기존 **8편·96문항을 전수 검토하고 사람 검토용 문항 revision 3과 시행 절차를 준비했다.** 실제 사람 평가를 시작하거나 교육적 타당도를 인증한 결과는 아니다. 전문가/학생 응답, gold/production, DB 쓰기와 발송은 모두 0이다.

## 완료한 자료

- [문항/채점 전수 검토본](./frym-calibration-instruments-3-review.md): 원 본문8편과 개정96문항·관련 인용·1/0.5/0점 기준. 책임자/문항 검토자 전용이다.
- [개정 실행 문항](../../scripts/textbook/frym-validation/calibration-instruments-3.draft.json): record ID별 배열. 기존 export의 --instruments로 명시하며 지문별12개·축별3개를 유지했다.
- [기존96개 → 개정96개 audit](../../scripts/textbook/frym-validation/calibration-instrument-audit-3.json): 각 문항의 원 질문/근거/채점·점검 사유·개정 대응과 정확한 pilot/문항 파일 SHA256.
- [사람 운영 안내](../FYM_CALIBRATION_OPERATIONS.md): 실제 결정/증빙, 지문·질문 분리, 단계별 답 회수, 정답/부분답 우선순위, 배포 구분과 기존 명령 연결.

기존 pilot 본문, v1/default 문항, 이전 실행 결과는 보존했다. 새 protocol의 student_instructions_revision=2만 한국어 v2 안내를 선택한다. 필드가 없는 기존 v2 연구/revision=1은 당시 영문 안내·패킷·응답을 그대로 읽고 수집한다. 안내 revision은 protocol/manifest에, 실제 안내는 packet_hash에 포함된다. 과거 안내의 패킷/응답을 새 안내의 패킷으로 바꾸어 인증하지 않는다. 변경은 새 회차/사전 등록 후 재생성한 패킷을 사용한다.

| 기존 문항의 점검 사유 | 건수 |
|---|---:|
| 부분점수가 correct/partly correct 수준으로만 쓰임 | 96 |
| 근거가 관련 문장 대신 본문 전체임 | 72 |
| 구조 문항에 같은 일반 기준을 사용함 | 24 |
| 서로 다른 추론 질문에 같은 기준을 사용함 | 24 |
| 추론 질문의 힌트/여러 요구를 검토할 필요 | 24 |
| 명시 정보와 추론 문항의 내용 중복 검토 | 8 |
| 허용 답 표현 검토 | 2 |
| 문맥 어휘 정의가 본문에 명시되지 않음 | 1 |

사유는 겹치며 합산하지 않는다. 에이전트의 내용 점검 코드이며 전문가가 판정한 실패율이 아니다. 단순 중복이나 본문 전체 인용이 곧 교육적 실패라는 뜻도 아니다.

교차 검토에서 정확한 ‘정보/증상/중환자실/할 수 있다’를 짧다는 이유로 감점하는 문제, 질문에 없는 주절 관계 요구, 열린 결론에 특정 예시만 허용하는 문제, 설문 근거 누락, 혼합 답의 0점/0.5점 충돌을 보완했다. 명시 정보는 일부 정답을 0.5점으로 인정하며, 다른 축은 명시한 의미 반전·근거 없는 단정을 우선 0점 처리한다. 같은 단위의 모순 답은 정답으로 인정하지 않는다. 비지지 결론을 비지지라고 구별한 답은 오류를 긍정한 것이 아니다. 모든 기준은 실제 사람의 사전 검토 대상이다.

문장 해석 문항의 인용이 다른 문항의 답을 제공할 수 있으므로 지문만 읽기 → 추론 → 명시 정보 → 어휘 → 문장 순서를 제안했다. 답을 단계별로 회수하고 이전 답의 수정을 막는 시행 방식은 사람이 protocol.operations에 확정한다. 현재 JSON/수집기는 단계 열람이나 잠금을 기술적으로 인증하지 않는다. 문항 순서를 바꿨다는 사실로 측정 축의 독립성이나 순서 효과 제거를 주장하지 않는다.

## 최종 실제 예행

최종 출력: `.agent-logs/frym-calibration-instruments-r3-instructions-v2-draft/`. 중간 r3/r3-reviewed-draft/r3-ready-draft도 보존하며 최종 입력과 섞지 않는다. 원 연구 스냅샷 대조를 포함하여 export → register --prepare → 빈 collect → verify를 실행했다.

| 항목 | 실제 확인 |
|---|---:|
| 전문가/학생 원본 JSON 패킷 | 각 8 |
| 개정 문항 | 96 |
| 분리 제시 검토본 | 40: 지문8 + 네 질문 단계32 |
| candidate | 8 |
| expert_validated/student_validated/gold/production | 각 0 |
| 실제 전문가/중재/학생 응답 | 각 0 |
| 미확정 학년 band | 20 |
| 봉인/DB 쓰기/발송 | 0 |

`student-phase-previews/`의 분리 검토본에는 미등록/시행 금지 표시, opaque ID·manifest/packet hash·본문 또는 해당 단계 질문만 넣었다. 채점 기준과 목표 학년은 넣지 않았다. 현재 preview는 **등록 전 검토 자료**이며 실제 학생에게 제시하지 않는다. 실제 봉인 후 같은 시행 원칙으로 해당 등록 패킷에서 자료를 준비해야 한다.

빈 collect의 입력/응답/출력 receipt SHA256 일치, 입력 데이터 보존, 모든 측정 null, 전문가/학생0을 확인했다. 준비 요청은 책임자/시각/증빙을 채우지 않았고 등록을 수행하지 않았다.

문항 파일 SHA256: `919eefd4b9387784f8777d50dee6d5c82884979f08c0e49ff140c101a2c7b742`. 최종 실행 instrument_hash: `ff81d272fd3297fe8f31ef7676660365bebbada8f34e7c3ebb30fae08686fedd`. protocol_hash: `9af354d390dc98089fdbdc612d4b1dc4d57983a0374cf33099ba8d06fef15973`. 파일 hash와 실행 hash는 입력 범위가 달라 같을 필요가 없다.

## 검증과 남은 사람 작업

라이브러리 전체 **2,944개/166파일**, 타입 검사, 관리자 도움말 **59개/3파일**, 도움말 ESLint, 에이전트 검사11개를 통과했다. 새4개 문항 회귀는 전체96개/축별개수·정확한 인용/어휘 등장·audit/hash 대응·명시적 export/패킷 내용 분리를 검사한다. 기존 v2 안내/봉인 보존과 명시적 한국어 revision 변경 시 옛 패킷 거절을 확인하는 회귀2개도 추가했다. focused124개(v1 54/v2 66/문항4)가 통과했다. exporter 통합 테스트의 원천/연구는 synthetic 로컬 픽스처이며 실제 연구 데이터로 세지 않는다. 원문 인용의 끝 공백이 schema 처리 후 달라지는 문제도 제거하고 파일과 내보낸 문항의 완전 일치를 검사했다. 문항 전수 교차 검토와 계획 목적 대조 리뷰는 통과했다. 최종 목적 대조에서 발견한 안내 호환성 결함은 protocol에 revision을 봉인해 보완했고 교차 검토를 통과했다.

실제 책임자/독립 전문가 수·학년별 학생 수는 이번 작업에서 입력받지 않았다. 책임자가 문항/채점·시행 순서·참여 운영과 20개 pass band/근거를 검토하고 실제 배정·사전 등록 증빙을 제공한 뒤에만 의미 평가 → 학생 calibration을 진행할 수 있다. calibration을 완료한 뒤 새 독립 validation 원천에서 gold를 검증한다. 이번 작업에서 실제 교육적 유효성·학년 규준·플랫폼 성능을 측정하거나 일반화하지 않았다.
