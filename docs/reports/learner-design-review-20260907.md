## 2. 실측 결함 — 시스템 층

### 2-1. 한글 웹폰트가 **0종**이다 (치명)

`app/layout.tsx:18-44` — `next/font/google` 4종이 전부 `subsets: ["latin"]` 이다.

| 변수 | 폰트 | 한글 글리프 |
|---|---|---|
| `--font-display` | Plus Jakarta Sans | 없음 |
| `--font-body` | DM Sans | 없음 |
| `--font-serif` | Lora | 없음 |
| `--font-mono` | JetBrains Mono | 없음 |

저장소 전체에서 Pretendard · Noto Sans/Serif KR · Nanum · Gowun · SUIT · IBM Plex Sans KR 를
grep 했을 때 **선언이 0건**이다(유일한 매치는 `Suitable`·`suite` 오탐).

무슨 일이 벌어지는가:

- `font-body` 한글 → DM Sans 실패 → OS 기본 산세리프. Windows **맑은 고딕** ·
  macOS **Apple SD Gothic Neo** · Android **Noto Sans CJK**. 자폭·굵기·베이스라인이 전부 다르다.
- `font-editorial`(Lora) 한글 → 폴백 체인이 `Iowan Old Style → Georgia → serif` 인데
  셋 다 한글이 없다 → OS **기본 세리프**. Windows 에서는 **바탕/궁서 계열**이 나온다.
  `components/library/vocab/VocabSeriesHeader.tsx:50` 의 `<h1 class="font-editorial …">단어장</h1>` 이
  정확히 이 경로다 — 실측 스크린샷(`apps/web/test-results-learner/vocab-shelf.png`)의
  「단어장」이 Lora 가 아니라 OS 세리프로 그려져 있다.
- 그래서 **같은 커밋이 세 OS 에서 세 제품처럼 보인다.** 디자인 시스템이 통제하는 것은
  영문 라벨(Books / Dispatches / Decks)뿐이고, 한국 고등학생이 실제로 읽는 글자는 전부 통제 밖이다.

> CLAUDE.md 「절대 하지 않을 것 · Typography」는 **한글에 Lora 금지**를 이미 적어 뒀다.
> 지침이 없어서 생긴 결함이 아니라, **지침을 강제하는 것이 없어서** 생긴 결함이다
> (회귀도 린트도 이 조합을 잡지 않는다).

### 2-1c. 브라우저 실측 — **웹폰트는 라틴에만 작동하고, 한글에서는 제목과 본문이 같은 글꼴이 된다** (19차)

§2-1 은 `layout.tsx` 를 읽고 내린 결론이었다. 19차에 **실제 브라우저에서** 측정했다
(`/library/vocab` · `document.fonts.ready` 이후 · canvas `measureText`).

**① 로드된 웹폰트는 4종뿐이다 — 한국어 폰트 0**

```
Plus Jakarta Sans · DM Sans · Lora · JetBrains Mono
(각각 Next.js 가 만든 _Fallback metric-adjust 페이스 동반, 총 106 face)
```

**② 웹폰트가 라틴에는 실제로 작동한다 (대조군)**
`Handgloves` 40px 폭 — 본문 스택 **213.88** vs 순수 `sans-serif` **212.85**.
값이 다르다 = **DM Sans 가 실제로 쓰이고 있다.**

**③ 그런데 한글에서는 모든 스택이 같은 값이다**

| 스택 | 해석된 font-family | 「가나다한글」 40px 폭 |
|---|---|---|
| `font-body` | `DM Sans … , sans-serif` | **200** |
| `h1` | `Lora, Iowan Old Style, Georgia, serif` | **200** |
| `font-editorial` | (동일) | **200** |
| 순수 `serif` | — | **200** |
| 순수 `sans-serif` | — | **200** |

**`serif` 와 `sans-serif` 가 한글에서 같은 폭을 낸다(`same: true`).**
반면 `Noto Sans KR` 은 **184** 로 다른 값이 나온다 — 즉 이 환경에 한국어 폰트가
「없어서」 200 이 나오는 게 아니라, **제목 스택과 본문 스택이 같은 폴백으로 수렴**한 것이다.

> **그래서 §2-1 의 결론이 한 단계 더 나빠진다.**
> 「한글이 OS 폰트로 그려진다」에서 그치지 않는다 —
> **한글에서는 제목(세리프)과 본문(산세리프)의 구분 자체가 사라진다.**
> Reading Room 의 시그니처인 「세리프 표제 + 산세 본문」이 **한국어에는 존재하지 않는다.**
> 한국어 제목과 한국어 본문은 **크기와 굵기로만** 구별되고, 이것은
> §2-4c 의 「대역이 10–13px 에 몰려 있다」와 곱해진다 —
> **구별 수단이 둘 중 하나(글꼴)를 잃은 채, 남은 하나(크기)마저 좁다.**

⚠️ **이 측정의 한계**: headless Chromium · Windows 1대에서 잰 값이다.
macOS·Android 에서는 두 generic 이 **다르게** 풀릴 수 있다.
그러나 **그 편차 자체가 §2-1 의 요지**다 — 통제하지 않으면 환경이 결정한다.
(`document.fonts.check()` 는 폴백 체인 전체를 보므로 4종 전부 `true` 를 반환한다.
**웹폰트가 한글을 가졌다는 증거가 아니다** — 이 API 로 판정하면 안 된다.)

### 2-2. 타입 스케일이 없다 — 자유 픽셀 **49종**

학습자 표면(30 컴포넌트 디렉터리 + 4 라우트 그룹) 실계수:

| | 값 |
|---|---|
| 토큰 사용 `text-[var(--t1..t3)]` | **2,316** |
| 자유 픽셀 `text-[NNpx]` | **2,611** (53%) |
| 자유 픽셀 **고유 값** | **49종** |
| 그중 반픽셀 | 7.5 · 8.5 · 9.5 · 10.5 · 11.5 · 12.5 · 13.5 · 14.5 · 15.5 · 16.5 |
| **≤10.5px** 사용 | **496회** |

`text-[11px]` 라벨과 `<Layers size={9}>` 아이콘이 들어 있다.

### 2-4b. 다크 테마는 하드코딩 색 위에서 작동하지 않는다

다크는 `app/globals.css:159` 의 `[data-theme="dark"]` 가 **토큰을 재정의**하는 방식이다.

|---|---|
| 하드코딩 색을 가진 비게임 학습자 파일 | **79** |

CLAUDE.md 「항상 지킬 것」의 `data-theme="dark"` 모든 컴포넌트 대응 필수 조항이

> ⚠️ **이 절은 정적 계수다. 결과는 §2-4b′ 의 실화면 실측으로 정정됐다** —
> 다크에서 대비가 무너지지는 **않는다**. 무너지는 것은 **위계**다. 아래를 그대로 읽지 말고 §2-4b′ 와 함께 볼 것.

가장 자주 보이는 예가 가장 나쁘다 — `components/library/PosBadge.tsx` 는

### 2-7-6. 데이터가 서로 어긋나는 자리

`/dashboard` — 우측 상단 「🔥 **3일 연속**」 배지 바로 아래에
「학습일 **28중 0일** · 리뷰 0건 · 단어 0개」와 점 28개가 전부 꺼진 스파크라인이 있다.
같은 카드가 「3일 연속」과 「0일」을 동시에 말한다. 디자인 결함이라기보다
**두 지표의 정의가 다른데 한 카드에 붙어 있는 것**이고, 학습자에게는 그냥 틀린 화면이다.

### 2-7-6c. 탐색 화면 세 곳 — 「누적으로 만든 레이아웃」 (5차)

**`/arcade` (Game Lab) — 다섯 번째 시각 정체성이지만, 타입은 여기가 가장 낫다.**
검정 캔버스 + 골드. 「VOCAFLOW RESEARCH DIVISION · 19 EXPERIMENTS」 아이브로,
「Game Lab」 60px, Recall Bay 6 / Synthesis Bay 6 / Inference Bay 7 의 만(bay) 분류 —
게임을 「실험」으로 재구성한 개념 자체는 좋고 자기 안에서 일관된다.
**그런데 이 화면의 타입 스케일(60 / 17 / 13px)이 제품에서 가장 건강하다.**
예외 구역(`/arcade`)과 `/dashboard` 가 위계를 지키고, **핵심 학습 루프
(`/hub` `/flashcard` `/wordvault` `/library/vocab`)가 가장 나쁘다.**

- 밝은 사이드바와 검정 캔버스가 **모서리 둥근 패널로 맞붙어** 페이지에 붙인 iframe 처럼 읽힌다.
  같은 뷰포트 안에 사이드바 핑크 · 캔버스 골드 · 브랜드 브라운이 공존한다
- 「단어 없이 바로 시작 · 맛보기 단어로 진행(**기록 안 됨**)」 — 결과가 저장되지 않는다는
  **결정적 고지**가 화면에서 가장 작고 대비가 낮은 11px 골드다. 위계가 뒤집혀 있다
- `Ambient켬` — 영어 단어에 한글 어미를 띄어쓰기 없이 붙인 라벨
- 하드코딩 색 51종. DESIGN_SYSTEM 의 게임 예외는 `components/game/` 대상인데
  이 파일은 `app/(main)/arcade/page.tsx` — **게임 캔버스가 아니라 런처**다

**`/wordvault/browse` — 접힌 위의 60% 가 컨트롤이다.**
소스 칩 → 「듣기 모드」 패널(경고 배너 + 4개 컨트롤군 **버튼 13개**) → 검색 + 셀렉트 2 +
토글 3 → 「전체 선택」 헤더 → **그제서야 단어 목록(y≈540)**.
듣기 패널은 상태가 「대기 중」이고 브라우저에 영어 음성이 없다고 스스로 경고하면서도 **기본 펼침**이다.

- **가장 중요한 발견**: 단어 행에 **기억 상태 색이 없다.**
  회색 점 5개(4px)와 CEFR 라벨뿐이다. Memory Decay 4색은 이 제품의 서명인데,
  **단어가 사는 자리에 그 서명이 없다.** `/flashcard` 「오늘의 큐」에만 있다
- 품사 표기가 **두 벌**이다 — 여기서는 `NOUN` `VERB` `ADJECTIVE` 8px 모노 대문자,
  다른 곳에서는 `PosBadge` 의 아이콘 + `n.` `v.` `adj.`
- 「Active Recall」 「Hide Word `H`」 「Hide Meaning `M`」 — 한국어 화면의 영어 라벨 + 8px 단축키 배지

**`/text` (My Library → Texts) — 누적 레이아웃의 표본.**

1. 상단 **페리윙클 그러데이션 배너**(≈100px)가 담은 것: 「1개를 모았어요」와
   **Books 0권 · Texts 1개 · Decks 0개 · Textbooks 0권** — 넷 중 셋이 0이다.
   그리고 이 색은 **여섯 번째 액센트**다(Reading Room·ios-purple·ModePills 바이올렛·PairFlip 네이비·Game Lab 골드 다음)
2. 「My Library」가 상단 130px 안에 **세 번** 나온다 — 사이드바 항목 · 배너 아이브로 · 배너 제목
3. **같은 4개 목적지가 두 벌로 동시에 보인다** — 사이드바 펼침 자식(Books/Texts/Decks/Textbooks)과
   300px 아래 알약 탭(Books 0 / Texts 1 / Decks 0 / Textbooks 0). 둘 다 카운트를 단다
4. 콘텐츠는 **1개짜리 캐러셀** — 350×260 카드 하나가 1000px 빈 벌판 가운데 뜨고 양옆에 `<` `>` 가 있다
5. 그 글의 제목은 **y≈874 — 접힌 아래**에 있다

세 화면 모두 같은 병이다: **결정에 필요 없는 줄이 먼저 오고, 하러 온 일이 아래로 밀린다**(§2-7-3).

### 2-7-6d. 학습 세션 실행 화면 — 제품에서 가장 좋은 자리, 그리고 같은 병 (6차)

셸을 걷어낸 실제 학습면 세 곳(`/flashcard/play` · `/spellforge/play` · `/scriptquiz/play`)을 처음 봤다.
**여기가 이 제품이 가장 잘하는 자리다.** 그리고 시스템 결함이 여기서도 똑같이 나온다.

**`/flashcard/play` — 제품 최고의 화면.**
셸이 사라지고 「study」가 Lora 56px 로 가운데 선다. IPA 가 모노로 아래에 붙고,
「머리 속에서 뜻을 떠올려보세요」가 위에 있다.

- **발명이 하나 있다** — 「첫 글자가 떠오르지 않으면: `st-`」.
  포기 버튼을 누르기 전에 **난이도를 한 칸 낮출 수단**을 준다.
  이것은 장식이 아니라 원칙 3(Desirable Difficulty)의 구현이다
- 답 버튼 두 개가 **빨강/초록이 아니다** — 웜 로즈(모르겠어요) · 웜 앰버(떠올렸어요).
  「모르겠어요」를 오답색으로 벌하지 않는다. 철학 3(Empathetic Feedback) 준수
- **그런데 그 두 버튼의 아이콘이 🤔 과 💡 이다.** 학습 루프 전체에서 가장 자주 눌리는
  **1차 결정**의 두 선택지가 이모지로 표시된다(§2-3b)
- 두 버튼의 시각 무게가 거의 같다 — 틴트 차이뿐이라 **눈으로 구분되지 않고 읽어야 한다**
- 카드가 y≈585 에서 끝나고 진행 「1 / 8」은 y≈853 에 있다. 사이 **270px 가 비어 있고**
  진행 표시가 그것이 재는 대상에서 떨어져 있다. 화면의 약 45% 만 쓴다
- 「머리 속에서」 → **「머릿속에서」**(사이시옷). 제품에서 가장 많이 반복되는 지시문의 맞춤법 오류
- 12단어짜리 화면에 서체가 **넷** — Lora(단어) · OS 산세리프(버튼·안내) · 모노(`SPACE` `st-`) · IPA

**`/spellforge/play` — 문제 글자가 통제 밖 폰트로 그려진다.**
5칸 입력 슬롯 · Tab 힌트 / Shift+Tab 나가기 / Esc 건너뛰기 키보드 트레이가 잘 만들어져 있다.
그런데:

- **자극(문제)이 「공부」 — 한글이다.** SpellForge 는 한글을 보고 영어 철자를 쓰는 과제이므로
  **한글이 곧 문항**인데, 그 글자가 OS 세리프 폴백으로 그려진다(§2-1 이 과제 자체를 때린다)
- 「정답 확인」 버튼이 **회색**이라 비활성처럼 읽힌다 — 1차 버튼 다섯 번째 처리
- 모드 선택 「기본 / 즉시 / 도전」이 **자극과 입력 사이**에 있다. 과제 한복판의 설정 컨트롤이고
  각각 ⓘ 툴팁을 단다
- 「정확도 100% | 힌트 0 | 진행 1/8」이 ~10px 로 흩어져 있다

**`/scriptquiz/play` — 정보 0 의 장식 제목이 접힌 위 120px 를 쓴다.**

- 「스크립트에 근거한 문제만 출제됩니다. 추론보다 **근거 찾기**에 집중하세요.」 —
  인식론적 프레임을 세우는 **좋은 카피**다. 이런 문장이 이 제품의 강점이다
- 그 위에 **하늘색 「QUIZ」 워드마크 72px**(≈`#5CB8E0`, **일곱 번째 액센트**)가 있다.
  헤더에 이미 「ScriptQuiz」가 있고 탭 제목도 그렇다. 120px 를 써서 아무것도 더 말하지 않는다
- 시작하기 버튼이 **네이비** — 1차 버튼 여섯 번째 처리
- 지표 라벨(문항 / 제한 시간 / 만점)이 ~9px 자간 확장, 숫자는 22px. 양극단(§2-7-1) 재현

> **1차 버튼 실측 — 최종 8종** (검토 전체에서 누적한 목록):
> ① 근접 검정(`/hub`) ② 마젠타(`/flashcard`) ③ 네이비→골드 그러데이션(`/pairflip`)
> ④ iOS 퍼플 `#AF52DE`(`/library/vocab`) ⑤ 회색(`/spellforge/play`) ⑥ 네이비(`/scriptquiz/play`)
> ⑦ 회색 비활성형(`/teacher` — §2-7-6f) ⑧ 파란 그러데이션(`/dictate/session` — §2-7-6n①).

### 2-7-6f. `/teacher` — 성장 산술이 걸린 화면이 제품에서 가장 덜 설계됐다 (7차)

`PLATFORM_AUDIT` 은 10만 학습자에 이르는 CAC 0 경로를 **「교사 3,500명 × 학급 30명」 하나로**
좁혔다. 그 경로의 첫 칸이 `/teacher` 다. 실측:

- **회색 폼 카드 두 장이 나란히 같은 무게**로 놓인다(클래스 만들기 / 초대코드로 참여).
  교사의 개설이 전략적 행동이고 학생의 참여는 후속인데, 화면은 둘을 구분하지 않는다
- **「+ 개설」 버튼이 회색**이다(입력 전 비활성). 그래서 이 화면의 1차 행동이
  **쉴 때 비활성처럼 보인다** — `/spellforge/play` 의 회색 「정답 확인」과 같은 문제이고
  1차 버튼 **일곱 번째** 처리다
- **가치 설명이 0줄이다.** 「클래스를 만들어 초대코드로 학생을 모아요」가 전부다.
  교사가 무엇을 얻는지 — 학급 현황이 어떻게 보이는지, 학생 화면이 어떤지,
  **이미 구현된 단어 과제**(`SentAssignments`/`ReceivedAssignments`)가 무엇인지 — 아무것도 없다.
  §C-6 「교사의 3분」을 통과하지 못한다
- 900px 중 **570px 이 비어 있다**
- 상단 띠의 「진단 시작」이 여전히 떠 있다 — **교사를 학습자 진단으로 끌어당긴다**

> **결함 아님으로 확인**: 두 입력이 placeholder 만으로 레이블되는 것처럼 보이지만
> `TeacherClient.tsx:154,173` 에 `aria-label` 이 있다. 접근성 규칙 위반은 아니다.

### 2-7-6g. `/csat` — 제품 최고의 글, 그리고 파이프라인 이음매가 화면에 보인다

「평가원이 유형마다 재려는 것은 좁습니다. 그래서 유형마다 볼 곳이 다릅니다.
여기 적은 절차는 전부 기출로 확인한 것이고, **통하지 않는 구간도 함께 적어 두었습니다.**」

**이 제품에서 가장 잘 쓴 문장이다.** 범위를 긋고, 근거를 밝히고, 한계를 먼저 말한다.
카드 본문도 그렇다 — 「어휘 겹침으로 자리를 정한다 — 8문항 전부에서 어휘가 가장 많이 겹치는
자리는 오답이었다」. 지어낼 수 없는 내용이고 §A-N1(자산 의존)을 통과한다.

그런데 그것을 담은 화면이 셋을 망친다:

1. **원본 마크다운이 글자로 나온다** — 「주제」 카드에 `**소재 세기**` 가 별표째 렌더된다.
   저장소 전체에 **마크다운 렌더러가 없다**(`react-markdown`·`marked`·`remark` 선언 0건 — 확인함).
   드레인이 채운 DB 문자열에 강조 표기가 들어 있고 UI 는 그대로 출력한다.
   **파이프라인 → UI 이음매가 사용자 화면에 노출된 것**이고, 같은 형태가 다른 드레인 산출물에도
   있을 수 있다(DB 계수 필요)
2. **8장 전부가 낱말 중간에서 잘린다** — 「3개대…」 「나온다…」 「2017#36 ·…」.
   가치가 **논증**인 화면에서 절 중간을 자르면 논증이 사라진다
3. **26유형이 26개 같은 타일**이다. 최근 4개년 문항 수가 52 vs 13 으로 넉 배 차이인데
   크기·무게·순서가 같다. 무엇부터 볼지 화면이 말하지 않는다
   (유일한 순서 장치가 「한 회차 주파 계획 보기 →」 텍스트 링크 하나다)

### 2-7-6h. `/library/books` — 제품 최고의 카드, 그리고 숫자 표기 세 가지

**최고의 카드**: 「만화로 읽기」 프로모 — Dickens 판화가 카드 오른쪽 가장자리까지
블리드하고, 메타 칩(90컷 · V8 · GONICK 화풍)과 골드 CTA 가 붙는다.

그 위아래가 문제다:

1. **한 줄에 숫자 표기가 세 가지** — `BOOKS 312` (원값) · `챕터 10922` (구분자 없음) ·
   `단어 31327k` (구분자 없이 `k` 접미). 세 칩이 붙어 있다.
   저장소는 `toLocaleString` **395회** · `tabular-nums` **567회**를 쓰고 있으므로
   **체계가 없는 게 아니라 여기서 빠진 것**이다
2. **「Books」 제목 아이콘이 📊(막대그래프) 이모지**다 — 책 화면에 그래프 그림이고,
   담은 상자는 스톡 오렌지다(§2-8)
3. **진단 CTA 가 한 화면에 두 번** — 상단 띠(「5분 진단이 끝나면 312권 중…」 + `진단 시작`)와
   본문 띠(「레벨을 진단하면 나에게 딱 맞는 책을…」 + `진단→`)가 570px 간격으로 같은 곳을 가리킨다
4. 그래서 **책이 y≈700 — 접힌 아래**에서 시작한다. 책을 고르러 온 화면이다

### 2-7-6o. 레일이 **단계를 나열하지 않고 서사한다** (12차 — 최대 강점)

`sidebar-config.ts` 의 각 그룹은 라벨 외에 `says` 를 갖는다. 소스 실측 6줄:

| 단계 | `says` |
|---|---|
| ① Read | 읽을 것을 고르고 만나요 |
| ② Words | **만난** 단어를 내 것으로 모아요 |
| ③ Practice | 어느 쪽이 무른지 골라 익혀요 |
| ④ Conquer | **읽던 본문으로 되돌아가** 확인해요 |
| ⑤ Complete | 들은 것을 통째로 다시 써 봐요 |

**이것은 목록이 아니라 문장 하나다.** ②의 「**만난**」은 ①을 받고,
④의 「**읽던 본문으로 되돌아가**」는 ①로 되돌아간다 —
레일이 단계를 **나열**하는 게 아니라 **루프를 이야기한다.**

§5-1③ 의 Duolingo 실증(선형 잠금 → 선택권 상실 반발)과 합치면,
**이 레일이 이 제품의 단일 최대 자산이다.** 재설계에서 가장 먼저 보호해야 한다.

>
> 그리고 하나는 **의미 충돌**이다: CONQUER 의 `#F59E0B`(앰버)는
> Memory Decay 의 shaky `#B5803A` 와 **같은 색상 계열**이다.

### 2-7-6p. `/comics` — 빈 화면이 그냥 나온다 (D5 위반, 원인 확인)

원인은 코드에 있다. `app/(main)/comics/adapted/page.tsx:152`:

**`else` 가 없다.** 목록이 비면 본문 전체가 사라진다.

| | 학습자 표면 |
|---|---|
| `.length > 0 &&` (fallback 없음) | **133회 / 78파일** |
| `.length === 0 ? … : …` (fallback 있음) | 88회 |

> ⚠️ **133 이 전부 결함은 아니다** — 배지 줄·「관련 항목」 띠처럼 없으면 안 그리는 게 맞는 자리가 많다.

> 다만 이 비율(60% 가 fallback 없음)이 §2-9 의 로딩 공백과 **같은 뿌리**임을 보여준다 —
> 「없을 때 무엇을 보여줄지」가 시스템 차원에서 정해져 있지 않다.

곁들여 `/dictate/setup` 은 **경유 전용 화면**이다 — 「받아쓸 자료를 고르는 화면으로 이동하고 있어요」
+ 「받아쓰기 열기 →」. 결정을 받지 않고 튕겨 보내므로 D5 전환 예산을 한 칸 쓴다.
다만 **자동 이동이 실패해도 누를 수 있는 수동 버튼**을 둔 것은 §2-9 의 맨 스피너보다 낫다.

## 2-1b. 한글 웹폰트 — 후보와 **실제 걸림돌** (9차)

우선순위 1(§2-1)이 「폰트 하나 추가」로 끝나지 않는다는 것을 확인했다. 1차 자료로 확인한 것만:

**후보 (Google Fonts 제공 — `next/font/google` 로 바로 쓸 수 있는 것)**

| 후보 | 계열 | 쓸 자리 | 비고 |
|---|---|---|---|
| **Noto Sans KR** | 산세리프 | `--font-body` · `--font-display` 한글 | Thin~Black · **가변 폰트 있음** |
| **Noto Serif KR** | **세리프** | **`font-editorial`(Lora) 한글 폴백** | §2-1 의 핵심 구멍을 정확히 메운다 |
| IBM Plex Sans KR | 산세리프 | `--font-body` 대안 | IBM 오픈소스 |

Pretendard · SUIT · Wanted Sans 는 **Google Fonts 에 없다** → `next/font/local` 자체 호스팅 경로.

**걸림돌 — `next/font/google` + `subsets: ['korean']` 은 한 줄 추가가 아니다**

- CJK 는 글리프가 많아 **패밀리 하나가 100개 이상의 폰트 파일로 쪼개진다.**
  전부 preload 하는 것은 말이 안 되므로 **`preload: false` 를 써야 한다**
- `preload` 를 끄면 `font-display` 기본값이 **`swap`** 으로 바뀐다 →
  첫 페인트에서 **OS 폴백으로 한 번 그려졌다가 바뀐다**(FOUT). 지금 상태(§2-1)와
  **첫 프레임이 같아 보이는 구간**이 생긴다는 뜻이고, 이건 Calm UI 관점에서 따져야 한다
- 그래서 실무 권장 경로는 **`next/font/local` + 미리 서브셋한 파일**이다

**아직 재지 않은 것 (문서 수치를 근거로 쓰지 않는다 — 이 저장소에서 직접 재야 한다)**

- 각 후보의 **실제 전송 바이트**(우리 화면이 쓰는 글자 범위 기준)
- FOUT 구간 길이와 그때의 레이아웃 이동(CLS)
- Lora(라틴) ↔ Noto Serif KR(한글)의 **x-height·베이스라인 정합** —
  §2-7-6d 의 「한 줄 안에서 폰트가 갈라지는」 문제는 폰트를 넣는다고 저절로 사라지지 않는다.
  두 폰트의 metric 이 안 맞으면 이음매가 **더** 보일 수도 있다

## 2-7-8. 타입 스케일을 올리면 무엇을 잃는가 — **거의 아무것도 잃지 않는다** (9차)

우선순위 2(타입 스케일 확정)의 유일한 반론은 **「글씨를 키우면 접힌 위 정보가 줄어든다」**였다.
그 트레이드오프를 재지 않고 결정하면 안 되므로 **실제로 재 봤다.**

방법: 실서버 1280×900 에서 각 텍스트 요소의 `fontSize` 를 세 시나리오로 올리고,
**접힌 위(y<900) 텍스트 문자 수**와 **문서 전체 높이**를 전후 비교했다.

| 시나리오 | 매핑 |
|---|---|
| minimal | <11px → 12px (10px 이하만 없앤다) |
| mid | <11→12 · 11~13.9→14 (본문 하한 14) |
| **hig** | <12→13 · 12~13.9→**15** · 14~15.4→**16** · 15.5~16.9→**17** (HIG 전면) |

**결과 — 접힌 위 문자 수 유지율 / 문서 높이 변화:**

| 화면 | 기준 접힌위 | minimal | mid | **hig** | 문서 높이 (기준→hig) |
|---|---|---|---|---|---|
| `/hub` | 580자 / 58블록 | 100% | 100% | **100%** | 961 → **961** (0%) |
| `/flashcard` | 611자 / 84블록 | 100% | 98% | **98%** | 900 → **900** (0%) |
| `/dashboard` | 1,001자 / 107블록 | 100% | 100% | **100%** | 1,211 → 1,288 (+6%) |
| `/wordvault` | 477자 / 98블록 | 100% | 97% | **97%** | 2,413 → 2,471 (+2%) |
| `/library/vocab` | 849자 / 137블록 | 100% | 95% | **95%** | 1,454 → 1,492 (+3%) |
| `/csat` | 1,574자 / 82블록 | 100% | 100% | **100%** | 2,358 → 2,488 (+6%) |
| `/practice` | 704자 / 78블록 | 101% | 99% | **97%** | 1,087 → 1,157 (+6%) |

**HIG 전면 적용의 대가는 접힌 위 정보 중앙값 −3%, 문서 높이 +0~6% 다.**
`/hub` 은 **0픽셀** 늘어난다.

왜 공짜에 가까운가 — **이 화면들은 빽빽하지 않기 때문이다.**
§2-7-3 이 이미 보였듯 `/hub`·`/flashcard` 는 접힌 위 아래로 **250–300px 를 비워 둔 채**
10–12px 로 쓴다. 작은 글씨가 정보 밀도를 사고 있는 게 아니라 **그냥 작은 것**이다.

> ⚠️ **이 측정의 한계**: 요소별 `font-size` 만 올린 순진한 시뮬레이션이다.
> 실제 재설계는 `line-height`·간격·컴포넌트 패딩도 함께 올리므로 높이 증가는 이보다 크다.
> 또 「문자 수」가 「정보량」과 같지는 않다. 그래도 **방향은 분명하다** —
> 흔히 가정하는 「크게 하면 정보가 밀린다」는 **이 저장소에서는 성립하지 않는다.**

이것으로 우선순위 2 의 주된 반론이 해소된다. 남은 것은 「어느 스케일을 쓸 것인가」이지
「올릴 것인가」가 아니다.

CLAUDE.md 는 트로피(🏆)를 완주 축하에서 금지하는데, 여기서는 **모듈 정체성**으로 쓰인다 —

## 2-8b. 난이도를 **네 가지 어휘**로 말한다 (11차)

§2-6 이 색·타이포에서, §2-8 이 아이콘에서 찾은 「체계 병존」이 **도메인 모델**에도 있다.
그리고 이쪽이 더 나쁘다 — 미감이 아니라 **이해**의 문제이기 때문이다.

| 난이도 어휘 | 학습자 표면 사용 파일 | 어디서 보이나 |
|---|---|---|
| **CEFR** (A1~C1) | **69** | `/wordvault/*` 단어 행 · `/wordvault/study` 카드 |
| **V-Level** (V1~V11) | **63** | `/library/books` 표지 배지 · `/plan` 카드 `V2` |
| **학년** (초등 저학년~고3) | **18** | `/library/vocab` 학년 카드 7장 |
| **입문~고급** (5단) | **10** | `/plan` 레벨 필터 열 |

**한 화면에 두 벌이 동시에 나온다** — `/plan` 은 왼쪽 필터가 「입문/초급/중급/중상급/고급」인데
바로 옆 카드 배지는 `V2` 다. `/library/vocab` 은 「고1 · 고2 · 고3/수능 상위」로 묶고,
`/wordvault` 는 같은 단어를 `A1` 이라 부른다.

학습자가 **네 개의 눈금자를 동시에 들고** 「내가 지금 어디쯤인가」를 계산해야 한다.
이 제품의 핵심 주장이 **「지금 읽을 수 있는 것」**인데, 그 「지금」을 재는 자가 넷이다.

> 넷이 다 필요할 수는 있다(CEFR 는 국제 표준 · V-Level 은 자체 자산 · 학년은 한국 맥락).
> 문제는 **어느 것이 학습자에게 보이는 정본인지 정해지지 않았다**는 것이다.
> §2-6 의 「정본 선언」과 같은 종류의 결정이 도메인 층에도 필요하다.

## 2-9b. 아케이드 19종 전수 — **프리미티브 채택이 가능하다는 반례** (19차)

`/play/*` 19개를 전부 열어 쟀다.

| 지표 | 값 |
|---|---|
| 공유 브리핑(`PROTOCOL`/`OBJECTIVE`/`PROCEDURE`) 보유 | **18 / 19** |
| 공통 배경색 | **1종** (`rgb(251,250,246)` — 전부 동일) |
| 브리핑 최대 글자 | 26px (19종 전부 동일) |
| **12px 미만 문자 비중** | **39 ~ 55%** (중앙값 ≈ 50%) |
| 예외 | `cascade` — 브리핑 없음 · 최대 18px |

**두 가지가 동시에 참이다.**

**① 구조는 이 저장소에서 가장 잘 지켜진 시스템이다.**
`components/game/brief/GameBriefModal.tsx` + `BriefBoard.tsx` 라는 공유 프리미티브를
**19종 중 18종(95%)이 실제로 지난다.** 섹션 구성도, 배경도, 최대 글자 크기도 같다.

> **이것이 §2-10 을 결정적으로 보강한다.**
> 「Button 프리미티브가 3% 밖에 안 쓰인다」를 「이 팀은 프리미티브를 채택하지 못한다」로 읽으면 틀린다.
> **같은 저장소가 다른 자리에서 95% 채택을 해냈다.**
> 차이는 능력이 아니라 **경로**다 — 아케이드는 브리핑을 **그 프리미티브로만** 만들 수 있었고,
> 버튼은 raw `<button>` 이라는 더 쉬운 길이 열려 있었다.
> 그러므로 우선순위 **0.5(프리미티브를 안 지나면 보이게 만들기)** 는
> 「하면 좋은 일」이 아니라 **이미 이 저장소에서 효과가 입증된 방식**이다.

**② 그런데 타이포는 제품에서 가장 나쁘다.**
브리핑 글자의 **약 절반이 12px 미만**이다(§2-4c 의 학습 화면 60~73%<14px 보다 더 작은 대역).
게다가 이 화면은 **규칙을 가르치는 유일한 자리**이고, `word-orrery` 에서 확인했듯
**3컷 스토리보드의 결과 부분이 모달 스크롤에서 잘린다**(§2-7-6r).
**가장 잘 만든 교육 장치가 가장 안 읽히는 크기로 조판돼 있다.**

`cascade` 1종만 브리핑이 없다 — 19종 중 유일한 이탈이라 의도인지 누락인지 확인이 필요하다.

## 2-10. **이 리포트의 모든 결함을 설명하는 한 숫자** (13차)

13차까지 각각 따로 세어 온 것들 — 폰트 49종 · 색 179종 · 1차 버튼 8종 · 스켈레톤 8 —
은 서로 다른 실수가 아니었다. **하나의 원인에서 나온 같은 증상**이다.

| 디자인 시스템 프리미티브 | 상태 | 학습자 표면 채택 |
|---|---|---|
| `components/ui/Button.tsx` | **209줄 · 8 variant × 3 size · loading/disabled/icon/fullWidth · WCAG AA · 44px · focus-visible · 다크 대응** | **임포트 2파일** |
| `components/ui/ios/PrimaryButton.tsx` | 160줄 | 임포트 3파일 |
| **raw `<button>`** | — | **522회 / 167파일** |
| `--ios-text-*` 9단 타입 스케일 | 완성돼 있음 | **0회** (§2-6) |
| `components/ui/Skeleton.tsx` | 있음 | 8파일 (스피너는 139회, §2-9) |
| `components/ui/EmptyState.tsx` | 70줄 | 14파일 |

**버튼을 그리는 167개 파일 중 5개(3%)만 프리미티브를 지난다.**
나머지 **522개의 `<button>` 이 각자 자기 Tailwind 클래스를 들고 있다.**

그래서:

- **1차 버튼이 8종**인 것은 여덟 번의 취향 판단이 아니라, **522번의 독립적 판단**의 결과다
- **자유 픽셀 49종**도, **비게임 색 179종**도 같은 자리에서 나온다 —
  프리미티브를 안 지나면 토큰을 지날 이유가 없다
- **다크 테마 대응이 77/79 파일에서 빠져 있는 것**(§2-4b)도 같다(결과는 §2-4b′ 로 정정 — 깨지는 것은 대비가 아니라 위계다).
  `Button.tsx` 는 CSS 변수 기반이라 다크가 **공짜**인데, raw `<button>` 은 매번 직접 해야 한다
- **빈 상태 품질이 들쭉날쭉한 것**(§2-9 · §2-7-6p)도 같다 —
  `/dashboard`·`/practice/dcp`·`/reports` 는 훌륭하고 `/comics/adapted` 는 백지다.
  **기술의 문제가 아니라 경유의 문제다**

> **그러므로 §6-0 의 「정본을 선언한다」만으로는 부족하다.**
> 정본을 선언해도 **522개의 `<button>` 은 그 선언을 지나지 않는다.**
> 필요한 것은 두 가지다 — ① 정본을 정하고 ② **정본을 지나지 않는 것이 보이게** 만드는 것
> (린트·회귀). 지금은 프리미티브를 안 써도 아무도 모른다.

이것이 「Claude Design 재설계로 품질이 올라가는가」에 대한 가장 정확한 답이다:
**올라간다. 단 새 컴포넌트를 그려서가 아니라, 이미 있는 209줄짜리 Button 을
167개 파일이 실제로 쓰게 만들어서다.**

## 3. 재설계로 **잃으면 안 되는 것** — 이미 국내 평균 위인 것

재설계 논의에서 이쪽을 먼저 못 박아 둔다. 여기를 취향으로 갈아엎으면 품질이 **내려간다**.

0. **레일의 `says` 여섯 줄** — 단계를 나열하지 않고 **루프를 서사한다**(§2-7-6o).
   「만난 단어를」이 ①을 받고 「읽던 본문으로 되돌아가」가 ①로 돌아간다.
   이 여섯 문장은 **이 제품의 단일 최대 자산**이고, 리뉴얼이 「간결하게」 지울 1순위 후보다.
1. **사이드바 레일 IA 와 그 논거.**
   `components/layout/sidebar-config.ts:1-40` 은 5단 레일(READ → WORDS → PRACTICE → CONQUER → COMPLETE)을
   클래스카드·Speak·Duolingo·Quizlet·Amazon Science 실험을 근거로 설계하고,
   **「순서는 보이되 잠그지 않는다」**는 결론과 **「레일은 현재 위치를 표시하지 않는다」**는 제약까지
   적어 놨다. 이 수준의 근거를 남긴 국내 어휘 앱은 드물다.
2. **Reading Room 아트디렉션.** 웜 오프화이트 지면 + 세리프 표제 + 3D 원근 표지 캐러셀은
   Quizlet/클래스카드의 형광 카드 그리드와 확실히 다른 관점이다. 흔한 취향이 아니다.
3. **Memory Decay 를 DB 에 저장하지 않고 R(t) 로 매번 계산한다**는 결정 — 색이 실시간 진실이다.
4. **감성 카피 자리 배분**(Lora italic = 사람 목소리 / tabular-nums = 숫자). 문서화돼 있고 지켜지고 있다.
   ⚠️ 단 **한국어에서는 Lora italic 이 성립하지 않는다**(합성 기울임 — §2-7-6n③).
   지키자는 것은 「사람의 목소리에 전용 활자 자리를 준다」는 **결정**이지 Lora italic 이라는 **수단**이 아니다.
5. **아케이드 19종의 하드코딩 색 예외** — 게임 표면은 토큰 밖이 맞다. 이건 결함이 아니다.
6. **`/dictate/session` 류의 오류 문구** — 무엇이 났는지 · 경계가 어디인지 · 잃은 것이 없다는 확인 ·
   다음 한 걸음. 재설계가 이 문장들을 「간결하게」 줄이면 **품질이 내려간다**(§2-7-6n①).
7. **`/wordvault/study` 키보드 범례와 5단 평가** — 파워유저 경로를 지운 리뉴얼은 후퇴다(§2-7-6n②).
8. **`/plan` 주간 보드** — 5축의 「혼자 × 이번 주」를 이미 점유한 유일한 화면이다(§2-7-6n③).

## 5. ③ 국내외 비교 — 어디서 이기고 어디서 지는가

### 5-1. 1차 자료로 확인된 것 (10차)

**① 클래스카드 학습 단계 = 암기 → 리콜 → 스펠 → 테스트** — 확인.
암기(전체 1차 노출) → 리콜(영→한 보기 선택) → 스펠(뜻→철자) → 테스트.
**4단 고정 순서**다.

> ⚠️ 그런데 `sidebar-config.ts:16` 은 「클래스카드(**한국 교사 1/3 사용**)」이라고 적어 뒀다.
> 그 수치의 출처는 **클래스카드 자사 홍보 문구**(「영어쌤 1/3이 선택한 스마트 단어장」)이지
> 독립 측정이 아니다. **경쟁사의 마케팅 숫자를 우리 설계 근거로 적어 둔 것**이고,
> 이 저장소가 스스로 금지한 「문서의 수치를 근거로 쓰지 않는다」와 같은 종류의 오류다.
> 설계 결론(순서를 보이되 잠그지 않는다)은 아래 ②·③ 로 충분히 선다 — **그 문구는 빼는 게 낫다.**

**② Quizlet 은 병렬** — 확인. Flashcards · Learn · Test · Match · **Blast · Blocks**
(저장소가 적어 둔 4개가 아니라 **6개**로 늘었다). 세트 페이지에서 **순서 없이 골라 들어간다.**
단 `Learn` 안에서는 적응형 시퀀싱이 있다 — 맞히면 객관식에서 주관식·플래시카드로 **난이도가 올라간다.**

**③ Duolingo 선형 전환의 대가 — 확인, 그리고 우리 결정을 뒷받침한다.**
2022 가을 tree → **단일 선형 path**. 사용자 반발의 핵심이 정확히 **「선택권 상실」**이었다 —
「어떤 레슨을 다음에 할지 고를 수 없다」. App Store 별 1개 캠페인 · Change.org 청원 ·
「Candy Crush 같다」는 비교. **Duolingo 는 되돌리지 않았고**, path 를 개선하는 쪽을 택했다.

> **이것이 `sidebar-config.ts` 의 「순서는 보이되 잠그지 않는다」를 1차 자료로 정당화한다.**
> Quizlet(병렬·안내 없음)과 Duolingo(선형·잠금) 사이의 정확한 중간이고,
> **잠갔을 때 무슨 일이 벌어지는지에 대한 실증**이 있다. 이 판단은 취향이 아니다.

### 5-1b. 경쟁사 **화면 타이포 실측** — 밀도 격차가 취향 차이가 아니다 (20차)

§5 에서 *가설*로 남겨 뒀던 「정보 밀도」를 **같은 도구로** 쟀다
(Playwright · 1280×900 · `ko-KR` · `getComputedStyle().fontSize` 문자 수 가중 — §2-4c 와 동일).

| 제품 | **<14px** | 14–16px | **≥17px** | 고유 크기 | 1차 폰트 |
|---|---|---|---|---|---|
| **Vocaflow** (7화면) | **60~73%** | 23~48% | **2~16%** | (클래스 **49종**) | Lora/DM Sans — **한글은 폴백** |
| Quizlet | **6%** | 72% | 21% | **8** | hurme_no2-webfont |
| **클래스카드** | **5%** | 16% | **80%** | 17 | **Noto Sans KR** |
| Duolingo (ko) | 15% | 32% | 54% | **8** | duolingo-sans |

**셋 다 <14px 가 5~15% 다. Vocaflow 는 60~73% 다.** 한 자릿수 배수의 차이가 아니라
**다른 체제(regime)** 다. 「우리는 정보 밀도를 택했다」로 설명되지 않는다 —
§2-7-8 이 보였듯 밀도를 사고 있지도 않다(글씨를 키워도 접힌 위 정보가 −3% 뿐이다).

그리고 두 가지가 더 나온다:

1. **클래스카드는 `Noto Sans KR` 을 로드한다** — §2-1b 가 권한 바로 그 폰트다.
   **국내 벤치마크는 이 문제를 이미 풀었고**, 그 위에 문자의 **80% 를 17px 이상**으로 놓는다.
2. **Quizlet 과 Duolingo 는 고유 크기가 8종이다.** 설계된 스케일의 실물이 8단이라는 뜻이고,
   §2-2 의 **49종**이 왜 스케일이 아닌지를 외부 준거로 확인해 준다.

> ⚠️ **비교의 한계**: 셋 다 **공개 홈/마케팅 페이지**이고 로그인 뒤 학습 화면이 아니다.
> 다만 Vocaflow 는 **공개면(`/fit`·`/pricing`)도 같은 체제**에 있고, 격차의 크기가
> 이 한계보다 훨씬 크다. 판정을 뒤집을 만한 여지는 없다고 본다.

**결론**: 「월등한 품질」은 **가능하다. 단 시각 리뉴얼로는 불가능하다.**
이기고 있는 칸(IA · **능력 지도** · 자산 · 첫인상 증명)은 전부 *구조*이고,
지고 있는 칸(한글 타이포 · 색 문법 · 밀도 · 교사 동선)도 전부 *구조*다.
새 폰트·새 그라디언트는 §F 「혁신처럼 보이지만 아닌 것」에 그대로 해당한다 — 하루면 복제된다.

그리고 10차의 확인이 결론을 한 칸 더 밀었다: **이기고 있는 칸이 「가설」이 아니라 「확인」이다.**
5단 레일과 능력 지도는 경쟁사가 **안 한 것**이 아니라 **Duolingo 가 반대로 갔다가 대가를 치른 자리**다.
그러므로 재설계의 위험은 「새로움이 없다」가 아니라 **「있는 것을 리뉴얼하다 지운다」** 쪽이다.

화면 30여 개 · 실측 4종(정적 계수 · 렌더 폰트 크기 · 스케일 시뮬레이션 · 마크다운 계수) ·

### ① Claude Design 재설계로 품질이 올라가는가 — **예. 그리고 그 일의 대부분은 발명이 아니라 정리다.**

이 저장소의 디자인 문제는 **취향이 나빠서**가 아니다. `sidebar-config.ts` 의 IA 논거,
`globals.css` 의 reduced-motion 처리, `/settings` 의 행 패턴, `/dashboard` 의 빈 상태 —
**개별 판단의 질은 국내 평균보다 확실히 높다.**

문제는 **정본이 없다**는 것이다. 같은 층에 체계가 두 벌씩 있다:

| 층 | 체계 A | 체계 B | 결과 |
|---|---|---|---|
| 타이포 | Reading Room 4폰트 | Apple HIG `--ios-text-*` 9단(**0회 사용**) | 자유 픽셀 **49종** |
| 색 | Memory Decay 의미색 4 | 스톡 Tailwind · iOS 팔레트 98토큰 | 비게임 고유 **179색** · 1차 버튼 **8종** |
| 아이콘 | lucide | 이모지(**203회 / 80파일**) | 같은 모듈이 화면마다 다른 그림 |
| 언어 | 영어 라벨(의도된 결정) | 한국어 제목 | 한 화면에서 같은 대상을 두 번 부름 |

그리고 그 어느 것도 **강제하는 회귀가 없다** — `learning-tone.test.ts` 는 콘페티·오류색·
하드코딩 ms 를 보고, **폰트·스케일·팔레트·아이콘·상시 모션은 아무도 안 본다.**

**가장 큰 한 방은 한글 웹폰트 0종**(§2-1)이다. 화면 글자의 대부분이 한글인데
디자인 시스템이 통제하는 것은 영문 라벨뿐이다.

### ② 혁신적인 디자인·플로우·단계·프로세스가 가능한가 — **예. 셋은 이미 있는데 안 보인다.**

| 이미 있는 혁신 | 지금 어디에 있나 |
|---|---|
| `/practice` **능력 지도** — 게임 19종을 Recognize/Spell/Sound/Build/Use 로 재분류 + can-do 정의 | 사이드바 3번 칸 **안쪽** |
| `/flashcard/play` **첫 글자 힌트** — 포기와 정답 사이의 난이도 한 칸 | 10px 회색 한 줄 |
| `/csat` **유형 분석 26종** — 범위·근거·한계를 먼저 말하는 글 | **별표 412개**에 덮여 있음 |
| `/text/[id]` **지문 하나 → 11모듈 모드 레일** | 1280px 에서 **오른쪽 끝이 잘린다** |
| `/plan` **주간 보드** — 자기주도 주간 편성(5축 「혼자 × 이번 주」) | 레일 **밖** · Growth 하위 카드 |
| `/wordvault/study` **키보드 우선 + 5단 평가** | 하단 작은 범례 · `1~5` 의 뜻이 안 적혀 있음 |
| `/dictate/session` **오류 문구** — 경계·데이터 보존·다음 걸음까지 | 오류가 나야만 보인다 |
| `/csat/plan` **자기 처방의 시간 예산을 재고 초과를 자백** | `/csat` 안의 텍스트 링크 하나 |
| `/diagnostic/history` **레벨 = 신뢰도 붙은 주장 + audit chain** | `/diagnostic` 안의 링크로만 |
| `/play/word-orrery` **실패 컷을 포함한 3컷 브리핑** | 9–10px · 모달에서 잘림 |

**혁신이 없는 게 아니라 혁신이 안 보인다.** 그래서 ①의 「정리」가 새 발명보다 먼저 값을 낸다.

새 발명 여지는 §B 5축의 **남은 빈 칸 넷**이다 — 학습·아케이드 표면 대부분이 (혼자 × 지금) 한 칸에 있고,
「과거의 나 × 학기 × 회상률 곡선」 · 「교사→학급 × 이번 주 × 커버리지」 · 「오답 계보」는
**새 테이블 0개 · 조인 하나**로 열린다.

### ③ 국내외보다 월등해지는가 — **가능하다. 단 리뉴얼이 아니라 정리로만.**

1차 자료로 확인한 결과, **이기고 있는 칸은 가설이 아니라 확인**이다(§5-1):
5단 레일의 「보이되 잠그지 않는다」는 Quizlet(병렬·안내 없음)과
Duolingo(선형·잠금 → **선택권 상실 반발**) 사이의 정확한 중간이고, **실증이 있다.**

지고 있는 칸(한글 타이포 · 색 문법 · 밀도 · 교사 동선)은 전부 **정리로 닫히는 것**이다.
그리고 §2-7-8 이 「크게 하면 정보가 밀린다」는 반론을 없앴다 —
**대가는 접힌 위 정보 중앙값 −3%, 문서 높이 +0~6%.** `/hub` 은 0픽셀이다.

> **그래서 이 재설계의 최대 위험은 「새로움이 부족하다」가 아니라 「있는 것을 리뉴얼하다 지운다」이다.**
> §3 의 「잃으면 안 되는 것」을 먼저 못 박고 시작해야 한다.
