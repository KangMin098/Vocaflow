# 기출 오버레이 — 「읽는 화면」을 「푸는 화면」으로 (2026-09-16)

> 대상: `/csat/overlay` (링크 모드 · 파일 모드) · `components/csat/OverlayPanel.tsx` · `lib/csat/overlay-reveal.ts`
> 성격: 결정 기록 + 실측. 수치는 전부 이 세션에 직접 잰 것이다.

---

## 1. 무엇이 틀려 있었나

의뢰는 「분석 자료가 원문 위에 자석처럼 붙게」였다. 그 절반은 **이미 서 있었다** —
2026-09-13~15 에 좌표 앵커(문제지 30개 · 문항 번호 45/45 · 사정권 기호 840/840)와
브라우저 전용 PDF 렌더, 해시 64자만 보내는 경계가 들어갔다.

붙지 않은 것은 **순서**였다. 문항 번호를 누르면 이 화면은 답·근거·오답 넷·절차를 **동시에**
펼쳤다. 거기서 학습자가 하는 일은 읽기이고, 답을 본 뒤에 읽는 근거는 재인이지 회상이 아니다
(원칙 1 Active Recall · Karpicke & Roediger 2008). **문제지를 손에 들고 있는 사람에게** 이건
가장 아까운 낭비다 — 인출을 시킬 재료가 눈앞에 있는데 안 시켰다.

그리고 더 나쁜 것이 하나 있었다. 파일 모드에 순차 공개를 넣고 같은 화면을 다시 보니
**바로 위 칸(링크 모드 옆 패널)이 서버 렌더로 답을 이미 다 펼쳐 놓고 있었다.**
아래에 문을 달고 옆벽을 터 둔 셈이었다. 이건 코드를 고치기 전에는 안 보였다 —
두 패널이 한 화면에 있다는 사실 자체가, 하나를 잠그기 전까지는 문제가 아니었기 때문이다.

## 2. 결정 (DECISIONS)

| # | 결정 | 근거 |
|---|---|---|
| D1 | 앵커를 **문장 해시**가 아니라 **좌표 + 인용 텍스트 매칭**으로 둔다 | 이미 서 있고 실측이 있다(문항 번호 45/45 · 기호 840/840). 해시 앵커는 PDF 추출 오차에 약하고, 이 저장소는 **그리는 쪽도 PDF.js** 라 좌표계가 같다 |
| D2 | 겹 만드는 규칙은 **한 곳**(`lib/csat/overlay-reveal.ts`)에 둔다 | 링크 모드와 파일 모드가 같은 분석을 **다른 이름**으로 들고 있다(`evidence_quote`/`answer_locus`). 두 벌 적으면 한쪽만 고쳐져 «화면마다 순서가 다른» 일이 생기고, 그러면 학습자가 배우는 절차가 화면 따라 달라진다 |
| D3 | 제출 전에는 해설을 **만들지 않는다**(패널에 `steps={null}`) | 감추기(`hidden`)는 도구·선택·읽기로 다 보이고, 무엇보다 설계가 코드로 하나도 지켜지지 않는다. 구조로 막아야 검사할 수 있다 |
| D4 | 겹 순서 = 근거 → 정답 → 오답(번호순) → 절차 → 어휘 | 오답부터 열면 "내가 왜 틀렸나" 로 시작해 자책이 앞선다(철학 3). `/csat/item/[slug]` 와 같은 순서 |
| D5 | **빈 겹을 만들지 않는다** | 재료 없는 카드를 끼우면 "다음" 을 눌렀는데 아무것도 안 바뀐다 — 고장으로 읽힌다 |
| D6 | 답을 **안 고르고도** 넘어갈 수 있다 | 강제하면 아무 번호나 찍는다. 그러면 정답률 기록이 거짓이 된다. 대신 `picked` 를 계측에 담아 그 비율을 본다 |
| D7 | 시간은 **재되 색을 바꾸지 않는다** | 초시계도 「정답률 빨간 글씨」와 같은 압박이다(CLAUDE.md 금지) |
| D8 | 지나온 겹은 **되돌아갈 수 있다** | 되감기 없는 순차는 그냥 불편함이다. 아직 안 연 겹만 `disabled` |
| D9 | `/csat/item/[slug]`(해설 전문)는 **열어 둔다** | 그 화면은 채점 뒤에 읽으러 가는 곳이고, 오버레이의 마지막 겹에서 «전문 보기» 로 이어진다. 거기까지 잠그면 같은 내용을 두 번 잠그는 것이다 |
| D10 | 어휘 겹은 **점선**, 근거는 **실선**, 오답 기호는 **파선** | 색 하나에 뜻 하나(E1)이되 색만으로 말하지 않는다(색맹 대응) |
| D11 | 전역 키보드는 **종이가 있는 쪽만** 건다 | 두 패널이 한 화면에 있다. 둘 다 window 에 걸면 숫자 하나가 둘을 동시에 움직인다 |
| D12 | 「밑줄 친 자리예요」는 **밑줄이 있을 때만** 말한다. 못 찾으면 배지로 드러낸다(2026-09-17) | 처음 구현은 찾든 못 찾든, 종이가 있든 없든 같은 문장을 띄웠다. 틀린 안내는 학습자를 종이 위에서 헤매게 한다 — 조용히 비우는 것보다 나쁘다 |
| D13 | 다음 문항 단추는 **마지막 겹에서만** | 중간에 두면 겹을 건너뛰는 출구가 된다 |

### 계측 — 그리고 함께 드러난 것

DB CHECK 제약에 **코드가 보내는 이름 8개가 없었다.** 그중 **6개는 오늘 만든 것이 아니다**:

```
csat_atlas_scoped · csat_plan_speed_set · csat_plan_ordered
csat_drill_answered · csat_drill_finished · csat_trap_opened
```

여섯 다 **보내고는 있었고 한 건도 안 쌓이고 있었다.** 수신구가 어떤 실패에도 204 를 주므로
화면도 콘솔도 사람도 눈치채지 못한다. 하필 그 여섯이 「오답 지도를 실제로 만지는가」·
「훈련 세트를 끝까지 가는가」 — 이 제품에서 **인출이 일어나는지**를 재려고 만든 바로 그 수들이다.

이 사고는 저장소에서 **네 번째**다(`fit_worksheet_printed` · 2026-09-06 의 5종 ·
`csat_evidence_opened` · 그리고 이번 여섯). 되풀이되는 이유는 허용 목록이 **세 곳**에 있기
때문이고, 바로 앞 마이그레이션(`20260915143000`)도 오버레이 2종만 더하며 옆의 여섯을 지나쳤다.
사람이 목록 셋을 눈으로 맞추는 한 다시 일어난다 — 지금 이것을 잡은 것은 지침이 아니라
**실제로 INSERT 해 보는 검사**(`db-allowlist.integration.test.ts`)다.

→ 마이그레이션 `20260916120000_funnel_allow_csat_rest.sql` 이 여덟을 함께 넣는다. **2026-09-17 적용** — 적용 뒤 실제 INSERT 검사 통과(전날 8건 거부 → 0).
  이 여섯의 **관측은 적용 시점부터** 시작한다. 그전 기간은 복구할 수 없다(보낸 이벤트가 어디에도 남지 않았다).

## 5. 남은 것

- **스캔본 문제지**는 텍스트 레이어가 없어 근거·어휘 밑줄이 조용히 빠진다(상자는 그대로 온다).
  클라이언트 OCR 은 넣지 않았다.
- **같은 낱말이 여러 번 나오면 첫 자리만** 표시한다(`locateQuotes` 가 첫 일치를 준다).
- payload 는 회차 한 벌을 통째로 받으므로 **분석 문자열이 브라우저 메모리에는 있다.**
  D3 가 막는 것은 DOM 렌더이고, 그것이 학습 설계가 걸린 지점이다. 문항 단위로 나눠 받으면
  메모리에서도 없앨 수 있지만 요청이 45배가 된다 — 지금은 그 값을 치르지 않는다.
- e2e 하네스: 구운 세션이 **낡으면 조용히 로그인 화면으로 튕기고**, 세 검사가 전부
  「요소를 못 찾음」으로만 보인다. 다시 구우면 4/4 통과(52.5초). 원인을 말해 주지 않는
  이 실패 모양은 따로 고칠 값이 있다.
