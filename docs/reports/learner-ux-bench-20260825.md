**현재 판정 — 사용성 105.2% ✅ · 디자인 97.4% · 연계성 94.9% · 흐름성 98.1% (달성률 25%)**

> 목표로 받은 문장: *"학습자에게 제공하는 화면 전체를 검토·분석하여 디자인·사용성·연계성·흐름성을

> 달성 가능한지**를 적는다. 인상은 적지 않는다.

## 1. 목표를 어떻게 숫자로 바꿨나

"105% 우위" 는 상대가 있어야 성립한다. 그래서 **같은 측정식**을 두 곳에 주입한다 —
Vocaflow 학습자 화면과, 대표 플랫폼의 **공개 학습 표면**.

```
우위비(축) = Vocaflow 축점수 ÷ max(플랫폼별 축점수)      목표: ≥ 1.05
```

상대를 **평균**이 아니라 **최고**로 잡는다. 평균을 쓰면 못하는 곳이 기준을 끌어내려
쉬운 목표가 된다.

### 네 축과 하위 지표 — 임계값의 출처

판단이 필요 없는 값만 넣었다. "예쁜가" 는 못 재지만 "대비가 4.5:1 인가" 는 잰다.
임계값은 전부 **공개 1차 기준**에서 가져왔다(짐작한 값은 넣지 않았다).

> **3회차 측정의 화면별 중앙값**이다(2026-08-25 · 96 측정 중 유효 74).
> 1회 측정으로 기준선을 고정하면 우리 우위가 그날 상대가 띄운 배너에 달린다 —
> 실측으로 LingQ 디자인이 두 실행 사이 88.4 ↔ 74.4 로 움직였다. 중앙값은 그 한 번을 흡수한다.
> 실제로 중앙값을 쓰자 디자인·사용성·연계성은 1회 측정과 거의 같았고, **흔들린 것은 속도(흐름성)뿐**이었다.

**못 잰 것 7건** — 점수 0 이 아니라 **분모에서 뺐다**:
Quizlet 4건(봇 차단 페이지, DOM 11~40) · 클래스카드 `b.` 2건(텍스트 0~3) · LingQ 모바일 1건.

### 이 표의 한계 — 숨기지 않는다

1. **로그인 뒤 학습 화면은 못 잰다.** 위 표는 각 플랫폼의 *공개* 표면이다. 그들의 실제 학습
   화면은 더 좋을 수도, 나쁠 수도 있다. 우리 쪽은 **로그인 뒤 실제 학습 화면**이므로
   비교가 완전히 대칭은 아니다.
2. **국내 표본이 얇다.** 국내 영어학습 서비스는 앱 전용이 많아 웹 학습 표면이 적다.
3. **실행 간 흔들린다.** 같은 커밋에서 두 번 재는 사이 LingQ 디자인 88.4 → 74.4,
   Duolingo 흐름 75 → 61.8 로 움직였다(라이브 사이트의 A/B·쿠키 배너·광고).
   **1회 측정으로 기준선을 고정하면 안 된다.** → 3차부터 `--runs 3` + 화면별 중앙값으로 바꿨다.

## 4. 판정

| 축 | 우리 | 상대 최고 | 상대 평균 | 우위비 | 결과 |
|---|---:|---:|---:|---:|---|
| 디자인 | 93.0 | 95.5 (띵커벨) | 83.1 | **97.4%** | ❌ · 상한 |
| 사용성 | 99.9 | 95 (Busuu) | 75.5 | **105.2%** | ✅ |
| 연계성 | 94.9 | 100 (스픽·Duolingo) | 71.6 | **94.9%** | ❌ · 상한 |
| 흐름성 | 98.1 | 100 (띵커벨) | 85.9 | **98.1%** | ❌ · 상한 |

**달성률 25%** (1/4 축이 105% 이상).

### ⚠️ 105% 는 세 축에서 **산술적으로 불가능**하다

점수 상한은 100 이다. 상대 최고가 95.3 을 넘으면 우리가 만점을 받아도 105% 가 나오지 않는다.

| 축 | 상대 최고 | 만점일 때 최대 우위비 |
|---|---:|---:|
| 디자인 | 95.5 | 104.7% |
| 연계성 | 100 | 100% |
| 흐름성 | 100 | 100% |
| 사용성 | 95 | 105.3% ← **여기만 가능** |

**목표를 지우지 않고 다시 적는다**:

- **사용성** — 우위비 ≥ 105% → **달성 (105.2%)**
- **디자인·연계성·흐름성** — 상대 최고와 **동률 100.0 + 그 축 하위 지표 결함 0**
  (현재 디자인 97.4% · 연계성 94.9% · 흐름성 98.1%)

달성 불가능한 목표를 "달성" 이라고 적는 것이 이 저장소가 가장 경계하는 실패다.
점수 상한을 늘리려고 채점식을 바꾸는 것도 같은 실패다(**답에 계측기를 맞추는 것**).

## 5. 계측기를 먼저 고쳤다 — 안 고쳤으면 우위가 자에서 나왔다

| 결함 | 무슨 일이 있었나 | 조치 |
|---|---|---|
| 빈 화면이 만점을 받았다 | Quizlet 봇 차단 페이지(DOM 11 · 텍스트 0)가 **디자인 100점**. 글자가 없으면 대비 위반도 0, 폰트 종수도 0 이라 전부 만점이 된다 | DOM<60 · 텍스트<5 · 컨트롤 0 · 차단 제목 → 측정 실패로 기록, 분모 제외 |
| 그라디언트 위 글자를 "대비 미달" 로 셌다 | `/arcade` 는 `radial-gradient` 로 어두운 무대를 깔고 밝은 글자를 얹는다. `backgroundColor` 가 비어 있어 흰색으로 떨어졌고 **68자 중 59자가 위반**, 디자인 31.7점 | 그라디언트·배경이미지를 만나면 **모른다고 답한다**(`contrastUnknown`). 점수로 바꾸지 않는다 |
| 로딩 스켈레톤을 그 화면 값으로 셌다 | `/diagnostic` 이 DOM 305·텍스트 15·컨트롤 6 으로 잡혔다. 같은 화면을 `10-a11y-sweep` 은 액션 버튼 12개로 잰다 — **막다른 길이라는 "제품 결함" 을 보고할 뻔했다** | networkidle + DOM 정지 900ms 대기, 얇으면 최대 3회 재측정. **양쪽에 똑같이** 적용 |
| 본문 안 탭 줄을 셸로 셌다 | 셸을 "본문 밖" 이 아니라 "nav 태그" 로 판별해, 화면 자신의 탭이 앞길에서 빠졌다 | 셸 = **본문 밖** 랜드마크로 정의 |
| `<main>` 없는 사이트의 셸 링크가 원리적으로 0 이었다 | `셸 = 전체 − 본문` 이라 상대를 구조적으로 깎았다 | 랜드마크로 직접 센다 |
| 속도가 우리에게만 유리했다 | 우리는 localhost 프로덕션 빌드, 상대는 공용 인터넷 | FCP·domInteractive 를 **판정에서 뺀다**(`flowNeutral`). 원래 값은 참고로만 |

## 6. 이번에 고친 제품 결함 — 위치 표시

**증상**: 52 측정 중 **20 이 `aria-current` 없음**. 사이드바가 아는 주소는 13개인데 정적
학습자 화면은 42개다. 모바일은 사이드바가 아예 없어 하단 탭 4개가 유일한 위치 표시인데,
활동 화면(`/arcade`·`/flashcard`·`/spellforge`·`/pairflip`·`/wordblitz`)에서 **넷 다 꺼져 있었다**.

시각적으로는 "아무 데도 아님" 이고, 스크린리더에서는 더 나쁘다 — 목록을 훑어도 현재 위치가
없어 되돌아갈 곳을 못 찾는다(WCAG 2.2 §2.4.8 Location · Nielsen #1).

**조치**: 라우트를 내비에 더 늘리지 않고(레일이 길어지면 그 자체가 결함이다) **소유 관계를
선언**했다 — `NavItem.owns` · `Surface.owns`.

| 소유자 | 떠맡은 화면 | 근거 |
|---|---|---|
| Growth (`/dashboard`) | `/diagnostic` · `/plan` · `/reports` | `ariaLabel` 이 이미 "Level·Plan·Report" 를 자기 소관이라 적고 있었다 |
| Practice (`/practice`) | `/flashcard` · `/spellforge` · `/pairflip` · `/wordblitz` | v06.202 가 도구 4개를 이 한 칸으로 접었다 |
| My Library (`/text`) | `/my/books` | 이 칸이 말하는 "내 책" 그 자체다 |
| Today (표면) | 활동 8종 | `axes.ts`: "활동은 Surface 가 아니다" — 활동 화면에서 켜지는 탭은 처방한 자리 |
| Library (표면) | `/text` · `/comics` · `/my/books` | `absorbs` 가 이미 셋을 자기 것이라 적고 있었다(산문이라 코드가 못 읽었다) |

**결과**: 연계성 축 **76.3 → 94.9** · C4(현재 위치 표시) 평균 61.5 → 96.2.

**회귀**: `components/layout/__tests__/wayfinding.test.ts` — 학습자 화면 목록을 **파일 시스템에서
읽어** 소유자 없는 화면이 하나라도 있으면 실패한다. 새 화면을 만들면서 소유자를 안 적으면
그 자리에서 잡힌다. `framework.test` 에 owns 겹침·중복·형식 3종 추가.

## 7. 3차에서 고친 것 — 사용성 105% 달성

전수 계측이 화면별로 **어떤 컨트롤이 몇 픽셀인지** 이름과 함께 뱉으므로, 고칠 곳을 찾는 데
판단이 필요 없었다. 전부 `CLAUDE.md` 의 절대 규칙(44×44)이나 WCAG 위반이다.

| 화면 | 실측 | 무엇이었나 |
|---|---|---|
| `/dashboard` | 66×18 ×3 | 카드 헤더의 "다시 측정·계획 수정·전체 보기" — 12px 글자에 히트 영역이 글자 크기 그대로였다 |
| `/plan` | 36~40px ×7종 | 자료 유형 칩·난이도 칩·설정 서랍의 행 전부 |
| `/hub` | 310×40 ×3 | "…먼저 하기" 목록 줄 — 4px 모자랐다 |
| `/diagnostic/history` | 126×20 | **이 화면의 유일한 앞길**(진단으로 돌아가기) |
| `/wordblitz` | 108×30 | 이 화면의 주 행동(바로 시작) |
| `/settings` | 31px ×5 · 128×**6** | 섹션 바로가기 알약 · **재생 속도 슬라이더**(막대 높이가 곧 히트 영역이었다) |
| `/text/new` | 36px ×4 | 되돌아가기·테마 전환·구조 토글 2종 |
| `/wordvault` · Frame 헤더 | 43×50 · 58×21 | 세그먼트 탭이 **폭 43px**(세로만 44 로 맞춰 뒀다) · 공용 헤더의 "더보기" |
| `/comics/restored` | 36px | 유형 바로가기 칩 |
| `/arcade` | 32px | 코스 보드 칩(`crs-chip`) |
| `/pairflip` · `/library/scripts` · `/library/books/[id]` | 36~40px | 모드 선택 · 주제 전환 · 미리보기 되돌아가기 |
| `/text` | 94×40 | 캐러셀의 "학습 시작" |

같은 회차에 이름·구조 결함도 함께:

- `/text/new` 의 **본문 입력 textarea 에 이름이 없었다** — 스크린리더에서 "편집" 으로만 읽혔다
  (placeholder 는 예시 문장이라 이름이 될 수 없다 · WCAG 2.2 §4.1.2)
- `/wordvault/browse` 의 검색 입력도 같은 문제 — `aria-label` 추가
- `/my/books` 는 `h1` → `h3` 로 한 단계 건너뛰었다 · `/library/scripts` 도 같은 결함(§1.3.1)

**결과**: 사용성 97 → **99.9** (우위비 105.2% ✅). U2·U3·U4·U5·U6 손실 **0**.
U1 에 남은 것은 3D 코버플로의 옆 카드뿐 — 원근 축소로 폭이 8~38px 이 되는
**의도된 예외**(가운데 카드 270px + 44px 점 인디케이터라는 대체 경로가 있다).

| 결함 | 무슨 일이 있었나 | 조치 |
|---|---|---|
| 문장 속 링크를 44px 위반으로 셌다 | "…학습하려면 **[내 자료]**에서 그 자료를 열고…" 의 인라인 링크(39×16). **WCAG 2.2 §2.5.5 는 Inline 을 명시적 예외로 둔다** — 문장 속 링크를 44px 로 키우면 줄 간격이 무너져 읽기가 더 나빠진다 | `display:inline` 이고 옆에 문장이 있으면 U1 분모에서 뺀다(양쪽 동일) |
| 키보드 전용 건너뛰기 링크를 터치 타겟으로 셌다 | `sr-only` 는 1×1 로 접혀 있다. 전 화면에서 1건씩 깎였다 | 2px 미만은 보이지도 눌리지도 않는다 — 컨트롤 집계에서 뺀다 |
| `sr-only` h1 을 "h1 없음" 으로 셌다 | `/library/textbooks` 는 시각 제목 자리가 없어 h1 을 `sr-only` 로 둔다(정석이다). 눈에 보이는 것만 세다 보니 결함으로 잡혔고, **고치는 방향이 정반대**가 될 뻔했다 | 제목·랜드마크는 **접근성 트리 기준**으로 센다(`display:none`·`aria-hidden` 만 제외) |
| 쿼리로 갈라지는 화면을 전부 "자기 자신" 으로 셌다 | `/comics/restored` 는 시리즈 13개를 `?series=` 로 가르는데, 쿼리를 버리고 세니 **앞길 1개**로 잡혔다 (`10-a11y-sweep` 도 같은 사각을 주석에 적어 두고 미뤄 뒀다) | 목적지 = **경로 + 쿼리**. 같은 화면 안 앵커(`#`)는 계속 제외 |
| 1회 측정으로 상대 기준선을 고정했다 | 같은 커밋 두 실행 사이 LingQ 디자인 88.4 ↔ 74.4 | `--runs 3` + **화면별 중앙값**. 그 결과 디자인·사용성·연계성은 안정적이고 **속도만 흔들린다**는 것이 확인됐다 |

### D4 를 이번에 쓸지 말지 — 그대로 뒀다, 이유가 있다

격자 밖 값이 **10px·6px 둘뿐**이라는 것은 이 앱의 간격이 **무작위가 아니라 체계적**이라는 뜻이다
(Tailwind 의 반 단계를 일관되게 쓴다). 그래서 "자가 틀린 것 아닌가" 를 의심했고,
**상대 값으로 확인했다**:

```
LingQ 97.4 · 띵커벨 94.5 · 스픽 82.2 · Busuu 71 / Vocaflow 68 / Duolingo 64.5 ·
YBM 54.2 · 클래스카드 53.9 · Vocabulary.com 42.5 · 케이크 35.5 · 퀴즈앤 21.8
```

지표가 **실제로 갈라지고 있고 우리는 중간**이다. 자를 바꾸면 점수는 오르지만
그건 답에 계측기를 맞추는 것이다. 그대로 두고 화면을 고치는 쪽으로 남긴다.

⚠️ 다만 **고치는 데 1,244곳이 걸린다**(`gap-1.5` 545 · `px-1.5` 171 · `py-1.5` 145 ·
`gap-2.5` 123 · `px-2.5` 116 · `py-2.5` 83 · 그 외). 화면 전체의 시각 밀도가 바뀌는
결정이라 **한 번에 쓸어 담지 않았다** — 이건 계측이 답할 수 있는 문제가 아니라
디자인 결정이다. 진행하려면 별도 승인이 필요하다.

### C2 는 부분적으로 **계정 데이터에 달려 있다**

`/scriptquiz` 는 설계상 **읽은 챕터만** 보여 준다(검증 계정은 읽은 것이 없어 빈 대기열).
`/my/books` 는 그 계정이 책 1권만 갖고 있다. `/diagnostic/history` 는 기록 열람 화면이라
되돌아가는 길 하나가 정상이다. **이 셋은 화면 결함이 아니다** — 그렇게 세는 지표의 한계다.
다음 회차에서 계정 데이터를 채운 뒤 다시 재야 판정할 수 있다.


### 4차 — 공용 컴포넌트 간격 정렬 (사용자 결정)

§9 의 두 선택지 중 **"공용 컴포넌트만 먼저"** 를 골랐다. `components/ui` · `layout` ·
`library/shared` · `hub` · `home` 의 반 단계 **66곳**을 4px 배수로 올렸다
(6px→8px · 10px→12px · 22 파일).

| | 전 | 후 |
|---|---:|---:|
| D4 4px 격자 | 68 | **78** |
| 디자인 축 | 90.5 | **93.0** |
| 우위비 | 94.8% | **97.4%** |

**남은 격자 밖 값** (전 화면 합산): 10px 1,102회 · 6px 780회 · 14px 391회 · 2px 377회 · 3px 124회.
디자인 축이 상대 최고(95.5)를 넘으려면 D4 가 **약 88** 이어야 하고, 그러려면 남은 것의
**절반쯤**을 더 정리해야 한다 — 주로 `components/plan` · `dictation` · `comic` ·
`diagnostic` 같은 기능 컴포넌트다. 그건 전면 결정이라 여기서 멈췄다.

회귀: 가로 넘침 0 · 콘솔 에러 0 · 이름 없는 컨트롤 0 · 터치 위반 27건/3화면(전부 코버플로 예외).
