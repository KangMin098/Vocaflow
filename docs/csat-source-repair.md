# 학평 정본 수리와 보류 해제

정답이나 기존 분석에서 원문을 추정하지 않는다. PDF의 해당 문항을 직접 확인하고, 파일 SHA-256과 수리 전후 값을 로컬 수리 계획에 기록한다. 원문을 담은 계획·정본 수리 레시피·코퍼스·분석 청크는 커밋하지 않는다.

`node --tls-max-v1.2 scripts/csat/source-repair.mjs --file <계획.json>`은 DB와 PDF를 대조하는 미리보기다. 계획은 `repairs` 배열이며 각 항목은 `item_id`, `pdf_file`, `pdf_sha256`, `before`, `after`를 갖는다. 수리는 학평 1~100문항의 `passage`, `choices`, `stem`만 허용한다. 선택한 모든 항목을 먼저 검증하며 정답·유형·원본 블록은 보존한다.

확인된 계획에 `--commit`을 붙이면 복원 레시피를 먼저 로컬에 보존하고 기존 값 전체를 조건으로 순차 갱신한다(문항당 350ms 대기). 다른 세션이 입력을 바꾸면 중단한다. 이미 처리한 항목은 같은 계획 재실행에서 건너뛰며, 처리하지 못한 항목만 이어간다. 레시피는 PDF 확인 기록이며 DB 반영 완료 기록은 아니다. 부분 실패 후에도 확인한 복원값은 남고, 같은 계획을 재실행해 DB·코퍼스·단위를 맞춘다. DB 체크포인트는 시작 전과 단위 생성 직후에 기록한다.

적용 후 `node --tls-max-v1.2 scripts/csat/units-build.mjs --set hakpyeong --commit`을 실행한다. 새 원문 해시를 확인한 불변 후속 청크로 분석을 다시 대조하고 사전 검사를 통과시킨다. 이전 입력·출력과 제외 검수 이력을 남긴다. 독립 검수 3인의 현재 입력에 묶인 pass만 발행 근거로 인정한다.

로컬 `scripts/csat/data/hakpyeong-source-repairs.json`은 PDF 해시와 첫 파서 입력을 유지한다. 같은 문항을 추가 수리할 때 기존 수리를 합쳐, 코퍼스를 재생성해도 확인된 복원이 사라지지 않도록 한다. 파서가 승인된 필드 일부를 스스로 복구한 경우에도 나머지 수리를 적용할 수 있다. PDF나 입력이 승인된 전후 어느 값에도 맞지 않으면 재대조가 필요하다.

2026-10-04 파서 수정은 폭이 다른 공유 문항 괄호를 인식하고, 삽입 문항 위치 보기를 다섯 표식으로 정리하며, 마지막 선지 뒤 확인사항 장식만 제거한다. 줄머리 `5.3` 같은 소수는 문항 번호로 제거하지 않는다. 코퍼스 재생성은 DB 반영과 별도다. 전체 재생성 결과를 무조건 동기화하지 말고 지정 보류 항목의 정본 대조와 새 단위·분석·검수를 마친다. 추가 수리로 대체된 옛 계획을 다시 적용하지 않는다. 최신 계획의 복원값과 현재 값이 같으면 건너뛰고, 이전 복원값으로 되돌리는 계획은 충돌로 거부한다.

검수 풀이 묶음은 문항마다 `{item_id, run_id, answer, note}` 객체로 작성하고 `validateBlindSolutions`로 전체를 먼저 검증한다. 별도의 답안·노트 배열을 순번으로 합치지 않는다. 근거 없는 `undefined`, 누락된 문항 연결, 중복 실행, 제외 실행은 첫 저장 전에 거부한다. 잘못 확정한 풀이를 발견하면 원본을 고치지 않고 `blind-invalid:<UUID>`를 기록하며 다른 독립 문맥에 재배정한다.

도표는 이미지가 풀이·공개·승인 해시에 연결되어야 한다. 현재 이미지 근거 없는 도표 발행 차단은 유지한다. PDF를 정답 공개 뒤 확인한 기록으로 독립 풀이를 대체하지 않는다.
