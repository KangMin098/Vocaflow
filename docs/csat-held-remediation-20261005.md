# 학평 보류 조치 현황

2026-10-05에 공유 DB와 실제 검수 실행을 대조했다. 보류 사유를 확인한 뒤 정본·단위 수리, 분석 교정, 독립 검수, 통과분 발행과 장부 적재를 수행했다. 사용자가 신규 도표 SQL 적용과 43파일 커밋·push를 승인했고, SQL 적용과 도표의 새 독립 3인 검수·발행까지 수행했다. 의미 근거가 부족한 두 문항은 보류를 유지한다.

## 발행과 검수

- 최신 학평 분석 2,608문항 중 2,606문항 발행, 2문항 보류다. 발행 전량을 DB 유효 검수 RPC와 최신 페르소나 판정으로 대조한 결과 독립 3인 승인 위반은 0건이다.
- 비도표 조치 대상 543문항 중 541문항을 후속 발행했다. 최신 분석·지문·근거 해시에 묶인 사전 검사 v4는 543문항 모두 통과했으며 이 결과는 독립 검수와 구분한다.
- 도표를 포함한 조치 대상 544문항 중 후속 발행은 542문항이다. 실제 제출 검수 2,718건, 조치 범위의 교정 분석 758버전을 장부에 기록했다. 같은 문항의 이전 분석·반려·최초 오답도 보존하며, 이 수를 고유 문항 수로 사용하지 않는다. 배정된 검수 lane의 미완료는 0건이다.
- 검수 장부 29배치·2,816추적 기록은 로컬과 DB 필드 대조 불일치 0건이다. 무효 블라인드 풀이의 영구 제외 641건은 모두 open을 유지한다. 과거 중단된 실행을 새 실행의 완료로 바꾸지 않는다.

입력 불변 문항은 해당 검수자의 실제 최초 풀이에 이어 재검수했다. 원문·근거 목록이 달라지거나 최초 풀이가 손상된 문항은 별도의 실제 문맥에서 풀이를 저장한 뒤 공식답·분석을 공개했다. 작성자 자체 QA는 독립 승인이 아니다.

## 도구와 P4

이슈 #145의 이름 이니셜 분할, 지문 없는 문항 export, 정본 복원, 검수 실행 재개, 원자적 장부 적재를 기존 후속 변경과 함께 검증했다. 추가로 전각 삽입 표지 뒤 공백이 없어 단위가 합쳐진 한 문항을 수정했다. 학평 2,912본문 전량 대조에서 이 문항만 단위가 6개에서 7개로 바뀌었고 나머지 2,911목록은 유지했다. 손상된 옛 세 풀이를 제외하고 새 실제 3인 풀이·재검수를 통과한 분석을 발행했다.

사전 검사 v4의 V11은 학생용 출제 의도에 반복된 특정 내부 수리 메모를 거부한다. 일반 원본 PDF 확인 지시를 금지하지 않으며 의미 결함까지 기계 통과로 보증하지 않는다. 밑줄·도표 6유형의 학습 화면은 실제 원본 크롭을 함께 표시하고 원본이 없으면 분석을 막는다. 크롭은 탭 메모리에만 유지하고 렌더 예외는 해당 문항에 격리한다.

리포트는 고1·고2에서 23유형 발행·도표 1유형 보류, 고3은 도표를 포함한 24유형 발행이다. 첫 도표 발행 뒤 집계에서 드러난 공통 절차 정의 누락을 수정하고, 발행 학년만 리포트가 만들어지는 회귀를 추가했다. 유형 미지정 16문항은 유형 집계에서 제외했다. 학평 함정 지도는 원문 예시를 내보내지 않는다. DB 통계 생성 명령도 실행했다.

## 검증과 한계

- 평가원 분석 3,140행 전체 행 해시 `ef14c7468da0fa55bbc0a62eb481de8e`, 유형 리포트 26행 해시 `cd3e34994e4e088c2990a6363d6252cc`는 기준값과 같다.
- 도구 회귀 241개 중 239통과, 선택적 환경 검사 2개 skip, 실패 0이었다. 첫 도표 발행을 집계하는 P4 절차·회귀 2파일 수정은 승인된 43파일 묶음과 별도로 커밋한다. 선택적 경로는 별도로 실제 실행해 로컬 PGlite 도표 SQL 56조건 및 읽기 전용 실 DB 블라인드 증거 9검사를 통과했다. 실 DB 테스트는 옛 NULL 근거 기록을 분석별로 보존하고 현재 단위에 묶인 정상 승인만 허용한다.
- 전체 `pnpm turbo run lint typecheck test` 15작업을 통과했다(12작업 cache hit, web lint·typecheck·test는 실제 실행). Web 4,130검사 통과·3 skip·실패 0이며 기존 lint 경고는 남아 있다. 학습 화면 관련 46검사와 관리자 검수 20검사도 통과했다. 현재 140개 복원 레시피로 코퍼스 4,680문항을 재생성한 대조의 불일치는 0이다.
- Claude 교차 리뷰의 테스트 보존 검사 지적을 수정한 뒤 재리뷰 `dd69b60f-3b08-430b-9ce5-f7fb7d38b587`에서 지적 사항이 없었다. 리뷰어는 코드를 읽었으며 위 검사는 작업자가 실제 실행했다.
- 도표 SQL의 운영 DB 적용·권한 검증·새 이미지 블라인드 검수·통과분 발행을 완료했다. 사용자 승인 범위의 커밋·push 뒤 새 CI 결과는 PR #149에서 확인한다. main 병합은 승인 범위에 포함하지 않는다.

추가 native 리뷰의 부분 원문 수리 상태 표시 결함도 수정했다. 기존 `body_ok:false`는 발문만 고치는 계획에서 지문·선지가 비어 있지 않아도 보존된다. 직접 확인한 전체 발문·지문·선지 다섯 개를 같은 PDF의 계획 `before`·`after`에 묶은 경우에만 해제한다. 새 CLI 회귀는 부분 수리 차단과 전체 수리 허용을 검증했고 로컬 경고는 모두 보존한다. 현재 140개 수리 레시피는 필드 일부만 담고 있었으며 구조 누락·빈칸 표식 누락은 0, 남은 로컬 경고는 50이었다. 부분 계획 140개라는 수를 실제 잘못 수리한 원문 140개로 해석하지 않는다. 이 읽기 전용 영향 조사와 코드 수정은 기존 DB 원문·발행 상태를 바꾸지 않았다.

도표·P4·작성 지시의 최종 반대 리뷰 `75a6d326-5caf-4f09-a21f-d079da55d957`도 지적 사항이 없었다. 이미지가 없으면 부분 분석을 작성하지 않고 보류 사유만 반환하도록 양쪽 작성 에이전트 지시를 맞췄다.

이 가드의 별도 반대 리뷰 `d2aee0b4-d638-4b5f-bbb4-3b1c7c7bf6be`는 수정 코드·CLI 회귀·도움말·영향 조사 범위를 읽고 지적 사항이 없음을 확인했다. 사용자가 승인한 43파일의 커밋·push와 처음 도표 발행 시 발견한 P4 절차 누락 수정은 구분해 커밋한다.
