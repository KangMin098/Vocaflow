# PC 학습자 Tines 디자인 개선 — Codex의 Claude Code 실행 지시문

> 작성: 2026-10-18 · Codex · 이 대화에서 생성한 5단계 지시문을 파일로 전달한다.
> 작업: T-0046 · 문서 기준: origin/main `c3a03d168`.
> 이 문서는 구현 완료 보고나 새 디자인 정본이 아니다. 스타일 정본은 루트 `DESIGN.md`이며, 실행 시 최신 사용자 지시와 저장소 정책을 함께 읽는다.

## 1. 사용자가 확정한 범위

- **일반 학습자·공개 화면: Tines 웹사이트 기준으로 개선한다.** 메인과 하위 화면, 팝업, 메뉴, 이미지, 아이콘, 디자인 구성과 동작을 포함한다.
- **학습자용 `/csat` 및 하위 전체: 기존 3B 디자인을 유지한다.** 사용자가 이 대화의 범위 질문에서 직접 선택했다.
- **관리자·모바일 웹·`apps/mobile`: 디자인 변경 대상에서 제외한다.** 공통 코드 변경이 제외 영역에 미치는 영향은 확인한다. 모바일 전용 디자인이나 검증 프로젝트를 이번 작업에 추가하지 않는다.
- 실행과 문서 정리는 Claude Code가 담당한다. 래스터 이미지 제작에서 품질 개선이 기대되는 자산은 Codex(ChatGPT) 이미지 생성을 활용할 수 있다.
- “Tines 스타일로 변경이 안되도록 하는 디자인 가이드 수정”은 문맥상 **Tines 적용을 방해하는 지침의 수정**으로 해석한다.
- 학습 콘텐츠·채점·FSRS·기억 4색·권한·기존 기능을 보존한다. 디자인 참조를 이유로 없는 기능이나 허위 수치를 추가하지 않는다.

## 2. 협업·정책 정정

1. 이 대화의 앞선 지시문에는 계획/최종 단계의 `review.mjs` 호출이 있었다. **그 자동 호출 지시는 이 문서에서 철회한다.** 최신 `origin/main`의 `AGENTS.md`·`CLAUDE.md`·`agents/router.md`는 2026-10-10 결정 RP-2026-10-10.2에 따라 자동 Codex 리뷰를 사용하지 않는다.
2. 사용자가 전달한 Claude의 “단계마다 리뷰를 허락해 달라”는 질문은 사용자 자신의 승인이 아니다. **이 트랙의 단계별 자동 리뷰는 아직 승인되지 않았다.** 기존에 한 번 받은 계획 리뷰도 향후 모든 단계의 리뷰 승인으로 확대하지 않는다.
3. 사용자에게서 이 트랙에 한정한 명시적 요청이 오면 해당 범위로만 리뷰한다. 그전에는 테스트·타입·lint·수용 기준 증거·Goal Check로 진행한다. 파일 전달이나 독립 작업을 리뷰 승인 대기 때문에 멈추지 않는다.
4. 사용자 승인이 있는 경우에도 “P0·P1만 반영”을 화면 수용 기준이나 접근성 결함을 무시하는 근거로 쓰지 않는다. 리뷰 발견사항의 처리 범위와 미해결 위험을 기록하며 등급과 실제 차단 사유를 구분한다.
5. 이 문서를 받은 Claude는 자신의 계획과 비교표를 만든다: 항목 / Codex 제안 / Claude 계획 / 차이 / 채택 방향 / 이유 / 증거. 이미 끝난 단계를 다시 실행하지 않고 부족한 범위만 보완한다.
6. Claude의 진행 파일 `docs/design/learner-tines-audit.md`와 `learner-tines-plan.md`는 실행 산출물이다. 이 파일은 그 파일을 덮어쓰지 않는 전달용 지시문이다. 다른 워크트리를 직접 수정하지 않는다.
7. 커밋·push·PR·병합·승인은 최신 사용자 지시와 현행 Git 정책을 따른다. 이 전달 작업에서는 main 병합이나 UI 구현을 수행하지 않는다.

## 3. 조사 근거와 확인 한계

이 대화의 초기 조사는 `D:/workspace/Vocaflow`의 `design/replica-first` 작업 복사본을 읽었다. 공개·사용자 페이지 후보 102개 중 CSAT 후보 12개, 그 외 90개가 관찰되었다. 이 수는 **그 복사본의 소스 후보 수**이며 현재 main의 정상 화면 수나 완료율이 아니다. Claude의 main 기반 목록에서 수가 달라지면 추가·삭제·리다이렉트·개발 경로 차이를 설명한다.

## 5. 1단계 — 작업 기반, 디자인 지침, 전수 목록

### Claude 실행 지시

1. 최신 `AGENTS.md`, `CLAUDE.md`, `apps/web/CLAUDE.md`, `agents/router.md`, `DESIGN.md`와 관련 하위 지침을 읽는다. `.agent-goal.md`의 목적·수용 기준·제외 범위를 맞춘다. 현행 작업 등록·잠금 규약을 따른다.
2. Git 상태·충돌·작업 소유권을 확인한다. 초기 조사 워크트리에는 대량 미커밋 변경과 병합 충돌이 있었다. 그 변경을 되돌리거나 임의로 해결하지 않는다. main 기준의 안전한 작업 브랜치·워크트리를 사용한다.
3. 저장소 전체 Markdown과 실제 로드되는 에이전트 지침·스킬을 검색하여 디자인 관련 문구를 목록화한다. 관련 검사·훅·테스트·CSS도 추적한다. 현행 규칙 / 과거 기록 / 생성물 / 참고 자료로 분류한다.
4. 충돌마다 파일·줄·원문·문제·수정·근거를 남긴다. 현재 Tines 적용을 막는 취향 규칙은 정리하되 접근성·보안·저작권·정직성·데이터 규칙은 유지한다. 외부 취향 스킬은 프로젝트의 사용자 지정 기준을 덮지 않는다. 설치된 외부 스킬을 일괄 변경하지 않는다.
5. 생성물은 생성 출처를 고친다. 역사 문서는 현재 기준과 구분한다. `DESIGN.md`를 스타일 정본으로 두고 중복 규칙을 늘리지 않는다.

초기 조사에서 확인한 재점검 대상(현재 브랜치에서 이미 해소했는지 먼저 확인):

### 전수 목록

- `page.tsx`, 조상 layout, loading/error/not-found, 내비게이션, 동적 import를 근거로 URL을 수집한다. 별칭·리다이렉트·폐기·개발용·역할 전용을 구분한다.

산출물은 기존 `learner-tines-audit.md`, `learner-tines-plan.md`와 충돌/수정표에 기록한다. 이 단계에서 화면을 대량 변경하지 않는다.

## 6. 2단계 — Tines 실물과 현재 화면 전수 감사

### Claude 실행 지시

1. 기존 참조 자료의 날짜와 현재 사이트 차이를 확인한다. 홈 외 제품·솔루션·목록·상세·교육·가격·폼·법률·오류 등 주요 템플릿을 조사한다. 사이트맵·내비·하위 링크를 따라 고유한 구성과 부품을 확보하고 접근 불가·중복·폐기 사유를 남긴다.
2. 실제 제공되는 메가메뉴·검색·탭·필터·FAQ·영상·쿠키 설정을 열어 본다. 관찰하지 못한 팝업이나 폼 상태를 추정해서 확보 완료로 쓰지 않는다. 문의 폼 등 외부 제출까지 실행할 필요는 없다.
3. PC 1440×900, 1280×900에서 캡처한다. 컨테이너 폭·정렬·구획 순서·여백·열 비율·타이포·면/글자색·테두리·모서리·이미지 비율·아이콘·팝업 기하·스크롤·전환을 측정한다.
4. 현재 Vocaflow는 실행 중인 서버를 재사용한다. 확인하려는 서버가 어느 워크트리/버전인지 기록한다. 별도 작업 복사본의 서버를 변경 전후 같은 버전이라고 취급하지 않는다.
5. 전수 목록의 정상 화면과 주요 팝업·분기를 직접 연다. 인증·실제 ID·데이터 조건을 해결한 뒤 캡처한다. 로그인 리다이렉트·오류·무한 로딩은 정상 렌더가 아니다. 열지 못한 상태는 미검증으로 남긴다.
6. 각 문제를 관찰 증거 → 사용자 영향 → Tines 대응 화면/부품 → 구체적 개선안 → 영향 URL·공통 부품 → 우선순위로 기록한다. 중앙 카드 반복·과도한 중첩·작은 장식 그림·정보 위계·가독성·팝업 품질을 실제 화면으로 판단한다.

참조에 다크 화면이 없으면 Vocaflow 다크는 자체 대응 설계로 구분한다. 카드나 보라색 자체를 결함으로 취급하지 않는다. 화면 유형별 참조 대응표와 개선 백로그를 갱신한다.

## 7. 3단계 — 메인과 공통 디자인·팝업 개선

### Claude 실행 지시

- `/`, 공개 헤더·메가메뉴·검색·푸터, 학습자 셸·내비, `/hub`, 버튼·입력·탭·필터·카드·목록, Dialog·시트·팝오버·툴팁·토스트를 우선한다.
- 기존 `marketing/site`, `layout`, `ui`, 토큰·스킨을 활용한다. 실제 작업 브랜치의 부품과 기능을 확인하고 없는 부품을 있다고 가정하지 않는다.
- 화면 골격·타이포·여백·색면·이미지 배치·동작을 함께 개선한다. 공통 규칙과 목적별 구성을 구분하고 모든 화면에 같은 히어로·보라 패널·카드를 반복하지 않는다.
- 학습 작업면은 집중과 밀도에 맞춘다. 기존 인터랙션·분석 이벤트·학습 기능을 보존한다. 사이트를 따라 보이게 하려고 불필요한 설정이나 팝업을 새로 만들지 않는다.
- 공통 CSS·포털 스타일을 수정하면 `/csat`, 관리자, 모바일 적용 경계를 확인한다. `.root`마다 브랜드 색·글꼴 재선언이나 임시 `!important`를 누적하지 않는다.
- 대표 화면에서 먼저 전후 검증한 뒤 공통 소비 화면으로 확장한다. 이미 확정된 Tines 방향을 다시 고르도록 새 디자인 4안이나 반복 승인을 요구하지 않는다.

팝업은 열기·확인·취소·닫기·Escape, 포커스 진입/이동/복원, 필요한 포커스 트랩, 배경 스크롤, 긴 내용·오류·내부 스크롤, body 포털 스킨을 확인한다. 양 테마·키보드·보이는 포커스·44px 조작 영역도 확인한다.

측정·비교 도구는 옵션과 실제 적용 범위를 읽고 실행한다. 초기 조사 복사본의 `ref-compare --learning/--growth`는 격리 서버 `http://127.0.0.1:3031` 전용이었다. 격리 결과를 `localhost:3000`의 실제 셸·인증·데이터 흐름 검증으로 보고하지 않는다. `--hub/--tines`도 존재·지원 범위를 확인한다.

전후 캡처·측정표·기능 검증·남은 차이를 기록하고 문서와 CHANGELOG를 함께 갱신한다.

## 8. 4단계 — 모든 학습자 화면과 이미지

### 화면별 실행 지시

전수 목록의 실제 존재 URL을 기준으로 묶음별로 구현·검증·기록한다:

| 묶음 | 대상 예시 |
|---|---|
| 탐색·상세 | library, books, scripts, textbooks, vocab, comics, video |
| 읽기·생성 | text, text/new, text/[id], comic, echo |
| 단어·반복 | wordvault, flashcard, spellforge, wordblitz, pairflip |
| 문맥·받아쓰기 | scriptquiz, dictate, practice |
| 게임 | arcade, play의 실제 게임 본체·HUD·일시정지·결과 |
| 성장 | dashboard, plan, reports, diagnostic |
| 계정·진입 | my, settings, 인증, fit, 요금제·정책·오류 |
| 연결 흐름 | 학습자에게 노출되는 과제·초대 |

각 묶음에서 정상 화면·팝업을 먼저 확인하고 대응 Tines 하위 참조를 지정한다. 목록·설정·읽기·학습·결과를 서로 다른 목적에 맞춰 개선한다. 진입→선택/입력→실행→결과→복귀, 저장·채점·학습 기록·오디오·TTS를 확인한다. 공통 머리만 바꾼 상태를 본문·팝업까지 완료로 쓰지 않는다.

### 이미지·아이콘 제작 계약

1. 현재 사용 자산·미사용 자산·중복·누락·저해상도·크롭·투명 배경·명암·그림체를 조사한다. 최근 미커밋 자산은 출처·소유권부터 확인한다.
2. 자산을 유지 / 수정 / 교체 / 추가로 분류하고 실제 URL·컴포넌트를 연결한다.
3. 기능 아이콘은 기존 Lucide 등 벡터 체계를 우선한다. 의미가 정확해야 하는 도해·차트·관계도·상태 아이콘은 SVG/CSS/코드로 구현한다.
4. 히어로·배너·편집 삽화·빈 상태의 래스터 자산은 Codex(ChatGPT) 이미지 생성 후보를 검토한다. 생성형이 항상 우수하다고 전제하지 않고 기존 자산과 실제 표시 크기에서 비교한다.
5. 제작 명세는 기존 `learner-tines-assets.md`가 있으면 갱신하고 없으면 생성한다. 필드: 자산 ID / URL·컴포넌트 / 목적 / 참조 구도·형태·색 원리 / 자체 소재 / 종횡비·해상도 / 크롭·텍스트 안전영역 / 투명 배경 여부 / 양 테마 / 후보 수 / 출력 이름 / 생성 프롬프트 / 검수 기준.
6. Tines 원본 삽화·로고를 제품 자산으로 전용하지 않는다. 자체 소재와 허용 서체를 쓴다. 제목·버튼·학습 문장은 HTML로 유지한다.
7. 연결 가능한 생성 도구가 없다면 명세를 Codex에 전달하고 독립 구현을 계속한다. 필요한 이미지가 미완성이면 의존 작업의 상태를 표시한다. 전달했다고 생성·반영 완료로 쓰지 않는다.
8. 결과 수령 후 실제 파일을 열고 크롭·잔상·그림체·명암을 검수한다. 실제 UI에서 기존 자산과 비교한 뒤 WebP/AVIF 등 적정 형식·용량, 크기 예약·alt·장식 처리·로딩 우선순위를 적용한다. 출처와 채택 이유를 기록한다.

## 9. 5단계 — 전수 재검증과 완료 판정

### Claude 실행 지시

- PC 1440×900·1280×900, 라이트·다크, 정상·감소 모션, 비로그인·인증 학습자, 실제 콘텐츠와 적용되는 빈/오류 상태를 확인한다.
- 대상 URL·동적 경로, 탭·쿼리·메뉴·검색·필터, 발견한 모든 팝업의 열기·닫기·취소·복귀를 전수 목록과 대조한다.
- 읽기→단어 저장→복습/학습→결과→회고의 실제 연결과 새로고침·뒤로가기·스크롤·sticky를 확인한다. 실제 학습 쓰기 검증은 허용된 검증 계정·환경과 DB 정책을 따른다.
- 이미지 로딩·크롭·해상도·레이아웃 이동·아이콘 정렬, 키보드·포커스·레이블·대비·조작 영역을 확인한다. 관리자·CSAT·모바일에 의도하지 않은 공통 변경이 없는지 확인한다.
- 변경 영역의 lint·타입·관련 회귀/E2E를 수행한다. 최종 통합에서는 `pnpm turbo run lint typecheck test`와 web build를 수행한다. 공유 dev와 빌드 산출물은 현행 격리 절차를 따른다.
- 디자인 테스트 설정의 실제 PC 프로젝트명을 읽고 실행한다. Windows에서 `pnpm.ps1`이 차단되면 `pnpm.cmd`를 쓴다. 불필요한 모바일 전체 실행을 완료 조건에 추가하지 않는다.
- 스냅샷 실패는 원인을 확인하고 기준선을 무조건 갱신하지 않는다. 실제 실패·기존 실패·미실행·환경 제한을 분리한다. 자동 검사 통과와 시각적 개선 판정을 구분한다.
- 에이전트 지침을 변경했다면 필요한 동기화와 `node agents/scripts/check.mjs`를 실행한다. **자동 Codex 리뷰를 호출하지 않는다.**

### 완료 보고 필수 항목

1. 범위별 전체 수 / 소스 확인 수 / 정상 렌더 수 / 상호작용 수 / 시각 검증 수 / 미검증 수와 분모 정의.
2. URL·상태·테마·뷰포트·날짜·코드 버전·입력 조건과 연결된 증거. 격리 부품 검증과 실제 셸 검증 구분.
3. 전후 화면 쌍, 이미지 교체 결과, 참조 URL·측정 대조표·남은 차이.
4. 지침 충돌 해소, 자동 검사·수동 확인·Goal Check 결과.
5. 남은 문제·이유·다음 행동, 변경 파일·커밋·PR.

대표 화면 몇 개·문서·색 토큰만으로 플랫폼 전체 완료를 선언하지 않는다. 캡처 파일 생성만으로 시각 검증했다고 쓰지 않는다. 실제 이미지와 동작을 확인한 범위만 완료로 표시한다. 개인 기록·기출 원문·인증 상태가 담긴 캡처는 현행 보관 정책을 따른다.

## 10. 이 파일을 받은 Claude의 다음 행동
