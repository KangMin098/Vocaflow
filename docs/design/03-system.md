# 03 — 디자인 시스템 「주묵 판면」 (v07)

> **[동결]** §3-9 렌더 규칙의 손으로 쓴 값은 **실물 확인 전 초안**이다. Stage 5 에서 실물(실제 라우트 캡처) 기준으로 교체된다. **수정 금지** — 고칠 것이 보이면 화면을 먼저 고치고 그 화면에서 값을 다시 뽑는다(DD-62).

확정 방향: **B 주묵(朱墨) 판면** — A 의 판면 구조(카드 없음 · 괘선 · 스케일 대비)에
**면적을 가진 색 하나**와 **데이터가 직접 그리는 표식**을 더한 것. (`02-directions.md` 참조)

> 한 줄 정의: **헤어라인으로 긋고, 자국(권점·붓 자국)으로 강조하며, 밑줄 두께는 데이터다.**

## 3-1. 타이포그래피 — 한글에 글꼴을 준다

### 역할 분담

| 역할 | 글꼴 | 라이선스 | Tailwind | 쓰는 자리 |
|---|---|---|---|---|
| 한글 디스플레이 | **Hahmlet** | SIL OFL 1.1 (Google Fonts) | `font-editorial` · `font-ko-display` | 제목 · 단어 뜻 · 감성 문장 |
| 영어 원문·표제어 | **Lora** | SIL OFL 1.1 | `font-english` · `font-editorial` | 지문 · 예문 · 표제어 · 워드마크 |
| UI·본문 (한글+라틴) | **IBM Plex Sans KR** | SIL OFL 1.1 (Google Fonts) | `font-display` · `font-body` | 라벨 · 버튼 · 설명 · 내비 |
| 숫자·코드 | **JetBrains Mono** | SIL OFL 1.1 | `font-mono` | 수치 · 키 힌트 · 식별자 |

**제거**: Plus Jakarta Sans · DM Sans (역할이 IBM Plex Sans KR 로 흡수됐다 — 같은 일을 하는
글꼴 두 벌을 둘 이유가 없고, 둘 다 한글 글리프가 없었다).

**Pretendard 를 일부러 쓰지 않았다.** 가장 안전한 선택이지만 지금 한국 웹의 상당수가 그 얼굴이라
"스크린샷 한 장으로 알아보기" 라는 목표와 정면으로 어긋난다(`01-research.md` §1-1).

### 구현 — 마크업 0줄 수정

클래스 이름(`font-display` 1,193회 · `font-body` 848회 · `font-editorial` 73회 ·
`font-english` 268회)은 **그대로 두고 스택만 갈아 끼웠다.** 이름을 바꿨다면 447파일을 손대야 했고,
손대는 순간 누락이 생긴다.

```
editorial : var(--font-serif) → var(--font-ko-display) → Lora → Hahmlet → Georgia → serif
            ↑ 글리프 단위 폴백이라 "Vocaflow 는 Lora, 되찾을 단어는 Hahmlet" 이 한 줄에서 섞인다
display   : var(--font-display) → "IBM Plex Sans KR" → system-ui → sans-serif
body      : var(--font-body)    → "IBM Plex Sans KR" → system-ui → sans-serif
english   : var(--font-serif) → Lora → Georgia → serif      ← 한글을 일부러 안 넣는다(영문 전용면)
mono      : var(--font-mono) → JetBrains Mono → … → var(--font-body) → monospace
            ↑ 한글이 모노 폴백으로 떨어지던 27노드를 막는다
```

`h1~h6` 기본 글꼴도 **세리프로 바꿨다**(영문 Lora + 한글 Hahmlet, weight 800→600).
이전에는 화면에서 가장 큰 글자가 가장 개성 없는 글자였다. `word-break: keep-all` 동반(CLAUDE.md I7).

### ⚠️ 성능 — `preload: false` 는 취향이 아니라 필수다

Google Fonts 의 한글은 `unicode-range` 로 **수백 조각**으로 쪼개져 온다. `next/font` 의
`preload` 기본값은 `true` 이고, 루트 레이아웃에서 켜면 **조각 전부를 preload** 한다
(공개 사례: 281조각 2.32MB 가 모든 페이지에서). 그래서 한글 두 벌은 `preload: false` 로 선언하고,
`subsets` 는 지정하지 않는다(next/font 목록에 `korean` 서브셋이 등재돼 있지 않아, 지정하면
오히려 라틴만 받아 온다).

> 이 실수는 **화면을 깨지 않고 느리게만 만든다** = 혼자서는 절대 발견되지 않는다.
> 그래서 회귀가 잡는다 — `learning-tone.test.ts` 「한글 글꼴에 preload 를 켜지 않는다」.

### 실측 확인

| 항목 | 값 |
|---|---|
| 한글이 실제 웹폰트로 그려지는가 | ✅ 「되찾을 단어」 렌더 폭 Hahmlet **117.55px** vs serif 폴백 128px — 폴백 아님 |
| 라우트 전송 폰트 | `/hub`·`/dashboard` 실측 — 아래 §3-7 |

## 3-2. 색 — 주묵(朱墨) 하나가 면적을 갖는다

### 왜 색 하나인가
`/dashboard` 실측에서 본문 글자색 **136/144(94%)** 가 같은 잉크 한 색의 알파 3단계였고,
브랜드 액센트를 글자로 쓴 노드는 **0개**였다. 차분한 게 아니라 **색이 없었다**.
2026 트렌드 기사들은 5~7색 시스템을 말하지만 이 제품에는 안 맞는다(학습원칙 6 인지부하).
**한 색을 크게** 쓴다.

### 토큰

| 토큰 | 라이트 | 다크 | 용도 |
|---|---|---|---|
| `--ju` | `#C0392B` | `#E0705C` | 면·선·표식. 브랜드가 면적으로 있는 자리 |
| `--ju-ink` | `#A8342A` | `#E0705C` | 작은 글자 |
| `--ju-light` | `#F5E4E0` | `rgba(224,112,92,.18)` | 활성 행 배경 |
| `--ju-wash` | `rgba(192,57,43,.13)` | `rgba(224,112,92,.20)` | 붓 자국(skew) |
| `--on-ju` | `#FFF7F0` | `#231D17` | 주묵 채움 위 글자 |

**대비 실측(WCAG 2.1)**: `--ju` 글자 on `--bg` **5.20:1** · 흰 글자 on `--ju` 채움 **5.13:1** ·
`--ju-ink` on `--bg` **6.34:1** · 다크 `--ju` on `--bg` **5.27:1** / on `--bg2` **5.79:1**.
(라이트 값 `#C0392B` 를 다크에 그대로 쓰면 3.07:1 로 미달 — 그래서 테마마다 뒤집는다.)

### 분류 팔레트 — 원색을 지면 색조로, **개수를 보존해서**

학습자 화면에는 정보를 나르는 팔레트가 둘 있다(POS 배지 8색 · 사이드바 그룹 6색).
일반 Tailwind 색조를 같은 구분력의 지면 색조로 **1:1** 로 옮긴다 — 한 색으로 접으면 구분이 사라진다.

| 일반(이전) | 지면(지금) | 토큰 |
|---|---|---|
| indigo `#6366F1` · blue `#3B82F6` | dusty blue | `--learn-fresh` `#50697F` |
| violet `#8B5CF6` `#7C3AED` | deep ink | `--p` `#0F2540` |
| amber `#F59E0B` | deeper warm amber | `--memory-shaky` `#B5803A` |
| emerald `#10B981` `#22C55E` | muted forest | `--memory-stable` `#2E7D5A` |
| cyan `#06B6D4` | muted teal | `--learn-progress` `#2F6E6B` |
| pink `#EC4899` | **muted plum (신규)** | `--accent-plum` `#7A4A6B` (다크 `#C79AB6`) |
| slate `#64748B` | warm gray | `--memory-new` `#8A8278` |
| red `#EF4444` | 중립 흑연 | `--learn-error` `#6B6258` |

`--accent-plum` 은 여섯 번째 색조가 필요해서 새로 만들었다. **주묵과 헷갈리면 안 되므로
색상환에서 붉은 쪽이 아니라 자주 쪽으로** 뺐다(종이 위 6.25:1 · 흰 글자 위 5.35:1, 둘 다 AA).

**모듈 전용 팔레트** — 아케이드(`components/game/`) · PairFlip 모듈 팔레트(`#F59E0B` `#FCD34D`
`#1E3A8A→#1E1B4B`) · SpellForge 패널 · WordBlitz 정글 · 만화 표지 장르색(아트워크).
`DESIGN_SYSTEM.md` §게임 전용 하드코딩 색상 이 정본이다.

⚠️ **canvas 는 `var()` 를 못 읽는다.** `ctx.strokeStyle = 'var(--x)'` 은 조용히 무시되고
기본 검정으로 그려진다(오류도 안 난다). `components/echo/PitchVisualizer.tsx` 두 상수만
실제 hex 로 두고 그 이유를 파일에 적어 뒀다.

### 주묵이 쓰이는 자리 (현행)

워드마크 · 사이드바 활성 표식 · 하단 탭 활성 · 1차 CTA · 완료 체크 · 권점(圈點) · 「지금」 표식 · 나침반 띠 CTA.
(「쓰지 않는 자리」 규칙 표는 DD-66 으로 삭제.)

### 오답을 빨강에서 뺐다

한 화면에 붉은색이 둘이면 "앱이 남긴 표식" 과 "내가 틀렸다는 낙인" 이 구별되지 않는다.

(2026-09-16 기록. 그 금지 문구는 DD-66 으로 삭제됐고, 아래 토큰 값은 현행 그대로다.)

## 3-3. 형태 — 헤어라인으로 긋는다

### 그림자를 헤어라인 링으로

```css
--sh-xs / --sh-sm / --sh-md / --sh-lg / --sh-xl   → 0 0 0 1px var(--bd)
--sh-ios-1 / --sh-ios-2 / --sh-ios-3              → 0 0 0 1px var(--bd)
--sh-card                                          → 0 0 0 1px var(--bd)
--sh-ios-button                                    → none
/* 실제로 떠야 하는 것만 남긴다 — 모달 · 바텀시트 · 토스트 · 팝오버 */
--sh-float  /  --sh-ios-4  → 0 0 0 1px var(--bd), 0 18px 48px -12px rgba(26,23,20,.22)
```

컴포넌트 **235곳을 손대지 않고** `box-shadow` 한 줄의 의미만 바꿔 카드가 판면이 된다.
(0으로 두지 않은 이유: 카드면 `--bg` 와 캔버스 `--bg2` 의 톤차가 3%뿐이라 경계가 사라진다.)

### radius 두 벌을 하나로

| 토큰 | 이전 | 지금 |
|---|---|---|
| `--r-sm` / `--r-md` / `--r-lg` / `--r-xl` / `--r-2xl` | 6 / 8 / 12 / 16 / 24 | **2 / 3 / 4 / 5 / 6** |
| `--r-ios-xs … --r-ios-3xl` | 6 / 8 / 12 / 14 / 18 / 24 / 32 | **2 / 2 / 3 / 4 / 4 / 6 / 8** |
| `--r-ios-modal` | 38 | **10** (시트는 실제로 뜨므로 조금 남긴다) |
| `--r-full` / `--r-ios-pill` | 9999 | **9999** (원형이 의미인 자리) |

이름은 그대로 둔다 — 484 + 223 + 172회 쓰인 클래스를 바꾸면 반드시 누락이 생긴다.

**실측 효과**: 한 라우트에 섞여 있던 radius 종류 `/dashboard` 4 → **3**(4px·6px·3px),
값 자체가 8~24px → **2~6px** 로 내려갔다.

## 3-4. 시그니처 장치 — 데이터가 직접 그리는 것

### DecayUnderline — 밑줄 두께 = 망각도

이 시스템에서 **유일하게 데이터가 형태를 정하는** 요소다.

| 상태 | 두께 | 선 | 색 |
|---|---|---|---|
| risk (흐릿해요) | **3px** | solid | `--memory-risk` |
| shaky (익숙해요) | **2px** | solid | `--memory-shaky` |
| stable (알아요) | **1px** | solid | `--memory-stable` |
| new (처음 만나요) | 2px | **dotted** | `--memory-new` |

- **왜 중요한가**: `lib/srs/fsrs.ts` 의 R(t) 없이는 그을 수 없는 선이다. 경쟁사가 폰트와 색을
  베껴도 이 선은 못 베낀다(vocaflow-design §A N1 을 통과하는 유일한 장치).
- **접근성**: 색이 아니라 **두께**가 정보를 나른다 → CLAUDE.md 「색상만으로 정보 전달 금지」를
  장치 자체가 충족한다. `sr-only` 로 상태 이름도 함께 읽힌다.
- FSRS 상태를 들고 오지 않는 표면(`ReadingRoomWord` 등)은 `bandFromOverdue(overdueDays)` 로
  **실제로 가진 값**을 두께로 옮긴다 — 상태를 지어내지 않는다.

### 그 밖의 어휘 (`components/ui/press`)

| 컴포넌트 | 하는 일 |
|---|---|
| `Rule` | 섹션 괘선 + 번호(`01`) + 라벨. 구획을 상자가 아니라 선으로 만든다 |
| `Panel` | 판면 표면. `paper` / `canvas` / `ju` 3톤 |
| `Wash` | 숫자·낱말 뒤 붓 자국(9° skew, `--ju-wash`). 장식이라 `aria-hidden` |
| `JuMark` | `dot` 권점 · `check` 마친 것 · `now` 지금 할 것. 전부 스크린리더 라벨 필수 |
| `SealMark` | 낙관(落款) — 라벨 첫 글자를 Hahmlet 으로 주묵 테두리 안에 찍는다. 분류 타일·목표 카드가 **이모지로 얼굴을 삼던 자리**를 대신한다(`sm` 28 · `md` 36 · `lg` 44px · `inverse` 톤). 라벨이 옆에 있으므로 `aria-hidden` |
| `Gwonjeom` | 권점(圈點) 아이콘 — lucide `Sparkles` 의 자리. `createLucideIcon` 으로 만들어 **`LucideIcon` 과 같은 타입**(호출부는 이름만 바꾼다). 「추천·새것·눈여겨볼 것」 |
| `PressButton` | 1차(주묵 채움) / 2차(잉크 외곽) / 3차(글자만). 48px 하한 · 4상태 |
| `Eyebrow` | 작은 라벨. 현행: 대문자 변환·넓은 트래킹 없음 |

> 기존 `components/ui/Card.tsx`(shadcn 형)는 학습자 447파일 중 **5개만** 쓰고 있었다.
> 그래서 "더 예쁜 카드" 를 만들지 않고 **카드가 아닌 어휘**를 만들었다.

## 3-6. 모션 — 방식을 판면에 맞춘다

## 3-7. 성능 실측 — 한글 웹폰트의 실제 비용

(측정 2026-09-16 · 390×844 · 콜드 캐시 · dev 서버 · 공개 라우트)

| 라우트 | 폰트 요청 | 전송량 | `<link rel=preload as=font>` |
|---|---|---|---|
| `/pricing` | 37건 | **372.7 KB** | **0** ✅ |
| `/about` | 37건 | **373.3 KB** | **0** ✅ |

**`preload` 링크 0개**가 가장 중요한 숫자다. 1개라도 있으면 한글 `unicode-range` 조각을
전량 preload 하는 경로가 되살아난 것이다(공개 사례 281조각 2.32MB).
지금은 브라우저가 화면에 실제로 쓰인 글자의 조각만 가져간다.

**정직하게 적는다 — 이건 비용이다.** 이전(라틴 4종)에는 폰트가 훨씬 가벼웠다.
373KB 는 한글 두 벌 + Lora + Mono 가 **그 페이지에 실제로 쓰인 글자만큼** 받아 온 양이고,
한 번 받으면 캐시된다. 그래도 요청 37건은 많다. 줄일 여지:

1. ~~`--font-display` 와 `--font-body` 를 각각 `IBM_Plex_Sans_KR()` 로 선언해 **같은 글꼴을
   두 벌** 받고 있었다~~ → 한 번만 선언하고 `--font-body` 를 CSS 별칭으로 이었다(적용함).
2. Hahmlet 5웨이트 → 실제 쓰는 3웨이트로 줄이기 (미적용 · 다음 단계)
3. 한글 본문을 한 벌로 통일하고 디스플레이는 제목에만 (이미 그 구조다)

> ⚠️ 위 표는 **중복 선언을 걷어내기 전** 값이다. 걷어낸 뒤 값은 dev 서버가 설정을 다시 문
> 다음에 재측정해야 한다(`scratchpad/fontcost2.mjs` 와 같은 방식). 재지 않은 개선을
> 개선이라고 적지 않는다.
