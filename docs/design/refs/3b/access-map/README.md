# 3B 참조 맞추기 — 측정 → 명세 → 변수 → 가드

> 참조 앱(`neon-currant.3b.dev`)을 따라 만드는 화면(학습 지도 · 팝업 등)이 **「요청한 대로」 안 맞던 이유와, 다시 어긋나지 않게 하는 절차**다.
> 정본 수치: [spec.json](./spec.json) · 참조 캡처: 이 폴더의 PNG · 코드: `scripts/design/ref-measure.mjs` · `ref-compare.mjs`.

## 왜 어긋났나 (2026-10-03 진단)

1. **참조를 에이전트가 열 수 없다.** 인증이 걸린 SPA 라 가져오면 본문이 `3B` 한 줄이다 → 계산된 크기·간격을 못 얻었다.
2. **눈대중 근사 + 「느낌」 보고.** 번들 CSS 에서 읽은 색 토큰과 캡처를 눈으로 보고 비슷하게 만든 뒤 「참조와 같은 느낌」이라고 보고했다. 크기·간격·구조를 **측정해 대조한 적이 없었다.**
3. **기하가 달랐다.** 참조는 노드 폭·열 간격이 **고정**(206×46, 피치 272)인데, 우리 지도는 화면 폭에 따라 늘어나는 반응형이었다 — 큰 화면일수록 다르게 보인다.
4. **구조가 달랐다.** 참조는 판 안의 판(머리 줄 + 구분선 + 노드 줄)인데 우리는 카드 한 덩이였다.

## 절차 (참조 화면을 따라 만들 때)

1. **캡처 저장** — 사용자가 준 스크린샷을 이 폴더에 둔다. **PNG 는 gitignore**(참조 앱 화면이라 저장소에 남기지 않는다 — 저장소에 남는 것은 spec.json 의 수치뿐). 다른 작업 트리에서 다시 재려면 같은 캡처를 사용자에게 다시 받는다. 가능하면 뷰포트 폭을 함께 적는다(이 캡처들은 2094px 폭, DPR 1 로 본다 — 본문 12px 과 맞는다).
2. **측정** — `pnpm design:ref-measure <png> [--color fbf9f7 --min-w … --max-w …]`. 흰 카드 · 옅은 면의 사각형을 픽셀 단위로 잰다(노드 폭·높이·열 피치·행 피치·카드 간격).
   패널 테두리 · 구분선 · 모달 바깥 사각형 · 대표 색은 `node scripts/design/ref-scan.mjs <png> --lines | --box x,y | --color x,y` 로, 열 머리 글자의 x 는 `--text y0,y1`(가로 띠의 글자 덩어리)로 잰다.
3. **명세** — 잰 숫자를 [spec.json](./spec.json) 에 적는다(노드 · 열 · 행 · 패널 · 모달). **코드를 먼저 고치지 않는다.**
4. **변수** — `map.module.css` 의 `.root` 맨 위 `--g-*`(지도) · `--p-*`(팝업)가 spec.json 의 값이다. 다른 곳에 크기 숫자를 다시 쓰지 않는다.
5. **가드(CI)** — `geometry.test.ts` 가 CSS 변수와 spec.json 이 같은지 본다. 눈대중으로 고치면 떨어진다.
6. **실측 대조** — `pnpm design:ref-compare`(dev 서버 필요, 런타임 테스트 계정). 참조 캡처와 같은 뷰포트로 열어 노드 · 머리 줄 · 모달 · 카드 간격을 재서 표로 낸다. 하나라도 ±2px 를 넘으면 실패.
7. **완료 보고에 그 표를 붙인다.** 표가 없으면 「참조와 같다」고 쓰지 않는다.

## 팝업 · 그래프 패턴

참조의 모든 팝업(Skill · Space · Group · Member · 역할 상세)과 Access map 화면의 부품은 [popup-patterns.md](./popup-patterns.md) 에 정리했다. 새 팝업은 거기 표의 부품(`PopupParts.tsx`)으로 조합한다.

## 새 참조 화면을 더할 때

PNG 를 이 폴더에 넣고 2–5 를 반복한다. 화면마다 `spec.json` 에 키를 하나 더한다(예: `modal` · `panel`). 측정이 안 되는 것(글자 크기 · 굵기 · 그림자 · 모서리 반경)은 아직 눈대중이다 — 아래 「한계」.

## 글자 크기 (2026-10-07)

참조 캡처에는 DOM 이 없어 font-size 를 바로 못 읽는다. 대신 **같은 문자 체계 · 같은 역할의 글자 잉크 높이**를 참조와 우리 화면(같은 뷰포트 · DPR 1)에서 같은 도구로 재서 비율을 낸다.
1. 참조: `node scripts/design/ref-scan.mjs <png> --ink x0,y0 x1,y1` (사이드바 Recents · 노드 이름 서준 강)
2. 우리: `node --env-file=<.env.local> scripts/design/ours-text-metrics.mjs` → 같은 글자의 DOM font-size + 화면 위치 → 같은 `--ink` 로 잰다
3. 비율을 spec.json `type` 에 적고 globals.css `--csat-fs-scale` · `--csat-fs-min` 으로만 쓴다. `type-scale.test.ts` 가 명세 = 토큰 · /csat 모듈 CSS 에 고정 px font-size 0 을 지킨다.

## 한계와 더 정확한 길

- 스크린샷 측정은 **크기·간격·색**까지다. **글자 크기 · 굵기 · 모서리 반경 · 그림자**는 DOM 이 없어 눈대중이다.
- 이것까지 정확히 맞추려면 로그인된 브라우저에서 해당 화면을 **Ctrl+S → 「웹페이지, 전체」** 로 저장해 경로를 주면 된다(`../CAPTURE.md`).
  그러면 `scripts/design/extract-computed.mjs` 가 계산된 값(px)을 그대로 뽑아 spec.json 의 눈대중 항목을 대체한다.
- DPR 은 1 로 가정했다(본문 12px 과 일치). 다르면 spec.json 의 `measuredFrom` 을 고치고 값을 환산한다.
