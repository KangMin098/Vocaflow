> 2026-09-20 · 브랜치 `design/admin-evidence` · 작성 Claude Code · 절차 [06-workflow](06-workflow.md) · 발명 정본 [vocaflow-design](../../.claude/skills/vocaflow-design/SKILL.md)

## 0. 왜 이 트랙이 필요한가

관리자 콘솔은 **화면 60개**로 이 저장소에서 가장 큰 표면인데, 디자인 결정이 두 번 갈렸다:

- 2026-09-18 DD-01: 액센트를 옛 보라 `#8B5CF6` → **`--p` Deep Ink** 로 바꾸고, 관리자 구분은 **색이 아니라 `ShieldCheck` + 「Admin」 텍스트**가 지기로 했다.
- 그런데 옛 보라는 **여전히 204곳**에 남아 있고(평균 신호 라쳇 기준 318), 라쳇은 **감소만** 허용한다 — 즉 "줄여라"는 방향만 있고 **무엇으로 대체하는가**가 비어 있다.

그 빈 칸을 이 브리프가 채운다. 질문은 하나다: **관리자 화면임을 무엇이 말하는가.**

## 1. 전수 감사 (실측 2026-09-20)

### 1-1. 규모

| 항목 | 값 | 어떻게 셌나 |
|---|---|---|
| 관리자 화면(`page.tsx`) | **60** | `find src/app/admin -name page.tsx` |
| 관리자 `.tsx` 전체 | **245** | `find src/app/admin src/components/admin -name '*.tsx'` |
| 화면도움말이 붙은 화면 | **59 / 60** | 화면 폴더 단위로 `AdminScreenHelp` 존재 확인(페이지가 아니라 클라이언트 컴포넌트에 붙는 경우가 많다). 도움말 항목은 41개(`lib/admin/help/*.ts` — 탭이 항목을 공유한다) |
| 도움말 없는 화면 | **`/admin/vocab/runs/[id]/seed/preview`** 1곳 | 위 검사에서 유일하게 걸린 폴더 |
| 섹션(라우트 1단) | vocab 11 · csat 11 · vrl 7 · kice 6 · quality 3 · comic 3 · pd-comics 2 · curation 2 · articles 2 · 기타 7 | 라우트 경로 집계 |

### 1-2. 형태 — **골격 선언 0/60**

| 항목 | 값 |
|---|---|
| `// @form:` 선언이 있는 관리자 화면 | **0 / 60** |
| 즉 | 관리자 화면 전부가 골격 선언 라쳇의 **기준선 목록**에 있다(150개 중 60개가 관리자) |

라쳇은 후퇴만 막으므로(새 화면은 선언 필수), **기존 60화면의 골격은 아직 아무도 말한 적이 없다.**
이것이 관리자 콘솔이 「표 + 카드 + 3열」로 수렴한 구조적 이유다 — 형태를 고르지 않으면 그릇이 기본값으로 온다(§G2).

### 1-3. 평균 신호 (관리자 표면 · 라쳇 기준선)

| 신호 | 관리자 | 학습자 | 읽는 법 |
|---|---|---|---|
| `ai-purple` | **318** | 38 | 옛 보라 계열. 관리자가 **8.4배** — 이 트랙의 주 대상 |
| `grid-3eq` | 35 | 58 | 3열 균등 격자 |
| `gradient` | 36 | 167 | 장식 그라디언트 |
| `glass` | 7 | 49 | glassmorphism |
| `float-hover` | 8 | 64 | 떠오르는 hover |
| `rounded-big` | 4 | — | 12px+ 둥근 카드 |
| `shadow-heavy` · `infinite-anim` | **0** | 0 | 이미 0 — 지켜야 할 값 |

### 1-4. 판면 방식이 갈려 있다

| 방식 | 파일 수 | 비고 |
|---|---|---|
| Tailwind 클래스 | 236 / 245 | 대부분 |
| CSS 모듈 | **9** | 새 CSAT 화면들(`evidence.module.css` · `sources.module.css` · `source-operations.module.css` …) |

⚠️ 이 갈림은 **접근성 검사에 구멍을 낸다**: 44px 터치 타깃 스캐너는 Tailwind 클래스만 읽으므로,
CSS 모듈 화면의 버튼은 「판정 불가」로 빠진다(2026-09-20 에 판정 불가가 78 → 150 으로 뛴 이유 · DD-51).
지금은 그 5화면의 CSS 가 `min-height: 44px` 을 일괄 보장하는지 테스트가 직접 확인하는 방식으로 막아 두었다.
**형태를 고를 때 판면 방식도 하나로 정해야 한다** — 두 벌이면 검사도 두 벌이 필요하다.

## 2. 액센트 3안 (고르는 것은 사람)

공통 전제 — 세 안 모두 이것을 지킨다:
- 새 색이 필요하면 `tokens.css` 에 이름으로 추가한다. (「토큰만 · 하드코딩 색 0」 전제는 DD-66 으로 삭제.)
- **색만으로 정보를 전달하지 않는다**(접근성) — 색에는 반드시 형태·텍스트가 붙는다.
- (옛 보라 감소 전제 · 관리자 N4 예외 없음 전제는 DD-66 으로 삭제.) 고른 안이 어떤 G1 축과 짝이 되는지는 참고로 함께 적었다.

### 안 A — 「같은 잉크, 다른 종이」 (액센트를 없앤다)

| 항목 | 내용 |
|---|---|
| 원리 | 관리자와 학습자가 **같은 `--p`** 를 쓰고, 다른 것은 **지면**이다. 관리자는 `--bg2`(page canvas)를 기본 바탕으로 깔고 학습자는 `--bg`. 액센트 색은 하나도 추가하지 않는다 |
| 구분 신호 | 지면 톤 + `ShieldCheck` + 「Admin」 (DD-01 그대로, 지면을 한 겹 더) |
| 토큰 | 추가 0. `--bg2` · `--bd` · `--p` 만 |
| G1 축 짝 | **환경 변형** — 「지금 어디에 있는가」를 색이 아니라 환경이 말한다(철학 4 Implicit Progress 와 같은 어법) |
| 옛 보라 318 | 전부 `--p` 로 교체(가장 큰 작업량) |
| 강점 | 토큰이 늘지 않는다 · 다크 모드 자동 · 학습자 앱과 한 몸으로 읽힌다 |
| 약점 | 관리자·학습자 화면이 **스크린샷에서 구별이 어렵다**(운영 사고 때 어느 쪽 화면인지 헷갈린다) |

### 안 B — 「주묵 도장」 (브랜드 색을 관리자 표식에만)

| 항목 | 내용 |
|---|---|
| 원리 | 액센트는 `--p` 로 통일하되, **관리자에서만** `--ju`(주묵 `#C0392B`)를 **도장·표식 자리에만** 쓴다. 면이 아니라 **점·선**이다: 헤더 도장, 파괴적 동작 버튼의 테두리, 활성 행의 왼쪽 2px |
| 구분 신호 | 주묵 도장(형태) + `ShieldCheck` + 「Admin」 — 셋이 겹친다 |
| 토큰 | 추가 0. `--ju` · `--ju-ink` · `--ju-light` 는 이미 있다(v07 판면) |
| G1 축 짝 | **주묵 문법** — 실선=지지 · 점선=배제 어휘가 이미 있고, 관리자 파이프라인 화면의 「막힌 곳」 표시에 그대로 쓸 수 있다 |
| 옛 보라 318 | `--p`(구조) + `--ju`(표식)로 갈라 교체 |
| 강점 | 브랜드가 면적이 아니라 **표식**으로 존재한다(DESIGN_SYSTEM §✒ 와 같은 어법) · 파괴적 동작에 색 의미가 생긴다 |
| 약점 | 주묵이 학습자 화면에서도 쓰이므로 **「주묵 = 관리자」로 읽히지 않는다** · 빨강 계열이라 경고와 혼동될 여지(그래서 면 금지·점선 규칙이 필요) |

### 안 C — 「공정 띠」 (색이 아니라 상태를 말하는 액센트)

| 항목 | 내용 |
|---|---|
| 원리 | 관리자 액센트를 **고정색이 아니라 파이프라인 상태**에 묶는다. 화면 머리에 8px 띠 하나를 두고, 그 띠가 그 화면이 다루는 공정의 **가장 앞선 막힌 단계** 색을 띤다(`--ok` 통과 · `--warn` 대기 · `--err` 막힘 · `--t3` 해당 없음) |
| 구분 신호 | 띠(형태+위치) + `ShieldCheck` + 「Admin」. 학습자 화면에는 이 띠가 없다 |
| 토큰 | 추가 0(상태 토큰 재사용). 단 띠 두께·위치를 DESIGN_SYSTEM 에 한 줄로 못박아야 한다 |
| G1 축 짝 | **환경 변형** + **주묵 문법**(막힌 단계 표시) |
| 옛 보라 318 | 전부 `--p`/상태 토큰으로 교체 |
| 강점 | **N1 통과** — 이 띠는 실제 파이프라인 수치(DB)가 없으면 그릴 수 없다 · 관리자가 묻는 「지금 어디가 막혔나」를 화면 머리에서 답한다 |
| 약점 | 상태를 읽어야 하므로 **모든 관리자 화면이 그 수치를 알아야 한다**(없는 화면은 `--t3` 회색 띠 = 정보 없음) · 색 의미가 하나 더 늘어난다 |

### 3안 비교 — 무엇이 다른가

| | A 같은 잉크 | B 주묵 도장 | C 공정 띠 |
|---|---|---|---|
| 관리자 구분이 지는 것 | 지면 톤 | 표식(점·선) | 화면 머리 띠 |
| 새 토큰 | 0 | 0 | 0 |
| N1(자산 없이 못 만드나) | 아니다 | 아니다 | **그렇다** |
| 스크린샷에서 즉시 구별 | 약함 | 보통 | **강함** |
| 색 의미 증가 | 없음 | 하나(표식) | 둘(상태) |
| 작업량(옛 보라 318 교체) | 큼 | 큼 + 표식 규칙 | 큼 + 상태 배선 |

1. **판면 방식 통일** — Tailwind 236 vs CSS 모듈 9. 새 화면이 CSS 모듈로 가는 중인데 접근성 스캐너는 Tailwind 만 읽는다(§1-4).
2. ~~**골격 선언 60건**~~ — (`// @form:` 선언 요구와 라쳇이 DD-66 으로 삭제돼 불필요.)
3. **도움말 1건 누락** — `/admin/vocab/runs/[id]/seed/preview` 에만 `AdminScreenHelp` 가 없다. Gate 1 에서 붙인다(자동화 정책 ②).
