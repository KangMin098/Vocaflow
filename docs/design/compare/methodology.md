# 방법론 작업 공간 — 네 가지 방향

2026-09-19. 선택 전 설계안이며 화면 구현/시각 QA 완료를 뜻하지 않는다.
공통 작업: 미조사 분야 찾기 → 방법론 선택 → 주장별 출처 확인 → 조건을 대조 → 검토 판정.
모든 안은 같은 연구 데이터와 검증기를 사용한다. 숫자 순위·장식 그래프는 사용하지 않는다.

| 안 | 골격(G1) / 첫 화면 | 기억할 요소·사용자 행동 | 얻는 것 / 한계 |
|---|---|---|---|
| **A. 주장과 근거의 판면** | **주묵 문법**. 중앙에 방법론의 주장, 난외에 출처. 실제 근거가 있는 주장에만 지지선 | 주장을 고르면 출처 위치와 판단 이유가 같은 줄에서 열린다. 상충 주장은 점선과 ‘조건 다름/반대’ 라벨 | 근거 검증이 가장 빠름. 전체 조사 공백은 별도 접기 영역 필요 |
| **B. 접근법의 계보** | **계보**. 개별 전문가의 설명이 정규 방법론으로 합류하는 흐름 | 원본·재업로드를 같은 가지로 접어 ‘여러 영상=여러 독립 근거’ 착시 제거 | 중복/독립성·전문가별 차이에 강함. 관계가 적은 초기에는 성긴 화면 |
| **C. 채워지는 연구 서가** | **환경 변형**. 기능별 연구 영역이 학령에 따라 펼쳐지며 확보한 근거·검토 상태가 층을 형성 | 빈 영역을 누르면 실제 미조사 후보와 다음 조사 행동으로 이동. 권리/접근 차단층은 별도 표시 | coverage와 다음 작업에 강함. 방법론 비교는 내부 inspector에서 진행 |
| **D. 적용과 검증의 시험지** | **시험지 사물**. 실제 CSAT 유형 옆에 적용 조건·풀이 절차·주장 출처가 나란히 놓임 | 두 방법을 고르면 같은 문항 유형에 대한 서로 다른 접근 단계가 맞물림 | Vocaflow CSAT 적용 판단이 직접적. 초등·회화·쓰기의 기본 홈으로는 적합도가 낮음 |

공통 토큰: `--bg`, `--bg2`, `--t1`, `--t2`, `--p`, `--ju`.
타입 역할: Hahmlet 한글 표제 / IBM Plex Sans KR 설명·조작 / Lora 영어 사례(시간은 JetBrains Mono).
모션: 선택한 근거 영역의 opacity 200ms 한 곳. 이동·상시 애니메이션 없음.

## 골격·서명·N4

- A: 근거 관계가 판면의 줄/난외 배치를 결정한다. 서명은 주장 옆에서 열리는 출처 주석. 주장-근거 연결 없이는 이 배치를 만들 수 없다.
- B: 원본 계열과 정규 방법론 합류가 가지를 결정한다. 서명은 같은 계열 접기. 출처 계열 없이는 실제 계보를 그릴 수 없다.
- C: 검토된 방법과 미분석 원천의 분포가 층을 결정한다. 서명은 미조사 칸에서 열리는 조사 큐. 실측 coverage 없이는 층을 채울 수 없다.
- D: 실제 `csat_types`와 연결된 절차가 판면을 결정한다. 서명은 같은 유형의 대조 주석. 출처가 있는 유형 매핑 없이는 비교를 채울 수 없다.

## 자기 검토

로고를 가린 앱 종류는 A=근거 검토, B=지식 계보, C=연구 운영, D=영어 문항 연구다.
Vocaflow 식별은 A/D에서 기존 주묵 근거 문법과 CSAT ID 연결이 가장 직접적이다.
B/C는 실제 데이터로 렌더한 뒤 일반 지식 그래프/대시보드와 구별되는지 추가 검증이 필요하다.
따라서 네 안 모두 최종 N4·익명성 통과를 아직 주장하지 않는다.
자기 포트폴리오는 정본에 실사례가 없어 비교 기준 없음. Admin 같은 계열의 골든도 별도 확인 필요.

제안: 근거 검토가 주된 일이면 A, 연구 확장이 주된 일이면 C. 선택은 사용자에게 있다.
선택 이후에만 최종 IA·route·화면 구현을 확정한다.
