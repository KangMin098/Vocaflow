# `/admin/csat` 발산 4안 — 관리자 콘솔 Gate 1

> 2026-09-20 · 브랜치 `chore/band-policy-and-admin-gate1` · 절차 [vocaflow-design §G3](../../../.claude/skills/vocaflow-design/SKILL.md) · Gate 0 [admin-brief](../admin-brief.md)
> **액센트는 B 「주묵 도장」으로 확정됐다**(사용자 결정 2026-09-20) — 네 안 모두 그 규칙 안에서 그린다. 다른 것은 **골격(G1 축)**이다.
> 코드 변경 0. 고르는 것은 사람이고, 고른 안을 2회 수정해 골든으로 고정한다.

## 이 화면이 지금 무엇인가 (대상 확정)

`/admin/csat` = **교재 공장 공정 현황판**. 조작 버튼이 없고, 각 공정이 **다음에 돌릴 명령**을 들고 있다.
지금 구성: 막힌 곳 한 줄 → 8칸 라인 도식(`FactoryLineDiagram`) → 고른 칸 상세(`StageDetail`) → 명령 복사(`CommandRow`) → 재고 패널 2개(`TextbookProductionPanel` · `FreedomPanel`).
대표 화면으로 고른 이유: 옛 보라가 가장 짙게 남은 화면이고(Gate 0), **파이프라인 화면의 원형**이라 여기서 고른 골격이 나머지 관리자 화면의 기준이 된다.

공통 제약(네 안 전부): 새 토큰 0 · 하드코딩 색 0 · 주묵은 **표식(점·선)만**, 면 금지 · 색 단독 정보전달 금지 · 모션은 상태 변화 시점에만 · 44px.

## 안 1 — 「정오표」 (골격: 시험지 사물)

| 항목 | 내용 |
|---|---|
| **골격(G1)** | **시험지 사물** — 화면이 한 장의 **정오표**다. 공정 8칸이 문항 번호처럼 왼쪽에 번호로 서고, 각 행이 「번호 · 이름 · 눈금 · 판정」의 괘선 표가 된다 |
| **서명** | 막힌 공정 행에만 **주묵 권점(•)**이 번호 왼쪽에 찍힌다. 그 행을 고르면 권점이 주묵 실선으로 이어져 상세 블록을 가리킨다(200ms, `--dur-normal`) |
| 색(토큰) | `--bg` 지면 · `--bg2` 행 교대 · `--bd` 괘선 · `--t1`/`--t2` 글자 · `--ju` 권점·실선 |
| 타입 역할 3 | 공정 이름 = IBM Plex Sans KR 600 · 눈금 = tabular-nums · 명령 = JetBrains Mono |
| 모션 1곳 | 권점 → 실선 연결 200ms(`transform: scaleX`) |
| 다른 셋과 다른 점 | 공정을 **순서 있는 목록**으로 본다. 8칸 전체를 한눈에 훑는 데 가장 빠르고, 인쇄해도 그대로 읽힌다 |
| N4 | 번호·괘선·권점 배치는 **공정 눈금(DB 실측)** 없이는 그릴 수 없다. 다만 「표」에 가까워 §G2 의 "그릇이 아니라 형태" 경계에 가장 가깝다 — 그래서 권점·실선이 골격의 일부다 |

## 안 2 — 「막힌 물길」 (골격: 환경 변형)

| 항목 | 내용 |
|---|---|
| **골격(G1)** | **환경 변형** — 8공정이 **수로**처럼 왼→오로 이어지고, 각 구간의 **폭**이 그 공정을 통과한 재고 비율이다. 막힌 구간에서 폭이 0 으로 좁아진다. 숫자를 읽지 않아도 "어디서 말랐는지" 가 지형으로 보인다 |
| **서명** | 막힌 구간 입구에 **주묵 한 획**(실선 + 화살촉)이 그려진다 — 그 획이 곧 "여기부터 푼다" |
| 색(토큰) | `--bg`/`--bg2` 물길 바닥·지면 · `--bd` 경계 · `--t3` 마른 구간 · `--ju` 막힌 지점 한 획 |
| 타입 역할 3 | 구간 라벨 = 작은 Eyebrow(대문자 금지) · 통과 수 = tabular-nums · 명령 = Mono |
| 모션 1곳 | 재고가 늘면 그 구간 폭이 200ms 로 넓어진다(`transform: scaleY`) |
| 다른 셋과 다른 점 | **양**을 형태로 옮긴다. 「몇 개인가」와 「어디가 막혔나」를 같은 그림에서 답하는 유일한 안 |
| N4 | 구간 폭 = 실제 재고 비율. 자산 없이는 빈 수로만 남는다 |

## 안 3 — 「판정 사슬」 (골격: 계보)

| 항목 | 내용 |
|---|---|
| **골격(G1)** | **계보** — 공정을 단계가 아니라 **의존 사슬**로 그린다. 「이 공정이 막힌 이유」가 앞 공정의 어느 판정에서 왔는지 선으로 이어진다(예: 조판 막힘 ← 해설 부족 ← 내용 판정 없음) |
| **서명** | 고른 공정에서 **거슬러 올라가는 점선**이 원인 공정까지 한 번에 켜진다(점선 = 배제·원인, 형태 문법 F2) |
| 색(토큰) | `--bg` 지면 · `--bd` 사슬 선 · `--t2` 중간 노드 · `--ju` 최초 원인 노드의 점 하나 |
| 타입 역할 3 | 노드 이름 = Sans KR 600 · 사유 코드 = Mono 11px · 영향 수 = tabular-nums |
| 모션 1곳 | 원인 경로 점선이 앞쪽부터 50ms 스태거로 켜진다(총 ≤300ms) |
| 다른 셋과 다른 점 | **원인**을 형태로 만든다. 「무엇을 먼저 고쳐야 하는가」에 가장 직접 답하고, 렌즈5(실패의 계보)를 관리자 쪽에서 처음 쓴다 |
| N4 | 사슬의 간선은 공정 간 실제 판정 의존(코드·DB)에서 나온다. 임의 배치가 불가능하다 |

## 안 4 — 「오늘의 한 장」 (골격: 주묵 문법)

| 항목 | 내용 |
|---|---|
| **골격(G1)** | **주묵 문법** — 화면이 **지시문 한 장**이다. 첫 시선에 「지금 돌릴 명령」 하나가 주묵 테두리 안에 서고, 8공정은 그 아래 한 줄 눈금으로 접힌다. 상세는 요청 시 펼친다(Progressive Disclosure) |
| **서명** | 명령 블록 왼쪽의 **주묵 세로선 2px** + 복사 시 그 선이 한 번 진해진다(120ms) |
| 색(토큰) | `--bg` 지면 · `--bd` 접힌 줄 · `--t1` 명령 · `--ju` 세로선·복사 확인 |
| 타입 역할 3 | 명령 = Mono 13px · 왜 이 명령인가 = Hahmlet 한 줄 · 눈금 = tabular-nums |
| 모션 1곳 | 복사 확인 — 주묵 세로선 명도 120ms(`--dur-fast`) |
| 다른 셋과 다른 점 | **결정을 하나로 줄인다.** 관리자가 화면에서 얻어야 할 것이 「다음 명령」 하나라는 전제를 끝까지 민다 |
| N4 | 어느 명령이 다음인지는 공정 판정 없이 못 고른다. 다만 8공정 정보가 접히므로 **현황 파악**은 가장 약하다 |

## 자기검토 (§G3)

로고를 가리고 (a) 앱 종류 (b) 이 제품인지:

| 안 | (a) 앱 종류 | (b) 이 제품인가 | 판정 |
|---|---|---|---|
| 1 정오표 | 시험·교육 운영 도구로 읽힌다 | **가능** — 권점·괘선·문항 번호는 이 제품의 시험지 어휘 | 통과 |
| 2 막힌 물길 | 데이터 파이프라인 도구 | 약함 — 물길은 일반 ETL 도구와 구별이 안 된다(주묵 한 획이 유일한 표식) | **경계** |
| 3 판정 사슬 | 의존 그래프 도구 | 약함 — 노드·간선은 어느 도구에나 있다 | **경계** |
| 4 오늘의 한 장 | 운영 콘솔 | **가능** — Hahmlet 한 줄 + 주묵 세로선 + Mono 명령의 결합 | 통과 |

[own-portfolio](../own-portfolio.md) 와의 쌍둥이: 2·3 은 일반 파이프라인 대시보드와 겹칠 위험이 있다(그 문서의 「차트형 도형」 경고와 같은 자리).

## 흡수된 것 — C 「공정 띠」의 막힌 공정 표시

사용자 결정으로 액센트 C 는 채택하지 않고, 그 알맹이(막힌 공정을 화면이 말한다)는 **커버리지 규격 한 줄**로 남았다:

> **관리자 파이프라인 화면은 「가장 앞선 막힌 단계」를 첫 뷰포트에 한 줄로 말한다** — 색이 아니라 문장 + 주묵 표식으로, 막힌 것이 없으면 그 줄을 비운다(없는 것을 색으로 꾸미지 않는다).

네 안 모두 이 규격을 지킨다(1 권점 행 · 2 마른 구간 · 3 최초 원인 노드 · 4 머리 한 줄).
