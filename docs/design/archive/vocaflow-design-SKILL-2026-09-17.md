# Vocaflow Design — 발명 엔진 + 병합 정본

> **이 스킬은 금지 목록이 아니다.** 앞쪽 Part 1(§A–§F)이 목표이고, 뒤쪽 Part 2(§0–§8)는 바닥이다.
> 제약만 지킨 화면은 "규정 위반이 없는 평범한 화면"이지 혁신이 아니다.
> 설치된 외부 취향 스킬 13개는 *생성 장치*(Design Read · Variation Engine · 개념법)를 갖고 있는데,
> 그 장치들은 전부 **시각 변주**를 만든다. 이 제품에서 시각은 차별점이 아니다 —
> 그래서 Part 1 은 같은 자리에 **학습 메커니즘 변주 엔진**을 놓는다.
> 정본 수치는 전부 저장소·DB 에서 읽은 실측값이다(출처를 각 줄에 적었다).

# Part 1 — 발명 (목표)

## §A. 혁신 판정 3문 — 통과 못 하면 그건 장식이다

새 화면·기능·프로세스를 제안할 때 **코드보다 먼저** 세 줄로 답한다.
(`design-taste-frontend` §0.B 의 "Design Read" 를 학습 제품용으로 바꾼 것이다.)

| # | 질문 | 통과 기준 | 불합격 예 |
|---|---|---|---|
| **N1** | **자산 의존** — 우리만 가진 실측 자산 없이는 성립 불가한가 | `shared_dictionary` 48,969 · `library_books` 401 · R(t) 동적 계산(`lib/srs/fsrs.ts`) · 커버리지 계산(`lib/textfit/coverage.ts`) · 4축 V-Level · CSAT 코퍼스 중 **최소 1개**에 의존 | 폰트·여백·그라디언트만 바뀐 안 — 경쟁사가 하루면 베낀다 |
| **N2** | **즉시 증명** — 200ms 안에 화면에서 눈으로 확인되는가 | 방문자가 값을 바꾸면 결과가 바뀐다(§3 I3) | "AI 가 분석해 드립니다"라고 쓰고 결과는 로그인 뒤에 두는 것 |
| **N3** | **학습과학 개선** — 7원칙 중 **어느 것**을 더 잘 하는가 | 원칙 번호를 하나 대고 이전보다 나아지는 이유를 한 줄 | "재미있어서" · "요즘 트렌드라서" |

세 줄을 못 쓰겠으면 그 안은 아직 발명이 아니다. **N1 이 가장 자주 탈락한다.**

## §B. 발명 엔진 — 5축 조합 (같은 칸을 두 번 만들지 않는다)

외부 스킬(`imagegen-frontend-*` §22 · `image-to-code` §12)의 Combinatorial Variation Engine 은
Theme / Hero Architecture / Motion Language 를 조합해 **시각**을 변주한다.
여기서는 같은 방식으로 **학습 메커니즘**을 조합한다.

| 축 | 값 |
|---|---|
| 1. 인지 계층 | L0 노출 · L1 이해 · L2 맥락 · L3 수집 · L4a 재인 · L4b 시각생성 · L4c 청각생성 · L5 정복 · L6 완성 · L7 회고 |
| 2. 증거 표면 (무엇을 보여줘야 "내 것"이 되는가) | 지문 채색 · 서가 · 회상률 곡선 · 오답 계보 · 시간대 분포 · 커버리지 % · 난이도 사정권 |
| 3. 주체 | 혼자 · 교사→학급 · 또래 · **과거의 나** |
| 4. 시간 | 지금(세션) · 오늘 · 이번 주 · 학기 |
| 5. 자산 | 사전 48,969 · 도서 401 · 챕터 퀴즈 2,453 · CSAT 코퍼스 · 만화 969호 · FSRS 상태 |

**규칙**: 각 축에서 하나씩 뽑는다. 뽑힌 조합이 이미 있는 화면과 같으면 **버리고 다시 뽑는다.**

> 9개 모듈이 거의 전부 `(혼자 · 지금 · 재인)` 근처에 몰려 있다 —
> **그래서 10번째 모듈은 아무리 잘 만들어도 새롭게 느껴지지 않는다.**
> 비어 있는 칸이 발명 지점이다: 「과거의 나 × 학기 × 회상률 곡선」,
> 「교사→학급 × 이번 주 × 커버리지」, 「또래 × 오늘 × 난이도 사정권」.

## §C. 디자인 발명 렌즈 6 — 일반 랜딩 취향으로는 나오지 않는 것

화면을 새로 만들 때 이 여섯을 순서대로 대 본다. 하나라도 걸리면 그쪽이 대개 더 좋은 안이다.

1. **망각을 보여준다** — `R(t) = exp(ln(0.9)·t/S)` 는 연속 함수인데 UI 는 스냅샷(4색)만 보여준다.
   시간을 축으로 꺼내면 "지금 안 하면 목요일에 이만큼 잃는다"가 **눈에 보인다.** 경쟁사엔 이 곡선이 없다.
2. **지문이 곧 인터페이스** — 컨트롤을 지문 바깥 툴바에 두지 않는다.
   아는 단어/모르는 단어가 칠해진 지문 자체가 조작면이다.
3. **성장은 환경으로** (철학 4 Implicit Progress) — 게이지를 그리고 싶어질 때마다
   "대신 무엇이 **변형**되는가"를 답한다. 서가가 차오르고, 색이 risk→stable 로 옮겨가고, 배경 톤이 달라진다.
4. **빈 상태가 최고의 전시장** — 기록이 아직 없을 때가 **실측 데이터로 남의 결과를 보여줄 유일한 기회**다
   (`lib/marketing/hero-demo.ts` 가 그 예). 빈 화면에 "데이터가 없습니다"를 쓰는 것은 발명의 포기다.
5. **실패의 계보** — 오답을 낱개로 세지 않는다. 어떤 단어가 어떤 오답을 낳고 그게 어느 문항에서 다시
   나오는지 **사슬**로 보여준다. `library_chapter_quiz` 2,453 과 FSRS 상태를 동시에 가진 곳만 할 수 있다.
6. **교사의 3분** — 허용 CAC 가입당 ₩400 이라 광고 경로가 성립하지 않고 **교사→학급 경로만 남는다**
   (`docs/PLATFORM_AUDIT.md`). 그러므로 모든 공개 표면은 *"교사가 3분 안에 학급에 던질 수 있는가"* 를
   통과해야 한다. 통과 못 하면 예뻐도 성장에 기여하지 않는다.

## §D. 기능 혁신 — 공급이 아니라 수요 쪽에서 찾는다

이 저장소의 실패 모드는 **공급 비대 · 수요 0** 이다 (공급:수요 **3,480:1**, 가입자 3).
새 기능을 제안할 때 **한 줄로 먼저 답한다**: *"이건 공급을 늘리는가, 수요를 늘리는가."*

- **공급 증가**(새 소스 · 새 코퍼스 · 새 콘텐츠 유형)면 **순위를 내린다.** 이미 충분하다.
- **수요 증가**(교사 유입 · 재방문 · 완료율 · 공유)면 올린다.
- **새 테이블을 만들기 전에 기존 자산의 새 결합을 먼저 시도한다.** 대부분의 발명은 **조인 하나**에서 나온다.
  예: `CSAT 코퍼스 × 개인 V-Level` = "이 지문이 네 수능에서 몇 등급 자리인가".

## §E. 프로세스 혁신 — 드레인이 이 저장소의 진짜 발명이다

Claude Code 3단 드레인(export → 내가 채움 → import)이 ScriptQuiz **1,292문항** · 사전 **466낱말** ·
PDCP **969호**를 만들었다. 새 작업을 설계할 때 먼저 묻는다:
**"이걸 드레인으로 돌릴 수 있게 export/import 를 먼저 만들 수 있나?"**

- **재실행 안전**(이미 채운 건 건너뛴다) · **빈 값 import 금지** — 둘 중 하나만 빠져도 구멍이 영영 남는다.
- **계측을 같은 커밋에** — 새 공개 표면은 진입 + 내부 상호작용 이벤트를 함께 넣는다(§4 D2).
  **안 재면 혁신인지 아닌지 영원히 모른다.**
- Admin 화면도움말도 같은 커밋에 — 프로세스가 바뀌었는데 도움말이 낡으면 잘못된 조작을 부른다.

## 3. 첫인상 — "말하지 말고 증명하라" (첫눈 임팩트 규칙)

이 제품의 주장은 **"내가 아는 비율"** 이고, 그건 본질적으로 **눈으로 보이는 것**이다
(지문 위에 아는 단어/모르는 단어가 칠해진 그림). 그런데 산문으로 설명하면 증명이 사라진다.

### 3.1 규칙 (검증 가능)

| # | 규칙 | 검사법 |
|---|---|---|
| I1 | 공개 화면의 **첫 화면(above the fold)** 에 제품이 하는 일을 **실제로 수행한 결과**가 하나 이상 있어야 한다 | 히어로에 실데이터 렌더 요소가 있는가 |
| I2 | 그 증명에 도달하는 데 필요한 클릭 = **0**. 입력 요구 = **0** | 진입 직후 스크린샷에 보이는가 |
| I3 | 증명은 **조작 가능**해야 한다 — 방문자가 값을 바꾸면 결과가 즉시 바뀐다 (자기 것으로 느껴져야 남는다) | 컨트롤이 1개 이상 있고 200ms 내 반응하는가 |
| I4 | 히어로 본문(부제) ≤ **2문장 / 90자**. 설명은 증명 뒤로 | 글자 수 |
| I5 | 수치는 **DB 실측 또는 그 자리에서 계산한 값**만. 상수 박기 금지 | `no-hardcoded-stats` 회귀가 잡는다 |
| I6 | 증명 요소는 **서버 렌더 HTML 에 남아야** 한다 — 크롤러가 읽을 것이 있어야 한다 | `curl` 결과에 텍스트가 있는가 |

### 3.2 순서 (세일즈가 아니라 도구 순서)

```
증명(작동하는 것) → 왜 그런가(근거 1줄) → 다음 문 → 신뢰 수치 → 상세
```
`gpt-taste` 의 AIDA(Attention→Interest→Desire→Action)를 쓰지 않는 이유:
교사·학생은 광고를 보러 온 게 아니라 **오늘 쓸 도구**를 찾으러 온다. 욕구를 만드는 단계가 낭비다.

## 4. 이탈 방지 — 못 재면 방지도 없다

### 4.1 규칙

| # | 규칙 | 근거 |
|---|---|---|
| D1 | **막는 것을 먼저 없앤다.** 가치 확인 앞에 로그인·입력·모달을 두지 않는다 | `/fit` 이 로그인 없이 열려 있는 이유와 같다 |
| D2 | 새 공개 화면에는 **진입 이벤트 + 내부 상호작용 이벤트**를 같은 커밋에서 넣는다. 진입만 재면 "왔다 갔다"밖에 모른다 | `lib/analytics/events.ts` 닫힌 목록에 추가 |
| D3 | 이벤트 속성은 **숫자·불리언·닫힌 열거형만**. 자유 문자열 금지 (지문 유출 차단이 타입으로 보장돼 있다) | `events.ts` 헤더 계약 |
| D4 | 파생 가능한 것은 수집하지 않는다 (구독·완료는 DB 행에 남는다) | `lib/admin/retention-math.ts` 결정 |
| D5 | 빈 상태(empty state)에 **다음 한 걸음**이 반드시 있어야 한다. 막다른 화면 = 이탈 | — |
| D6 | 실패·오답 화면에서 **비난 금지**. 정답률 빨간 글씨·경고 아이콘 금지 | 철학 3 Empathetic Feedback |

### 4.2 첫 세션 예산

가입 직후 **첫 학습 1회 완료까지 화면 전환 ≤ 3**. 넘으면 그 경로를 줄이거나 건너뛰게 한다.

## 5. 모션 예산 — 숫자로 못 박는다

Vocaflow 토큰(`packages/design-tokens/src/tokens.css:200-204`)은 이미 업계 권장 대역 안에 있다.
아래는 그 사실을 **규칙으로 고정**한 것이다.

| 항목 | 값 | 토큰 |
|---|---|---|
| 마이크로(호버·프레스·토글) | **100–200ms** | `--dur-fast` 100ms · `--dur-normal` 200ms |
| 표준 전환(패널·모달·페이지) | **200–300ms** | `--dur-normal` · `--dur-slow` 300ms |
| 이징 | `cubic-bezier(.4, 0, .2, 1)` | `--ease` |
| 스태거 | **50ms** | DESIGN_SYSTEM §Motion |
| 이동 거리 — 마이크로 | **4–16px** | — |
| 이동 거리 — 리빌 | **20–40px** (현 `translateY 20→0` 준수) | — |
| 총 지속 | **1초 초과 금지**. 예외: `--dur-breath` 4s 앰비언트(정지 배경 한정) | — |
| 프레임 | `transform` · `opacity` 만 애니메이트 (레이아웃 스래시 0) | — |

### 5.1 reduced-motion 은 "끄기"가 아니라 "낮추기"

```css
@media (prefers-reduced-motion: reduce) {
  /* 위치 이동·회전·스케일은 제거하되, 상태 변화는 여전히 보여야 한다 */
  .x { transition: opacity var(--dur-fast) var(--ease); transform: none !important; }
}
```
전부 `0.01ms` 로 죽이면 **무엇이 바뀌었는지 알 수 없게 되어** 오히려 접근성이 나빠진다.
페이드는 남긴다. (외부 `accessible-animation` 계열의 tiered 처리와 같은 입장)

### 5.2 학습 화면 모션 화이트리스트

학습 중에는 아래 **7가지 외 모션 금지**:
카드 뒤집기 · 정답 `scale(1.05)→1` · 오답 shake 3회 · 진행률 바 · 점수 카운트업 ·
페이지 전환 페이드 · 포커스 링. (`DESIGN_SYSTEM.md §Motion 사용 매핑`)

**금지 명시**: 폭죽 · 트로피 · 콘페티 · 배지 팝업 · 루프 애니메이션 · 자동재생 캐러셀.

## 6. 감성 — 어디서 사람의 목소리가 나는가

| 자리 | 서체 | 말투 |
|---|---|---|
| 격려·회고·빈 상태 — **한국어** | **Hahmlet(세리프) · 이탤릭 없음** | 사람이 옆에서 말하듯. "오늘 잘 마쳤어요" |
| 격려·회고·인용 — **영어** | **Lora italic** | 진짜 이탤릭 자형이 있는 쪽 |
| 지표·수치 | Plus Jakarta / tabular-nums | 말을 얹지 않는다. 숫자만 |
| 오답 직후 | IBM Plex Sans KR + 한국어는 Hahmlet 1줄 | 원인을 말하고 다음 한 걸음. 평가하지 않는다 |

**Implicit Progress** — 성장은 게이지보다 **환경**으로 보인다: 서가가 차오르고, 지문의 색이
`risk → shaky → stable` 로 바뀌고, 배경 톤이 미세하게 달라진다. 숫자 100%에 폭죽을 터뜨리지 않는다.

## 7. 3D / 제너러티브 — 쓸 자리와 안 쓸 자리

스택 고정: `three` 0.184 · `@react-three/fiber` **8.17** · `drei` 9.122
(외부 Three.js 스킬 다수가 r3f 9.x / three r16x 전제다 — API 가 다르므로 그대로 복사하지 않는다.)

| 쓴다 | 안 쓴다 |
|---|---|
| 성장 시각화(서재·풍경) — **결정론적 시드**로 학습자마다 재현 가능하게 | 학습 화면 배경 |
| 아케이드 게임 표면 | 랜딩 히어로 (LCP 를 깎는다 — 히어로 증명은 DOM/SVG 로) |
| 표지·앰비언트 정지 이미지 | 스크롤 연동 3D 카메라(모바일에서 프레임이 무너진다) |

제너러티브를 쓸 때는 **해시 시드 결정론**을 지킨다 — 같은 학습자·같은 상태면 같은 그림이 나와야
"내 것"이 된다. 매번 달라지면 성장 신호가 아니라 노이즈다.
