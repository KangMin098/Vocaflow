## A. 활자 지면 (Editorial Page)

> 상자를 없앤다. 괘선 · 섹션 번호 · 스케일 대비만으로 위계를 만든다.

| | |
|---|---|
| **시그니처 장치** | 카드 **0개**. `01 오늘` `02 첫 단어` 처럼 **번호 + 얇은 괘선**이 구획을 만든다 |
| **타이포** | Hahmlet 30px 헤드라인(본문의 2.3배) · Lora 52px 단어 · IBM Plex Sans KR 라벨 |
| **색** | 잉크 1색 + 지면 1색. CTA 는 버튼이 아니라 **잉크 블록** |
| **상태 표현** | 단어 아래 Memory Decay 색 밑줄(1px) |
| **참조** | Are.na(괘선 위계) · Monocle(섹션 번호) · Apple Books(종이) |

**장점** — 지금 방향(Reading Room)의 **가장 순수한 완성형**이다. Calm UI 와 충돌이 0이고,
C2(균일 카드 스택)·C7(radius 두 벌)을 근본에서 없앤다. 447파일에 흩뿌려진 `border+rounded+shadow`
세 클래스를 **삭제**하는 방향이라 적용 비용도 셋 중 가장 낮다.

**약점** — **색이 여전히 없다.** 00-inventory §0-4 가 지적한 "글자색 94%가 같은 잉크"는 그대로다.
스크린샷 한 장으로 알아보게 하는 힘이 셋 중 가장 약하다 — 잘 만든 에디토리얼 사이트와 구별이 안 된다.

**§A 혁신 판정** — N1 ❌(자산 의존 없음 · 폰트와 괘선은 하루면 복제된다) · N2 △ · N3 ⭕(원칙 6 인지부하↓)

## B. 주묵(朱墨) 판면 (Vermillion Annotation) — **추천**

> 붉은 교정 잉크가 **면적으로** 존재한다. 망각도가 밑줄 두께가 되고, 완료가 붉은 표식이 된다.

| | |
|---|---|
| **시그니처 장치** | ① 상단 **주묵 띠**(면적을 가진 브랜드 색) ② 숫자 뒤 **붓 자국**(skew된 연한 주묵) ③ 단어 옆 **권점(圈點)** ④ **밑줄 두께 = 망각도** (risk 3px · shaky 2px · stable 1px) |
| **타이포** | A 와 동일 체계 (Hahmlet + Lora + Plex Sans KR) |
| **색** | 주묵 `#C0392B` 1색이 **면·선·표식**으로 반복. 지면은 A 보다 살짝 따뜻한 `#FBF8F2` |
| **상태 표현** | 밑줄 **두께**가 R(t)를 말한다 — 색맹 대응이 색 단독이 아니라 두께로도 된다 |
| **참조** | 한국 학습 정서의 원형(선생의 빨간펜 · 권점) · Readlang(지문이 인터페이스) |

**장점**
- **스크린샷 한 장으로 알아본다** — 목표 기준을 셋 중 유일하게 정면으로 만족한다.
- **디자인이 곧 데이터다.** 밑줄 두께는 `lib/srs/fsrs.ts` 의 R(t) 없이는 못 그린다 —
  경쟁사가 폰트를 베껴도 이 선은 못 베낀다(§A N1 통과의 유일한 안).
- 색 단독 정보전달 금지(접근성 하한선)를 **두께**로 이미 충족한다.
- 문화적 뿌리가 있어 한국 고등학생~성인에게 설명이 필요 없다.

**약점 / 반드시 정할 규칙**
- ⚠️ **빨강 = 압박**이 되면 철학 3(Empathetic Feedback)과 CLAUDE.md 「정답률 빨간 글씨 압박 금지」를
  정면으로 위반한다. → **주묵은 "앱이 페이지에 남기는 표식"에만 쓴다.**
  **학습자의 오답을 칠하는 데는 절대 쓰지 않는다.** 오답은 지금처럼 `--memory-*` 언어로 말한다.
  (이 규칙은 03-system 에 회귀 테스트로 박는다 — 규칙만 적어 두면 반드시 새어 나간다.)
- 기존 `--error #9C3A30`(warm red)과 색이 가깝다. → 주묵 도입 시 **error 를 빨강 계열에서 뺀다**
  (오답은 색이 아니라 표식·문장으로). 이건 팔레트 전체에 영향을 주는 결정이라 03 에서 다룬다.

**§A 혁신 판정** — N1 ⭕(FSRS R(t) 의존) · N2 ⭕(밑줄이 즉시 보인다) · N3 ⭕(원칙 2 간격반복 가시화 · 4 이중부호화)

## C. 도구함 (Instrument)

> 라운드 0, 모노 라벨, 격자 괘선. 장식 대신 눈금이 위계를 만든다.

| | |
|---|---|
| **시그니처 장치** | radius 0~2px · 3열 계기판 · 전 요소가 격자로 이어붙는다 · 상태는 **작은 정사각형** |
| **타이포** | JetBrains Mono 라벨 · Plex Sans KR 본문 · Lora 단어 |
| **색** | deep ink `#0F2540` 액센트 + 회색 지면 `#F3F2EE` |
| **상태 표현** | 색 사각형 + **R 값 숫자 그대로 노출**(0.41) |
| **참조** | Teenage Engineering · Linear 리스트 · 계측기 UI |

**장점** — 밀도가 높아 `/wordvault/browse`(5,154px 캡처) 같은 목록 화면에 가장 잘 맞는다.
숫자를 숨기지 않아 "왜 이 단어인가"가 늘 보인다.

**약점** — 지면이 **차갑다.** 철학 3(Empathetic)·6(감성)과 어긋나고, 고등학생 학습자에게
"관리 도구"로 읽힌다. `/admin` 과 얼굴이 비슷해져 **학습자 앱과 콘솔의 구분이 흐려진다**(실제 위험).
또 R 값 노출은 Progressive Disclosure 위반 소지가 있다.

**§A 혁신 판정** — N1 △ · N2 ⭕ · N3 ❌(인지부하를 오히려 올린다)

## 결론 — B 를 추천하고, A 를 그 안에 흡수한다

B 와 A 는 **배타적이지 않다.** B 의 지면 문법은 A 그대로이고(괘선·스케일 대비·카드 없음),
B 는 거기에 **면적을 가진 색 하나와 데이터에서 나온 표식**을 더한 것이다.

> **채택안: A 의 판면 구조 + B 의 주묵 표식 = 「주묵 판면」**
> C 의 밀도·표 문법은 버리지 않고 **목록 화면 한정 변형**으로 남긴다
> (`/wordvault/browse` · `/library/*` — 지금 가장 읽히지 않는 화면들).

이 방향이 확정되면 03-system 에서 토큰·컴포넌트를 만들고, 그 전에는 학습자 코드를 건드리지 않는다.
