## 4. 읽기 흐름을 보존하는 화면·상태 설계

### 4.1 읽는 중 저장

기존 StoryUnitText → WordLookupPopover 안에 **선택 낱말의 뜻을 확인한 뒤** “내 단어장에 담기” 하나를 둔다. 본문 도구 줄에 Flashcard/Dictation/Echo/교재 버튼을 늘리지 않는다. 읽던 단위·문단은 그대로이고 저장 요청은 자동 이동이나 진도 저장을 유발하지 않는다.

상태: `확인 전/다른 계정`에는 조작 없음 → 사전 `loading` → 정확한 항목 `ready`일 때 명시 저장 → `saving` 중 중복 조작 차단 → `saved` 또는 `already_exists`를 같은 위치의 `aria-live=polite`로 안내 → 필요하면 단어장 이동. 없음·유사어 추정·연결 오류는 “뜻을 확인한 뒤 담을 수 있어요/다시 시도”이며 임의 뜻을 생성하지 않는다. 실제 재시도는 사용자가 선택한다. 본문 표면형과 저장할 사전 원형이 다르면 둘을 표시해 무엇을 담는지 알게 한다. 사전 예문은 **사전 예문**으로 표시하고 Story 인용문처럼 저장하지 않는다. 서버 실패는 제한된 사용자용 사유로 바꾸며 raw DB 오류·내부 식별자·인증 정보를 창/로그로 전달하지 않는다.

모달을 새로 만들지 않는다. D4 비모달 초점·Tab 이탈·Esc·직접 낱말/44px 도구별 복귀를 보존한다. 저장 응답이 늦게 와도 계정/판본/단위/선택 낱말이 바뀌었으면 현재 창에 성공을 적용하지 않는다. 작업 성공 알림 때문에 본문이 스크롤되지 않아야 한다.

### 4.2 단어장 이동·복귀

단어장은 기존 `/wordvault/browse`의 독립 세션 셸을 활용한다. Story의 공통 헤더·Library 탭을 단어장 위에 추가하지 않는다. Story에서 명시 이동했을 때만 상단에 작은 문맥 줄 `읽던 이야기 · The Blue Carbuncle · 3번째 단위`와 **“Story로 돌아가기”**를 제공한다. 기존 지도에서 온 MapReturnBar를 Story로 위장하지 않는다. WordVault 내용은 본인 기존 목록이며 **Story 전용 단어 목록이라고 표시하지 않는다**.

같은 탭 안에서는 유효한 initiator DOM/스크롤을 보조 기억할 수 있으나 진도 계약은 단위다. 복귀 시 서버가 해당 release와 권리를 재확인하고 단위를 연다. URL 복귀는 문장 위치 보장을 뜻하지 않는다. 재로그인·새로고침 후에도 안전한 구조화된 복귀 주소를 전달하되 계정이 바뀌면 기존 개인 UI/비동기 응답은 폐기한다. 다른 계정도 같은 공개 Story를 읽을 수 있는 것과 타인 진도를 복원하는 것은 별개다.

### 4.3 독서 후와 소리 도움

완독 후 기본은 D4의 실제 가능한 행동이다. 저장한 항목이 이 탭에 있는 경우에만 보조 링크를 제공한다. 단어장 담기는 완료나 숙달 조건이 아니다. 다음 에피소드·다른 작품이 없으면 서비스 훈련을 대신 “다음 이야기”라고 부르지 않는다.

기존 **낱말 발음**은 유지한다. 문장 TTS 후보는 한 문장을 명시 선택→재생/멈춤→같은 문장으로 복귀이며 자동 다음 문장·step 따라하기·마이크가 기본이 아니다. 권리·지원 여부가 미충족이면 실행 버튼을 노출하지 않는다. 기기 음성 목록·지원성 확인은 실제 청취 품질 검증이 아니다. 신규 오디오 엔진·서버 생성/캐시 작업은 범위 밖이다.

| Story 본문 | D4의 본문 약610px·19px/33.25px, 단위 제목과 도구 줄 유지 | 같은 판면, 도구만 필요할 때 줄바꿈 | 새 연결 때문에 본문 폭·문단·기본 순서/첫 시작 위치를 바꾸지 않음 |

클릭 시안 [d5-story-connections.html](./design/d5-story-connections.html)은 **제품 밖 가상 상태**다. 저장·실패·중복·복귀의 정보 구조를 확인하는 도구이고 실제 API·DB 성공 증거가 아니다. 실제 화면/시안 캡처 및 확인 결과는 §11을 따른다.

## 5. 최소 데이터·권한·revision 계약

### 공통 식별과 복귀

1. Story 식별은 기존 `release_key + unit_index`다. unit index는 **0-based, 0 이상 unit_count 미만**이다(화면의 “3번째 단위”는 index2). 서버에서 현재 공개/철회·권리·불변 edition/source/policy/target 해시·본문을 기존 learner 경로로 재확인한다. release는 고정 발행본이며 slot/work 이름만으로 최신 본문을 대신 읽지 않는다.
2. 외부 서비스로 넘길 복귀 후보는 `story_release=<엄격한 release 형식>&story_unit=<정수 범위>` 같은 **구조화된 내부 문맥**이다(제안 이름, 현재 미지원). 기존 `readerHref`와 `loginUrlWithReturn/safeInternalPath`를 재사용한다. 임의 `return_url`, 사용자 ID, 토큰, 본문·뜻·문장·진도는 URL에 넣지 않는다.
3. `story_release`는 접근 권한이나 개인 기록 조회 키가 아니다. 본인 신원은 정상 서버 Auth에서 얻는다. 로그인 next에 안전한 전체 내부 주소를 보존한다. 두 복귀 문맥(Story/map)이 동시에 오면 임의 우선순위를 숨기지 말고 유효 initiator 하나만 적용/잘못된 조합은 중립 서비스로 처리한다.
4. 복귀 실패는 상태별로 구분한다. 권리/철회→본문 없이 현재 이용 불가+Stories, 잘못된 단위→확인 가능한 판본 입구, 새 revision→이전 이력 보존+새 판본을 명시 선택, 인증 확인 실패→개인 정보 숨김. 없거나 실패한 자료를 준비된 서비스로 표시하지 않는다.

### 낱말 저장 후보 계약 — SQL 없이 가능한 최소 범위

5. 기존 서버 액션·중복 처리·사전 해석·FSRS를 재사용한다. nullable textId를 허용하는 작은 공용 함수 보정 또는 Story 전용 얇은 wrapper 중 **다른 호출자에 영향이 작은 방법**을 구현 단계에서 선택한다. 새 공개 HTTP API·테이블·origin enum은 기본 요구가 아니다.
6. 서버 입력은 release/unit/선택 위치와 예상 판본 결속, 현재 viewer 확인용 계약으로 제한한다. 서버가 다시 읽은 현재 본문의 실제 낱말을 동일 토큰화 규칙으로 확인하고 사전 확정 항목/lemma를 재조회한다. 클라이언트가 보낸 뜻·예문·textId·userId를 권위로 저장하지 않는다. suggestion은 자동 확정하지 않는다. 구·문장 저장은 현재 단일 word 계약으로 확장하지 않는다.
7. `text_id=null`, `origin=manual`, 본인 UID, 검증된 사전 필드만 저장하는 후보는 현재 DB 형태와 맞는다. `library`로 위장하거나 가짜 texts UUID를 만들지 않는다. Story 본문·민감 해설을 예문으로 대량 복사하지 않는다. 같은 `(user_id,word)`는 기존 뜻/FSRS/출처를 덮지 않고 이미 담음으로 응답한다. 네트워크 응답 손실 후 재시도도 멱등이어야 한다.
8. **영구 Story 출처 추적은 현재 vocab row에 없다.** 이 최소안은 일반 개인 단어 저장이며, 복귀 문맥은 명시 이동에 붙는 임시 문맥이다. “항상 원래 Story로 복귀/Story별 목록”을 약속하지 않는다. 영구 provenance가 실제 필수라고 확인되면 별도 계약/승인 대상으로 제시하며 임의 json/컬럼에 숨겨 적지 않는다.
9. 저장·뜻 확인·소리 듣기는 FSRS 평가를 호출하지 않는다. 실제 지원되는 복습에서 학습자가 응답한 기존 경로만 서버 권위 `applyReview`를 사용한다. Story 완독/지도 숙달과 통합 점수를 만들지 않는다. 새 카드가 생성돼도 암기나 성장의 증거가 아니다. 기존 WordVault study는 due 우선 정렬/cap이며 due만 필터하는 Story 전용 큐가 아니다. 담은 낱말만의 복습 세션이나 저장 수와 세션 길이가 같다고 약속하지 않는다.

### 오디오·훈련 적격성과 수명

10. source_text 확인을 기존 녹음/번역/신규 파생 오디오 사용 승인으로 확대하지 않는다. 문장 낭독이 기존 권리 결정·판본 제작 조건에서 허용되는지 구체적으로 검토한다. 영구 생성 오디오는 별도 asset 권리·정렬·정확한 release/hash 조건이 필요하다. 승인되지 않은 제작·audio confirmed 기록은 하지 않는다.
11. 재생기를 재사용해도 현재 단위의 실제 문자열만 재생하고, 재생/정지/오류/미지원 상태를 제공한다. 화면 이탈·로그아웃·계정/판본/단위 변경에서 cancel, 이전 비동기 결과 폐기, 숨겨진 Story 내용의 발화 금지. shared singleton을 쓰면 다른 화면 발화를 취소/덮는 영향도 검증한다.
12. Dictation/Echo는 기존 출처/DB 제약·실제 문장/오디오·평가 범위·세션 권한·복귀·보존/철회 정책을 갖춘 뒤 연결한다. `custom` 출처나 자동 texts 복사로 Story 권리·revision 계약을 우회하지 않는다. 교재/지도는 사전 검수된 문제·Gold/근거·TASK·학습 역할 적격성까지 별도이며 현재3개 deep_reading JSON의 존재만으로 충족되지 않는다.

## 7. 최소 실행 단위 — 실제 TASK 생성 아님

| ID·owner | 기존 자산·변경 범위 / 이유 | 선행·난도·부작용 | 최소 수용·화면/학습자 검증 |
|---|---|---|---|
| **LCP-D5-I01 선택 낱말 저장** · 구현 `lcp-story-claude`, 독립 수용 `lcp-story-codex` | StoryUnitText/Popover Story opt-in + 기존 add-word 서버 경로의 작은 어댑터. 사전 뜻을 이해한 뒤 나중에 살펴볼 낱말만 선택 | 상세 §5.5~9 확정, 기존 nullable/FSRS/중복 계약 재사용. L3·중간. provenance·구 저장 범위 과장 금지 | 정상/이미 있음/오류/응답손실·재시도, 사전 없음/유사어, 인증 확인 중/전환/늦은 응답/위조 입력/철회 거부. 단어1개가 본인 목록에1개, 타인0, 기존 FSRS 불변. 1440/1280 End→picker·열기→저장→Esc 복귀·스크롤 유지. 사람은 저장 강요/읽기 중단·나중에 정말 필요한지 관찰 |
| **LCP-D5-I02 안전한 왕복** · 같은 구현/수용 owner | 기존 WordVault Browse의 MapReturnBar 구조 참고, Story 전용 작은 문맥 줄·엄격한 parser·login next 재사용. 지도 contract 자체는 변경하지 않음 | I01과 parser/문구 설계는 병행 가능, 실제 저장→이동 종단은 I01 뒤. L3·중간. stale/공유 URL을 개인 진도로 오해할 위험 | Story→일반 단어장→같은 release/unit, 새로고침·로그인 실패/취소·안전 복귀. 외부URL/음수·범위초과/철회/다른 revision/계정전환 차단·중립 안내. 기존 map 진입/일반 단어장 무회귀. 실제 SR 별도. 자발적 왕복 뒤 사건 흐름 회복 관찰 |
| **LCP-D5-P03 문장 소리 적합성 검토** · 조사/구현 후보 `lcp-story-claude`, 검토 `lcp-story-codex` | 기존 Web Speech/controller 재사용 적합성·권리 범위·한 문장 일시 좌표·cleanup을 문서/제한 probe로 확인 | I01/I02와 독립. **실행 버튼/신규 오디오 제작 승인 아님**. L1 조사, 실행을 고치면 L2/L3. voice품질·기기차이·권리 경계 | 기존 단어 발음과 문장 낭독 구분, 권리 결과·지원/음성없음/오류/취소·재생중 이동·singleton 영향 기록. 실제 청취·발음 이해가 확인되기 전 듣기 품질 PASS 없음. 부적합하면 기존 낱말 발음만 KEEP |

I01+I02가 다음 구현 묶음의 최소 범위다. P03 결과가 없어도 저장/왕복과 D5 설계를 막지 않는다. DB 쓰기 검증에는 당시 승인 범위·격리 환경을 재확인한다. **이번 설계가 dev 낱말 INSERT나 새 SQL 적용 승인을 뜻하지 않는다.** 기존 SQL 승인은 다른 DB 변경에 전용하지 않는다. 불필요한 대형 TASK·전면 서비스 연결을 만들지 않는다.

교재/지도 작업이 실제 필요해질 때만 기존 `learning-map`, `factory-order-lineage`, 해당 자격 담당의 살아 있는 범위를 확인한다. 원장의 오래된 PID를 실행 증거로 쓰거나 다른 owner 파일·대화·작업을 수정하지 않는다. 현재 독서용 두 단위는 이 영역의 변경을 의존성으로 만들지 않는다.

## 8. 실제 학습자 검증과 기술 검증 분리

[기존 관찰표](./LEARNER_OBSERVATION.md)를 재사용한다. 참가자 모집·동의·자료 보호는 미실행이며, 개발 계정의 행동은 사람 효과에서 제외한다. 새로운 이벤트·테이블·대시보드를 이번에 설계의 선행조건으로 만들지 않는다.

| 확인할 가치 | 최소 관찰·직접 자료 | 기존 보조 기록 / 성급하게 결론내리지 않을 것 |
|---|---|---|
| 읽기 지속 | 도구 없는 읽기 선택도 허용하고 도움 필요 순간·복귀·중단 이유 관찰 | Story start/resume/position. 체류시간·완료가 흥미/이해 아님 |
| 선택 저장 | 어떤 뜻/표현을 왜 남겼는지, 저장 후 읽기 흐름 회복·과잉 저장 여부 | 본인 vocab의 존재는 저장 성공일 뿐 회상·숙달 아님 |
| 소리 지원 | 음성이 필요한 순간·실제 이해 변화·방해/기기 실패 직접 관찰 | 지원 API/voice 수/재생 성공은 청취 품질·이해 증거 아님 |
| 훈련 선택 | 교사 지시인지 스스로 선택했는지, 독서/훈련의 다른 목적을 이해하는지 | Dictation/Echo/SRS 기록은 각각의 과제 결과이며 Story 독해 성장으로 합산하지 않음 |
| 다음 자발 독서 | 읽지 않음·동일 작품·실제 다음 episode·다른 작품을 구분 | 현재 단일 공급에서는 다른 Story 선택 `NOT_RUN_NO_ALTERNATIVE` |
| 독립 이해 성장 | 새로운 미노출 글·독립 평가자/근거·노출/지원 조건·지연/비교 설계 | D6에 이관. 같은 Story를 반복한 향상·AI 검수·기술 PASS를 전이로 해석하지 않음 |

관찰 중 수집할 직접 의견은 동의 범위의 비공개 자료다. 공개 analytics 속성에 제목·본문·사용자 ID·자유응답을 추가하지 않는다. 현재 이벤트가 단어/맥락 도움 성공·개발 traffic 자동 제외를 완비하지 않은 사실을 유지한다. 이벤트가 없다고 행동이 없었던 것으로 세지 않는다.

## 9. 콘텐츠 공급·권리와 독립적인 진행 범위
