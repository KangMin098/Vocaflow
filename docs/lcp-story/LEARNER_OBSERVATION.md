# U4 — 실제 학습자 Story 관찰 준비

> T-0187 · D2 U4 · 2026-10-26 · **준비 완료 / 실제 참가자 관찰 NOT_RUN / EDUCATION_EFFECT_UNVERIFIED**
> 기존 화면·이벤트·본인 진도 조회를 재사용한다. 새 이벤트·테이블·대시보드, 참가자 모집·동의·평가는 이번에 실행하지 않았다.

[D2 §8](./LCP_D2_CURATION.md#8-실증-검증평가-계획)과 [S7 §6](./S7_PILOT.md#6-측정-계획-실행-전-고정--데이터-없음)의 준비물을 관찰표로 구체화한다. 기존 [IMPLEMENTATION S7](./IMPLEMENTATION.md)의 측정 정의를 대체하거나 별도 파일럿을 시작하지 않는다. 사전 기준선 이후 목표를 정하고, 작품 간 결과를 장르/각색의 인과 효과로 해석하지 않는 기존 경계를 유지한다.

## 시작 조건과 개인정보

실제 참가자와 필요한 동의/자료 이용 조건이 준비된 뒤 실행한다. 이미 승인된 AI 개발 계정은 참가자가 아니다. 관찰자는 참가자에게 읽지 않기·중단·다른 작품 선택이 가능함을 알리고 성적·완독 보상을 전제로 하지 않는다. 교사가 지정한 읽기와 참가자의 자유 선택을 분리한다. 실제 답변·이름·UID·이메일·인증정보를 저장소나 제품 이벤트에 기록하지 않는다.

외부 관찰표의 익명 참가자 코드는 동의 후 부여하며 개인정보 대응표는 이 문서/저장소에 두지 않는다. 직접 발언이 필요한 경우 동의 범위의 별도 비공개 자료에서만 다룬다. 관찰표는 평가/자동 채점 도구가 아니며 이해·선호 판단에 실제 근거를 남기는 최소 준비물이다.

## 관찰표 공통 필드

`관찰코드 | 익명 참가자코드 | 콘텐츠코드·release key | 최초/재독 | 제시 순서 | 행동 맥락 | 과제·성적·보상 유무 | 시스템 권유 여부 | 계정분류 | 기록 상태 | 관찰/동의된 짧은 직접 응답`

이 필드는 **외부 관찰표**용이다. release key·자유 응답·참가자 코드를 새 이벤트 속성으로 추가하지 않는다.

- 행동 맥락: `자발 / 교사 지시 / 조사자 요청 / 불명`.
- 계정분류: `확인된 사람 / AI 개발 / 불명`. 개발·불명은 사람 실증 집계에서 제외한다. 개발 표식이 없다는 사실만으로 사람이라고 확정하지 않는다.
- 기록 상태: `관찰됨 / 선택 거절 / 관측 기회 없음 / 기술 차단 / 미관찰`. 결측을0이나 성공으로 바꾸지 않는다.

## 최소 진행 순서

| 단계 | 실제 관찰·짧은 질문 | 재사용할 보조 자료 | 해석 경계 |
|---|---|---|---|
| 1 발견·선택 | 소개를 보고 선택/거절한 작품과 이유. “어떤 점 때문에 골랐나요?” | 공개 `/library/stories`, catalog 이벤트의 전체 작품/판본 수 | 카드 노출·클릭은 흥미 확정이 아님. 제시 순서/교사 지시를 함께 기록 |
| 2 실제 읽기 시작 | 시작 후 본문이 보였는지와 실제 읽기 관찰/자기보고 | 기존 `start` 저장 성공 이벤트와 본인 reader context | GET·prefetch·위치 저장만으로 실제 읽음 판정 금지. 기술 차단 별도 |
| 3 도움 사용 경험 | 스스로 뜻/원문 도움을 요청했는지, 성공/실패, “도움이 됐나요, 흐름이 끊겼나요?” | 현재 단어 도움·원문 앵커 패널, source_open 이벤트 | 낱말 도움은 Story 전용 성공/실패 이벤트가 없음. 직접 관찰로 보완. 도움 횟수=이해 점수 아님 |
| 4 이해·흥미 직접 피드백 | 자연스러운 중단 시 “무슨 일이 있었나요?”, “궁금하거나 부담스러운 부분은?” | 동의된 직접 응답·본문 구간 대조 | 언어/서사/배경/정서/기술 원인 분리. 미검증 문항으로 합격/수준을 확정하지 않음 |
| 5 독서 재개 | 나중에 돌아온 이유·지시 여부, 복구 위치와 실제 읽기 재개 | 기존 resume·본인 last/furthest/완료 상태 조회 | 마지막으로 연 단위와 이해/독서량을 구분. 재로그인·새로고침 테스트와 자발 복귀도 다름 |
| 6 자발 다음 독서 | 다른 작품을 스스로 선택했는지, 본문을 실제 읽기 시작했는지 | 기존 다음 서가 이동·후속 작품의 start, 직접 관찰 | 서가 이동·같은 작품 재독·조사자의 요청을 ‘자발 다음 작품’ 성공으로 바꾸지 않음 |

현재는 대표 Story **1편**만 제공된다. 다른 작품 선택·시작은 `NOT_RUN_NO_ALTERNATIVE`다. 서가 복귀 동작은 따로 관찰할 수 있지만 성공률 분모/분자를 임의로 만들지 않는다. C06은 원천 준비 대상이며 아직 선택 가능한 발행본이 아니다.

## 기존 계측의 정확한 의미

`story_catalog_viewed`는 `works:number / editions:number / signed_in:boolean`이다. `story_reader_action`은 `action / kind / coverage / unit_index:number / completed:boolean`이다. action 허용값은 `start|resume|navigate|unit_complete|source_open|edition_switch`, kind는 `story_edition|easy_reader`, coverage는 `complete_work|episode|excerpt`다. 작품/발행 식별자와 주관 피드백이 없으므로 기존 퍼널만으로 작품별 흥미 전환을 계산할 수 없다.

목록·본문 GET/새로고침은 진도를 기록하지 않는다. start/resume/navigate는 위치 저장 성공, unit_complete는 명시적 완료 저장 성공에 관한 기술 신호다. 단어 뜻 조회 성공/실패 이벤트는 없다. 완료 클릭이나 FSRS 상태로 흥미/이해/원문 완독을 판정하지 않는다.

보호된 `app_metadata`의 AI 개발 표식은 승인된 범위의 계정 분류 대조에 사용할 수 있지만, 현재 analytics 경로는 이를 읽어 자동 제외하지 않는다. 익명/출처불명 이벤트는 관찰된 사람과 연결되지 않으면 실증 분모에서 제외한다. analytics API는 오류에도204를 반환할 수 있으므로 이벤트 부재를 행동 부재로 해석하지 않는다. 이번에 계정분류 자동화·계측 변경을 구현한 것은 아니다.

코드 근거: `apps/web/src/lib/analytics/events.ts`의 Story 이벤트, `components/library/story/story-reader-session.ts` 저장 성공 이벤트, `lib/library/story/learner.ts` 본인/조회/저장 경계, `app/api/analytics/event/route.ts`의 세션/응답 처리, `scripts/db/lcp-story-s3/dev-accounts/forward.sql`의 보호된 개발 표식.

## 수용·D6 인계

관찰 준비의 수용은 여섯 행동을 구분하고 지시/자발·개발/사람·결측을 기록할 수 있는지다. 빈 관찰표는 결과가 아니므로 실제 수치나 사례를 채우지 않는다. 콘텐츠 품질·UX·흥미·지속·성장을 각각 보고한다.

독립 독해 성장은 D6에서 미노출 지문·병렬형·채점 기준/독립성·비교 조건·지연 평가를 준비한 뒤 별도 측정한다. 이미 읽은 Story의 이해나 AI 개발 계정의 인증/완독 기록으로 전이를 입증하지 않는다. 참가자·동의·평가 자료가 없는 상태는 U1의 기술 보완이나 C06 원천 준비를 중단하는 이유가 아니다.
