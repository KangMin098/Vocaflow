# CSAT 원천 게시 게이트 — 검증 체계와 파이프라인 정보 설계 (v1, 2026-09-05)

> 확보한 원문은 **교재 생성 파이프라인을 거쳐 학습자에게 게시된다.** 그래서 이 문서가 정하는
> 것은 "좋은 지문의 기준"이 아니라 **게시해도 되는지의 판정 절차**다. 판정이 느슨하면
> 19세기 인종 서열이나 폐기된 의학이 학생 앞에 놓인다. 실제로 그런 책이 코퍼스에 있었다.

---

## 1. 왜 필요한가 — 대역 채점기로는 못 막는다

대역 채점기(`lib-fit.mjs`)는 **문장 길이 · 낱말 길이 · 연결사/지시어** 세 가지만 본다.
그 셋은 다음을 전부 통과시킨다:

| 통과했지만 게시 불가 | 실제 코퍼스에서 나온 것 |
|---|---|
| 성경 절 번호 | `18:22 So he overcame the destroyer…` |
| 도판 캡션 잔재 | `Pen drawing from the artist's water color… ]` |
| 서사문 | `Musing a few moments, he next slowly extended the arm…` |
| 저자 1인칭 방백 | `And when I read what modern critics say…` |
| 교리문 | Summa Theologica · Moral theology 합 **649편** |
| 우생학 교과서 | *A Civic Biology* (1914) — 스콥스 재판 교재, 인종 서열 5단계 |

**2026-09-05 실측**: 무작위 18편을 손으로 읽어 쓸 만한 것은 **3편**이었다.
채점기의 버그가 아니라 **채점기가 볼 수 없는 축**이다.

> ⚠️ 그래서 "적합도 100%"라는 말은 **"대역 통과 100%"**로만 써야 한다.
> "교재로 쓸 수 있음 100%"가 아니다. 두 수치를 같은 이름으로 부르면 안 된다.

## 2. 3층 게이트

| 층 | 무엇을 보나 | 판정자 | 규모 |
|---|---|---|---|
| **L1 기계** | 문서 잔재·자족성 파괴 — 규칙 11개 | `gate-rules.mjs` | 조각 전량 |
| **L2 책 단위 LLM** | 장르·교리·의사과학·차별·폐기된 사실 | Claude Code 드레인 | 책 812권 |
| **L3 조각 LLM** | L2 가 `mixed` 로 답한 책만 | Claude Code 드레인 | 해당 책의 조각 |

### 왜 책 단위인가

조각 28,015편을 하나씩 판정하는 것은 규모가 감당되지 않는다. 그런데 **같은 책에서 나온
조각은 장르가 같다** — 전기는 끝까지 전기고 교리서는 끝까지 교리서다. 812권을 판정하면
28,015편이 따라온다. **판정 수가 35배 준다.**

가정이 깨지는 경우(논설과 서사가 섞인 여행기, 부록에 표가 붙은 교과서)를 위해 책마다
**서로 떨어진 위치의 발췌 3개**를 준다. 발췌끼리 장르가 다르면 판정자가 `mixed` 로 답하고
그 책만 L3 로 내려간다.

## 3. L1 기계 규칙 — 기출로 검증한다

**실제 수능·모평 지문을 떨어뜨리는 규칙은 그 자체로 틀린 규칙이다.**
기출 810지문이 대조군이고, 규칙마다 그 위에서의 오탐률을 잰다(`gate-screen.mjs`).
**오탐이 0.00% 가 아니면 그 규칙은 못 쓴다.**

첫 실행에서 3개가 걸렸고 셋 다 성격이 달랐다:

| 규칙 | 오탐 | 정체 | 처리 |
|---|---|---|---|
| `doc-glyph` | 2.35% | `※` — 기출 안내문 23편이 쓴다 | 글리프 집합에서 `※` 제거 |
| `ref-reader` | 0.74% | `the reader` — 문학 소재 기출이 본문에서 쓴다 | 소유격 형태(`my readers`)만 남김 |
| `lex-list` | 1.23% | **대조군 오염** — `passage` 앞에 문항 번호 `39. ` 가 붙어 온다 | 규칙이 아니라 대조군을 고침 |

세 번째가 중요하다. **오탐이 났다고 규칙부터 고치면 안 된다** — 무엇에 걸렸는지 먼저 보고,
대조군이 틀린 경우가 실제로 있다.

현재 규칙 11개 · 기출 오탐 **0.00%**:

`doc-figure` · `doc-page` · `doc-footnote` · `doc-verse` · `doc-glyph` · `doc-markup` ·
`doc-caption` · `ref-crossref` · `ref-reader` · `lex-entry` · `lex-list`

## 4. L2 판정 코드 (정본 — 바꾸면 과거 판정을 못 읽는다)

### verdict

| 값 | 뜻 |
|---|---|
| `use` | 설명·논증문. 빈칸·주제·제목·순서·삽입·요약 유형의 재료 |
| `narrative` | 서사·전기·기행. **버리지 않는다** — 심경·분위기(R-MOOD)와 내용일치(R-FACT)가 요구하는 것이 정확히 이것이다. 다만 추론 유형에는 못 쓴다 |
| `reject` | 게시 불가 |

> ⚠️ **이 표와 코드가 어긋나 있었다 (2026-09-05 발견·수정).**
> `gate-import.mjs` 가 `publishable = verdict === 'use'` 로 판정해 **`narrative` 3,698편을
> 전부 archived** 로 내렸다. 표는 "버리지 않는다" 고 적었는데 코드가 버린 것이다.
>
> 그중 **1,241편이 초·중 교재용 발췌**(`feed_id='kid-excerpt'`)였다. 초·중 독해 교재는
> 이야기 지문을 싣는다 — 이 저장소가 "초·중 창의 narrative 재고가 **0편**" 이라
> StoryWeaver 를 새로 배선한 것이 그 기록이다. **수능이 서사를 빼는 것과 교재가 이야기를
> 필요로 하는 것은 다른 용도의 다른 판단**이고, 한 자로 두 용도를 재면 한쪽이 반드시 틀린다.
>
> → `NARRATIVE_OK_FEEDS`(현재 `kid-excerpt`)를 두어 **용도로 가른다.**
> `reject` 는 용도와 무관하게 게시 불가다(교리·차별·폐기된 사실).
> 되돌림은 **이 게이트가 내린 것만**(`status_message` 가 `게시 게이트:` 로 시작) 대상으로 하고,
> 예행에서도 그 수를 센다 — 예행이 영향을 안 보여주면 예행이 아니다.

### reject 사유 (`genre` 에 담는다)

| 코드 | 뜻 |
|---|---|
| `doctrine` | 종교 교리·설교·경전·교리문답 |
| `pseudoscience` | 신비주의·심령·골상학·점성술·연금술을 사실로 서술 |
| `reference` | 사전·용어집·색인·목록·연감 |
| `obsolete-fact` | 지금은 틀린 것으로 아는 과학·의학을 사실로 서술 |
| `bias` | 인종·식민·성차별 서술을 중립적 사실인 양 제시 |
| `poetry-drama` | 운문·희곡·대본 |
| `fragmentary` | 캡션·표·목록·주석 장치가 본문보다 많음 |
| `polemic` | 현행 정치·종교 갈등에서 **한쪽을 선동**하는 글 |
| `mixed` | 발췌끼리 장르가 달라 책 단위 판정이 불가 |

> **`polemic` 은 1차 판정 뒤에 생긴 코드다.** 판정자 세 명이 서로 모른 채 같은 구멍을
> 지적했다 — Trotsky *Dictatorship vs. Democracy* · Ingersoll 반교권 강연 · *War—What For?*
> 셋 다 **형식은 완벽한 논증문**이라 `use` 로 갈 수 있었고, 앞의 둘은 판정자가 `bias`/`doctrine`
> 으로 코드를 늘려 막았다. 세 명이 같은 자리에서 코드를 비틀었다는 것이 그 코드가
> 없다는 신호다.
>
> ⚠️ **정상 논설과 구별할 것.** 버크의 의회 논박, 베이컨의 조언, 쇼펜하우어의 논쟁술은
> 전부 `use` 다. 기준은 "논쟁적인가" 가 아니라 **"지금 살아 있는 갈등에서 편을 들어
> 행동을 촉구하는가"** 다. 이 기준으로 `use` 220권 중 걸린 것은 **1권**이었다.

> **`bias` 와 `obsolete-fact` 는 다른 모든 것을 이긴다.** 문장이 아무리 좋아도 `reject` 다.
> 판정 애매하면 보수적인 쪽을 고른다 — 잘못된 `use` 는 학생에게 도달하고,
> 잘못된 `reject` 는 공급만 줄인다. 두 비용은 같지 않다.

## 5. 파이프라인이 요구하는 정보 — 필드 설계

교재 생성기는 지문 하나를 받아 **어떤 유형의 문항을 몇 개 만들 수 있는지** 판단해야 한다.
그 판단에 필요한 것만 담는다. 이미 있는 컬럼은 다시 만들지 않는다.

### 이미 있는 것 (그대로 쓴다)

`source` · `source_url` · `author` · `license` · `copyright_safe_in_kr` (출처·법적) ·
`word_count` · `cefr_level` · `article_v_level` · `register` · `syntax_score` (난이도) ·
`csat_fit.topic` (기출 8칸 소재)

### 신설 — `csat_fit.gate` (마이그레이션 불필요, jsonb 키 추가)

```jsonc
{ "v": 1,
  "publishable": false,        // 게시 가능 = verdict==='use' && codes.length===0
  "verdict": "reject",
  "genre": "bias",
  "why": "19c 인종 서열을 사실로 서술",
  "codes": ["doc-figure"],     // L1 기계 규칙 사유
  "by": "book-llm+rule",
  "at": "2026-09-05T…" }
```

### 신설 — `csat_fit.make` ⚠️ **읽는 코드가 없다 (2026-09-06 실측)**

```jsonc
{ "v": 1,
  "words": 312, "sents": 16, "paras": 1,
  "windows": [{"s": 3, "e": 9}] }   // 대역을 만족하는 창의 **위치**
```

설계 의도는 "문항 생성기가 어느 구간에 빈칸을 뚫을지 다시 계산하지 않게 한다" 였고,
14,052편을 채웠다. **그런데 이 열을 읽는 코드가 저장소에 하나도 없다.**

실제 경로는 다르다 — 문항 생성기(`store-new-types`)가 문단을 잘라 `passage_text` 로 저장할 때
**그때** `itemWordSpec`(유형·학년별 시중 어수창)을 통과시키고, 조판(`composeUnits`)은
그 문항을 골라 인쇄한다. 즉 자를 자리는 **생성 시점에** 유형을 알고 정해진다.
지문 단위로 미리 계산해 둘 수 있는 값이 아니었다.

> ⚠️ **이 문서가 바로 아래에서 경고한 실수를 이 필드가 저질렀다.**
> "검증 안 된 값을 필드로 만들면 파이프라인이 그것을 근거로 고른다" 고 적어 놓고,
> **생성기가 실제로 어떻게 동작하는지 확인하지 않은 채** 필드를 만들었다.
> 다행히 아무도 안 읽어서 잘못된 선택을 유발하지는 않았지만, 그건 운이다.
>
> **초·중 6,393편의 `windows: []` 도 같은 이유로 고치지 않는다.** 수능 대역(124~163어)을
> 초·중 발췌(99~200어, 중앙값 128)에 댄 결과라 값 자체가 무의미하고, 읽는 쪽이 없으므로
> 고쳐도 아무 일이 일어나지 않는다. 초·중은 이미 자체 기준을 쓴다 —
> FK 학년대역 + 어수창 100~200(`docs/reports/grade-level-bench.json`).
>
> 남길지 지울지는 **별도 결정**이다. 지금은 "쓰이지 않는다" 는 사실만 여기 적어 둔다.

### 원문이 교재에 실리는 실제 경로 (2026-09-06 실측)

| | 수 |
|---|---|
| 게시 가능 수능 지문 | 23,382 |
| **문항이 붙은 원문** | **19,204** |
| 문항 행 | 656,182 |

**문항 보유가 진짜 신호다.** 문항이 붙었다는 것은 이미 규격에 맞게 잘린 지문이
존재한다는 뜻이고, 조판이 인쇄하는 것이 그것이다.

### ⚠️ 유형별 적합도 점수는 **넣지 않는다** — 검증에 실패했기 때문이다

처음 설계에는 `types: {blank: 2, order: 1, insert: 1 …}` 과 그 근거가 될
`cohesion`·`thesis`·`chunks3` 가 있었다. **빼기로 했다.** 저장소에 이미 그 검증 기록이 있다:

`test-passage-selection.mjs` 는 "삽입용으로 선정된 지문은 인접 문장 결속이 더 촘촘하다" 를
예측하고 기출로 쟀다. 결과(`data/passage-selection.json`):

| 무엇에 쓰인 지문 | 결속 점수 |
|---|---|
| 삽입용 (38·39) | 1.008 |
| **선정 안 된 산문 (대조군)** | **0.936** |
| 순서용 (36·37) | 0.899 |
| 주제·제목·요지용 | 0.893 |
| 빈칸용 (31~34) | 0.860 |

**대조군이 세 유형보다 높다.** 즉 결속도는 유형을 가르지 못한다. 앞선 가설 H1~H9 도
전부 유의미한 분리에 실패했다(lift 최대 37%p, 대부분 12%p 안팎).

> 검증 안 된 점수를 필드로 만들면 **파이프라인이 그것을 근거로 문항을 고른다.**
> 그때는 틀렸다는 사실조차 안 보인다 — 숫자가 있으니 근거가 있는 것처럼 보이기 때문이다.
> **비어 있는 편이 틀린 값보다 낫다.** 유형 배정은 당분간 생성기가 시도해 보고
> 실패를 세는 쪽(사후 측정)으로 간다.

## 6. 적용 절차 (재실행 안전 여부를 단계마다 적는다)

| 단계 | 명령 | 재실행 안전 |
|---|---|---|
| ① 규칙 검증 | `node scripts/csat/gate-screen.mjs` | ✅ 읽기 전용 |
| ② 판정 자료 뽑기 | `node scripts/csat/gate-book-export.mjs` | ✅ 이미 판정한 책은 다시 안 뽑는다 |
| ③ 판정 | Claude Code 서브에이전트가 `chunk-NN.out.json` 작성 | ✅ 파일 단위 |
| ④ 적용 | `node scripts/csat/gate-import.mjs --commit` | ✅ 판정이 그대로면 쓰지 않는다 |

**④ 가 하는 일**: `csat_fit.gate` 를 더하고, 게시 불가면 `status='archived'` +
`status_message` 를 남긴다.

> ⚠️ **지우지 않는다.** `archived` 는 이미 있는 상태값이고 파이프라인이 이미 거른다.
> 되돌릴 수 있게 남기는 쪽을 골랐다 — 판정이 틀렸을 때 원문을 다시 못 구하기 때문이다.
> 진짜 `DELETE` 는 판정이 굳은 뒤 **별도 결정**으로 한다.
>
> ⚠️ **`csat_fit` 을 통째로 덮으면 안 된다.** 그 안에 대역 채점 결과(`pass`·`topic`)가 있고,
> 덮으면 균형 사정권 계산이 통째로 날아간다. 읽어서 키 하나만 더한다.

## 7. PLOS 논문 전문에서 지문 뽑기 (2026-09-05)

36,337행은 평균 **36,559자**로 지문이 아니라 논문 전문이었다. 500행 표본 어디에도 수능 지문
크기(700~1,000자)가 없었다. `plos-extract.mjs` 가 **Introduction 만** 잘라 300어대로 묶는다.

### 산출물을 읽고 설계를 세 번 바꿨다

이 절이 이 문서에서 가장 중요하다. **매번 기계는 통과시켰고 사람이 읽어야 보였다.**

| 회차 | 산출물에서 본 것 | 바꾼 것 |
|---|---|---|
| 1 | `…caused by L. Since the knowledge of…` — 종명 약어에서 문장이 잘려 **뒷부분이 사라짐**. 대문자로 시작하고 마침표로 끝나 모든 관문 통과 | 자르기 **전에** 약어의 마침표를 제어문자로 보호 |
| 2 | `personnel had very low subjective norms about rat tickling…` — 1인칭·참가자 지시어를 다 걷어내도 **자기 연구 보고**가 남음 | **Discussion 을 뺐다.** Introduction 만 남긴다 |
| 3 | `This section will introduce…` · `The top right graph demonstrates…` | 문서 내부 지시·도판 참조 관문 추가 |

### 규칙은 기출로 검증하고, 못 쓰는 규칙은 버렸다

| 규칙 | 설명·논증 기출 549편 오탐 | 결과 |
|---|---|---|
| `doc-deixis` | 0.00% | 채택 |
| `as-shown` | 0.00% | 채택 |
| `graphref` (좁힘) | 0.00% | 채택 |
| `graphref` (넓게) | 0.55% — 이야기의 '줄거리(plot)'를 잡음 | 좁힘 |
| **소제목 눌어붙음** | **7.29%** — `that Australia was` 같은 고유명사를 잡음 | **폐기** |

> **소제목이 문장에 눌어붙는 것은 기계로 못 가른다.** PLOS 측정 리포트도 같은 결론이다
> (눌어붙은 제목의 2.7% 만 잡힌다). 안전 결함이 아니라 품질 결함이므로 기록하고 넘어간다.
> ⚠️ 이 실패는 `lib-plos.mjs` 에 적혀 있다 — **다시 시도하지 말 것.**

### 판정 표는 한 벌이어야 한다

추출기와 재검사기가 각자 문장을 나누자, 재검사기가 약어를 보호하지 않아
**스스로 만든 조각을 보고 `truncated-abbr` 370건**을 냈다. `lib-plos.mjs` 로 표를 공유하니
실제 결함 **183편(4.4%)** 만 남았다. 그 183편은 내렸다.

### 결과 (2026-09-06 실측)

| | 게이트 직후 | PLOS 추출 후 | L3 반영 후 |
|---|---|---|---|

> ⚠️ **`purposeOf` 의 한 줄 순서가 추출 성과를 통째로 지웠다 (2026-09-06 발견·수정).**

> 이렇게 생긴다 — 그래서 매 단계 뒤에 **같은 자로 다시 잰다**.

## 7-2. L3 — 책 단위로 못 가른 49권 (2026-09-06)

조각 **1,290편**을 서브에이전트 6개가 하나씩 판정했다. 이 작업은 위험을 줄이는 것이 아니라
**잘못 묶여 내려간 공급을 되찾는 것**이다 — 그 책들은 이미 전부 격리돼 있었다.

| 판정 | 편 |
|---|---|
| `use` | 200 |
| `narrative` | 182 |
| `reject` | 908 |

`reject` 사유: `fragmentary` 369 · `not-selfcontained` 279 · `poetry-drama` 106 ·
**`bias` 59** · `reference` 36 · `polemic` 20 · `doctrine` 17 · `obsolete-fact` 16 · `pseudoscience` 6.

**251편을 격리에서 되살렸다.**

### 판정자 여섯이 각자 같은 결함을 지적했다

내보내기가 900자에서 잘라 발췌 절반이 **낱말 중간에서 끝났다.** 여섯 명이 서로 모른 채
전부 같은 판단을 했다 — "그건 저장된 본문의 성질이 아니라 내보내기 산물이므로
`fragmentary` 로 세지 않는다". 세었다면 조각의 2/3 가 기계적으로 반려됐을 것이다.
문장 경계에서 자르도록 고쳤다.

> **여섯이 독립적으로 같은 자리를 짚었다는 것이 그 자리가 진짜라는 신호다.**
> 한 명이 말했으면 취향이었을 것이다.

### `not-selfcontained` 를 새로 두었다

L2 에는 없던 코드다. 조각을 하나씩 보니 **문법은 멀쩡한데 혼자 못 읽는 글**이 279편으로
두 번째로 많았다 — "Similarly horses suffer…", "the aforementioned hollow",
"if you look at the picture on page 145". 책 안에서는 자연스럽고 지문으로는 못 쓴다.

판정자들이 "다듬으면 살릴 수 있다" 고 표시한 것들이 있다(Plutarch 의 습관화 논증,
Byzantine Churches 의 반증 논증, Wells 의 궤간 경로의존성). 규칙상 반려가 맞고 그대로 뒀다 —
**다듬어서 살리는 것은 판정이 아니라 편집이고, 별도 단계여야 한다.**

### 조각 판정은 책 판정에 덮이지 않는다

`gate.by = 'chunk-llm'` 표시를 두고 `gate-import` 가 그 행을 건너뛴다.
두 층이 같은 칸을 쓰면 마지막에 돈 쪽이 이기고, 그게 하필 더 자주 도는 쪽이다.

## 8. 규칙을 고쳐도 데이터가 안 바뀌고 있었다 — 규칙 판 (2026-09-06)

이 절이 이 문서에서 두 번째로 중요하다. **실행은 성공했고, 보고도 정상이었고, 반영은 안 됐다.**

### 무엇이 있었나

`csat` 용도가 `narrative` 를 막고 있었다. 수능에는 **서사여야만 서는 유형**이 있는데
(19번 심경 · 43~45번 장문) 그 한 줄이 통째로 막았다. 고쳤는데 — **4,401편이 격리에 그대로 남았다.**

원인은 `gate-import.mjs` 의 재실행 최적화였다:

```js
// 저장된 판정과 지금 용도가 같으면 건너뛴다
if (!g || g.v !== 2 || g.purpose !== purposeOf(r)) return false
```

**규칙이 바뀐 것을 볼 방법이 이 조건에 없다.** 그래서 전량을 "이미 같음" 으로 건너뛰고
`이미 같음 90,327` 을 정상 보고했다. 아무도 안 틀렸는데 데이터가 안 움직였다.

> ⚠️ **이 종류가 가장 위험하다.** 오류가 나면 고치는데, 정상 종료하고 안 바뀌면
> 다음 측정까지 아무도 모른다. 실제로 이 세션에서 "게이트 적용 완료" 라고 두 번 보고한 뒤
> 사용자가 "목표 달성?" 을 물어 재측정하고서야 드러났다.

### 판을 둘로 나눈 이유

| 상수 | 무엇의 판 | 올리면 |
|---|---|---|
| `RULES_VERSION` | 판정 논리(`purposeOf`·`decide`·`PURPOSE_RULE`) | 전량 재판정 |
| `CODES_VERSION` | 기계 규칙(`HARD_RULES`) | 전량 **본문 재수신** + 재판정 |

처음엔 하나였다. 그랬더니 판정 논리만 바꾼 재판정이 **본문 9만 편(1.3 GB)을 다시 받아**
회차당 1,600편으로 기어갔다 — 42회가 더 필요한 속도였다. 저장된 `gate.codes` 는
기계 규칙이 그대로면 여전히 유효하므로, 그때는 본문이 필요 없다. 분리 후 **6,000편**.

⚠️ v2 기록에는 `cv` 가 없다. 그 기록은 지금의 `HARD_RULES` 로 쓰인 것이므로 판 1로 인정한다 —
안 그러면 첫 재판정에서 본문을 전부 다시 받아 이 분리가 아무 일도 못 한다.

### 흩어진 잔여분은 `--from` 으로 못 줄인다

판을 올린 뒤 남은 행은 id 전체에 흩어져 있다(서사는 어느 책에나 있다). 매 회차가 처음부터
훑으며 이미 수렴한 5만 행을 페이지로 다시 넘겨 **회차당 220편**까지 떨어졌다.

- `--from <uuid>` — 앞쪽이 통째로 수렴한 경우에만 쓴다
- `--stale` — **아직 지금 판이 아닌 행만 질의한다.** 220 → **3,165편**

그리고 판정이 **안 바뀌는 것이 자명한 31,444행**(서사도 아니고 `plos-extract` 도 아닌 행)은
SQL 로 판만 찍었다. `decide()` 가 같은 값을 돌려주는 것이 확실한 행을 스크립트로 왕복시키는 것은
낭비다 — 다만 이 지름길은 **"판정이 안 바뀐다"를 사람이 확인한 경우에만** 쓴다.
