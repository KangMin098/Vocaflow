# 학습 원리 지식 체계 — 설계 (1단계)

작성 2026-09-28 · 상태 **설계 제안(사용자 확인 대기)** · 마이그레이션 없음(2단계에서 SQL 제출 → 승인 후 적용).
목적: Vocaflow 가 「영어 학습의 본질·원리를 꿰뚫는 플랫폼」이 되기 위한 **근거 있는 지식층**. 모든 문장은 출처로 거슬러 올라갈 수 있어야 하고, 모르는 것은 「없음」이 아니라 「공백」으로 남는다.

## 1. 다섯 층 — 무엇을 구분해 관리하는가

용어가 섞이면 관리가 무너진다. 「학습법·공부법·방법론·원리·본질」을 **층**으로 나눈다. 위로 갈수록 적고 오래가며, 아래로 갈수록 많고 구체적이다.

| 층 | 질문 | 예 | 개수 감각 | 바뀌는 속도 |
|---|---|---|---|---|
| **L1 본질** Essence | 이 영역에서 「잘한다」는 게 결국 무엇인가 | 독해 = 글쓴이의 주장-근거 구조를 복원하는 일 | 영역당 1–3 | 거의 안 바뀜 |
| **L2 원리** Principle | 왜 그렇게 하면 배워지는가 (기제) | 인출 연습 · 간격 반복 · 바람직한 어려움 · 이중 부호화 | 전체 20–40 | 연구가 쌓일 때 |
| **L3 방법론** Method | 원리를 한 영역에 적용하는 절차 | 예문 → 확인 문제 → 다른 문장에 적용 (문법) | 영역당 5–20 | 전문가 근거가 늘 때 |
| **L4 공부법** Practice | 학습자가 오늘 하는 구체 루틴 (조건 포함) | 고1·기초: 하루 15분, 틀린 빈칸 문항의 근거 문장 다시 찾기 | 방법론당 1–5 | 자주 |
| **L5 근거** Evidence | 누가·어디서 그렇게 말했나 / 무엇이 관찰됐나 | 영상 03:12–04:05 · 교재 특징 절 · 연구 논문 · 기출 원천 서지 | 무제한 | 계속 쌓임 |

- 층은 **위로만 연결**한다: 공부법 → 방법론 → 원리 → 본질. 근거는 어느 층에든 붙는다.
- L3·L4 의 각 항목은 **조건**(학령·숙련도·시험·과정)을 가진다. 조건이 다르면 같은 문장이라도 다른 항목이다(기존 Gate 0 규칙 유지).
- L2 원리는 이미 제품에 있는 **학습 과학 7**(LEARNING_MODEL)을 씨앗으로 쓴다. 새로 만들지 않는다.
- L1 본질은 사람이 쓰고 사람이 승인한다. 자동 추출이 L1 을 만들지 않는다.

## 2. 축 — 무엇으로 자르는가 (기존 분류 그대로)

## 3. 근거 등급 — 하나의 사다리로 통일

영상·교재·연구·기출 원천이 서로 다른 말로 「확인됨」을 쓰지 않게 한 사다리로 맞춘다.

| 등급 | 뜻 | 방법론 근거에서 | 기출 원천(Codex)에서 |
|---|---|---|---|
| **A 직접 확인** | 원문 위치까지 대조 | 영상 초 구간·문서 절을 읽고 재서술 | `confirmed_exact` |
| **B 유력** | 서지는 공식 확인, 해당 부분 대조 미완 | 교재 목차·소개만 확인 | `supported_candidate` |
| **C 계보** | 같은 소재·연구의 다른 원천 | 같은 주장을 다른 사람이 한 것 | `topic_lineage_only` |
| **G 공백** | 찾았으나 검증 불가 | 자막 미확보 · 권리 미확인 | `unresolved` |

- 표시 규칙: A 만 「확인」, B 는 「후보」, C 는 「관련」, G 는 공백 목록으로. 개수는 등급별로 따로 센다.
- **주장 귀속**: 출처가 명시한 것(`stated`)과 분석자가 추론한 것(`inferred`)을 칸으로 가른다. 추론을 전문가 말로 쓰지 않는다.
- **효과 강도**는 연구 설계가 확인된 근거가 있을 때만. 없으면 `평가 안 함`. 전문가 다수 동의 ≠ 효과 검증.

## 4. 출처의 종류 — Codex 조사는 여기에 들어간다

| 출처 종류 | 예 | 원문 보관 |
|---|---|---|
| 영상 | 강사 채널 309편 (`channel-videos.json`) | 안 함 — 링크·초 위치만 |
| 공식 대본 | BBC Learning English · VOA · British Council | 안 함 — 링크·절 위치만 |
| 교재·강좌 소개 | 쎄듀 교재특징 · 메가스터디 강의특징 | 안 함 |
| 연구 | 논문·리뷰 | 안 함 — 서지·DOI |
| **기출 원천** | 수능·모평 지문이 발췌된 책·논문 (Codex 2026-09-28) | 안 함 — 문항 ID·본문 해시·서지·근거 URL |

### Codex 「평가원 영어 원천 전수 조사」 반영 방식

산출물: `docs/reports/csat-source-origin-results-20260928.jsonl`(713 지문) · `scripts/csat/source-origin-curated.json` · 보고서 `csat-source-origin-audit-20260928.md` (브랜치 `design/replica-first`, 커밋 `7abae358`).

이것은 **방법론 근거가 아니라 「수능 독해」 영역의 본질을 밝히는 1차 관찰 자료**다. 이렇게 넣는다:

1. **출처**: 등급 A·B·C 인 49 지문의 책·논문을 `기출 원천` 종류 출처로 등록(서지·근거 URL·등급). 664 미확인은 출처가 아니라 **공백 1건**(「미확인 664 지문 — 원천 검색 방법 개선 필요」)으로.
2. **관찰(근거 L5)**: 「어느 시험의 어느 문항이 어느 학문 분야 책에서 왔는가」 — 문항 ID·해시·분야만. 지문 원문 없음(기존 JSONL 원칙 유지).
3. **본질(L1) 초안 후보**: 관찰을 집계해 사람이 쓰는 문장의 **근거**로 붙인다. 예) 「수능 독해 지문은 대학 교양·학술서의 한 단락이다 → 독해의 본질은 낯선 학문 분야의 논증 구조를 배경지식 없이 복원하는 것」. 이 문장은 **분석자 추론(`inferred`)** 으로 표시하고, 근거 수는 A 등급만 센다(현재 26).
4. **제품 적용**: 원천 분야 분포 → 지문 배경지식 태그 · 「원천을 읽어 볼 책」 추천 후보(권리 확인 후). 자동 처방 아님.

주의: A+B+C = 49/713(6.9%). 이 표본으로 「수능 지문 전체가 ~ 이다」라고 쓰지 않는다 — 문장에 표본 크기를 함께 적는다.

## 5. 수명주기 — 한 항목이 거치는 상태

```
수집됨 → 추출됨 → 검토 중 → 채택 ─→ 제품 적용
   │         │          └→ 반려(이유)     └→ 재검토(근거 변화 시)
   └→ 공백(접근 실패·권리 미확인·자막 없음)
```

- **수집됨**: 출처 메타데이터만 (영상 309편은 지금 여기).
- **추출됨**: 에이전트 드레인이 주장(claim)과 위치를 뽑음. 아직 사실로 쓰지 않는다.
- **검토 중 → 채택**: 사람(관리자)이 승인해야 L3·L4 로 올라간다. L1 은 사람만 쓴다.
- **재검토**: 근거가 추가·철회되면 해당 방법론이 자동으로 검토 대기에 다시 뜬다.

## 6. 저장 — 기존 테이블과의 관계 (2단계에서 SQL 로)

현재 `methodology_*` 10 테이블은 **스냅샷(batch) 모델**이다: 모든 행이 `batch_id` 에 묶이고 가져오기마다 새 스냅샷이 생긴다. 가져오기 기록에는 좋지만, 관리자가 항목 하나를 승인·수정하기엔 무겁다(수정 1건 = 스냅샷 1개).

**제안**: 스냅샷은 「가져오기 원장」으로 남기고, 그 위에 **살아 있는 등록부**를 둔다.

| 새 테이블 (안) | 담는 것 |
|---|---|
| `knowledge_items` | L1–L4 한 항목 (층 · 문장 · 조건 축 · 상태 · 검토자 · 버전) |
| `knowledge_links` | 층 간 연결 (공부법→방법론→원리→본질) · 반대/보완/조건 차이 관계 |
| `knowledge_evidence` | 항목 ↔ 출처 위치 · 등급(A/B/C) · stated/inferred · 가져온 스냅샷 id |
| `knowledge_gaps` | 공백 (영역 · 질문 · 다음 행동 · 원인) |
| `knowledge_reviews` | 상태 전이 기록 (누가·언제·왜) |

- 출처·전문가·채널은 **기존 `methodology_sources` / `_experts` / `_channels` 를 참조**한다(중복 테이블 없음).
- 기출 원천은 `csat_items` 를 문항 ID 로 참조하고 원문 열을 두지 않는다.
- 전부 RLS · service role 전용 (기존과 동일). 학습자 화면 노출은 「채택」 상태만, 별도 결정.

## 7. Admin 메뉴 (3단계 안)

사이드바에 새 그룹 **「학습 원리」** — 「교재」와 「콘텐츠 공급」 사이. 공급이 아니라 **판단 기준**이기 때문.

```
학습 원리
├─ 원리 지도          /admin/knowledge            본질 ↔ 원리 ↔ 방법론 연결 한눈에 · 영역별 공백
├─ 본질·원리          /admin/knowledge/principles L1·L2 목록 · 사람만 작성
├─ 방법론·공부법      /admin/knowledge/methods    L3·L4 · 조건 필터(학령·숙련도·시험·과정)
├─ 검토 대기          /admin/knowledge/review     추출됨 → 채택/반려 · 재검토
├─ 근거 · 출처        /admin/knowledge/sources    영상·대본·교재·연구·기출 원천 · 등급별
│   └─ 기출 원천      /admin/knowledge/sources/csat   Codex 713 지문 · A26 · B22 · C1 · G664
├─ 전문가 · 채널      /admin/knowledge/experts    강사 21 채널 · 영역 · 수집 상태
└─ 공백               /admin/knowledge/gaps       모르는 것 목록 · 다음 행동
```

기존 `/admin/methodology`(Codex 초안 워크벤치)는 「근거 · 출처」로 흡수한다.

## 8. 화면 골격 (4단계 안)

**원리 지도** — 판면 = 영역 11열 × 층 4행 격자. 칸 = 항목 수(등급 A 만 진하게) · 빈칸은 공백으로 **보이게**(0 이 아니라 「모름」). 칸을 누르면 오른쪽 판에 항목 → 연결 → 근거가 한 줄씩 펼쳐진다(점진 공개).

**항목 상세** — 위: 층 표지 · 문장 · 조건 칩. 가운데: 위로 연결(이 공부법은 어떤 원리를 쓰나)·아래로 연결. 아래: 근거 목록 — 등급 배지(A/B/C) · stated/inferred · 출처 링크(영상은 초 위치로 열림). 오른쪽: 검토 기록.

**검토 대기** — 한 번에 하나. 왼쪽 추출 주장 + 근거 위치, 오른쪽 기존 유사 항목(병합 후보 — 자동 병합 안 함). 행동 셋: 채택 · 반려(이유 필수) · 조건 다름으로 분리.

**기출 원천** — 시험 × 문항 번호 격자, 칸 색 = 등급. 분야별 막대(A 만/전체 토글). 칸 → 서지 · 근거 URL · 연결 문항 목록.

디자인: Admin 스킨 그대로(먹색 · Inter · 액센트 `--p`, DD-82). 등급은 색만으로 전하지 않고 글자(A/B/C/G)를 함께 쓴다(접근성). 44px 터치 타겟 · 보이는 focus.
