### P1 — 세션 없는 합성 시도의 synthetic 을 뒤집으면 실제 효과 판정이 통과한다

재현(격리 PG):
1. `learning_attempt_record(p_session_id => null, p_synthetic => true)` 로 같은 trial 에 사전 · 사후 시도를 기록한다(independent · min_n 1). 이 상태에서 `analyzed` 전환은 **거부**된다.
2. `update learning_task_attempts set synthetic = false where trial_id = …` 를 실행하면 **허용**된다.
3. 그 뒤 `analyzed · supported` 로 전환하면 **허용**된다 — 합성 데이터가 실제 효과 근거가 됐다.

원인:
- `learning_trial_sample_frozen_attempt` 는 분석이 끝난 표본만 막는다.
- `learning_first_attempts` 는 세션이 없는 시도에 대해 그 시도의 `synthetic` 값만 본다.

이 빈틈은 **적용된 160000 부터 있었고 M8 도 막지 않는다**. 이 경로는 service_role 이나 관리자가 직접 UPDATE 할 때만 열린다. 학습자 키에는 쓰기 권한이 없다.

수정 권고: 시도의 `synthetic` 도 바꿀 수 없게 한다(`new.synthetic is distinct from old.synthetic` 이면 예외). 세션 synthetic(M8) · trial synthetic(170000)과 같은 원칙이다. 이 수정을 M8 에 넣고 하네스에 단언을 더한다. f5 에 전달함.

## 3. f5 제품 통합 현황(브랜치 읽기 · f5 회신 대기)

- 커밋 `c1f4471ea`: 문항 확인 과제 기록을 G2 `learning_attempt_record` 계약으로 옮겼다.
  - 요청 본문: `{ response, sec, clientSessionId, clientMutationId, answeredAt, helpLevel }` → 응답: `{ grade, attempts, outcome }`
  - 클라이언트 메타는 `task-meta.ts` 가 만든다. 패널을 열 때마다 세션을 하나 만든다. 같은 답을 재전송할 때만 같은 mutation id 를 쓴다. 해설 극장을 이미 열었으면 `viewed_first` 로 보수 판정한다.
- Practice 이식은 커밋 `54aa73186` 까지 반영됐다. 해설 열람은 시도 payload 밖으로 뺐다.
- **머지 주의**: 이 브랜치는 main 의 과제 거부 코드(`no_task` · `not_live` · `invalid_input`, `16eafd3ad`) 이전에서 갈라졌다. `TaskInputError` 에서 충돌이 난다. 코드를 유지하고 `conflict` 등 새 사유에도 코드를 붙여 달라고 f5 에 요청함.
- B6′ 실제 DB 멱등 검증 결과와 기출 → Practice → 복습 → 재평가 E2E 결과: f5 회신 대기.
