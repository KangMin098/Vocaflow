# 학습 원리 vNext — 두 고리의 완료 판정 기준과 기준선

작성 2026-10-08 · 검증 담당 세션(사용자 결정: 실제 DB 검증 · 결과 판정). **구현은 정본 세션(「학습 지도 설계 검토 및 구현」) 몫** — 이 문서는 그 결과를 판정할 기준과 측정 방법만 정한다.
기준은 사용자 지시(2026-10-08 감사 판정문 §4·§5)를 검증 가능한 문장으로 옮긴 것이다. 측정 쿼리: `scripts/knowledge/loop-probes.sql`(읽기 전용).

## 고리 A — 학습 결과 → 원리·방법론 재평가

사용자 규칙: 성과 변화가 원리를 **자동으로 확증·반박하지 않는다**. 성과 집계는 재검토를 **촉발**할 수 있을 뿐이고, 인과 판단은 연구 설계·데이터 품질에 따라 따로 한다. 실제 효과 데이터가 없으면 `insufficient_evidence`.

| # | 판정 기준 | 측정 | 기준선(2026-10-08) |
|---|---|---|---|
| A1 | 모든 학습자 시도가 「어떤 적용 · 버전으로 배웠나」를 갖는다(application_id · 버전) | probe A1 · 코드: 기록 경로가 적용 id 를 넘기는가 | 시도 0행 — 판정 불가 |
| A2 | 효과 표본은 실제(비합성) · 독립(해설 먼저 아님) · 해설 뒤 아님 · 첫 시도만 | probe A2 · DB 뷰 `learning_first_attempts` 정의 | 뷰 정의는 기준 충족(160000) · 행 0 |
| A3 | trial 이 계획 → 진행 → 분석으로 가는 **경로가 코드에 있다**(시도에 `trial_id` · 단계 부여, 분석 결과 기록) | probe A3·A4 · 코드 호출처 grep | trial 4건 모두 planned · 시도에 trial_id 0 · 분석·기록 호출처 0 → **없음** |
| A4 | 표본 부족이면 결과가 `insufficient_evidence`(또는 동등)로 남고 efficacy 가 열리지 않는다 | probe A5 · 단위 시험 | efficacy 열린 항목 0(가드 정상) |
| A5 | 성과 신호(성과 부족 · 상충 · 데이터 품질 경고)가 **관리자 검토 큐**에 항목으로 뜬다 — 자동으로 상태를 바꾸지 않는다 | 관리자 화면 · 코드 | 없음 |
| A6 | 검토자가 그 신호로 원리·방법론을 「검토 중」으로 돌리면 기존 트리거가 적용을 멈춘다(근거 · 버전 기록) | probe A6 · E2E | 결과 기원 재검토 0(첫 측정 9건은 채택 사유 문구 오탐 — 쿼리 수정) |
| A7 | 합성 · 미리보기 · 골격 문항 기록은 A2~A6 어디에도 들어가지 않는다 | probe A2 · 단위 시험 | 뷰 · 170000 가드 기준 충족 |

## 고리 B — 진단 → 학습 원리 → 학습 과제 추천

사용자 규칙: 「틀린 유형 → 바로 원리」 금지. **진단 관찰 → 역량 후보 → 추가 확인 과제 → 확인된 학습 요구 → 원리 기반 과제 추천**. verified 진단 전에는 약점을 확정하지 않는다. 미채택 · 재검토 중 · 비활성 적용은 학습자에게 보이지 않는다. 읽기 7단계 · 단일 CTA 유지.

| # | 판정 기준 | 측정 | 기준선(2026-10-08) |
|---|---|---|---|
| B1 | 진단 산출(속성별 숙달 · `insufficient` · 증거 플래그)이 「역량 후보」로 전달되는 계약이 있다 | 코드: 진단 → 지식 조회 계약 | 진단 · 지도 코드에 학습 원리 참조 0 → **없음** |
| B2 | 후보는 「추가 확인 과제」를 거쳐야 「확인된 요구」가 된다 — 한 번의 오답으로 확정하지 않는다 | 코드 · 단위 시험 | 없음 |
| B3 | 확인된 요구 → 채택 · active 적용 과제만 추천(라이브 사슬 게이트) | probe B3 · `live-chain` | 게이트 자체는 있음(과제 포함 여부만) |
| B4 | 학습 지도 FIND 연결은 적용 행(`learning_map_find`)으로만 — 코드에 박지 않는다 | probe B2 | b6-3 active · a3-4 draft |
| B5 | 사람 검토 전 비노출 결정(3항목)이 학습자 서버 조회 · 지도 링크까지 지켜진다 | probe B4 · B3 | **위반 상태** — 아래 §주의 |
| B6 | 원리가 과제의 문항 · 단계 · 순서를 실제로 정할 때만 「원리 기반」이라고 표시한다 | 코드 · 화면 문구 | 지금은 켜기/끄기만 — 표시도 그래야 한다 |

## 판정 방법

- 각 기준은 「코드 근거 + 측정 값」 둘 다 있어야 통과. 코드만 있고 측정 0 이면 「경로 있음 · 미실증」.
- 실제 학습 효과(인과)는 이 문서의 어떤 기준으로도 통과하지 않는다 — 실학습자 표본 · 연구 설계가 필요.
