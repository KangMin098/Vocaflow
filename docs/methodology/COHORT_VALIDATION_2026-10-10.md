# 합성 학습자 집단으로 본 학습 결정 엔진 검증 (2026-10-10)

> **합성 결과다 — 인간 학습자의 학습 효과가 아니다.** 목적은 시뮬레이션 정답률이 아니라 결정 엔진이 수행 근거에 맞게 · 일관되게 · 설명 가능하게 결정하는지 보는 것이다.
> 실행: `scripts/knowledge/synthetic-cohort-run.mts`(실제 학습자 화면 · 개발 DB · `cohort-p01~40@vocaflow.local` 합성 계정 · 기록 전부 synthetic) · 분석: `scripts/knowledge/cohort-analysis.mts`(DB 쓰기 없음).
> 페르소나 원자료(답 · 지문 번호 문장)는 저장소에 두지 않는다(지문 저작권) — 세션 작업 폴더에 보존.

## 2. 응답 생성 방식 — 검증 한계를 먼저 적는다

- 1차 응답(120) — 역할 에이전트 4개가 **문항별 기준 답 하나를 정하고 페르소나별로 일부만 바꿔 손으로 쓴 것**(본인 보고). 페르소나 시점의 새 읽기가 아니다 → **결정 엔진 검증(근거 → 결정)에는 쓰고, 「페르소나 역량 대 수행」 근거로는 쓰지 않는다.**
- 1차 지시에 「근거는 보통 1–3개」라고 써서 화면 지시(「모두」)와 달랐다 → 근거 누락의 교란.
- 2차 응답(120) — 화면 문구 그대로 지시 · 페르소나 × 문항마다 직접 판단(스크립트 생성본 2벌은 반려 · 보관). 지시문이 0부터 센 번호를 「N번째」로 써서 2차는 1부터 셌다 → 주장 · 근거는 0 기준으로 변환, **관계 답은 다른 문장을 본 것이라 제외**.

## 3. 완전 정답과 세부 수행(같은 페르소나 · 같은 문항)

| 프로필 | 주장 1차→2차 | 근거 누락 1차→2차 | 주장+근거 1차→2차 |
|---|---|---|---|
| A 상위권 | 83% → 97% | 57% → 20% | 37% → 60% |
| B 중위권 | 93% → 90% | 60% → 37% | 33% → 37% |
| C 첫 문장 편향 | 20% → 33% | 90% → 47% | 10% → 23% |
| D 하위권 | 47% → 60% | 77% → 50% | 10% → 33% |

- 근거 누락의 큰 몫은 **1차 지시 교란**이었다(화면과 같은 지시로 A 누락 57%→20%). 채점 기준 결함 근거는 없다 → **완전 정답 기준 · 주석은 바꾸지 않았다.**
- 화면과 같은 지시에서 주장 단계 순서는 프로필 예상과 같다(A 97 > B 90 > D 60 > C 33). C 의 오답 주장은 대부분 1번째 문장(첫 문장 편향).
- p01(A · 3문항 실패): 세 문항 모두 **주장은 맞힘** — 근거 누락 2(그중 2021#20 은 근거 6개 요구 + 지시 교란) · 핵심 근거 누락 + 이유를 재진술로 판단 1. 주석 오류 아님.

## 4. 결정 적절성

| 질문 | 결과 |
|---|---|
| 같은 근거 → 같은 결정 | 예(40/40 재현 · 패턴별 결정 1종) |
| 추가 확인이 필요한 학습자에게 연습을 확정하지 않는가 | 예 — 맞힌 문항이 하나라도 있으면(1O2X · 2O1X, 16명) 연습 확정 대신 더 확인 |
| 충분히 하는 학습자에게 연습을 요구하지 않는가 | 예 — 3O0X(p03) → 다음 단계 · 연습 링크 없음 |
| 부분 정답을 같은 실패로 취급하지 않는가 | **v1 아니오** → v2 수정(아래) |
| 이유가 원리 · 방법 · 관찰에 연결되는가 | 예 — 추적에 원리 · 방법 · 과제 id · 버전 · 관찰 문항 · 막힌 부분 |

불일치 · 주의 사례
- 강한 페르소나 연습 처방 3명(p01 · p09 · p10) — p01 · p10 은 근거 누락(1차 지시 교란 영향 있음), p09 는 주장 2회 실패.
- 약한 페르소나가 전부 맞힌 사례 없음.
- 1O2X 학습자는 확인 문항이 다 떨어질 때까지 「더 확인」이 이어진다(보수적 설계 — 실제 학습자에서 확인 피로를 볼 것).

## 5. 개선 — find-policy.v2

- v1: 「주장은 맞고 근거만 누락」과 「주장부터 틀림」을 같은 실패로만 기록(1차 120응답 중 부분 정답 50).
- v2: 수행 기록의 세부 채점(`response.grade`)으로 막힌 부분을 추적 · 이유 · 학습자 문구에 남긴다. **행동 규칙 · 완전 정답 기준 · 「서로 다른 2문항」은 그대로.**
- v2 검증 중 결함 1건 발견 · 수정: 주장이 틀린 문항의 근거 · 관계 실패는 따라 틀린 것이므로 주장으로만 센다(수정 전 C 그룹 처방 초점이 support 로 잘못 잡혔다).
- 같은 입력 비교: 행동 동일 40/40 · 초점 분포 A support 2 · claim 1 / B support 4 · relation 1 / **C claim 8** / D claim 4 · support 4 · v1 이 구별 못 한 「주장은 맞고 다른 부분에서 막힘」 처방 11명.

## 6. 원리 기반 결정이 바꾼 것

- 같은 단계라도 학습자마다 다음 할 일이 달라졌다: 연습 24 · 더 확인 15 · 다음 단계 1.
- v2 에서 연습 처방의 초점이 프로필과 맞물렸다(C 는 주장 찾기, A · B 는 근거 고르기 · 관계).

## 7. 남은 한계

- **효과는 모른다** — 합성이고, 연습 후 재확인 · 지연 · 전이를 돌리지 않았다.
- 페르소나 응답은 Claude 가 설계한 행동이다 — 실제 학습자의 오류 분포와 다를 수 있다.
- 2차 응답의 관계 답은 번호 오류로 제외 — 관계 단계 프로필 비교는 못 했다.
- 연습 처방의 초점(주장 · 근거 · 관계)은 아직 **연습 내용**을 바꾸지 않는다 — 연습 화면이 초점별 과제를 갖는 것이 다음 단계.
- 원리 사슬이 하나라 「요구별로 다른 원리」 선택은 검증 범위 밖.
