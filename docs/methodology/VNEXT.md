# 학습 원리 시스템 vNext — 통합 아키텍처 정본

작성 2026-10-08 · 브랜치 `feat/knowledge-vnext` · 이전 정본 [SYSTEM.md](./SYSTEM.md)(1–4단계, 등록부)는 그대로 유효하고 이 문서는 그 위에 **설계 → 적용 → 검증** 층을 더한다.
수치는 2026-10-08 DB 직접 질의 값. 「미구현」으로 적은 것은 코드에 없다.

## 0. 한 줄 목표

**근거 있는 학습 원리가 학습자의 실제 행동을 결정하고, 그 결과가 다시 원리를 재평가하는 닫힌 고리**를 독해 한 역량에서 먼저 완결한다.

```
탐구 질문 → 다중 출처 근거 → 역량·기제·방법론(등록부) → 학습 설계 → 배포 → 학습자 과제 → 수행 기록
     ↑                                                                                         │
     └──────── 원리 재평가 ← 효과 검증 프로토콜(사전·사후·지연·전이) ←────────────────────────────┘
                  └ 근거가 바뀌면(채택 해제·등급 하락) 배포 자동 중단
```

## 2. 지식 모델 — 여섯 객체

층을 늘리지 않고 **기존 4층에 면(facet)과 근거 축을 더한다.** 기존 행·트리거·이력을 그대로 쓴다.

| 객체 | 저장 | 기존과의 매핑 |
|---|---|---|
| ① 영역 본질·역량 목표 | `knowledge_items.layer='essence'` | 그대로. 화면 이름만 「역량」 |
| ② 언어 처리 기제 | `layer='principle'`, **`facet='language'`** | 기존 추론 원리 6개(순차 처리·음운 해독·응집 단서·과제 지향 주의·산출 자동화·피드백 대조 중 처리 쪽) |
| ③ 학습·기억·습득 기제 | `layer='principle'`, **`facet='learning'`** | 학습 과학 7 |
| ④ 교수·학습 방법론 | `layer='method'` | 그대로 |
| ⑤ 구체 학습 실행 과제 | `layer='practice'`(강사 주장 = **가설**) + **`knowledge_designs`**(학습자에게 실제로 주는 과제) | 공부법 118 은 가설로 남고, 설계가 그중 무엇을 근거로 썼는지 연결한다 |
| ⑥ 근거·효과 검증 | `knowledge_evidence`(+ 세 축) · **`knowledge_validation_runs`** | 기존 근거 + 학습 결과 |

면은 원리에만 붙는다(DB CHECK). 면이 비어 있는 원리는 「분류 전」으로 보인다 — 자동으로 채우지 않는다.

### 2-1. 근거 세 축 — 서로 독립

| 축 | 칼럼 | 값 | 누가 정하나 |
|---|---|---|---|
| 출처 확인도 | `grade`(기존) | A 위치 대조 · B 서지 확인 · C 계보 · (G 는 공백) | 대조한 사람/에이전트 |
| 연구 근거 수준 | **`research_level`** | meta_analysis · systematic_review · rct · quasi_experimental · correlational · expert_consensus · practitioner_claim · observation · not_assessed | 서지를 읽은 사람 |
| 학습 적용 적합성 | **`fit`** + `fit_note` | direct(같은 대상·과제) · adapted(대상·언어가 달라 옮겨 씀) · weak · not_assessed | 설계자 |

- 강사 주장은 `practitioner_claim` — 전문가 다수 동의 ≠ 효과 검증.
- AI 에이전트는 비교·중복·반례·초안을 돕지만 근거 수준을 「확정」하지 않는다: 에이전트가 쓴 근거는 `created_by` 로 남고, 채택은 사람만(기존 규칙).

### 2-2. 새 객체

| 테이블 | 담는 것 | 상태 |
|---|---|---|
| `knowledge_inquiries` | 탐구 질문 · 대상 역량 · 결론 후보 · 불확실성 · 다음 행동 | open → collecting → synthesizing → concluded / parked |
| `knowledge_inquiry_positions` | 질문에 대한 입장 하나 = 항목 또는 근거 + **stance**(supports · contradicts · qualifies · counterexample) + 메모 | — |
| `knowledge_designs` | 학습 설계: 대상 역량 · 학습자에게 보일 이유 · 절차 단계 · 대상/제외 조건 · 모듈 키 · 문항 유형 · 평가 계획(사전·사후·지연·전이) · 버전 | draft → ready → deployed ⇄ paused → retired |
| `knowledge_design_items` | 설계 ↔ 등록부 항목 + 역할(capability · language_mechanism · learning_mechanism · method · practice) | — |
| `knowledge_deployments` | 배포 구간: 설계 버전 · 시작/끝 · 끝난 이유(evidence_changed · manual_pause · rollback · retired) | 설계당 열린 배포 1개 |
| `knowledge_task_runs` | 학습자 수행 한 번: 문항 · 응답(jsonb) · 주장 문장 적중 · 선지 정답 · 확신 · 초 · preview · synthetic | — |
| `knowledge_validation_runs` | 프로토콜 계산 한 번: 표본 수 · 지표 · 판정(insufficient_data · positive · no_effect · negative · inconclusive) · synthetic | — |

### 2-3. 불변식(DB)

1. **배포 문턱**: 설계가 `deployed` 가 되려면 역할 capability·method 항목이 1개 이상 있고 **연결된 모든 항목이 채택(adopted/applied)** 이어야 한다.
2. **근거 변화 → 추천 중단**: 설계에 연결된 항목이 채택에서 벗어나면(기존 재검토 트리거가 등급 하락·근거 삭제 때 이미 그렇게 만든다) 배포 중인 설계는 `paused`, 열린 배포는 `evidence_changed` 로 닫힌다. 학습자 화면은 다음 요청부터 그 과제를 보이지 않는다.
3. **수행 기록 쓰기**: 학습자는 자기 행만, **열린 배포가 있는 설계**에만, preview=false·synthetic=false 로 쓴다. 미리보기·합성은 service role 만.
4. **설계 버전**: 절차·이유·조건이 바뀌면 version+1. 수행 기록은 그 시점 버전을 함께 남긴다(버전이 섞인 결과를 한 효과로 세지 않는다).

## 3. 출처 — 확장

| 출처 | 등급의 뜻 | 연구 수준 |
|---|---|---|
| 국내외 강사(영상·공식 대본) | A = 초 구간 대조 | practitioner_claim |
| SLA · 응용언어학 · 인지과학 1차 연구 | A = 해당 절·표 대조 · B = 서지만 | rct · quasi · correlational |
| 체계적 문헌고찰 · 메타분석 | 〃 | meta_analysis · systematic_review |
| 공식 교육과정 · 평가원 자료 | 〃 | expert_consensus |
| 수능·모평·학평 기출(원천 · 해부) | 기존 원천 등급 | observation |
| **실제 학습 결과** | 수행 기록 → 검증 실행 | 검증 실행이 판정 |

외부 링크 근거는 기존 `source_type='external'`(https)로 들어간다. 연구 서지는 DOI 링크를 쓰고, 읽지 않은 논문은 B 로 둔다.

## 4. 관리자 — 다섯 업무 공간

사이드바 「학습 원리」 그룹을 다섯 공간으로 재편한다. **기존 8개 화면은 경로 그대로** 해당 공간의 하위 메뉴가 된다(삭제 없음).

```
학습 원리
├─ A 원리 운영실          /admin/knowledge             (신규) 단계별 현황 · 병목 · 우선 처리 → 각 수치가 작업 화면 링크
├─ B 역량·원리 지도        /admin/knowledge/map         (신규) 영역 × 층 관계 + 노드 상세 패널(근거 세 축 · 설계 · 학습 지도 코드)
│   ├─ 본질 · 원리        /admin/knowledge/principles   (기존)
│   ├─ 방법론 · 공부법    /admin/knowledge/methods      (기존)
│   └─ 검토 대기          /admin/knowledge/review       (기존)
├─ C 탐구·근거 연구소      /admin/knowledge/lab         (신규) 탐구 질문 목록 → /lab/[slug] 입장 비교(지지·반박·한정·반례) · 결론 후보
│   ├─ 근거 · 출처        /admin/knowledge/sources      (기존)
│   ├─ 기출 원천          /admin/knowledge/sources/csat (기존)
│   ├─ 전문가 · 채널      /admin/knowledge/experts      (기존)
│   ├─ 공백               /admin/knowledge/gaps         (기존)
│   └─ 가져오기 원장      /admin/methodology            (기존)
├─ D 학습 설계·검증        /admin/knowledge/design      (신규) 설계 목록 → /design/[slug] 절차 · 연결 항목 · 조건 · 평가 계획 · 배포 문턱 점검 · 미리보기
└─ E 제품 적용·품질        /admin/knowledge/quality     (신규) 배포 구간 · 수행 기록 · 검증 판정 · 근거 변경 영향 · 중단/재개/종료
(메뉴 밖) 항목 상세 /admin/knowledge/item/[slug] (기존)
```

원칙: 숫자 하나마다 「다음에 누를 곳」이 있다. 운영실의 병목 카드는 그 병목을 푸는 화면으로 바로 간다.

## 5. 학습자 계약

| 학습자에게 보이는 것 | 출처 |
|---|---|
| 지금 확인된 역량 / 추가 확인이 필요한 역량 | 자기 수행 기록 — 최근 N 회 주장 문장 적중. **표본 5회 미만이면 판정하지 않고 「직접 확인 과제」를 권한다** |
| 추천 과제와 추천 이유 | 배포 중 설계의 `learner_summary` (관리자 용어·근거 등급은 노출하지 않음) |
| 구체 절차 | 설계 `procedure` |
| 결과와 다음 행동 | 이번 수행 결과 + 다음 문항 · 다른 유형(전이) 제안 |

- 자유 이동: 문항을 직접 고를 수 있고 과제를 건너뛸 수 있다. 추천은 강제가 아니다.
- 저작권 경계: 서버는 지문 글자를 보내지 않는다. 학습자는 자기 문제지(PDF·종이)를 보고 **문장 번호**로 답한다. 판정은 커밋된 지문 골격(`skeleton-data`, 정답 근거 문장 번호)으로 한다.

## 6. 첫 수직 경로 — 「주장과 근거 관계 이해」

| 단계 | 산출 |
|---|---|
| 1 탐구 질문 | 「글쓴이의 주장 문장을 먼저 찾게 하면 대의 파악(주장·요지·주제·제목) 정답률과 근거 판단이 나아지는가?」 |
| 2 근거 | 텍스트 구조 지도 메타분석 · 자기 설명 메타분석 · 기존 강사 공부법(필자 주장 먼저 표시 등) · 기출 해부(정답 근거 문장) — 각각 세 축으로 |
| 3 역량 | 「글의 주장과 그 근거의 관계를 복원한다」(본질 `essence-meaning-processing` 아래 역량 항목) |
| 4 기제 | 언어: 응집 단서 추적(`cohesion-cues`) · 과제 지향 주의 / 학습: 인출(예측 먼저) · 피드백 대조 |
| 5 방법론 | 주장 문장 먼저 표시 → 근거 문장 번호 → 선지 판단 → 정답 근거와 대조 |
| 6 학습 과제 | 설계 `claim-evidence-v1` · 모듈 키 `csat_claim_evidence` · 대상 R-CLAIM·R-GIST(훈련) · R-TOPIC·R-TITLE(전이) |
| 7 학습자 화면 | `/csat/practice/claim-evidence-v1` |
| 8 수행 기록 | `knowledge_task_runs` |
| 9 검증 프로토콜 | 사전 = 첫 3회 · 사후 = 4회째 이후 · 지연 = 마지막 훈련 7일 뒤 · 전이 = 훈련하지 않은 유형. 지표: 주장 문장 적중률 · 선지 정답률. 판정 문턱: 실학습자 20명 이상 · 학습자당 사후 5회 이상 — 못 미치면 `insufficient_data` |
| 10 재평가 | 검증 판정이 E 화면과 해당 항목 상세에 붙는다. 부정 판정이면 중단을 권고(자동 중단은 근거 변화 때만). 항목의 `efficacy` 는 사람이 바꾼다 |

문항 범위: 지문 골격에 정답 근거 문장이 있는 R-CLAIM 25 · R-GIST 29 · R-TOPIC 30 · R-TITLE 31(합계 115, 2026-10-08 `skeleton-data` 실측).
**한계**: 정답 근거 문장 = 「주장 문장」으로 쓴다. 주제·제목 문항의 정답 근거는 주장 문장이 아닐 수 있다 — 전이 지표로만 쓰고 적중 판정 문구를 「정답 근거 문장」으로 쓴다.

## 7. 학습 지도(`csat_map_*`)와의 관계

학습 지도는 `feat/map-vnext` 에서 개발 중이고 main 에 없다. 이 브랜치는 그 코드를 고치지 않는다.
연결 계약: 설계에 `map_codes text[]`(예: `A5`, `B6`)를 둔다. 학습 지도가 main 에 들어오면 지도의 과제(`A5-1 근거 문장 표시`, `B6-1 필자 주장 먼저 표시`)가 이 설계의 학습자 화면으로 링크하는 것은 지도 쪽 작업이다. 두 원리 체계의 통합(P1–P8 ↔ 등록부)은 **미구현** — 다음 확장 1순위.
