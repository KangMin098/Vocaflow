# Vocaflow Admin「학습 원리」 — 외부 재검토용 전체 정리

작성 2026-10-08 · 수치는 이날 DB(Supabase) 직접 질의 값 · 설계 정본은 [SYSTEM.md](./SYSTEM.md), 영상 주장 계약은 [claim-extraction.md](./claim-extraction.md).
용도: 외부 검토자(ChatGPT)가 이 문서 하나로 설계·방향·프로세스·화면·기능을 점검하고 재설계안을 낼 수 있게 한다. 마지막 절에 검토 요청 질문을 둔다.

---

## 0. 배경 — 제품과 이 기능의 자리

- **Vocaflow**: 영어 스크립트 기반 학습 플랫폼(Web, Next.js 14 + Supabase). 대상 한국 고등학생~성인. 학습 모듈 9개(읽기·단어장·플래시카드·스펠링·따라말하기·스크립트퀴즈·받아쓰기 등)와 수능(CSAT) 기출 학습 영역이 있다.
- 제품에는 이미 「학습 과학 7」(인출 연습·간격 반복·바람직한 어려움·이중 부호화·맥락 의존·인지 부하·정서 부호화)이 설계 원칙으로 박혀 있다. 단, 그 원칙은 문서에만 있고 **근거 출처와 연결된 관리 대상**은 아니었다.
- **학습 원리(Admin)** 는 2026-09-28 시작된 기능으로, 목적은 「영어 학습의 본질·원리를 꿰뚫는 플랫폼」이 되기 위한 **근거 있는 지식층**을 만드는 것이다.
  - 모든 문장은 출처로 거슬러 올라갈 수 있어야 한다.
  - 모르는 것은 「없음」이 아니라 「공백」으로 남긴다.
  - 콘텐츠 공급이 아니라 「무엇이 좋은 학습인가」의 **판단 기준**을 관리한다.
- 현재 사용자 측(학습자 화면)에서 이 등록부를 읽는 코드는 **없다**(2026-10-08 grep 확인). 관리자 전용 지식층이다.

## 1. 핵심 설계 — 다섯 층

「학습법·공부법·방법론·원리·본질」이 섞이지 않게 층으로 나눈다. 위로 갈수록 적고 오래가며, 아래로 갈수록 많고 구체적이다.

| 층 | 질문 | 예 | 목표 개수 | 변화 속도 |
|---|---|---|---|---|
| L1 본질 Essence | 이 영역에서 「잘한다」는 게 결국 무엇인가 | 독해 = 글쓴이의 주장-근거 구조를 복원하는 일 | 영역당 1–3 | 거의 안 바뀜 |
| L2 원리 Principle | 왜 그렇게 하면 배워지는가(기제) | 인출 연습 · 간격 반복 | 전체 20–40 | 연구가 쌓일 때 |
| L3 방법론 Method | 원리를 한 영역에 적용하는 절차 | 예문 → 확인 문제 → 다른 문장에 적용 | 영역당 5–20 | 전문가 근거가 늘 때 |
| L4 공부법 Practice | 학습자가 오늘 하는 구체 루틴(조건 포함) | 고1·기초: 하루 15분, 틀린 빈칸 문항의 근거 문장 다시 찾기 | 방법론당 1–5 | 자주 |
| L5 근거 Evidence | 누가·어디서 말했나 / 무엇이 관찰됐나 | 영상 03:12–04:05 · 교재 절 · 논문 · 기출 원천 서지 | 무제한 | 계속 쌓임 |

규칙
- 연결은 **아래층 → 바로 위층**으로만(`implements`): 공부법 → 방법론 → 원리 → 본질. 근거는 어느 층에든 붙는다.
- 옆 관계: 반대(`contrasts`) · 보완(`complements`) · 조건만 다름(`condition_variant`) · 중복 후보(`duplicate_candidate`) — 층 제한 없음.
- L3·L4 는 **조건**(학령·숙련도·시험·과정)을 가진다. 조건이 다르면 같은 문장이라도 다른 항목이다. 자동 병합 없음.
- L2 원리는 제품의 학습 과학 7을 씨앗으로 쓴다.
- L1 본질은 사람만 쓰고 사람만 승인한다. 자동 추출이 L1 을 만들지 않는다.

## 3. 근거 등급 — 한 사다리

| 등급 | 뜻 | 방법론 근거에서 | 기출 원천에서 |
|---|---|---|---|
| A 직접 확인 | 원문 위치까지 대조 | 영상 초 구간·문서 절을 읽고 재서술 | confirmed_exact |
| B 유력 | 서지 공식 확인, 해당 부분 대조 미완 | 교재 목차·소개만 확인 | supported_candidate |
| C 계보 | 같은 소재·주장의 다른 원천 | 같은 주장을 다른 사람이 함 | topic_lineage_only |
| G 공백 | 찾았으나 검증 불가 | 자막 미확보 · 권리 미확인 | unresolved |

- 표시: A만 「확인」, B「후보」, C「관련」, G는 공백 목록. 개수는 등급별로 따로 센다.
- **귀속**: 출처가 직접 말함(`stated`, 권고) · 수업 진행 관찰(`observed`) · 분석자 추론(`inferred`)을 가른다. 추론을 전문가 말로 쓰지 않는다.
- **A 는 위치 대조일 뿐 효과 검증이 아니다.** 효과는 항목의 `efficacy` 칸(평가 안 함 / 연구 지지 / 혼재 / 지지 안 됨)이 따로 다루며, 연구 설계가 확인된 근거가 있을 때만 채운다. 전문가 다수 동의 ≠ 효과 검증.
- 원문(자막·지문·본문)은 어디에도 저장하지 않는다 — 링크·위치·서지·재서술만.

| 기출 원천 | 수능·모평 지문이 발췌된 책·논문 | 713 지문 등록 |

## 5. 수명주기(프로세스)

```
수집됨 → 추출됨(extracted) → 검토 중(in_review) → 채택(adopted) → 제품 적용(applied)
                                    └→ 반려(rejected, 이유 필수)      └→ 재검토(근거 변화 시)
   └→ 공백(gap: 접근 실패·권리 미확인·자막 없음)
```

- 추출됨: 에이전트 배치가 뽑은 주장. 아직 사실로 쓰지 않는다.
- 채택: 사람이 근거를 열어 확인해야 한다. **근거 0 이면 채택 불가**(DB·서버 거부).
- 자동 재검토(DB 트리거): 기출 원천 등급이 내려가거나(A→B·C) G 가 되면 그 근거로 채택·적용된 항목이 「검토 중」으로 되돌아간다. 근거가 모두 지워져도 같다. 전이는 `knowledge_reviews` 에 자동 기록.
- 근거 버전: 화면을 연 뒤 근거가 바뀌면 채택·반려가 거부된다(본 것과 저장된 것이 다른 채로 판단 금지).
- 동시 저장: 「읽은 상태 그대로일 때만」 쓴다. 덮어쓰지 않고 오류.
- **미구현**: 근거가 추가될 때의 재검토, 위층 문장이 바뀔 때(version+1) 아래층을 자동 재검토로 올리기(지금은 버전 번호만 오름).

### 5-1. 영상 → 주장 추출 파이프라인(LLM 배치 드레인)

1. `yt-import.mjs` — 영상 목록 + 검토 틀 생성(요약 기반, 검토 전).
2. 에이전트(Codex/Claude)가 자막 캐시와 **원문 대조**해 주장 jsonl 작성 — 한 줄 = 주장 하나, `kind`(권고/관찰/추론) · `procedure`(실행 절차 단계) · `skill`/`audience`/`conditions`(분류 id 또는 「미명시」) · `segment`(대조한 초 구간 + 300자 이내 재서술) · `grade` · `verdict`(import/hold/exclude) · `reviewer`.
3. `claims-import.mjs` — 형식 검증 → 미리보기 → `--commit` 으로 RPC `knowledge_import_claim` 한 트랜잭션 적재. L4 공부법 · 상태 「추출됨」. 같은 slug 가 있으면 건너뜀(사람 판정 보호, 재실행 안전).
4. 사람이 「검토 대기」에서 채택/반려.

검증기가 보장하지 않는 것: 절차가 실제로 실행 가능한지 · 원문 복사 여부(300자 제한은 완화일 뿐) · 재서술이 구간과 맞는지 — 검토자 몫.

### 5-2. 기출 원천 파이프라인

수능·모평 713 지문의 원전(책·논문)을 조사 → 검수 JSON(전후 판정 + 연결 문항별 본문 해시) → `source-origin-review.mjs` 가 SQL 생성 → DB 체크포인트 → 한 트랜잭션 적용 → 재실행해 전부 already_applied 확인. 해시·판정이 어긋나면 전체 롤백.
의도: 방법론 근거가 아니라 **「수능 독해」 본질을 밝히는 1차 관찰 자료**. 예) 「수능 지문은 대학 교양·학술서의 한 단락 → 독해의 본질은 낯선 분야의 논증 구조를 배경지식 없이 복원하는 것」(분석자 추론으로 표시). 학문 분야(`field`) 칸은 아직 비어 있음.

## 7. 메뉴 구조(Admin 사이드바)

사이드바 그룹 **「학습 원리」** — 「기출(CSAT)/교재」 그룹과 「콘텐츠 공급」 그룹 사이에 둔다(공급이 아니라 판단 기준이므로).

```
학습 원리
├─ 원리 지도            /admin/knowledge                 본질↔원리↔방법론↔공부법 격자 · 층×상태 · 공백 · 원천 등급
├─ 본질 · 원리          /admin/knowledge/principles      L1·L2 목록 (사람만 작성)
├─ 방법론 · 공부법      /admin/knowledge/methods         L3·L4 목록 · 조건 칩
├─ 검토 대기            /admin/knowledge/review          추출됨·검토 중 목록 → 항목 상세에서 판정
├─ 근거 · 출처          /admin/knowledge/sources         출처 종류별 유입·연결 현황
│   ├─ 기출 원천        /admin/knowledge/sources/csat    시험×문항 등급 격자 + 서지 표
│   └─ 가져오기 원장    /admin/methodology               초기 조사 스냅샷(읽기 전용)
├─ 전문가 · 채널        /admin/knowledge/experts         강사·연구자와 소유 채널 (순위 아님)
└─ 공백                 /admin/knowledge/gaps            모르는 것 · 원인 · 다음 행동
(메뉴 밖) 항목 상세     /admin/knowledge/item/[slug]     격자·목록에서 진입
```

모든 화면 상단에 화면도움말(`lib/admin/help/knowledge.ts`)이 붙는다.

## 8. 화면별 기능

| 화면 | 보이는 것 | 할 수 있는 것 | 미구현 |
|---|---|---|---|
| 원리 지도 | 영역 10열 + 「공통」 1열 × 층 4행 격자. 칸 = 「채택 n / 초안 n / 모름」 글자. 아래 층×상태 표 · 열린 공백 · 기출 원천 등급 수 | 칸 클릭 → 항목 1개면 상세, 여럿이면 층 목록 | 칸 클릭 시 오른쪽 판에 항목→연결→근거 펼침, 등급별 진하기 |
| 본질·원리 | L1·L2 목록 · 근거 없음 표시 · v 번호 | 새 항목 작성 | — |
| 방법론·공부법 | L3·L4 목록 · 조건 칩 | 새 항목 작성 | 조건 필터 고도화 |
| 검토 대기 | 추출됨·검토 중 목록 + 근거 없는 항목 수 | 항목 상세로 이동해 판정 | 한 건씩 넘기는 검토 흐름, 유사 항목 나란히 보기, 「조건 다름으로 분리」 한 번에 |

## 10. 알려진 약점·긴장(자체 진단)

1. **근거가 아래층에만 있다.** 근거 118건이 전부 L4. L1–L3 은 0이라 규칙상 하나도 채택할 수 없다. 위층은 「아래층에서 묶어 올린 추론」 뿐이고 1차 연구 서지가 없다.
2. **근거 원천 편향.** L4 전부가 국내 강사 YouTube 영상 73편. 연구·공식 대본·교재 근거는 사실상 0. 「A 등급」이 많아 보이지만 의미는 「강사가 그렇게 말한 위치를 확인함」이지 효과 검증이 아니다.
3. **사람 검토 병목.** 채택은 사람만 한다는 원칙인데, 실제 사람 검토자가 사실상 없고 채택 0 이다. 153건 검토 기록은 대부분 자동 전이.
4. **제품과 단절.** 학습자 화면·학습 모듈이 등록부를 읽지 않는다. 「제품 적용(applied)」 상태로 가는 경로·기준이 정의돼 있지 않다.
5. **엄격한 무결성 vs 사용성.** 근거 버전·동시 저장·재등급 잠금 등 DB 불변식은 강하지만(마이그레이션 6개), 그 위에서 실제로 쌓인 판단은 0 이다. 설계 비용이 산출보다 앞섰을 가능성.
6. **기출 원천의 위치가 애매.** 원천 등록부는 「본질」의 관찰 자료로 설계됐지만 학문 분야 칸이 비어 있어 본질 문장에 아직 쓰이지 않았고, 확인률도 14%.
7. **층 정의의 경계.** 「원리」에 학습 과학 일반 기제(간격 반복)와 영어 특화 처리 기제(순차 처리·음운 해독)가 섞여 있다. 「본질」 4개가 기능 영역(skill)과 1:1 이 아니라 묶음 단위라 원리 지도 격자(영역 10열)와 어긋난다.
