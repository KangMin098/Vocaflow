## 8. PLAN·이력·권한·snapshot

하나의 SavedPlans.goal로 점수·범위·PLAN 근거를 만든다. 조회 사이 목표 변경 반례의 원본80점/Target90점/다른 PLAN 목표 버전은 수정 후 같은 snapshot으로 일치했다. 목표 팝업의 요청값은 서버 재계산 이전에 저장된 목표/추천에 섞지 않는다.

PLAN v1은 저장 당시 goal_version_id를 유지한다. 목표 변경 뒤 v1 복원은 새 PLAN 버전을 append하고 현재 계산 목표에 결속하며 목표를 되감지 않는다.22개 목표를 추가한 뒤 옛 PLAN의 목표는 '과거 목표 상세 확인 불가'를 명시한다. 최신 목표 값을 차용하지 않는다. goal_version_id·PLAN version·canon_version은 각각 다르다.

새 UI 요청은 expectedGoalVersion을 포함한다. 다른 탭에서 목표를 바꾼 옛 화면은 같은 점수/다른 시험도409다. 초안·메모·ack는 점수와 목표 이력 ID에 결속한다. 버전 없는 이전 기기 초안은 보관하고 자동 적용하지 않음을 안내한다. 성공한 같은 요청은 최초 목표 버전과 본문을 확인한 뒤 최초 결과를 반환한다. 필드가 없는 legacy API는 기존 서버 계산 의미로만 호환한다.

최종 확인 이후의 목표 변경까지 commit 시점 절대 최신성으로 원자 보장하지는 않는다. 저장 행은 계산한 불변 snapshot을 가리킨다. 더 강한 최신성은 공유 잠금/RPC compare-and-commit의 별도 승인 범위다. 다른 학습자의 실제 Workspace·이력·목표는 소유 계정 A/B로 검사했다.

## 10. 승인안과 남는 작업

LM-G1_3b_PENDING_DELTA는 검증 생략이 있는 미적용 SQL 초안이다. 승인 가능한 완성 마이그레이션으로 취급하지 않는다.

1. grade-only: NULL 점수와 '이력 없음'을 분리하고 최신 표/이력/계산 fallback을 함께 정해야 한다.
2. 확장 spec: 실제 kind/회차/형·복합 의미·허용값·버전·예산 단위·개인 초점 소비 경로를 확정해야 한다.
3. RPC v2: 서비스 호출 수준의 원자 본문 비교, 필요하면 PLAN 최신 목표 compare-and-commit을 별도로 설계한다. 현재 API 안전 보완에 DB 적용은 필요하지 않았다.
4. SECURITY DEFINER: 고정 search_path·명시 권한 회수/부여·세션 user ownership·호환·적용/rollback을 검증해야 한다. 기존 설치 함수는 service_role 실행권한을 SELECT로 확인했다.
5. 교육청은 자료/검수·적격 reader가 필요한 BLOCKED_CONTENT다. SQL 적용만으로 지원되지 않는다.2021 month 정정은 별도 데이터 승인/원천 검토 범위다.

DB/RPC/RLS 적용, 실제 학생 변경, 새 콘텐츠·공장 내부·교재 공개는 수행하지 않았다. 테스트 계정의 생성/기존 API 실행/소유 확인 후 정리만 수행했다. V2/S5·실제 Factory·학습 효과는 이번 완료로 승격하지 않는다.
