# 문항↔TASK 매핑 — 계약 v2.1 추가 규칙 (goal-data-d2-v2.1)

> v1 [ANALYST_CONTRACT](../../../csat-learner/v62/data-expansion/ANALYST_CONTRACT.md) + [v2](./CONTRACT_V2.md) 를 그대로 따르고 아래만 더한다. 근거: b2-v2 R3 갈림 11 전부 indirect↔무관(T-0088 confirmed) · 삽입 8문항 주어진 문장 오독(T-0088 정정).

## 1. R3 문장 · 문단 기능 경계

| 판정 | 조건 |
|---|---|
| direct | 결정이 **한 문장 · 단락의 기능 판정 자체**다 — 무관한 문장(흐름 기능 이탈) · 예시/결론/도입 위치가 정답을 정하는 순서 · 삽입 |
| indirect | 발문이 기능 명명을 요구하지 **않더라도**, 특정 문장의 기능(정의 · 예시 · 도입 배경 · 양보 · 반론 · 결론)을 잘못 보면 **특정 오답 선지**로 간다(반사실 `choice` 필수). 예: 도입 배경 문장을 중심으로 읽어 그 내용을 담은 선지를 고른다 |
| not_applicable | 기능 오독이 어떤 오답 선지와도 대응하지 않는다 |

- 「기능 이름을 말하라는 요구가 없으니 무관」 은 v2.1 에서 **판정 근거가 아니다**(b2 A 트랙의 갈림 원인).
- R4 와 겹칠 때: 한 문장의 기능이면 R3, 여러 문장 · 단락의 배열이면 R4.

## 2. 삽입 문항(R-INSERT)의 주어진 문장

- DB `passage` 는 **[주어진 문장] + [본문 첫 부분] + ( ① ) …** 순서로 저장돼 있다(인쇄본의 박스 문장이 앞에 붙음). 청크 입력의 `insert_split.given_sentence` 가 첫 문장 분리 결과다.
- 인용은 여전히 `passage` 원문에서 그대로 복사한다(주어진 문장도 passage 안에 있다).
- `insert_split.confidence = "uncertain"`(① 앞 문장이 하나뿐) 인 문항은 배치에 넣지 않는다.
