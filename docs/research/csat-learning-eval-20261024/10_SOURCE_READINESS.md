## 3. 공식 정답 — 2025 수능 독립 확인

- 저장소의 2025 정답은 화면 캡처 수기 전사 한 출처뿐이었다(`answers-manual.json`). 로컬 정답표 PDF(sha256 `65b52a67…`)는 텍스트가 없어 자동 해독이 안 된다.
- 이번에 그 PDF 를 이미지로 렌더해(pdfjs-dist + @napi-rs/canvas, 저장소 밖 스크립트) 2쪽을 판독했다: 1쪽 홀수형, 2쪽 짝수형.
- 짝수형: 22=①, 33=②, 34=⑤, 38=④, 39=④ — DB·수기 전사와 모두 일치. → 수기 전사와 **독립된 두 번째 출처**로 확인.
- **발견**: 홀수형 22번 정답은 ② 로 짝수형(①)과 다르다. 2025 문제지는 짝수형이고 DB 정답도 짝수형이다. 그런데 `csat_exams.paper_form` 은 「단일」로 기록돼 있다 — 형 정보가 데이터에 없다. 평가 입력에는 `item_version` 에 형을 함께 적는다(예: `2025-even`). DB 정정은 제품 owner 판단(E 는 수정하지 않음).
- 판독 방법의 한계: AI 시각 판독이다. 정답표 PDF 출처(평가원 원본 여부)는 2026 외에는 해시 대조 기록이 없다 → 사람 확인 서명 항목에 포함.

## 4. PDF 문자 이동 복원 — 처리 이력

| 문제지 PDF | sha256(앞 16) | 추출 그대로 `the` 수 | ASCII −2 복원 뒤 `the` 수 | 처리 |
|---|---|---|---|---|
| 2025 짝수형 | `de8035bedf1ac1a5` | 0 | 285 | 복원 |
| 2025-09 모평 | `73a48f9bba4265fe` | 0 | 504 | 복원 |
| 2027-06 모평 | `b7e913209134cd89` | 0 | 559 | 복원 |
| 2026-06 모평(대조군) | `55ba46646ada079e` | 212 | 0 | 복원 안 함 |

- 원인: 해당 PDF 의 영문 글리프가 코드값 +2 로 매핑돼 추출된다(`Itgcv` → `Great`). 한글은 영향 없음.
- 규칙: 0x22–0x7E 문자만 −2. 복원본의 `the` 수가 원본의 3배+20 을 넘을 때만 적용(대조군은 적용되지 않음을 위 표로 확인).
- 검수 근거: 복원 뒤 DB 지문 30자 조각 포함률 0 → 0.84–1.00, 선지 0.97–1.00 으로 바뀌었다(source-evidence.json). 복원은 **대조용 메모리 안에서만** 했고 PDF·추출기(`pdf-cid-text.mjs`)·DB 는 고치지 않았다. 추출 텍스트는 저장하지 않았다.
- 남은 위험: 이 규칙은 영문 `the` 빈도에 기대는 휴리스틱이다. 다른 회차에 쓰려면 같은 대조군 확인을 반복한다.

## 5. 교수 분석 판본 — 결속 규칙

- DB 의 모든 revision 은 `status=published` 다. **published 는 수용이 아니다** — 이 연구에서 모든 revision 은 candidate 로 취급한다. 최신 revision 을 자동 정본으로 고르지 않는다.
- 각 revision 은 `content_sha256` = sha256(정규 JSON{choice_analysis, answer_locus, solve_procedure, design_intent}, 키 정렬)로 고정했다(analysis-revisions.json). 사람이 하나를 수용하면 `accepted_revision` 과 그 해시를 채운다.
- 평가 입력 결속: 판정 기록의 `analysis_version` = `<item_id>@v<N>#<content_sha256 앞 16>`. 수용 전에는 `UNKNOWN` — 도구 `check` 가 버전 불일치·미상을 보고한다.
- 옵션 번호는 `choice_analysis[].n` 으로 맞춘다. **배열 순서는 번호가 아니다**(2026#34 v5 는 정답 ③을 배열 첫 칸에 둔다). 34·38 AI 후보 작성 에이전트는 번호 필드를 못 찾고 배열 순서를 가정했으나, `n` 기준 재대조 결과 그들이 보고한 버전 차이(34계열 M2706#34 ③④⑤, 38계열 2025#39 ③⑤ · M2509#38 ④ · M2606#38 ② · M2706#38 ①④)는 analysis-revisions.json 과 일치한다.
- 공식 정답은 판본과 독립이다 — 정답은 §3 기준으로 고정, 오답 라벨·근거·원리 설명만 감수 대상.

같은 원리 — AI 후보 요약:
- **22계열**: 앵커(진단→처방 역할 포괄)와 같은 짝 0. 다섯 문항 모두 처방 문장이 없다. 2025#22 · M2609#22 는 「역할 포괄」만 공유(UNSURE) — 전이 짝인지, U4 반례인지 사람이 정한다.
- **34계열**: 앵커의 조건·부정·귀결 기능 공유 0/6 — 34 조건 명제 판단을 일반화하지 않는다는 원칙과 일치. 2025#33 은 귀결절 빈칸이라 겉모습만 가깝다(UNSURE). M2606#34 는 전건 빈칸(2026#33 반례 쪽).
- **38계열**: 뒤 이음매 결정형 SAME 5, M2509#38 은 앞·뒤 이음매가 같이 결정적(UNSURE).

사람 감수 필요 항목(우선순위): ① 문항별 근거 span gold 와 대체 설명 인정 범위 ② UNSURE 4건의 원리 판정 ③ 의미 충돌 5건의 revision 수용 ④ 코드표 밖 라벨(OTHER_ATLAS) 처리 ⑤ 후보 6건(38계열)의 `choices` 에 본문 조각·각주 혼입(CC-07 과 같은 형태) — 선지 표시 데이터로 채점하지 않는다.

AI 판정과 사람 감수의 구분: AI 후보끼리 일치해도 `human_verdict`·`human_approval` 은 비어 있다. 수용은 사람이 누가·언제·어느 revision 으로 승인했는지 적을 때만 생긴다.

## 7. P6 인계 — 평가 입력 요구

csat-lecture-disclosure owner 세션에 원장 0행 사실을 전달했다(09 §5). 이번에 평가 쪽 입력 요구를 덧붙여 보낸다: 시도마다 `exposure_order_at` · `help_level` · `item_ref`, 노출 행마다 `kind`(answer_direct / decisive_hint) · `source` · `received_at`. E 는 테이블·RPC·공개 API 를 만들지 않는다. 기록 없는 시도는 독립 수행으로 처리하지 않는다.
