# 13 · 이중 에이전트 검수 규약 v2 — 미반영 4개 게이트 보정 (2026-10-24)

> T-0149(COMPLETED)와 결정 근거 gold 18건은 **그대로 보존**한다. v1 판정(`review/judgments-A.json` · `-B.json` · `aggregate-AB.json`)을 소급 수정하지 않는다. v2 판정은 `review/v2/` 에 새로 기록한다.
> 목표는 합의율이 아니라 **유효한 평가 문항과 채점 근거**다. 그래서 v2 는 합의 규칙을 느슨하게 하지 않는다(하한 0.85 · 정확 일치 그대로). 바꾼 것은 판정자가 같은 것을 보도록 하는 **정의와 판단 순서**뿐이다.
> 대상: 후보 17건, 게이트 4개(원문 · 같은 원리 · 매력 오답 · revision 라벨). 기준 3건은 정의 참고용으로만 패킷에 남고 판정하지 않는다.
> 규약 해시: 이 문서와 `tool/review-gates-v2.mjs` 의 sha256 을 판정 전 커밋에 고정한다(15 문서에 기록).

## 1. 원문 게이트 — 내용과 데이터 결함 분리 (38계열 보정)

v1 은 「선지가 본문 조각·각주 혼입」 같은 **DB 표시 데이터 결함**과 「지문 내용이 기출 원문과 같은가」를 한 판정에 섞어 38계열 7건이 갈렸다. v2:

- `original.content_verdict`: CONFIRM · REJECT · UNSURE — **지문(주어진 문장 포함)과 발문의 내용**이 온전한 기출 문항인가. 기계 대조 비율(지문 ≥0.8)과 문장 흐름으로 판단. 선지 표시 형식은 여기서 보지 않는다.
- `original.data_defects`: 아래 목록에서 해당하는 것 전부(없으면 `["NONE"]`).
  - `CHOICES_ARE_FRAGMENTS` — 위치형 문항의 선지가 ①~⑤ 위치 표지가 아니라 본문 문장 조각
  - `FOOTNOTE_IN_CHOICE` — 선지에 각주·쪽 번호·문항 번호가 섞임
  - `GIVEN_SENTENCE_MERGED` — 주어진 문장이 지문 첫 문장에 구분 없이 붙음
  - `PASSAGE_TRUNCATED` — 지문 중간·끝이 잘림
  - `OTHER` — 그 밖(이유에 적음)
- 데이터 결함은 **원문 서명을 막지 않는다**. 대신 그 결함이 있는 표시 데이터(예: 조각 선지)는 채점·학습자 화면에 쓰지 않는다는 제한으로 기록된다. 결함 목록은 합의 대상이 아니라 두 판정의 합집합으로 기록한다.

## 2. 같은 출제 원리 — 필요조건 3개로 판정 (34 경계 보정 포함)

판정자는 조건마다 `met: true | false | unsure` 와 근거 문장 번호를 적는다. **verdict 는 조건에서 기계적으로 정해진다**: 셋 다 true → SAME, 하나라도 false → DIFFERENT, 그 밖 → UNSURE. 검증기가 불일치를 거부한다. 「출제 사고 기능이 같다」는 인상 판정은 쓰지 않는다.

**22 계열 — DISCOURSE_ROLE_COVERAGE (기준 2026#22)**
- C1 지문에 서로 다른 역할의 문장이 둘 이상 있고, 그중 하나가 결론·처방·주장(글쓴이가 요구하거나 결론 내리는 문장)이다.
- C2 정답 선지가 그 결론·처방 역할을 담는다(진단·예시·세부만 담으면 false).
- C3 가장 매력적인 오답이 지문에서는 참이지만 결론 역할을 담지 못해 실패한다.

**34 계열 — CONDITIONAL_NEGATION_ENTAILMENT (기준 2026#34)**
- C1 빈칸이 명시적 조건(If · unless · without · only when · Ideally 같은 한정)의 **귀결 쪽**에 있다. 빈칸이 조건(전건) 쪽에 있으면 false.
- C2 빈칸이 든 절이 부정(not · cannot · never · no · fail to)의 범위 안에 있다. 부정이 빈칸 절이 아닌 다른 문장(예시 문장 등)에만 있으면 false.
- C3 정답을 고르려면 「조건이 성립할 때 무엇이 따르는가」를 추론해야 한다. 앞 문장 하나를 다시 말한 것만으로 정해지면 false.
- 경계 예시(후보가 아닌 기준 주변 문항, E1 §2): 2026#33 — 빈칸이 조건 쪽 → C1 false. 2026#31 — 인과 설명 빈칸, 조건·부정 없음 → C1 false. 2026#32 — 대조 뒤 재진술 빈칸 → C3 false. 34 의 조건 명제 판단은 이 세 조건을 모두 만족할 때만 같은 원리다.

**38 계열 — TWO_BOUNDARY_COHESION (기준 2026#38)**
- C1 주어진 문장에 앞 문장을 요구하는 단서(지시어 · 정관사 지시 · 연결사 · 대조 표지)가 있고 정답 자리 앞 문장이 그것을 채운다.
- C2 정답 자리 뒤 문장이 주어진 문장을 요구한다(예시 · 부연 · 지시 대상) — 뒤 이음매가 결정적이다.
- C3 가장 매력적인 오답 자리에서는 두 이음매 중 하나는 맞지만 다른 하나가 깨진다.

`counterexample_condition`: 이 문항에서 원리가 적용되지 않게 되는 조건 변경 한 가지(예: 「뒤 문장의 예시 표지를 지우면 C2 가 false 가 된다」).

## 3. 매력 오답 코드 — 판단 순서와 구분 규칙 (trap-atlas 코드표 유지)

코드 목록(`rubric/distractor-logic.json` 의 19개)은 바꾸지 않는다. 겹치는 코드에 **판단 순서**를 둔다. 판정자는 `primary_code` 하나와, 순서상 그 앞 단계에서 왜 아니었는지 `code_decision_path` 를 적는다.

내용형(요지·빈칸·주제 등) — 위에서부터 처음 해당하는 것:
1. 선지 명제가 지문과 무관 → `OFF_TOPIC`
2. 지문 근거 없이 통념에 기댐 → `OUTSIDE_KNOWLEDGE`
3. 지문 명제의 극성·방향을 뒤집음 → `REVERSAL` · 행위자/대상을 바꿈 → `AGENT_SWAP` · 인과를 뒤집음 → `CAUSE_REVERSAL`
4. 지문 한정보다 넓힘 → `SCOPE_OVER`
5. **주장(결론) 문장의 일부 축만** 담음 → `SCOPE_UNDER`
6. **주장이 아닌 문장(진단·예시·세부)** 의 내용을 담음(지문에 참) → `PARTIAL_TRUE`
7. 지문 낱말을 끌어왔으나 그 명제는 지문에 없음 → `LEX_BAIT`
- 구분: 5 와 6 은 「선지가 옮긴 문장이 주장 문장인가」로 가른다. 7 은 「선지 명제가 지문에 있는가」 — 있으면 7 이 아니다.

위치형(삽입·순서) — 위에서부터:
1. 그 자리에서는 주어진 문장이 가리키는 대상이 아직 나오지 않음(실패가 **앞쪽**) → `FIRST_MENTION_VIOLATION`
2. 삽입이 기존 문장의 지시어와 그 선행사를 떼어 놓음(실패가 **뒤쪽** 기존 연결) → `REF_ANTECEDENT_CUT`
3. 조건과 귀결을 떼어 놓음 → `COND_RESULT_CUT` · 열거·병렬 항목을 떼어 놓음 → `ENUM_CUT`
4. 시간·인과 순서를 뒤집음 → `SEQ_REVERSAL` · 총론과 각론 순서를 뒤집음 → `GENERAL_SPECIFIC_REVERSAL`
5. 연결사 방향이 앞뒤와 충돌 → `CONNECTIVE_CLASH`
6. 낱말 겹침만으로 자리처럼 보임 → `LEX_REPEAT_LURE`
- 그 외 이름은 `OTHER_ATLAS`(원 trap 문자열을 reason 에 적음).

`counter_evidence` 는 그 오답을 실패하게 만드는 문장 번호다. 근거 정확성 감사(§6)의 대상이다.

## 4. revision 라벨

충돌 옵션마다 버전에 있는 라벨 하나 또는 NONE 을 고르고, **§3 판단 순서로 그 라벨이 맞는지** 근거 문장 번호와 함께 적는다. 라벨 이름은 trap-atlas 한국어 이름 그대로(코드 아님).

## 5. 합의 라벨과 정식 반영 라벨

- `pair_agreed_value`: A·B 가 같은 값을 냈다. **수용 값이 아니다.**
- `reflected_value`: 게이트 일치율 ≥ 0.85 **그리고** 근거 정확성 감사(§6) 통과일 때만 채워진다.
- readiness 에는 `reflected_value` 만 수용 값으로 쓴다. 미반영 칸은 `pair_agreed_value` 이름으로만 남는다.

## 6. 근거 정확성 감사 (합의율 외)

- 오케스트레이터(Claude 메인)가 게이트마다 반영 후보 칸을 원문과 대조한다: 게이트별 반영 후보가 10건 이하면 전수, 넘으면 10건.
- 감사에서 틀린 칸이 하나라도 나온 게이트는 반영하지 않는다(사유 기록).
- 공식 독립 Codex 검증(AI-Control 리뷰어)이 별도로 5건 이상을 다시 대조한다.

## 7. 독립성 · 블라인드

- A(Claude 신규 서브에이전트)와 B(Codex)는 **입력 전용 폴더**만 받는다: v2 패킷(후보 17 + 기준 정의) · 이 규약 · 코드표. v1 판정 · AI 초안 · readiness · 10/12 문서는 그 폴더에 없다.
- 한계: A 는 같은 머신의 다른 경로를 읽을 수 있는 도구를 갖고 있어 「읽지 않았다」를 기술적으로 강제하지 못한다(지시 + 사후 자기보고 + 결과 비교로만 확인). B 는 읽기 전용 샌드박스이며 입력 폴더만 있는 별도 worktree 에서 돈다.
- 작성 역할: 규약·도구·집계·감사 = Claude 메인(오케스트레이터). 판정 = A·B. 공식 독립 검증 = Codex 리뷰어 owner(판정자 B 와 다른 실행).

## 8. 권리 경계 (사용자 결정 2026-10-24)

원문 PDF 는 접근이 확인된 이 연구 환경(로컬)에서만 쓴다. 저장소에는 원문을 복제하지 않고 출처 · 문항 ID · 해시 · 일치 여부 · 사용 범위만 남긴다. 외부 제공과 실제 학습자 연구는 별도 권리·동의 충족 전까지 보류한다. 따라서 **SOURCE_READY 는 「연구 내부 사용」 범위로만 판정**하고, 학습자 대상 사용은 별도 상태(`LEARNER_USE: RESERVED`)로 둔다.
