## 남은 한계(실측 필요 · 모두 fail-closed)
1. `permissionDecision: "ask"` 와 함께 낸 `updatedInput` 이 반영되는가. 반영되지 않으면 승인된 배포가 실패한다.
2. PreToolUse 훅 두 개가 모두 ask 를 낼 때, guard 의 원래 입력과 이 훅의 갱신 입력 중 어느 쪽이 이기는가. 원래 입력이 이기면 난수가 빠져 실패한다.
3. 거부한 승인 창의 갱신 명령(난수 포함)이 에이전트가 읽는 transcript 나 도구 결과에 남는가. 남더라도 러너를 정식 경로가 아닌 방법으로 불러야 쓸 수 있는데, 그건 PR #286 러너의 `realpath(argv[1])` 검사가 막는다.
4. 같은 OS 계정에서 티켓을 위조하는 것은 막지 못한다. 이 장치는 방어선이 아니며, 의도적 위조까지 막아야 할 때는 사람이 TTY 에서 직접 실행하는 경로를 쓴다.
5. 불변식 1·3 은 PR #286 러너가 난수 소비와 `realpath` 확인을 구현해야 완성된다.
