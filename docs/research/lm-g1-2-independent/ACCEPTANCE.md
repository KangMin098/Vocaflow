## 수정 과정 원장(중간 판정 보존)

아래는 진행 당시의 관찰·보완 기록이다. 최종 판정과 실행 범위는 위 표를 따른다.

후속 P1 복원 반례와 P2 전이0/조회 오류의 최초 실패도 보존했다. 서버 함수의 실제 표현식/루프를 격리 실행한 오류·식별·빈 풀7개를 분리했다. UI는 최근20개 배정 이력을 표시하고, 복원의 운영량 검사는 전체 이력에서 계산한 compact snapshot을 사용한다. 저장 stub에서 필수 version이 없던 기존 검사 한 곳에 version=1만 추가했고 기대값은 바꾸지 않았다.

자료0의 기존 운영 정책은 적용을 건너뛸 수 있지만 진행 완료·준비 true·성취로 판정하지 않는다. 조회 오류나 존재하는 후보의 원문 식별 실패는 실제0이 아니며 기존 오류 화면으로 보낸다. 실제 개발 DB 장애를 유발한 검사가 아니라 원래 함수/표현식에 격리한 실패 의존성을 주입한 검사다.

복원 시 현재 단계가 TRANSFER라면 새 배정 payload도 복원 정책과 같은 수량이어야 한다. UI는 동일 snapshot으로 요청하고 서버는 불일치 입력을422로 거절한다. 기존 잘못된 payload 이력은 수정하지 않고 재생/표시에서 분리한다. 공개 적격성 실패 두 분기도 같은 실제 함수/호출부로 수정 전 실패를 재현한 뒤 오류 전파를 확인했다.


최종 단계 초안 반례: 동일 목표/PLAN 버전에서 미저장 REPAIR 수량1이 TRANSFER 기본2에 재사용되는 실패를 보존했다. 로컬 초안은 TASK별 단계에 결속하고 출처 없는 구형 수량은 적용하지 않는다. 현재 단계에 결속된 새 초안은 이전 저장 응답의 단계가 다르더라도 보존한다. 단계 변화는 같은 단위의 공급량 변화와 구분하여 기존 재계획 안내/확정 버튼에 반영한다. API/DB의 승인·버전 조건은 변경하지 않았다.


마지막 응답 경계: 실제 조회 실패가 빈 저장 정책/기본2로 변하는 반례와, 응답 뒤 새 서버 버전으로 재진입할 때 초안3→저장2·메모 소실이 재현됐다. 정상 미설치는 유지하고 조회 오류를 전파했다. 성공 응답에서 편집기 부재와 무관하게 정확한 사용자/목표/Workspace/다음 버전 키로 원본 초안을 이관한다. 대상의 더 새로운 수량과 메모는 각각 보존하며 원래 키의 관찰도 유지한다. 재현 계정은 삭제·부재 확인했다.


후속 초안 복구 반례: 사용자가 다음 버전에서 비운 메모와 초기화한 초안은 명시적 편집이다. null/빈 문자열 마커와 유효 저장값 존재 검사를 도입하여 이전 응답보다 우선한다. 보조 TASK의 과거 전이 수량은 중심 정책이 아니므로 복원 버튼의 별도 중복 차단을 제거하고 서버와 같은 중심 TASK/이력 snapshot 검사를 사용한다. 실제 함수·JSX 조건의 격리6개 중 수정 전3개 실패·수정 후6개 통과를 보존했다. 중심 전이2/자료1 차단은 유지된다.


마지막 저장 상태 경계: 추가 편집 없이 닫힌 요청의 이미 저장된 메모가 새 미저장 초안으로 복사되는 실제 실패를 보존했다. 제출 시 원본 로컬 값의 stamp와 성공 시 값을 비교하여 변하지 않은 원본만 정리한다. 저장소 오류는 동일성 미확인으로 남기며 새 편집·명시 초기화·대상 편집은 보존한다. 원자/단계 엔진은 변경하지 않았다. 두 PC 전체26개는 cd7af4c5b에서 통과했고, 이후 한 UI 파일의 응답 분기 수정은 별도 최종 커밋의 두 PC 무편집 저장·응답/권한/재진입 및 기존 회귀로 검증한다. 전체26개를 마지막 UI 수정 커밋에서 다시 실행했다고 표현하지 않는다. cd7의 후속 security는 PLAN 선택자 시간 초과로 중단됐고 PASS가 아니다. 관찰된 서버 종료·aborted 로그의 원인은 확정하지 않았으며 최종 별도 실행으로 재검증한다.


## 판정 범위와 후속 작업

T2는 R5의 기존 API를 통한 수행 저장 → 근거 재판정 → MAP/Workspace/PLAN 갱신의 제품 수직 경로를 대상으로 한다. 계획량 달성은 독립 확인 준비 조건이며 숙달·점수 상승·실제 학습 효과와 구분한다. 테스트 계정과 AI 교차 검토는 인간 전문가 검수나 학생 실증의 대체물이 아니다.

- 자료가1개일 때 기본/저장2는2를 유지한다. 사용 가능한 지문을 소진하면 다음 독립 확인을 열지 않는다. 새 확정/복원에서 planned≤available인 기존 DB 계약을 유지하므로 해당2 확정은 **BLOCKED_CONTENT**이며 명시 조정1만 별도로 가능하다.
- 정상적으로 확인된 실제 후보0은 기존 건너뛰기 정책을 유지한다. 준비 값은null이고 전이 완료·숙달 근거로 승격하지 않는다. 원문·후보·공개 적격성 조회 실패와 후보의 원문 식별 누락은0으로 취급하지 않는다.
- 현행2분·서버 시각 v1 노출 정책은 보존한다. C2 사후 근접 해설, G 공유지문 노출 확장안은 **BLOCKED_APPROVAL**이다. 이번 지문 중복 집계 수정이 노출 정책v2까지 구현했다는 뜻은 아니다.
- 원자성은 설치된 함수 본문4개의 동일성을 확인하고 격리 PostgreSQL(PGlite)에서 중간 실패/재전송/충돌을 검사했다. 실제 개발 DB에는 기존 성공·오류·권한 API만 사용했다. 운영 전체 trigger/RLS의 고의 장애·다중 연결 원자 장애 주입은 **NOT_TESTED**다.
- V2/S5 도구,30TASK 전체 지원, 실제 Factory 주문/생산/납품, 실제 학습 효과는 범위 밖이다. 테스트성 콘텐츠를 교육 상품으로 승인하지 않았다.

LM-G1.3a는 기존 목표 시험·목표 점수/등급·목표일의 정본 입력/표시와 저장된 PLAN의 목표 버전 근거를 연결하는 범위에서 착수 가능하다. 등급을 점수로 임의 변환하거나 총 필요학습량·점수상승 예측을 생성하지 않는다. 시간 예산 신규 저장·새 DB/RPC가 필요하면 LM-G1.3b의 별도 승인 의존성으로 분리한다.
