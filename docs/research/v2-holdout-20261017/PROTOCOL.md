# 신규 V2 Instrument 독립 평가 프로토콜

이 파일은 표본 준비 단계의 실행 계약이다. 현재 상태는 `SAMPLE_PREPARED / NOT_EVALUATED / WAITING_FOR_INSTRUMENT_FREEZE`다. 신규 뜻 정답·선택지·근거 주석을 이번 작업에서 작성하지 않는다.

## 1. Instrument 동결이 먼저다

새 측정 정의, B/D/C의 관찰 범위, UI 제시 순서, 확인·재시도·도움 노출 정책, 채점 기준, 옵션 형식 및 코드 commit을 확정하고 SHA256으로 동결한다. 평가 지표와 통과 기준도 결과를 보기 전에 별도 revision으로 고정한다. 지금은 최종 계약이 없어 성과 통과 기준을 만들거나 통과를 주장하지 않는다.

표본 원장의 sourceRevision·골격 projection·공식 답의 출처 fingerprint를 재검증한다. 하나라도 달라지면 해당 문항을 중단한다. 계약이 현재 선정 규칙의 다섯 밑줄형과 맞지 않으면 규칙을 조용히 바꾸지 않고 호환성 보류 또는 연결된 새 표본 revision을 낸다.

## 2. 역할과 노출을 분리한다

- F2 개발자에게는 이 공개 원장의 ID/hash/규칙/검증 상태만 전달한다. 원문 접근 자체를 통제했다고 주장하지 않으며, 새 평가용 의미·근거·선택지 정답은 전달하지 않는다.
- 이 표본 관리자는 이미 공식 B와 원문을 봤으며 기존 유형 분석의 절차 발췌에도 노출됐다. 새로운 미노출 첫 판정 검수자로 재사용하지 않는다.
- 후속 검수자는 개발, 새 주석 작성, 원래/새 해설과 정답, 다른 조건의 동일 지문 노출 이력을 기록한다. 동일 문항을 여러 조건에서 순서대로 풀고 독립적인 첫 시도라고 부르지 않는다.
- 수능 기출이 모델의 학습 이력에 포함되지 않았다는 보장은 하지 않는다. 이번 독립성은 기존 파일럿 12개와 표본/지문을 분리하고 역할·정보 전달·첫 판정 revision을 기록하는 범위다.

## 3. 첫 독립 판단 → 선택지 검수 → 합의 순서

Instrument 동결 이후에만 다음을 시작한다.

1. 미노출 검수자에게 승인된 원문·문장 범위·밑줄만 전달한다. 공식 B·새 옵션·작성자 정답·배제 이유·해설은 숨긴다. B, 자기 말 문맥 뜻, 결정 표현, 대안 해석, 충분성, 불확실성 및 V2/S5 경계를 독립 기록한다.
2. 문항별 첫 판단 파일과 sourceRevision·actor·시각·SHA256을 봉인한다. 골격 문장 번호와 핵심 표현 지목을 별개로 보존한다. 모호·근거 부족을 단일 정답으로 강제하지 않는다.
3. 동결된 Instrument의 옵션/과제 입력 중 검수에 필요한 부분만 분리한다. 정답 키와 작성자 배제 이유를 제외하고 입력 hash를 대조한 뒤 대안별 타당성을 독립 검토한다.
4. 선택지 검수 결과를 새 revision으로 봉인한 후에만 작성자와의 합의를 계산한다. 원래 첫 판정은 고치지 않으며 사후 변경은 revisedAfterExposure 같은 별도 기록으로 남긴다.
5. 공식 B 일치를 독립 문맥 의미 성공으로 세지 않는다. B+D 성공, 근거 위치, 핵심 표현·논증, 문장 논리 부담을 각각 보고한다.

V2/S5 경계는 `V2_PRIMARY / SENTENCE_LOGIC_BOUNDARY / AMBIGUOUS / INSUFFICIENT_EVIDENCE` 중 하나와 이유로 관찰한다. 지금 51개는 전부 `NOT_ASSESSED_PRE_INSTRUMENT`이며 그 분류로 표본을 골라내지 않았다.

## 4. F1 실제 UI 검증

본표본 12개 모두에서 실제 앱을 확인한다. B 확정 전의 최초 진입, 제출 실패, B 재선택, 뒤로/재진입 및 도움 상태에서 D 내용이 시각·DOM·접근성 트리에 노출되는지 기록한다. disabled는 내용 비노출의 증거가 아니다. B의 확정 시점은 새 계약 정의를 따른다.

스크린샷/노출 기록·코드 commit·Instrument hash를 묶는다. 노출이 있으면 D가 B 위치를 역추론하는 단서가 되는지 별도로 판단한다. UI를 실행하지 않은 경우 `NOT_TESTED_UI`이며, JSON 검수 통과를 F1 해결로 대체하지 않는다. 후속 UI 시험은 그 시점의 제품 경로와 데이터 권한을 따르며 이번 표본 작업은 제품 코드를 바꾸지 않는다.

## 5. F2 조건별 비교

서로 미노출인 검수자/시도로 조건을 나눈다. 각 조건의 입력을 정확히 저장한다.

| 조건 | 제공 정보 | 관찰 |
|---|---|---|
| 전체 문맥 | 원문과 동결 과제 | 독립 뜻·근거의 정확성 및 모호성 |
| B+밑줄 단어 | 알려진 B 위치의 단어와 과제 | 사전 뜻·반대말만으로 후보가 정해지는가 |
| B+최소 구 | 위 단어가 포함된 최소 구와 과제 | 전체 문맥을 빼도 극성·관용구만으로 가능한가 |
| 옵션/과제 단독 | B·밑줄 단어·구·원문 없음 | 과제 자체의 어색함·내용·길이로 답이 누설되는가 |

최종 Instrument가 선택형이 아니면 이 조건에서 무엇을 숨기고 무엇을 관찰하는지 대응표를 먼저 동결한다. 이 표본을 본 뒤 유리한 조건을 선택하지 않는다. lexical 반전으로 나온 후보와 교육적으로 유효한 정답을 구별한다. 분석적 우회 가능성, 실제 관찰 수행, 작성자 키 일치를 같은 수치로 합치지 않는다.

본표본 12개는 R/X 각 6개, 각 유형 내 수능/6월/9월 각 2개다. 세부 셀은 2개에 불과하므로 대표성·일반화·통계적 검정력을 보장하지 않는다. 결과는 개수/분모와 문항별 실패 상태를 함께 보고하며, 모호·보류·실패를 분모에서 지우지 않는다. 통계적 효과를 주장하려면 별도의 사전 표본수 설계가 필요하다.

## 6. 예비 표본과 revision

예비는 유형·시험 형태별 1개씩, 총 6개다. 본표본이 원문/권리/revision/노출 문제로 부적격해졌을 때 같은 셀의 봉인된 예비만 사용할 수 있다. 교체 이유와 이전 ID/hash를 별도 revision에 남긴다. 정답률이 낮거나 F2 우회가 발견됐다는 이유로 교체하지 않는다. 예비까지 부적격이면 셀 부족을 보고하고 다른 셀로 채우지 않는다.

## 7. 경계와 완료 산출물

원문·공식 B·이미지·뜻·검토 전문은 비공개로 보존한다. 공개 원장에는 ID/hash/규칙/검증 상태만 남긴다. 공식 문제 공개나 로컬 소유가 제품의 재배포 허가를 뜻하지 않는다. [평가원 기출문제 게시판](https://www.suneung.re.kr/boardCnts/list.do?boardID=1500236&m=0403&s=suneung)은 문제지의 저작권 보유와 무단 복제·배포 등에 대한 제한을 명시한다. 이 작업은 사용자가 허용한 로컬 읽기 전용 조사이며 제품의 권리 정리는 미완료다.

후속 보고서는 첫 판정 봉인, 입력 hash, 옵션별 상태, F1 실제 UI 결과, F2 조건별 결과, 의미/문장 논리 경계, 미검증·모호·제외 및 교체 사유를 남긴다. accepted/releasable/등록/DB 변경·출시 승인·실제 V2 학습 가능 수 증가는 이 프로토콜 실행의 자동 결과가 아니다. 이번에는 평가용 표본 준비만 완료한다.
