## 입력 정합성을 닫는 작업

이번 소규모 후속 우선순위는 본시험 재파일럿에서 결함이 남은24개 연구 입력이다. 각주·잘린 발문·밑줄/빈칸·표 행/열·보기 경계를 별도 복원본으로 만들고 원본/첫 판정/hash는 유지한다. DB 다른 필드의 각주 보관 여부를 먼저 확인한다. 코드북 v1.2 후보에는 정답 탐지/전체 선지 검수, 내용 판정의 기준 문맥, 실제 읽기 창의 시작·끝을 분리한다. 이번32개 재검토는 탐색이며 새 발견 표본으로 검증해야 한다. 최근2025~2026은 아직 유지한다.

1. 16보류 원인을 문장 번호, 직접 인용, 밑줄/자료 범위, 정답 출처, 해석 미해결로 구분한다. 기존 상태와 최초 반려를 유지하고 새 연구의 source 상태를 추가한다. 공개 승인과 연구 편입을 혼동하지 않는다.
2. 장문5그룹의 시험 제시문/문항별 저장본 차이를 분리한다. 원문 빈칸이 제목 문항 저장본에서 사라지거나 보기 머리가 섞인 상태를 정상 공통 본문이라고 확정하지 않는다. 이 단계의 교정은 **로컬 연구 입력에만** 새 버전으로 만들고 이전 hash/판정을 보존한다.
3. 정답표가 듣기대본인 모평은 기존 보완 JSON과 실제 원본 PDF의 계보를 잇는다. 보완 숫자와 DB가 맞는 것만으로 공식 PDF 직접 확인 완료를 표시하지 않는다. 실제 PDF 미확보 문항은 확인적 결론 보류.
4. 공식 기출 게시판의 기간별 책자·첨부 목록을 독립적으로 대조한다. 현재 모평14책자 누락 후보가 있으므로 먼저 확보 여부를 확인하고, 못 확보하면 ‘보유분 전수’만 보고한다. 학평을 구멍에 끼워 넣지 않는다.
5. 도표·밑줄·순서/삽입 자료를 텍스트 다섯 보기로 잘못 해석하지 않도록 각 유형의 제시 단위를 직접 확인한다. 원문 전체의 높은 문자열 유사도를 실제 해당 표시 확인과 구분한다.

## 확대의 단위와 검수

발견606문항은 본시험과 모평을 나누고, 유형보다 담화 목적·근거 범위가 다양한 배치를 만든다. 초기32는 대표성 표본이 아니므로 분포 추정에 사용하지 않는다. 실제 분류가 존재하는 문항만 측정 분모에 넣고 미분류·미해결·입력보류를 함께 보고한다.

PROTOCOL 기준을 넘은 축만 확대한다. 실패 축은 v1.1 경계 정의와 새 미열람 발견32표본으로 다시 분류한다. 합의본을 최초 일치도 표본에 섞거나 지지 사례만 새 표본으로 골라 일치도를 높이지 않는다. 제3 판정도 AI이면 그대로 표시한다. 인간 영어교육/평가 전문가가 최소2명 각자의 독립 판정을 할 때까지 인간 검수 완료로 승격하지 않는다.

확대 출력은 문항별9축 모두가 강제로 완결되어야 하는 단일 상태가 아니다. 예를 들어 담화 축은 통과했지만 추론 축은 미해결이면 그대로 저장한다. 전수 담화 통계가 있다고 전수 추론 통계를 수행한 것처럼 말하지 않는다. 모든9축 완료는 적격 전 문항에 실제 근거·판정·검수 기록이 있을 때만 주장한다.

## 확인적 검증 구조

- 최근 검증 후보168문항을 문항/공유 지문으로 연결한다. 공개보류와 사전 노출을 제외한 수를 명시하고, source 대조 완료분만 확인적 분석에 포함한다.
- 연구 총괄이 메타/기존비교 감사 중 내용을 본 최근 문항은 2026#34·2026#19·M2606#19·M2609#18, 추가 비교 초점에서 본 2025#18·M2609#19다. 마지막2개 노출은 사전 프로토콜 이후·원리 확정 및 검증 이전이다. item-manifest의 previously_exposed로 기록했다. 공유/동일 본문에 전파하여 제외한다.
- 공식답·기존 v3 없는 입력을 새로운 문맥에 제공하고 최초 분류·풀이를 저장한 뒤 답을 공개한다. 독립 분석자는 다른 판정과 설계 결론을 먼저 읽지 않는다.
- 원리별 적용가능 분모와 성공/실패/미해결을 보존한다. 수정한 원리는 이미 본 검증 문항에서 탐색 결과로만 보고하고 새 미열람 자료를 확보해야 재검증할 수 있다.
- 본시험/모평, 2014 A/B, 과제 종류, 공유 본문을 층화·군집화한다. 표본 부족은 ‘변화 없음’이 아닌 판단 불능으로 보고한다.

## 학생 교수 효과의 별도 연구

연구 A~D는 문항의 성립과 처리 요구를 분석한다. E의 교수 효과에는 학생 실험이 필요하다. 비교 교수·시간·자료·도움 조건을 맞추고, 학생 사전 수준·미학습 문항·지연 검사를 사전 등록한다. 학생의 실제 의미 갱신/자기 설명을 관찰하지 않고 문항 논리에서 인지 과정을 추정해 대신 쓰지 않는다. 인간 전문가 검수·학생 실험을 수행할 수 없는 상태에서는 H/E 미확정을 유지한다.

## 재실행

Windows에서 `pnpm.cmd`와 Node를 사용한다. 기존 자격 증명은 출력·복사·커밋하지 않는다.

```powershell
node --tls-max-v1.2 scripts/research/csat-reading/snapshot.mjs --workspace D:/workspace/Vocaflow --as-of 2026-10-12 --snapshot-id 20261012-r1
node scripts/research/csat-reading/audit.mjs --source D:/workspace/Vocaflow --corpus scripts/research/csat-reading/local/snapshots/20261012-r0/db-corpus.json --as-of 2026-10-12
node scripts/research/csat-reading/render-audit.mjs
node --test scripts/research/csat-reading/agreement.test.mjs
node scripts/research/csat-reading/agreement.mjs
```

등록 입력은 로컬 `snapshots/20261012-r0`에 원문·blind 입력·정답키를 보존했고 execution-record.json에 소스 commit, 사전 규칙 commit/hash, 원문 snapshot·pilot manifest·입력·정답키 hash를 등록했다. 이 원문 없이는 metadata만으로 전문을 복원할 수 없다. 새 snapshot은 별도 ID 디렉터리에만 쓰며 같은 ID가 이미 있으면 거부한다. 새 r1은 현재 DB 상태의 다른 연구 입력이지 r0 재현이 아니다. 기존 판정에 결속된 hash가 바뀌면 agreement가 거부하며 새 판정을 구판에 자동 결속하지 않는다. 날짜는 명시 인자이고 통계 로직에서 현재 시계를 읽지 않는다. 과거 공유 워크스페이스와의 drift는 등록 원장의 기존 hash를 사용하며 그 폴더의 현재 값이 과거 버전이라는 보장은 없다.
