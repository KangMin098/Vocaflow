# LM-G1.4 독립 T4 검증 절차

고정 제출 `68b1541fff7dd0dd880e6bd51e1ba091d770786c`, 기준 main `8ee927dcee80a9b19d70b2d4c86869e8ea013813`. 별도 worktree에서 원본 실패와 수정 재검증을 분리한다. 기존 제출 원장·스크린샷을 덮어쓰지 않는다.

1. A~G 첫 시도 반례는 기존 DB 뷰의 `attempt_id`와 실제 시도 `id`를 기준으로 한다. 시각 정렬이나 배열의 첫 원소로 새로운 첫 시도를 선출하지 않는다. ID가 없거나 연결 결과가 충돌하면 UNKNOWN이다.
2. 수행/원장 정오/현재 주석/독립 자격을 별도 판정한다. 현재 주석이 UNKNOWN·STALE이면 현행 조건 성공을 주장하지 않는다. 독립 첫 오답은 성공이 아니라 독립 관찰로 구별한다.
3. 연습·도움 확정은 부적격, 시각·도움 누락은 보류다. 합성 기록은 효과 표본이 아니다. resolved/verified_need, 120일, 전이 운영량 및 P1~P7 정책을 변경하지 않는다.
4. 2,505행 ID 커서·보류 필터·둘째 페이지 실패·정상0건을 실제 loader 함수와 고정 query fixture로 검증한다. 12,001행·4 TASK key·24 조합에서 실제 과제 레지스트리 주석/해시 호출을 측정한다. 일부 실패와 전체 실패를 구별한다. 단일 시간 관찰로 속도 개선을 일반화하지 않는다.
5. 실제 개발 DB의 소유 합성 계정과 Chromium 1280×900·1440×900에서 세 표면, 원장 ID 연결, 다른 목표 snapshot의 compose, 과거 asof와 T1/T2/T3를 검증한다. 예외/연결 중단/정리 미확인을 PASS로 세지 않는다.
6. 원문·전체 runtime·계정 식별자·실행 로그는 ignored local에 보존하고 공개 원장은 whitelist metadata와 선정 화면만 포함한다. UI 증거는 코드 hash와 실행 버전에 결속한다.
7. A 계보/B 첫 시도/C 현재성/D 주장 범위/E 세 표면/F 회귀/G 권한·성능을 독립 판정한다. 미해결 핵심 P1/P2이면 REWORK, 자료/정책 부재는 NOT_TESTED/BLOCKED_APPROVAL이다. 최종 제품·보고 revision·CI를 구별하고 safe-merge만 사용한다.

증거 층위는 순수 정책·고정 query fixture, 실제 개발 DB/API, 실제 Chromium, 실제 학습 효과를 구별한다. 마지막 층위는 이번 범위에 없다. SQL/RPC/RLS 적용, 실제 학생 변경, 새 평가 엔진·화면·콘텐츠를 수행하지 않는다.
