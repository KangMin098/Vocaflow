# Lexicon v2.1 vs v3.1 — 비교 분석 보고서

> 작성일: 2026-05-20
> 목적: Phase 1 진행 전 두 모델의 양립 가능성 + 진행 전략 결정

## ⚠ 핵심 발견 — v2.1은 이미 production 적용 상태

메모리 기록 ("Lexicon v2.2 KICE 13y ingest — word_lexicon 5,421 lemmas + 5 auto-curated sets")에 따라 v2.1 schema는 **이미 production Supabase 에 적용되어 운영 중**이며 5,421 lemma + 5 auto-curated sets 가 적재됨. 따라서 "v2.1을 폐기" 옵션은 사실상 production schema drop 을 의미하며 위험.

→ **올바른 질문은 "폐기 vs 보존" 이 아니라 "v3.1 Phase 1이 live v2.1과 양립 가능한가?"**

## 두 모델 핵심 차이

| 영역 | v2.1 (live) | v3.1 Phase 1 (proposed) |
|---|---|---|
| 통합 단위 | `word_lexicon` 신규 별도 테이블, UUID PK | `shared_dictionary` (기존) 확장, `word` TEXT PK |
| 다품사 | `UNIQUE(lemma, part_of_speech)` row 분리 | `senses` JSONB 단일 row 내부 sense_idx |
| 출처 마스터 | `frequency_data_sources` ✅ 생성됨 | 동일 — 신규 5건 ON CONFLICT DO NOTHING 시드 |
| 빈도 통계 | `word_frequency_stats` (lexicon_id FK) | `lexicon_frequencies` 신규 (lemma TEXT FK → shared_dictionary) |
| shared_words 연결 | `lexicon_id UUID` ✅ 추가됨 | `lemma TEXT` 신규 추가 (병행 dual-write) |
| 의도 | KICE 빈도 통계 분리 저장 (sprint 한정) | 마스터 사전 통합 (전체 시스템 정합) |

## 양립 가능성 — Phase 1 한정

v3.1 Phase 1 SQL은 모두 **ADD COLUMN / CREATE TABLE / INSERT ON CONFLICT** 만 사용. 기존 v2.1 객체를 변경·삭제하지 않음:

| Phase 1 변경 | v2.1 영향 |
|---|---|
| shared_dictionary 11개 컬럼 추가 | ❌ word_lexicon 무관 — 충돌 0 |
| lexicon_frequencies 신설 | ⚠ word_frequency_stats 와 의미 중복 — Phase 2~5 에서 통합 |
| 신규 frequency_data_sources 5건 INSERT | ✅ ON CONFLICT DO NOTHING — 기존 6건 보존 |
| vocabularies / shared_words / library_*_vocabularies.lemma 추가 | ✅ v2.1의 lexicon_id (UUID) 컬럼과 별개 — 공존 |
| 큐레이션 테이블 lemma_normalized | ✅ 새 컬럼 — 충돌 0 |

**결론: Phase 1 SQL은 v2.1과 양립 가능**. 두 사이드카 (`word_frequency_stats`, `lexicon_frequencies`) 가 잠시 공존하며, Phase 2~5 에서 통합 또는 한쪽 폐기.

## Phase 2~ 에서 발생할 진짜 충돌

| 충돌 | v2.1 | v3.1 | 해결 방향 |
|---|---|---|---|
| 다품사 표현 | row 분리 (UUID + UNIQUE lemma,pos) | senses JSONB | **v3.1 senses 채택, word_lexicon UUID row → senses 항목으로 머지** |
| 빈도 사이드카 | `word_frequency_stats(lexicon_id UUID)` | `lexicon_frequencies(lemma TEXT)` | **lexicon_frequencies 로 통합 + word_frequency_stats 데이터 이전** |
| shared_words FK | `lexicon_id UUID` | `lemma TEXT` | **lemma TEXT 유지, lexicon_id Phase E에서 DROP** |
| 신규 단어 ingest 경로 | word_lexicon | shared_dictionary | **shared_dictionary 단일화** |

→ Phase 2~5 작업 시 v2.1 의 5,421 lemma + 빈도 통계를 shared_dictionary.senses + lexicon_frequencies 로 정확히 이전하는 ETL 필요.

## 권장 진행 방향

### 옵션 A — v3.1 Phase 1 즉시 진행 + v2.1 동결 (권장)
- Phase 1 SQL은 ADD-only 라 안전. v2.1 객체 보존.
- word_lexicon 신규 INSERT 동결 (이후 모든 신규 단어는 shared_dictionary 로만 ingest).
- Phase 2 에서 word_lexicon → shared_dictionary 데이터 머지 ETL 작성.
- Phase E (Week 4~5) 에서 word_lexicon / word_frequency_stats / lexicon_source_tags DROP.

### 옵션 B — v2.1 보존 + v3.1 별도 PoC
- 두 시스템 병행 운영 → 단어 dual-source 문제 발생 가능 (어느 게 진실?)
- 큐레이션 파이프라인 복잡도 증가.
- 비권장.

### 옵션 C — v2.1로 통일, v3.1 폐기
- production 안정성 최우선.
- v3.1 의 senses JSONB / surface_index MV 장점 포기.
- shared_dictionary 21,740 단어를 word_lexicon 으로 옮겨야 함 (역 ETL — 위험 더 큼).
- 비권장.

## 추천 결정

**옵션 A**. Phase 1 SQL은 그대로 진행 가능하며 v2.1 production 데이터를 위협하지 않음. Phase 2 ETL 설계 시점에 word_lexicon 의 5,421 lemma + 빈도 통계 이전 절차 작성.

## 실행 전 추가 확인

1. word_lexicon ↔ shared_dictionary lemma 중복도 확인 (대부분이 shared_dictionary 21,740 안에 포함되는지)
2. word_frequency_stats 의 metadata.years_appeared 등 KICE 전용 메타가 lexicon_frequencies.metadata JSONB 로 1:1 매핑 가능한지 (Phase 2 ETL 설계 시)
3. Phase E DROP 시 위 5,421 + 28,124 매핑 데이터 손실 0 보장 절차 (백업 + 데이터 무결성 검증)
