# 목적 대조 리뷰 — 결함 + 목적 이탈

> 정본. Codex 자동 리뷰(Stop 훅 · `agents/scripts/review.mjs`)와 사람이 부르는 교차 리뷰가 같은 기준을 쓴다.
> 왜: 코드 결함만 보는 리뷰는 **사용자가 원하지 않은 방향으로 잘 만든 코드**를 통과시킨다.
> 실측(2026-10-01, PR #135 → #141): 진단 MVP 가 Codex 리뷰 11회를 통과했지만 사용자는 「불필요하고 잡다한 내용」
> (프로필 설문 · 진단 테스트 · 습관 · 시나리오 · 역량 9개)이라며 전면 재설계를 지시했다. 리뷰가 목적을 몰랐다.

## 목적 파일 — `.agent-goal.md` (워크트리 루트 · gitignore)

작업을 시작할 때 쓰고, 사용자가 방향을 바꾸면 **그 자리에서 고친다**. PR 본문의 「목적 · 수용 기준」 절로 옮긴다.

```markdown
# 목적
<사용자가 원하는 결과 한두 문장 — 사용자 말 그대로>

# 수용 기준
- <눈으로 확인할 수 있는 조건>

# 하지 않을 것 (사용자가 걷어냈거나 범위 밖이라고 한 것)
- <예: 프로필 설문 · 진단 테스트 · 습관 신호>

# 지시 기록
- 2026-10-01 「…」 → <무엇을 바꿨나>
```

## 리뷰가 보는 것

결함(기존 기준 그대로)에 더해, 목적 파일과 변경을 대조해 **목적 이탈**을 같은 등급으로 보고한다.

| 등급 | 목적 이탈 |
|---|---|
| P1 | 「하지 않을 것」을 다시 들여왔다 · 목적과 반대 방향 · 수용 기준을 깨뜨렸다 |
| P2 | 요청하지 않은 기능 · 화면 · 설정 · 단계가 늘었다(범위 확장) · 수용 기준 하나가 빠졌다 · 사용자가 쓰지 않을 복잡도(설문 · 옵션 · 단계)가 늘었다 |
| P3 | 목적과 무관한 잔손질 · 문구가 지시와 어긋남 |

- 근거를 적는다: `[P2] path:line — 목적 이탈: <목적 파일의 어느 줄과 어긋나는가> — <되돌리거나 줄이는 법>`.
- 목적 파일이 없으면 **그 사실을 [P2] 로 보고한다**(「목적 파일 없음 — 목적 대조를 못 했다」). 통과로 치지 않는다.
- 목적 파일에 없는 판단(취향 · 더 나은 설계)은 이탈이 아니다. 사용자의 말과 어긋날 때만 보고한다.

## 계획 리뷰 — 코드보다 먼저

실측(2026-10-02): 「학습 지도」 설계안을 계획부터 세웠지만, 코드 리뷰는 커밋 뒤에야 돈다. 목적 이탈은 계획에서 잡는 게 가장 싸다.

- **언제**: 계획·설계안을 사용자에게 승인 요청하기 **전**(plan mode 포함). 3개 이상 영역 · 새 테이블/마이그레이션 · 새 화면이면 필수, 한 파일 수정은 생략.
- **어떻게**: 계획을 파일로 쓰고(`.agent-plan.md` · gitignore 권장) `node agents/scripts/review.mjs --plan .agent-plan.md`. 목적은 같은 `.agent-goal.md`.
- **보는 것**: 위 목적 이탈 등급 + 계획 결함(저장소와 다른 주장 · 이미 있는 자산 무시 · 가드 없는 되돌릴 수 없는 단계 · 말없이 기대는 빈 데이터 · 같은 정보 두 곳 표시).
- **결과 처리**: P1·P2 는 계획을 고친 뒤 다시 돌린다. 사용자에게 계획을 낼 때 **리뷰 결과(남은 P3 · 반영한 지적)를 함께 적는다**. Codex 를 못 돌리면(미설치·한도) 「계획 리뷰 못 함」이라고 밝힌다 — 통과로 치지 않는다.
- Codex 가 계획을 쓴 쪽이면 반대로 Claude 가 같은 기준으로 리뷰한다.
