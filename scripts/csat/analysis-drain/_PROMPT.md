# 기출 문항 분석 드레인 — 작업 명세

> 이 파일은 청크와 함께 **남는다**(`.gitignore` 가 청크만 지운다). 절차를 잊고 다시 정하는 일을 막는다.
> 대상: 평가원 수능·모의평가 **독해·장문(듣기 제외)** 830문항. 사정권 유형 26.

---

## 0. 이 분석이 무엇을 위한 것인가

목표는 **학습자가 이 분석을 읽고 그 유형에서 실점하지 않는 것**이다.
**듣기는 전체에서 제외한다**(사용자 지시). 우리가 책임지는 것은 **독해 사정권에서 실점 0** 이다 —
2015학년도 이후 63점, 2014학년도 A/B형은 듣기가 22번까지라 53점이다.
(「99점」이라 쓰지 마라. 배점 단위가 2·3점이라 99점이라는 점수가 아예 안 나오고, 100점은 듣기까지
만점이어야 한다. 독해를 다 맞혀도 총점은 100 − 듣기 실점이다.)
곧 "대체로 맞힌다" 는 목표 미달이다. **한 문항도 놓치지 않는 절차**를 쓴다.

그래서 금지되는 서술이 있다:

| 금지 | 왜 |
|---|---|
| "글의 흐름을 파악하면 답이 보인다" | 순환논법. 파악하는 방법이 절차다 |
| "선지 ③은 지문과 다르다" | 어디가 왜 다른지 없으면 검증 불가 |
| "어휘력이 필요하다" | 어떤 낱말인지 적어야 처방이 된다 |
| 정답을 이미 안다는 전제의 서술 | 학습자는 정답을 모르는 상태에서 읽는다 |

## 1. 할 일

`chunk-NN.json` 을 읽고 **같은 폴더에 `chunk-NN.out.json`** 을 쓴다.

```jsonc
{
  "chunk": 1,
  "type_id": "R-BLANK",
  "analyses": [ /* 청크의 items 수만큼. 순서 무관, item_id 로 짝짓는다 */ ]
}
```

### analyses[] 한 개의 모양

```jsonc
{
  "item_id": "2026#31",

  // ── ① 출제자 층위 ────────────────────────────────────────────
  "measured_ability": "빈칸 앞 문장의 일반화를 뒤 예시가 어떻게 좁히는지 읽어 내는 능력",
  "design_intent": "출제자가 이 문항으로 무엇을 가르려 했는지 한두 문장. 유형 일반론이 아니라 이 문항 고유의 것",
  "answer_locus": {
    "sentence_index": [3, 7],        // 지문 문장 번호 1-base. 지문이 없으면 raw_block 기준 근사
    "quote": "지문에서 그대로 따온 정답 근거 (20~120자)",
    "reasoning": "그 문장이 왜 정답을 확정하는지. '주제이므로' 같은 되풀이 금지"
  },

  // ── ② 선지 층위 — **정답 확정 + 오답 배제**, 선지 5개 전부 ────
  //
  // ⚠️ **이 자리가 이 파이프라인의 본체다.** 학습자가 알고 싶은 것은 "왜 ③인가" 하나이고,
  //    나머지는 전부 그 답에 딸린 것이다. 그런데 오래도록 이 블록에 **오답용 필드 둘**밖에
  //    없었다 — 정답 선지는 `verdict: "correct"` 만 찍히고 서술이 비었다(실측 146/606).
  //    정답 근거 인용은 606/606 있는데 **그 인용이 정답 선지와 어떻게 맞물리는지**가 없으니,
  //    학습자에게 "그래서 왜 ③인가" 가 끝내 닿지 않는다.
  //
  //    정답 선지에는 `why_correct` 를, 오답 선지에는 `why_tempting`+`how_to_reject` 를 쓴다.
  //    **정답 선지에 `why_tempting`/`how_to_reject` 를 쓰지 마라** — 이름이 뜻과 어긋난다.
  "choices": [
    {
      "n": 3,
      "verdict": "correct",
      // 정답 선지 **필수**. 두 가지를 한 문장 안에 다 담는다:
      //   ① `answer_locus.quote` 의 어느 부분이 ② 이 선지의 어느 부분과 맞물리는가.
      // "주제를 가장 잘 나타내므로" 같은 되풀이는 반려된다. **대응을 낱말 단위로 지목**해야 한다.
      "why_correct": "근거 문장의 'the absence of directness leaves them without advice' 가 이 선지의 '문제 해결에 도움이 되지 않는다' 와 대응한다. 주어(간접 화법)도 선지 주어와 같다.",
      // 정답 선지가 **어디서 확정되는지** — 인용만으로 부족하면 두 번째 자리를 적는다
      "confirmed_at": { "sentence_index": [7], "note": "6번 문장은 사례라 확정력이 없다" }
    },
    {
      "n": 1,
      "verdict": "distractor",
      "trap": "<유형군에 맞는 라벨 — 아래 두 표 중 하나에서 고른다>",
      // 라벨표는 §1-b 에 있다. **유형군에 따라 다른 표를 쓴다.**
      "why_tempting": "이 선지가 왜 골라지는지 — 지문의 어느 표현을 어떻게 오독하면 여기 닿는지",
      "how_to_reject": "지문의 어느 자리를 보면 배제되는지. **근거 위치를 반드시 적는다**(몇 번째 문장 · 어느 단락 · 어느 어구)"
    }
    // … 5개. **다섯 개 전부** 서술이 있어야 한다. 비면 게이트가 막는다
  ],

  // ── ③ 학습자 층위 ────────────────────────────────────────────
  "solve_procedure": [
    { "step": "발문에서 빈칸이 문단 어디에 있는지 먼저 본다", "on_fail": "위치를 못 정하면 역접 표지를 찾는다" }
    // 3~6단계. 각 단계는 **지문을 아직 안 읽은 학습자**가 실행할 수 있어야 한다
  ],
  "time_budget_sec": 100,            // 이 문항에 쓸 수 있는 시간. 독해 63점 70분 기준으로 배분
  "difficulty": {
    "predicted": 0.62,               // 예상 정답률 0~1
    "drivers": ["추상 명사 다수", "빈칸이 마지막 문장"]
  },
  "required_vocab": ["arbitrary", "convention"],   // 이 문항 정답에 실제로 필요한 낱말만. 지문 전체 어휘 나열 금지

  // ── ④ 3인 검수 ───────────────────────────────────────────────
  "reviews": [ /* §2 */ ]
}
```

**정답을 모르는 문항**(`answer_known: false` — 모평 7회차는 평가원 정답표가 없다):
`answer_locus` 와 `choices[].verdict` 를 **쓰지 않는다**. 대신 `"answer_unknown": true` 를 넣고
`measured_ability` · `solve_procedure` · `difficulty` · `required_vocab` 만 채운다.
**추정한 정답을 정답인 척 적지 않는다.** 그 한 줄이 학습자를 반대로 훈련시킨다.

**`body_ok: false` 문항**: 지문·선지를 못 떴거나 미덥지 않다. `raw_block` 에 **문항 블록 + 회차
원문 창**이 함께 들어 있다. 단이 안 갈린 페이지에서는 블록 자체가 두 단이 낱말 단위로 섞인
뭉갬이므로(`sunk cost ______ This makes sense from the perspective of information fallacy`)
**원문 창에서 좌우를 갈라 읽는다.** 복원했으면 `"body_recovered": true` 를 넣는다.

**`same_item_as` 가 붙은 문항**: 2014학년도는 수준별(A/B형) 시행이라 두 문제지가 일부 문항을
공유한다 — 지문·선지·정답이 문자열까지 같고 번호만 다르다(실측 2쌍: `2014A#24 ≡ 2014B#23` ·
`2014A#32 ≡ 2014B#29`). **분석은 양쪽 다 쓴다**(각각 그 회차의 문항이므로 원장에 있어야 한다).

- `type_report.n_analyzed` 는 **그대로 청크의 분석 개수**다. 줄이지 마라 — 게이트가
  "빠뜨린 문항이 없는가" 를 이 값으로 본다. 중복 제거는 **import 가 코퍼스를 보고 직접** 한다.
- `recurring_traps[].count` 는 **한 번만 센다.** 같은 문항의 같은 함정을 두 번 세면
  그 유형의 함정 순위가 그만큼 틀어진다.
- 무엇을 한 번만 셌는지 리포트 본문에 한 줄 적어라.

**선지 번호 분포를 말할 때** — 청크의 `type_answer_distribution` 을 쓴다. 유형 **전체**의 실측이고
`keyed`(정답표가 있는 문항 수)가 분모다. **분모를 지어내지 마라.** 실제로 겪었다 — 한 청크가
절차 1단계에 「13개년 192문항에서 1번이 정답인 적은 0회(보정 p=1.0e-25)」를 넣었는데, 192는
근거가 없고(R-ORDER 사정권 56 · 정답표 42) **①은 한 번 정답이었다**(M2506#36). 저장소의 옛 문서도
같은 거짓을 적고 있었으니 **되풀이되는 실수**다. 그리고 「N회 0」 은 이 저장소의 Bonferroni 문턱
(가족 130 · 3.85e-4)을 넘은 것만 사실로 쓴다 — 넘지 못하면 "유의하지 않다" 고 쓰고 **절차에 넣지
않는다.** 찍기를 가르치는 것은 이 파이프라인의 목적이 아니다.

**⚠️ 청크와 코퍼스가 다르면 코퍼스가 정본이다.** 청크는 뽑힌 시점의 코퍼스를 담는데
(`corpus_built_at` 참조), 그 사이 파서가 고쳐지면 청크가 낡는다. **인용은 반드시
`scripts/csat/data/corpus.json` 의 현재 지문에서 뽑아라** — 게이트가 그것을 건초더미로 쓴다.
청크 본문에서 뽑으면 멀쩡한 인용이 "지어냈다" 로 걸린다(실측으로 겪었다).

## 2. 3인 검수 — 서로 다른 전문가 입장

**한 사람이 세 번 보는 것이 아니다.** 세 입장은 서로의 맹점을 덮도록 고른 것이고,
같은 분석을 셋이 다른 자로 잰다. **셋 다 `pass` 여야 published** 다.

| persona | 누구의 눈 | 무엇을 보나 | 반려(fail/revise) 사유 |
|---|---|---|---|
| `setter` | 출제자 (평가원 출제위원) | 서술한 출제 의도가 이 유형의 실제 설계와 맞나. `answer_locus.quote` 가 **지문에 실제로 있나**. **`why_correct` 의 대응이 실제로 성립하나** — 인용의 그 낱말이 정말 그 선지의 그 부분과 맞물리나. 유형 정의를 벗어난 서술이 없나 | 인용이 지문에 없다 · 대응이 낱말 단위로 확인되지 않는다 · 유형과 어긋난다 · 의도가 유형 일반론뿐이다 |
| `analyst` | 오답 분석가 (채점·문항반응 통계) | 오답 4개의 `trap` 이 **서로 다른가**. `why_tempting` 이 선지 텍스트에 실제로 근거하나. `how_to_reject` 에 지문 위치가 있나 | 함정 라벨 중복 · 선지 텍스트와 무관한 서술 · 배제 근거에 위치가 없다 |
| `tutor` | 현장 강사 (학습자 대리) | `solve_procedure` 를 **지문을 아직 안 본 학생**이 실행할 수 있나. 순환논법이 없나. `time_budget_sec` 안에 끝나나. `required_vocab` 이 실제로 정답에 필요한 것인가 | 실행 불가 · 순환논법 · 시간 초과 · 어휘 나열 |

## 1-b. 함정 라벨표 — **유형군에 따라 다른 표를 쓴다**

한 표로는 안 된다. 선지가 **문장**인 유형과 **위치·순열 기호**인 유형은 함정이 걸리는 층이 다르다.
서로 다른 청크 **넷**이 독립적으로 "명제형 라벨 9종이 이 유형 오답에 한 건도 안 맞는다" 고
보고했고(R-ORDER 48개 중 0 · R-INSERT 48개 중 0), 억지로 붙이면 라벨이 정보를 잃는다.

### (A) 명제형 — 선지가 문장·구인 유형

`R-BLANK` `R-SUMMARY` `R-TITLE` `R-TOPIC` `R-GIST` `R-CLAIM` `R-PURPOSE` `R-MOOD` `R-IMPLY`
`R-NOTICE` `R-FACT` `X-TITLE` `X-FACT` `X-BLANK*`

`범위 과대` · `범위 과소` · `인과 역전` · `주체 역전` · `부분 사실` · `어휘 함정` ·
`지문 밖 상식` · `반대 진술` · `무관`

> `주체 역전` 은 나중에 더했다 — 청크 셋이 "이 라벨이 없어 인과 역전으로 대신 달았다" 고
> 보고했다. 행위는 지문과 같은데 **하는 사람이 바뀐** 함정이다.

### (B) 위치형 — 선지가 기호(①~⑤ 위치 · (A)(B)(C) 순열)인 유형

`R-INSERT` `R-ORDER` `R-IRRELEVANT` `X-ORDER`

`첫 등장 위반`(부정관사→정관사 · 익명→지명이 뒤집힘) · `지시어 선행사 절단` ·
`지시어 선행사 앞당김` · `연결사 방향 충돌` · `열거·병렬 절단` · `총론-각론 역전` ·
`조건-귀결 절단` · `시간·인과 순서 역전` · `어휘 반복 유인`(겹치는 낱말이 단서가 아니라 미끼) ·
`마무리 문장 위치 오판`

> **어휘 반복 유인은 이 유형군의 최대 함정이다.** 옛 회차 8문항 전수에서 주어진 문장과
> 낱말이 가장 많이 겹치는 자리가 예외 없이 오답이었다. 겹치는 낱말의 **기능**(수단인가
> 특징인가)이 다르면 근거가 아니다.

### (C) 어법·어휘 밑줄형

`R-GRAMMAR` `R-VOCAB` `X-VOCAB` `R-REFER` `X-REFER` — 위 둘 중 가까운 쪽을 쓰되,
맞는 라벨이 없으면 **새로 쓰고 `open_questions` 에 등재를 제안한다.** 억지로 붙이지 마라.

## 1-c. 유형마다 **「근거의 모양」이 다르다** — 606문항을 전수로 읽고 얻은 것

`why_correct` 를 쓸 때 이 표를 먼저 본다. 여기 적힌 것은 전부 **실측**이고, 옆의 수는
그 명제가 몇 문항 중 몇에서 성립했는지다. 「어떻게 쓰나」를 모르면 분석자는 어김없이
**「왜 이 정답을 놓치기 쉬운가」**(학습자 심리)를 쓰고 정답 근거를 쓴 것으로 착각한다 —
2026-09-03 전수 판정에서 그 착각이 130건 나왔고, **정답이 「틀린 것」인 유형에 몰렸다.**

| 유형군 | 확정 근거는 무엇인가 | 실측 |
|---|---|---|
| **불일치 찾기**<br>`R-FACT` `X-FACT` `R-NOTICE` | 정답 선지는 지문 문장의 **성분을 딱 하나만** 갈아 끼운다. 나머지가 글자 그대로 맞는 것은 확인이 아니라 **출제자가 맞춰 둔 미끼**다. 갈린 자리는 예외 없이 술어의 극성이나 그 앞 수식어 한 자리 — `poorly`↔매우 · `light`↔무거웠다 · `after`↔이전에 · `only`·`not`·단위·시간대 | 사건 자체는 언제나 참 (X-FACT 6/6 · R-NOTICE 10/10) |
| **무관한 문장**<br>`R-IRRELEVANT` | 정답 문장은 **떼어 읽으면 참이고 상식적**이다. 「틀린 문장 찾기」로는 원리상 안 잡힌다. 잡히는 자리는 **뒤 문장의 되받는 표현이 그 문장을 건너뛰어 두 칸 앞에 닿는가** 하나. 그리고 정답 문장은 앞 문장과 **낱말이 가장 많이 겹친다** — 겹침을 근거로 쓰면 정확히 거꾸로 간다 | 12/12 참인 문장 · 12중 9가 건너뜀 |
| **문장 삽입**<br>`R-INSERT` | **양쪽의 교집합**이다 — ① 앞 문장이 주어진 문장의 표지(`Thus`·`Rather`·`twice as long`)에 전제를 대주는가 ② 뒤 문장의 지시어(`these experiences`·`this way`)가 주어진 문장 없이는 선행사를 잃는가. 한쪽만 적으면 이웃 위치가 안 배제된다. 그리고 **낱말이 가장 많이 겹치는 자리가 정답보다 한두 칸 앞**에 놓인다 | 겹침 유인 8중 6 |
| **순서 배열**<br>`R-ORDER` `X-ORDER` | 이음매마다 **어느 표지가 어느 낱말을 받는지** 한 줄씩. 이음매가 둘이면 둘 다(하나만 적으면 여섯 순열 중 둘 이상이 남는다). 근거는 **앞 덩어리의 마지막 문장**에 숨는 경우가 많다 — 뒤 덩어리 첫머리의 정관사·지시어가 받을 **첫 등장**이 거기 있다 | 12중 9 · 결정 표지는 「지시 강도의 한 단계 상승」 9중 8 |
| **어법**<br>`R-GRAMMAR` | **무엇이 그 자리를 지배하는가** 하나. **최근접 명사 오인**이 설계 장치다 — 진짜 지배 주어는 늘 한두 구 너머에 있고 밑줄 바로 왼쪽에 미끼 명사가 놓인다. 처방: 밑줄이 걸린 절의 **정동사를 먼저 세고 그 주어를 적은 다음**에야 가까운 명사를 본다. ⚠️ `as if` 절의 `were` 는 가정법이라 수의 증거가 못 된다 | 다시 쓴 12중 6이 최근접 명사 오인 |
| **어휘 밑줄**<br>`R-VOCAB` `X-VOCAB` | 밑줄 문장 **자신의 종속 구조**가 극성을 이미 고정한다(`In much the same way that` 직유 · 콜론 자기설명 · `since` 이유절 · `better ~ than` · `Without ~` · 바로 뒤 `For example`). 오답 낱말은 예외 없이 **일상 상식으로 그럴듯한** 쪽이다. 어휘력이 아니라 문맥 추론을 재는 유형 | 14중 12가 문장 안에서 닫힘 |
| **지칭**<br>`R-REFER` `X-REFER` | 두 짝을 다 댄다 — ① 정답 밑줄의 대상을 확정하는 **문법 근거**(직전 절 주어 승계 · 소유격 임자 · 인용 화자 · 재귀형 아님) ② 나머지 넷이 한 사람으로 모인다는 것. 단일 체크: **밑줄이 든 문장이 다른 사람을 이름·관계어·호격으로 따로 부르면 밑줄은 그 사람이 아니다** | 12/12 |
| **목적**<br>`R-PURPOSE` | 「화행 동사 대응」과 **「목적어 대응」** 둘로 쪼갠다. 끝까지 남는 오답은 예외 없이 **동사는 같고 목적어만** 다르다 — 동사만 짚으면 함정이 갈리는 바로 그 성분을 비워 두는 것이다. 근거 자리는 **양 끝단**(요구형은 맺음 인사 앞 1~3문장, 통보형은 첫 문장 예고문)이고 중간 단락은 오답의 재료다 | 중간 단락 근거 8중 0 |
| **요약문 / 두 칸 빈칸**<br>`R-SUMMARY` `R-BLANK2` `X-BLANK2` | (A)·(B)를 **각각 다른 근거 문장**으로 짚고, **어느 칸이 판별 칸인지** 적는다. 정답표 있는 문항 **전부**에 「한 칸만 정답과 같은」 오답이 있어, 한 칸 근거로 고르면 2지선다가 남는다 | 8/8 |
| **빈칸 / 대의 파악**<br>`R-BLANK` `X-BLANK` `R-GIST` `R-TOPIC` `R-TITLE` `R-CLAIM` `R-IMPLY` | 「넣으면 말이 된다」·「주제를 잘 나타낸다」는 근거가 아니다. 빈칸 문장 자신의 **구조 표지**가 근거의 방향과 거리를 지정하고, 근거가 세 문장 이상 떨어진 경우가 흔하다. **정답 선지는 지문 낱말을 안 쓰고 오답이 쓴다** — 그래서 근거는 낱말 일치가 아니라 **역할 일치**로만 선다. 한 문장으로 안 끝나는 것이 보통이다 | 대의파악 7/7이 두 문장 이상 |
| **도표**<br>`R-CHART` | ⚠️ **수치는 그림 안에 있어 텍스트에 없다.** 없는 수치를 지어내지 마라(실제로 두 번 났던 사고다). 확인 가능한 것은 선지 문장 안의 수치·비교 표현뿐이니, **선지끼리 대조해** 서로 함의·충돌하는 쌍을 찾아 좁히고 **그림을 봐야만 정해지는 부분은 거기까지만 적고 멈춘다** | 한 선지가 다른 선지의 절을 함의하는 구조가 반복 |
| **심경**<br>`R-MOOD` | **감정어와 신체 반응 묘사**를 인용하고 그것이 선지의 **앞뒤 심경 중 어느 쪽**에 붙는지 짚는다. 변화형은 **전환점 문장**을 따로 대야 두 칸이 다 확정된다 — 뒤 칸만 대면 앞 칸이 뜬다 | 한 청크 8건 전부가 그 반쪽 결함이었다 |

> **표에 없는 것을 지어내지 마라.** 여기 수치는 전수 판정에서 실제로 센 것이다.
> 새 유형을 맡았는데 이 표에 없으면, 관찰한 것을 `type_report.open_questions` 에
> **분모와 함께** 적어라 — 다음 사람이 그것을 이 표에 올릴지 판단한다.

### 정답표 없는 문항에서 `analyst` 는 무엇을 보나

`answer_unknown: true` 문항에는 선지 판정이 없으므로 `analyst` 가 잴 것이 없어 보인다.
실제로 그런 일이 있었다 — 정답표 없는 5문항에서 반려가 한 건도 안 나왔고, 그건 검수가
아니라 도장이다. **그 경우 `analyst` 는 이것을 대신 잰다:**

1. `answer_locus` 와 `choices` 가 **정말로 비어 있는가** — 추정 정답이 스며들지 않았는지
2. `difficulty.predicted` 가 무엇을 근거로 나왔는가 — 정답을 모르는데 정답률을 예측했다면 근거를 요구한다
3. `required_vocab` 의 낱말이 **지문에 실제로 있는가** (문자열 대조)
4. `measured_ability` 가 선지를 전제하지 않는가 — "①을 배제하려면" 같은 서술이 남아 있으면 반려

`checked` 에 이 넷 중 무엇을 했는지 적는다.

```jsonc
"reviews": [
  {
    "persona": "setter",
    "verdict": "pass" | "revise" | "fail",
    "findings": ["지적사항. pass 여도 관찰이 있으면 적는다"],
    "checked": ["quote 를 지문에서 문자열 대조", "유형 정의 대조"]   // 무엇을 실제로 했는지
  },
  { "persona": "analyst", "verdict": "pass", "findings": [], "checked": [...] },
  { "persona": "tutor",   "verdict": "pass", "findings": [], "checked": [...] }
]
```

**검수는 형식이 아니다.** `revise`/`fail` 이 나오면 **분석을 고쳐서 다시 검수**하고,
고친 흔적을 `"revised": true` 와 함께 남긴다. 세 페르소나가 전부 pass 인 것만 export 가 완료로 센다 —
검수만 붙이고 pass 를 찍으면 통계가 거짓이 되고, 그건 학습자에게 그대로 간다.

> 실제로 반려가 0건이면 그것 자체가 신호다. 세 자가 같은 것을 재고 있다는 뜻이므로,
> 그때는 자를 고쳐야 한다(§3 에 기록).

## 3. 유형별 분석 결과 — 청크 하나가 끝날 때

`chunk-NN.out.json` 에 `type_report` 를 함께 넣는다. 문항 단위 분석을 유형 단위로 접은 것이다.

```jsonc
"type_report": {
  "type_id": "R-BLANK",
  "n_analyzed": 12,
  "recurring_traps": [ { "trap": "범위 과대", "count": 7, "signature": "선지가 지문의 한정어를 떨어뜨린다" } ],
  "answer_locus_pattern": "12개 중 9개가 빈칸 **다음** 문장에 근거를 둔다",
  "procedure": [ /* 이 유형 전체에 통하는 절차. 문항별 절차의 공통분모 */ ],
  "failure_modes": ["학습자가 실제로 어디서 미끄러지는지"],
  "time_budget_sec": 100,
  "open_questions": ["표본이 모자라 말할 수 없는 것 — 다음 청크로 넘긴다"]
}
```

## 4. 재실행 안전

- export 는 `.out.json` 에서 **3 페르소나 pass** 가 확인된 `item_id` 만 완료로 센다
- 분석만 있고 검수가 비면 **미완**으로 세어 다시 나온다
- export 는 매번 옛 `chunk-*.json` 을 지우고 새로 뽑는다 (남은 몫이 줄었는데 옛 청크가 남으면 두 번 일한다)
- `.out.json` 은 지우지 않는다 — 그게 원장이다
