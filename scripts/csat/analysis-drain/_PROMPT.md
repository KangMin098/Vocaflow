# 기출 문항 분석 드레인 — 작업 명세

> 이 파일은 청크와 함께 **남는다**(`.gitignore` 가 청크만 지운다). 절차를 잊고 다시 정하는 일을 막는다.
> 대상: 평가원 수능·모의평가 **독해·장문(듣기 제외)** 830문항. 사정권 유형 26.

---

## 0. 이 분석이 무엇을 위한 것인가

목표는 **학습자가 이 분석을 읽고 그 유형에서 실점하지 않는 것**이다.
총점 100 = 듣기 37 + 독해 63이고 배점 단위가 2·3점이므로, **99점 이상 = 독해 실점 0** 이다.
곧 "대체로 맞힌다" 는 목표 미달이다. **한 문항도 놓치지 않는 절차**를 쓴다.

그래서 금지되는 서술이 있다:

| 금지 | 왜 |
|---|---|
| "글의 흐름을 파악하면 답이 보인다" | 순환논법. 파악하는 방법이 절차다 |
| "선지 ③은 지문과 다르다" | 어디가 왜 다른지 없으면 검증 불가 |
| "어휘력이 필요하다" | 어떤 낱말인지 적어야 처방이 된다 |
| 정답을 이미 안다는 전제의 서술 | 학습자는 정답을 모르는 상태에서 읽는다 |

## 1. 할 일

`chunk-NN.json` 을 읽고 **같은 폴더에 `chunk-NN.out.json`** 을 쓴다.

```jsonc
{
  "chunk": 1,
  "type_id": "R-BLANK",
  "analyses": [ /* 청크의 items 수만큼. 순서 무관, item_id 로 짝짓는다 */ ]
}
```

### analyses[] 한 개의 모양

```jsonc
{
  "item_id": "2026#31",

  // ── ① 출제자 층위 ────────────────────────────────────────────
  "measured_ability": "빈칸 앞 문장의 일반화를 뒤 예시가 어떻게 좁히는지 읽어 내는 능력",
  "design_intent": "출제자가 이 문항으로 무엇을 가르려 했는지 한두 문장. 유형 일반론이 아니라 이 문항 고유의 것",
  "answer_locus": {
    "sentence_index": [3, 7],        // 지문 문장 번호 1-base. 지문이 없으면 raw_block 기준 근사
    "quote": "지문에서 그대로 따온 정답 근거 (20~120자)",
    "reasoning": "그 문장이 왜 정답을 확정하는지. '주제이므로' 같은 되풀이 금지"
  },

  // ── ② 오답 층위 — 선지 5개 전부 ──────────────────────────────
  "choices": [
    {
      "n": 1,
      "verdict": "correct" | "distractor",
      "trap": "<유형군에 맞는 라벨 — 아래 두 표 중 하나에서 고른다>",
      // 라벨표는 §1-b 에 있다. **유형군에 따라 다른 표를 쓴다.**
      "why_tempting": "이 선지가 왜 골라지는지 — 지문의 어느 표현을 어떻게 오독하면 여기 닿는지",
      "how_to_reject": "지문의 어느 자리를 보면 배제되는지. 근거 위치를 반드시 적는다"
    }
    // … 5개
  ],

  // ── ③ 학습자 층위 ────────────────────────────────────────────
  "solve_procedure": [
    { "step": "발문에서 빈칸이 문단 어디에 있는지 먼저 본다", "on_fail": "위치를 못 정하면 역접 표지를 찾는다" }
    // 3~6단계. 각 단계는 **지문을 아직 안 읽은 학습자**가 실행할 수 있어야 한다
  ],
  "time_budget_sec": 100,            // 이 문항에 쓸 수 있는 시간. 독해 63점 70분 기준으로 배분
  "difficulty": {
    "predicted": 0.62,               // 예상 정답률 0~1
    "drivers": ["추상 명사 다수", "빈칸이 마지막 문장"]
  },
  "required_vocab": ["arbitrary", "convention"],   // 이 문항 정답에 실제로 필요한 낱말만. 지문 전체 어휘 나열 금지

  // ── ④ 3인 검수 ───────────────────────────────────────────────
  "reviews": [ /* §2 */ ]
}
```

**정답을 모르는 문항**(`answer_known: false` — 모평 7회차는 평가원 정답표가 없다):
`answer_locus` 와 `choices[].verdict` 를 **쓰지 않는다**. 대신 `"answer_unknown": true` 를 넣고
`measured_ability` · `solve_procedure` · `difficulty` · `required_vocab` 만 채운다.
**추정한 정답을 정답인 척 적지 않는다.** 그 한 줄이 학습자를 반대로 훈련시킨다.

**`body_ok: false` 문항**: 지문·선지를 못 떴거나 미덥지 않다. `raw_block` 에 **문항 블록 + 회차
원문 창**이 함께 들어 있다. 단이 안 갈린 페이지에서는 블록 자체가 두 단이 낱말 단위로 섞인
뭉갬이므로(`sunk cost ______ This makes sense from the perspective of information fallacy`)
**원문 창에서 좌우를 갈라 읽는다.** 복원했으면 `"body_recovered": true` 를 넣는다.

**`same_item_as` 가 붙은 문항**: 2014학년도는 수준별(A/B형) 시행이라 두 문제지가 일부 문항을
공유한다 — 지문·선지·정답이 문자열까지 같고 번호만 다르다(실측 2쌍: `2014A#24 ≡ 2014B#23` ·
`2014A#32 ≡ 2014B#29`). **분석은 양쪽 다 쓴다**(각각 그 회차의 문항이므로 원장에 있어야 한다).
다만 `type_report.n_analyzed` 와 `recurring_traps[].count` 에서는 **한 번만 센다** —
두 번 세면 "이 유형 n문항" 이라는 신뢰의 근거가 그만큼 부푼다. 몇을 빼고 셌는지 리포트에 적어라.

**⚠️ 청크와 코퍼스가 다르면 코퍼스가 정본이다.** 청크는 뽑힌 시점의 코퍼스를 담는데
(`corpus_built_at` 참조), 그 사이 파서가 고쳐지면 청크가 낡는다. **인용은 반드시
`scripts/csat/data/corpus.json` 의 현재 지문에서 뽑아라** — 게이트가 그것을 건초더미로 쓴다.
청크 본문에서 뽑으면 멀쩡한 인용이 "지어냈다" 로 걸린다(실측으로 겪었다).

## 2. 3인 검수 — 서로 다른 전문가 입장

**한 사람이 세 번 보는 것이 아니다.** 세 입장은 서로의 맹점을 덮도록 고른 것이고,
같은 분석을 셋이 다른 자로 잰다. **셋 다 `pass` 여야 published** 다.

| persona | 누구의 눈 | 무엇을 보나 | 반려(fail/revise) 사유 |
|---|---|---|---|
| `setter` | 출제자 (평가원 출제위원) | 서술한 출제 의도가 이 유형의 실제 설계와 맞나. `answer_locus.quote` 가 **지문에 실제로 있나**. 유형 정의를 벗어난 서술이 없나 | 인용이 지문에 없다 · 유형과 어긋난다 · 의도가 유형 일반론뿐이다 |
| `analyst` | 오답 분석가 (채점·문항반응 통계) | 오답 4개의 `trap` 이 **서로 다른가**. `why_tempting` 이 선지 텍스트에 실제로 근거하나. `how_to_reject` 에 지문 위치가 있나 | 함정 라벨 중복 · 선지 텍스트와 무관한 서술 · 배제 근거에 위치가 없다 |
| `tutor` | 현장 강사 (학습자 대리) | `solve_procedure` 를 **지문을 아직 안 본 학생**이 실행할 수 있나. 순환논법이 없나. `time_budget_sec` 안에 끝나나. `required_vocab` 이 실제로 정답에 필요한 것인가 | 실행 불가 · 순환논법 · 시간 초과 · 어휘 나열 |

## 1-b. 함정 라벨표 — **유형군에 따라 다른 표를 쓴다**

한 표로는 안 된다. 선지가 **문장**인 유형과 **위치·순열 기호**인 유형은 함정이 걸리는 층이 다르다.
서로 다른 청크 **넷**이 독립적으로 "명제형 라벨 9종이 이 유형 오답에 한 건도 안 맞는다" 고
보고했고(R-ORDER 48개 중 0 · R-INSERT 48개 중 0), 억지로 붙이면 라벨이 정보를 잃는다.

### (A) 명제형 — 선지가 문장·구인 유형

`R-BLANK` `R-SUMMARY` `R-TITLE` `R-TOPIC` `R-GIST` `R-CLAIM` `R-PURPOSE` `R-MOOD` `R-IMPLY`
`R-NOTICE` `R-FACT` `X-TITLE` `X-FACT` `X-BLANK*`

`범위 과대` · `범위 과소` · `인과 역전` · `주체 역전` · `부분 사실` · `어휘 함정` ·
`지문 밖 상식` · `반대 진술` · `무관`

> `주체 역전` 은 나중에 더했다 — 청크 셋이 "이 라벨이 없어 인과 역전으로 대신 달았다" 고
> 보고했다. 행위는 지문과 같은데 **하는 사람이 바뀐** 함정이다.

### (B) 위치형 — 선지가 기호(①~⑤ 위치 · (A)(B)(C) 순열)인 유형

`R-INSERT` `R-ORDER` `R-IRRELEVANT` `X-ORDER`

`첫 등장 위반`(부정관사→정관사 · 익명→지명이 뒤집힘) · `지시어 선행사 절단` ·
`지시어 선행사 앞당김` · `연결사 방향 충돌` · `열거·병렬 절단` · `총론-각론 역전` ·
`조건-귀결 절단` · `시간·인과 순서 역전` · `어휘 반복 유인`(겹치는 낱말이 단서가 아니라 미끼) ·
`마무리 문장 위치 오판`

> **어휘 반복 유인은 이 유형군의 최대 함정이다.** 옛 회차 8문항 전수에서 주어진 문장과
> 낱말이 가장 많이 겹치는 자리가 예외 없이 오답이었다. 겹치는 낱말의 **기능**(수단인가
> 특징인가)이 다르면 근거가 아니다.

### (C) 어법·어휘 밑줄형

`R-GRAMMAR` `R-VOCAB` `X-VOCAB` `R-REFER` `X-REFER` — 위 둘 중 가까운 쪽을 쓰되,
맞는 라벨이 없으면 **새로 쓰고 `open_questions` 에 등재를 제안한다.** 억지로 붙이지 마라.

---

### 정답표 없는 문항에서 `analyst` 는 무엇을 보나

`answer_unknown: true` 문항에는 선지 판정이 없으므로 `analyst` 가 잴 것이 없어 보인다.
실제로 그런 일이 있었다 — 정답표 없는 5문항에서 반려가 한 건도 안 나왔고, 그건 검수가
아니라 도장이다. **그 경우 `analyst` 는 이것을 대신 잰다:**

1. `answer_locus` 와 `choices` 가 **정말로 비어 있는가** — 추정 정답이 스며들지 않았는지
2. `difficulty.predicted` 가 무엇을 근거로 나왔는가 — 정답을 모르는데 정답률을 예측했다면 근거를 요구한다
3. `required_vocab` 의 낱말이 **지문에 실제로 있는가** (문자열 대조)
4. `measured_ability` 가 선지를 전제하지 않는가 — "①을 배제하려면" 같은 서술이 남아 있으면 반려

`checked` 에 이 넷 중 무엇을 했는지 적는다.

```jsonc
"reviews": [
  {
    "persona": "setter",
    "verdict": "pass" | "revise" | "fail",
    "findings": ["지적사항. pass 여도 관찰이 있으면 적는다"],
    "checked": ["quote 를 지문에서 문자열 대조", "유형 정의 대조"]   // 무엇을 실제로 했는지
  },
  { "persona": "analyst", "verdict": "pass", "findings": [], "checked": [...] },
  { "persona": "tutor",   "verdict": "pass", "findings": [], "checked": [...] }
]
```

**검수는 형식이 아니다.** `revise`/`fail` 이 나오면 **분석을 고쳐서 다시 검수**하고,
고친 흔적을 `"revised": true` 와 함께 남긴다. 세 페르소나가 전부 pass 인 것만 export 가 완료로 센다 —
검수만 붙이고 pass 를 찍으면 통계가 거짓이 되고, 그건 학습자에게 그대로 간다.

> 실제로 반려가 0건이면 그것 자체가 신호다. 세 자가 같은 것을 재고 있다는 뜻이므로,
> 그때는 자를 고쳐야 한다(§3 에 기록).

## 3. 유형별 분석 결과 — 청크 하나가 끝날 때

`chunk-NN.out.json` 에 `type_report` 를 함께 넣는다. 문항 단위 분석을 유형 단위로 접은 것이다.

```jsonc
"type_report": {
  "type_id": "R-BLANK",
  "n_analyzed": 12,
  "recurring_traps": [ { "trap": "범위 과대", "count": 7, "signature": "선지가 지문의 한정어를 떨어뜨린다" } ],
  "answer_locus_pattern": "12개 중 9개가 빈칸 **다음** 문장에 근거를 둔다",
  "procedure": [ /* 이 유형 전체에 통하는 절차. 문항별 절차의 공통분모 */ ],
  "failure_modes": ["학습자가 실제로 어디서 미끄러지는지"],
  "time_budget_sec": 100,
  "open_questions": ["표본이 모자라 말할 수 없는 것 — 다음 청크로 넘긴다"]
}
```

## 4. 재실행 안전

- export 는 `.out.json` 에서 **3 페르소나 pass** 가 확인된 `item_id` 만 완료로 센다
- 분석만 있고 검수가 비면 **미완**으로 세어 다시 나온다
- export 는 매번 옛 `chunk-*.json` 을 지우고 새로 뽑는다 (남은 몫이 줄었는데 옛 청크가 남으면 두 번 일한다)
- `.out.json` 은 지우지 않는다 — 그게 원장이다
