# 근거 서술 재작성 — 명세

`chunk-<TYPE>.json` 하나를 읽고 `chunk-<TYPE>.out.json` 을 쓴다.

## 왜 하는가

유형 리포트의 「정답 근거가 어디 있나」(`answer_locus_pattern`)는 드레인 청크마다 **덧붙어**
쌓였다. 그래서 분석자끼리 하는 말이 그대로 남아 있고, **그 글이 학습자 화면 `/csat/<유형>` 에
그대로 나간다.** 학습자에게 「청크」는 아무 뜻이 없고, 자기가 읽는 것이 완성된 설명인지 작업
메모인지 구별할 방법도 없다.

## 무엇을 쓰는가

같은 사실을, **학습자에게 하는 말로** 다시 쓴다. 요약이 아니라 재작성이다 —
관찰이 사라지면 이 유형의 가치가 사라진다.

읽는 사람은 **그 유형을 이제 막 공부하려는 고등학생**이다. 그가 이 글을 읽고 다음 문제를 풀 때
**어디를 먼저 볼지 정할 수 있어야** 한다.

### 반드시 뺄 것 — 이것이 있으면 게이트가 막는다

| 표지 | 예 |
|---|---|
| 청크 | 「앞선 청크의 관찰 ①은 이 청크에서는 성립하지 않는다」 |
| 관찰 번호 | 「관찰 ①·③은 재확인된다」 |
| 날짜 갱신 표시 | 「── 2026-09-04 갱신:」 |
| 내부 필드명 | `confirmed_at` · `answer_locus.` · `_PROMPT` |
| 배치 지시 | 「이번 회차분」 · 「다음 배치에서 누적할 것」 |

### 반드시 남길 것

- **위치 규칙과 그 비율** — 「근거가 빈칸 뒤에 있는 것이 12중 4」 같은 수는 학습자가
  기대치를 세우는 근거다. 수를 지우면 「대체로」만 남아 쓸모가 없어진다.
- **표지어 목록** — `Thus` · `in other words` · `As a result` · `However` 처럼 근거 위치를
  가리키는 말. 이것이 이 유형의 실행 가능한 부분이다.
- **예외** — 통하지 않는 구간을 지우면 학습자가 규칙을 과신한다.
- **문항 id 인용** — 남겨도 되고 빼도 된다. 다만 **원본에 없는 id 를 새로 쓰면 안 된다**
  (게이트가 대조한다). 근거를 지어내는 순간 이 자료 전체를 못 믿게 된다.

### 어떻게 쓰는가

- 시간 순서(옛 회차 → 최근 회차)가 아니라 **학습자의 순서**로 — 먼저 어디를 보는가,
  그다음 무엇으로 확인하는가, 언제 그 규칙이 깨지는가.
- 한 문단이 한 가지만 말한다. 원본은 한 문단에 다섯 회차의 관찰이 겹쳐 있다.
- 겁을 먼저 주지 않는다(Empathetic Feedback) — 함정은 이 글이 아니라 다른 칸에서 말한다.
- 길이에 상한을 두지 않되, **원본보다 짧아지는 것이 정상이다** — 겹친 관찰이 접히기 때문이다.
  다만 200자 미만이면 게이트가 막는다(요약으로 뭉갠 것으로 본다).

## 출력 형식

```json
{
  "type_id": "R-BLANK",
  "answer_locus_pattern": "<재작성한 글>",
  "note": "<무엇을 접었고 무엇을 뺐는지 한 줄 — 사람이 나중에 대조할 때 쓴다>"
}
```

`context`(절차·함정·실패 모드)는 **고치지 않는다.** 이 드레인이 손대는 것은 근거 서술 하나뿐이다.

## 게이트가 보는 것

`node scripts/csat/locus-refold-import.mjs` (미리보기)가 다음을 막는다.

1. 작업 표지가 하나라도 남아 있으면 — 재작성의 목적 자체다
2. 200자 미만이면 — 요약으로 뭉갠 것
3. 원본에 없는 문항 id 가 새로 나오면 — 근거를 지어낸 것
4. 원본과 글자가 똑같으면 — 안 고친 것

통과해도 `--commit` 없이는 **아무것도 쓰지 않는다.**
