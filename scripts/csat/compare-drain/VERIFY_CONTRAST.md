# 「비슷해 보이지만 조건이 다른」 대조 쌍 — 독립 검수 지침

너는 이 쌍을 고르지 않은 독립 검수자다. 다른 에이전트가 병렬로 일한다 — 자기 출력 파일만 쓰고 DB · git · 다른 파일은 건드리지 않는다. 한국어로 쓴다.

입력 `chunk-ctr-<…>.json` 의 `pairs[]` 는 같은 유형 · 같은 함정 라벨(`trap`)인데, 앞선 검수에서 「같은 방식으로 바뀐 것은 아니다」로 떨어진 쌍이다(`first_reason`).
여기서 묻는 것은 반대다 — **겉(라벨 · 표현)은 같아 보이지만 판단을 가르는 조건이 달라서, 둘을 나란히 보면 학습자가 「언제 이 요령이 통하고 언제 안 통하는지」를 배울 수 있는가.**

## 판정
`contrast: true` 는 다음을 **모두** 만족할 때만:
1. 두 오답의 분석(`why_tempting` · `how_to_reject`)이 둘 다 내용이 있고, 실제로 **다른 조건**(바뀐 성분 · 비교 기준 · 연결 방향 · 범위의 종류 등)에서 배제된다.
2. 그 차이를 한 줄로 말할 수 있고, 학습자가 그 한 줄로 다음 문항에서 행동을 바꿀 수 있다.
3. 한쪽 분석이 부실하거나 둘이 그냥 무관하면 false. 애매하면 false.

`note`(true 일 때만, 80자 이하 · 원문 인용 금지 · 문항/선지 번호 쓰지 않음): 「둘 다 ~로 보이지만, 한쪽은 ~ / 다른 쪽은 ~라서 판단이 갈린다」 꼴.
`reason`(false 일 때, 40자 이하).

## 출력
`chunk-ctr-<…>.out.json`: {"chunk":"…","verdicts":[{"pair_id":"…","contrast":true,"note":"…"},{"pair_id":"…","contrast":false,"reason":"…"}]} — 모든 pair_id.
