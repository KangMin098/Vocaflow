# 같은 원리 비교 쌍 — 독립 검수 지침

너는 비교 쌍을 고르지 않은 독립 검수자다. 다른 에이전트가 병렬로 일한다 — 자기 출력 파일만 쓰고 DB · git · 다른 파일은 건드리지 않는다. 한국어로 쓴다.

입력 `chunk-<이름>.json` 의 `pairs[]`: 같은 유형 · 다른 회차의 두 오답(`a`, `b`)이 같은 함정 라벨(`trap`)을 달고 있다는 **자동 후보**다.
각 오답에는 검수된 분석의 `why_tempting`(끌리는 이유) · `how_to_reject`(지우는 근거)가 있다. 지문 · 선지 원문은 없다 — 분석만으로 판정한다.

## 판정
`same_principle: true` 는 다음을 **모두** 만족할 때만:
1. 두 오답이 **같은 방식**으로 지문에서 벗어났다 — 라벨 이름이 같은 것으로는 부족하다. 바뀐 성분(주체 · 범위 · 방향 · 인과 · 위치 연결 등)이 실제로 같은 종류인지 두 분석에서 확인한다.
2. 학습자가 한 문항에서 배운 확인 행동을 다른 문항에 **그대로** 옮겨 쓸 수 있다.
3. 둘 중 한쪽 분석이 비었거나 라벨과 내용이 어긋나면 false.

애매하면 false. 수를 채우려고 true 를 주지 않는다.

`note`(true 일 때만, 80자 이하 · 원문 인용 금지): 학습자에게 보일 한 줄 — 「무엇이 같은 방식으로 바뀌었고, 소재 · 조건은 무엇이 다른가」. 문항 번호 · 선지 번호를 쓰지 않는다(화면이 붙인다).
`reason`(false 일 때, 40자 이하): 왜 같은 원리가 아닌가.

## 출력
`chunk-<이름>.out.json`:
{"chunk":"<이름>","verdicts":[{"pair_id":"…","same_principle":true,"note":"…"},{"pair_id":"…","same_principle":false,"reason":"…"}]}
입력의 모든 pair_id 를 빠짐없이 넣는다.
