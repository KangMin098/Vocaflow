# T11 — 아포스트로피 표제어의 예문 되쓰기

T10 배치가 예문에 아포스트로피를 금지했다. TTS·따옴표 처리를 위한 규칙이었는데,
**표제어 자체가 아포스트로피를 품고 있으면 빼는 순간 틀린 철자를 가르치게 된다.**

- `hobson's choice` → `"Hobsons choice"` ← 이런 예문이 지금 DB 에 들어 있다
- `o'clock` (A1/v1) → 아예 예문을 못 쓰고 비어 있었다
- `ne'er-do-well` · `devil's advocate` · `adam's apple` · `mother's day` … 103건

에이전트가 이 모순을 지적해 게이트를 고쳤다. 이제 **표제어에 아포스트로피가 있으면 예문에도 허용**된다.
이 배치는 그렇게 잘못 쓰인 103건을 되쓰는 것이다.

## 할 일
`chunk-00.json` 의 각 항목에 대해 **아포스트로피를 살린 예문**을 새로 쓴다.
`example_en` 필드에 지금 들어 있는 값이 문제의 예문이다 — 참고만 하고, 자연스러우면 아포스트로피만
되살려도 되고 문장을 새로 써도 된다.

### 규칙
1. **표제어를 정식 철자 그대로** 문장에 넣을 것 — 아포스트로피 포함. ASCII `'` 를 쓸 것(곡선 `’` 금지).
   표제어에 `somebody`·`something` 자리표시자가 있으면 실제 명사로 바꿔 쓰되, **아포스트로피가 붙은
   부분은 그대로** 유지한다 (`on somebody's coat-tails` → `on his mentor's coat-tails`).
2. 대문자로 시작하고 `.` `!` `?` 로 끝날 것.
3. 20~160자.
4. `meaning_ko` 가 가리키는 그 뜻을 보여줄 것.
5. 난이도를 `cefr`/`v` 에 맞출 것. 예문의 다른 단어는 표제어보다 쉽게.
6. 폭력·성·마약·차별 소재 금지. 정의문이 아니라 용례.
7. **아포스트로피는 표제어에서 온 것만.** `don't`·`it's` 같은 축약은 여전히 쓰지 말 것
   (`do not`·`it is` 로). 소유격도 표제어에 있는 것 외에는 만들지 말 것.

`skip: true` 는 표제어가 학습자 카드에 부적절할 때만.

## 출력
`chunk-00.out.json` — 입력과 **같은 순서·같은 개수**:
```json
{ "word": "<입력 word 그대로>", "example_en": "…", "note": "(선택)" }
```

검증: JSON 파싱 · 개수·순서 일치 · **모든 예문에 ASCII `'` 가 최소 1개** · 곡선 `’` 0개 ·
표제어의 아포스트로피 붙은 토큰이 예문에 그대로 등장 · 규칙 2·3 충족.
Bash/node 로 직접 세어 확인할 것. DB·git·입력 파일은 건드리지 말 것.
