# T13 — T6 가 진단한 뜻 결함 잔여 425건 처리

T6(예문 정합성) 배치가 예문을 고치면서 **뜻 쪽 결함 968건**을 보고만 하고 남겼다.
T7 이 543건을 처리했고, 이 배치가 **나머지 425건**을 맡는다. 각 항목의 `issue` 가 T6 의 진단이다.

## ⚠️ 이 배치의 성격 — 더하는 배치이지 바꾸는 배치가 아니다

**기존 `meanings_ko` 의 모든 뜻 문자열은 그대로 남아야 한다.** 하나라도 사라지면 apply 가
그 항목 전체를 거부한다. 맞는 뜻을 덮어쓰는 것이 이 배치의 최대 위험이다.
틀린 뜻이 섞여 있으면 **지우지 말고**, 맞는 뜻을 앞으로 올리고 틀린 쪽에 반증을 괄호로 덧붙여라.

## 결함 갈래와 처리법

| `issue` 가 말하는 것 | 어떻게 고치나 |
|---|---|
| **`pos` 가 대표 sense 와 어긋남** (`lead` pos=noun 인데 뜻은 "이끌다"부터) | `meanings_ko` 순서를 실제 대표 뜻이 먼저 오게 바꾸고, **`pos` 필드를 그 품사로** 보낸다 |
| **sense 누락** (예문이 쓰는 뜻이 `meanings_ko` 에 없음) | 새 sense 를 **추가**한다. 기존 것은 전부 유지 |
| **대표 뜻 선택이 어긋남** (`branch` 가 "지점"인데 아동 도서에선 "나뭇가지") | 순서만 바꾼다 |
| **사용역 문제** (`want` 의 "부족하다"가 고어인데 같은 줄에) | 해당 sense 에 `(고어)`·`(문어)` 표시를 붙이고 뒤로 보낸다 |
| **뜻이 틀림** | 맞는 뜻을 0번으로, 틀린 뜻은 **원문 보존 + 반증 주석 + 강등** |

## 출력 형식

입력과 **같은 순서·같은 개수**의 배열:
```json
{
  "word": "<입력 word 그대로>",
  "meaning_ko": "카드 앞면용 짧은 글 — 3구획·90자 이내",
  "meanings_ko": [ { "pos": "verb", "meaning": "…", "v_level": 6 }, … ],
  "pos": "verb"
}
```

- `meanings_ko` 의 각 원소: `pos`(noun/verb/adjective/adverb/interjection/preposition/conjunction/pronoun/determiner) ·
  `meaning`(한국어) · `v_level`(0~11 정수). **입력의 기존 sense 문자열을 그대로 복사해 넣을 것** —
  글자 하나라도 다르면 "소실"로 판정된다. 새 sense 만 새로 쓴다.
- **`meaning_ko` 는 `meanings_ko[0]` 의 핵심어로 시작해야 한다.** 설명부(`—` 뒤)는 넣지 말 것 —
  카드 앞면은 짧아야 한다(Calm UI·인지 부하). 전체 정의는 `meanings_ko` 가 보관한다.
- `pos` 는 **선택**이다. `pos` 결함을 고칠 때만 보내고, **반드시 `meanings_ko` 안에 실제로 있는 품사**여야 한다.
  없는 품사를 보내면 apply 가 무시한다.
- 손댈 필요가 없으면 `{ "word": "...", "skip": true }`.

## 검증 (작성 후 직접 돌릴 것)
JSON 파싱 OK · 입력과 단어 수·순서 일치 · **입력 `meanings_ko` 의 모든 `meaning` 문자열이 출력에 그대로 존재** ·
`meaning_ko` 가 `meanings_ko[0]` 의 핵심어로 시작 · `pos` 를 보낸 항목은 그 품사가 `meanings_ko` 에 존재 ·
모든 `v_level` 이 0~11 정수. Bash/node 로 세어 확인하라.

**청크 하나를 끝낼 때마다 즉시 그 `.out.json` 을 쓸 것.**
DB·git·입력 파일은 건드리지 마라.
