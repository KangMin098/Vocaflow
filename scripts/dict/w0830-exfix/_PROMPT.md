# D0830-T6-3 — 예문 교체

`example_en` 을 덮는 **유일한 배치**다. 앞 배치들이 낱말을 읽으며 "이 예문은 못 쓴다" 고
짚어 둔 것을 받는다.

## 무엇이 문제인가

| 갈래 | 실례 |
|---|---|
| **문장이 아님** | `a great deed` · `public library public park` · `straight, no chaser` · `an amorous disposition` |
| **비문·오타** | `I am visiting my mother any moment.` · `the sale of company` · `brush your tooth` |
| **뜻과 어긋남** | 표제어의 등재된 뜻이 아니라 **다른 뜻**을 보여 준다 |
| **난이도 역전** | 예문 속 낱말이 표제어보다 어렵다 — 예문이 아니라 새 문제가 된다 |

WordNet 용례를 그대로 들여온 자리다. 학습자에게 보여 줄 문장이 아니다.

`why` 에 이 낱말이 뽑힌 이유가 적혀 있다. 기계가 잡은 것(`끝맺음 부호가 없다` 등)과
사람이 읽고 짚은 것(`노트에서 예문 문제로 짚힘`)이 섞여 있으니 **직접 보고 판단하라.**

## 할 일

고쳐야 할 자리마다 **새 예문과 그 한국어 해석**을 낸다.

- **뜻 단위**(`senses[].example`)를 고치려면 `senses` 에 `idx` 와 함께 낸다.
- **최상위**(`example_en`)를 고치려면 `example_en` 과 `example_en_ko` 를 낸다.

⚠️ **둘이 같은 문장인 경우가 많다** — 앞 배치가 `example_en` 을 뜻 0번으로 복사해 뒀다.
그때는 **한쪽만 내면 된다.** apply 가 같은 문자열을 들고 있는 나머지 자리를 함께 바꾼다.
(해석 없이 남는 자리가 생기면 그 낱말을 통째로 거부하므로, **해석은 반드시 함께 낸다.**)

## 예문 규칙 — 어기면 apply 게이트가 거부한다

1. **표제어(굴절형 허용)가 반드시 들어갈 것.**
2. **4~22낱말.** 6~14 가 좋다. **한 문장.** 문장부호로 끝낸다.
3. **영문만** — 한글·한자·이모지 금지 (accent 는 허용).
4. **그 뜻으로만 읽혀야 한다.** 여러 뜻이 있는 낱말이면 그 갈래의 뜻이 드러나는 문맥을 심어라.
5. **수준을 맞춰라.** `v_level` 1~3 은 중학 수준, 4~6 은 고교, 7 이상은 학술/시험.
   **예문 속 다른 낱말이 표제어보다 어려우면 예문이 아니라 새 문제다.**
6. **자연스러운 실제 영어.** 사전 문장 흉내(`This is a bank.`)나 억지 구문 금지.
7. 고유명사는 되도록 피하고, 쓰면 흔한 이름(`Mina`, `Tom`)으로.

## 해석 규칙

1. **자연스러운 한국어.** 직역해서 어색하면 실패다. 한국어 어순으로 옮긴다.
2. 그 뜻이 해석에 드러나야 한다.
3. 설명문은 평서형(`~다`), 대화체는 대화체로.

## 고칠 필요가 없으면 내지 마라

`why` 가 붙었어도 **실제로 멀쩡하면** 그 자리는 비워 둔다. 다만 낱말 한 줄은 **반드시 낸다**
(`{"word": "...", "note": "예문이 실제로는 멀쩡하다 — 기계 신호 오탐"}`).
빠뜨리면 다음 배치가 영원히 다시 묻는다.

**억지 교체가 그대로 두는 것보다 나쁠 수 있다** — 지금 예문이 짧아도 옳은 문장이면 놔둬라.

## `note` — 부수 발견

`meaning_ko` 오류 · 표제어 오철자 · 갈래 문제 등. 고치지 말고 적기만 하라.

## 출력

`chunk-NN.json` 옆에 `chunk-NN.out.json`. 배열 하나. JSON 만.
**입력의 모든 낱말에 한 줄씩.**

```json
[
  {
    "word": "deed",
    "example_en": "She was honored for her brave deed during the fire.",
    "example_en_ko": "그녀는 화재 때 보인 용감한 행위로 표창을 받았다.",
    "senses": [
      { "idx": 0, "example": "She was honored for her brave deed during the fire.",
        "example_ko": "그녀는 화재 때 보인 용감한 행위로 표창을 받았다." }
    ],
    "note": "기존 예문 `a great deed` 는 문장이 아니었다"
  },
  {
    "word": "chaser",
    "senses": [
      { "idx": 0, "example": "He ordered a whiskey with a beer chaser.",
        "example_ko": "그는 위스키에 맥주를 체이서로 곁들여 주문했다." }
    ]
  },
  { "word": "amorous", "note": "예문이 실제로는 멀쩡하다 — 기계 신호 오탐" }
]
```

- `senses[].idx` 는 입력의 `idx` 를 **그대로** 쓴다.
- 고치지 않는 자리는 아예 넣지 마라 (빈 문자열 금지).
- 입력에 없는 낱말을 추가하지 마라. 앞뒤 설명 문장 금지.
