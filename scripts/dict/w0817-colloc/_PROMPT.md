# T14 — `collocations` 채우기

연어(collocation)는 **"이 낱말이 실제로 어떤 낱말과 붙어 다니는가"** 다.
뜻과 예문을 알아도 `make a decision`(o) / `do a decision`(x) 를 구분하지 못하면 **산출이 안 된다.**
T9·T12 학습자 노트 배치에서 가장 자주 나온 오류 갈래가 바로 이 연어 제약이었다.

담당 청크의 항목들은 `collocations` 가 비어 있다. 빈도 상위부터 정렬돼 있다.

## 할 일
각 항목의 `meaning_ko` · `pos` · `pos_set` · `example_en` · `synonyms` · `cefr` · `v` 를 근거로
**그 낱말이 실제로 쓰이는 짝 2~4개**를 쓴다.

### 무엇을 고르나
- **원어민 코퍼스에서 실제로 빈번한 짝**만. 문법적으로 가능하다고 다 쓰지 마라.
- `meaning_ko` 가 가리키는 **그 뜻**의 연어여야 한다. 다의어면 대표 뜻 쪽으로.
- 품사별 전형 패턴을 노려라:
  · 명사 → `형용사 + 명사`(`high risk`) · `동사 + 명사`(`take a risk`) · `명사 + 명사`(`risk factor`)
  · 동사 → `동사 + 목적어`(`devolve power`) · `동사 + 전치사`(`devolve upon someone`)
  · 형용사 → `형용사 + 명사`(`arrogant attitude`) · `연결동사 + 형용사`(`sound arrogant`)
  · 부사 → `동사 + 부사`(`remark drily`)
  · 구동사 → 실제 목적어와 함께(`lay up supplies`)
- **한국인이 틀리는 짝을 우선**하라. `make/do`·`take/have`·전치사 고정처럼 직역하면 깨지는 것.

### 형식 규칙 — 전부 필수. 어기면 apply 게이트가 거부한다
1. **2~4개** (최대 5). 억지로 늘리지 마라 — 셋이면 셋만.
2. 각 항목은 **2~5낱말**. 한 낱말은 연어가 아니고, 긴 문장도 아니다.
3. **표제어(굴절형 허용)가 반드시 들어갈 것.** `risk` → `take a risk`(o) / `dangerous`(x)
4. **ASCII 영문·공백·하이픈·아포스트로피만.** 곡선 따옴표 `’` 금지, 숫자·괄호·쉼표 금지.
5. 표제어 그 자체(`risk`)만 덜렁 쓰지 마라.
6. 소문자로. 고유명사가 포함될 때만 대문자(드물다).
7. 관사·소유격은 실제 쓰임대로. `take a risk`(관사 있음) · `high risk`(없음) — 임의로 붙이거나 빼지 마라.

### skip
그 낱말에 **고정된 짝이 실제로 없으면** `"skip": true`. 학명·순수 전문용어·고유명사·
기능어가 여기 해당한다. **억지 연어가 빈칸보다 나쁘다** — 학습자가 그걸 외워서 쓴다.

### 부수 발견 — `note` 에
`meaning_ko` 오류·잘림 · `pos` 오기 · 표제어가 영어 낱말이 아님 · 오철자 · 중복 등재 ·
난이도(cefr↔v) 불일치. 자동 수정하지 않고 사람 검토 목록으로 모은다.

## 출력
입력과 **같은 순서·같은 개수**의 배열:
```json
{ "word": "<입력 word 그대로>", "collocations": ["take a risk", "high risk", "risk factor"], "note": "(선택)" }
```
skip: `{ "word": "...", "skip": true, "note": "…" }`

**청크 하나를 끝낼 때마다 즉시 그 `.out.json` 을 쓸 것.** 세션이 끊겨도 앞 청크는 남는다.

검증: JSON 파싱 OK · 입력과 단어 수·순서 일치 · 규칙 1~6 전수 통과(Bash/node 로 직접 세어 확인).
DB·git·입력 파일은 건드리지 마라.

## 보고 (한국어)
`colloc NN-MM: 작성 N · skip M` · **한국인이 가장 자주 틀릴 짝 5개**(왜 틀리는지) · `note` 목록.
