# D0830-T5 — 예문 해석 달기

우리 사전에는 영어 예문이 48,730 개 있고, **한국어 해석이 붙은 것은 0개**다.
시중 교재는 예문마다 해석을 단다. 해석 없는 예문은 대다수 학습자에게 **읽히지 않고 넘어간다** —
예문을 실어 놓고도 그 자리가 비어 있는 것과 같다.

담당 청크의 항목은 낱말 하나 + 그 낱말의 대표 예문(`example`)이다.
**예문을 고치지 마라.** 할 일은 그 문장의 한국어 해석 하나뿐이다.

## 해석 규칙

1. **자연스러운 한국어.** 직역해서 어색하면 실패다. 학습자가 읽고 바로 이해되는 문장.
   영어 어순을 흉내 내지 말고 한국어 어순으로 옮긴다.
2. **표제어의 뜻이 해석에 드러나야 한다.** `meaning_ko` 가 그 낱말의 대표 뜻이다.
   예문 속 그 낱말이 한국어로 무엇이 되었는지 읽는 사람이 알아볼 수 있어야 한다.
3. **문장이면 문장으로, 구면 구로.** 기존 예문 중에는 문장이 아니라 구(`a great deed`)나
   여러 항목을 이어 붙인 것(`public library public park`)이 섞여 있다.
   그런 것은 **있는 그대로 구로 옮기고**, `note` 에 "문장이 아님" 을 적는다.
4. **문체** — 설명문은 평서형(`~다`), 대화체 문장은 대화체로. 존댓말/반말은 문장 성격에 맞게.
5. **고유명사·숫자·단위는 그대로.** 억지로 한국식으로 바꾸지 마라.
6. 문장부호는 한국어 관행대로. 원문에 없는 정보를 더하지 마라 (의역은 좋지만 창작은 안 된다).

## 이런 것은 `note` 에 적는다 (고치지는 말고)

- 예문이 문장이 아님 (구·목록·조각)
- 예문 속 낱말이 표제어보다 어려움 (예문이 아니라 새 문제가 된다)
- 예문이 `meaning_ko` 와 다른 뜻을 보여 줌 (동음이의어 오염)
- 예문이 비문이거나 오타가 있음
- `meaning_ko` 자체가 틀렸거나 잘림

## 출력

`chunk-NN.json` 옆에 `chunk-NN.out.json`. 배열 하나. JSON 만. **모든 낱말에 한 줄씩.**

```json
[
  { "word": "abandon", "example_ko": "선원들은 침몰하는 배를 버리고 떠나야 했다." },
  { "word": "deed", "example_ko": "위대한 행위", "note": "예문이 문장이 아니라 구다" }
]
```

- 앞뒤 설명 문장 금지. 입력에 없는 낱말을 추가하지 마라.
- 해석이 도저히 불가능한 항목(예문이 깨져 있음)은 `example_ko` 를 생략하고 `note` 만 남긴다.
