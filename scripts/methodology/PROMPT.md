# 방법론 추출·정규화 드레인

에이전트가 직접 판단한다. API 키가 없다는 이유로 별도 모델 호출을 기다리지 않는다.
이 절차는 사람이 선택할 화면 디자인이나 원격 마이그레이션 승인을 대체하지 않는다.

## 입력과 원문 경계

1. 공식 활동 출처와 채널 소유 관계부터 확인한다. 동일 이름만으로 전문가를 연결하지 않는다.
2. `drain.mts seed <new.json>`으로 초기 조사 번들을 만들거나 현재 DB 스냅샷을 받아 출발한다.
3. 공개 문서는 실제 읽은 절을 기록한다. 제목/검색 요약만 읽었으면 `metadata_only`를 유지한다.
4. 허용된 자막은 저장소 밖에 둔다. permission JSON에 `analysisPermitted: true`, 허용 근거 `basis`, `sourceId`, `sourceUrl`, UTF-8 원문 SHA256 `sha256: "sha256:<64 hex>"`를 적는다. 권리가 미확인이면 그 자료는 중단하고 다른 확인 가능한 출처로 진행한다.
5. `drain.mts captions <file.vtt> <permission.json>`은 자막을 메모리에서 정규화하고 구간을 stdout으로만 낸다. stdout을 파일로 리다이렉트하지 않는다. 도구/터미널 기록에도 내용이 남을 수 있으므로 비공개 원문에는 해당 환경의 보관 정책까지 확인한다.
6. 구간의 `budget` 경계는 길이 제한이지 주제 경계가 아니다. 앞뒤 구간을 함께 읽어 주제·방법·화자를 판정한다. 자막의 문장 끝만으로 의미 단위가 완성됐다고 단정하지 않는다.

## 출력 계약

원문이 아닌 **파생된 전체 번들**을 새 `<batch>.out.json`으로 만든다. `types.ts`와 `validateBundle`이 계약이다.

- `Source.revision`: 자막은 permission과 같은 SHA256. 문서는 읽은 버전 표식. 문서 본문이 달라졌으면 새 버전으로 취급한다.
- `Source.access`: 실제 읽은 범위와 일치. 자막을 읽었으면 `transcript_read`, `rights: analysis_permitted`, 양수 영상 길이 필요.
- `Method.statement`: 핵심 원칙 주장의 재서술과 정확히 같아야 한다. 처음에는 `review: extracted`, 효과는 `not_assessed`, 제품 적용은 빈 배열.
- `Claim`: 원칙·조건·절차·이유·예시·실패·예외·전이를 각각 별도 주장으로 둔다. 출처가 말하지 않은 슬롯은 생성하지 않는다. 각 주장에는 supporting evidence가 필요하다.
- `Evidence`: 문서 절 또는 실제로 읽은 영상 초 구간, 원문 버전, 주장 ID, 그 출처에 등장하는 전문가 ID. 모호한 "영상 전체" 위치는 피한다. 전문가가 명시한 말과 분석자의 추론을 구분한다.
- 원문 전체나 긴 발췌를 output에 넣지 않는다. 현재 계약은 인용 필드를 제공하지 않고 짧은 재서술만 허용한다.
- 학령·숙련도·시험·기능·학습과정·문제유형을 서로 다른 축으로 부여한다. 제목만으로 CEFR·대상 학령을 추정하여 채우지 않는다.

## 정규화와 충돌

`report`의 문자열 유사도는 **후보 검색**일 뿐 의미적 동등 판정이 아니다. 에이전트가 기존 방법들과 목표·조건·절차를 대조한다.

- 같은 원칙·같은 조건이면 기존 method/claim에 새 evidence를 연결한다. 기존 근거를 지우지 않는다.
- 표현이 비슷해도 조건이 다르면 별도 방법을 보존하고 `context_differs` 관계를 검토한다.
- 서로 반대되는 절차는 `contradicts`로 남기되 양쪽 방법의 근거와 조건을 연결한다. 두 영상 제목의 대립만으로 충돌을 만들지 않는다.
- 관계마다 양쪽 method에서 최소 하나씩 evidence ID가 있어야 한다. 최초 관계는 `extracted`.
- 같은 강사·재업로드·쇼츠·공동 교재는 독립 출처처럼 세지 않는다. 독립 여부 미확인 자료는 보수적으로 같은 `originGroup`으로 묶는다.
- consensus는 명시적인 원칙 주장에 찬성하는 서로 다른 전문가/출처 계보만 센다. 교육 효과는 논문 제목·홍보 문구·동의 수로 판단하지 않는다.

## 검증·적재·복구

1. `validate <batch>.out.json` → 오류가 있으면 적재하지 않는다. 근거가 없는 주장을 채우기 위해 내용을 지어내지 않는다. 이 단계는 읽기 전용이며 재실행 안전.
2. `report <batch>.out.json` → 커버리지에서 색인/본문 열람/추출/사람 검토를 구분하고 중복 후보를 사람이 검토한다. 읽기 전용이며 재실행 안전.
3. `prepare <batch>.out.json` 또는 `import <batch>.out.json` → 원격 쓰기 없는 사전 점검. 행 수·입력 fingerprint를 확인한다.
4. **승인되어 적용된 schema가 있는 경우에만** `import <batch>.out.json --commit --actor=<담당자> [--parent=<현재 snapshot ID>]`. 최초 import만 parent가 없다. 동일 입력 재실행은 no-op, 다른 입력은 이전 snapshot을 보존하는 신규 버전이다.
5. 다른 작업이 먼저 적재하면 head 검사가 거부한다. 최신 snapshot을 읽어 양쪽 변경을 합친 새 번들을 검증하고 새 parent로 재시도한다. 단순히 parent 값만 바꾸지 않는다.
6. 네트워크 오류 때는 적재 실패/성공을 추정하지 않는다. 같은 입력을 재시도하면 기존 배치를 반환하거나 원자적으로 새 배치를 만든다. 모든 FK/근거 검증 실패는 배치 전체가 롤백된다.
7. 원문 자막은 이 파이프라인이 복사하지 않는다. 사용자가 제공한 원본 파일을 에이전트가 임의 삭제하지도 않는다.

사람 검토 전 번들은 추천 엔진에 연결하지 않는다. 검토 후 `reviewedBy`·`reviewedAt`과 검토 근거를 남긴다. 웹에서 편집/검토하는 화면은 별도 디자인 선택 후 구현한다.
