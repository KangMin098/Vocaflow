# 교재 문항 3인 검수 — 명세

> `item-review-drain-export.mjs` 가 뽑은 `chunk-NN.json` 을 읽어 `reviews` 셋을 채우고
> **같은 이름 + `.out.json`** 으로 저장한다. 그다음
> `item-review-drain-import.mjs --band N --commit` 이 `csat_item_reviews` 에 넣는다.

## 왜 이 검수가 생겼나

DB 실측 2026-09-12:

| 대상 | 3인 검수 | 학습자에게 가는가 |
|---|--:|---|
| 기출 분석 2,234건 | **6,702행**(정확히 ×3) | 아니오 |
| 조판된 19권 · 지면 **1,860문항** | **0행** | **예** |

검증이 거꾸로 걸려 있었다. 학습자에게 가지 않는 분석물은 세 사람이 읽었고, 손에 쥐는 책의
문항은 기계 게이트만 통과했다. 여기서 채우는 것이 그 빈자리다.

⚠️ **뽑히는 것은 「그 권에 실릴 문항」뿐이다.** 창고 65만 문항 중 60% 는 어느 권에도 안
실린다 — 지면에 없는 문항을 검수하는 것은 아무도 읽지 않을 글을 검수하는 것이다.

## 세 페르소나 — 무엇을 보는가

기출 분석 검수(`scripts/csat/analysis-drain/_PROMPT.md`)와 **같은 세 사람**이지만, 보는
대상이 「분석문」이 아니라 **문항 자체**다.

| persona | 누구 | 무엇을 보는가 | `revise`/`fail` 을 주는 자국 |
|---|---|---|---|
| `setter` | 출제자 (평가원 출제위원) | **정답이 유일하게 성립하나.** 근거가 지문에 **문자 그대로** 있나. 이 유형의 정의에 맞는 문항인가 | 근거가 지문에 없다 · 정답이 둘로 읽힌다 · 유형과 어긋난다(빈칸인데 내용일치로 풀린다) |
| `analyst` | 오답 분석가 (채점·문항반응 통계) | **오답 4개가 서로 다른 이유로 틀리나.** 매력이 있나(아무도 안 고를 선지는 선지가 아니다). 정답과 배타적인가 | 오답 둘이 같은 이유로 틀린다 · 지문과 무관한 선지 · 정답과 겹쳐 둘 다 맞다 |
| `tutor` | 현장 강사 (학습자 대리) | **그 학년(V-Level)이 풀 수 있나.** 해설이 「왜 나머지가 아닌지」를 짚나. 어휘가 학년 밖으로 튀지 않나 | 학년 밖 어휘가 정답을 좌우한다 · 해설이 정답만 설명한다 · 지문 길이가 그 학년 창 밖이다 |

세 사람은 **각자 독립으로** 읽는다. 앞 사람의 판정을 보고 맞추면 3인 검수가 아니라 한 사람의
판정이 세 번 적힌 것이다.

## 채우는 모양

```json
{
  "id": "…",
  "type": "blank",
  "v_level": 5,
  "payload": { "…": "export 가 넣어 준 그대로 — 고치지 않는다" },
  "answer_key": { "…": "그대로" },
  "reviews": [
    {
      "persona": "setter",
      "verdict": "pass",
      "findings": [],
      "checked": ["정답 근거가 3문장 'however …' 에 문자 그대로 있다", "빈칸 유형 정의에 맞다"]
    },
    {
      "persona": "analyst",
      "verdict": "revise",
      "findings": ["② 와 ④ 가 같은 이유로 틀린다 — 둘 다 지문에 없는 인과다"],
      "checked": ["오답 4개의 탈락 이유를 각각 확인", "정답과 배타성 확인"]
    },
    {
      "persona": "tutor",
      "verdict": "pass",
      "findings": [],
      "checked": ["해설이 ②④ 의 탈락을 짚는다", "어휘가 고1 창 안"]
    }
  ]
}
```

## import 가 거르는 것 — 넣히지 않으려면

| 거르는 것 | 왜 |
|---|---|
| `verdict` 가 빈 문자열 | 안 본 것이다. 빈 값이 들어가면 다음 export 가 「완료」로 세어 **구멍이 영영 남는다** |
| 정의 밖 `persona`·`verdict` | DB CHECK 가 막지만 import 가 먼저 이름을 말해 준다 |
| 같은 `persona` 두 번 | 같은 눈이 두 번 본 것은 다각이 아니다 (DB 의 `unique (item_id, persona)` 도 막는다) |
| `pass` 인데 `checked` 가 빈 것 | 무엇을 봤는지 없는 pass 는 검수가 아니라 **도장**이다 |

`fail`·`revise` 는 **적재한다** — 기록이기 때문이다. 발행 게이트는 「pass 3인」만 세므로
fail 이 있는 권은 그대로 막힌다. 드레인은 사실을 남기고, 판정은 게이트가 한다.

## 재실행 안전

| 단계 | 안전한가 | 왜 |
|---|---|---|
| export | **예** | 읽기만 한다. 이미 3인 pass 를 받은 문항은 안 나온다. 청크 파일만 덮어쓴다 |
| Claude Code | 예 | 로컬 파일만 쓴다 |
| import (미리보기) | **예** | `--commit` 없이는 아무것도 안 쓴다. 거를 것과 건너뛴 이유만 찍는다 |
| import `--commit` | **예** | `unique (item_id, persona)` 에 upsert — 몇 번 돌려도 행이 안 늘고 마지막 판정이 남는다 |

## 끝났는지 확인

1. `item-review-drain-export.mjs` 를 다시 돌려 「3인이 읽을 몫」이 줄었는지 본다.
2. 그 밴드를 조판하면 발행 게이트의 **「3인 검수」 축이 오른다** — 전부 차면 그 축이 사라진다.
3. `revise`·`fail` 이 남아 있으면 조판이 계속 막힌다. 문항을 고치는 것은 별개 작업이고,
   고친 뒤에는 그 문항의 검수 행을 지우고 다시 받는다(`delete from csat_item_reviews where item_id = …`).
