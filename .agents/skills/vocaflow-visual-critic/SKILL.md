# 렌더 결과 비평

[DESIGN.md](../../../DESIGN.md)와 해당 화면의 도메인 결정을 읽는다. 화면별 골격·서명 배정은 DESIGN.md 표에 있다.
스크린샷을 직접 열어 확인하고 라우트·뷰포트·테마·상태·촬영 시점을 함께 기록한다.
화면이 없으면 시각 검토는 미실행으로 남긴다. 코드만 보고 시각적 통과를 선언하지 않는다.

## 판정 순서 — [06-workflow](../../../docs/design/06-workflow.md) 5단계와 같다

1. **(a) 익명성** — 로고·제품명을 가린 채 이 화면만으로 (1) 앱 종류 (2) 이 제품인지 말할 수 있는가. (2)가 안 되면 재작업.
2. **(b) 평균 회귀** — 보이는 것을 **위치와 함께** 적는다:
   카드+그림자 묶음 · 3열 균등 격자 · 중앙 정렬 제목 · 의미 없는 선/아이콘 · 서명 요소 부재 · 같은 색이 두 의미 · 본문보다 큰 제목.
   골격이 카드 목록·표·격자면 vocaflow-design §G(N4 불통과)로 판정한다.
3. **(c) 골든 대조** — [docs/design/golden/](../../../docs/design/golden/README.md) 의 같은 뷰포트 이미지와 나란히. 차이 중 "의도된 새 결정 1개"가 아닌 것만. 비어 있으면 "기준 없음".
4. **(d) 포트폴리오** — [own-portfolio.md](../../../docs/design/own-portfolio.md) 와 팔레트·서체·서명 중 둘 이상 겹치면 "쌍둥이". 비어 있으면 "기준 없음".
5. **(e) 규칙·접근성** — Part 2 하한선과 아래 관찰 항목.

관찰할 것 (e):

- 첫 시선이 원문·근거·주 행동 중 어디로 향하는가. 장식이나 보조 행동이 핵심과 경쟁하는가.
- 제목·본문·주석의 위계, 한글 줄바꿈, 영어 원문의 가독성, 정렬·간격·밀도.
- 불필요한 카드·컨테이너, 관계를 숨기는 배치, 같은 의미의 표식 불일치(형태 문법 F1–F5 와 다른 뜻으로 쓰인 선).
- 선택·정답·오답·근거가 색 이외의 모양·문구로도 구분되는가.
- 좁은 화면의 잘림, 겹침, 가로 넘침, 가려진 조작, 첫 화면에서의 가치 확인.
- 키보드 접근·포커스 표시·복원, 상태 설명, 다크모드, reduced-motion.
  정지 이미지로 증명할 수 없는 항목은 브라우저에서 확인하거나 미검증으로 표시한다.

## 출력 — 이 형식만

```
화면 · 뷰포트 · 테마 · 상태 · 촬영 시점
(a) 익명성: 통과/불통과 — 근거 한 줄
(b) 평균 회귀: [위치 — 무엇] 목록 (없으면 "없음")
(c) 골든: 차이 목록 또는 "기준 없음"
(d) 포트폴리오: 쌍둥이/아님/기준 없음
(e) 규칙·접근성: 목록
차이 ≤5 (위 전부 합쳐 영향 큰 순)
가장 나쁜 것 1개: 관찰 위치 → 사용자에게 생기는 문제 → 수정 제안 → 코드 위치 → 재검증 방법
판정: 통과 / 재작업
```

**칭찬하지 않는다** — 잘된 점 목록은 출력에 넣지 않는다. 판정에 필요한 것은 결함과 근거뿐이다.
수정 지시는 **가장 나쁜 것 1개만**. 그것을 고치고 같은 조건에서 재검증한다. 루프는 2회까지, 그 뒤는 사람 판단.
취향 제안과 기능·접근성 결함을 구분한다. 픽셀 차이나 점수만으로 미감을 판정하지 않는다.
관찰되지 않은 문제를 개수에 맞춰 지어내지 않는다.
검토 요청만 받았으면 파일을 수정하지 않는다. 구현 작업의 일부라면 허용된 범위의 수정을 이어간다.

종료 기준은 (a) 통과, 핵심 행동을 막는 결함의 해결, 합의한 화면 조건 충족, 동일 조건 재검증이다.
잔여 문제와 검증 한계를 남긴다. 새로운 제품 기능·디자인 취향을 계속 추가하지 않는다.
