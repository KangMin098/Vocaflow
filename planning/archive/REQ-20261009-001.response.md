# ChatGPT 독립 기획 검토 — REQ-20261009-001

**판정: REVISE (범위 수정 후 구현 제안)**  
**작업:** T-0006 / VG-L3-D1-02  
**정본:** v1.1.0  
**지위:** PROPOSED — 사용자 승인이나 AC1 전체 PASS가 아님

## 핵심 결론

이번 작업은 관리자 리텐션의 **내부/QA 계정 오염을 제거하는 좁은 변경**으로 추진하는 것이 적절합니다. 반면 원래 수용 기준의 “사용자 지표 및 효과 평가 전체”를 이번에 완료했다고 기록해서는 안 됩니다.

**권장 설계:** 서버가 소유한 명시적 계정 ID 분류를 1차 근거로 쓰고, 관리자 역할은 내부 계정 식별에 한해서 보완합니다. 예약·자사 이메일 도메인은 검토 후보를 찾는 힌트일 뿐 자동으로 실사용/내부를 확정하는 근거가 아닙니다. 미분류 계정은 실사용으로 집계하지 않고 별도로 표시합니다.

## 코드·목표 정본에서 확인한 근거

- `retention.ts`는 `auth.admin.listUsers()`로 받은 사용자 전체를 그대로 `computeRetention()`에 전달합니다. 현재 외부 학습자와 내부 계정을 분리하는 필터가 없습니다.
- `retention-math.ts`는 전달받은 전체 배열을 가입자 분모로 사용합니다. 수학 계산을 변경하기보다 **입력 집합의 의미를 고치는 것이 우선**입니다.
- `RetentionPanel.tsx`는 `가입자`, `활성화`, `D1/D7/D30`을 제시하므로 내부 계정을 일반 실사용 학습자로 오해할 수 있습니다.
- 승인 정본 `VG-L3-D1-02-AC1`은 **QA·합성 데이터가 사용자 지표 및 효과 평가에서 제외**되는 것을 요구합니다. 단일 리텐션 패널 수정만으로 전체 수용 기준을 충족하지 않습니다.
- 첨부 7개 파일은 요청서에 기재된 SHA-256과 모두 일치합니다. 공개 GitHub URL과의 실시간 비교는 이번 검토에서 별도로 수행하지 않았습니다.

## 설계 결정 및 구현 순서

**이번 단위:** 서버 전용 registry/allowlist, 분류 순수 함수, 관리자 조회 필터, 집계 및 화면 표시, 회귀 테스트를 진행합니다. 신규 DB SQL·기존 DB 데이터 변경은 하지 않습니다. `auth.users` 사용자 ID만을 키로 사용하고 이메일은 표시·판정 근거로 외부에 내보내지 않습니다.

**다음 단위:** 검증된 `user_type` 또는 영속적인 중앙 분류 모델을 승인·마이그레이션하고, 퍼널·효과 분석·사용성 파일럿까지 동일 계약으로 통합합니다. 실제 외부 사용자의 `verified` 지위는 명시적으로 관리해야 합니다.

**집계 상태:** 미분류가 존재하면 실제 외부 0명과 미분류 N명을 동시에 보여주되, “외부 사용자 자체가 0명임이 증명되었다”고 표현하지 않습니다. registry의 구조적 오류가 있으면 값을 임의로 0으로 내리지 않고 계산 불가로 분리합니다.

**우선순위: P1.** R0 운영 판단 근거의 신뢰성을 바로잡는 작업입니다. 단독으로 제품 전반의 학습 효과를 입증하거나 수정하는 작업은 아닙니다.

## 구현·검증에 대한 유의점

기존 20명 미만 퍼센트 숨김, D1/D7/D30 분모 성숙도, KST 날짜, 실패 시 `null` 반환 같은 정직성 계약은 그대로 유지합니다. 계정 집합을 필터링하기 전후의 통계를 관리자에게 보여주되, 계정 ID·이메일 주소와 서버 registry 내용은 노출하지 않습니다.

제안 단계에서는 데이터베이스 쓰기나 승인된 전략 SD-R0-01~04의 변경을 허용하지 않습니다.
