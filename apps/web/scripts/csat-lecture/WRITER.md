# 강의 대본 작성 지침 — 드레인 작성자용

> 이 파일은 서브에이전트 작성자에게 그대로 전달된다. 파일럿(Gate 1) 세 번의 독립 심사가 짚은 것을 전부 반영했다.
> 정본 지시문: `docs/csat-lecture-tts-brief.md` · 결정: `docs/csat-lecture/DECISIONS.md`

## 너의 일

`scripts/csat/lecture-drain/chunk-<이름>.json` 의 문항마다 **소리로 읽히는 강의 대본**을 쓴다.
결과는 `chunk-<이름>.out.json` 하나:

```json
{ "lectures": { "<문항 id>": { "attempt": 1, "cues": [ { "r": "...", "t": "...", "p": 700, "s": [ ... ] } ] } } }
```

- `r` 역할 — `intro` → `strategy` → `structure` → `evidence`(1~3개) → `eliminate`(오답마다 하나) → `trap` → `vocab` → `wrapup`. **이 순서를 거꾸로 가지 않는다.** 같은 역할을 이어서 여러 번 쓰는 것은 된다.
- `t` 타깃 — 이 큐를 말하는 동안 화면에서 빛날 곳. 문항의 `targets.analysis`·`targets.anchor` 에 **있는 값만** 쓴다.
  - `sentence:k` — 지문의 k번째 문장 막대(0부터). 말할 때는 **(k+1)번째**다.
  - `head` 문항 머리 · `ability` 재는 능력 · `intent` 출제 의도 · `map` 지문 지도 전체 · `answer` 정답 블록 · `reject:n` n번 오답 블록 · `procedure` 풀이 순서 · `vocab` 어휘
  - 역할별로 쓸 수 있는 타깃: intro=`head|ability|intent` · strategy=`head|ability|intent|procedure|map|sentence:k` · structure=`map|intent|ability|procedure|sentence:k` · evidence=`answer|map|sentence:k` · eliminate=`reject:n` · trap=`reject:n|sentence:k` · vocab=`vocab|sentence:k` · wrapup=`procedure|head|ability`
- `p` 큐 뒤 쉼(ms, 300~900). 생략하면 역할 기본값.
- `s` 조각 — 문자열은 **한국어**, `{ "en": "..." }` 는 **영어**. 한국어 조각에 로마자를 넣지 않는다.

## 절대 규칙 (적재기가 기계로 막는다 — 하나라도 걸리면 적재되지 않는다)

1. **원문 낭독 금지.** 영어 조각은 지문·선지·문두와 **8단어 연속 일치가 0**이어야 한다. 인용은 **6단어 이하**로. 긴 문장은 위치로 가리킨다(「여기 세 번째 문장」).
2. **분석 원고를 베껴 읽지 않는다.** `analysis` 의 한국어 문장과 20자 이상 똑같으면 막힌다. 뜻을 **말로 다시** 한다.
3. **한국어 조각에 아라비아 숫자·원문자·로마자·% 금지.** 적재기가 ①→「일 번」, 23번→「이십삼 번」, 2014학년도→「이천십사 학년도」, (A)→「에이」로 바꿔 주지만, **고유어 수 자리는 네가 한글로** 쓴다(「세 번째 문장」·「두 개」). 「3번째」라고 쓰면 막힌다. 달 이름은 한글로(「유월」·「구월」·「십일월」).
4. **「여기 N번째 문장」이라고 말하면 그 큐의 `t` 는 반드시 `sentence:(N-1)`.** 화면이 다른 곳을 켜 놓고 「여기」라고 하면 막힌다. 오답 블록(`reject:n`)을 켠 큐에서는 「여기」 없이 「세 번째 문장을 짚어 보세요」처럼 말한다. **지도가 없는 문항(`targets.anchor` 가 빈 배열)은 「여기 N번째 문장」을 쓰지 않는다.**
5. **큐마다 지시어가 하나 이상** — 「여기」「보세요」「짚어 보세요」「확인하세요」「찾으세요」「표시하세요」「주목」 중 하나.
6. **학습자를 「여러분」으로 부른다**(한 강의에 한 번 이상). 존댓말. 구어체.
7. **무근거 난이도 판정 금지** — 「이 문제는 쉽습니다/어렵습니다」「어려운 문항」.
8. **길이** — 큐 하나 ≤ **20초**(1배속 한국어 **초당 4음절** · 문장마다 0.3초 · 영어 초당 2.6단어로 계산). 한 강의 **150~270초**(쉼 포함), 큐 **8~14개**. 한 문장 **40음절 이하**(권장 22음절 이하 — 짧을수록 낭독 점수가 오른다).
9. **오답 배제는 오답 하나에 큐 하나** — `targets.analysis` 의 `reject:n` 전부를 빠짐없이, 겹치지 않게. 정답을 지우는 큐는 없다.
10. `targets.analysis` 에 `vocab` 이 있으면 `vocab` 큐가, 오답 분석에 함정 이름(`trap`)이 하나라도 있으면 `trap` 큐가 있어야 한다. 정답을 아는 문항(`answer` ≠ null)은 `evidence` 큐가 있어야 한다.

## 품질 (독립 심사관이 80점 만점으로 매긴다 — 합산 80점 미만이면 떨어진다)

| 항목 | 점수 | 파일럿 심사관이 실제로 깎은 것 |
|---|---|---|
| 왜 | 20 | 근거 **자리**(몇 번째 문장)와 **논리 관계**를 둘 다. 결정적 논리는 **그 근거 문장을 켠 큐**에서 말한다(다른 문장을 켜 놓고 핵심을 말하면 깎인다) |
| 오답 배제 | 20 | 오답마다 **결정적 근거를 먼저**, **문장 번호와 함께**. 「본문에 없다」「거리가 멀다」 같은 보조 근거만 대면 깎인다. 선지가 지문 어느 낱말을 비틀었는지 정확히(「살짝 바꾼 말」처럼 틀린 비유 금지) |
| 함정 | 15 | 함정 이름 + **미끄러지는 정확한 자리(문장 번호)** + 왜 끌리는지 + 끝에 **구체적 행동** 한 줄. 분석의 가장 강한 함정을 고른다 |
| 전략 | 15 | 지문을 **읽기 전에** 할 일 **하나**. 이 문항·이 유형에 맞는 것. 정리(wrapup)의 첫 십 초 행동과 **같은 행동**이어야 한다 |
| 공식 | 10 | 정리: 다음 같은 유형에 옮길 수 있는 **한 줄 규칙** + 「다음에는 첫 십 초에 ○○부터」 |

### Gate 3(강의만 듣고 설명할 수 있는가)이 짚은 구멍 — 여기서 점수가 샌다

- **근거 ↔ 정답을 낱말 단위로 짝지어 말한다.** 「세 번째 문장의 믿음이 선지의 확신과, 앞으로 남는다가 어디로 가는지와 맞물리죠」처럼. 「그래서 정답입니다」로 건너뛰면 듣는 사람은 연결을 못 한다.
- **논리 고리를 한 칸도 건너뛰지 않는다.** 「평가가 바뀐다 → 그래도 산다 → 그러니 미래를 내다본다」에서 가운데 칸이 빠지면 구멍이다.
- **오답 배제에 순환 논리 금지** — 「연약함은 원하는 상태가 아니다」는 근거가 아니다. 지문의 어느 말과 어떻게 어긋나는지를 말한다.
- **정리의 공식은 이 문항을 실제로 푼 결정적 단서와 같아야 한다.** 예고문으로 풀어 놓고 「지시어로 첫 자리를 거른다」로 정리하면 공식이 제 문항과 어긋난다.
- **도입에서 「○○가 순서를 정한다」라고 했으면 그것만으로 끝까지 설명이 되어야 한다.** 다른 단서(Indeed 등)도 필요하면 도입에서 함께 말한다.
- 연결어·지시어가 **왜** 그 자리만 가리키는지(다른 후보가 왜 안 되는지)를 한 문장 붙인다.

**사실 오류는 점수와 상관없이 떨어진다.** 지문과 어긋나는 말, 틀린 문장 번호, 틀린 단락 순서, 과장(「처음부터 끝까지」·「절반을 지운다」)이 그렇다. 분석 원고에도 오독이 있다 — **지문을 직접 읽고** 확인한 것만 말한다.

### 유형별로 strategy·structure 가 반드시 말할 것

| 유형 | strategy (읽기 전에) | structure (뼈대) |
|---|---|---|
| 빈칸(R-BLANK·R-BLANK2·X-BLANK·X-BLANK2) | 빈칸 문장의 주어·연결어·틀(not only A but B 등)을 먼저 — 빈칸이 주장인지 근거인지 예시인지 | 주장 문장 → 빈칸 문장의 관계(재진술·대조·인과) |
| 순서(R-ORDER·X-ORDER) | 주어진 글의 마지막 문장 · 각 단락 첫 문장의 지시어·연결어를 먼저 표시 | 연결어·대명사 사슬, 단락 시작 문장 번호 |
| 삽입(R-INSERT) | 주어진 문장의 지시어·연결어가 무엇을 받는지 | 논리가 끊기는 자리 |
| 주제·제목·요지·주장·목적(R-TOPIC·R-TITLE·X-TITLE·R-GIST·R-CLAIM·R-PURPOSE) | 반복 어휘 두 개를 먼저 찾는다 | 첫·끝 문장의 관계, 전환 신호 |
| 요약(R-SUMMARY) | 요약문의 빈칸 두 자리를 먼저 읽고 무엇을 찾을지 정한다 | 원인·결과/대조 축 |
| 어법(R-GRAMMAR) | 밑줄 다섯을 품사·역할로 먼저 분류 | 문장 뼈대(주어–동사) |
| 어휘(R-VOCAB·X-VOCAB) | 밑줄 낱말의 앞뒤 논리 방향을 먼저 | 글의 흐름(긍정·부정 축) |
| 무관(R-IRRELEVANT) | 첫 문장의 화제를 한 줄로 | 각 문장이 화제에 붙어 있는가 |
| 함축(R-IMPLY) | 밑줄 표현의 비유를 풀 단서가 어디 있을지 | 비유 ↔ 본문의 대응 |
| 지칭(X-REFER·R-REFER) | 등장인물을 먼저 적는다 | 대명사 사슬 |
| 심경·분위기(R-MOOD) | 처음과 끝의 감정 단서 위치 | 감정이 바뀌는 전환점 |
| 안내문·도표·내용 일치(R-NOTICE·R-CHART·R-FACT·X-FACT) | **선지를 먼저** 읽고 숫자·조건만 대조 | 표의 행·열 / 안내문 항목 대응 |

## 모양 예시 (빈칸 문항, 약식)

```json
{ "r": "evidence", "t": "sentence:1", "p": 700,
  "s": ["결론부터 말할게요. 정답은 일 번입니다.",
        "근거는 빈칸 옆이 아니라 여기, 두 번째 문장이에요.",
        { "en": "for contemplation, research, display" },
        "목적을 위해 골라 지키는 상태, 곧 원하는 상태죠."] }
{ "r": "eliminate", "t": "reject:3",
  "s": ["삼 번, 고립된 상태. 여섯 번째 문장을 짚어 보세요.",
        "최대한 덜 건드린다는 건 그대로 두는 쪽의 태도죠. 빈칸의 주어와 편이 다릅니다."] }
```

## 끝내기 전에 반드시

```bash
cd D:/workspace/Vocaflow/apps/web
npx tsx scripts/csat-lecture/drain-import.mts --chunk <이름>
```

출력에서 `ungraded`(아직 심사 전) **외의 문제가 하나도 없을 때까지** 고친다. `cue-long` 은 문장을 줄이거나 큐를 나눈다(큐 14개 한도). `pointing` 은 타깃을 그 문장으로 바꾸거나 「여기」를 뺀다.
**다른 청크의 파일은 건드리지 않는다.** `--commit` 은 쓰지 않는다(적재는 심사 뒤에 조정자가 한다).
